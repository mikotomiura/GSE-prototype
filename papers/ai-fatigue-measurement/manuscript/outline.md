# Manuscript outline

This outline fixes the structure of the manuscript, the evidence for each claim and the rules for reporting before
any record of the confirmation set is coded. It contains no result value and no expectation about results. Each claim
names the item of the registration that defines it (GSRR numbers refer to the registered protocol, Generalized
Systematic Review Registration form), the output from which its values are copied, and the table or figure that
reports it. The registration, its codebook and its amendments take precedence over this outline wherever they differ.

## Title

How do studies of "AI fatigue" attribute fatigue to AI, measure it, and report it? A registered methodological review

The title is fixed here and is not changed after the results are known. It repeats the registered title, with the
article type in place of "Protocol for a methodological review".

## Journal requirements to be met

The target journal is not chosen. Until it is, the manuscript is prepared to the conventions of the Publication
Manual of the American Psychological Association, 7th edition, with an abstract of no more than 250 words, a
Declarations section, an Open Practices Statement and a data availability statement. The journal's instructions are
read when it is chosen, and this section is rewritten then. Whatever the journal, the following are part of the
manuscript:

- the reporting checklist of Murad and Wang (2017) for meta-epidemiological methodology research, supplemented by the
  items of PRISMA 2020 (Page et al., 2021) that it lacks (registration and amendments, data and code availability,
  competing interests, the flow diagram), as a completed checklist in the supplement; items that do not apply outside
  health research are marked as not applicable;
- whether a reporting guideline for methodological studies has been published since the registration (Lawson et al.,
  2020) is checked again immediately before submission;
- the registration, its amendments, the code table, the codebook, the coding form, the screening decisions and the
  scripts are cited with persistent identifiers.

## Scope of the claims

- The review describes; it estimates no effect and tests no hypothesis (GSRR-13, GSRR-56). No significance test, no
  prevalence estimate and no comparison between sets is reported.
- Primary answers come from the confirmation set only (GSRR-11). The exploration set, from which the rules were
  built, is reported in a separate table and is never used to state that a problem was observed in the confirmation
  set (GSRR-57). The late stratum is reported separately and outside the primary counts (GSRR-39).
- A table based on fewer than 10 studies reports counts only (GSRR-39). A statement about a problem type is one of
  "was observed in the confirmation set", "was not observed in the confirmation set" or "could not be evaluated", each
  with the count, the number of evaluable records and the number unresolved (GSRR-57). No other word of frequency or
  severity ("common", "widespread", "rare", "serious") is used about a problem type.
- The item-content types (C2b) are described and are not called problems (GSRR-57). The level of attribution (C1) is
  described and is not a problem type; claiming "AI fatigue" on a weak attribution is counted only through C7 (ii).
- C7 says how far a conclusion is supported by what was measured; it does not judge whether a finding is true
  (GSRR-57). C2d and C4 describe reporting and are not quality ratings (GSRR-55).
- The confirmation set is the set of studies included by both screeners by 31 December 2026. It is not a census of
  the literature on AI and fatigue, and the population groups were screened unevenly before registration (GSRR-42).
  Every claim about the confirmation set is about that set.

## Relation to the authors' earlier narrative review

The authors' critical narrative review described measurement problems in 11 reports drawn from the same exploratory
bibliography, without registration. This manuscript cites it as prior work and does not restate its observations as
findings. What this review adds, and what the manuscript claims as new, is limited to: rules fixed and registered
before coding; primary counts from records that were not used to build the rules; item-level coding of instrument
content with targets (C2b); the codes that the narrative review does not cover (C3, C6, C7 per study); and the
recalculation and consistency rules applied to every record (C4). If the narrative review is not yet published when
this manuscript is submitted, it is cited as a preprint or as an unpublished manuscript, and the overlap of authors is
stated in the Declarations (GSRR-19, GSRR-20).

## Contributions

1. **A registered coding scheme for measurement and reporting in studies of AI-related fatigue.** Seven codes (C1 to
   C7) with their rules, a codebook for item content, a coding form and a synthesis script that derives every value
   and table from the code table, all fixed before the confirmation set was coded.
2. **A description of how a set of studies not used to build the rules attributes fatigue to AI, measures it and
   reports it** (RQ1 to RQ5, SQ1, SQ2), with the problem statements of the registration.
3. **Item-level content of the fatigue instruments** first seen in the confirmation set: the composition of each
   instrument by type of item content and, for reduced interest, avoidance and futility, the target of the item.
4. **A released code table** with codes, item numbers and source pages (no item text), the screening decisions made
   after registration, and a per-instrument summary table, so that the tables can be recomputed and extended.

## Rule for the abstract

Fixed before coding. The abstract reports, for the confirmation set only: the number of studies and instruments
coded, with the number of calibration records removed and the number of candidates still unscreened on 31 December
2026; and, for each problem type of GSRR-57, the registered statement with its count, the number of evaluable records
and the number unresolved. It names the item-content types found in at least one instrument, without proportions. It
gives no value from the exploration set and no comparison with it. It uses no evaluative word about any value. If
the abstract does not fit the word limit, the item-content sentence is moved to the main text; the problem statements
are not shortened.

## Section plan

Sections are numbered here for reference; the manuscript follows the heading levels of the journal.

### Abstract

Background (studies of "AI fatigue" are multiplying; existing reviews point to unvalidated scales and unclear
construct boundaries). What was done (a registered methodological review of the studies included from a literature
database after the rules were fixed; seven codes; two independent coders). Results by the rule above. Availability
(registration, code table, codebook, scripts).

### 1. Introduction

- The growth of studies that report fatigue, exhaustion or burnout in relation to the use of AI systems, and the use
  of the term "AI fatigue" for constructs that range from fatigue attributed to AI in the items to general fatigue
  measured among AI users.
- Why measurement matters for this literature: a conclusion about "AI fatigue" is only as specific as the measure on
  which it rests; items that ask about avoidance, irritation or disengagement change what a "fatigue" score contains;
  internal inconsistencies and overlapping samples change how much evidence a set of reports carries.
- What is known: reviews of the topic and the COSMIN-based reviews of AI-related instruments evaluate measurement
  properties (Jonaid, 2026); studies of measurement practice in other fields count what reports disclose (Perrig et
  al., 2024). No review was found that tabulates, study by study, how fatigue is tied to AI, what the fatigue items
  ask about, and whether reports are internally consistent (the search is described in GSRR-10).
- The authors' narrative review and what this review adds (the section above).
- The research questions RQ1 to RQ5 and SQ1 to SQ2, stated as in GSRR-11 and GSRR-12, and the contributions.

### 2. Background

- Constructs: fatigue, exhaustion and burnout as the review's eligibility defines them (GSRR-24), including
  motivational and behavioural depletion, and why that definition shapes some outcomes (the share of reduced-interest
  items; the truncation of "no attribution" by the exclusion of studies without a relation to AI).
- Technostress and its exhaustion component; general fatigue scales adapted to AI; scales built for AI.
- Methodological studies and their reporting (Mbuagbaw et al., 2020; Murad & Wang, 2017; Long et al., 2024 on
  registration and reporting quality); recalculation of reported statistics (Nuijten et al., 2016).
- Only literature read in a free full text or a free abstract is cited; each citation is checked against its primary
  source before the manuscript is complete.

### 3. Method

1. Registration and amendments: the registration (GSRR form, van den Akker et al., 2023), its date, the list of
   amendments with dates, reasons and affected items (GSRR-65), and the reporting guideline.
2. Source of records: the literature database built by both authors and its searches (GSRR-21 to GSRR-32); the
   exploratory bibliography and the additional candidates; no search of this review's own.
3. Eligibility and screening: criteria (GSRR-24, GSRR-35); the two-screener process; what was screened before
   registration and by whom (GSRR-32, GSRR-34); the fixed screening order after registration and the release of every
   decision (GSRR-33, GSRR-41).
4. Sets: exploration set, confirmation set, late stratum, candidate pool and calibration sample, small-pool rule,
   minimum sizes (GSRR-39).
5. Coding: units, instrument and main-instrument rules, missing-value codes, and the codes C1 to C7 with the C4f and
   C6b rules (GSRR-43); the codebook (version 2); the use of AI drafts for C4f and C5 only (GSRR-44).
6. Calibration, coding, blinding and reconciliation (GSRR-44 to GSRR-48), including the procedure if coder 2 is
   unavailable.
7. Synthesis: derived values, missing data, the tables, the problem statements and the sensitivity analyses
   (GSRR-52 to GSRR-62); the script and its tests (GSRR-64).
8. Deviations from the registration, each with its reason (also in Table 2).

### 4. Results

1. Records and sets: flow diagram; candidates screened and unscreened on 31 December 2026 by population group;
   exclusions by code and, for E2 and E3, by population group; calibration rounds and records removed; whether the
   small-pool rule applied; studies and E5-linked records (Figure 1, Table 3).
2. Coder agreement per code and set, with the AI-draft cross-check for C4f (Table 4).
3. RQ1 attribution (Table 5).
4. RQ2 instruments and items: origin, modification and format; adaptation procedures; measurement properties; item
   content per instrument; AI-side variable instruments (Tables 6, 7 and 8).
5. RQ3 reporting completeness and consistency (Table 9).
6. RQ4 sample overlap (Table 10).
7. RQ5 title and abstract versus content, and SQ2 conclusions beyond what was measured (Table 11).
8. Problem statements (Table 12).
9. SQ1 by centre (supplementary tables; C7 with conditions (i) and (iii) only).
10. Sensitivity analyses 1 to 4 (Table 13).
11. Exploration set and late stratum (supplementary tables, labelled as such).

The text of each subsection is written only after the tables have been generated from the code table. It states what
the tables show in the registered terms and does not add interpretation.

### 5. Discussion

Written after the results. Its structure is fixed now:

1. What the confirmation set shows, question by question, in the terms of the problem statements.
2. Relation to the narrative review: which of its observations were and were not observed when the rules were fixed
   in advance and applied to a different set, without saying that a problem is more or less common than in the
   exploration set (GSRR-57).
3. Practical recommendations for authors and reviewers of studies of AI-related fatigue. Each recommendation is
   tied to one code and to the registered definition of that code (for example, printing the items administered;
   stating the level of attribution; reporting adaptation procedures), and is given whether or not the corresponding
   problem was observed, since the recommendations follow from the definitions, not from the counts.
4. Limitations (GSRR-65 in full, with any added by deviations).

### 6. Conclusions

The registered statements of the abstract, without additional claims.
