## 1. 測定の原理（★ なぜ既存ログで測れるか）

`src-tauri/src/input/liveness.rs:86-103` の `step()` は純関数で 3 分岐しか持たない:

| 条件 | 挙動 |
|---|---|
| `!session_active \|\| hook_event_seen`（打鍵が来た） | `starved_ms = 0` に**リセット** |
| `!system_input_seen`（OS の最終入力時刻が動かない） | **凍結**（`prev` をそのまま返す） |
| それ以外（OS は入力を見たが打鍵は無い） | `starved_ms += tick_ms` |

→ ★★★ **`starved_ms` は「沈黙のあいだ入力デバイスに触れていた累積時間」そのもの**であり、
打鍵でリセットされるので**ギャップ間で汚染しない**。

`src-tauri/src/lib.rs:2923` は `if health == prev_health && !rehook { continue; }` で間引き、
`liveness.rs:63-66` の既定は `log_after_ms: 30_000` / `down_after_ms: 120_000`。
→ ★ **NDJSON に出る `hook_health` 行は 3 種類**:

| 行 | 意味 |
|---|---|
| `alive:true`, `starved_ms≈30000` | 在席×非打鍵が累積 **30 秒**に達した（Suspect） |
| `alive:false`, `starved_ms≈120000`, `rehook:true` | 同 **120 秒**に達した（Down）＋ **測定器がフックを再設置** |
| `alive:true`, `starved_ms = peak` | ギャップが**打鍵で閉じた**（復帰行・peak を搬送） |

⚠️★★★ **30 秒未満の在席×非打鍵は 1 行も残らない。本実験は micro 帯（2–15 秒）について何も言わない。**

## 2. 対象と単位

- **対象**: `session_active` 中の、連続する 2 打鍵（`{"type":"key","press":true}`）のあいだの
  無打鍵区間で、長さが **30 秒以上**のもの。以下「**沈黙ギャップ**」と呼ぶ。
- **単位**:
  - **L1 / L3** = 沈黙ギャップ
  - **L2** = **5 分窓**（★ `window_counts` を再利用。⚠️ **窓の切り方を再発明しない**）
- **person-period**: ギャップを **10 秒ビン**に離散化する。

### 2.1 ⚠️ 窓の切り方が上流と同一であることの機械検査

★ 本実験の抽出器が窓ごとの keydown 数を再計算し、
**`block_variance.window_counts()` の出力と完全一致する**ことを検査する（`selftest` S1b）。
⚠️ 一致しなければ **exit 非 0** で止める。★ 一致は「窓の切り方を再発明していない」ことの構造的な証明である。

## 3. 解析の 3 層

| 層 | 問い | モデル依存 |
|---|---|---|
| **L1** | 沈黙ギャップは「在席×非打鍵」と「入力皆無」にどう分かれるか（被験者別の分布） | ★ **無し** |
| **L2** | ⚠️★★★ **5 分窓の時間は「打鍵中 / 在席×非打鍵 / 入力皆無」にどう配分されるか**。特に `keydown < 100` の窓 | ★ **無し** |
| **L3** | 在席情報は T0 に対して増分を持つか（2 基線への勝ち幅） | あり |

⚠️★★★ **L1 / L2 は model-free であり、L3 の成否と独立に結論を持つ。**

## 4. L3 の定式化

### 4.1 アウトカム

**打鍵再開（`typing_resumption`）** = 沈黙ギャップが打鍵によって終わること。
⚠️★ **「回復（recovery）」ではない** —— 別作業を始めただけの可能性を排除できないため、
`self_directed_recovery` と同一視しない。

**離散時間ハザード** `h(t | x) = P(ビン t で再開 | ビン t まで再開していない, x)` を推定し、
そこから `CIF(H) = 1 − Π(1 − h)` を導く。

⚠️★★★ **単一の二値 C-index を主指標にしない**
（`personalization-and-online-learning.md §8.1` 逐語「それは旧定式化の遺物である」）。

### 4.2 共変量（★ 事前に固定。探索・選択・変換を一切しない）

| 群 | 中身 |
|---|---|
| **時間** | ビンの区分定数 3 区分: `[30s, 120s)` / `[120s, 3min)` / `[3min, ∞)` |
| **T0（基線 b）** | 沈黙ギャップ**直前 30 秒**の打鍵統計: 打鍵数 / BS・Del 率 / IKI 中央値 / バースト長（連続 FT<200ms の平均文字数）/ 2 秒超ポーズ数 |
| **presence（提案）** | `presence_state(t)` ∈ {`Ok`, `Suspect`, `Down`}（**時変**・t までに出た行だけで決まる） |

⚠️★★★ **`feat` 行の `keys` / `bs_keys` は使わない。**
`personalization-and-online-learning.md §5.2` 逐語「**旧 NDJSON には本フィールドが無い**ので、
`--metrics` 経路では欠測が `0` に倒れる（「実測 0 打」と区別できない）」。
Tier 0 配線は **2026-08-16** であり、Phase1 コホート（P010–P014）のログは**それ以前**である。
→ ★ **`key` 行の `vk` / `press` / `t` から直接数え直す。**

⚠️ [V83] が挙げる 3 脅威（小標本 / 強い不均衡 / **尺度の場当たり変換**）は本コホートの条件と
3 つとも一致する。→ **正則化なし・ハイパーパラメータ調整なし・特徴量選択なし。**

### 4.3 モデルと分割

- **モデル**: person-period データ上の**ロジスティック回帰**（離散時間ハザード）
- **分割**: **leave-one-subject-out**（★ `research-positioning.md §8` が subject split を必須にしている）

### 4.4 比較（★ 2 基線・[V83] の要求）

| 記号 | 中身 |
|---|---|
| **基線 (a)** | **多数派** = 共変量なしの周辺 `CIF`（★ [V83] 逐語 `We cannot replicate models that significantly improve over the baseline of a majority classifier.`） |
| **基線 (b)** | **T0 のみ** |
| **提案** | **T0 + presence** |

### 4.5 主指標と地平

- **主指標**: LOSO 平均の **時間依存 Brier score**
- **地平**: **主 H = 3 分 / 副 H = 10 分**（★ [P121] の `short 15–180s` / `mid 3–10min` / `long >10min`
  の境界に接地。★ **GSE の外で決まった値**である）
- **副指標**: `CIF(H)` の較正 / 時間依存 AUC / 生存曲線（全帯域）

> ★★★ **第 2 版の明確化（2026-08-19・実データ未参照）— 先読みの排除**
>
> ⚠️ `presence_state(t)` は**時変**である。ギャップ開始時点で `CIF(H)` を予測しようとすると
> **将来の presence を知っている必要があり、情報の先読みになる。**
>
> → ★ **「時間依存 Brier score」を person-period（10 秒ビン）ごとのハザード予測の Brier と定義する。**
> 各ビンで使うのは**そのビンの開始時刻までに観測済みの情報だけ**なので、
> **先読みが構造的に起こらない**。地平 H は「**評価に含めるビンを `gap_time < H` に限る**」という意味で使う。
> ★ これは `§8.1` が名指しした「時間依存 Brier score」の素直な読みであり、
> 同節の「⚠️ 単一の二値 C-index を主指標にしない」にも従う。
>
> ★ `CIF(H)` は **30 秒ランドマーク**（presence を 30 秒時点の値で固定）で別途出し、**較正にのみ**使う。
>
> ★ **リスク集合は 30 秒から始める（遅延エントリ）。** コホートが「30 秒生き延びたギャップ」なので、
> 0 秒から数えると条件付けを二重に効かせてしまう。

### 4.6 ⚠️★★★ 打ち切りは上下界で扱う

`personalization-and-online-learning.md §3.4` は「**独立打ち切りの仮定を捨てる**」と改訂しており、
`§8.2` G2 は上下界で判定する様式を定めている。→ **同じ様式を借りる。**

| 界 | セッション終了で切れたギャップの扱い |
|---|---|
| **下界** | すべて**独立打ち切り** |
| **上界** | すべて**再開しなかった**（競合イベント） |

→ ★★★ **上下界が同じ符号を与えるときだけ勝ち幅を主張する。**

### 4.7 ⚠️★★★ 測定器が 120 秒で介入することへの対処

`src-tauri/src/lib.rs:2914`:
`if health == Down && !rehook_done_this_episode { rehook = request_reinstall(); }`

⚠️ **120 秒でフックが再設置される。** フックが本当に死んでいた場合、再設置で打鍵記録が**復活**するため、
「ギャップが終わった」が**利用者の再開ではなく装置の復旧**でありうる。
⚠️★ **主 H = 3 分は 120 秒より後なので直撃する。**

★ 実在する両側の証拠:
- 誤検知側: `.steering/20260809-g1-hook-liveness-detection/measurements.md §3` —
  63 分の vibe coding で starvation ≥30 秒が **8 回・合計 504 秒 = セッションの 13.3%**、
  **1 回が 120 秒に到達**（`dropped` は全行 0）
- 本物側: 同 `validate_blocks.py:526` の注記 — **P010 block07 は誤検知ではなかった**
  （3 分 17 秒ぶん打鍵が 1 件も記録されず）

→ ★ **ギャップを除外しない**（除外すると一番知りたい長ギャップが系統的に消える）。代わりに:

| 解析 | 内容 |
|---|---|
| **主** | 全ギャップ。`Down` を共変量に含む。★ **`rehook:true` の出現数を必ず報告する** |
| **副（必須）** | ⚠️★★★ **120 秒で行政的打ち切り**。★ **装置が一度も介入していない区間だけ**で presence の効果を見る。★ **第 2 版の明確化: この副解析の評価地平は `H_sens = 120 秒`**（打ち切った先は観測が無いので 3 分では評価できない） |

★★★ **副解析で効果が出れば、それは再設置の産物ではありえない**（時間的に先行するため）。
⚠️ **主で出て副で消えたら「装置の介入と分離できない」を結論にする。**

## 9. ⚠️ 事前に認めている限界（★ 隠さない）

1. ⚠️★★★ **`presence` は「入力デバイスに触れた」ことしか意味しない。**
   ★ 「作業していた」ことの証明ではない（マウスを弄びながら考えていた／別アプリを見ていた／
   ポインタが震えただけ、を区別しない）。
2. ⚠️★★★ **30 秒未満の在席×非打鍵は観測できない**（`lib.rs:2923` の間引き）。
   → **micro 帯（2–15 秒 = [P121] が「局所思考」と位置づけた帯）について本実験は何も言わない。**
3. ⚠️ **「打鍵再開」は「回復」ではない。** 別作業を始めただけの可能性を排除できない。
4. ⚠️ **n = 5・全セッション `task_kind = argumentative`（分散ゼロ）**
   （`experiments/20260802-task-scope-detector/data.md:14`）。
   → ★ **「個人差か実タスク差か」は本データでは原理的に切り分けられない。**
5. ⚠️ **`starved_ms` は `GetLastInputInfo`（Windows）/ macOS の最終入力時刻に依存する。**
   ★ `liveness.rs:309-325` がテスト名 `mouse_only_work_is_a_known_false_positive` で
   「マウスだけ動かしている人も Down になる」を**仕様として固定**している。
   → ⚠️ **本実験はその「誤検知」を信号として使い直している。**★ 用途の転用であることを明示する。
6. ⚠️ **本実験は探索トラックであり、確証主張に使わない**（適格性ゲートを適用していない）。
