## 3. ★★★ B1 が答えた問い —— 「解決」と「放棄」はどれだけ混ざるか

★ ADR-023 §D7 の「計器の問題 2」(**content-free では解決と放棄を区別できない**) を
実データで測るのが B1 の仕事だった。★ 答えは **2 つの経路があり、大きさが違う**:

### 経路 1: 分母 (ADR-023 **D8** が指摘したもの) —— **−3.5pt**

★ R₀ の分母に「fix に至らなかった 16 件」が混ざっている。
⚠️ しかしその効果は **3.5pt** しかない。

### 経路 2: 分子 (⚠️★★★ **D8 は指摘していない**) —— **+11.2pt**

★ R₀ の **分子** は「参照 0 回」だけを要求し、**解決を要求しない**。
→ ★ **70 件のうち 10 件 (14.3%) は「参照せずに、直さずに終わった」**。
★ 分子に成果を要求する R₀′ にすると **0.787 → 0.674** へ **11.2pt** 落ちる。

> ★★★ **GSE の `self_recovery_without_paste` は R₀′ の形である** ——
> 分子が「回復した **かつ** ペーストが挟まらなかった」を要求し、分母は全エピソード
> (`metrics.rs:390`)。★ したがって GSE 側で効いているのは **経路 2 のほう**である。

### ⚠️★★★ 方向が直観と逆である (★ 本実験で最も重要な発見)

| | 外部資源を参照した | 参照しなかった | 計 |
|---|---|---|---|
| **fix に至った** | 13 (17.8%) | 60 | **73** |
| **fix に至らなかった** | **6 (37.5%)** | 10 | **16** |

★★★ **放棄・未解決の episode ほど、外部資源を *より多く* 参照している** (37.5% vs 17.8%)。
★ episode 長も **中央値 511.5s (未 fix) vs 165s (fix)** で、⚠️ **未解決の episode は長く、外部を見る**。

→ ★★★ **含意**: 「`paste_after_stuck_rate` が下がったのは実は放棄では」という
ADR-023 D5 / §8 指摘 D の懸念に対し、⚠️ **少なくともこのデータでは放棄は受領を *増やす* 側に効く。**
★ つまり **放棄の混入は `*_without_receipt` 系の指標を *押し下げる* 方向**であって、
⚠️ **「放棄が自力解決に化けて見える」向きではない。**

⚠️★★★ **ただしこれを GSE の反証や擁護として使ってはならない** (→ §4)。
★ 言えるのは **「混入の向きは自明ではない。事前に決め打ちしない」**までである。

### ★ ついでに測れたこと: 中断をまたいだ episode は **9/89**

★ 20 の DF4/DF7 対は **9 個の episode** に集中していた。
★ block 数の分布は **{1: 80, 2: 4, 3: 1, 4: 2, 5: 2}** ——
★ **最大 5 block ＝ 1 つの episode が最大 4 回中断されている**（★ 中断回数の合計 = 20）。
→ ⚠️★★★ **M1 の観測単位「中断 → 再開」は、debugging episode の単位では *まれ* である** (約 10%)。
★ GSE が見るポーズ (≥2s) / 沈黙区間 / 離席候補 (≥180s) は **[P321] の「中断」よりずっと細かい**ので、
⚠️ **[P321] の 9/89 を GSE の中断頻度の見積もりに使わない** (★ 粒度が違う)。

## 4. ⚠️★★★ 主張してはいけないこと (★ 先に固定する)

1. ⚠️★★★ **R₀ / R₁ / R₀′ を GSE の期待値として使わない。**
   - ★ 対象が **デバッグ** (GSE は writing / coding の開放的作業)
   - ★ **人手ビデオコーディング** (GSE は content-free 自動観測)。⚠️★★★ **かつ 89 episode 全体は *第一著者 1 名* が付けたラベルである** —— ★ 一次逐語 *"the **first author** then coded the entire dataset"*。★ 2 名で突き合わせたのは **較正用の 20 episode / 166 activity だけ**（Chen's Kappa 75% / 84%）。→ ⚠️ **R₀ / R₁ は「1 人の判断」に乗っている。**
   - ★ **N = 11 名 / 15 セッション**、⚠️ **セッションは開発者に対して独立でない**
     (★ 論文自身が「2 時間未満なら同じ開発者の別セッションを足した」と書いている)
2. ⚠️★★★ **「GSE の値が R₀ より高い / 低い」を良し悪しに読まない。** ★ 測定手続きが違う。
   - ⚠️ 特に **受領の検出手段が違う**: [P321] は **人がビデオで見た「外部資源の参照」**、
     GSE は **クリップボード経由の paste のみ** (ADR-023 **D6** / 計器の問題 4)。
     ★ [P321] の `Seeking information` には **検索・ドキュメント閲覧・チャットでの質問**が入るが、
     ⚠️ **GSE ではそのどれも `receipt` を立てない。**→ ★ **GSE 側は構造的に「受領なし」に倒れる。**
3. ⚠️★★★ **Wilson 95% 区間を額面どおりに読まない。** ★ 個体内クラスタを無視した素の区間であり、
   **実際の不確実性より狭い**。⚠️ 実測で **セッション別 R₀ は 0.00–1.00** に散っている
   (中央値 0.78)。→ ★ 区間は **「オーダーの目安」**として読む。
4. ⚠️ **[P321] の「14%」を全 episode の未 fix 率として引かない** (→ §7 の訂正 1)。
5. ★ **言えるのはここまで**: 「この型の指標が実データでどのオーダー (**0.7–0.8 台**) を取り、
   **分子に成果を要求するかどうかで 11pt 動き**、**放棄の混入の向きは直観と逆でありうる**」。

## 7. ⚠️★★★ 一次で確認して分かった「引き継ぎメモ (三次資料) の誤り」

★ `verify-before-claiming` ルール 1 に従い、引き継ぎメモを根拠にせず一次に降りた結果:

1. ⚠️★★★ **「A = fix に至らなかった episode の割合。論文は **14%** と報告している」は誤り。**
   ★ 論文の **14% は「自ら埋め込んだ defect」の部分集団 (79 件) の値**である。
   ★ 論文はもう 1 つ **「報告された defect は *半分* (10 件中 5 件) が fix に至らない」**とも書いており、
   ★ **全 89 episode を通した未 fix 率は 16/89 = 18.0%** である。
   → ★ 検算は **部分集団ごとに**行った (★ そうしないと通らなかった)。
2. ⚠️★★★ **「データの所在 = figshare」は *半分* しか正しくない。**
   ★ 論文が案内する主たる配布元は **`observe-dev.online`** (脚注 5 / 脚注 7 ＋ zip 内の
   `Observe-devOnlineDataSetLink.txt`) だが、⚠️ **このドメインは消滅している**
   (NXDOMAIN。★ ローカル resolver と Cloudflare DoH の両方で確認)。
   → ★ **figshare の replication package が唯一の生存経路**であり、
   ⚠️ **それも private link 1 本に依存している** (★ 公開 API にも figshare 検索にも出ない)。
   → ★ だから **`raw/` に現物を保持し、SHA-256 を来歴として刻んだ**。
3. ⚠️ **「R₀ は公開データから計算可能だが論文は未報告」(`docs/references.md` [P321] の gloss) は正しい。**
   ★ ただし ⚠️ **`rowData.json` に「参照 0 回」という列があるわけではない** ——
