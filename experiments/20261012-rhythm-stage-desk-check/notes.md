### 項目 2（打鍵の有無・記述）

秒ごとの識別の AUC（秒 `k` の打鍵の有無を、秒 `k+1` の始まりの `a`・`r` とその直前 1 s の差から当てる）:

| 写像 | hold sec / sub | decay sec / sub | ground sec / sub |
|---|---|---|---|
| raw | 0.543 / 1.000 | 0.940 / 1.000 | 0.947 / 1.000 |
| smooth | 0.560 / 0.827 | 0.933 / 0.983 | 0.934 / 0.992 |
| rank | 0.537 / 0.999 | 0.847 / 0.999 | 0.924 / 0.999 |
| jitter | 0.535 / 0.998 | 0.864 / 0.998 | 0.928 / 0.997 |

- `res=sec` の `hold` は、1 秒ごとの有無をほとんど写さない（0.54〜0.56）。F 系列の 30 秒の窓の値は止まっても据え置かれ、`hold` はそれをさらに据え置く。`decay`・`ground` は止まりの判定（2 s）を通して有無を写す（0.85〜0.95）。
- `res=sub` は、`τ_s` 0.5 s の `u_a` が打鍵ごとに跳ねて減るので、止まり方によらず秒ごとの有無をほぼ完全に写す（`smooth-hold-sub` だけ 0.83）。
- 止まりの遅れ（`a`・中央値・`jitter` を除く 18 本）: `ground-sec` は 2.5 s（止まりの判定 2 s ＋秒の粒度）。`raw`・`rank` の `sub` は 0.45〜0.61 s（判定の前に `u_a` 自身が落ちる・推論）。`smooth` の `sub` は遅く、`smooth-ground-sub` 2.05 s・`smooth-decay-sub` 4.76 s で、`smooth-hold-sub` は 98% が「変わらない」。`decay-sec` は `raw`・`smooth` で約 6 s（時定数 60 s の減衰で、止まりから 9〜10 s の変化の半分に届くまで）だが、`rank-decay-sec` は 0.73 s（41% が「変わらない」）。`raw-hold-sec` の止まりは 93% が「変わらない」（`smooth-hold-sec` は 100%・`rank-hold-sec` は 52%）。
- 再開の遅れ（`a`・中央値・`jitter` を除く）: `raw`・`rank` の `sub` で 0.18〜0.24 s。`smooth-decay-sub`・`smooth-ground-sub` は 5.1 s・3.4 s。`sec` は 0.5〜5.2 s で、`raw-ground-sec` 4.5 s・`raw-decay-sec` 5.2 s・`smooth-hold-sec` 4.2 s・`rank-ground-sec` 5.1 s（97% が「変わらない」）と、`smooth-decay-sec`・`smooth-ground-sec` の 0.52 s に分かれる。`raw` の遅さは 30 秒の窓の打鍵数が再開の後にゆっくり戻るためかもしれないが、同じ入力の `smooth-*-sec` が 0.52 s で戻ることと合わず、理由は確かめていない。
- `jitter` の 6 本の遅れの中央値と割合は判断 18 により読まない（揺らぎと区別できない）。秒ごとの識別の AUC は読む。

### 項目 3（速さ・記述）

- 窓の打鍵の数と窓の `a` の平均の Spearman は、`res=sub` で 0.56〜0.99（`raw`・`rank`・`jitter` は 0.94〜0.99、`smooth` は 0.56〜0.81）、`res=sec` で 0.34〜0.87（`smooth` が低い）。窓の打鍵の数を描画の特徴 20 から当てる R² は、`jitter-hold-sec` の 0.34、`rank-hold-sec` の 0.65、`rank-decay-sec` の 0.75 を除いて 0.87〜1.00。振幅は「どれだけ打ったか」をよく写す。
- 窓の打鍵の間隔の中央値（2 s 未満）と `r` の平均の Spearman は、`jitter` を除く `hold` で −0.21〜−0.38（間隔が短いほどテンポが高い・向きは意図どおり）、`rank` を除く `ground` では −0.02〜+0.05 でほぼ 0（`rank-ground` は −0.21・−0.23）。`r` は打鍵の数と `ground` で 0.65〜0.88、`decay` で 0.26〜0.74 の相関を持つが、これは止まると地へ戻ることによる有無の写りで、速さではない。
- **判断 20 の読み方**: `res=sec` のテンポは F1（離鍵から次の押下までの中央値・合成の列では打っている間ほぼ 46〜80 ms）を 80〜600 ms の尺度で写すので、打っている間はほぼ常に 1 で、速さをほぼ運ばない。上の `hold-sec` の −0.38 は主に窓の中の打っている時間と止まっている時間の混ぜ方から来ていると読む（推論・確かめていない）。`res=sub` は押下どうしの間隔（約 150〜230 ms）を使うので中ほどの値になる。2 方式のテンポの違いには、解像度のほかにこの尺度の違いが入る（design §0 の項目 6 の注）。world v4 では FLOW と STRUGGLE の打鍵の時刻の作り方が同じなので、テンポが速さを運んでも停滞は運ばない。

### 項目 4（止まっている間・記述）

窓の終わりの「最後の打鍵からの時間」を、窓の終わりの `a`・`r` と「最後に値が変わってからの時間」から当てる R²:

| 写像 | hold sec / sub | decay sec / sub | ground sec / sub |
|---|---|---|---|
| raw | 0.395 / 0.403 | 0.683 / 0.674 | 0.399 / 0.399 |
| smooth | 0.397 / 0.398 | 0.683 / 0.686 | 0.399 / 0.399 |
| rank | 0.386 / 0.388 | 0.664 / 0.664 | 0.397 / 0.398 |
| jitter | 0.003 / 0.175 | 0.442 / 0.380 | 0.272 / 0.247 |

- `decay` は止まっていた時間を値の大きさで写す（0.66〜0.69）。`hold`・`ground` の約 0.40 は「最後に値が変わってからの時間」（止まると値が動かなくなる）から来ると読む（推論・その量だけの R² は出していない）。`jitter` は値が常に動くのでその量が使えず、`hold` で 0.003 まで下がる。

### 項目 6（2 方式・記述）

- 双子（秒ごとの打鍵の数を保ち、秒の中の時刻を引き直した列）と元を当てる AUC は、24 本すべてで 0.96〜1.00。`res=sec` も 0.96〜1.00 で、design §3.4 の注（M6）どおり、双子では F 系列が揃わず、`res=sec` も双子を見分ける。`res=sec` の `u_a` は 30 秒の窓の打鍵の数なので双子でもほぼ同じで、差は `u_r`（`f1`）から来ると読む: 元の列では `f1` が 46〜80 ms で `u_r` が 1 に張り付き（判断 20）、秒の中の時刻を一様に引き直すとバーストの中の間隔が崩れて `f1` が 80 ms を越え、`u_r` が下がる（推論・`a` だけ・`r` だけの AUC は出していない）。
- 読める範囲（同じ写像と止まり方の `sub` − `sec`）: 差は −0.027〜+0.039（例 `rank-ground` 0.961 → 1.000、`smooth-ground` 0.998 → 0.971 は逆向き）。どちらの方式も天井に近く、この記述で秒未満の情報の量を比べることはできない。
- 項目 1 では、L300 の判定は 2 方式で同じだった（緑の 14 本は sec・sub の対で 7 組、判定不能の 10 本も 5 組の対）。上乗せの上限の最大も対どうしで ±0.004 以内。読めるのは、緑の 7 組について `res=sub` が停滞を運ぶことは見つからなかった、までである。v4 は FLOW と STRUGGLE の打鍵の時刻を同じに作っているので、秒未満の時刻が停滞を運ぶ余地は作りの上で無く、これは予想どおりの結果である。判定不能の 5 組については何も言えない。2 方式が同等であることも確かめていない（各方式の区間は、方式どうしの差の区間ではない）。打鍵の時刻に停滞が出る世界での秒未満の寄与は、この検査では未検証。
- 項目 2 では方式の違いがはっきり出る（秒ごとの識別・止まりと再開の遅れ）。`res=sub` は有無を 1 打鍵の単位で写し、`res=sec` は止まり方しだいで 2.5 s 以上遅れるか、`hold` ではほぼ写さない。

## 読み方（design §3.3 の固定した文）

- **緑**（L300 の 14 本・L60 の 16 本）: この合成の世界と、固定した 4 通りの攻撃者が見る窓ごとの要約 20 では、描画のパラメータが A_speed に入れた有無と速さの要約を超えて停滞を 0.03 以上識別することは見つからなかった。人が描画を状態計として読むかについては何も言わない。描いた画（列そのもの）についても何も言わない（判断 8）。
- **v4 の宣言**（結果の前に固定した文）: world v4 では FLOW と STRUGGLE の打鍵の時刻は同じ作り方で、停滞は訂正の率と区間の構造にだけある。候補は訂正を読まないので、候補の上乗せが残りうるのは区間の構造を A_speed の要約より細かく運んだ場合だけで、項目 1 は作りの上で緑に寄りうる。**v4 の緑は「打鍵の時刻に停滞が出ない世界で、写像の処理が区間の構造の手がかりを A_speed の要約を超えて運ばなかった」までで、「停滞が打鍵の時刻に出るときにステージがそれを写さない」ことは言わない**（v2 では速さそのものが停滞を写した・design §3.0 の下見 0 で AUC(A_speed) − AUC(A) が L300 で +0.18〜+0.19）。
- 本番の値はこの宣言の見込みどおりだった: 候補の上乗せは 24 本とも点推定の最大 +0.006 以下で、PC-corr（訂正を写す）だけが +0.27 を運んだ。v4 の作りからの推論（本番では v4 しか回していない・v2 は下見 0 の基準のモデルの値だけ）として、このステージの写像が停滞を写すかどうかは、主に「打鍵の時刻に停滞が出るかどうか」と「訂正を写すかどうか」に依ると見込まれる。前者は合成では決められず、後者は判断 5 で写さないと決めている。
- **判定不能**（L300 の 10 本・L60 の 8 本・L1800 の 24 本）: その候補の経路で検査器が 0.03〜0.08 の漏れを拾えることを示せなかった。`raw` は PC-stall が弱く、`smooth-hold`・`smooth-decay` は強すぎた。上限が小さいことを「漏れが無い」の根拠に使わない。
- 赤が 0 件であることについて: 判定の赤の分岐（赤・検出／赤・未確認／止まりの経路）は、手で作った値の単体検査で確かめてある（`selftest.py` の `judge:` の項）。自己検査の変異（写像に `seg` を混ぜる・本番の実行のログで L300 の点推定の最大 +0.272）は、攻撃者が上乗せを拾うことを示す。ただし、変異を候補として最後の判定まで通して赤になることは確かめていない（その候補の PC-stall・土台・帰無の条件を通るかは見ていない・Codex の指摘）。「この経路で赤を出せる」ことは、端から端までは示していない。土台の上限の最大は 3 ラベルで約 +0.010（L1800 の `smooth-decay-sub` が +0.0101）で、下限が 0.03 を超えた土台は無い。
- **判断 18**: `jitter` の 6 本の項目 2 の遅れは読まない（揺らぎと区別できない）。項目 1 の判定と、ほかの記述は読む。
- **判断 20**: `res=sec` のテンポは速さをほぼ運ばない（尺度の写しによる）。項目 3・6 で `res=sec` と `res=sub` のテンポを比べるときは、解像度の違いと尺度の違いを分けられない。

## 親タスクへの材料（判断 3・5 の見直し）

- 判断 3（秒未満の時刻を描画に使うか）: world v4 の項目 1 では、緑の 7 組について `res=sub` が停滞を運ぶことは見つからなかった。ただし v4 は打鍵の時刻に停滞を置いていないので、作りの上で予想どおりで、打鍵の時刻に停滞が出る世界での秒未満の寄与は未検証である。判定不能の 5 組については何も言えない。一方、項目 2 では `res=sub` が打鍵の有無を 1 打鍵の単位で写す（秒ごとの識別 0.83〜1.00。`raw`・`rank` の `sub` で止まりの遅れ 0.45〜0.61 s・再開 0.18〜0.24 s。`smooth` の `sub` は遅い）。秒未満の時刻を使うかの判断は、この検査の範囲では停滞の漏れでは決まらず、「有無をどれだけ即座に見せるか」と `data-privacy` の側の材料が主になる（研究者・design §3.5）。
- 判断 5（入力は有無と速さだけ・訂正を読まない）: 訂正の率を写した PC-corr が +0.27 を運んだ。v4 の停滞は訂正にだけあるので、この値は作りの帰結で、「訂正を写すと停滞が写る」ことの量の目安にとどまる。「訂正を読まない」ことが停滞を写さないことにつながったのも、v4 で停滞を訂正にだけ置いた作りの上でそうなるもので、判断 5 の効果の証拠としては読まない。
- 判定不能の 10 本（L300）のうち `raw` の 6 本は、下見 1 の選び方で固定した λ 0.05 では判定できなかった。下見 1 では λ 0.10 で `raw` の点推定の最大が +0.064〜+0.073、下限の最大が +0.049〜+0.059 で帯に入っており、λ 0.05 が選ばれたのは「目標 0.05 に最も近い」がほぼ同点だったため（|0.037 − 0.05| = 0.013 と |0.064 − 0.05| = 0.014）である。λ 0.10 なら判定できた見込みがある（推論・本番では未検査）。λ の選び方を直した再実行で確かめる（研究者の判断 21）。

## 逸脱・気づいたこと

- 本番での逸脱は無い（design §8 の行のまま）。
- **下見と本番の PC-stall**（L300・選んだ λ。値は点推定の最大 / 下限の最大。λ = 0 は下見の `@0.00` と本番の `PC0-<候補>` の点推定の最大）:
