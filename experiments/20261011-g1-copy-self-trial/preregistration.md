2026-10-11 に、照らし合わせ・照合・加工を 1 回も計算する前に書き、コミットした。値は `config.json` と `SEED`、作業記録は `.steering/20261011-g1-copy-self-trial/`（判断 1 が研究者の選択、判断 2 が Claude の細部）。

## 固定の前に見たもの（開示）

固定の前に、Claude は次を計算して見た。結論に使う量（区間の長さの並び・揃え・正答率）は 1 つも計算していない。

- 20 本の記録（と P010 block06 の重複 1 本）の、種類ごとの押下の数・最初と最後の押下の間の秒数・1 行目の `meta`（アプリの版）と `session_meta`。
- 書き写しの 4 本（P009・P010 の block01・block10）の、最初の 400 押下の種類の並び（英字・BackSpace・Enter・Space・other の記号の列）。冒頭が 4 本で似ていることと、`other` が語の途中（「メートル」の「ー」）と Enter の間（句読点）に出ることを見た。
- 原文の区切りの文字の数（、23・。20・ー 4・・1 の計 48）と行ごとの累積、SudachiPy での原文の分かち書きと読み（「A」「B」は独立の語になり、無効な区間は無い）。
- 書き写しの 4 本の `other` の押下の数（23・26・23・29）。原文の 48 区切りのうち 10〜13 行目あたりまで打ったと見積もった。

## 問い

研究者本人が G1 で打った書き写しのブロック（原文 `copy.md`・5 分・4 本）の記録で、

1. 原文から合成した区間の長さの並びは、記録のカテゴリ列から数えた並びとどれだけずれるか。ずれの原因（綴りの揺れ・BackSpace・変換・区切りの挿入と欠落・止まった位置）はどう分かれるか。
2. 記録の連続した k 区間から、原文を候補 N 本の中で当てる正答率は、偶然の水準 1/N と比べてどうか。
3. 前の試作の L の加工で、正答率はどこまで偶然の水準に近づくか。

## 固定した値と手順

### 記録の区間（`scripts/records.py`）

| 項目 | 値 |
|---|---|
| 書き写しのブロック | P009・P010 の block01・block10（G1 の設計で最初と最後・`consent.md` §2）。P010 block06 の重複のファイルは使わない（SHA-256 が block06 と同じ） |
| 読む行 | `type` が `key` で `press` が true の行を、ファイルの順に |
| 数え方 | 英字・数字 +1、BackSpace −1。`other` の押下で区間を閉じる。Enter・Space・矢印・修飾・機能・Esc・Delete・Tab は数えず、区切りにもしない |
| 止まった位置 | 最後の `other` の後の区間は使わない（5 分で途中まで打った区間）。最初の区間は使う |
| 掃除した記録（L_clean） | `other` の押下のうち、次の押下（Enter・Space などを飛ばし、英字・数字・BackSpace・`other` の中で次のもの）が BackSpace のものは区切りにせず、その BackSpace も数えない（打った句読点や「ー」を消した組）。左から順に当てる |

G1 のアプリの版（P009 は v0.1.29、P010 はそれより古い版）は、句読点と記号のキーを `Punctuation` と `SentencePunctuation` に分けず、すべて `other` にする（`git show v0.1.29:src-tauri/src/analysis/anonymize.rs` の `from_vk`）。だから「、」「。」「ー」「・」は記録で区別できない。

### 揃え（`scripts/align.py`）

記録の区間 x と原文の区間 y を、動的計画法で先頭から揃える。1 つの組は「記録 p 区間 ↔ 原文 q 区間」（p, q ∈ {1, 2, 3}、どちらかが 1）、費用は |x の和 − y の和| ＋ λ ×（p − 1 ＋ q − 1）、λ = 8。記録の最後まで使い、原文は途中で終わってよい。同じ費用の経路は 1 対 1 → 記録 2:1 → 1:2 → 3:1 → 1:3 の順で選ぶ。

揃えは正解の窓を決めるためと、照らし合わせのためだけに使う。攻撃者は揃えを知らない。

### 照合（`scripts/matching.py`）

| 項目 | 値 |
|---|---|
| 記録（窓） | 1 ブロックの記録の連続した k 区間（すべての始まり・重なりあり） |
| 正解 | 窓の先頭の区間が揃った原文の区間（組の最初の原文の区間）から k 区間。原文の終わりを越える窓は使わない |
| k・N | k = 1, 2, 3, 5, 8, 12, 20・N = 10, 100, 1000 |
| おとり | N − 1 本。1,500 作品のうち長さ k の有効な窓を持つ作品から重複なしに一様に作品を選び、作品の中で有効な窓を一様に 1 つ選ぶ（前の実測と同じ）。1 つの窓に 50 回抽選する |
| 攻撃者 L | 区間ごとの数と、候補の標準の打鍵数の差の絶対値の和が最小の候補。同点が m 個で正解を含めば 1/m |
| 加工 | なし・floor(値/w)（w = 2, 4, 8, 16）・値を捨てる・m 区間ずつ足す（m = 2, 5）・合計だけ・並べ替え。記録と候補の両方に同じ加工をかける（前の試作と同じ定義） |
| L_clean | 掃除した記録で、加工なし |
| 乱数 | `SEED` = 20261011。用途・記録の種類・ブロック・k・N・始まり・抽選の番号を `:` でつないだ文字列の SHA-256 から作る |

### 集計と区間

- 窓の正答率は 50 回の平均、ブロックの正答率は窓の平均、全体は 4 ブロックの平均（人ごとの 2 ブロックの平均も出す）。
- ブロックは 4 本で、窓は重なって独立ではない。信頼区間は出さず、ブロックごとの値と最小〜最大を並べる（ADR-039 D6 の論点 4 の推奨: 単位はブロック）。抽選の揺れはモンテカルロの標準誤差で示す。

### 診断

- 記録を使わない予測: 窓の合計が、k × 1,500 作品の有効な区間の数の中央値に最も近い候補（同点は 1/m）。
- 陰性対照: 書き写し以外の 16 ブロック（block02〜09）の記録の窓に、原文の同じ番号の窓（原文の終わりを越えるなら最後の窓）を正解として同じ照合をする（L_none）。正解は常に同じ原文で、おとりと同じ引き方から来ていないので、偶然の水準の前提を確かめる。1/N に近いことを期待する。

### 照らし合わせ（`scripts/crosscheck.py`）

ブロックごとに、区間の数・揃えの組の種類の数・最後に揃った原文の位置・1 対 1 の組の差（記録 − 合成）の分布を出す。1 対 1 の組は、区間の中の BackSpace・数字の有無で「BackSpace も数字も無い」「BackSpace あり」「数字あり」に分ける。BackSpace も数字も無い組の差は、綴りの揺れと読みの違いを表すと読む（どちらかは記録から分けられない）。区間あたりの Enter と Space の数も出す。

探索（結論の主な表には使わない）: BackSpace も数字も無い 1 対 1 の組で、`romaji_table.py` の 5 つの癖（ん = n・si・ti・tu・jya）の 32 通りの組のうち差の絶対値の和が最小の組と、そのときの一致の割合。

## 記録の扱い

- 復号した NDJSON・記録から作った区間の並び・揃えの組は repo の外（`run.sh` の `G1_RECORDS`・`G1_WORK`）に置き、作業が終わったら消す。repo に入れるのは集計（ブロックごとの正答率・差の分布の要約）だけ。ファイル名とセッションの日時は書かない。
- 記録・区間の並びは外部の LLM（Codex を含む）に送らない。Codex のレビューはコードと集計の結果だけ。

## 結論に使わないこと

- 照合の危険の上限・安全の証明とは書かない（言語モデル・時刻・本人の過去の文章を使わない攻撃・1 人の 4 ブロック・同じ原文）。
- 合格・不合格の判定はしない。人による違いを言わない。
