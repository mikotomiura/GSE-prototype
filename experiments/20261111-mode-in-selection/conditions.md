## 問い

## D2 候補に最頻値を足す（研究者の選択の「候補」）

- τ 他人（構造ごと）: 候補を「∞・最頻値・10^6・3×10^5・…・0」の順に並べる（mode の変異 m22 と同じ位置）。同点は先の候補（∞ が最優先、次に最頻値）。値は mode と同じ「本人(τ) − 同じ構造の共通」で、最頻値の値は「最頻値 − 同じ構造の共通」。
- 2 段（他人）: (構造, τ) の候補の τ に最頻値を足す。並べは τ の順（∞ → 最頻値 → 10^6 → … → 0）、同じ τ の中では自由な母数の少ない構造が先（tau-extend の `joint_cands` に最頻値を ∞ の次に挟む）。値は「本人 − r1」で、最頻値の値は「最頻値 − r1」。
- 最頻値が −∞ の書き手の値は −∞ のまま中央値に入る（mode の判断 4・9）。選びは w を除く書き手の中央値（tau-extend と同じ・w の値は入らない）。
- τ 本人 CV・2 段（構造は他人・τ は本人 CV）・K 本人 CV は最頻値の折り目の量が無いので変えない（mode の値のまま・候補は足さない）。

## D3 相手（研究者の選択の「列」）

- 主の表の行（τ 他人の各構造・2 段（他人））に、相手の列を 3 つ並べる: r1（本人の 1 次マルコフ連鎖）・同じ構造の共通（`pool_same`）・同じ構造の最頻値（`mode_same`）。書き手ごとの差の中央値・区間（mode と同じ復元抽出）・良い側の割合・n・±∞ の人数。全記号を主に、押下のある記号を並べる。
- 選ばれた τ が最頻値の書き手は、本人 = 最頻値なので 本人 − 最頻値 = 0（mode の `tau_mode` × `mode_same` と同じ扱い）。選ばれた τ が ∞ の書き手は 本人 − 共通 = 0。
- 比べのために、候補に最頻値を入れない行（mode の summary の値）を同じ表に並べる（「前」の列）。

## D4 量と表

- パネルと k は mode の主のパネル（CoAuthor P15・P30・CS1 C5）と、その k すべて。主のセルは前と同じ（P15 の k = 1〜15・C5）。
- セルごとに、選ばれた (構造, τ) の人数（τ の領域: ∞・最頻値・格子の上の有限の端 10^6・格子の中・下の端 0）。
- 表（`report.py` が summary から作る・手で書き換えない）: 2 段（他人）と τ 他人（hmm3・ar1〜ar3）の、前と後の「本人 − 共通」「本人 − 最頻値」「本人 − r1」。

## D5 読みの形（結果より前に決める・閾値を置かない）

見る所: 2 段（他人）の後の行・CoAuthor P15・k = 1〜15。

- 形 M（最頻値が選ばれる）: 半分を超える書き手に最頻値が選ばれた k が、k の半分を超える →「最頻値を候補に置くと、手順は多くの書き手に最頻値そのものを選ぶ。その書き手の 本人 − 最頻値 は作りの上で 0 で、本人 − 共通 は最頻値と共通の差であり、本人の上積みではない」。
- 形 S（本人が残る）: 有限の τ が選ばれた書き手が半分を超え、本人 − 最頻値の中央値が正で良い側の割合が 0.5 を超える k が、k の半分を超える →「最頻値を候補と相手に置いても、本人の記録の寄与（中央値 値）が残る」。
- 形 N（本人が残らない）: 有限の τ が選ばれた書き手が半分を超え、本人 − 最頻値の中央値が 0 以下か良い側の割合が 0.5 以下の k が、k の半分を超える →「最頻値に対しては、選ばれた本人の当てはめは上回らない」。
- どれにも当たらない: k ごとに値を並べ、形を書かない。
- ∞ が半分を超える書き手に選ばれた k は、本人 − 共通が作りの上で 0 の k として数え、形の数に入れない（CS1 の前の値と同じ扱い）。
- CoAuthor P30 と CS1 C5 は同じ形で読み、値を並べる。主の文は P15 に限る。

外枠への持ち込み:

- Table 2 の主の行を「後」の値に替え、「本人 − 最頻値」の列を足す。前の値は S9 か S8 に移す。
- 形 M か形 N: Take-home の残り（at most about 1e-3）を「最頻値を比べの相手と候補に置くと、本人の上積みは（0 か負の値）」へ書き換える候補にする（書き換えは計算 1・2 の結果と合わせて研究者に問う）。
- 形 S: 「最頻値を置いても、本人の寄与（値）が残る」と書き、計算 1 の分解の読みと並べる。
- 推奨（Take-home の 2 文目）に「最頻値を比べの相手と候補に置く」を足すかは、形に依らず研究者に問う。

## V1 門（実データの前・合成だけ・Mac と HP Z2 の両方で通す）

| 門 | 通る条件 |
|---|---|
| P-HASH | D1 の SHA-256 がすべて一致（読み込みの時点で止める） |
| P-OLDSAME | 合成の書き手の値（mode の selftest の作り）で、最頻値を足さない並べで作った 2 段・τ 他人の選びが、mode の `summarize_em` の選びと一致する |
| P-MODECAND | 合成で、他の書き手の最頻値の値をとても良くすると、その書き手たち以外の w に最頻値が選ばれ、w 自身の最頻値の値を書き換えても w の選びは変わらない（乱数 200 回） |
| P-ZEROCOL | 最頻値が選ばれた書き手の 本人 − 最頻値 がちょうど 0、∞ が選ばれた書き手の 本人 − 共通 がちょうど 0 |
| P-ORDER | 同点の作った例で、∞ が最頻値より、最頻値が 10^6 より先に選ばれる |
| P-NEGINF | 最頻値が −∞ の書き手を含む合成で、選びと集計に NaN が出ず、±∞ の人数が手で数えた値と一致する |

| 変異 | 赤になるべき門 |
|---|---|
| n1: 選びに w 自身の値を入れる | P-MODECAND |
| n2: 最頻値を ∞ より先に並べる | P-ORDER |
| n3: 最頻値が選ばれた書き手の 本人 − 最頻値 を最頻値 − 共通にする | P-ZEROCOL |
| n4: −∞ の書き手を選びの中央値から捨てる | P-NEGINF |
