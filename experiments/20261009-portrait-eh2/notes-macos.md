## 回す前に見つかったこと

- 最初の dry-run で、壁紙がもう存在しないファイルを指していた（`desktopImageURL` はそのパスを返し、ファイルは無い）。画面には何かが表示されていたので、WallpaperAgent は消えたファイルの代わりに、何らかの写しを表示していると思われる（確かめていない）。このままではスクリプトの戻し先が無いので、研究者が今あるファイルの静止画に替えた。元の見た目には戻していない（研究者が決める）。

## 判断 M1: 読み戻しを待つようにスクリプトを直した

**見つかったこと**（13:33 の quick と、その後の小さな診断。診断のスクリプトはリポジトリに入れていない）:

1. `setDesktopImageURL` はすぐ返る（数 ms）が、getter（`desktopImageURL(for:)`）が新しい画像を返すのは約 0.2 秒後だった。修正前のスクリプトは設定の直後に読み戻していたので、`readback_ok` は 0 になり、戻しも `false` と記録された。設定そのものは効いていた。
2. 何も設定していないのに、数秒後に getter が過去の値（その前に設定した仮の画像、さらに前の、もう無いファイル）を約 1 秒だけ返したことが 2 回あった。設定を短い間隔で続けた直後に起きた。WallpaperAgent が前の要求を遅れて再生しているように見えるが、仕組みは確かめていない。30 秒見守った後は安定していた。
3. 診断の途中で、戻しの呼び出しが `NSCocoaErrorDomain` の code 4（ファイルが無い）で失敗した。2 の間に getter から読んだ「元の画像」が、もう無いファイルだったためと考えている。オプションの組（`desktopImageOptions` の 3 キー）を渡し直すこと自体は、別に試して成功した。

**直したこと**（`macos/eh2_wallpaper.swift`）:

- `readbackLagMs`: 設定の後、getter が新しい画像を返すまで 20 ms ごとに読み、遅れを測る（5 秒を超えたら失敗）。`per_screen` の `readback_ok` はこれで数える。直後の読み戻しは `readback_immediate_ok` として別に残す。遅れは `readback_lag_ms_*` に記録する。
- 画面ごとに別々の画像を確かめるところ、手の確認の読み戻しも同じ関数にした（手の確認は 2 秒まで待つ）。
- `settled`: 戻した後、getter が元の画像を 5 秒続けて返すまで待つ（30 秒まで）。`restore_settled` に記録する。続かなければ restore ファイルと仮の画像を消さずに残す。2 の再生が仮の画像を指したまま起きると、消したファイルを指す壁紙が残るのを避けるため。
- 修正前と後の両方の結果を残した。修正前の quick（`...133311.json`）は、直後の読み戻しが失敗することの記録として使える。

**Windows 版への含み**: Windows 版は確かめていない。同じ「すぐの読み戻し」をしているなら、同じ型の偽の失敗が出うる。
→ （2026-10-09・まとめのセッション）Surface Pro 8 の Windows 版は直後の読み戻しで 30 / 30 一致した（`notes-windows.md`）。その機械では起きていない。他の Windows の機械は確かめていない。

## レビューの後に直したこと（2026-10-09・まとめのセッション・`/cross-review` 1 巡目）

> ⚠️ 上の結果のファイルは直す前のスクリプトで回したもの。直した後のスクリプトは**コンパイルも実行もしていない**（Windows の機械で直した）。次に Mac で回すときは、最初に `swiftc -typecheck` と `--quick` を通す。

- **戻した後の安定の確かめを、全画面同時・30 s にした**（`heldFor`）。前の `settled` は画面ごとに順番に 5 s を見ていた。そのため、(1) 先に確かめた画面が後で仮の画像に戻っても見逃す（Codex）、(2) 観測した再生（数秒後・30 s で収まった）が 5 s の後に来ると、仮の画像を消した後に、消したファイルを指す壁紙が残りうる（code-reviewer）。キーは `restore_settled`（画面ごと）から `restore_settled_all`（真偽 1 つ）に替えた。戻しが失敗した画面があるときは待たない。
- **手の確認の `readback_matches_on_other_space` を「2 s 続けて一致」にした**。2 s の間に 1 回でも一致すれば真、だと、過去の要求の再生が偽の一致を作りうる（code-reviewer）。
- 待つ前に「最大 60 s 確かめています・閉じないで」と表示する（待ちの間に端末を閉じると、結果の JSON が書かれない・code-reviewer 2 巡目）。
- ⚠️ **限界**: 30 s は 1 回の観測（再生は 30 s 以内に止まった）から決めた値で、60 s より後の再生は捕まえない（そのときは消したファイルを指す壁紙が残りうる）。30 s を少し過ぎて再生が来ると偽になる（仮の画像を残す側・安全）。次に回すとき `restore_settled_all` が偽になった回数を記録する。
- ⚠️ **次に Mac で確かめること**（`/cross-review` 2 巡目 Codex）: `swiftc -typecheck` → `--quick` で戻ること。できれば、(1) 待ちの途中で別の画像に替えると 30 s の数えがやり直しになる (2) 60 s で確かめられなければ仮の画像と restore ファイルが残る (3) 戻しに失敗したときも残る、を確かめる。
- `manual_spaces` の `readback_matches_on_other_space` は意味が「1 回でも一致」から「2 s 続けて一致」に変わったが、名前は替えていない（前の意味で記録した結果が 1 件も無いため）。
- `per_screen` の `readback_ok` を `readback_within_5s_ok` に改名した（修正前の `…133311.json` の `readback_ok` は「直後」の意味で、同じ名前で意味が違っていた）。
