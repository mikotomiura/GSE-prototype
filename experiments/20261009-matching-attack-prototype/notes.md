# 結果のノート

2026-10-09〜10 に G-GEAR（Windows 11）で実行した。手順と値は結果の前に固定し（`preregistration.md`・コミット `19f16862`）、コードも本計算の前にコミットした（`52f9c0da`・自己検査の強化 `c73fc37e`）。表の全体は `results/summary.md`、数値は `results/*.json`。合否の判定ではない（ADR-039【決 6-a】）。

## 何を測ったか

IME 論文の Windows のセル（MS-IME・TSF）の記録を使った。executor が計画どおりに送った合成入力で、人の打鍵ではない。2,925 試行（13 シナリオ × 3 速さ × 75・117 ブロック）からなる。1 試行は語句 1 つ（青空文庫 12 作品の 1,800 句・読み 6〜30 字）を、シナリオの手順で打ったもの。

1. 照らし合わせ: 前のタスクの手順で語句の本文から合成した長さの並びと、記録のカテゴリ列から数えた並びを試行ごとに比べた。前のタスクの手順は、SudachiPy の読みをローマ字の打鍵数に直し、読点・句点と改行で区切る。記録は「英字＋数字＋記号 − BackSpace」の数で、Enter と句読点で区切る。
2. 照合攻撃: 同じブロックで続く k 試行（S12 を除く）を 1 つの記録にした。候補 N 本の中から、打った読みの組（正解）を当てる正答率を測った。おとりは位置ごとに、そのシナリオで計画が選びえた 1,791 句から独立に引いた。攻撃者は 2 つで、どちらにも試行の切れ目を与えた。
   - 長さだけの攻撃者（L）: 前のタスクの L1。試行ごとの打鍵数を、候補の読みの標準の打鍵数と比べる。手順は知らない。
   - シミュレーション攻撃者（S）: IME 論文の closed set の攻撃（K2）で、時刻は使わない。手順を知り、カテゴリ列を編集距離で比べる。
3. 加工: 長さを粗い区間にまとめる・区切りを落とす・順序を捨てる（L）。連なりの長さを粗くする・捨てる・カテゴリをまとめる（S）。

- 長さを粗い区間にまとめる加工は、k = 1 では効く（L の幅 16 で 0.35%・S の幅 16 で 1.03%）。ただし k が増えると戻り、k = 20 で L の幅 16 が 98.1%、k = 8 で S の幅 16 が 94.8% になった。前のタスクの「雑音は短い k でだけ効く」と同じ形。
- 区切りを落とす加工（m 試行ずつ足す）は、残る区間の数が減る分だけ効く。合計だけにすると、k が増えるほど偶然の水準に近づいた（k = 20 で 0.03% [0.00, 0.11]。区間が 1/N を含んだのは k = 20 の N = 100・1,000 だけ）。ただし、試行の中の長さの情報は失われる。
- 順序を捨てる加工（並べ替え）は、k が増えるほど効いた（k = 20 で 22.5%）。それでも偶然の水準の 200 倍を超える。
- 連なりの長さを捨てる加工（S の w = 無限）でも、偶然の水準より高いままだった。どのセルでも区間が 1/N を含まず、k とともに増えた（N = 1,000 の k = 20 で 3.77% [2.17, 5.66]・N = 10 の k = 20 で 31.3%）。長音（「ー」は記号のキー）の位置で英字の連なりが切れる形、予測の候補の数字、前半だけの読みなど、連なりの並び方そのものが語句によって違うため（推測で、確かめていない）。
- 区切りのキー（Enter・Esc・Tab・句読点）を 1 種類にまとめる加工は、S の距離を 1 つも変えなかった（距離のファイルがバイト単位で同じ）。区切りのキーはシナリオで決まり、攻撃者はシナリオを知っているため。文字キーをまとめる加工は、主に S2（Space で候補を回す）と S7（変換の後に矢印）で効いた（k = 1・N = 100 で S2 が 23.9% → 10.1%、S7 が 41.6% → 27.1%）。全体では N = 1,000 の k = 3 で 95.0%。
- IME 論文の `counts_only` と、連なりの長さを持ったまま同じカテゴリの連なりをすべてまとめる `S_rle1` は、全セルで同じ正答率だった。距離の値は 0.09% で違ったが、正答率には出なかった。

### 診断

- 無作為の予測・記録を使わない予測（打鍵数がコーパスの中央値に最も近い候補）・記録を別のブロックの同じシナリオの試行に入れ替えた陰性対照は、84 個の区間のうち 79 個が 1/N を含んだ。含まなかった 5 個のうち 3 個は、当たりが 0 件で区間が [0, 0] に縮んだもの（N = 1,000 の k = 12・20 で、期待される当たりは 0.5〜1.4 件）。残る 2 個（無作為の k = 12・N = 100 が 0.50% [0.14, 0.91]、入れ替え L の k = 1・N = 10 が 11.3% [10.2, 12.5]）は、95% 区間 84 個で偶然に期待される数（約 4）の範囲にある。
- 長さを捨てる L（`L_bininf`）は、構造上すべての候補が同点になるので、正答率はちょうど 1/N になった（採点の検査を兼ねる）。
- おとりの引き直しは、k = 2・N = 1,000 で 375 回あった。語句の組の重複（引いた組が前のおとりと同じ）の期待値（約 320 万組から 999 組を引くと窓あたり約 0.16 回・2,583 窓で約 400 回）と合う。引き直しの理由ごとの数は記録していない。

## 読み方の注意（限界）

- **上限ではない**。攻撃者には試行の切れ目を与えた。言語モデル・時刻・本人の過去の文章・同じ書き手の複数の記録の組み合わせは使っていない。S は予測の記録を 1 本しか作らない（IME 論文と同じ）。一方で、切れ目を推す難しさは含まない。実際の記録では Enter・Esc・Space などのカテゴリから推せる見込みが高いが、測っていない。
- **合成入力**。人の打鍵のリズム・推敲・貼り付け・変換のやり直し・読み違いを持たない。打った読みはコーパスの読み（SudachiPy）そのもの。手順は 13 シナリオを同じ数ずつ混ぜたもので、人の操作の頻度ではない。打鍵数を変える手順（S6・S8・S10）が試行の 25% を占めることは、L の曲線の形を大きく左右した（事後の探索）。
- **長い記録は、独立に引いた語句をつないだもの**。続いた文章ではない。候補も同じ規則で作った。前のタスクの k の曲線（作品の続いた本文の窓・区間の平均 27.9 打）とは、区間の長さの分布（語句は読み 6〜30 字・ローマ字で約 11〜60 打）と候補の作り方が違う。
- **正解は打った読み**。取り消した語句や消した語句も含む（IME 論文と同じ）。最終的な文章と突き合わせる照合は測っていない。取り消した語句は文章に残らないので、その照合では S4・S5・S6・S14 の試行が雑音になる。
- **照らし合わせの読み**は、語句の本文だけに付けた。元の行の文脈では付けていない。
- **Windows のセルだけ**。macOS のライブ変換では Return が 2 回になり、区切りの数が変わる。区切りの数の違いは攻撃者が手順を知っていれば補える（S の区切りキーをまとめる加工が距離を変えなかったのと同じ理由）が、確かめていない。
- **合否の判定ではない**。ADR-039【決 6】の許す差・信頼の水準・本番の N は、本番の関門の設計で研究者が決める。

## 関連して見つけたこと（IME 論文・本タスクの外）

IME 論文の `closed_set.py` の `runs="count"`（`no_runs`・`bin1s_count`・`counts_only`）は、英字の連なりを 1 トークンにまとめる。ただし、トークンの個数に連なりの長さを入れ、距離もその差を使う。事前登録 §6.8 と原稿 `recoverability.tex` は、これらを「連なりの長さなし」と書いている。本タスクの `S_counts_only` と `S_rle1`（長さを持つ）が同じ正答率になり、長さを本当に捨てた `S_rleinf` が大きく下がった（N = 100・k = 1 で 44.3% → 1.68%）ことは、この読み（`counts_only` は長さを捨てていない）と合う。IME 論文の側での扱いは研究者が決める（`.steering/20261009-matching-attack-prototype/decisions.md` 判断 2）。

## 【決 9】と本番の関門への含意（Claude の推論・決定ではない）

1. 合成入力の範囲でも、打鍵のカテゴリ列（段 2 をそのままの粒度で出す形）は、語句 3 つほどで候補 1,000 本から正解を当てられた。前のタスクの「合成した並び」の前提は、手順と読点を除けば実機の記録で成り立った。IME 論文の k = 1 の値（約 8%）は、つないだ記録の当たりやすさを大きく低く見せる。【決 9】（G1 の参加者に知らせるか）の材料として、研究者の手元の記録では、候補の文章があれば照合が易しいことを示す。ADR-039 D6 の未決の論点 6 の推奨（合成入力は危険を低く見積もりうるので「知らせる」側の根拠にだけ使う）に沿う向きの結果。
2. 試行ごとの長さを残す加工（粗い区間・連なりの長さの幅）は、数〜十数試行つなぐと効かなくなった。偶然の水準に近づいたのは、長さを全部捨てるか（それでも k とともに上がる）、合計だけを残すときだけ。段 2 を出すなら、記録の長さ（つなげて使える試行の数）を含めて測る必要がある。前のタスクの含意 4 と同じ。
3. 人の打鍵では、推敲（S6 のような消去・取り消し）が多いほど、手順を知らない攻撃者には雑音になる。ただし、手順を知る攻撃者には効かなかった（S は S6 でかえって当たりやすい。BackSpace の数が読みの字数を表すため）。自由な作業の記録で照合を測る方法（未決）では、攻撃者がどこまで推敲の型を推せるかが鍵になる。
