# 結果の前に固定したこと

2026-10-09 に、照らし合わせ・照合攻撃・加工を 1 回も計算する前に書き、コミットした。手順の詳細は `.steering/20261009-matching-attack-prototype/design.md`、値は `config.json` と `SEED`。

この試作は合否を判定しない（ADR-039【決 6-a】: 試作は合成入力、本番の関門は決まった文章を打つ課題、合格は測った条件に限る）。ここに書く k・N・加工の段階は合格の基準ではない実験の値で、Claude が推奨と理由を添えて出し、研究者が結果を見る前に選んだ（`.steering/20261009-matching-attack-prototype/decisions.md` 判断 1）。ADR-039【決 6】の数値（許す差・信頼の水準・本番の N）はここでは決めない。

## 問い

IME 論文の Windows のセル（MS-IME・TSF・executor が送った合成入力 2,925 試行）の記録で、

1. 前のタスク（`experiments/20261009-length-sequence-uniqueness/`）の手順で語句の本文から合成した長さの並びは、記録のカテゴリ列から数えた並びと一致するか。ずれるなら、どこで・どれだけ・何が原因か。
2. 同じブロックで続く k 試行の記録から、候補 N 本の中の正解（打った読みの組）を当てる正答率は、偶然の水準 1/N と比べてどうか。k とともにどう変わるか。
3. 加工（長さを粗く・区切りを落とす・種類をまとめる・順序を捨てる）で、正答率は偶然の水準にどこまで近づくか。

## 固定した値

| 項目 | 値 |
|---|---|
| 入力 | `config.json` の `inputs`（SHA-256 を照らし、違えば止まる）。人のデータは使わない |
| 記録の割り当て | IME 論文の `segment_by_plan`（ブロックの印・`markers_in_obs`）。採点しないブロックは使わない |
| 試行の打鍵数 | 英字＋数字＋記号の押下 − BackSpace の押下（Space・Enter・Esc・Tab・矢印は数えない） |
| 照らし合わせ | 全 2,925 試行。記録は Enter と句読点で区間に切る。合成は前のタスクの B0 の手順を語句の本文に当て、最後の区間を確定の Enter で閉じる。原因の印は配送・手順（S4・S5・S6・S8・S10・S12・S14）・読点・読み。印の無い不一致は試行の ID を列挙する |
| 記録（窓） | ブロックの中で計画の順に並ぶ S12 以外の採点した試行の、連続した k 個（すべての始まり・重なりあり・ブロックをまたがない）。正解は打った読みの組 |
| k・N | k = 1, 2, 3, 5, 8, 12, 20・N = 10, 100, 1000 |
| 候補 | 正解の組 ＋ おとり N − 1 組。おとりは位置ごとに、そのシナリオで計画が選びえた語句（読みの重複を除いた 1,791 句から `_scenario_pool`）から一様に独立に引く。打った読みの組が正解と全位置で同じ組と、前に引いたおとりと同じ組は引き直す。引き方は攻撃者と加工の間で共通 |
| 偶然の水準の前提 | 正解とおとりはどちらも語句のほぼ一様な引き方から来る（計画はシナリオごとに語句の全体を順に回して引いた）。記録は抽選に使わない。採点は候補の順によらない。同点は 1/m |
| 攻撃者 L | 試行ごとの打鍵数と、候補の読み全体の標準の打鍵数（IME 論文の `romaji.to_keys` の長さ）の差の絶対値の和が最小の候補。手順を知らない |
| 攻撃者 S | IME 論文の `closed_set.py` の予測と距離（K2・種 20260929・時刻を使わない）。試行ごとの距離の和が最小の候補 |
| 切れ目 | どちらの攻撃者にも試行の切れ目を与える |
| 加工 | L: なし・floor(値/w)（w = 2, 4, 8, 16）・値を捨てる・m 試行ずつ足す（m = 2, 5）・合計だけ・並べ替え。S: IME の `no_time`・`counts_only`、同じカテゴリの連なりをまとめて個数を ceil(個数/w)（w = 1, 2, 4, 8, 16）・個数を捨てる、文字キー（英字・数字・記号・Space）をまとめる・区切りキー（Enter・Esc・Tab・句読点）をまとめる・両方 |
| 区間 | ブロック（117）を単位にした百分位のブートストラップ 2,000 回・95%。すべてのセルで同じ抽出 |
| 診断 | `L_none` と `S_no_time` で、無作為の予測・記録を使わない予測（打鍵数がコーパスの中央値に最も近い候補）・記録を別のブロックの同じシナリオの試行に入れ替えた陰性対照 |
| 再現の確認 | k = 1 の `S_no_time` と `S_counts_only` を IME 論文の候補と同点の決め方で採点し、公開された `acc_raw`（K = 10, 100, 1000）と正答の数まで一致すること。一致しなければ本計算をしない |
| 乱数 | `SEED` = 20261009。用途のタグ・k・N・ブロック・始まりを `:` でつないだ文字列の SHA-256 から作る |

## 報告すること

- 照らし合わせの全シナリオ（S12 を含む）と原因ごとの数。印の無い不一致の試行。
- 441 セルすべて（よい結果だけを選ばない）。k = 1 のシナリオごとの正答率（記述）。
- 診断と再現の確認。
- 前のタスクの B0・N = 1,000 の理想と強い雑音の値を横に並べる（条件が違うので同じ量ではないと書く）。

## 結論に使わないこと

- 照合の危険の上限・安全の証明とは書かない（試行の切れ目を与えた攻撃・言語モデルと時刻と本人の過去の文章を使わない・合成入力・独立に引いた語句をつないだ記録）。
- 合格・不合格の判定はしない。
- 時刻を使う特徴量の組は計算しない（合成入力の打鍵の間隔はキーと独立）。

## 逸脱の扱い

ここに書いた値や手順を変えたら、変えた時刻と理由を `notes.md` の「逸脱」に書き、変える前の値の結果も残す。
