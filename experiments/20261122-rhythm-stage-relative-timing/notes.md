## 読み（記述・判定の語は判定を写すだけ）

- **主の問い**: 2 つの段のどちらでも、案 D の 2 本は基準 A の上で `red_detected` だった。design §3.3 への追加 (c2) のとおり、これは「案 D の画は打鍵の有無を超えて停滞を写した」と書き、「案 D は相対のタイミングで停滞を写した」とは書かない。錨の 4 本も 2 段とも `red_detected` で、g050 では利得の大きさは案 D とほぼ同じ（0.22 対 0.24〜0.25）だった。
- **副の問い**: この試行は答えていない。g050 は A_speed が天井、f200 は A_speed の上で停滞の陽性対照が働かなかった。f200 の判定不能は、揺れの形の回の f200（L300 の 16 本が `weak_stall_pc`）と同じ形である。見込み（design §3.3 への追加 (d)「`g050` は天井、`f200` で測れる」）のうち、g050 の天井は当たり、f200 で測れるという見込みは外れた。判定に使わない A_speed の上の利得（案 D 0.045〜0.049）を、緑や赤の手がかりとして読まない。
- **(d2) 見込みとの違い**: design §3.3 への追加 (d) は「`D-run` の倍率の当てはまりは 0 に近い」と見込んだが、f200 の `u` の R² は D-run 0.468・D-all 0.453 で、0 に近くなかった。「`D-all` は `D-run` より大きい」という見込みとも違い、2 本はほぼ同じだった。滑らかさの 6 量だけで D-run 0.419・D-all 0.387 に届き、全量の R² の大半はこの 6 量で出る。窓の打鍵の数でも、f200 では滑らかさだけの R² が全量にほぼ等しい（0.612 対 0.627）。§1.2 の塞がない道（1 秒あたりの窓の入れ替わりを通して、秒ごとの系列の時間方向の量が速さを運ぶ）が、案 D の画に速さを運ぶ主な道である、と読むのが自然だが、この検査ではほかの道と分けていない（推論）。窓の統計量そのものの倍率への不変（自己検査の作り物の列と N1）は、比べられた秒では、これと矛盾しない（N1 は同じ押下で終わる窓どうしを比べ、時間方向の量を見ない。比べられる秒は s = 2 で 0.177・s = 0.5 で 0.255 と狭く、2000 ms の上限に掛かる秒の不変は確かめていない・design §3.7）。
- **(c) 落とした変種**: 滑らかさの 6 量を落としても、案 D の A の上の利得はほとんど変わらなかった（g050 の D-run 0.217 → 0.216、f200 0.229 → 0.227）。`a` の側を落とすと最も下がった（g050 の D-run の small で 0.15 → 0.12）が、どの変種も 0.03 を大きく上回った。速さの道の量（滑らかさ）を除いても、残りの量（`a`・`r` の水準と分位など）で、A の上の停滞の手がかりは残った。design のとおり、これを「手がかりは滑らかさに無い」「`a` にある」とは読まない（量どうしは相関し、攻撃者は残りの量で埋め合わせうる）。また、滑らかさを除いた残りの量が速さを運ばないことは確かめていない（g050 では停滞の間に打鍵が遅くなるので、速さを運ぶ量はどれも停滞を運びうる・(c2)）。
- **錨**: 見込み（`S-raw-hold-sub` は A の上で大きく運ぶ）どおり、g050 で 0.246 だった。f200 では 0.161 で、`S-raw-hold-sec` は 0.078 まで下がった。案 D と `S-rank` の 2 本は f200 でも 0.22〜0.24 を保った（記述。world の間で列は対にならないので、段の差を確かめたとは言わない）。
- 人の打鍵、人が画を見て停滞を読めるか、本人が自分の打ち方だと分かるか（判断 14 の (a)）については、何も言わない。1 つの seed で、world の差は確かめていない。
- 個人の再識別と個人ごとの読み手（元の引き継ぎ §3 の 5・6）は測っていない（判断 5）。この world には人の区別が無く、人ごとの違いに当たるのは f200 のセッションの倍率だけである。案 D の画がセッションの倍率を R² 0.45〜0.47 で運んだこと（(d2)）は、人ごとのリズムの型を持つ world で再識別を測る理由の 1 つになる（推論）。その段は次の段として行う（`.steering/_handoff/next-session-rhythm-stage-person-world.md`）。

## 逸脱・気づいたこと

- design の固定の後の変更は無い。§8 は値の追記だけ。§8 の g050 の本番の行で、N1・N2 の値が本番の前の自己検査（`TEST_SEED` 7）の値であることを書き足した（はじめ「本番の N1」と書いていた）。
- 下見 0 の前の CI と重い処理の確認を、下見 0 の後に行った（§8）。
- 再実行の一致（design §6・判断 17）: 本番の後に、2 段のスモークを同じ seed でもう一度回した（g050 83 s・f200 122 s・rc 0・自己検査 0 件の失敗）。1 回目の `results/<段>/main-smoke/` の JSON（g050 4 つ・f200 5 つ）と、時間の欄（`timing`・`wall_s`・`_wall_s`）と `provenance.json` を除いて比べ、すべて一致した。陰性対照として g050 と f200 のスモークどうしを同じ道具で比べ、違いが出ることを確かめた。本番そのものは回し直していない（2 段で約 1.7 h かかり、スモークは本番と同じ道を小さく通るため）。したがって、受け入れ条件の「同じ SEED での再実行で出力がバイト一致する」は、本番の規模では確かめておらず、スモークの規模で時間の欄と `provenance.json` を除いた一致を確かめた、までである。`main-smoke/` は `.gitignore` の対象で、いま入れ物にあるのは 2 回目（表の秒は 1 回目）。比べの出力は判断 17 に写した。回し直しの 2 本の `provenance.json` は `experiment_dir_dirty` が true（コミット `f9ac0d5e`）。そのとき入れ物で未コミットだったのは書きかけの `notes.md` と `check_notes.py` だけで、計器の指紋の対象（`scripts/*.py`・`run.sh`）は変えていない。下見 0・下見 1・本番の記録はすべて false。
- notes の表（判定の並び・AUC・利得・落とした変種・(d2)）は、`check_notes.py`（この dir の直下・計器の指紋の外）で一次の JSON と照らせる: `python check_notes.py .`（`bad 0` で一致・不一致なら終了コード 1・数は書いた桁へ四捨五入した JSON の値と等しいことを求める）。検査そのものの変異は `python check_notes_mutants.py . <空の作業 dir>`（壊した notes 7 つで終了コード 1、壊さない notes で 0）。照らすのは表だけで、本文の数（項目 2・4・6、止まりの遅れ、重要度、比、画だけの AUC、PCs・PC0・帰無の範囲、所要）は照らしていない（完了時の code-reviewer が手で JSON と照らし、帰無の範囲の 1 件を直した）。1 回目は f200 の D-all の「落とさない」の行の書き違い 1 件を見つけ、直した。
- f200 の A_speed の部分で、PC-stall の λ が格子の上端 0.3 に張り付き、本番で 6 本とも働かなかった。揺れの形の回の f200 と同じ形で、規則は変えていない。副の問いを f200 で読むには、PC-stall の格子を延ばすなどの作りが要る見込み（推論・採るかは研究者が決める）。
