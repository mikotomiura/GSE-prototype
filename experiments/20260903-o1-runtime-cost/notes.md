## ★★★ 結果（2026-09-04・macOS のみ）

### ★ 実測値（`with-gse`・880 サンプル・7.99 時間）

| 指標 | 全 880 行 | ⚠️ CI 窓を除く 867 行 | 閾値 | 判定 |
|---|---|---|---|---|
| CPU 平均 | **0.980 %** | **0.982 %** | < 1 % | ★ **合格**（⚠️ **ぎりぎり**） |
| CPU 最大 | 4.30 % | **1.80 %** | < 15 % | ★ 合格 |
| RSS 傾き (top MEM) | **+0.005 MB/h** | +0.004 MB/h | < 5 MB/h | ★ 合格 |
| RSS 傾き (ps rss) | **−0.437 MB/h** | −0.389 MB/h | < 5 MB/h | ★ 合格（★ **減っている**） |
| RSS 最終 (top MEM) | **27.0 MB** | — | < 300 MB | ★ 合格 |
| NDJSON / 日 | **11.05 MB / 12.3 h ＝ 21.6 MB/日 に外挿** | — | < 30 MB | ★ 合格 |
| バッテリー | ⚠️ **—** | — | < 5 pt/8h | ⚠️ **測れていない** |
| **総合** | | | | ⚠️ **DataInsufficient** |

★ **メモリのリークは無い。** ⚠️ 2 指標が逆向き（top MEM は +0.005、ps rss は −0.437）だが、
★ **どちらも 5 MB/h の閾値から 3 桁小さい**ので、向きの違いは判定に効かない。

⚠️★★ **CPU 最大 4.30 % は CI 窓の中だけで出た値である。** 窓を除くと **1.80 %**。
→ ★ 4.30 % を「GSE の最大負荷」と読まないこと。

### ⚠️★★★ 対照 (`without-gse`) は **何も測れなかった**

★ 958 サンプル・7.99 時間を回したが、⚠️ **使える情報はゼロ**である。

| ⚠️ 理由 | 詳細 |
|---|---|
| **① 対照が寄与できるのは指標 3（バッテリー）だけ** | ★ CPU / メモリ / NDJSON は **GSE のプロセスを測る**ので、GSE が居ない条件では **全列が 0** になる（★ 設計どおりであり、計測器の欠陥ではない） |
| **② その指標 3 が両条件で成立していない** | ⚠️ `with-gse` は **AC で充電**（75 % → 100 %）＝ 放電を測れない。★ `without-gse` は **途中で AC が外れ**（2026-09-04 11:15 頃）、100 % → 82 % と放電した |
| **③ したがって電源条件が違う** | ⚠️ **同じ条件で比べていない**ので、差を取っても意味が無い |

⚠️★★★ **これは実験設計の誤りである（★ 私の計画ミス）。**
★ 「AC で回してバッテリー指標は諦める」と決めた時点で、⚠️ **対照は原理的に無意味になっていた**。
→ ★ **決めた瞬間に対照を外すべきだった。** 8 時間ぶんを無駄にした。

★ 唯一の副産物: **GSE が居ないとき全列が 0 になる**ことを確かめた（＝ 計測器の陰性対照）。

### ⚠️★★★ 計測器の欠陥を 3 件見つけて直した（★ 判定より先にこれを潰した）

| # | 欠陥 | ★ 影響 |
|---|---|---|
| ① | macOS の `top` が `#TH` を **`31/1`** で出す行が **880 中 21 行**。⚠️ 集計側が数値化に失敗して **その行を丸ごと捨てていた**（CPU も RSS も一緒に） | ★ **結論は変わらなかった**（捨てた行の CPU 平均 0.957 < 全体 0.980）。⚠️ **偏っていたら変わっていた** |
| ② | AC で充電され低下が **−25.03** になり、⚠️ 判定関数の `value < good` に当たって **`PASS` と表示された** | ⚠️★★★ **「測っていない」を「合格」と読ませていた** → `DataInsufficient` に倒した |
| ③ | ①を直した後、⚠️ **列不足の行は「捨てた行」に数えられないまま**だった（★ 陽性対照を置いて初めて分かった） | ★ 検査を書いたのに空回りしていた型 |

★ ①はサンプラ側 (`sample-macos.sh`)、②③は集計側 (`summarize.py`) を直し、
⚠️ **陽性対照（壊れた行で報告が出る）と陰性対照（正常データで出ない）の両方**で確かめた。

### ⚠️ 計測中に観測された **既存の**欠陥

`starved_ms=30088` の CGEventTap 失効（memory `macos-tap-idle-away-probe-bug`）。
★ 本実験の欠陥ではないが、⚠️ **数週間回す O1 で実際に起きる**ことの実測。
