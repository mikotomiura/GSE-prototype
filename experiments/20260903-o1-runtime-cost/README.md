## やり方

```bash
# ★ 1. 計測を仕掛ける（★ GSE を起動した後・8 時間以上放置する）
bash experiments/20260903-o1-runtime-cost/run.sh with-gse

# ★ 2. 翌日、対照（GSE を終了した状態）を同じ時間だけ回す
bash experiments/20260903-o1-runtime-cost/run.sh without-gse

# ★ 3. まとめる
python3 experiments/20260903-o1-runtime-cost/scripts/summarize.py
```

⚠️ Windows は **git-bash** で `run.sh` を叩く（★ 中で PowerShell を呼ぶ）。

## ⚠️★★★ 対照 (`without-gse`) を回す条件（★ 2026-09-04 の失敗から）

⚠️ **対照が寄与できるのは指標 3（バッテリー持ち）だけである。**
★ CPU / メモリ / NDJSON は **GSE のプロセス**を測るので、GSE が居ない条件では全列が 0 になる。

→ ⚠️★★★ **AC 運転で回すなら、対照は回さないこと（無意味である）。**
★ 対照を回すのは「**満充電から、両条件とも最後までバッテリー駆動**」で測るときだけ。
⚠️ 2026-09-04 は AC で `with-gse` を回しながら対照も 8 時間回してしまい、
★ **途中で AC が外れて条件が食い違い**、8 時間ぶんが丸ごと無駄になった。

## ⚠️ 判定（★ 先に決めておく。測った後に基準を動かさない）

| 指標 | ★ 合格 | ⚠️ 要対処 |
|---|---|---|
| CPU 平均（アイドル） | **< 1%** | ≥ 3% |
| CPU 最大 | **< 15%** | ≥ 30% |

| バッテリー消費の増分 | **< 5 pt / 8h** | ≥ 10 pt / 8h |
| NDJSON / 日 | **< 30 MB** | ≥ 48 MB（⚠️ 受け口の `MAX_BYTES` に当たる） |
