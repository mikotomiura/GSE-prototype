# notes — 背景のステージの机上の検査・揺れの world の `res=sub` の赤の原因の切り分け

> これは EH0 の実験で、探索的・記述的である（design §0）。書くのは「読み」で、判定ではない。前のタスク（`experiments/20261014-rhythm-stage-speed-confound-world/`）の判定は書き換えない。合成した「停滞」と「速さの揺れ」は打鍵の統計の型であって、認知の状態でも人の打鍵の性質でもない。「GSE が示した」とは書かない。

## 接続

- **問い**: 揺れの world の L300 で赤になった `res=sub` の候補について、次の 2 つを問う（`.steering/20261015-rhythm-stage-speed-cause-split/design.md` §0）。
  - (a) A_speed の特徴に加法の非線形の変換を足した lr（`lrbin`）を基準にしても、上乗せは 0.03 を超えて残るか。
  - (b) 描画の特徴から `r_absdiff`・`r_sd`（`R2`）を落とすと、上乗せは消えるか。
- **事前登録に当たるもの**: 同 design。計器とともに `6599c5e4` で固定し、本番は `c98e1b2f` で回した。`c98e1b2f` は固定の後に decisions の判断 6 を足しただけのコミットで、計器は変えていない。固定の後の逸脱は無い（design §8）。
- **列**: 前のタスクの計器をその場所のまま使い、同じ seed 20261020 で本番の列を作り直した。照合の門は、前の `e13.json` の L300 の 866 値（AUC 2 つと、72 本 × 攻撃者 4 × 3）と許容差 1e-9 で比べる（design §1.1・§1.5）。

## 読み（探索的・design §3.4 の表のとおり。判定の語は使わない）

c100 と c200 は別々に読む（c200 は前のタスクで探索的と併記した段）。多重の補正はしていない。

### (a) 攻撃者の能力の差

- **c100**: `lr|none` で「残る」だった 8 本のうち 7 本（`raw` の 3 本・`smooth-hold`・`jitter` の 3 本）が、`lrbin` を基準にしても「残る」。上乗せは 0.003〜0.013 だけ小さくなり、`rank-decay-sub` は「決まらない」に移った。design §3.4 の「`lrbin` で残る」の行に当たる: A_speed の特徴を加法の非線形で使っても上乗せは残り、加法の非線形だけでは読み 2 を説明できない。表は「hgb の値を並べて読む」とするが、c100 の hgb は検出器の条件を満たさず読めない（上）。候補自身の hgb の上乗せが +0.014 以下という事実はそのまま残るが、それを「消える」とは読まない。
- **c200**: `lrbin` で「残る」は 6 本（`raw` の 3 本と `jitter` の 3 本）で、`lr` の 4 本より多い。`jitter-hold`・`jitter-decay` は `lr` で「決まらない」だったのが、`lrbin` では上乗せが大きくなって「残る」になった。基準の AUC は lr 0.770 → lrbin 0.788 と上がったのに、上乗せは増えた（理由は分けて確かめていない）。hgb では `raw` の 3 本が「残る」（+0.039〜+0.041）。
- **`lrbin2`**（描画の側も bin にする・記述だけ）: c100・c200 とも「残る」の候補は `lrbin` と同じで、上乗せは多くの候補で少し大きい（全件ではない: c200 の `smooth-decay-sub` は 0.014 → 0.012。c100 では「決まらない」が 1 本から 3 本に増えた）。描画の側を線形に使うことが上乗せを作っている、という見方とは合わない。
- **見込み（design §3.5）との比べ**: c100 で「`lrbin` でも多くが消えるか決まらないに寄る」と見込んだが、外れた（7 本が残る）。c200 の「`raw` の `sub` の 3 本は `lrbin` でも残る」は当たった。

### (b) 推論の元の特徴

- **`R2` を落とす**: `lr`・`lrbin`・hgb（c200）のどれでも、「残る」は c100・c200 とも 0 本になった。`lrbin|R2` では 24 本すべてが「消える」。`lr|R2` で「決まらない」に残るのは、`raw-hold`・`raw-decay` と `rank` の 3 本（上乗せ +0.026〜+0.034）。
- **`Rall` を落とす**: `lr` と `lrbin` は両段で、hgb は c200 で、24 本すべてが「消える」。c100 の hgb は「読めない」（落とさない変種と同じく検出器の条件を満たさない）。
- **比べ `A2`**: 段と基準で分かれる（`/cross-review` で直した）。
  - c100 の `lr`・`lrbin` と c200 の `lrbin`: `A2` の下げ幅は `res=sub` の 12 本で 0.0075 以下で、`R2` の下げ幅よりずっと小さい。`r` の 2 量が特に効くと読む前提（design §3.4 の 1 つ目の注）を満たす。
  - c200 の `lr`: `A2` の下げ幅が `R2` に近い候補がある（`jitter-hold-sub` 0.0096 と 0.0124、`jitter-decay-sub` 0.0116 と 0.0134、`raw-hold-sub` 0.0069 と 0.0097）。この 3 本は注に当たり、`r` の 2 量が特に効くとは読まない。「残る」の本数も 4 → 2 に減った。
- **design §3.4 の表での読み**: `raw` と `jitter` と `smooth-hold` の `sub` の上乗せは、`r_absdiff`・`r_sd` の系統が運んでいた（赤の候補が `R2` で「残る」から「消える」か「決まらない」へ移った・下げ幅 0.013〜0.051。c200 の `lr` の 3 本は上の `A2` の注のとおり除く）。
- **`rank` の 3 本は §3.4 の表の外**: `R2` を落としても上乗せはほとんど下がらない（下げ幅は `lr` で 0.0016〜0.0052、`lrbin` で 0.0014〜0.0075）。下がるのは `Rall` のとき（`lr` で 0.014〜0.022）。c100 の `rank-decay-sub`（赤）は、`lrbin` の時点ですでに 0.027 の「決まらない」で、`R2` で 0.024 の「消える」に移っただけである。`rank` の上乗せは `r_absdiff`・`r_sd` ではなく `r` のほかの量が運んでいるように見えるが、`R2` が「決まらない」なので、表の「`R2` で残る・`Rall` で消える」の行には当たらない（記述にとどめる）。
- `raw-hold`・`raw-decay` の `lr` も `R2` で「決まらない」に止まり、`Rall` で「消える」。同じく表の行には当たらない。
- **限り（design §3.2・§3.4・必ず併記する）**: (b) の「消える」は、落とした量がその攻撃者の上乗せを運んでいた、までである。列を落とせば上乗せは機械的に減りうるので、「`r` の系統にしか停滞の手がかりが無い」とは読まない。`hold` で `jitter` でない組（`raw-hold`・`smooth-hold`・`rank-hold`）では、PC-stall の `r` の列はもともと定数なので、`R2`・`Rall` の検出器の条件は落とさない変種とほぼ同じになる。そのため、落とした後の感度を独立に確かめる力は弱い。
- **結果を見て足した限り**: 実際には、`hold` で `jitter` でない組に限らず、`ground`・`decay`・`jitter` の組でも、PC-stall の `gain_max` は `none` と `R2` でほぼ同じだった（例: `lr` の c100 の `raw-ground-sub` で 0.0655 と 0.0655、`jitter-decay-sub` で 0.0664 と 0.0664、c200 の `jitter-decay-sub` で 0.0561 と 0.0563）。|`none` − `R2`| の最大は `lr` で 0.0005（c100）・0.0009（c200）、`lrbin` で 0.0005 以下、c200 の hgb で 0.0022。言えるのは「`R2` を落としても PC-stall の上乗せは変わらない」までで、手がかりが `r_absdiff`・`r_sd` を通らないのか、他の列でも重ねて運ばれているのかは区別できない。どちらでも、`R2` の後の検出器の条件は落とさない変種と事実上同じになり、どの候補でも独立の確かめにならない（§3.2 の限りが、`hold` で `jitter` でない組から全部の組に広がる）。示されるのは PC-stall の型の漏れへの感度までで、`r` の揺れの量の側に残る手がかりへの感度は示されない。`Rall` では `raw` の `decay` と `ground` の組で PC-stall の上乗せが少し下がる（`lr` の c100 で 0.0083〜0.0094、c200 で 0.0096〜0.0106。`smooth`・`rank`・`jitter` の `ground` は 0.0005〜0.0032）が、条件は満たしたまま。
- **見込みとの比べ**: 「`R2` を落とすと `raw` と `jitter` の `sub` の上乗せは大きく減る」は当たった。`Rall` まで落とさないと「消える」にならない候補（`raw-hold`・`raw-decay` の `lr`）もあった。`rank` は `R2` ではほとんど減らなかった（見込みの対象の外）。

### 前のタスクへの材料（判定は変えない）

- 揺れの world の `res=sub` の赤は、A_speed を加法の非線形で使う基準（`lrbin`）でも多くが残る。`raw`・`jitter` の赤は `r_absdiff`・`r_sd` を落とすと残らなくなり、この 2 量に集まっていた（c200 の `lr` では `a` の側の 2 量を落としても近い幅で減る候補がある）。`rank` の赤（と `red_unconfirmed`）は、この 2 量ではなく `r` のほかの量の側にある。落とした後に `r` の側に残る手がかりへの感度は示されていない（上の限り）。
- 読み 1（描画が A_speed に無い停滞の手がかりを運ぶ）と読み 2（A_speed の中の手がかりを lr に取り出せる形で運び直す）のどちらかに決める力は、このタスクには無い。加法の非線形までは読み 2 を支えない。交互作用まで取る hgb は、c100 で検出器の条件を満たさず読めない。c200 では hgb でも `raw` の 3 本が残る。
- 次の候補（研究者が決める）: 揺れの形の world（引き継ぎの別タスク）で `r` の秒ごとの揺れの量が速さの揺れそのものとどう結びつくかを作りの側から確かめる。または、c100 の hgb で余地を作る（PC-stall の大きさを上げた対照）ことで、交互作用の側を読めるようにする。

## 逸脱・気づいたこと

- design §8 の逸脱は無い。
- c200 の `provenance.json` の `dirty: true` は、上の「実行の記録」のとおり、未コミットの c100 の結果を数えたため。`git_state` が未追跡のファイルも数える作りであることは、固定の前の自己検査で確かめていなかった。次のタスクでは、結果の dir を数えない（`-- . ':!results'`）か、段ごとにコミットしてから次の段を回す。
- c100 の hgb がすべて「読めない」ことは、design §9 の 3（天井の規則の代わりに検出器の条件で余地を確かめる）が働いた結果で、作りどおり。ただし design §3.5 の見込みは、前のタスクの hgb の上乗せ（+0.014 以下）の小ささを根拠にしながら、その段の hgb に余地が足りない可能性（§1.3 で併記していた）を見込みに入れていなかった。
