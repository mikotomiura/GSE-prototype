### 3.2 ★★★ 実測が本物の欠陥を 1 件見つけた —— **層 2 が完全に無音だった**

> ★ **静的検査 58 件が全部緑のまま通り、捕まえたのは陽性対照だけだった。**

- **症状**: `層 2 単体 RMS = 0.000e+0`。**層 2 は 1 サンプルも音を出していなかった。**
- **原因**: `grain-processor.js` の `parameterDescriptors` に **既定 0 の `gain` AudioParam** があり、
  player 側は**外部の `GainNode` だけ**を設定していた。★ **ゲインの制御点が 2 つあり、片方が 0 のままだった。**
- ★★ **どうやって気づいたか**: **陽性対照 [3]（層 2 のゲインを 0.01 Hz で変調して検出できるかを見る）が
  `-61.8 dB` を返し、「検出できない = 計器を疑う」と出た。**
  ⚠️ **他のすべての検査は緑だった**——4 Hz 判定も側帯波も、**無音なら当然通る。**
  ★ **「危険な成分が無い」ことは「何も鳴っていない」でも満たされる。**
- **直し方**: ★ **Worklet からゲインの AudioParam を削除**し、**制御点を外部 `GainNode` 1 つに絞った。**
- ★ **同じ型を捕まえる検査を 3 つ足した**（`verify-before-claiming` ルール 6）:
  1. 動的 `[0]`: ★ **層 0 単体と層 2 単体の RMS を対照つきで測る**（片方だけでは無音と測定死を区別できない）
  2. 静的: **Worklet が `gain` AudioParam を持たない**（二重制御を作らせない）
  3. 静的: **player が `renderRms()` の定義と呼び出しの両方を持つ**
- ⚠️ **修正後の値**（同じ測り方）: 層 0 単体 **2.407e-1** / 層 2 単体 **1.716e-1** / 比 **0.713**。

### 3.3 ★ 検査自体の欠陥を 3 件、実測で見つけて直した

#### BF-1 ⚠️★★★ 音割れ —— **私が足した軸が原因だった**

- **原因**: `density_norm_exp < 0.5` は密度が上がるほど**素直にレベルが上がる**設計なのに、

  1. ★ **最大密度のとき `normExp=0.5` と同じレベルになるよう静的に割る**

- **原因（私の実装）**: 校正は「**いま選ばれている密度の写し方**」で比を測る。
  ★ `c_texture` はレベルが動かない設計なので比は必ず ≈1 になる。
  そのまま**対照（マスタゲイン）**を回すと **A と B が完全に同一**の条件を検査として提示してしまう。
  ⚠️★ **警告も出さなかった。**
- ★★ **これは「対照が空回りしていないか確かめる」という自分で書いた規律を、自分で破った形である**
  （`browser-verification` §2.0: control が 0 なら target が 0 でも何も言えない）。
- **直し方**（2026-08-13・実測で両方向を確認）:
  - ★ **対照条件で |比| < 0.5 dB なら盲検を始めない。** 理由を画面とログに出す。
  - ★ 校正の表示に**密度の写し方**と**警告**を併記する。
  - 実測: 比 0.987（−0.11 dB）→ **開始されない** ／ 比 1.30 → **開始される**。
- ⚠️★ **無効と分かった測定は記録から消さない。** ★ **無効であると書いて残す**
  （消すと「なぜその条件を避けるのか」が次の人に伝わらない）。

#### BF-3 ⚠️★★ 校正が遷移時間に引きずられていた

- **症状**（2026-08-13）: 密度の写し方を `c_level` にしたのに、校正の比が **1.011（+0.10 dB）**しか出ない。
- **原因（私の実装）**: 遷移時間の軸を足したとき、校正が呼ぶ `abxSet()` も
  **選択中の遷移時間に従うようになった**。★ 遷移 60 秒のまま校正すると、
  校正が待つ 3 秒間に **0.6% しか動いていない状態**を「B」として測る。
- ★ **切り分けの根拠**: `densityNormExp` は **0 に到達済み**だった（写し方の設定は正しく効いていた）。
  → ★ **原因は写し方ではなく校正手順**だと特定できた。
- **直し方**: ★ **校正は必ず端点で測る**（遷移時間を無視して即座に A / B へ飛ばす）。
  ★ 遷移時間は「盲検で何を提示するか」の変数であって、「端点がどれだけ違うか」とは無関係である。
- **実測**: 修正後 **1.127（+1.04 dB）**。★ 遷移軸を足す前の測定値 1.126 と一致 —— **回復の裏取りになった。**
- ⚠️★ **併せて警告文も直した** —— 「差が実質ありません」の理由を
  **密度の写し方のせいだと決めつけていた**。★ いま効いている値を見て、当てはまる理由だけを出す。

#### BF-4 ⚠️★★★ 盲検の出題が均衡していなかった（**点数が感度を測っていなかった**）

- **症状**（2026-08-13）: 遷移 0 秒・本番（密度）で **6/8**（閾値 7）。
  ⚠️ ところが研究者の主観は **「かなり違いは分かりやすい。60 秒と比べて」**。★ 数字と耳が食い違った。
- **原因（私の実装）**: 各試行を独立に `rnd() < 0.5` で振ったため、
  ★★ **8 回中 same が 6 回・diff が 2 回**になった。

  | 内訳 | 実測 |
  |---|---|
  | 出題 | same 6 / **diff 2** |
  | 正答 | same 5/6 ・ **diff 1/2** |

  → ★★★ **「毎回 same と答える」だけで 6/8 取れる。** 実際の点数と一致する。

  ★ **既にある正しい型を、新しく作った検査で使わなかった。**
