## 主の結果（揃えた対照・`results/dwell100/auc.json`）

| `stall_onset`（副） | 計器が動いていなかった（下） | | | |

- C7 の読み方で、主の 2 つはどちらも「逆向き」: 要求の手前は、同じ長さの休止の途中の対照より、詰まり側でない。
- 揃えない対照でも中央値は同じ（`p_stuck` 0.422・`ewma_x` 0.443）。揃えても揃えなくても差は休止で説明されない（直前の休止が短いことは下の探索で見たもので、判定には使っていない）。
- `p_stuck` の 97.5% 区間の上限は dwell 100 ms で 0.492 と、0.5 に近い。
- `stall_onset` は 1,447 セッションの全体で 0 件だった。理由は変換の不備で、`gse-replay --features` は入力の `feat` 行の時刻から観測区間を作るのに（`replay.rs` の `collect_all_feat_timestamps`）、変換した NDJSON は `feat` 行を持たなかった。観測区間が 0 本になり、評価が 1 回も走っていない（1 本で `provenance.observed_intervals` が 0 本と実測。code-reviewer の指摘）。当初書いた「立ち上がりに届かない」は誤り。`feat` 行を足すと、推定の値は変わらず、同じ 1 本で onset が 2 件立った。1 回目の `stall_onset` の結果は「判定不能」ではなく「計器が無かった」と読む。2 回目で直して回す（逸脱 4）。

## 計器の確かめ

- 推定器はこのデータでも詰まり側に振れる: 5 本に 1 本の抜き取り（290 セッション・192,349 行）で `p_stuck` の 99 分位 0.921・0.6 以上の行 5.1%。「逆向き」は計器が動かないせいではない。
- 合成の離しの影響: `f1` の 10 分位が 1 ms（速い連打で離しを次の押下の 1 ms 前に置いたため）。感度（下）で結論が動かないことを確かめた。

## 感度（dwell 60 / 140 ms）

揃えた対照・AUC の中央値と 97.5% 区間（書き手 50・要求 3,316 はどの dwell でも同じ）:

| dwell | `p_stuck` | `ewma_x` |
|---|---|---|
| 60 ms | 0.434（0.390–0.484） | 0.447（0.406–0.485） |
| 100 ms | 0.422（0.393–0.492） | 0.449（0.406–0.485） |
| 140 ms | 0.421（0.390–0.468） | 0.449（0.406–0.485） |

どの dwell でも主の 2 つは「逆向き」。`ewma_x`・`f3`・`f5` の AUC は dwell でほとんど変わらない（小数第 3 位で動く。理由は確かめていない）。`stall_onset` はどの dwell でも 0 件（上の変換の不備による）。replay の標準エラーは 3 本とも空だった（この時点の run.sh は追記のみだったが、各 dwell の置き場は新しく作ったので 1 回ぶん）。

## 言える範囲

- 言える: 英語の共同執筆で、Tab で提案を求めるよう教示された MTurk の書き手 50 人では、GSE の今の推定（個人の較正なし・合成の離し）の `p_stuck` と `ewma_x` は、提案を求める手前で「詰まり側」に寄っておらず、むしろ逆向きだった。
- 言えない: 自然な作業での AI の利用・日本語や IME・GSE の参加者で同じかどうか。要求が「詰まりの自己申告」ではないことの確かめ（要求の理由は記録に無い）。
- 構造の偏りの可能性: 対照は前後 60 秒に提案まわりの出来事が無い時刻、要求は直前 60 秒だけを課した（C5・C6 どおり）。対照が AI の利用から遠い時間帯に寄るので、AI を使う局面で書き方が違えば AUC に効きうる。
- `cursor-*` はマウスでの選択を含みうるが、すべて navigation の打鍵として数えた（C3 どおり・確かめていない）。英語以外の記号は other（文字を生まないキー）になる。
- `friction_rising` への含意（研究者が判断する材料）: 「AI を求めた時刻の手前」を、そのまま「詰まる前」の正解の時刻として使うことは、このデータでは支持されない。区切りでの要求と、詰まった後の要求を分ける手がかりが無いと、AI の要求の時刻は詰まりの学習の的にならない。

## 逸脱

1. run.sh に `scripts/slim.py` を足した（2026-10-31〜11-01）。ディスクが一杯になり感度の計算が止まったため、replay の出力から analyze.py が読む項目だけを残す。dwell 100 の中間に当てて analyze.py を回し直し、counts.json・auc.json・trajectory.csv がバイト単位で同一であることを確かめた。
2. 感度の 1 回目は、計算中に中間の置き場が消されて壊れたので、止めて最初からやり直した（結果は使っていない）。
3. Step 0（`capabilities_gate.py`）は当たらないので、変換時の行種の数え上げ（`results/*/convert_stats.json`）で代えた（decisions.md 判断 5）。
4. `stall_onset` は変換の不備で評価されていなかった（上）。2 回目で `feat` 行を足して回す。
5. 書き手の除外を 2 度かけた: C7 は「C5 を通った要求が 5 件以上」だが、analyze.py は対照を引けなかった要求を除いた後にも 5 件以上を課した（52 人 → 50 人）。
6. 揃えた対照の間隔は「P より長い」（`>`）にした。conditions.md C6 は「P 以上」。T_c が次の押下と重なるのを避けるため。
7. レビューの後に analyze.py を直した（対照の時刻と値を組のまま除く・スナップショットの無い要求を数える・一様抽出の端）。dwell 100 で auc.json・trajectory.csv がバイト同一であることを確かめた。run.sh に来歴（git の HEAD・gse-replay の SHA-256・標準エラーの大きさ）と、中間の掃除を足した。
8. 全行の分布の抜き取り（290 セッション・`p_stuck` の 99 分位 0.921）は一時のスクリプトで計算し、残していない。2 回目では残す。
