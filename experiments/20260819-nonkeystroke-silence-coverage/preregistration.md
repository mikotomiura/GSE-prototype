## 1. 測定の原理（★ なぜ Stage 0 が既存ログで測れるか）

`src-tauri/src/input/liveness.rs:86-104` の `step()` は純関数で 3 分岐しか持たない:

| 条件 | 挙動 |
|---|---|
| `!session_active \|\| hook_event_seen` | `starved_ms = 0`（★ 打鍵でリセット） |
| `!system_input_seen` | `prev` を返す（★ **入力皆無で凍結**） |
| それ以外 | `starved_ms += tick_ms`（★ **OS は入力を見たが打鍵が来ていない**） |

→ ★★★ **`starved_ms` は「打鍵が無い時間のうち、OS が入力（マウス含む）を見ていた累積時間」そのもの。**
★ `lib.rs:2951-2956` の復帰行が**エピソードのピーク**を搬送する。

⚠️ **これは設計者が明示的に用意した再解釈である**（ADR-011 D5・`liveness.rs` のテスト
`mouse_only_work_is_a_known_false_positive` 逐語「だから NDJSON には `starved_ms` を載せ、
**後から再解釈できる**ようにしてある」）。

⚠️★★★ **`starved_ms` は「入力デバイスに触れた」ことしか意味しない。「作業していた」ことの証明ではない。**

## 2. 定義（★ 凍結）

```
沈黙区間      := 打鍵イベントが 1 つも無い連続時間区間で、長さ ≥ 30 秒
                 ★ 30 秒は liveness.rs:64 の log_after_ms と揃える。
                 ⚠️ 揃える理由は既存トラックと同じ土俵で読むためであって、
                    30 秒に理論的な意味があるからではない。

被覆(t, c)    := チャネル c のイベント時刻 t が区間 [t − w, t + w] を覆う
                 ★ w = 5000 ms に凍結する（⚠️ 実データを見て変えない）
                 ★ これは「イベント型チャネル」(L-b / L-c) の定義である

被覆率(C)     := Σ(チャネル集合 C のイベントが覆った沈黙時間) / Σ(沈黙時間)
                 ★ 重なりは 1 度だけ数える（和集合をとる）

限界寄与(c)   := 被覆率(C) − 被覆率(C \ {c})

null 被覆率(c):= そのチャネル自身のイベント数を、同じ沈黙区間の集合の中で
                 一様無作為に配置し直したときの被覆率の中央値（★ 置換 1000 回・seed 固定）
                 ⚠️ 併記必須（§6）
```

⚠️★★★ **`w` を凍結する理由**: `w` を後から動かすと被覆率は単調に動く。
★ **実データを見てから `w` を選ぶことは、閾値を後から選ぶことと同じ**である（forking paths）。

### 2.1 ⚠️★★★ L-a は **持続時間型チャネル**であり、上の定義では計算できない

⚠️ **Stage 0 の L-a（`starved_ms`）はイベント列ではない。** `hook_health` 行が運ぶのは
**そのエピソードのピーク持続時間**（`lib.rs:2951-2956`）であって、時刻の並びではない。
→ ★ **上の `[t−w, t+w]` の定義をそのまま当てられない**（code-reviewer HIGH）。

★ **したがって L-a には別の推定量を置く**:

```
被覆率_L-a  := Σ_g min(peak_starved_ms(g), gap_duration_ms(g)) / Σ_g gap_duration_ms(g)
               ★ g は沈黙区間。★ 既存パイプラインの presence_ratio と同じ量である
                 (experiments/20260819-silence-presence-decomposition/ の extract.py / describe.py)
```

⚠️★★★ **2 つの推定量は同一ではない**:

| | L-a（持続時間型） | L-b / L-c（イベント型） |
|---|---|---|
| 素材 | ピーク持続時間 | イベント時刻列 |
| 打ち切り | ⚠️ **30 秒で左打ち切り**（下界） | ★ 打ち切りなし |
| `w` | ★ 使わない | `w = 5000 ms` |

→ ⚠️ **`θ`（L-a 由来）と `C_nonkey`（イベント型）の比較は同一土俵ではない。**
★ **`θ` は左打ち切りにより系統的に低く出る ＝ 甘い側に外れる。**
⚠️★★★ **したがって `ADR-012 D5` の「θ を最大値に置くから厳しい側」は、この打ち切りの分だけ相殺される。**
→ ★ **`θ_floor`（§5.1）がその相殺への保険でもある。**
★ **Stage 1 でも L-a を並行して算出し、L-a 同士の比較（同一推定量）を必ず併記する。**

## 5. 閾値 θ の決め方（★ 凍結）

```
θ := max( max_i C_write,i ,  θ_floor )      ← Stage 0 で決まる
θ_floor := 0.20                              ← ★ 事前登録で固定（⚠️ 恣意的であることを明示する）
```

- ★★★ **θ を人が選ばない**。⚠️ これが本実験の中心的な設計である（ADR-012 D2・段 2）。
- ⚠️ **Stage 0 は別コホート・別モダリティ**であり、**非打鍵データを 1 バイトも見ずに θ が決まる**
  → ★ forking paths を踏まない。
- ⚠️ **G1 は確証標本 1/3 名**。★ **`C_write` は点推定として扱わず、全被験者値を必ず併記する。**
- ★ **θ を「最大値」に置くのは厳しい側に倒す意図である** —— 甘い θ は「同じ形」を「違う」と読ませてしまう。
  ⚠️★★★ **ただし §2.1 のとおり `C_write` は 30 秒で左打ち切りされるため θ は系統的に低く出る。**
  → ★ **「最大値だから厳しい」は打ち切りの分だけ相殺されている。** ⚠️ **厳しさを主張しない。**

### 5.1 ⚠️★★★ なぜ `θ_floor` が要るか（★ 2026-08-19 の実測で判明した穴）

⚠️ **`C_write` が 0 に近くなる可能性が実測で高い。**

| 実測 | 出所 |
|---|---|
| ローカルにある NDJSON **76 ファイル（P000 13 + Phase1 63）すべてで `hook_health` が 0 行** | ★ 本実験の設計時に直接計数（2026-08-19） |
| G1 P010 は **10 ブロック中 9 ブロックで `hook_health` 行が 1 件も出ていない** | `experiments/20260801-controlled-friction-task/notes.md:1808` 逐語「★ **他の 9 ブロックは `hook_health` 行が 1 件も出ていない**（＝ 30 秒の閾値にすら一度も届いていない）」 |

★ 意味論上、**沈黙のうち *入力を伴った累積時間* が 30 秒未満なら `hook_health` 行は出ない**（★ `step()` は入力ありの tick だけ加算し入力なしで凍結、`lib.rs:2924` は状態変化時のみ出力する）。⚠️★★★ **60 秒の沈黙中に 25 秒マウスを動かしていても 0 行になる。**
→ ⚠️ **`C_write ≈ 0` になりうる。**
⚠️★★★ **ただしその場合に「打鍵タスクの沈黙はほとんど入力皆無だった」と読んではならない** ——
★ **30 秒未満の入力エピソードが多数あっても同じく 0 になる**（＝ **左打ち切り**）。
→ ★★★ **`C_write` は真の被覆率の *下界* であって推定値ではない**（§12-3b）。

⚠️★★★ **`θ = max(C_write)` だけだと、θ ≈ 0 になって主基準が空文になる。**
→ ★ **床 `θ_floor = 0.20` を置く**（「沈黙の 5 分の 1 以上を覆う」）。

⚠️ **`θ_floor = 0.20` は実データから導いた値ではなく、恣意的な実務的下限である。**
★ **恣意的であることを隠さず、実データを見る前に宣言することで forking paths を避ける。**
⚠️ **後から動かさない。**

⚠️★★★ **報告に `theta_source` を必須フィールドとして出す**（★ Codex 指摘）:
**`theta_source ∈ {stage0, floor}`** を `results/` に必ず書く。
→ ⚠️ **これが無いと「実測由来の閾値を超えた」と読まれる。**

⚠️★★★ **そして正直に書く**: `θ = θ_floor` に落ちた分岐では、
**「θ をデータから導く」という本トラックの中心的な主張は *成立していない*。**
★ その場合の θ は **dev が事前宣言した恣意値**であり、
⚠️ **`design-comparison.md` が v1 を破棄した理由（θ が dev の推測のまま）と同じ構造に戻っている。**
→ ★ **隠さず結論に明記する**（★ 隠す方が本トラックの作法に反する）。

⚠️★★★ **`C_write ≈ 0` を「所見」として提示しない。**
★ それは **計器の左打ち切りが産んだ値でありうる**（30 秒未満の入力エピソードは記録されない）。
→ ⚠️ **これを実質的所見として書くことは、本トラックが防ごうとしている
「計器が無い／信号が無い」の混同そのものである。**
★ 報告は **「`C_write` の下界は X であった。上界は本計器では出せない」** の形にする
（★ 前トラック `experiments/20260819-silence-presence-decomposition/preregistration.md §4.6` が
打ち切りを**上下界**で扱ったのと同じ様式を借りる）。
★ なお **§6 の副基準（null 超過）**が独立に効くので、θ が低いことによる素通りは起きない。

## 6. 合格基準（★ 凍結）

> **「その層で覆えた」= 次の 3 つを *すべて* 満たす。**
>
> 1. 層 L の**合同**被覆率が **n 名全員**で **θ を超える**
> 2. **null 被覆率を超える**（★ 置換検定・§2）
> 3. **`C_write`（同一人物の論述ブロック）を超える**（★ Stage 1 のみ・within-person）

⚠️★★★ **1 つでも欠けたら「覆えた」と書かない。**
★ **2 基線（null ／ `C_write`）の値を必ず併記する**（[V83] 逐語
`We cannot replicate models that significantly improve over the baseline of a majority classifier.`
＋ `§8` 2026-08-16 決定「勝ち幅は 2 つの基線に対して報告する」）。

**superset への採否**（★ チャネル単位）:

> チャネル `c` を superset に入れるのは、**限界寄与(c) ≥ δ** かつ **null 超過**のとき。
> ★ **δ = 0.05** に凍結する（⚠️ 実データを見て変えない）。

⚠️★★★ **`θ`（L-a 由来）とイベント型の合同被覆率の比較は「探索的な便宜基準」である**（★ Codex 指摘）。
★ §2.1 のとおり **2 つは同一推定量ではない**（片方は 30 秒で左打ち切りされている）。
→ ⚠️★★★ **主要な結論は *同一推定量内の比較* に限定して書く**:
**L-a(非打鍵) vs L-a(論述)** と、**L-b/L-c の null 超過**。
⚠️ **層進行（次の層へ進むか）の判定にのみ `θ` を便宜的に使い、結論の根拠にしない。**

## 7. Stop 条件（★ 凍結）

| 条件 | 帰結 |
|---|---|
| `hook_health` が対象コホートに無い | ⚠️ **Stop**（`instrument_absent`）。★ ADR-013 を先に実装してから収集し直す |
| **Stage 0** が §9 の下限を満たさない | ★ **`θ = θ_floor`（0.20）を使う**。⚠️ **下限を緩めない。** ★ 「Stage 0 では θ を出せなかった」を `results/` に記録する |
| 沈黙区間が **20 本未満**の被験者がいる | ★ その被験者を**除外**し、除外数を必ず報告する（⚠️ n が 3 未満になったら **Stop**） |
| 層 L で合格基準を満たさない | ★ **次の層へ進む**（L-a → L-b → L-c） |
| **L-c まで進んでも満たさない** | ⚠️★★★ **本トラックは Stop**。「**L-a〜L-c では覆えなかった**」を結論にする。⚠️ **L-d へ進むか T3 を future work に戻すかは *別 ADR で裁く*** |
| ★ `C_nonkey ≈ C_write`（θ を超えない） | ★★★ **「まさに *同じ形* である」を実測の結論として書く。** ⚠️ **これは失敗ではない** |
| 入力の manifest 不一致 | ⚠️ **exit 非 0 で停止** |

⚠️★★★ **Stop は失敗ではない。**
★ `cv-gate-null` が「`0.502` は統制下 CV の推定ではない」を結論にしたのと同じく、
**覆えないことの特定も成果である。**

## 8. 除外規則（★ 凍結）

| # | 除外 | 理由 |
|---|---|---|
| **E1** | セッション境界をまたぐ沈黙区間 | `step()` は `!session_active` で `starved_ms` を 0 に落とす（`liveness.rs:95`）＝累積が汚染される |
| **E2** | warm-up ブロック | 開始直後の立ち上がりを本体の分布に混ぜない（`task-adaptation-and-scope-gating.md §2.3`） |
| **E3** | block 境界をまたぐ沈黙区間 | ★ 読み出し窓長 ≤ 最短 block 長（同 `§3.4`） |
| **E4** | `dropped_delta > 0`（ADR-013 実装前は `dropped` の増加）を含む区間 | ログキュー溢れ＝記録の欠落。⚠️ **`dropped` は累積カウンタである**（`hook.rs:140`）ので、**そのまま「この区間で落ちた」と読まない** |
| **E5** | `probe_assignment` / `realtime_label` / `vignette_response` を含む区間 | ⚠️ **装置由来の沈黙**（プローブ提示が打鍵を止める） |

★ **各除外の件数を必ず `results/` に出す**（⚠️ 黙って落とさない）。

## 9. n と期間の下限（★ 凍結）

**n≥3 名 × 各 ≥3 セッション × 各 ≥30 分、かつ沈黙区間 ≥20 本/人。判定は「全員一致」。**

★ 根拠は**既存先例と同型**（新しい原則を持ち込まない）:
- 「全員」条件 = GATE3 の「C-index 中央値 ≥0.65 & **全員 >0.55**」（`§8`）
- 「≥20 件/人」= `§8` 逐語「**≥20件/人 は floor**: 単一事例最小 ~15–18点 [V28] と
  within-person 信頼性理想 ~70–100機会 [V27] の間に位置し、Stage-1 の方向検定の最低床として採る」

⚠️ **n=1,2 で判定しない** —— `cv-gate-null §5-6` と前トラックで
**P011 が `<100` 窓 1 個で実質的に情報を与えなかった**ことが実測されている。

## 10. セッション設計（Stage 1・★ 凍結）

```text
[warm-up] → [A: 非打鍵タスク] → [B: 短い論述] → [A': 非打鍵タスク]
  破棄       （普段の作業）        ★ 同一人物内の比較   （復帰の確認）
```

- ★ 順序は被験者間で **counterbalance**（B を常に中央に置かない）。
- ⚠️ **要因を掛け合わせない**（`§2.8` 逐語）。論述ブロックは**セッションあたり 1 本**。
- ★ block 境界は既知の時刻として記録する（**新しいイベント種別を作らない**）。
  ⚠️★★★ **ただし「どこに記録するか」を実装前に決める**（★ Codex 指摘・現状未定義）:
  境界時刻が NDJSON の外に出る場合は、**sidecar の schema / ハッシュ対象 /
  計測器との時刻同期の方法 / 改ざん防止**を決めてから収集する。
  ⚠️ **除外規則 E1 / E3 と再現性が直接この上に乗っている。**
- ★ 宣言は **block 単位**であり、**観測と融合しない**（ADR-012 D3 / ADR-010 D3）。

## 11. 自己検査（★ 本解析より先に回す）

|---|---|---|

## 12. ⚠️ 事前に認めている限界（★ 隠さない）

1. ⚠️★★★ **被覆率は「入力があった」ことしか言わない。「作業していた」ことの証明ではない。**
   ★ [P121] の mid 帯が「**離脱 or 外部資源への相談**」で割れたままなのと同じ曖昧さが残る。
   → ★ **検証用サブサンプルの参照チャネル（画面録画）でのみ点検する**（ADR-012 D12）。
2. ⚠️ **Stage 0 の `C_write` は G1 の確証標本 1/3 名**から出る。★ 点推定として扱わない。
2b. ⚠️★★★ **Stage 0 は現時点で実行できない。** **ローカルの NDJSON 76 ファイル
   （P000 13 + Phase1 63）すべてで `hook_health` が 0 行**である（★ 2026-08-19 に直接計数）。
   → ★ **`liveness.rs` 導入（2026-08-09）以降に収集されたログは、G1 以外にローカルに存在しない。**
   ⚠️ さらに **G1 P010 は 10 ブロック中 9 ブロックで `hook_health` が 0 行**
   （`controlled-friction-task/notes.md:1808`）であり、**1 ブロック 5 分**なので、
   ⚠️ **§9 の下限（≥20 沈黙区間/人・≥30 分/セッション・n≥3）を満たさない可能性が高い。**
   → ★ **その場合は §7 の Stop に従い「Stage 0 では θ を出せなかった」と記録し、
   `θ = θ_floor` を使う**（⚠️ **勝手に下限を緩めない**）。
3b. ⚠️★★★ **`C_write` は 30 秒で *左打ち切り* された下界である。**
   ★ `starved_ms` は入力ありの tick だけ加算され、`lib.rs:2924` は状態変化時のみ出力するので、
   **沈黙のうち入力を伴った累積時間が 30 秒未満のエピソードは 1 行も残らない**。
   → ⚠️ **`C_write` を「真の被覆率の推定値」として扱わない。** ★ **下界として報告し、上界は
   「本計器では出せない」と明記する**（★ 前トラック `preregistration.md §4.6` の上下界様式に倣う）。
3c. ⚠️ **L-a とイベント型（L-b/L-c）は別の推定量である**（§2.1）。★ 混ぜて 1 つの表に並べない。
3. ⚠️ **30 秒未満の沈黙は対象外**（`lib.rs:2924` の間引き）。
   → **micro 帯（2–15 秒 = [P121] の「局所思考」）について本実験は何も言わない。**
   ★ ADR-013 D4 の `starve_window` が入って初めて言えるようになる。
4. ⚠️ **割り当てブロックは自然発生と同じではない**
   （`§2.4` 逐語「**割当正例で推定できるのは検出可能性の上界である**」）。
5. ⚠️ **モダリティは 1 つに限定する**（`§Adapter C` 逐語）。★ 他モダリティへ一般化しない。
6. ⚠️ **形成的トラックであり確証主張に使わない**（適格性ゲート未適用）。
