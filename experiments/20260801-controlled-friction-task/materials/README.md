# 課題文（materials/）

> 制約の出典は `../preregistration.md §2.2 / §2.7`（凍結）。**本文書はそれを変更しない。**
> 機械検証は `../validate_materials.py`。`bash ../run.sh` から自動で走る。

## 1. 何が必要か

| 用途 | 必要なもの | 状態 |
|---|---|---|
| positive control | **copy task 用の定型文 1 本**（全被験者共通・位置固定） | ✅ `copy.md` |
| パイロット（`preregistration.md §2.8`） | **1 題材 × 2 版**（LO / HI） | ✅ `topic01_lo.md` / `topic01_hi.md` |
| 本番 | **8 題材 × 2 版**（`preregistration.md §2.7` の counterbalance に必要） | ❌ **未作成**（パイロット後に作る） |

⚠️ **本番用の 8 題材 × 2 版はパイロット後に作る。** パイロットで「5 分ブロックで両条件とも
十分な打鍵が出るか」「資料の量が適切か」が分かってから量産する（先に 16 本作ると作り直しになる）。

## 2. 命名規則

```
copy.md              positive control（全被験者共通）
topicNN_lo.md        題材 NN の LO 版（資料 1 本・要約）
topicNN_hi.md        題材 NN の HI 版（資料 3 本・統合）
```

`NN` は 2 桁ゼロ埋め（`01`〜`08`）。★ **同じ NN の lo / hi は同じ題材**でなければならない
（`preregistration.md §2.7`: 8 題材すべてに両版を作る）。

## 3. ファイル様式（機械検証される）

```markdown
---
id: topic01
version: lo
title: 題材の名前
sources: 1
output_requirement_chars: 300-400
---

## 教示

（被験者に読ませる教示。★ 「300〜400 字」を必ず含める）

## 資料 1

（本文）
```

- `version` は `lo` / `hi` / `copy` のいずれか。
- `sources` は `lo`=1 / `hi`=3 / `copy`=0。`## 資料 N` セクションの数と一致すること。
- `copy` 版だけは `## 資料 N` の代わりに `## 原文` を置く。

## 4. 内容の制約（`preregistration.md §2.2` から。**変更しない**）

1. **LO** = 与えた **1 本**の短い資料を、**指定の読み手**向けに**要約**する（knowledge-telling 寄り）。
2. **HI** = 与えた **3 本の相互に矛盾する**短い資料を統合し、**1 つの主張**にまとめる
   （knowledge-transforming）。
3. **産出要求を揃える**: どちらも **300〜400 字**。
4. ★ **資料の総量を揃える**: 同じ題材の LO の 1 本と HI の 3 本で、
   **資料本文の総文字数をほぼ等しく**する（許容 **±5%**・`validate_materials.py` が検査）。
   読解量の差を摩擦の差と取り違えないため。
5. ★ **専門知識を要さない一般的な題材**にする。題材の難度は個人の予備知識に依存し、統制できない。
6. **5 分で書き切れる量**であること。
7. **copy 用の文は中立で退屈**であること（内容に引き込まれて「考えて」しまわないように）。
8. ★ **HI の 3 本は「対立」でなければならない。** 3 つの別々の話題を並べるのではなく、
   **同じ問いに対して食い違う答え**を与えること。統合が要らなければ HI にならない。

## 5. 作ってはいけないもの（`README.md §2.2` が却下した操作）

- ❌ 語彙制約（頻出語の使用禁止など）— 機械的にポーズを増やすだけで、摩擦の検出にならない。
- ❌ 時間圧を煽る文言 — 焦りは摩擦と別物。
- ❌ 難しい題材・専門的な題材 — 個人の予備知識に依存し統制できない。
- ❌ 感情を強く動かす題材 — 交絡になる。

## 6. プライバシー

- ★ **課題文は被験者の産出物ではない**ので repo に置いてよい。
- ★ **被験者が書いた本文は保存しない**（content-free 原則・`data-privacy` Skill）。
- 実在の個人・団体を特定できる記述を入れない（架空の自治体名・架空の調査を使う）。

## 7. 検証

```bash
python3 ../validate_materials.py          # 全ファイル
python3 ../validate_materials.py --strict # 本番用 8 題材 × 2 版が揃っているかも検査
```
