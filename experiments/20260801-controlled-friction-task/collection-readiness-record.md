# G1 収集開始 — 人手確認の記録票

> ★ 作成: 2026-09-20。`.steering/20260920-g1-collection-readiness-gate/` 判断 3。
> ★ 読む側: `scripts/check-g1-collection-readiness.sh` の検査 [8]。

## ⚠️ この票は何のためにあるか

事前登録の収集開始の前提条件 1〜7 のうち、**3 つの部分は機械検査に載らない**。
いずれも **外部サービスの状態**（配布済みフォーム・Drive・CI の両 OS ジョブ）で、
手元のリポジトリを読んでも分からないからである。

⚠️★★★ **ゲートがこの票について見ているのは「人が確かめたと書いたこと」だけである。**
★ Drive 上の実物も、配布済みフォームの中身も、CI の実際の run も、**ゲートは見ていない。**
→ **埋めた人が中身に責任を持つ。**（★ 埋めれば緑になるが、それは「確認したと申告した」の意味しかない）

⚠️ **前提条件そのものが未達のまま、この票だけを埋めてはならない。**

## ⚠️★★★ 書いてはいけないもの（★ ここが最優先）

**本リポジトリは一時 public にする運用がある**（`blocks/.gitignore` 逐語 /
`docs/pilot-runbook.md:80` / `protocol.md:1112`）。`protocol.md:1133` は逐語で
**「❌ ★ 成果物にセッション日時・氏名・メール・所属を出す」**と禁じ、
`notes.md:1057` は **「★ 実 URL は repo に置かない。」**と決めている。

→ ★ **この票にも同じ規約がかかる。** 次のものを書かない:

| ❌ 書かない | ✅ 代わりに書く |
|---|---|
| URL（`https://...`）— ⚠️ フォームや Drive のリンクは**それ自体が鍵**である | 定数名・通称（例: `G1_CONSENT_FORM_C`） |
| Google の ID（フォーム ID / Drive フォルダ ID / スプレッドシート ID） | 同上 |
| 氏名・メールアドレス | **ロール**（例: `研究者 A`） |
| セッション日時（時刻） | **日付まで**（`YYYY-MM-DD`） |

⚠️ **検査 [8] はこれを機械で弾く**（`- ` で始まる記入欄の行に `http` / `@` /
28 文字以上の英数字トークンがあれば赤）。★ 弾かれたら、書き方を変えること。

## ⚠️ 記入の規則

- ★ **`**未実施**` を `**確認済み**` に書き換え、その節の「（未記入）」を全部埋める**と、
  検査 [8] のその節が緑になる。⚠️ **状態だけ書き換えても緑にならない**（欄が空なら赤）。
- ★ **確認日は `YYYY-MM-DD`**（例: `**2026-09-20**`）。⚠️ 時刻は書かない。
- ★ **「対象のコミット」は 7〜40 桁の hex**（例: `**9b64f52**`）。
  ⚠️★★★ **そのコミットが現在の HEAD の祖先でなくなると、検査 [8] は赤に戻る。**
  ★ 一度埋めたら永久に緑、にはしない（確認したのは「その版」だから）。
- ⚠️ **やり直したら書き換える**（★ 古い確認日を残さない）。
