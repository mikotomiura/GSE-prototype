## 設計上の判断（記録）

1. **摩擦の操作を「語彙制約」「時間制限」ではなく「統合の必要性」にした。**
   前二者は打鍵の機械的な変化を直接作るため、分離できても「制約の検出」であって
   「認知的摩擦の検出」ではない。**交絡そのもの**なので採らなかった（README §2.2）。
2. **ブロック数を 8 に固定した。** 個人内の並べ替え検定で p<0.05 に到達するために必要
   （C(8,4)=70 → 最小 p ≈ 0.014。4 ブロックでは C(4,2)=6 → 最小 p ≈ 0.167 で**原理的に到達不能**）。
   検出力の話ではなく**検定が成立するかの話**なので削れない。
3. **特徴量セットを 2 本（FS-A / FS-B）立てた。** G1 を合否判定だけでなく**診断的**にするため。
   「観測空間が足りないのか、打鍵では原理的に測れないのか」を切り分けられる（README §3.2）。
4. **操作チェックを先に見る。** 摩擦を操作できていなければ、分離できなくても
   「打鍵で測れない」の証拠にならない。

5. ★ **L2 罰則を事前固定し、並べ替え検定を主判定に据えた**（2026-08-01 の `/cross-review` で Codex が指摘）。
   1 人 8 ブロック（各 fold の学習は約 6 ブロック）に対し FS-B は 14 特徴量あるため、
   **無正則化では完全分離が起きて AUC が人工的に上がる**。罰則で係数を有限に保ち、
   さらに**並べ替えのたびにパイプライン全体を再実行する**ことで小標本由来の楽観を帰無分布に吸収させた。
   → **AUC しきい値は「実用的な大きさの目安」へ降格し、有意性の主判定は並べ替え検定**（README §3.3）。

### ★★ 先行プロトコル調査の結果（設計を変えた）

G1 の HI/LO は language testing の **integrated vs independent writing task** と**同型の操作**だった。

- **[P43] Chan 2017**（N=2・探索的）: integrated が demanding。ポーズ長・修正数↑、産出速度↓。
- ★ **[P44] Michel et al. 2020**（**N=60**・TOEFL iBT・counterbalanced・eye-tracking 併用）:
  **source use を除けば挙動は概ね similar**。

→ **G1 の 12 倍の標本で「同系統の操作が広い行動差を作らない」と報告されている。**
これを受けた改訂は 3 つ:

1. **自前設計と主張しない**（`preregistration.md §1.1-1`）。
2. **帰無が現実的**なので、`§3.7` で**負の結果の価値を事前に宣言**した。
3. ★★ **positive control（copy task ブロック）を新設**（`§2.5`）。
   `FS-A ✗ / FS-B ✗` を「打鍵では測れない / 操作が弱い / 計器故障」に**分解できないまま
   軸を疑う判断へ進むのを防ぐ**ため。写経 vs 自然な執筆は打鍵のみで判別可能と独立に確立している
   （[P37] RF 99% / [P36] / [P38]）＝**検出できることが分かっている差**を同じ計器で流す。

⚠️ **ブロック数が 8 → 10 に増えた**（約 48 分 → 約 62 分）。copy は**位置固定**（先頭・末尾）で、
G1 の 8 ブロックの**強制比較の鎖を壊さない**ことを優先した。

1. ⚠️★★ **「べき等だから二重起動を気にしなくてよい」は言い過ぎだった。**

   → ★ 排他ロックを置き、取れなければ何もせずに帰るようにした（**収束型なので損失にならない**）。
   ⚠️ ★ 猶予を 0 にすると**自分で置いたばかりのロックまで奪う**ことを実測し、下限をテストで固定した。
2. ⚠️★ **初回起動で、ID を入力する前に赤いエラーが出ていた**（自動提出が「ID 未登録」で失敗扱い）。
   ★ 手引きは「未送信が残っていないことだけ確認」と書いているので、これは**被験者を無用に不安に
   させる**。→ ID 未登録は失敗ではなく「何もしなかった」として扱い、画面に出さないようにした。

### 8-3c. ⚠️★★ レビューで見つかった 4 件（★ どれも「黙って壊れる」型・修正済み）

`code-reviewer` と `security-checker` を並列で回した結果。★ **設計文書の主張が実測で否定された**ものを含む。

1. ⚠️★★ **収束の対象が G1 に絞られていなかった。**
   `~/Documents/GSE-sessions` は **participant 非依存の共有ディレクトリ**で、
   Phase1 の較正セッションや P-1 の記録が同じ端末に残る（★ P-1 実機には `.age` が 4 本ある）。
   → ⚠️ **同意していない経路で古い記録が送られ**、さらに古いセッションがブロック番号 1〜4 を
   食い潰して **本物の G1 ブロック 1 が block05 になる**。★ 事後には分からない壊れ方である。
   → ★ `meta` 行の `g1_mode` を条件に足し、送信・件数も `<participant>_block` 形式に限定した。
2. ⚠️★ **送信先が未設定でも画面に出なかった。** `g1-submit.json` を置き忘れると
   `.age` はできて errors も空・exit 0 のまま、★ **未送信件数だけが静かに増える**。
   画面は「次のブロックの後に再試行します」と書くが ⚠️ **永久に送られない**。
   → ★ 「この端末は自動送信の設定がされていません」を別文言で出す。
3. ⚠️★ **ブロック終了の合図が 1 回分ずれ続ける経路があった。** 合図の channel は容量 1 で、
   待ち切れなかった回の合図が残る → 次のブロックで即座に返り、以後ずっと 1 ブロック遅れる。
   ★ プロセスは × で終了しない（D-10）ので **最後のブロックが送られない**。
   → ★ 送る前に古い合図を捨てる。
4. ⚠️★ **受け口の「同名・同サイズなら保存しない」が、提出を握り潰す経路だった。**
   同名・同サイズのダミーを先回りで置かれると本物に `ok` を返し、端末は `.sent` を書く。
   ★ 送信先から成否を追えないので **誰も気づかないまま 1 本失われる**。
   → ★ **必ず保存する**（重複は研究者が中身を見て捨てられるが、消えた 1 本は取り返せない）。

### 8-3e. ⚠️★★ 送信前の確認を入れた（研究者判断 D-14・2026-08-08）

ブロックが終わるたびに「このブロックの記録を送信しますか？」を出し、
★ **「送信する」を押したときだけ送る**。目的は **同意の担保**である。

実装で被害を最小化した: **`.age` は確認の有無に関わらず必ず作る**（止めるのは送信だけ）／
