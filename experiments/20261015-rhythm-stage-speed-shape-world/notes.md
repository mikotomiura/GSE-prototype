# notes — 背景のステージの机上の検査・揺れの形を分けた world（倍率だけ・漂いだけ）

設計: `.steering/20261015-rhythm-stage-speed-shape-world/design.md`（固定 `74754d26`・逸脱の表 §8）。判断: 同 `decisions.md` 判断 1〜14。

## 接続

- 問い（design §0）: 揺れの world `h(c)` の L300 の赤（とくに `r_absdiff`・`r_sd` が運ぶ上乗せ）は、速さの揺れの 2 つの成分（セッションごとの倍率 `u`・秒ごとの漂い `d`）のどちらから来るのか。
- world: 倍率だけ `f(c)`（`z = c·δ·u`）と漂いだけ `d(c)`（`z = c·δ·d(k)`）。段は `f100`・`f200`・`d100`・`d200`。成分の乱数の引きは `h(c)` と対（同じ `SEED` 20261020）。区間と打鍵は対にならない。
- 段・world・規則は、揺れの world と原因の切り分けの結果を見た後に決めた（探索的・判断 2・3）。world の式・段・PCr の形・読みの表は、どの段の下見 0 よりも前に固定した。
- 開示（判断 9・design §3.0）: 固定の前の 1 回目の試作が本番の seed のままで、本番の下見 0 の列の最初の 40 セッションの L300 の AUC(A_speed) を見た（f100 が天井になりそうなことを含む）。段・world・天井の規則は、それより前の grill で決めてあり、見た後に変えていない。ほかに固定の前に計算した本番の値は無い（試作の 2 回目以降は seed 7770000）。

### 項目 1 の判定の数（L300 / L60 / L1800）

`rd` = `red_detected`、`ru` = `red_unconfirmed`、`g` = green、`u` = `undecidable`（`red_detected_stop_path` はどの段でも 0）。

| 段 | L300 | L60 | L1800 | world の状態 |
|---|---|---|---|---|
| c100（`h(1)`） | rd 8・ru 2・g 14 | rd 6・g 6・u 12 | g 24 | 赤あり |
| f100 | 走っていない | 走っていない | 走っていない | 走っていない |
| d100 | rd 7・g 9・u 8 | u 24 | g 18・u 6 | 赤あり |
| c200（`h(2)`） | rd 4・ru 5・g 15 | rd 1・g 1・u 22 | g 21・u 3 | 赤あり |
| f200 | ru 4・g 4・u 16 | rd 9・ru 6・g 1・u 8 | u 24 | 決まらない |
| d200 | rd 6・ru 3・g 15 | rd 4・g 4・u 16 | g 24 | 赤あり |

- `undecidable` の理由はすべて `weak_stall_pc`（PC-stall がその候補で働かない）。d100 の L300 は smooth-ground・rank の 8 本、f200 の L300 は smooth の 6 本・rank の 6 本・jitter-hold/ground の 4 本。f200 の L1800 は 24 本とも。d100 と f200 では、下見 1 で PC-stall の λ が格子の上端（0.3）に張り付き、「帯に入る λ なし → 格子の上」で選んだ候補が多い（design §8）。
- L300 の赤（`rd`）の候補:
  - d100: raw の `-sub` 3 本・smooth-hold-sub・jitter の `-sub` 3 本。
  - d200: raw の `-sub` 3 本・jitter の `-sub` 3 本（`ru` は smooth-hold-sub・rank-decay-sub・rank-ground-sub）。
  - f200: なし（`ru` は raw-hold-sec と raw の `-sub` 3 本）。
  - 参考（揺れの world）: c100 は raw・jitter の `-sub` 6 本・smooth-hold-sub・rank-decay-sub、c200 は raw の `-sub` 3 本・jitter-ground-sub。
  - 候補ごとには読まない（列は world の間で対にならない・design §3.3 への追加 (i)）。

### (i) 成分の読み（固定した表のとおり）

| c | `h(c)` | `f(c)` | `d(c)` | 読み |
|---|---|---|---|---|
| 1 | 赤あり | 走っていない（f100 は天井） | 赤あり | `not_run` |
| 2 | 赤あり | 決まらない | 赤あり | `unsettled` |

- **どちらの c でも、固定した表の読みは作られなかった。** 表の読みを作るには `f(c)` と `d(c)` がともに「赤あり」か「赤なし」である必要があり、`f(c)` は c = 1 で天井、c = 2 で 24 本のうち 16 本が判定不能だった。したがって、この試行は「`h(c)` の赤は `u` と `d` のどちらから来るのか」に答えていない。
- 言えるのは状態の記述までである。この試行では、`d(1)`・`d(2)` のどちらでも L300 に赤が出た。`f(2)` では赤は出ず、4 本が `red_unconfirmed`、16 本が判定不能、4 本が緑だった。`f(2)` で赤が出なかったことを「倍率では赤が出ない」とは読まない（判定できなかった候補が 3 分の 2 ある）。

| d100 | 7 / 9 / 0 / 8 | 0 / 15 / 1 / 8 | 6 / 9 / 1 / 8 | 0 / 8 / 0 / 16 | 読めない 24 | 読めない 24 |
| c200 | 4 / 15 / 5 / 0 | 0 / 19 / 5 / 0 | 2 / 17 / 5 / 0 | 0 / 24 / 0 / 0 | 3 / 17 / 1 / 3 | 0 / 21 / 0 / 3 |

- c100・c200 は原因の切り分けの読み（このタスクでは回していない・写しただけ）。`Rall` はどの段でも「残る」0。
- `d(c)` は、原因の切り分けの `h(c)` と同じ型だった。落とさない（`none`）では上乗せが「残る」候補があり、`R2` を落とすと読めるモデル（d100 は `lr`・`lrbin`、d200 は 3 つとも）で「残る」が 0 になり、`A2`（`a` の側）を落としても「残る」はほぼ変わらない。見込み（(k)「`d(c)` で赤が出れば、`R2` を落とすと消える」）どおり。
- `f(2)` は「読めない」が多く、型を言えない。

### PCr の読み（このタスクの段だけ・`works` の数 / 24）

| 段 | モデル | level `none` | level `R2` | var `none` | var `R2` | `R2` の読みを使う候補（level / var） |
|---|---|---|---|---|---|---|

| d100 | lrbin | 24 | 24 | 24 | 21（fails 2・unclear 1） | 24 / 23 |
| d100 | hgb | 0（fails 23） | 0 | 0（fails 22） | 0 | 0 / 0（天井） |
| d200 | lr | 24 | 24 | 24 | 22（fails 2） | 24 / 24 |
| d200 | lrbin | 24 | 24 | 24 | 18（fails 2・unclear 4） | 24 / 20 |
| d200 | hgb | 18（unclear 6） | 18 | 22（unclear 2） | 20（fails 1） | 18 / 20 |

- `over` と `unreadable` と `not_calibrated` はどこにも無い（土台の漏れは 0.03 に届かず、λ はすべて較正できた）。
- **`d(c)` の読み（design §3.3 への追加 (j) の読み方）**: `lr`・`lrbin` の `PCrl`（水準）は、`R2` を落としても 24 本すべてで `works` のままだった。この攻撃者は、`R2` を落とした後も、この大きさの `r` の水準の型の手がかりを拾えた。候補の上乗せが `R2` を落とすと消えたことを、「`R2` を落とすと `r` の側が何も見えなくなる」ことでは説明できない。
- `PCrv`（揺れ）も、`R2` を落として大半が `works` のままだった（`lr` で d100 23 本・d200 22 本）。この大きさの点ごとに独立な揺れの手がかりは、`R2` を落としても残りの量で拾えた。それでも候補の上乗せが消えたので、候補の手がかりは PCr-var の揺れとは違う形で `R2` の 2 量に偏っていたか、PCr-var より小さかった（どちらかは分けない）。`fails` になった候補（d200 の `lr` で smooth-ground の 2 本など）について、候補の手がかりが `R2` だけにあったとは読まない。
- `d(c)` で `PCrv` が `R2` で `works` でなくなった候補は、すべて `smooth` の候補だった（`lr`: d100 は smooth-ground-sub が `unclear`、d200 は smooth-ground の 2 本が `fails`。`lrbin`: d100 は 3 本、d200 は 6 本すべて）。`PCrl` は `smooth` でも `R2` で `works` のまま。
- 見込みとの違い: `smooth` の候補の PCr-var は働かないと見込んだ（design §1.3）が、`d(c)` の `none` では `smooth` の 6 本も `lr`・`lrbin` で `works` だった。働かなくなるのは `R2` を落としたときで、平滑の後の揺れの手がかりは主に `R2` の 2 量に乗っていた見込み（推論）。
- hgb は d100・f200 で本番の L300 が天井で、PCr は `fails` だが、余地が無かった可能性があるので読まない（design §3.3 への追加 (j)）。

## 読み（記述・判定の語は前の判定を写すだけ）

- 主な問い（`u` か `d` か）には、この試行は答えていない。`f(c)` が c = 1 で天井、c = 2 で判定不能が多く、固定した表の読みはどちらの c でも作られなかった。
- 漂いだけの world `d(c)` では、c = 1・2 のどちらでも L300 に赤が出て、`R2` を落とすと「残る」が 0 になる型も `h(c)` と同じだった。`r` の側の対照は、`R2` を落とした後も水準の手がかりを拾えた。この試行では、漂いだけでも `h(c)` と同じ型の赤が出た、とまで言える。倍率が赤を生むかどうかは、この試行からは何も言えない。
- 見込み (k) の「`f(c)` は赤が出にくい」は、確かめられていない（判定できなかった）。
- `f(c)` で判定できなかったのは、`A_speed` が強すぎて（L300 の hgb 0.979）停滞の陽性対照 PC-stall が帯に届かず、格子の上端 0.3 でも働かない候補が多かったため。倍率の world を読むには、`A_speed` を弱める作り（c を上げる・別の要約）か、PC-stall の格子を延ばす（PCr で行ったように）ことが要る見込み（推論・採るかは研究者が決める）。
- 人の打鍵の速さの揺れについては何も言わない。world の差を確かめたとも言わない（1 つの seed・列は world の間で対にならない・検出の力が world ごとに違う）。

## 逸脱・気づいたこと

- design の固定の後の変更は無い。§8 は値の追記だけ。
- `d100` の design §8 の行に、L300 の赤を「raw・smooth・jitter の `-sub`（smooth-decay-sub は green）」と書いたが、smooth-ground-sub は `undecidable` で、正しくは「raw の `-sub` 3 本・smooth-hold-sub・jitter の `-sub` 3 本」。§8 の行を直した。
- PC-stall の λ が格子の上端に張り付く問題は、confound world でも同じ規則で起きていた（変えていない）。PCr の格子だけを延ばした（判断 10）ので、`f(2)` では `r` の側の対照は働き、停滞の対照は働かない、という非対称が出た。
