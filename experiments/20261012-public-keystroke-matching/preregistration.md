## 問い

1. 公開の打鍵の記録の加工（公開の現場の加工と候補の加工）は、記録から本文を照合する攻撃に対して、どこまで効くか。正答率を、偶然の水準 1/N と、記録の全長だけを使う攻撃者 A0 の正答率と並べて示す（判断 18）。
2. 効き目は、残す列（位置・語数・区切り・時刻）と攻撃者でどう変わるか。
3. 加工の後に、作文研究の標準の指標はどこまで計算でき、加工の前の値とどこまで一致するか（判断 11・19）。
4. 日本語 IME の翻訳の記録（ENJA15）で、同じ型の照合の正答率は偶然の水準 1/N と A0 からどれだけ上か（差と 95% 区間・判断 5・12・30）。「上回る」と書くのは、1/N との差と A0 との差の両方の区間の下限が 0 を超えるときだけとする。

「加工が効く」とは書かず、「この攻撃者に対して、この N で、正答率が 1/N の何倍か・A0 からどれだけ上か」と書く。

## 脅威モデル（判断 23）

- **場面**: 打鍵の記録を公開する者（研究者・教育データの提供者・コンペの主催者）が、本文を隠す目的で記録に加工を掛けて公開する（[V265] の `q` のマスクが実例）。一方、本文そのものは別の経路で存在する: 同じ作文が別の公開物で本文ごと出ている、教員・採点者・プラットフォームが本文を持つ、作文が授業や投稿で公開されている。
- **攻撃者の知識**: 加工した記録 1 本と、正解を含む候補の本文 N 本（同じ課題の作文）。加工の手順を知る（Kerckhoffs・判断 16）。同じ型の公開データ（加工の前の記録と本文の組）を学習に使える（本実験では、評価する記録と別の課題の書き手の組・判断 29。学習の組の本文は評価の候補に入らない）。本人の過去の文章・言語モデルでの本文の生成・複数の公開物の結び付けは使わない。KeyTAR の公開モデル（A4）は公開の言語モデルを含むので、この脅威モデルの外の参照として別の行に出す。Wagner & Eckhoff の分類では、受動・外部・静的・事前の知識あり（候補の集合と学習用のデータ）。
- **目的と害**: (a) 隠された本文の中身を知る（加工の目的が破られる）。(b) 記録とそこに付いた列（時刻・推敲の過程・得点・他の列）を、本文とその書き手に結び付ける（本文の書き手が分かる場面では、記録の過程が書き手に結び付く）。本実験が測るのは (a)(b) の前提となる「記録 ↔ 本文」の結び付きで、書き手の身元の特定は行わない。
- **N と場面**: N = 10（候補が絞れている: 小さな授業・提出の一覧）、100（学年・講座）、1,000（同じ課題の大きなコーパス）。
- **閉じた世界**: 正解が必ず候補に入る。開いた世界は診断で見る（正解を候補から抜いたときの最小費用の分布との分けやすさ）。

## 揃え（A1・A1'・A2・A3 に共通）

- 1 つの組は「記録の p 区間 ↔ 本文の q 区間」で、(p, q) は (1,1)・(2,1)・(1,2)・(3,1)・(1,3) の 5 通り（`align.py` の `ORDER` と同じ・判断 23）。費用は |記録の和 − 本文の和| ＋ λ ×（p − 1 ＋ q − 1）、λ = 8（調整しない）。
- 同じ費用の経路は `ORDER` の先の組を選び、終点が選べるときは本文の位置の小さい方。
- 終点: 窓の照合は記録の最後まで使い、本文は途中で終わってよい。全文の照合は記録と本文の両方を最後まで使う（終点を (記録の区間の数, 本文の区間の数) に固定・判断 23）。
- R7(p) だけ群の上限を広げる（判断 26）: 抑制で区切りの押下が落ちると記録の 1 区間が本文の複数の区間に当たるので、(1,q) の q と (p',1) の p' の上限を ceil(3/(1 − p))（p = 0.1・0.25 で 4、p = 0.5 で 6）とし、組を (1,1) の後に p' と q の小さい順・同じ大きさは (p',1) を先に並べる。費用の式は同じ。
- 道が無い候補の費用は ∞（選ばれない）。全候補が ∞ なら全候補の同点（1/N）。形 × 攻撃者ごとに、「全候補が ∞」の数と「正解だけが ∞ で、おとりに有限の費用がある」の数を分けて報告する。
- 型の `align.py`（`experiments/20261011-g1-copy-self-trial/scripts/align.py`）は窓の終点だけを実装している。全文の終点の固定・∞ の扱い・R7 の群の上限は包みの関数として足し、合成の記録の検査で確かめる。

- 各形で使えない列を使わない。
- 書き手の識別子は、配布の ID の列の文字列をそのまま使う（種の式の `writer`）。

### 窓での各攻撃者の手順

窓は R0 の区間の列で定める: R0 の記録の連続した k 区間を窓とし、その窓に入る押下だけを各形で取り出して、その形の規則で区間を作り直す（どの形でも同じ押下の範囲から始まる）。

| 攻撃者 | 窓での入力と比べ方 |
|---|---|
| A0 | 窓の押下から全文と同じ数え方で数えた値と、候補の窓の英数字の数（R3-u は全文字の数・R4 は floor(値/w) の和） |
| A1・A1' | 窓では行わない（最終稿を組み立て直す手順で、過程の一部からは最終稿が定まらない） |
| A2・A2-b | 窓の区間の並びと候補の窓の区間の並びを、窓の終点の規則で揃える。窓では A2 を R0・R1・R5・R6 にも当てる（どの形でも押したキーの種類が分かり、区間が作れる。R4 は区間の値そのもの） |
| A3 | A2 の揃え（R3-u は A2-b の区間の揃え）の上で、全文と同じ尤度を足す |
| A4 | 窓の押下の間隔の並びを復元し、候補の窓と比べる |

## 報告する量

- **主な量**: 各形 × 攻撃者 × N × 範囲の正答率と区間、1/N に対する倍率、A0 からの上乗せ（正答率の差と区間）。
- **最も強い攻撃者**: 各形で、適応する攻撃者（A0〜A3・A1'・A2-b のうちその形で使えるもの）の最大。区間はブートストラップの各回の中で最大を取り直して作り、各回で選ばれた攻撃者の割合も報告する。A4 は別の行に出す。
- **形の対比**（判断 18・監査の指摘）: 最も強い攻撃者の正答率の差と区間を、隣り合う形の組で出す: R1 − R2（`q` のマスクから種類への縮約と `activity`・`text_change` の削除）・R2 − R3（位置と語数を同時に落とす）・R3 − R3-u（区切り）・R3 − R3-t(w)（時刻の丸め。時刻を使わない攻撃者では差が 0 なので A3 の差も出す）。どの組も 1 列だけの対比ではなく、組ごとに違う列を書く。時刻をすべて落とした形は置かない（丸めの最も粗い w = 1,000 ms で代える）。
- **副次**: 正解の順位（top-5 の正答率・逆順位の平均）、書き手ごとの正答率の分布（10・50・90 パーセンタイル）、λ = 4・16 の A2（N = 1,000・全文）、開いた世界の診断（最も強い攻撃者の、正解を含む候補の最小費用と正解を抜いた候補の最小費用の分けやすさの AUC・N = 1,000・全文）、組み立て直しの一致・不一致で分けた正答率、道が無かった数。

## ENJA15 の節（判断 5・12）

- 形: R0j（加工なし）・R3j（種類: ローマ字の英字・変換と確定のキー・`[Back]`・句読点の確定・Enter・移動・その他）・R3j-t(w)（keydown の時刻を丸める・w = 10・100・1,000 ms）・R4(w)。keyup が無いので保持時間は使わない。
- 攻撃者: A0 と A2。A1・A1'・A3・A4 は行わない（英語のモデルと最終稿の組み立て直しのため）。
- 除外: 記録か訳文が欠けたセッション／訳文が空のセッション／記録に `Type="IME"` も英字の `Type="insert"` も無いセッション（日本語の入力でない）。数を報告する。
- おとり: 同じ原文の他の訳者の訳文（N は 10 と全員）。N = 10 は他の訳者から重複なしに一様に 9 本（種 `enja_decoys`・記録ごとに 20 回）、N = 全員は全部。訳者が 10 人未満の原文は N = 10 のセルを出さず、数を報告する。同じ訳文は同点として 1/m。訳者の識別は問わない。
- 推定の単位: 訳者を単位にし、原文で層別した百分位のブートストラップ 2,000 回・95%。ENJA15 は KLiCKe より小さく（訳者の数は検査の 5 で数える）、区間は広くなる見込みで、その幅をそのまま報告する。
- 問い 4 に答える量: 全文・N = 全員での A2 の正答率と、1/N との差・A0 との差（差と区間・原文ごとと原文の平均）。「上回る」の語の規則は問い 4 に書いたもの。
- IME の経路の検査（取得の後・本計算の前）: 未確定の文字列の更新・変換の取り消し・確定を含む記録で、R3j の後のどの列（`IMEtext`・`Value` など）にも文字列が残らないことを確かめる。残れば形を直し、逸脱に書く。

- Menlo Report の原則に照らす: 人の尊重（参加者が同意した目的は作文研究で、本研究は公開の記録の保護の評価である。新しい収集をせず、個人を識別せず、人口統計を取得せず、集計だけを出す）・善行（結果は公開する者が加工を選ぶ材料になり、参加者を含む書き手の保護に資する。害は記録 ↔ 本文の結び付きの手順の公開）・正義（参加者に新しい負担を課さず、研究の利益は打鍵の記録を公開されるすべての書き手に及ぶ。費用の要らない公開データとコードで、誰でも同じ評価を繰り返せる）・法と公益の尊重（データの利用条件 [V273] に従い、出典を示す）。
- Kaggle の記録と KLiCKe を突き合わせない（判断 3）。

## AI の使用（論文の節の材料）

- 設計の案・事前登録の文面・予測の案は AI（Claude）が書き、研究者が選んだ（`decisions.md` に、どの問いで研究者が推奨と違う案を選んだかを記録している）。凍結前の攻撃（プレ査読）にも AI の査読者を使い、指摘は一次の資料で裏取りしてから研究者が採否を決めた。プレ査読は研究の証拠に使わない。
- 記録と本文は AI に送らない（上の「記録の扱い」）。

## Open science（論文の節の材料）

- 公開する: 事前登録（OSF の registration・判断 25）・加工と攻撃者と集計のコードと集計の結果（論文の git リポジトリのリリースを Zenodo に置き DOI を付ける・判断 24・25）。Zenodo の記録と論文から OSF の DOI を引く。
- 公開しない: データ（各公開元から取る・再配布しない）・個々の書き手の結果。
- 攻撃のコードの公開の範囲は論文の段で研究者が決める。候補: (1) すべて公開、(2) KLiCKe と ENJA15 の読み込み・加工・評価のコードは公開し、他の公開の記録に直接当てるための読み込みは書かない（[V265] を読み込むコードは判断 3 によりそもそも書かない）、(3) 申し出に応じて共有。

## 結論に使わないこと

- 安全の証明・照合の危険の上限とは書かない（ここで試した攻撃者・閉じた世界に限る）。
- 合格・不合格の判定はしない。
- 書き手の属性による違いは言わない（人口統計を取得しない）。
- 本文の照合の結果を、書き手の身元の特定の結果として書かない。
- ENJA15 の結果を、日本語の自由作文や日本語 IME の記録の一般に広げない。KLiCKe との差を言語や IME のせいにしない（課題・入力の方式・言語が同時に違う）。
- KLiCKe の結果を、他の課題の形（30 分の時間制限・議論文・クラウドソーシングの書き手）や、KLiCKe の配布の段の選別（貼り付けの多い記録などの除外・[V264]）を経ていない記録に広げない。
- 照合という攻撃そのものを新しいと書かない（[V266] [V267] [V268] [V269]）。加工（置換・並べ替え・抑制）そのものも新しいと書かない（[V275]）。新しいと書いてよいのは、本文の分かる公開の打鍵データで、公開の現場の加工の効き目を記録から本文への照合の攻撃で評価したことまでである。
