### 模擬の仮定（実の記録で確かめるのは取得の後の検査 2）

`scripts/synthetic_logs.py` の冒頭に書いた。要点: 押下とマウスの操作が 1 行ずつ（貼り付け・切り取り・取り消し・ドラッグも 1 行）、選択の後の位置は動いた端（[V264] §2.1.5）、修飾キーの保持時間は 0、`up_event` は `down_event` と同じ、Control の行は続く操作の前の状態で記録される、取り消しは打った直後の語を消して Remove/Cut として記録される、次の押下はマウスの操作を離した後に起きる。書き手は 60〜140 語を打ち、語の頭で確率 8%（「編集あり」）・2%（「編集の軽い」）・0%（「編集なし」）で、途中への挿入・途中の削除・選択の削除・置換・コピーと貼り付け・切り取り・ドラッグでの移動のどれかを行い、語を打った直後に確率 1%（同 0.25%・0%）で取り消す。打ち間違い（3%）は BackSpace で直す。操作の数は `results/synthetic_check.json` の `operations_executed`。呼んだ回数（`called:`・編集あり 300 本で、挿入 569・途中の削除 466・選択の削除 450・取り消し 313・コピーと貼り付け 303・置換 277・ドラッグでの移動 152・切り取り 150）と、行に効果が出た回数（`effect:`・空でない貼り付け 292・置換 274・ドラッグでの移動 150・切り取り 149・取り消し 313。空の語を選んだときなどは効果が出ない）を分けて出す。時刻の模擬は 3 つ: 内容に依らない（`free`）・ドラッグの長さが保持時間に出る（`drag`）・文字の組で間隔が変わる（`digraph`・A3 の検査）。量の大きさは模擬の仮定に依る。

## 実装で決めたこと（本計算のコード・データの前・2026-10-13）

事前登録に細部の無いところを、データに触れる前に次のとおり決めた（コードの冒頭の注にも同じことを書いた）。どれも合成の記録だけを見て決めた。

- 行の形: Kaggle の列名に正規化する（`corpus.py`）。KLiCKe の列名の対応は検査 2 で書く。本文の改行は `\r\n` を `\n` にそろえる。
- 能動的に書いた時間: 最初の押下より前のマウスの行は落とす（最初の押下 = マウスでない最初の行）。
- 種の欄: R7(p) の抑制の種は `r7_drop` で `draw` に p（3 つの p は別の流れ）。窓のおとりは `decoys` で `k` に k、`draw` に「始まりの番号:抽選の番号」。陰性対照の B は `negative_control`（`prompt`・`writer`）で、記録の書き手を除いた課題の全員（ID の順）から一様に 1 人。課題での分割は課題名を並べてから `split` で並べ替え、前の 2 つを一方の組にする。500 人は課題ごとに ID の順に並べてから `eval_sample` で 125 人。
- 候補の集合: 課題の除外の後の全員（ID の順）。1 記録につき、その全員との費用を一度だけ計算し、抽選はその添字を引く（結果は抽選ごとに計算するのと同じ）。
- 窓: 有効な始まりが 5 つに満たない記録は全部を使う。おとりの窓の始まりは、おとりの本文の k 語の窓から一様に。窓の本文の文字数（R3-u の A0）は、最初の語の頭から最後の語の終わりまでと、その次の 1 字。
- 間隔: 押下の時刻の差。対数は max(間隔, 1 ms) で取る。
- A3（R3-u と R7 以外）: 揃えは A2 の揃え（記録の区間 ↔ 本文の語）。BackSpace を含まない区間の、数えた押下の隣り合う間隔を、その区間の群の本文の語の英数字に対応させる（群に記録の区間が複数あれば、前の区間の値のぶんだけ後ろの字から）。記録の間隔は全部数え、候補の字が足りない間隔は「全部の間隔」の値で評価する。理由: 合成の記録で、候補の字が足りない間隔を数えない版は、正解ほど項が多く対数尤度の和が小さくなり、R3-t(1000) の A3 が偶然の水準を下回った（N = 10 で 0.044）。直した版では 0.60。
- A3 の文字の組の表: 学習の記録の R0 で、隣り合う字の押下（間に修飾と移動の押下だけ。ショートカット・BackSpace・Delete・マウス・その他で切れる）から作る。R3-t もこの表を使い、丸めた差 d に対して区間 (d − w, d + w) の確率を取る。
- A3 の R3-u: 長さの項の平滑化は、学習の最小 − 50 から最大 + 50 の整数に 1 を足し、その範囲の外も同じ値。

### 分析 1: 語の長さの並びの、候補 N 本の中の一意さ

### 分析 2: 差分プライバシーの形 R-DP(ε)

- 基の形: R3（種類と押下の時刻だけ）。ε = 0.5・1・2・4（判断 56）。2 つの機構に同じ ε を使う。
- (a) 区間の押下の数: R3 の種類の列に区間の規則（登録どおり・ショートカットは数えない）を当て、各区間の数えた英字・数字の押下の数 c に、両側の幾何分布の雑音 Z（P(Z = z) ∝ α^|z|・α = exp(−ε)・感度 1: 隣り合う記録は 1 つの区間の押下が 1 つ多いか少ない）を足す。c' = max(0, c + Z)。Z > 0 なら種類「英字」の押下を Z 個足し、Z < 0 なら区間の数えた英字・数字の押下から min(|Z|, c) 個を一様に（重複なしに）消す。BackSpace と他の行は触らない。足す位置: 区間の「差し込み口」（区間の最初の行の前と、区間の数えた英字・数字の各押下の後）から一様に選ぶ（同じ口に 2 つ以上なら続けて並べる）。足した押下の時刻は、前の行と次の行の時刻の中点（整数に切り捨て。次の行が無ければ前の行の時刻、記録の先頭の前で前の行が無ければ最初の行の時刻）。R-DP では英字と数字を 1 つの種類「英字」として出す（足した押下は「英字」なので、残った「数字」が足した押下でないことを明かし、(a) の保証が崩れる。Codex のレビュー・結果の前・2026-10-13）。保証は各機構をそれぞれの隣り合いの定義（(a) は種類の列の他の部分を固定して 1 つの区間の押下が 1 つ多いか少ない、(b) は行を固定して 1 つの間隔が違う）で見たときのもので、押下を時刻ごと足し引きする隣り合いについて、組み合わせた公開全体が DP だとは主張しない（論文では「DP の雑音を加えた形」と書き、保証の範囲をこのとおりに限る）。
- (b) 押下の間隔: (a) の後のすべての行の隣り合う押下の時刻の差 d を C = 2,000 ms で切り（min(d, C)）、両側の幾何分布の雑音（α = exp(−ε/C)・感度 C: 隣り合う記録は 1 つの間隔が [0, C] の中で違う）を足して、0 未満は 0 にする。時刻は最初の行の時刻から差を足し直して作る。切ることは機構の一部で、2 秒を超える休止は 2 秒になる。
- 順序: (a) の後に (b)。`event_id` は振り直す。窓は、R0 の窓の行の範囲 [a, b] に入る元の行と、足した押下のうち「直後の元の行」が [a, b] に入るもの（区間の最初に足したものは区間の最初の行、区間の途中と最後に足したものは次の元の行）。区間の最後の押下の後に足したものは、その区間を閉じる区切りの行が直後の元の行になる。
- 雑音の引き方: Z = G1 − G2（G1・G2 は独立に numpy の `geometric(1 − α) − 1`）。種は `exploratory_dp`（`prompt`・`writer`・`draw` に `eps:<ε>`）。書き手ごとに ε ごとに 1 回引く。A3 の表のための学習の記録の時刻の雑音（下の「攻撃者」）は、同じ種の用途で `draw` に `eps:<ε>:train` として別に引く（実装のときに書き直した・結果の前・2026-10-13。最初の文「評価でも学習でも同じ記録を使う」は、学習の側は (b) だけを R0 に掛けるので同じ記録にはならず、不正確だった）。これは評価の模擬で、本当の公開の実装ではない（浮動小数の DP の実装の攻撃 [V296]・論文に書く）。
