# source-command-reimagine

Use this skill when the user asks to run the migrated source command `reimagine`.

## Command Template

# /reimagine

## 目的

確証バイアスを排除する。初回プランを意図的に捨て、要件だけに立脚して
再設計した v2 案と並べて比較することで、設計品質を底上げする。

## 前提条件

- [ ] `.steering/[現在のタスク]/requirement.md` が記入済み
- [ ] `.steering/[現在のタスク]/design.md` に初回プランが記入済み
- [ ] **まだ実装に着手していない**（着手後は使用禁止）

---

## Step 1: 初回案の退避

`design.md` の内容を `design-v1.md` に Write ツールでコピー保存する。

> 「初回案を design-v1.md に退避しました。これからゼロから再生成します。」

---

## Step 2: コンテキストの意図的リセット宣言（省略禁止）

> 「これから同じ要件に対して、design-v1.md を **見なかったことにして**
> ゼロから最良案を設計する。初回案の用語・構造・技術選定を自動で
> 引き継がず、requirement.md だけに立脚する。」

---

## Step 3: v2 案の生成

`requirement.md` のみを Read で読み直す（`design-v1.md` は参照しない）。

新しい `design.md` に v2 案を Write で記入:
- 実装アプローチと理由
- 変更対象ファイル
- 既存パターンとの整合性
- テスト戦略

---

## Step 4: 2 案の比較表を作成

`design-v1.md` と `design.md` を Read し、
`.steering/[現在のタスク]/design-comparison.md` に Write で保存:

```markdown
## 設計案比較

### v1 の要旨
[3-5 行]

### v2 の要旨
[3-5 行]

### 主要な差異
| 観点       | v1 | v2 |
|---|---|---|
| アプローチ | .. | .. |
| 技術選定   | .. | .. |
| 変更規模   | .. | .. |
| テスト戦略 | .. | .. |
| リスク     | .. | .. |

### 推奨案
[v1 / v2 / ハイブリッド] — 理由:
```

---

## Step 5: ユーザーへの提示と判断

> 「2 案を比較しました。どれを採用しますか?
> 1. v1（初回案）を採用
> 2. v2（再生成案）を採用
> 3. 両案のハイブリッド（具体的に指定してください）
> 4. どちらも不十分 → もう一度 /reimagine を実行（残り N 回）」

---

## Step 6: 採用案を確定

| 選択   | アクション |
|---|---|
| v1     | `design-v1.md` の内容を `design.md` に Write で上書き |
| v2     | 現状の `design.md` をそのまま維持 |
| hybrid | Edit ツールで `design.md` を修正 |
| 再実行 | Step 1 から繰り返し（**最大 3 回まで**） |

`design.md` 末尾に採用根拠を Edit で追記:

```markdown
## 設計判断の履歴
- 実行回数: N 回目
- 採用: [v1 / v2 / ハイブリッド]
- 根拠: [ユーザーの判断理由]
```

---

## Step 7: 完了通知

> 「破壊と構築が完了しました。/add-feature・/fix-bug・/refactor の Step 3 承認後に続行してください。」

---

## 制約

- 実装着手後は使用しない（副作用の巻き戻しが困難）
- Step 2 の宣言を省略しない（省略すると初回案に引きずられる）
- 「どちらも良い」で終わらせない。必ず採用判断をする
- 繰り返しは最大 3 回。超過したら要件側を見直すようユーザーに促す

## 使用しない場面

- 自明な実装（CRUD 単純追加、文言変更など）
- 小さなリファクタ、ドキュメント更新のみのタスク
- 実装着手済みのタスク
