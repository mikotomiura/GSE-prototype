# 要約を書く依頼文（文献 DB・`docs/literature/refdb/summaries.json` の 1 件）

2026-10-18 に 675 件を書いたときの依頼を起こしたもの。`build.py` が出す `missing_summaries.json` を 100 件ほどの束に分け、束ごとに Sonnet の探索役へ下の「依頼文」を渡す。束の中身（JSON）は依頼文の末尾に貼る。返ってきた JSON は、メインが `merge_summaries.py` で検査してから `summaries.json` に足す（手順は `README.md` の §3）。

依頼文の `{in_path}` と `{out_path}` は、束の入力ファイルと返すファイルの絶対パスに置き換える。

---

## 依頼文

あなたは文献 DB の要約を書く係です。`{in_path}` の JSON 配列を読み、1 件ごとに要約と特徴を書いて、`{out_path}` に JSON で書き出してください。ファイルを書く以外のことはしないでください（ネットで調べない・ほかのファイルを読まない・書き換えない）。

### 入力（1 件）

- `key`: 文献の key（そのまま返す）
- `title`: 著者と題
- `venue`: 出典
- `abstract`: 抄録（3,000 字まで。空のこともある）
- `gse_note`: GSE でこの文献をどう使ったか（接地の文・700 字まで）

### 出力

`key` を名前にしたオブジェクトを 1 つ返す。

```json
{
  "doi:10.xxxx/yyyy": {
    "summary": "…",
    "features": "種類: … ｜ 対象・N: … ｜ 主な結果・数値: …",
    "basis": "抄録"
  }
}
```

### 書き方

1. `summary` は日本語で 80〜160 字。何を調べ、何が分かったか。自分の言葉で書き、抄録から英語でも日本語でも連続 15 語以上を写さない。
2. `features` は「種類: ｜ 対象・N: ｜ 主な結果・数値:」の 3 つを ` ｜ ` でつなぐ。種類は 実験・調査・系統的レビュー・メタ分析・理論・論考・システム・データセット・規格・手引き など。
3. 数値は入力（`abstract`・`gse_note`・`title`・`venue`）にあるものだけを書く。人数や効果量が入力に無ければ「不明」または「（N は抄録に無し）」と書き、推し量らない。
4. `basis` は材料を表す。`abstract` が空でなければ `抄録`、空で `gse_note` から書いたなら `接地のみ`、題しか手がかりが無ければ `題のみ`。
5. `abstract` が空のときは、`summary` を `（抄録なし）` で始め、文献そのものの説明と、GSE でどう使ったかを分けて書く（例「…を扱う文献。GSE では…の根拠として参照」）。原著を読んだかのように書かない。
6. 入力のすべての `key` を 1 件ずつ返す。足さない・落とさない。
7. 記号の ★・⚠️ を使わない。
