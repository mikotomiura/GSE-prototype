# 設計（v2 — /reimagine 再生成案）

## 1. 実装アプローチ

### 1.1 3 層に分ける（★ 下 2 層は model-free）

`requirement.md` のゴール 2 は「2 基線への勝ち幅」を要求しているが、**予測モデルだけを作ると
モデルが外れた瞬間に何も残らない**。`cv-gate-null` が `§3-2` / `§3-3` を **model-free** に保ち、
モデル依存の `§3-4` と分離したのと同じ構造を採る。

| 層 | 問い | モデル依存 |
|---|---|---|
| **L1 記述（ギャップ）** | 沈黙ギャップは「在席×非打鍵」と「入力皆無」にどう分かれるか | ★ **無し** |
| **L2 記述（窓）** | ⚠️★★★ **`cv-gate-null` の 617 窓で、除外された 38%（論述限定 29%）の時間は何に使われていたか** | ★ **無し** |
| **L3 予測** | 在席情報は T0 に対して増分を持つか（2 基線への勝ち幅） | あり |

★★★ **L2 が `§0` の問いに最短で答える。** 「打鍵が薄い窓」を打鍵数でなく**時間の内訳**で見れば、
「席にいて非打鍵作業」「入力皆無」「実は打っている」の比率がそのまま出る。
→ ★ **L3 が全滅しても L2 は結論を持つ。**

### 1.2 `presence` の再構成（3 層すべての土台）

`input/liveness.rs:86-103` の `step()` は純関数で 3 分岐しか持たない:

| 条件 | 挙動 |
|---|---|
| `!session_active \|\| hook_event_seen`（打鍵が来た） | `starved_ms = 0` に**リセット** |
| `!system_input_seen`（OS の最終入力時刻が動かない） | **凍結**（`prev` をそのまま返す） |
| それ以外（OS は入力を見たが打鍵は無い） | `starved_ms += tick_ms` |

→ ★★★ **`starved_ms` は「沈黙のあいだ入力デバイスに触れていた累積時間」そのもの**であり、
**打鍵でリセットされるのでギャップ間で汚染しない**。

観測できる行は `lib.rs:2923`（`if health == prev_health && !rehook { continue; }`）と
`liveness.rs:63-66`（`log_after_ms: 30_000` / `down_after_ms: 120_000`）から **3 種類だけ**:

| 行 | 意味 | 時刻の意味 |
|---|---|---|
| `alive:true, starved_ms≈30000` | 在席×非打鍵が累積 **30 秒**に達した | ★ **この時刻が分かる** |
| `alive:false, starved_ms≈120000, rehook:true` | 同 **120 秒**に達した | ★ 同上 |
| `alive:true, starved_ms=peak` | ギャップが**打鍵で閉じた** | peak を搬送 |

### 1.3 ★★★ 時変共変量にすることでランドマークを不要にする（v2 の核）

⚠️ 「ギャップ開始から L 秒時点で在席か」という**固定ランドマーク**にすると、
(i) L 未満のギャップを全部捨てる、(ii) L の選択が恣意的、という 2 つの損が出る。

→ ★ **離散時間ハザードモデルにして、`presence_state(t)` を時変共変量にする。**

```text
presence_state(t) ∈ { Ok, Suspect, Down }
  Ok      … まだ Suspect 行が出ていない
  Suspect … 30 秒到達行の時刻を過ぎた
  Down    … 120 秒到達行の時刻を過ぎた
```

★★★ **各時点 t で使うのは「t までに出た行」だけ**なので、
**情報の先読みが構造的に起こらない**（ランドマーク不要・打ち切り自然）。

### 1.4 ⚠️★★★ 打ち切りを二値問題に潰さない

⚠️ 「H までに終わったか」を素朴な二値にすると、**セッション終了で切れたギャップ**の扱いで必ず歪む
（捨てれば選択バイアス、「終わらなかった」に倒せば過小推定）。

★ `personalization-and-online-learning.md` `§8.1` の逐語:

> ★ **離散時間・競合イベント下の指標を使う**…**時間依存 AUC / Brier score**…
> **`CIF_rec(H)` の較正（複数の H で）**…
> ⚠️ **単一の二値 C-index を主指標にしない——それは旧定式化の遺物である**

→ ★ **主指標は離散時間ハザードから導く `CIF(H)` の較正と Brier score** とし、
grill が決めた **主 H = 3 分 / 副 H = 10 分** は **その `CIF` を読む地平**として使う（矛盾しない）。

さらに `§3.4` が「**独立打ち切りの仮定を捨てる**」と改訂している以上、G2 と同じ**上下界**を出す:

| 界 | 仮定 |
|---|---|
| **下界** | セッション終了で切れたギャップを**すべて独立打ち切り**とみなす |
| **上界** | 同を**すべて「再開しなかった」**（競合イベント）とみなす |

★ **上下界が同じ結論を与えるときだけ結論を書く**（`§8.2` G2 の判定様式をそのまま借りる）。

## 2. ⚠️ 実データを見る前に凍結する事項（`preregistration.md`）

### 2.1 対象と単位

- **対象**: `session_active` 中の、連続する 2 打鍵のあいだの**無打鍵区間 ≥ 30 秒**
- **単位**: L1/L3 = ギャップ、L2 = `cv-gate-null` と同一の 5 分窓（★ **窓の切り方は再発明しない**）
- **person-period**: ギャップを **10 秒ビン**に離散化（★ `hook_health` の tick が 1 Hz なので 10 秒で十分粗い）

### 2.2 共変量

| 群 | 中身 | 備考 |
|---|---|---|
| **T0（基線 b）** | 直前 30 秒窓の打鍵統計: 打鍵数 / BS 率 / IKI 中央値 / バースト長 / 直前 2 秒超ポーズ数 | ⚠️★ **`feat` 行の `keys`/`bs_keys` は使わない** —— Tier 0 配線は 2026-08-16 で、**Phase1 ログ（P010–P014）より後**。`§5.2` 逐語「旧 NDJSON には本フィールドが無い」。★ **`key` 行の `vk`/`press` から直接数え直す** |
| **presence（提案）** | `presence_state(t)` ∈ {Ok, Suspect, Down}（時変） | 1.3 |
| **時間** | ビン番号のスプラインでない**区分定数**（3 区分: 30–120s / 120s–3min / >3min） | ⚠️ [V83] の「尺度の場当たり変換」を避けるため**事前に固定**する |

⚠️★★ **特徴量の探索・選択・変換を一切しない。** [V83] が挙げる 3 脅威
（小標本 / 強い不均衡 / 尺度の場当たり変換）は Phase1 の条件と 3 つとも一致する。

### 2.3 モデルと評価

- **モデル**: person-period データ上の**ロジスティック回帰**（離散時間ハザード）。正則化なし・調整なし
- **分割**: **leave-one-subject-out**（n=5 → 5 分割）。★ `§8` が subject split を必須にしている
- **主指標**: LOSO 平均の **時間依存 Brier score**（H = 3 分 / 10 分）
- **副指標**: `CIF(H)` の較正プロット / 時間依存 AUC / 生存曲線

| 比較 | 基線 |
|---|---|
| (a) | **多数派（周辺 `CIF`・共変量なし）** ★ [V83] 逐語の要求 |
| (b) | **T0 のみ** |
| 提案 | **T0 + presence** |

→ **「情報があった」= LOSO の Brier が (b) より改善し、かつ上下界の両方で符号が同じ。**

### 2.4 ⚠️★★★ 装置が 120 秒で介入することへの対処（v1 案からの主要な変更点）

`lib.rs:2914`: `if health == Down && !rehook_done_this_episode { rehook = request_reinstall(); }`

⚠️ **120 秒で測定器がフックを再設置する。** フックが本当に死んでいた場合、
**再設置で打鍵記録が復活する**ので、「ギャップが終わった」が
**利用者の再開ではなく装置の復旧**でありうる。⚠️ **主 H = 3 分は 120 秒より後なので直撃する。**

★ v1 案は「`rehook` を含むギャップを丸ごと除外」としていたが、**それだと長いギャップが系統的に消える**
（＝一番知りたい領域を捨てる）。→ ★ **除外せず、装置介入前だけを見る解析を必須の副解析に置く**:

| 解析 | 内容 |
|---|---|
| **主** | 全ギャップ・`Down` を共変量に含む。`rehook:true` の出現数を必ず報告 |
| **副（必須）** | ⚠️★★★ **120 秒で行政的打ち切り**。★ **装置が一度も介入していない区間だけ**で presence の効果を見る |

→ ★★★ **副解析で効果が出れば、それは再設置の産物ではありえない**（時間的に先行するため）。
⚠️ **主で出て副で消えたら、「装置の介入と分離できない」を結論にする。**

### 2.5 除外規則

| # | 除外 | 理由 |
|---|---|---|
| **E1** | セッション境界をまたぐギャップ | `step()` が `!session_active` で `starved_ms` を 0 に落とす（`liveness.rs:95`）＝累積が汚染される |
| **E2** | `probe_assignment` / `realtime_label` / `vignette_response` を含むギャップ | ⚠️ プローブ提示が打鍵を止めさせる＝**装置由来の沈黙**。`phase1-calibration-analysis/notes.md:213` が提示と応答の欠測 11 件を報告 |
| **E3** | `dropped > 0` の行を含むギャップ | ログキュー溢れ＝記録の欠落 |

⚠️ **`rehook` は除外しない**（2.4 のとおり副解析で扱う）。

### 2.6 Stop 条件（★ 実データを見る前に決める）

| 条件 | 帰結 |
|---|---|
| 対象ギャップが 5 名合計 **30 未満** | **Stop**。「測れなかった」を結論に記録 |
| `Suspect` 行を持つギャップが **10 未満** | **L3 を出さない**。L1/L2 の記述のみ |
| 上下界で符号が割れる | **「打ち切りの仮定に依存する」を結論**にし、勝ち幅を主張しない |

## 設計判断の履歴

- **実行回数**: 1 回目（`/reimagine` 2026-08-19）
- **採用**: **v2**（再生成案）
- **根拠**:
  1. ⚠️★★★ **v1 は `personalization-and-online-learning.md §8.1` の逐語
     「単一の二値 C-index を主指標にしない——それは旧定式化の遺物である」に抵触していた。**
     v2 は同 `§8.1` が名指しした指標（時間依存 Brier / `CIF(H)` の較正）に乗る。
  2. ★★★ **v2 は `§0` の問いに model-free で答える層（L2）を持つ。**
     「打鍵が無い窓で何が起きていたか」は窓の時間内訳を出せばそれで答えであり、
     予測モデルの成否と独立に残る。v1 はこれを持たなかった。
  3. ⚠️ **v1 の除外規則 E2（`rehook` 含むギャップを除外）は一番知りたい長ギャップを系統的に消していた。**
     v2 は除外せず 120 秒で行政的打ち切りする副解析で反証する（情報量も反証力も上）。
  4. ★ v2 は **`keys` / `bs_keys` が Phase1 ログに存在しない**ことを特定し
     （`§5.2` 逐語「旧 NDJSON には本フィールドが無い」・Tier 0 配線は 2026-08-16）、
     `key` 行から数え直す形に修正した。v1 のままなら欠測が `0` に倒れて静かに誤っていた。
- **v1 から引き継いだもの**: 「T0 = 沈黙長のみ」の循環の発見と修正 / 除外規則 E1・E2・E3 /
  想定される結末の事前準備。
- **代償と対策**: 離散時間ハザード + person-period 化の実装が重くバグ余地が増える。
  → **S1（手計算照合）と S4（上下界の一致）を必須の自己検査に置いて塞ぐ。**
