## D-1: 弁別対象を「在席×非打鍵入力あり」/「入力皆無」の 2 分割に置く

- **判断日時**: 2026-08-19
- **背景**: `_handoff` §0 は逐語で「**打鍵が無い 4 割の窓で、*何を* 弁別したいのかを先に定義する**」
  と要求している。定義せずに観測を増やすと、`§9` A-Q3 が禁じた「需要の問題を汎用性で解く」に落ちる。
- **選択肢**:
  - A: **在席×非打鍵入力あり / 入力皆無** の 2 分割
  - B: 停滞 / 熟考 / 離席 の 3 分割（`docs/mhd` 系裁定 `15de344` の逐語）
  - C: 離脱 / 外部資源への相談（[P121] mid 帯の未分割 2 つ・`ff59807` が新軸の本命と特定）
- **採用**: **A**
- **理由**:
  - ★ **A だけが既存ログから構造的に決まる。** `input/liveness.rs:95-102` の `step()` は
    `system_input_seen && !hook_event_seen` でのみ進み、`!system_input_seen` では **凍結する**。
    → **「OS は入力を見ているが打鍵が無い」時間が `starved_ms` としてそのまま量になっている。**
  - ★ 素材は `hook_health` 行として **既に NDJSON に出ている**（`logger.rs:1393`）。
    **新規 sensing ゼロ・privacy 境界の再検討ゼロ。**
  - ⚠️ B と C は **正解ラベルが存在しない**。content-free なので「停滞か熟考か」を
    事後に確かめる手段が Phase1 に無い（`cv-gate-null §5-4` 逐語「**「ゼロ打鍵窓＝離席/非打鍵作業」は
    解釈であって観測ではない**」）。
  - ★ A は解釈を挟まない。**測った量（`starved_ms`）の定義そのもの**である。
- **トレードオフ**: 「停滞か熟考か」には答えない。A が答えるのは
  「**その沈黙のあいだ、入力デバイスに触れていたか**」だけである。
- **影響範囲**: 実験の目的変数・`docs/glossary.md`・`§8` への追記文言。
- **見直しタイミング**: B/C の正解ラベルを供給できる収集（想起型プローブ等）が入ったとき。

    mid 3–10min / long >10min）であり、**GSE の外で決まった値**である。
