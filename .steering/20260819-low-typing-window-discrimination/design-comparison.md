# 設計案比較

> `/reimagine` 1 回目（2026-08-19）。v1 = `design-v1.md` / v2 = `design.md`。

## v1 の要旨

固定ランドマーク **L = 60 秒**で「最初の 60 秒以内に Suspect 行が出たか」を二値の予測子にし、
アウトカム「ギャップが H までに終わるか」を **二値分類**として LOSO で評価する。
装置の再設置（120 秒）を含むギャップは **除外規則 E2 で丸ごと落とす**。
`§8` の 2 基線（多数派 / T0）への勝ち幅を主判定にする。
★ v1 の功績は **「T0 = 沈黙長のみ」という grill 由来の循環を発見して潰したこと**。

## v2 の要旨

解析を **3 層**に分け、下 2 層を **model-free** に保つ。
**L2（5 分窓の時間内訳＝打鍵 / 在席×非打鍵 / 入力皆無）が `§0` の問いに最短で答える。**
L3 は **離散時間ハザード**にし、`presence_state(t)` を **時変共変量**にしてランドマークを消す。
打ち切りは `§8.2` G2 と同じ **上下界**で扱う。装置介入は除外せず、
**120 秒で行政的打ち切りする副解析**で「再設置の産物でないこと」を積極的に示す。

## 主要な差異

| 観点 | v1 | v2 |
|---|---|---|
| **解析の構造** | 予測モデル 1 層 | ★ **3 層**（L1/L2 = model-free、L3 = モデル） |
| **`§0` の問いへの回答** | ⚠️ L3 が外れると**何も残らない** | ★ **L2 が単独で答える**（窓の時間内訳） |
| **アウトカムの定式化** | 二値分類（H までに終わるか） | ★ **離散時間ハザード**→ `CIF(H)` を任意の H で導出 |
| **`§8.1` との整合** | ⚠️ **逐語「単一の二値 C-index を主指標にしない」に抵触** | ★ **時間依存 Brier / `CIF(H)` の較正**＝ `§8.1` が名指しした指標 |
| **presence の使い方** | 固定ランドマーク L=60s の**二値** | ★ **時変 3 値**（Ok/Suspect/Down）。先読みが構造的に起こらない |
| **標本の使い方** | ⚠️ ギャップ **≥ 60 秒**に限定（30–60 秒を捨てる） | ★ **≥ 30 秒すべて**が person-period として寄与 |
| **打ち切り** | ⚠️ 明示的な扱いなし（`§3.4`「独立打ち切りの仮定を捨てる」に未対応） | ★ **上下界**（`§8.2` G2 と同じ様式） |
| **装置の再設置（120 秒）** | ⚠️ **ギャップごと除外** → 長いギャップが系統的に消える | ★ **除外せず 120 秒で行政的打ち切りする副解析**で反証する |
| **T0 の作り方** | `feat` 行の `f1..f6` + `keys`/`bs_keys` | ★ ⚠️ **`keys`/`bs_keys` は Phase1 ログに存在しない**（Tier 0 配線は 2026-08-16・ログはそれ以前）と特定し、**`key` 行から数え直す** |

| **変更規模** | 同等（`src-tauri/` ゼロ・`docs/` 追記のみ） | 同等。スクリプトが 4 → 5 本 |
| **テスト戦略** | 自己検査 4 種 + 漏洩 + 回帰 | ★ **8 種**（上下界の一致 S4 を追加） |
| **リスク** | ⚠️ L の選択が恣意的／除外で長ギャップが消える／二値化で打ち切りが歪む | ⚠️ ハザードモデルの実装が重い／person-period 化のバグ余地 → **S1 で手計算照合**して塞ぐ |

## ★ v2 が v1 より優れている決定的な点

1. ⚠️★★★ **v1 は `§8.1` の逐語に抵触していた。**
   「⚠️ **単一の二値 C-index を主指標にしない——それは旧定式化の遺物である**」。
   v1 の二値分類はまさにその形。v2 は `§8.1` が名指しした指標
   （時間依存 Brier / `CIF(H)` の較正）に乗る。
2. ★★★ **v2 は `§0` の問いに model-free で答える。**
   「打鍵が無い 4 割の窓で何が起きているか」は、**窓の時間内訳を出せばそれで答え**であり、
   予測モデルの成否と独立に残る。v1 はこれを持たない。
3. ⚠️★★★ **v1 の除外規則 E2 は一番知りたい領域を捨てていた。**
   120 秒に達するギャップ＝長い沈黙＝低打鍵窓の本体である。
   v2 は除外せず、**装置介入前だけの副解析で反証する**方が情報量が多く、かつ反証力が強い。
4. ★ **`keys`/`bs_keys` が Phase1 ログに無い**ことを v2 が特定した
   （`§5.2` 逐語「旧 NDJSON には本フィールドが無い」・Tier 0 配線は 2026-08-16）。
   v1 のまま実装すると **欠測が `0` に倒れて「実測 0 打」と区別できない**まま T0 を作っていた。

## ★ v1 から引き継ぐべきもの

- **「T0 = 沈黙長のみ」の循環の発見と修正**（v1 §0）。→ v2 でも T0 は直前窓の打鍵統計。
- **除外規則 E1（セッション境界）/ E3（プローブ）/ E4（`dropped`）**。→ v2 の E1/E2/E3 に継承済み。
- **想定される結末の事前準備**（`notes.md` の書き方）。→ v2 §8 に継承・拡張済み。

## 推奨案

★★★ **v2 を採用する。**

理由: v1 は **SSOT の逐語（`§8.1`）に抵触する定式化**であり、
かつ **`§0` の問いに model-free で答える層を持たない**。
v2 はその 2 点を解消したうえで、v1 の功績（循環の発見・除外規則）をすべて引き継いでいる。
さらに v2 は **`keys`/`bs_keys` が Phase1 ログに存在しない**という、
v1 のままなら実装時に静かに誤る欠陥を 1 つ潰している。

⚠️ **v2 の代償**: 離散時間ハザード + person-period 化の実装が v1 より重く、バグ余地が増える。
→ **S1（手計算照合）と S4（上下界の一致）を必須の自己検査に置く**ことで塞ぐ。
