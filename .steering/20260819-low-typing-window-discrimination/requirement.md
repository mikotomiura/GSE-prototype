# 低打鍵窓の観測空間 — T1/T2 昇格判断と沈黙の 2 成分分解

## 背景

### 出発点の問い

> **そもそも「作業中にキーボードを打つ人」は思っているより少ないのではないか。**
> 打鍵以外の観測を増やしてから adapt する、というのが元々の趣旨ではなかったか。

この問いは `.idea/20260801-architecture-signal-and-online-learning.md:154-156` が既に
言い当てており、`personalization-and-online-learning.md:125-133` へ昇格して
「軸の再定義と観測空間の拡張はセットで初めて意味を持つ」という SSOT の記述になっている。
**ゼロから発想し直さない。**

### 実測（`experiments/20260816-cv-gate-null/`・P010–P014・5 分窓 617 個）

| ゲート | 残る窓 | 落ちた窓 | 除外率 |
|---|---|---|---|
| なし | 617 | 0 | — |
| `keydown ≥ 1` | 494 | 123 | 打鍵ゼロが **19.94%** |
| `≥ 100`（G1 凍結ゲート） | 382 | 235 | **38.09%** |

⚠️★★★ **ただし 38.09% は上限側の数字である**（本タスクで確認・`expression-power/data.md:40-42` 逐語）:

> 事前登録は逐語で **「論述セッション」** と限定しており、本実験は **全セッションを入れている**
> （読解・離席を多く含む）。→ **「事前登録の数字を再現した」とは書かない。本実験の CV は上限側である。**

→ ★ **確証解析の母集団（論述セッション）では G1 事前登録 §2.9 が `<100` を 29%・360 窓と記録している。**
**38.09%（617 窓・全セッション）と 29%（360 窓・論述のみ）を混ぜて書かない。**

### 決定的な事実 — 低打鍵窓は打鍵分布の裾ではない

`cv-gate-null §3-4 (b)`: 打ち切り最尤で当てた対数正規から `[1, 100)` の期待窓数を外挿すると、
**情報のある 4 名すべてで H0 予測の 4.7〜19.9 倍の低打鍵窓が観測される**
（B=P011 は `1–99` 窓が 0 で判定に情報を与えない）。
→ **ゼロ打鍵窓とは別に、「席にいて作業しているが打鍵しない」モードが実在する。**

補強（本タスクで発見・handoff 未引用）: `task-scope-detector/notes.md §3` は
`keys/min` が P011=252.0 / P013=21.2 と **12 倍差**である一方、`iki_p50` は 142–185ms で
**ほぼ同一**であることを実測している。→ **差は「打つ速さ」ではなく「打っていない時間の割合」。**

⚠️ ただし `task_kind` は Phase1 全 40 セッションで `argumentative`（分散ゼロ・`data.md:14`）であり、
**「個人差か実タスク差か」は Phase1 データでは原理的に切り分けられない**
（ADR-008 Context の Codex 指摘「『個人差』が実は作業種別差の可能性」に対応する材料が無い）。

### 文献は「モダリティを足せば上がる」を支持していない

| ID | 数値 | 含意 |
|---|---|---|
| [P117] | precision 0.57 / recall 0.48（base rate ≈0.5 = 偶然 +0.07）・しかもアプリ識別子依存 | GSE が禁じた情報に支えられてなお 0.57 |
| [P118] | 計算機操作 74.8% vs 生体 68.3% vs 併用 75.7% | **モダリティ追加の限界利得 +0.9pt** |
| [P120] | アプリ切替を単独主信号で約 78% | 2011 の単独 ≈ 2018 の全部入り |
| [V84] | マウス軌跡 → mind wandering は F1 が無作為基線 +15% 止まり | [P117] と同帯域 |
| [P119] | FlowLight は 12 か国 449 名の実配備・中断 −46% | ★ **T0 + 個人正規化には実配備実績がある。ただし低操作量側の弁別を一度も要求されていない** |

→ **したがって本タスクの問いは「モダリティを足すか」ではない。**
**「打鍵が無い窓で *何を* 弁別したいのか」を先に定義し、それが既存ログで測れるかを実測する。**

### ★★★ handoff の「最初の一手」は SSOT の凍結条件と衝突する（本タスクで発見）

handoff §0 は「`paste`/`keys`/`bs_keys`/`ime_dwell` を推論へ流すのが最初の一手・
新規 sensing ゼロ・privacy 境界の再検討ゼロで着手できる」と書いていた。しかし:

| 出所 | 逐語 |
|---|---|
| `personalization-and-online-learning.md:786` | **「消費者はまだ存在しない（記録のみ）。読む実装へ進む前に G1 の判定を通すこと」** |
| 同 `:1152` | **「例外はここまでであり、P1 本体（episode 化・baseline 更新）を G1 より前に出すことはしない」** |

「推論へ流す」＝ まさにその **「読む実装」** である。
そして **G1 は 1/3 名**（`controlled-friction-task/data.md:4` 逐語「確証標本 1/3 名: P010…
n = 3 で凍結済み（残り 2 名）」）。→ **待つと止まる。**

→ ★ 本タスクは **G1 ゲートに掛からない経路**（本番推論経路に触れないオフライン再解析）を取る。

## ゴール

**2 つを同時に達成する。**

1. **裁定**: `_handoff` §1 が「着手前に裁くこと」と挙げた 4 点を裁き、SSOT に記録する。
2. **実測**: 既存 Phase1 ログのみを使い、**沈黙を 2 成分（在席×非打鍵 / 入力皆無）に分解して
   「次に打鍵が再開するか」を予測できるか**を、`§8` が [V83] 由来で義務化した
   **2 基線（多数派分類器 / T0 baseline）への勝ち幅**として報告する。

### 裁定の内容（grill で確定・2026-08-19）

| # | 論点 | 裁定 |
|---|---|---|
| 1 | 弁別対象を何にするか | **「在席×非打鍵入力あり」/「入力皆無」の 2 分割** |
| 2 | 成果物の境界 | **裁定 + オフライン検証実験**（`src-tauri/` のコード変更ゼロ） |
| 3 | `§8` 段別表の T1/T2 行 | **据え置き**（抑制側のまま）+ 探索的実験トラックを開く |
| 4 | 適格性ゲート `keydown ≥ 100` | **触らない**。低打鍵窓は事前登録の外の探索トラックで扱う |
| 5 | アウトカム | **次に打鍵が再開するか**（recovery proxy・ラベル不要） |
| 6 | 回復地平 H | **主 H = 3 分 / 副 H = 10 分**（[P121] の short/mid/long 境界に接地） |
| 7 | 30 秒未満の沈黙 | **対象外として事前宣言**（`hook_health` が状態変化時のみ出力されるため原理的に見えない） |
| 8 | 合格基準 | **LOSO ablation の勝ち幅を 2 基線に対して報告**（上回らないことも結論） |

詳細と却下案は `decisions.md`。
