## 一次で分かった、引き継ぎの設計案にない事実

1. **受け口とビルダーは別の Apps Script プロジェクト**。受け口=`DriveApp` のみ（`FOLDER_ID`・`SHARED_SECRET`）、ビルダー=`MailApp`/`SpreadsheetApp`/`ScriptApp`（`O1_MGMT_SHEET_ID`）。台帳は Drive＋Sheets＋Mail＋Trigger の 4 つが要るので、**どちらに置いてもスコープが増える**。
2. **日番号は暦日ではなく端末側の通し番号**（`reconcile.rs:553` `next_o1_day_number` = 既存 `.age` 名と台帳の最大値 + 1）。→ 「欠番」は「端末で作られたが届いていない」を意味し、休んだ日は欠番にならない。暦日の欠番より**強い信号**。ただし猶予 48 時間・再送で順序が前後して届くのは正常。
3. **フォルダを見るだけでは「一度も届かない人」が見えない**（G-1 の最有力の失敗）。登録ログ（`O1 登録ログ`・列: 記録日時/種別/P-ID/結果/理由/備考）との突合が要る。記録日時は `"yyyy-MM-dd HH:mm:ss"` の文字列で書かれるが、Sheets が Date に自動変換しうる → 読み側は両方を受ける。
4. **Drive のファイル ID は時刻順である保証がない**。引き継ぎの「前回の最終 ID より新しいものだけ」は成り立たない → 判断 5。

## 判断 1: 置き場所 = 新しい第 3 Apps Script プロジェクト（研究者裁定）
- **決定**: `Form_O1/GSE_O1_Ledger.gs` を**第 3 のプロジェクト**へ貼る。受け口にもビルダーにも触れない。
- **理由**: スコープ追加で稼働中の受け口（Web App）や同意フォームのトリガーが再認可待ちで止まりうる挙動を避ける（⚠️ この挙動自体は**未検証**。避けるための判断であって、起きると断定していない）。
- **却下案**: ビルダーに足す（Drive スコープ追加）／受け口に足す（`doPost` 不変の方針と相性が悪い）。
- **代償**: 貼付先が 1 つ増える。スクリプト プロパティを 3 つ入れ直す（`O1_RECEIVE_FOLDER_ID` / `O1_MGMT_SHEET_ID` / `O1_LEDGER_NOTIFY_EMAIL`）。
- ⚠️ 受け口の `FOLDER_ID` と**同名にしない**（別プロジェクトの取り違えを名前で見分ける）。

## 判断 2: 出力先 = O1 管理シートに新タブ 2 枚（研究者裁定）
- **決定**: 「O1 受領台帳」「O1 途絶」を既存の O1 管理シート（研究者のみ・登録ログと同じ表）へ足す。`参加者ロスター` タブを持つ表なら**書かずに止まる**（ビルダーと同じ歯止めを複製）。
- **却下案**: 専用の別スプレッドシート（ID 設定が増える）。

## 判断 3: 未受領の検知を入れる・N=7 日（研究者裁定）
- **決定**: 登録ログの `ok`/`partial` の P-ID の最古の記録日時から 7 日たっても受領 0 件なら `未受領`。読むのは P-ID と日時だけ（氏名・メールは列に無い）。
- **理由**: 上の事実 3。登録→配布→初回同席→最初の提出の段取り＋猶予 48 時間を見込み、途絶の 5 日より長く取る。
- **注意**: 登録日時は同意フォーム提出時点で、配布（バイナリを渡す）はその後。配布前の人が `未受領` に出うる（誤報は許容し、通知は 1 回だけ）。

## 判断 4: 判定の日数と通知（研究者裁定＋前段の裁定）
- 途絶 = 最終受領から **5 日**（前段の裁定）。欠番 = 欠けた番号より**後ろの番号が届いてから 5 日**たっても埋まらない。未受領 = 登録から **7 日**。
- 通知 = **悪化方向に状態が変わったとき 1 回**（`ok`→異常、または異常の種類の追加）。復帰（異常→`ok`）では送らないが状態は更新する（再び異常になれば再送）。宛先未設定・送信失敗のときは**通知済みにしない**（設定後に 1 回届く）。
- **欠番の 5 日は私の既定**（研究者に聞いていない）。値は定数 1 か所。異論があれば変える。

## 判断 5: 走査は全走査＋既知 ID の除外＋時間予算（私の判断・実測は配備時）
- **決定**: `folder.getFiles()` を全走査し、台帳に既にある Drive ファイル ID をスキップ。240 秒の時間予算で打ち切り、打ち切ったらそのことを台帳タブに明記して次回に持ち越す（冪等なので安全）。
- **却下案**: 引き継ぎの「前回の最終 ID より新しい」＝上の事実 4 で不成立。`searchFiles('modifiedDate > …')` は構文をこの環境で検証できず、**空結果が黙って返ると欠測が見えない**ので採らない。
- **未実測**: 実フォルダでの走査時間。O1 全体で数百本の想定だが**測っていない** → 配備後の通し確認で測る（`o1LedgerCheck()` に所要時間を出す）。

## 判断 6: 受領時刻 = `getDateCreated()`、ただし配備時に実測して確かめる
- 台帳には `getDateCreated()`（受領時刻とみなす）と名前由来のセッション開始日時を**両方**残す。`途絶` は前者の最大値で判定。
- ⚠️ **未確認**: Web App 実行者の保存時刻と一致するか・`.age` 以外がフォルダにあるか。→ `o1LedgerCheck()`（読み取り専用）が名前の形の内訳と両日時の差を出し、実フォルダで 1 回確かめる。`.age` 以外は `対象外の名前` として数え、通知する（G1 の名前の混入も同じ経路で検知できる）。

## 判断 7: セルへの書き込みは常にテキスト形式・PII を持たない
- ファイル名は被験者の端末由来（`doPost` が正規表現で絞るが、フォルダには研究者も置ける）。数式注入を避けるため名前列は `@`（テキスト）形式で書く。列は P-ID・日番号・日時・サイズ・Drive ファイル ID のみ（氏名・メール・URL は持たない）。通知メールにも P-ID と判定だけを書き、**シートの URL を載せない**。

### 判断 8: 「同じ判定のまま中身が悪化した」も通知する ★（3 系統一致）
- **事実**: 旧実装は旗の有無だけを状態に持った。台帳は追記のみなので `対象外の名前` の件数は**単調非減少** → 一度通知すると二度と通知されず、**G1 混入の 2 回目以降を検知できない**。欠番も、旗が立っている間に番号が増えても無通知。
- **決定**: 状態を `旗[:詳細]`（欠番=番号の集合・対象外=件数）にし、**新しい欠番の番号／件数の増加**で通知する。減少・同一では通知しない。
- **却下案**: 毎回通知（読まれなくなる）／旗だけ（上の穴）。

### 判断 9: 走査が打ち切られた回は判定の通知を保留し、運用アラートを 1 回出す ★（2 系統一致）
- **事実**: 打ち切り中の台帳は部分的。判定すると届いている人を「途絶」「未受領」と誤報し、**復帰では通知しない**ので誤報が訂正されない。
- **決定**: `scan.truncated` の回は判定の通知も状態更新もしない。代わりに運用アラート「走査打切り」を 1 回だけ出す（沈黙させない）。次の完全な走査で、保留していた**本当の**異常が届く（テストで P040=誤報・P042=本物 の対で固定）。
- 同じ枠に **「登録ログの日時が読めない行」「台帳の読めない行」**も入れる（バナーだけだと研究者がシートを開かない限り黙って破れる）。

### 判断 10: 検知器が黙って死ぬことを外へ出す ★（cross-reviewer）

- **決定**: 失敗時に研究者宛てに 1 通（同じ原因では再送しない・成功で解消・例外は再送出・本文の長い英数字と URL は伏せる）。⚠️ **トリガーが消えた／認可が切れた場合は本ファイルが走らない** → 配備手順に「トリガーのエラー通知設定を『今すぐ通知』」と「途絶タブの更新時刻を見る」を追記（Apps Script の画面の表記は**未確認**と書いた）。
