# T3 設計 — G1 / O1 の人単位ライフサイクル台帳（設計のみ・実装しない）

> 出所の格: 「一次」= 2026-09-27 に私が開いた行（`preregistration.md` 第 20 版 §「9 マス」「公表物の書き方」／`ADR-034` D4）。
> ⚠️ 実装・配備・シートの作成は**していない**。URL・Google の ID・氏名・メールは書かない。
> ⚠️ 実在の P-ID の状態を私が入力することはしない（研究者が手で入れる）。

## 0. 何のための台帳か

第 20 版は人単位の数え方（**登録 k・解析 m**）と、「やめた」「削除の求め」「未実施」の扱いを固定した。
その**内訳は公表しない**（n=3 では人数の公表が個人を指す）ので、**研究者手元の台帳にだけ**残す必要がある。
T1 の受領台帳は「届いたか」だけを言い、**人の状態は言えない**。→ 本台帳が**人の状態**を持つ（手入力が主）。

## 1. 一次で確かめた制約（設計を縛るもの）

| # | 制約 | 出所（一次） |
|---|---|---|
| 1 | **「やめた」は本人の申し出で確定する**。時刻と**文言**を記録し、**理由は聞かない**。技術的な中断・連絡の途絶・研究者の推測では「やめた」としない | 第 20 版 語の表 / ADR-034 D4-2c |
| 2 | **「中断」と「やめた」は別**。曖昧な発言は「中断」。取り消しは**申し出から連続した同一セッションの内に限る**（⚠️ 一次に根拠が無い運用パラメータ・研究者が採用） | 第 20 版 (iii) |
| 3 | **「削除の求め」は「やめた」とは別の申し出**（やめても削除を求めないことができる） | 第 20 版 語の表 |
| 4 | **完了 = G1 の 8 ブロック（HI4/LO4）を全て実施**。解析 n には適格性ゲート（各ブロック keydown ≥ 100）も要る | 第 20 版 語の表 |
| 5 | **「開始していない」の判定** = 課題ページの開始ゲートもアプリの「開始する」も押していない（**実験者の実施記録で確認**）。⚠️ 打鍵 0 件でも開始ゲート後にクラッシュした人は**開始済み** | 第 20 版 (i) 例外 |
| 6 | **未実施のまま長期の人は名簿から外せる**が、**結果を見る前に・条件や成績と無関係に**決める。**期限の日数は未決**（研究者判断） | 第 20 版 (i) 例外 |
| 7 | **公表物には「登録 k 名・解析 m 名」まで**。内訳（未完了・やめた・削除）・削除の人数/時期/理由は**書かない**。`results/` に P0xx 単位の理由ラベルを**置かない**（`results/` は追跡されうる） | 第 20 版 公表物の書き方 |
| 8 | **O1 に先に参加した人を G1 に入れない**（不可逆）。G1 → O1 は G1 の完了（か本人の「やめた」）後・翌日以降・別の同意・**同じ P-ID** | ADR-034 D4-2 / 2b / 2c |
| 9 | O1 と G1 の記録は**結合しない**（独立標本として数えない） | ADR-034 D4-6 / D4-7 |

## 2. 設計

### 2.1 置き場と閲覧
- **別のスプレッドシート**（Phase1 のロスター・O1 管理シートのどちらとも別）。**研究者のみ閲覧・共有しない**。
- **氏名・メール・連絡先の列を持たない**（P-ID のみ。連絡先は既存のロスターにあり、そこから引く）。
- **repo に置かない**（`results/` にも置かない）。シートの ID・URL は repo に書かない。

### 2.2 構造 = 「状態ログ」（追記のみ）＋「現在の状態」（導出）
状態セルを直接書き換えると、**いつ・何を根拠に**変えたかが残らず、「やめた」のような不可逆に近い判断の監査ができない。
→ **イベントを 1 行ずつ追記**し、現在の状態は**そこから導出**する（T1 の受領台帳と同じ流儀）。

**タブ 1「状態ログ」**（研究者が 1 行ずつ追記。⚠️ 行は消さない・直さず訂正行を足す）
| 列 | 内容 | 入力規則 |
|---|---|---|
| 記録日時 | 入力した日時 | （自動: 手入力） |
| P-ID | `P<数字>` | 形式（正規表現） |
| 研究 | `G1` / `O1` | 2 択 |
| 出来事 | 案内 / 登録 / 配布 / 開始 / 中断 / **やめた（申し出）** / 取り消し / **削除の求め** / 完了 / 未実施のまま据え置き / 名簿から外した | **限定リスト**（自由記入なし） |
| 出来事の日時 | 出来事が起きた日時（記録日時と別） | 日時 |
| 根拠 | 本人の申し出 / 実施記録 / 連絡 / 受領台帳（参考） | 限定リスト |
| 申し出の文言 | 「やめた」「削除の求め」のとき**逐語**（⚠️ 理由は聞かない・書かない） | 出来事が上記 2 つのときだけ必須 |

**タブ 2「現在の状態」**（導出・数式のみ・**スクリプトなし**）: (P-ID, 研究) ごとの最新の出来事・日時、開始済みか、完了か。
**タブ 3「数える」**: 公表用の **2 数だけ**（登録 k・解析 m）。**内訳を出す欄は作らない**。

### 2.3 自動で入れてよいもの / 入れないもの
| 項目 | 方針 | 理由 |
|---|---|---|
| O1 の「最終受領日・受領番号数」 | **参考列として読み取り表示のみ**（T1 の「O1 途絶」タブから）。⚠️ 2026-09-28 追記: 途絶タブは状況ボードになり、**見出しは行 5・データは行 6 から・並びは要対応順**（P-ID 順ではない）。読むときは P-ID で引く（`GSE_O1_Ledger.gs` `O1_LEDGER_DASH_HEAD_ROW`）。状態には**影響させない** | 表示は無害。ただし制約 1（途絶 ≠ やめた） |
| 「途絶」「未受領」→ 状態 | **自動変換しない** | 制約 1・D4-2b（取り違えると不可逆） |
| 「開始」 | **手入力**（実施記録で確認） | 制約 5（受領の有無では決まらない） |
| 「やめた」「削除の求め」 | **手入力のみ**（申し出の文言つき） | 制約 1・3 |
| G1 の受領 | **本設計では自動化しない** | G1 の受け口は別プロジェクト・名前の形も違う（`_block<NN>_`）。要るなら T1 の G1 版を別タスクで |

### 2.4 機械で検知してよい**矛盾**（数式・条件付き書式）
1. **D4-2b 違反**: 同じ P-ID で **O1 の「開始」が G1 の「案内/登録」より前**なら赤（O1 に先に参加した人は G1 に入れない）。
2. **D4-2 違反**: 同じ P-ID で G1 が「完了」でも「やめた」でもないのに O1 の「案内」があれば黄（G1 を先に完了する）。
3. **D4-2c**: 「やめた」の行に**文言が空**なら赤。「取り消し」は同一セッション内の申し出との**時刻差**を表示（判断は人）。
4. **削除の求め**の行があれば、`docs/o1-deletion-ledger.md`（O1）／G1 の記録破棄手順（**未整備・前提条件 8**）へ**誘導する注記**を出す（⚠️ 破棄の実体は本台帳の仕事ではない）。

### 2.5 やらないこと
- 途絶・未受領からの自動遷移、メール送信、被験者への連絡。
- 氏名・メール・理由の記録。「未完了」「やめた」等のラベルを `results/` に置くこと。
- G1 と O1 のデータの結合・対にした集計。

## 3. 研究者に決めてほしいこと（★ 私は埋めない）

1. **「状態ログ＋導出」方式でよいか**（推奨）。代案は「1 人 1 行で状態セルを直接書き換える」— 簡単だが**根拠と日時が残らない**。
2. **O1 の参考列の取り込み方**: (a) 手で写す（推奨・結合ゼロ）／(b) `IMPORTRANGE` で読み取り表示（両シートの共有設定が要る・ID が数式に入る＝**repo には出ないがシート間の結合**が増える）。
3. **未実施のまま長期の期限の日数**（第 20 版で未決）。決まるまで「経過日数」の**表示だけ**を出し、判定はしない。
4. **G1 の受領も台帳化するか**（別タスク・G1 の受け口は別プロジェクト）。
5. 名簿から外す判断の**記録の書式**（第 20 版は「結果を見る前に・条件や成績と無関係に」を要求 → 判断日と、その時点で結果を見ていないことの**自己申告欄**を持つか）。

## 4. 次のステップ（承認後）
1. 研究者が 1〜5 を裁定 → 2. **数式のみ**のテンプレートを作る（スクリプトなし・別承認で配備）→ 3. ダミーの P-ID で矛盾検知（2.4）を**赤・黄・緑**の 3 状態で確かめる（`verify-before-claiming` 5b）→ 4. 実 P-ID は研究者が入れる。
