# 重要な設計判断

判断 0 は引き継ぎ（`.steering/_handoff/next-session-gse-s1-probe-one-tap.md`）で研究者が決めたことの写し。判断 1 以降はこのタスクで決めた。

## 判断 0: 答え方を 1 タップにし、キーで答える（2026-11-25・研究者・引き継ぎより）

- Q3 は大きなボタンの 1 タップで送る。「回答する」を無くす。注記を短くし、優先の規則は初回の説明へ移す。
- Q1・Q2 は Q3 で詰まり・熟考・作業のときだけ、初期値の無い 5 つのボタンで続けて聞く。
- 修飾キー 1 つ＋数字で答える。カードが出ているあいだだけグローバルショートカットとして登録する。
- 3 名の版から当てる。本人の段 1 は今の形で終える（ADR-043 D9）。頻度は変えない。

## 判断 1: クリックも残す（2026-11-25・研究者）

- **選択肢**: A キーを主にしてクリックも残す / B キーだけ
- **採用**: A
- **理由**: ショートカットの登録に失敗したとき（他のアプリが同じ組を使っている等）に、答える手段が無くなるのを避ける。ボタンにキーを書いておけば、キーの覚え方にもなる。
- **影響範囲**: カードのボタンはクリックで送る。「回答する」は無い。

## 判断 2: 修飾キーは macOS ⌥、Windows Ctrl（2026-11-25・研究者）

- **選択肢**: A mac ⌥ / Win Ctrl / B 両方 ⌥・Alt / C 両方 ⌃・Ctrl
- **採用**: A
- **理由**: Windows の Alt は、ホットキーの数字がアプリに届かず Alt の押下と離しだけが届くため、離したときに作業中のアプリのメニューバーにフォーカスが移るおそれがある。mac の ⌃＋数字はミッションコントロールのデスクトップ切り替えと重なることがある。
- **トレードオフ**: Windows の Ctrl＋数字はブラウザのタブ切り替えと重なる（カードの表示中だけ）。
- **見直しタイミング**: 実機で衝突やフォーカスの移動が見えたとき。

## 判断 3: Q3 の後にカードが閉じたら、押した分を残す（2026-11-25・研究者）

- **選択肢**: A 押した分を残す（未回答の Q1・Q2 は null） / B Q1・Q2 が揃わなければ閉じたものとして記録する
- **採用**: A
- **理由**: Q3 は回答として受け取った。Q1・Q2 を聞くかは Q3 の選択肢で決まるので、「聞かなかった」と「答えなかった」は記録から区別できる。
- **トレードオフ**: `realtime_label` の「answered なら q1/q2 は 1..=5 の必須」を緩める（schema・gse-dataset の照合が要る）。
- **影響範囲**: `realtime_label` の書き方、`schema_dto.rs`、replay・calibration_eval・s1_replay の読み方。

## 判断 4: /reimagine を使う（2026-11-25・研究者）

## 判断 5: 答えの打鍵はフックで落とさず、カードの区間で除く（2026-11-25・研究者）

- **背景**: フックの `InputEvent` は修飾キーの状態を持たないので、⌥＋数字・Ctrl＋数字は数字の打鍵として `key` 行と段 1 の押下（`s1_send_press`）に入りうる（impact-analyzer の報告を `hook_macos.rs:640`・`lib.rs:709` で確かめた）。回答の打鍵を除く仕組みは今は無い（事前登録 S1-B3 の「確かめていない」の答え）。
- **選択肢**: A カードの表示から閉じるまでの区間を分析で除く / B 表示中の Atomic と修飾キーの状態をフックで見て落とす
- **採用**: A
- **理由**: 両 OS のフックに手を入れず、Windows の実機確認を待たない。クリックで答える今の形も同じ性質を持つので、区間で除けば両方を同じ規則で扱える。
- **トレードオフ**: 生きている調停器では答えの押下が最後の押下になる。`key` 行には答えの数字が残る。限界として ADR に書く。
- **影響範囲**: 事前登録 S1-B3、ADR。
- 研究者はこの答えで design.md の初案を承認した（Step C）。次は /reimagine。

## 判断 6: 設計は v1 ＋ webview の登録の権限を外す（2026-11-25・研究者・/reimagine 1 回目）

- **選択肢**: v1（backend が途中の答えとキーを持つ）/ v2（押すたびに書く・新しい行種・画面がキーを登録）/ ハイブリッド
- **採用**: ハイブリッド（v1 ＋ overlay の webview の `global-shortcut:allow-register`・`allow-unregister` を外す）
- **理由**: `design-comparison.md` の推奨のとおり。v2 の「落ちても押した分が残る」はカードの表示中の数十秒の落ちに限られ、行種の追加の波及に見合わない。
- **トレードオフ**: カードの表示中にアプリが落ちると、押した分は残らない。

## 判断 7: 答えのキーの登録の更新は別のスレッドから投げる（2026-11-25・実機で固まった）

- **背景**: macOS の実機で ⌥2 を押した直後に開発版が固まった（AX が何も返さない。前の起動にも hang の報告があった）。`sample` で、メインスレッドが global-shortcut のプラグインのハンドラ → `s1_on_answer_key` → `s1_answer_probe` → `run_s1_effects` → `s1_request_answer_keys` → `run_on_main_thread` → その場で `s1_sync_answer_keys` → `unregister` → プラグインの登録表の Mutex を待って止まっていた。メインスレッドから `run_on_main_thread` を呼ぶとその場で走り、プラグインはその Mutex を持ったままハンドラを呼ぶため、自分自身と待ち合う。
- **選択肢**: A 短いスレッドから `run_on_main_thread` へ投げ、走るときに最新の組へそろえる / B ハンドラの中では何も登録・解除せず、tick に任せる
- **採用**: A（`S1_ANSWER_WANT` に最新の組を置き、`s1_sync_answer_keys` は走るときにそれを読む）
- **理由**: 投げた順が入れ替わっても結果が最新の組になる。B は tick（1 秒）まで前の問いのキーが残る。
- **確かめたこと（直した版・macOS・TextEdit を前に置いて合成キー）**: 詰まり ⌥2 → Q1 ⌥4 → Q2 ⌥2 で q1=4・q2=2、離席 ⌥5 は 1 押しで閉じて q は null、⌥0 は dismissed、クリック（作業・Q1 の 3）と ⌥3 の混在で q1=3・q2=3。どの場合も TextEdit に何も入らず、前面は TextEdit のまま。カードの文字（7 択とキーの表示・「あと 2 問」「あと 1 問」・両端の言葉）は AX で読んだ。答えのキーは `key` 行に numeric として残る（判断 5 の想定どおり）。
- **確かめていないこと**: 画面の撮影は今回保存されず、見た目は AX の文字だけで確かめた。Windows（配る前の条件 14）。
- **研究者の段 1 のアプリ**: 研究者が止めた（「段1は消した」）。再開は研究者が行う。

## 判断 8: 答えのキーはカードを出してから 2 分で外し、Windows は Ctrl＋Alt＋数字にする（2026-11-25・研究者）

- **背景**: security-checker の M1・M2。カードには表示の期限が無く（`s1_driver.rs`・`probe_arbiter.rs` で確かめた）、答えるか閉じるまで出たままなので、キーが何時間も他のアプリから奪われうる（ADR の「数十秒だけ」が成り立たない）。Windows の Ctrl＋数字はブラウザのタブや VSCode のエディタの移動でふだん使われ、表示中にそのつもりで押すと本人が選んでいない答えになる。
- **選択肢**: 期限は A キーだけ 2 分で外す / B カードごと期限で閉じる（未回答の理由の値が増える）/ C 今のままで文だけ直す。Windows は D Ctrl＋Alt＋数字 / E Ctrl＋数字のまま / F Windows ではキーを使わない。
- **採用**: A と D（研究者の選択）。
- **理由**: A は記録の形と同意文書の表を変えない（昨夜の実際の回答は 58 秒）。D はふだんの操作と重なりにくい。mac の ⌥＋数字はふだん使う人が少ないので変えない。
- **実装**: `S1_ANSWER_KEYS_FOR_MS = 120_000`。`s1_answer_digits_at` が probe_id ごとに数え始めを持ち、過ぎたら問いが進んでも付け直さない。tick が駆動役のロックの外で `s1_expire_answer_keys` を呼ぶ。Windows は `CONTROL | ALT`、表示は「Ctrl＋Alt＋1」。
- **影響範囲**: ADR-057 D5、同意文書 注 D と配る前の条件 14、フォームのビルダーとテスト、data-privacy の追記、同意の画面の文。Windows の実機での確かめは条件 14 に残る（macOS では Windows の部分がコンパイルされないので CI で見る）。

## 判断 9: 実装の後のレビュー（code-reviewer・security-checker）への対応（2026-11-25）

- **直したもの**:
  - code-reviewer HIGH: 途中まで答えた層化のカードが差し替わると、記録は answered で閉じるのに、再生の差し替えが記録と結べなかった。一次で確かめると「記録の欠け」ではなく「tick の境目」（赤にしない分類）に落ちていた（直す前の往復で 3 件）。再生の側で、記録がその tick に answered で閉じたカードは照合済みとして扱い、写しの `rows_of` に `ProbeAnswered` を加え、往復のテスト（直しを外すと落ちることを確かめた）を足した。ADR D3 の文も直した。
  - code-reviewer MEDIUM: キーが先に入った後のクリックは、内部向けの文言の失敗ではなく、捨てて受け付けた扱いにする。
  - code-reviewer MEDIUM: capabilities に global-shortcut の権限が無いことをテストで縛る。
  - code-reviewer LOW・security-checker L1: 外すのに失敗したキーは一覧に残して次に外し直す。
  - code-reviewer LOW: 画面は listen を張り終えてからキーの状態を読む。
  - security-checker L2: 退けた答えのキーの数字を applog に書かない。
  - security-checker L4・code-reviewer LOW: 消したコマンド名の残った注釈を直した。
  - security-checker M1・M2: 判断 8。
- **限界として ADR に書いたもの**: 差し替えの瞬間のキーが無作為のカードの Q3 に入りうること、「思い出せない」「閉じる」のクリックが問いを照合しないこと、段 1 の版の記録を較正の読みに通すと回答率が低く出ること（段 1 は段 1 の再生で読む）。
- **見送ったもの**: 押したままの印をカードが替わったら消す（code-reviewer LOW・推測）。消すと押しっぱなしの繰り返しが次のカードに入る危険が戻るので、今のままにする。security-checker L3（同意文書の言い切り）は配る前の条件 14 の実機の結果で文を合わせる。
- **判断 8 の実機の確かめ（macOS・直した版）**: カードを出してから約 2 分でキーが外れ（applog に「released after the time limit」）、カードのキーの表示が消えた。外れた後の ⌥1 はふつうの打鍵として TextEdit に入った（「¡」）。ボタンで答えると Q1 に進み、Q1 でもキーは付け直されなかった。

## 判断 10: /cross-review（Claude と Codex）への対応（2026-11-25）

- **実施の条件**: cross-reviewer は code-reviewer を別に起動できず、差分を自分で読んだ。Codex は実際に走ったが、wrapper を使わず同じ固定のパラメータで手で呼び、依頼文に対応済みと既知の未決の一覧を添えた（secrets-filter は REDACTED 0 件）。本線の台帳に 535,763 tokens を記帳した（per_invocation_max の約 18 倍）。
- **直したもの**:
  - Codex X1（中）: Q1 のボタンのダブルクリックで、2 回目が替わったばかりの Q2 の同じ位置のボタンに入り、Q2 も同じ値で記録されうる。画面は問いが替わってから 400 ms は押下を受けない。
  - Codex X2・Claude C3（低〜中）: 期限の後に OS 側の解除が失敗するとキーが残り、ハンドラが期限を見ないので期限の後の答えになりうる。ハンドラは `S1_ANSWER_ACCEPT`（Atomic）だけを見る。期限で印をすぐ下ろし、残ったキーがあれば tick ごとに外し直す。
  - Codex X3（低）: 壁時計を戻すとキーを長く持つ。今 < 付けた時刻なら過ぎた扱い（単調時計はスリープで止まるので使わない）。
  - Claude C1（低）: functional-design・ADR の README・probeTypes の古い記述（Ctrl・表示中だけ）を直した。
  - Claude C2（低）: Ctrl＋Alt は欧州系の配列の AltGr と同じ組。ADR の限界と配る前の条件 14（確認の参加者の配列）に書いた。
- **両者一致**: なし。
