## 設計案比較（/reimagine 1 回目・2026-11-06）

### v1 の要旨
前の試験を写し、最頻値 normalize(S̄) を `rk["self"][name]["mode"]` に置いて既存の `em_rows` をそのまま使う。c = 0 か非有限があれば両方の量を −∞。区間・中央値は ±∞ のまま扱えると見た。P-REPRO は前の試験の summary の全セルに広げる。対照 6・変異 6（m16〜m21）。

### v2 の要旨
同じく写すが、最頻値は `res["mode"]` に分けて置き `rk["self"]` の鍵を変えない。前向きの NaN の道・区間の linear の NaN・(−∞) − (−∞) の NaN・和 0 の行の 0/0 を、numpy のソースと `forward` の行で確かめて個別に塞ぐ。前の試験のコードを別のプロセスで回して `em_writer` が一致することを見る（P-SAME）。npz は中身のハッシュで照らす。対照 8・変異 9（m16〜m24）。

### 主要な差異
| 観点 | v1 | v2 |
|---|---|---|
| 最頻値の置き場 | `rk["self"]` に鍵を足す（前の試験と辞書が変わる） | `res["mode"]` に分ける（前の鍵を保つ） |
| NaN の道 | 前向きの NaN だけ | 前向き・区間の linear・tau_mode × mode_same・和 0 の行の 4 つ（2 つは Mac で確かめた） |
| 押下のある量の −∞ | どこかに 0 があれば両方 −∞ | t0 から後の押下を含むときだけ −∞（未決として研究者に） |
| 和 0 の行 | 見落とし（0/0 で NaN になる） | 0 にして −∞ に数える（未決として研究者に） |
| 前の試験との一致 | P-REPRO（HP Z2）だけ | P-SAME（Mac の合成）＋ P-REPRO（HP Z2） |
| 保存 | 読み戻しの一致（P-SAVE） | 中身のハッシュ（ZIP の時刻で SHA-256 が揺れる）＋ P-SAVE |
| 変更規模 | 小さい | やや大きい（same_old.py・enc・区間の分岐・原因別の人数） |
| リスク | 本計算で NaN が出て門か集計が壊れる | 実装の量が増える分の誤り（対照と変異で捕まえる） |

### 推奨案
v2 — v1 には本計算で NaN を生む道が 2 つ残っていた（区間の linear・和 0 の行）。v2 はそれを塞ぎ、前の試験との一致を Mac の合成でも確かめられる。未決の 2 点（和 0 の行・押下のある量）は研究者に聞く。
