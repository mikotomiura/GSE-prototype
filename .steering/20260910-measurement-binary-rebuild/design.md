# design

## アプローチ（★ 引き継ぎ §3-2 の手順どおり・順序が本質）

⚠️★★★ **ビルドは 8h 計測を汚す**（★ 一次資料: notes.md「CPU 最大 4.30 % は CI 窓の中だけで
出た値。窓を除くと 1.80 %」）→ ★ **計測を止めてからビルドする**。

| # | 手順 | ★ 検証 |
|---|---|---|
| 1 | サンプラ停止 (`pkill -f sample-macos.sh`) | ★ `pgrep` が空 |
| 2 | 途中の 8h 結果を退避（⚠️ 削除しない） | ★ `_aborted-...-v0131/` |
| 3 | `npx tauri build --bundles app --features package --target aarch64-apple-darwin` | ★ exit 0 ＋ `.app` の mtime |
| 4 | ⚠️ **差し替え前に**ゲート（引数 = 新 app） | ★ rc=0・版 0.1.33・`tap_enabled` ≥1・陽性対照 4/4 |
| 5 | 旧 app を退避してから差し替え、GSE 再起動 | ⚠️ `rm -rf` しない・`mv` で退避 |
| 6 | ⚠️ **もう一度**ゲート（引数なし＝稼働中 NDJSON と照合） | ★ rc=0 ＝ 再起動できている |
| 7 | 8h 再測を開始 | ★ `meta.json` の label / `cpu_source` |

## ⚠️ 3 状態で試す（★ 作業規約 3）

- **正常**: 新 app でゲート rc=0
- **不在**: 差し替え前に稼働中と照合すると「別の版」と言う（★ step 5 の直前で観測できる）
- **壊れ**: 陽性対照が 0 なら rc=2（★ 既に前セッションが実測済み）

## 陰性対照

- ★ ゲートの ② は `tap_enabled` 以外の 4 文字列を**先に**見ている。新 app でもこの 4 つが
  出続けることを確認する（⚠️ 出なくなったら検査器かビルドが壊れている）。
- ★ 8h の CPU はレート系 → ⚠️ **`calibrate-cpu.sh` で校正してから**数字を出す。

## テスト戦略

- ★ コード変更は無い（★ ビルドと計測の運用）。`cargo test` は回帰確認としてのみ。
- ★ ゲート自身の `--self-test` があれば通す。
