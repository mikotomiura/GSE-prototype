> ★ 本文書に並ぶのは **実装上どうしても決めざるをえなかった点**と、
> ⚠️ **研究者へ返すべき論点**である。

## ⚠️★★★ 研究者へ返す論点 (★ 実装では決めきれない・確認を求める)

### R-1. ⚠️★★★ O1 の目印を **`meta` 行ではなくファイル名**に置いた

- ★ **やったこと**: O1 のセッションを **`gse_o1_<ts>.ndjson`** という名前で開く。
  `reconcile` はこの名前で O1 の記録を識別する。
- ⚠️ **本来は `meta` 行に `o1_mode` を刻むほうが強い** —— `g1_mode` の先例と同じ形で、
  ★ **提出物そのものから事後に「O1 モードで取れていたか」を判定できる**。
- ⚠️ **そうしなかった理由**: それは `schema_dto.rs` → `schema/current.json` の変更を伴い、
  引き継ぎ §0-3 が **「`schema/current.json` は 1 バイトも変えない」** を
  ⚠️ **最上位の不変条件**に挙げていた (＋ gse-dataset の parity 更新が要る)。
- ★ **失敗様式は同等に fail-loud である**: マーカーが外れれば `gse_<ts>.ndjson` になり、
  ⚠️ **提出候補から外れて研究者に届かない** (無音でデータが増えることはない)。
- ★ **判断を求める**: `o1_mode` を `MetaDto` に足すか (**additive・`Option`・`required` に入らない**ので
  ADR-005 の additive-only は満たす)。⚠️ 足すなら gse-dataset の parity 更新が同時に要る。
  → ★ **足すなら 1 行の変更で済む。**

### R-2. ⚠️★★★ O1 は **`.age.ok` (被験者の送信確認) を求めずに送る**

- ★ **やったこと**: `reconcile` を `CollectionMode::{G1, O1}` で分け、O1 は
  `unsent_age_files` (承認不要) を送る。⚠️ **G1 は `approved_unsent_age_files` のまま**。
- ★ **根拠**: 同意文書 §5 の逐語「**48 時間おいてから暗号化して自動的に研究者へ送ります**」。
  ⚠️ 毎日「送信する」を押させると**その逐語が嘘になる** (引き継ぎ §0-1 の失敗 #3)。
- ⚠️ **失うもの**: `.age.ok` は D-14 で
  「**同意手続きを経ていない人が配布ビルドを起動する**経路を塞ぐ」ために入った (security-checker 指摘)。
  ★ O1 ではその役割を **配布フォルダのマーカー (`o1.mode`)** が担う (G1 の `g1.mode` と同じ形) が、
  ⚠️ **確認の 1 段が減っていることは事実**である。→ ★ 研究者の承認を求める。

### R-3. ★ 日次ローテートの境界を **「ローカル深夜 0 時」ではなく「開いてから 24 時間」**にした

- ⚠️ ローカル時刻の取得には OS 呼び出しが要る (repo に `chrono` は無く、
  `logger::chrono_like_filename` は **UTC 近似**)。★ UTC 深夜は **JST 09:00 = 就業時間の真ん中**で、
  そこでローテート ＋ `engine.reset()` が走る。
- ★ 「開いてから 24 時間」でも **1 日 1 本**は保証され、TZ の曖昧さが 1 つも無い。
- ⚠️ **代償**: 境界がアプリ起動時刻に依存するので、被験者ごと・日ごとに時刻が違う。
  ★ 同意文書 §5 の「1 日ごとにひとまとまり」とは矛盾しない。

### R-4. ★ **日次ローテートでも `engine.reset()` する**

- ⚠️ しないと **新ファイル先頭 30 秒の `feat` 行が前ファイルの状態に依存**し、
  ★ **replay が本番を再現しない** (N-3 と同じ理由)。
- ⚠️ **代償**: 1 日 1 回、任意の時刻で HMM の信念と特徴量窓が冷える。
  ★ O1 は推論に流さない (ADR-011 D4) ので判定量への影響は無いが、
  ⚠️ **`feat` 列を後から解析するときは日境界の直後 30 秒に暖機があることを前提にする必要がある**。

### R-5. ★ **O1 の参加者 ID 入力欄を `RecordingControls` に足した**

- ⚠️ **足さないと自動提出が 1 本も動かない** (`run_reconcile_blocking` が
  「ID 未登録なので何もしない」で帰る)。★ O1 はスタート画面を通らないので、
  G1 の ID 入力欄には**到達しない**。
- ⚠️ **被験者に見せる文言・置き場所は本来 UX の判断**である。★ 最小限
  (「参加者 ID（研究者からお伝えした記号）」・保存済みなら非表示) にした。→ ★ 文言の確認を求める。

### R-6. ★ **O1 ではダッシュボードを常にブラインドにした** (`calibrationMode` 強制)

- ★ 自然作業を数日〜数週間観測するあいだ推定状態が画面に出ていると、
  ⚠️ **被験者はそれを見て行動を変える** (観測したい行動そのものが変わる)。
  ★ `preregistration.md §2.12` がトレイに状態を出さないと決めたのと同じ趣旨である。
- ⚠️ **これは repo に明示の決定が無かった** (ADR-014 / ADR-016 とも O1 の画面表示に触れていない)。
  → ★ 研究者の確認を求める。

## ★ 実装判断 (⚠️ 研究者判断を変えていないもの)

### D-1. ⚠️ `decide_start_action` に O1 の枝を足さず、`o1.rs` に置いた

- ★ **引き継ぎ §1-C の文面**は「`decide_start_action` に O1 の枝を足す」だった。
- ⚠️ ★ **`decide_start_action` は `start_session` 押下専用**の判定であり、
  **O1 は `start_session` を通らない** (通すと `SESSION_START_MS` が立ってプローブが動き、
  `record_session_meta` が走って**未宣言を表せなくなる** = 判断 4b-3 の破れ)。
- ★ G1 の enum と関数に O1 の引数を通すと **G1 の分岐が O1 を知る**ことになり、
  §4-1「分岐はすべて O1 モードの中に閉じる」に反する。
- → ★ **`o1::decide_declaration_action`** に置いた。⚠️ **実質の内容は同じ**
  (ローテートする / G1 のブロック数は数えない)。

### D-2. ⚠️ `App.tsx` の `TASK_KINDS` lock は**そのまま**にした

- ★ 引き継ぎは「`App.tsx` の lock を O1 モードでのみ解除」と書いていたが、
  ⚠️ **O1 ではスタート画面そのものを出さない**ので、その lock は O1 に到達しない。
- → ★ **Phase1 / G1 は論述固定のまま** (ADR-014 判断 5 を満たす)。
  宣言 4 択は `RecordingControls` 側 (`O1_TASK_KINDS`) に置いた。

### D-3. ★ 非 O1 では稼働中インジケータが `paused` を見ない

- ⚠️ 現行 Phase1 / G1 は **一時停止中でも「計測中」と表示する**。
- ★ 直したくなるが、⚠️ それは「G1 / Phase1 の挙動を 1 バイトも変えない」に反する。
  → ★ **別タスクにする** (`o1::recording_active` の doc に明記)。

### D-4. ★ `g1.rs` のソース走査テストを「区間の中に 1 個」へ強めた

- ⚠️ `block_transition_is_held_across_the_whole_block_boundary` は
  `LogEntry::Rotate { new_path }` が **repo 全体で 1 個**であることに依存していた。
  ★ O1 の `o1_rotate` が 2 個目を作るので赤になった。
- ★ テストの doc が指示するとおり **2 つの不変条件が成り立っているか目で確認**した上で、
  「**`start_session` の排他区間の中に Rotate が 1 個**」に書き換えた。
  ⚠️ **緩めていない** —— 位置関係そのものを見るので、むしろ強くなっている。

### D-5. ★ プローブには手を入れなかった

- ★ O1 は `start_session` を通らないので `SESSION_START_MS` は **0 のまま**で、
  プローブスケジューラは**構造的に発火しない** (`lib.rs` の `if session_start == 0 { continue }`)。
- ⚠️ ★ 将来 O1 で宣言に `session_start` を持たせるなら、
  **プローブを自然作業中に出すかどうかは別途研究者判断が要る**。

### D-6. ★ トレイの**初期状態**をログに 1 行残すようにした

- ⚠️ 更新スレッドは**変化したときだけ**書くので、初期値のまま動き続けたセッションでは
  ★ 「トレイに何が出ていたか」を `gse-app.log` から**事後に確認できなかった**。
- ★ O1 は「記録しているのに『記録していません』と出ていないか」を後から検証する必要がある
  (同意文書 §4 の逐語) ので、1 行だけ残す。→ ★ **本タスクの実機検証もこの行で取れた。**

## ⚠️★★★ PR #120 の CI で見つかったもの（2026-08-27）

### F-11. **「両 OS で検算する」テストが、片方の OS でしか通らなかった**

★ `o1::tests::marker_path_matches_the_distribution_layout_on_both_os` が
**macOS の self-hosted CI で落ちた**（★ Windows は緑）。

⚠️ 原因: Windows 形の入力を `C:\dist\O1-app\gse-next.exe` と**バックスラッシュ**で書いていた。
★ **Unix では `\` は区切りではない**ので文字列が**丸ごと 1 コンポーネント**になり、
`parent()` が空を返して `marker_path_for` が `"o1.mode"` を返す。
→ ⚠️★★★ **テスト名が `on_both_os` なのに、両 OS を検算できていなかった。**

★ 直し方: `g1.rs` の同種テストは最初から `/c/G1-app/gse-next.exe` と**スラッシュ**で書いてある。
⚠️ **その先例に揃える**（★ `/` は Windows でも区切りとして解釈されるので、
両 OS で**同じコンポーネント列**になる = これが「両 OS で検算する」の実体）。

⚠️ **区別すべき例外**: `logger::cloud_synced_paths_are_recognised` は
`\` のままでよい —— ★ `looks_cloud_synced` は**文字列包含**であって
**パスのコンポーネント演算をしていない**。⚠️ スラッシュに「直す」と実環境の形を検査しなくなる。
→ ★ 両方のテストに**なぜそう書くのか**をコメントで残した。
