# 調査結果: `.idea/20260909-content-evanescent`（63KB）と `20260909-pigment`（14KB）

> 調査日: 2026-09-11
> ⚠️ これは `.idea` の**抽出**であって SSOT ではない。昇格時は既存 ADR / docs と逐条照合すること。

## ★ 第一候補が入れ替わっている（最重要）

**`Semantic Reagent`（意味試薬）は第一候補から降格**し、「本人が任意の語や短句を材料として渡した場合に限る
**比較条件**」へ後退。代わりに **`Palimpsestic Practice Membrane`（書き換わる実践膜）**が第一候補。

理由（`§17.8` 逐語）:
> 作業内容を読む必要がなく、既存の密な時間データを作品の物性と履歴へ変換でき、
> 低注意のスマホ表現と計測なき身体回帰を一つの物体の生涯として接続できるからである。

★ 理論名と物体名を分けている（`§18.1`）:
- 理論名 = **副詞的実践体 / Adverbial Practice Object**
- 物体名 = **書き換わる実践膜 / Palimpsestic Practice Membrane**

### content-free が構造的に保証される仕組み（`§17.3`）

```
object(t + 1) = dynamics(object(t), feature_trajectory, session_seed, invitation)
```

`feature_trajectory` は **F1/F4 推移・F3/F6 推移・F5 推移・X/Y の軌跡・invitation** という
**既存の content-free 特徴量のみ**。⚠️★★★ **意味試薬と異なり、このオブジェクトは
入力に生テキストや意味処理経路を一切持たない** —— content-free さは新規に設計・検証する対象ではなく、
**既存の GSE content-free 基盤の流用で自動的に成立する**。

### 具体的にどう見えるか（`§17.4`「手つきの相 / Phase of Practice」）

1. 作業開始時: 輪郭の定まらない一つの物質だけが**低い運動量で漂う**
2. 連続的な行為: **繊維が揃い、粒が細い流れをつくる**
3. 修正が重なる: **表層が剥がれて編み直され、痕だけが半透明に残る**
4. 停止: 凍結ではなく**内部に空隙が吊られ、周囲がゆっくり沈降する**
5. 摩擦上昇: ⚠️ **赤色や警告記号にはせず**、局所的な**粘性と張力**として現れる
6. invitation: **一辺が透過し物質がそこから画面外へほどける**。⚠️ 達成演出・命令文なし

**五層構造**（`§18.4`）: 外側の膜（作業世界との接続・遮断・透過）／内部の繊維と粒（微細な反復・連続性）／
折り・剥離・再接着（修正と再開の履歴）／**空隙**（欠如でなく次の変化を保持する**能動的な間**）／
局所的な成長と消散（そのセッション固有の形態生成）

**二層構成**（`§17.5`）:
- **Layer A** = 内容を持たないイデオフォン的シルエット（常時周辺共在・低注意・低推測可能性）
- **Layer B** = 折り・履歴・内部流動を含む実践体（**本人が明示的に開いたときのみ**鑑賞）

## privacy threat model

| # | 脅威 | なぜ GSE に効くのか |
|---|---|---|
| 1 | ⚠️★★★ **embedding inversion** | Morris et al. 2023 `[P1]`「**32-token の 92% を完全復元、臨床記録から氏名も回復**」→「原文を捨てても embedding だけ保存する案は採れない」の直接根拠 |
| 2 | **一時メモリ・異常系の残留**（`§5.1`） | input buffer / tokenizer 複製 / GPU memory / OS swap / debug print / 例外メッセージ / tracing / telemetry / crash dump / 診断収集 / スクリーンショット / バックアップ / clipboard history / IME・アクセシビリティ API 履歴 / モデル runtime cache → ⚠️ **zeroization は best effort であり「一切残らない」と書けない** |
| 3 | **生成物自体が漏洩媒体になる**（`§5.3`） | 聴診器・裁判槌・企業色・特定ロゴに似た形が出れば**作品が意味の記録になる**。抽象化しても「元の topic・固有名詞・アプリを推測できるか」「別セッションを link できるか」等 **5 項目の攻撃者テスト**が必要 |
| 4 | **第三者の権利**（`§5.4`） | 顧客文書・同僚氏名・顔・メール・NDA 対象・著作物。⚠️ **本人が GSE に同意しても、それらを作品化する権限を持つとは限らない**。ADR-012 の画面録画要件と比較して「常時アート生成は**より危険範囲が広い**」 |
| 5 | カーソル/スクロールの軌跡復元性（`§3.1`） | 細かい軌跡は UI 配置・クリック位置・操作癖を再構成できる。ADR-012 が signed dx/dy・絶対座標・イベント単位時系列を禁止 |
| 6 | 簡易幾何処理の非匿名性（`§3.2`） | 一段のぼかし/幾何変換は匿名化でも暗号化でもない。絶対位置除去・回転・並べ替え・空間 pooling まで行うと **content-free へ「収束する」** |
| 7 | ⚠️ **本人性↑と匿名性↑の非両立（肖像とプライバシーの逆説）**（`§8`） | 本人らしさを安定再現できるほど**複数セッションの linkability が上がる**。「**自己認識可能性／外部非連結性の非対称**」という二目的評価軸を提案 |

### content-free 境界を破る経路
- GSE 共通 `InputEvent` / NDJSON / 表現チャネル / スマホへの raw text 直接搭載（`§6` で明示的に禁止対象）
- 選択元アプリの adapter 内で primitive 化しても「token が安全かは別途 threat model で検証」必要
- ⚠️ **生成物（primitive 自体）も「個人データではないと仮定しない」**（`§5.2` 末尾）

### 既存規約との整合
- 「全キーの Unicode 文字」禁止は **`data-privacy` ルール 1 と完全整合**（メモも明示的に引用）
- カーソル軌跡禁止は **`data-privacy` ルール 7 と整合**。⚠️ ただしメモはルール 7 を明示引用せず
  ADR-012 を引用しており、**`data-privacy` SKILL 側への直接参照が欠けている**（相互参照の抜け）
- ⚠️★★★ **embedding inversion は `data-privacy` SKILL に一切記載がない新規知見**。
  SKILL ルール 3 は「VK コード → キー種別カテゴリ変換」レベルの匿名化しか想定しておらず、
  **dense embedding や token 列そのものの危険性に触れていない** → **SKILL への追記候補**
- ⚠️ `docs/agent-shared.md` 技術的制約 7（TSF composition 観測不可）とは**論点が交差していない**。
  制約 7 は「そもそも取得できない」技術的不能性、メモは「取得できたとしても取得すべきでない」policy 側。
  ★ **これは論拠の補強になりうる未活用の事実**（「全打鍵文字の受動取得」は日本語 IME 変換過程に関しては
  現行フック実装で**構造的に不可能**）だが、メモ内では未言及。

## 本人提供 seed の opt-in（検討可の条件）

`§2.3` / `§6` / `§14` より: (1) **自動取得はしない**、選択テキストのショートカット渡しは可
(2) どの内容が処理されたか**本人が知っている** (3) パスワード欄・通知・第三者画面を横断しない
(4) **意味利用への同意と GSE 利用への同意を分ける** (5) 層 A の周縁的常時経路には入れず**層 B 実験に限定**

`§6` の処理境界（8 段）:
```
独立した local transient process（network capability なし・file/log/telemetry 出力なし）
  → sensitive gate（固有名詞・資格情報・長文・引用を拒否。⚠️ 完全検出は保証しない）
  → closed transducer（raw text → 2 operations + 2 materials + 1 phonesthetic quality、embedding 非保持）
  → 破棄境界（best-effort zeroize）
```
⚠️★★★ `§6` 末尾が明記: 「**この構成も現在の `data-privacy` と `domain-adapter-boundary` を満たさない。**
実装前には…**別 ADR、同意文、privacy audit、倫理審査判断が必要**。」

## `20260909-pigment` — 色素/流体の役割分離

### 四層色場モデル（`§2.1`）
**湿潤場 / 移動色素 / 沈着色素 / 基材・繊維** —— 色を「**現在**」と「**履歴**」の物質的分離語彙として導入。

### 「色を state へ直接マップしない」規約（`§2.2`, `§2.3`）

⚠️ **禁止するのは「赤 = 悪化、緑 = 成功、青 = 集中」型の状態色コード化。**

- 代わりに現在状態は「hue より、**湿り・透明度・粒状性・粘性・重なり**へ強く作用させる」
- ⚠️ **彩度 = 報酬、退色 = 失敗という規範も禁止**
- invitation 時は**警告色を足さず**「色素が境界へ移動し、外へ薄まる」
- 文脈由来色素は行為由来の沈着より**早く消す**
- 終端時は「移動色素が膜の外へ流れ、沈着色素も低速で**可読不能な基材色へ戻る**」
- ⚠️ 内容（文脈 seed）については **topic-to-color 対応も禁止**。代わりに
  「**色素粒径の分布・染み込みやすさ・沈殿と再浮遊の比率・透明な層が重なる順序・にじみ縁の幅・
  異なる色素同士の分離しやすさ**」という**物性パラメータの偏り**にのみ反映（`§1.2`）

★ ⚠️ **メモは ADR-022 D1（A-6: 色を主符号にしない）を一度も引用せずに独自にこの規約へ到達している。**
両者の関係（同一規則の別名か、層 A と層 B で別々に成立する規則か）が**文書間で明示されていない**。

### モバイル移植方針（`§4.4`・明記あり）

```
PC art laboratory → 造形文法・shader・texture・parameter range を確定
  → 軽量 mobile renderer へ移植
  → Layer A = 低解像度・低更新の周辺表現
  → Layer B = 本人が開いた時だけ高密度に描画
```

⚠️ **TouchDesigner/Adobe の画面をスマホへ常時ストリーミングする設計は明示的に否定**
