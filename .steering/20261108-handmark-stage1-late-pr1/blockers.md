# blockers（1a 実装中に見つけた、設計に無い分岐・Claude が仮に決めたもの。止まってはいない）

1. gse-replay の ReplayEvent に `handmark_day`（読み飛ばし専用）を足した。`KNOWN_LINE_TYPES` の受理検査が要求するため。
2. `capabilities.rs` の `handmark_day` は段 1 のとき宣言するが、送出元（lib.rs）は 1b。`s1_line_types_are_declared_only_in_s1` の送出元リストには足していない（1b で足す）。
3. 区間指定削除で `handmark_day` の要素だけ消えたとき、`redact_file` の戻り値（落とした行数）には数えない。画面の「消しました（件）」に出ない。数えるかは未決。
4. `Stage::press` は格子を過ぎてから届いた打鍵を刻みに反映しない（ライブの遅れの扱いは 1b で受信側が決める）。state.rs の冒頭に記載。
5. 読めない `.sha256` は `sha_mismatch`、読めない表は `table_broken` に倒した。
6. 検め直し（60 秒）では状態ファイルの書き込みを試さない（起動と日付の変わり目だけ）。
7. 検査用のモジュール `handmark_guard.rs` は `s1_driver_wiring_tests`（lib.rs のソース走査）を壊さないよう、lib.rs でなく handmark_store.rs から `#[path]` で宣言した。

# 判断 4 の直しで見つけたもの（止まってはいない）

- `Stage::advance_to` は未来の巨大な時刻（例 u64::MAX 近く）を渡されると、250ms 刻みで回り続ける。溢れは直したが、上限は設計に無いので入れていない。1b で受信側が時計の飛びを弾くか決める。
- `turn_off` は、開いているときだけ `OffToday` に変わる。すでに別の理由で閉じていれば、その理由を残す（`decide` の優先順どおり）。
- `scrub_state` は累計が無い（状態ファイルが壊れている）ときは何もしない。

# 1b の実装中に決めたもの(設計に細部が無かった所・止まってはいない)

1. 打鍵は、設計の「受信ループで `on_press` を直接」ではなく、段 1 の駆動役と同じ有界のチャンネル(4096)で駆動スレッドへ渡し、スレッドが 250 ms ごとに `on_press` へ流す(分析スレッドをロックで止めない)。
2. 駆動スレッドは段 1 かつ macOS のときだけ起こす。Windows では窓が無いので `handmark_day` の行も書かない。
3. 窓は `setup()` で隠したまま作る(段 1 かつ macOS のとき)。開け閉めは `run_on_main_thread`。閉じるときは窓に `null` を送って描画を止めさせる。
4. 日が変わって窓が出たままのときは、新しい日の描画の種で `Stage` を取り直し、`OpenWindow` を出し直す(窓は冪等に前へ出る)。
5. `delete_time_range` に `app: tauri::AppHandle` の引数を足した(IPC の呼び方は変わらない)。
6. トレイの項目の出し入れは、既存の招待の項目と同じく 1 秒ごとの更新スレッドが行う(状態は `AtomicU8`)。反映は最大 1 秒遅れる。
7. 試作にあった `GSE_HANDMARK_STAGE_SPIKE_PROTECT`(共有の種別をなしにする)は写していない(設計に無い)。

# 判断 9 の直しで決めたもの(止まってはいない)

1. 補助ファイル(状態ファイル)を直せなかった・消せなかったときの「削除の結果に失敗を載せる」は、DTO に欄を足さず、記録の削除と台帳を済ませた後に `Err("…一部の補助ファイルを消せませんでした。もう一度実行してください。")` を返す形にした(画面は既存の `setError` で出す。手跡の語は被験者に見せない)。成功時の件数は画面に出ない。
2. 状態ファイルを消すときは、切っていた日なら先に `handmark_off_<day>` の印を残す(消えると同じ日にまた出てしまうため)。消した後は 1a の `Fresh`(累計 0・`first_shown_day` 無し)になる。
3. 窓の様子は `Pending / Shown / Failed` の 3 値で駆動役に渡す。`Shown` を受けるまで `shown_ms` / `first_shown_day` を積まない。`Failed` で `window_unavailable` で閉じ、60 秒の検め直しでもう一度試す。
4. トレイの項目は、押された項目の文言(更新スレッドが書く `HANDMARK_TRAY_SHOWN`)と駆動役の状態が違えば何もしない。
5. 窓の capability を絞ったので、窓が動くかは画面の確かめ(design-1b §6)で見る。
