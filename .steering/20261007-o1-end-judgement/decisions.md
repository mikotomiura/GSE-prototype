# 重要な設計判断

## 判断 1: 基準（研究者判断 2026-10-07）
起算日 = 最初に記録した日・暦日 21 日・届いた日数は条件にしない（表示のみ）・研究者宛ての通知に含める。
⚠️ 台帳はファイル名しか見られないので、事前登録の「有効日」は判定できない（届いた日の数で代える）。

## 判断 2: 受領台帳（第 3 の Apps Script）に置く
受領ファイルの名前（セッション開始）と登録ログの両方を既に読んでいるため。ビルダー・受け口には足さない（スコープを増やさない）。

## 判断 3: 3 系統のレビュー（code-reviewer・security-checker・Codex）の指摘を反映した（2026-10-08）
- **3 系統一致**: `clear()` してから書く途中で失敗すると研究者の記入（ほかに写しが無い）が消える → `clear()` をやめ、上書き ＋ 余った行を空で上書き。前回の色は書式だけ戻す。
- **3 系統一致**: 名前の日付は端末由来で信用できない（時計の狂い・他人の P-ID を名乗る送信）→ **サーバ側の受領日で挟む**（受領日 + 1 日より後と、受領日の `O1_LEDGER_END_MAX_LAG_DAYS`＝14 日より前は使わない）。登録日より前も使わない。
- **2 系統一致**: 登録ログに無い P-ID は登録日の下限が効かない → **判定しない**（「判定できない（登録が見つからない）」・通知もしない）。
- 見出しが想定と違えば書かない（列の挿入で記入がずれるのを防ぐ）。
- 通知の本文に日付を載せない（「P-ID・判定・日数だけ」の約束）。終了だけの回は途絶の注意を付けない。
- 貼られた日付（Date）を `yyyy-MM-dd` にする。同じ P-ID の行の重複をログに出す。2000 年より前の年を読まない。
- タイムゾーンが Asia/Tokyo でなければ表題に警告。走査の打ち切り・登録ログの読めない行も表題に出す。
- 削除台帳 A-14 に「O1 終了判定」タブと `O1_LEDGER_ENDED` を足した（台帳の tombstone と登録ログの P-ID を空にすることの両方が要る）。
- 残る限界（受け入れた）: 共有の秘密を持つ参加者が他人の P-ID を名乗って送れば、14 日の範囲で起算日を前へ動かしうる（受け口の認証の限界・既存）。読んでから書くまでの数秒に研究者が書いた分は上書きされうる（注意の行に明記）。

## 判断 4: Codex の再レビュー（2026-10-08）の指摘を反映した
- [高] 重複した P-ID の行の、下の行だけの記入が消えていた → 記入を合わせて 1 行にする（空なら下の値・食い違えば「／」でつないで両方残す）。
- [中] 日付が全部除外された人で除外数が出なかった → 起算日が無くても出す（「記録待ち」と区別できる）。
- [中] 14 日より遅れて届いた正当な記録（長いオフライン）で起算日が黙ってずれる → 遅れて除外した数を**別に**出し「起算日を確かめる」と表示する（自動で起算日は変えない＝研究者が確かめる）。
- テスト 289・変異 116 件すべて赤。

## 判断 5: Codex の 3 度目の確認（2026-10-08）の軽い指摘を反映した
