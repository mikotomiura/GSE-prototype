# 要件 — 止めている間の O1 の宣言の行の表示

## 背景
- 「すぐ止める」の件（`.steering/20261031-pause-auto-resume/`）の残り。止めている間も、O1 の宣言の行に「記録中 · 作業の種類: ○○」と出たままで、「選ぶ・変える」も押せた。
- 止めている間の宣言は、バックエンド（`lib.rs` の `o1_rotate`）が「記録を止めているあいだは変更できません」と断る。画面は押せてから断られる形だった。
- 同意文書 §2 の約束は「記録中はいつも、画面のすみに『記録中 · 作業の種類: ○○』と出ている」。止めている間に「記録中」と出すのは、記録していないのに記録中と見せることになる。
- あわせて、`logger.rs` の `RecordingPause` の腕のコメント「書いてから状態を進める。先に進めると止める行自身がゲートに落ちる」が実装（状態を進めてから書く）と食い違っていた。ゲートは match の前にあり、`recording_pause` は止めている間も通るので、実装が正しくコメントが違う。

## ゴール
- 止めている間は、宣言の行が「止めています · 作業の種類: ○○」になり、「選ぶ・変える」は押せず、「作業の種類は、記録を再開してから選べます。」と出る。
- 止めたときに種類の欄が開いていたら閉じる。
- 再開したら元の「記録中」の表示に戻り、選べる。
- logger のコメントを実装に合わせる（振る舞いは変えない）。

## 受け入れ条件
- tsc・cargo fmt・clippy・cargo test が緑。
- O1 の形の開発版で、止める前・止めている間・再開の後の行の文字と、ボタンの押せる・押せないを AX で読み、画面も見て確かめる。止めていた間のデータの行が 0 であること。

## スコープ外
- 非 O1 のトレイが一時停止を表示しない件（`o1.rs` の recording_active・設計どおり）。
- 同意文書・README の文面の変更（約束と食い違わないので変えない）。
- CPU を軽くする作業（別のタスク）。
