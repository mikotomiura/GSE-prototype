# 重要な設計判断

★ すべて 2026-10-02 の grill で研究者が選んだもの。

## 判断 1: 5 つ目の値を足す（ADR-016 判断 4b-2 を覆す）

- **背景**: 4 択では「どれとも決めづらい」自然作業の受け皿が無く、無理な選択か陳腐化した宣言を誘発する
- **選択肢**: A: 足さない（現状）/ B: 「未設定に戻す」ボタンだけ足す（schema 不変）/ C: enum に値を足す
- **採用**: C
- **理由**: B は「忘れた」と「どれでもない」を区別できない。C は本人の明示ラベルになる。O1 未配布で代償が最小
- **トレードオフ**: schema 変更・gse-dataset parity・同意フォーム改訂のコストを払う
- **影響範囲**: schema / logger / heads routing / O1 UI / Form_O1 / 事前登録ドラフト / gse-dataset
- **見直しタイミング**: パイロットで `other` の比率が極端に高く、4 種のデータが痩せたとき

## 判断 2: `other` の間は Writing fallback で採点する

- **選択肢**: A: Writing fallback（`head_id = writing_fallback`）/ B: 推定を止める
- **採用**: A
- **理由**: R3-a（`task_kind` 非依存の `left_observation` 内訳）の入力を途切れさせない。除外は解析側で `task_kind = other` で行える
- **却下案**: B —— 自然作業の大部分が観測から抜ける恐れ
- **トレードオフ**: `writing_fallback` に Creative と Other が同居する（`task_kind` で事後分離できる）

## 判断 3: 語は「その他・細切れの作業」、値名は `other`

- **補足 1 行**: 「メールを読む・調べものなど、どれとも決めづらいとき（メールを *書く* のは「通信文」）」
- **却下案**: 「フリー作業 / `free_task`」—— 境界の説明が同じだけ要り、値名として汎用の `other` の方が後の解析で誤読されにくい

## 判断 4: 同意の改訂は `other` の 1 点だけ（ADR-031 と束ねない）

- **理由**: ADR-031 は Proposed で承認待ち。束ねると本タスクがその承認に縛られる
- **トレードオフ**: 同意フォームの再配備が将来もう 1 回要る可能性がある

## 判断 5: 完了は main マージまで／gse-dataset は対 PR を出す

- **理由**: タグ切り・GAS 再配備・配布タグ記録は配布直前の別タスクにまとめる方が、配布物の版を 1 回で固定できる
