# Phase1 未提出者リマインドメール自動化

## 背景
Phase1 ユーザー検証を実施中。課題を忘れて取り組んでいない被験者がいる。
較正歩留まり (GATE2) が有効ラベル不足で FAIL した既知問題があり、
「忘れ」と「意図的な非実施(休養日)」を分離できると歩留まり分析にも効く。

## ゴール
1. **日次リマインド**: 一日の終わり(20:00 JST)に、本日 F4 未提出の被験者へ
   丁寧なリマインドメールを自動送信。メール内の2ボタンで
   「これから取り組みます / 本日はお休みします」を回答させ記録する。
2. **停滞チェックイン**: 2日連続で提出も応答も無い被験者へ、督促ではなく
   「お困りごとはないですか」という気遣い文面のチェックインを自動送信。

## 判定信号 (既存資産の再利用)
- `refreshRosterStatus()` が6時間毎トリガーで F4 を P-ID 別集計済み。
- `countByPid_("F4", props)` が各人の最終 F4 提出日 (`latest`, yyyy-MM-dd) を返す。
- F4 = セッション後アンケート(毎回) ⇒ 最終 F4 提出日 = 最後に作業した日。
- ロスターに `メール`(col3)・`撤回/除外`(col13)・`F1同意日`(col6) 列あり。

## 決定事項 (ユーザー確定 2026-07-08)
- 停滞しきい値: **2日連続**
- ボタン実装: **Web アプリ (doGet)** — 押下即記録・完了画面表示
- 送信時刻: **20:00 JST** 日次
- 送信方式: **自動送信** (既存 F1 通知 AUTO_SEND=true と同方針)

## 受け入れ条件
- [ ] 本日 F4 提出済みの人には送らない
- [ ] 当日「本日はお休み」を押した人には日次リマインドを送らない
- [ ] 同一人・同一日に日次リマインドを二重送信しない (冪等)
- [ ] 停滞チェックインは throttle し、毎日は送らない
- [ ] 撤回/除外(col13) の人は対象外
- [ ] メールは丁寧・非督促トーン (至急という語を使わない)
- [ ] doGet は pid 正規表現 + action ホワイトリストで検証
- [ ] P-ID のみ URL に載せる (実名・メールは載せない = PII 分離維持)
- [ ] トリガー設置と Web アプリ公開は研究者が手動実行 (誤送信防止)
