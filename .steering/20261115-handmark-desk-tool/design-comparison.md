## 設計案比較（/reimagine 1 回目・2026-11-15）

v2 は、v1 を開かない別のエージェント（Opus）が requirement・decisions・ADR-051・コードだけから作った。v2 が引いたコードの箇所は、メインが一次で確かめた（ライブの種 `handmark_store.rs:422`・4:00 区切り `eh3.rs:353`・`replay_trace` は波紋を捨てる `trace_replay.rs:217`・`FULL_WIND_SPEED = 0.6`・閾値 0.60 の 3 か所）。

### v1 の要旨
gse-replay の新モードが key の行から推定を計算し直し、30 秒の窓ごとに A・状態の特徴・描くコマ（NDJSON の中）・T1（窓の全部の刻みで p_stuck ≥ 0.60）・T2 を書く。t0 はセッションの始まり。漏れは窓の直前の p_stuck の平均を speed・irreg に足す。統計は λ 固定の L2 ロジスティック。

### v2 の要旨
純粋なモジュール `desk.rs` に窓の規則を集め、IO と注入は bin に置く。T1・T2 は記録の feat（系が実際に出した判断）から読み、計算し直したものとの一致 0.95 を門にする（合成は計算し直す）。t0 は `stage_starts` か `max(セッションの始まり, 4:00)`、立ち上がりの 30 秒と一時停止・離席の窓を除く。A を多尺度に厚くし、柔軟さの差を B_perm・A2 で測る（判定には入れない）。合成は「詰まる」の差の一部をキーの種類にだけ出し、A を超える情報が乗るようにする。

### 主要な差異
| 観点 | v1 | v2 |
|---|---|---|
| 当てる対象の元 | key から計算し直す | 記録の feat（系が実際に出した判断）・計算し直しとの一致の門 |
| T1 | 窓の全部の刻みで ≥ 0.60 | 窓の平均 ≥ 0.60（全部の刻みは副として報告） |
| t0 と区間 | セッションの始まり | ライブの `stage_starts`（後期）・規則（前期）、立ち上がりの 30 秒を除く |
| 除く窓 | feat の無い窓だけ | 一時停止・feat が 25 本未満・離席の候補 |
| A の特徴 | 30 秒の要約 | 10・30・60 秒の多尺度（約 22 次元） |
| B の状態 | 6 時点の値・sin/cos(phase) | 30 点の要約・Δphase、drift・layout_seed・生の phase は入れない |
| 画素 | 160×90・16×9 の明るさと差 | 灰の背景で 320×200・16×10 の明るさと動き・折り目の中で PCA |
| 統計 | λ 固定 | λ を内側の検証で選ぶ・B_perm と A2 の診断 |
| 引き直しの方式の選び方 | 合成で幅の広い方 | 合成で真の差を含む割合（0.85）を見る |
| 合成の入力 | 3 つの打ち方を切り替える | 潜在の状態のマルコフ連鎖・詰まるの差の一部をキーの種類にだけ出す |
| 変更規模 | 中 | 中〜大（desk.rs・run_replay の分割・診断） |
| リスク | 陽性対照が効かない恐れ（合成の差が全部 A に出るので、注入しても A を超える情報が乗らない）。T1 が少なすぎる恐れ | 実装が増える。run_replay の分割が既存のモードに触れる |

### 推奨案
v2 — 理由:
- v1 の陽性対照は、合成の打ち方の差が全部打鍵の時刻に出るため、`p_stuck` も A からほぼ当たり、注入した漏れが A を超えにくい。v2 はこの穴を名指しで塞いでいる。
- 当てる対象を「系が実際に出した判断」にするのは ADR-048 D2 の問いに合う。
- `drift`（経過時間）を状態の特徴から外すのは、経過時間の漏れが系の判断の漏れに混ざるのを防ぐ。
- t0・立ち上がりの扱いがライブに近い。
