# 手跡の PR 4 —— 机上の道具（漏れの確かめ）

## 背景

- ADR-051 D3 は、手跡が「許した行為の情報（打鍵の速さ・リズム・止まり ＋ `pointer_bin`）」を超えて系の判断を漏らさないことを、記録から見た目を描き直し、予測器 A（許した情報）と B（A ＋ 見た目）の AUC の差で確かめると決めた（δ = 0.05・日のブロックのブートストラップ両側 90%・3 値の判定・天井）。
- ADR-051 決めずに残すもの 2: 見た目の特徴を画素から作るか状態から作るかは、この PR で両方を作って比べて決める。
- ADR-052 D4・D5: 3 名の記録を開く前までに PR 4。本人の記録の集計は Claude が集計の出力だけを見る。
- PR 1・2・3 は main 済み。再生の契約は `src-tauri/src/analysis/handmark/trace_replay.rs` と `state.rs` の `replay_live`。描画は `src/components/HandmarkStage.tsx` の中にある。
- 前のタスク（`.steering/20261114-handmark-s1-predist-fixes/`）で、区間の削除のあった日の `handmark_day` の量が小さく出ること、一時停止中は量を足さないことが決まった。

## ゴール

本人の記録を開く前に、漏れの判定の道具と条件が固定され、合成の入力で効くことが示されている。

- `gse-replay` の新しいモードが、記録から窓ごとの表（日・A の特徴・B の特徴（状態から）・画素を描くための入力・T1・T2）を決定的に書き出す。
- 描画を純関数に切り出し、画面と机上が同じ関数を呼ぶ。
- `experiments/` の実験として、統計（1 日ずつ抜く交差検証・AUC・日のブートストラップ・3 値・天井・合わせ方）を行う。
- 合成の打鍵列で、漏れを注入した陽性対照が「満たさない」、注入しない陰性対照が「満たす」か「満たす（天井）」になる。
- 記録を開く前に固定すべき条件（conditions.md）を先にコミットする。

## スコープ

### 含むもの
- gse-replay の新モード（窓の表）と、そのテスト（決定性・窓の境・日の境）
- 描画の純関数への切り出し（画面の振る舞いは変えない・画面を見て確かめる）
- 画素からの特徴を作る node のスクリプト
- experiments/ の統計のスクリプト・run.sh・SEED・lockfile・conditions.md
- 合成の入力の生成器と、陽性・陰性の対照
- 入れ子の引き直しと固定の予測の引き直しの比べ（ADR-051 D3 限界 3）

### 含まないもの
- 本人の前期の記録で区間の幅を測ること（次の短いタスク。前期の日数がたまってから・判断 5）
- 3 名の記録
- 停滞の中身の推定器・`level` の実装
- 製品の写像の変更（漏れの注入は机上だけ）
- Windows 版
