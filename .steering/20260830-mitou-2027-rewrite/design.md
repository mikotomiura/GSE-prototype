### ★ 方針: 「アンカー置換」ではなく「全面書き下ろし ＋ 機械検算」

⚠️ 引き継ぎ §6-1 は「Write ツールで Python の置換スクリプトを作り、アンカー出現回数を検算してから

⚠️ **ヒアドキュメントは使わない**（引き継ぎ §6-1: CJK ＋ 記号の混在で壊れる・実測）。
⚠️ **Windows コンソールは cp932** なので、Python を回すときは `PYTHONUTF8=1` を付ける（§6-2）。

### ★ 主役の置き方（研究者決定・`decisions.md` D1）

```text
主役 (A) = Stuck 検出の妥当性 × 介入機会
           ├ 確証核: L0（X/Y 二軸）の順序妥当性のみ（C-index ≥ 0.65 = GATE3）
           └ 探索:   L1 (p_stuck) / L2 (Need 判断性能) / L2' (Opportunity)
第2の柱 (B) = 表現チャネル（(B) 結合側・⚠️ 効果を主張しない・de-risk 先行）
第2の柱 (C) = 計測なき身体回帰（時間 ＋ 復帰・⚠️ GPS/歩数/加速度を本体で使わない）
```

⚠️★★★ **B と C は「柱」と呼ぶが *温度が違う***。★ A は確証ゲートを持ち、
B は `de-risk 先行`（効果を主張しない）、C は Lv3/Lv4 が未実装で Phase1 の実体は WoZ ＋ 自己申告である。
→ ★ **同じ語で並べず、各柱の直後に「何を主張し、何を主張しないか」を必ず書く。**

⚠️ **ADR-017 D7 / 既決 D8** に触れないよう、B を書くときは **必ず出口（Physical Anchor）を併記する**
（★ 表現層のみを headline アームにしてはならない）。
