# 事故記録 — G1-C を作り直して回答と設問の紐付けを失った（2026-08-07）

⚠️ ★ **これは「気をつける」で終わらせてはいけない類の事故である。** 原因は不注意そのものより、
★ **人間の 1 クリックのミスが同意記録を壊せる設計**にあった。対策は §4。

## 1. 何が起きたか（★ 事実だけ）

研究者判断は「**追加分だけ当てる（既存回答を保全）**」だった。にもかかわらず、
Apps Script の**関数セレクタで別関数を選んだつもりが選択が反映されておらず**、
既定の `setupG1Forms` のまま「実行」を押した。

`setupG1Forms` → `buildConsentForm()` → `CLEAR_EXISTING = true` → `clearForm(form)` で
**G1-C の全設問が削除され、作り直された。**

## 2. 被害（★ 実測）

| 対象 | 結果 |
|---|---|
| **G1-C の回答** | ⚠️ **レコード 3 件は残存**（「3 件の回答」表示）。★ しかし**要約タブ・個別タブとも全項目が「回答なし」**＝ **答えと設問の紐付けが失われた** |
| 失われた分量 | ★ 適用前は同意項目に「1 件の回答」が出ていた → **1 件分**。残り 2 件は**以前の再構築で既に切れていた**（＝この事故は初犯ではない） |
| G1-M / G1-S | 回答 **0 件**だったため損失なし（再構築のみ） |
| 運用管理シート | ★ **無傷**（`G1 実施トラッキング` の P009 行・ヘッダとも残存） |
| フォーム URL / ID | ★ **不変**（固定 ID 方式）。配布済みリンクは有効 |

⚠️ ★ **Google Forms に回答の版履歴は無い。UI から戻す方法は見つからなかった。**

★ 研究上の影響は限定的である（★ **G1 本実施はまだ開始していない**・研究者確認 2026-08-07）。

## 3. ★ なぜ起きたか（2 層）

1. **近因**: セレクタの選択が反映されないまま実行した。
   ⚠️ ★ **選択が変わったことを確認せずにクリックした。**
   → ★ その後の検証で、**このセレクタは自動操作を 4 回とも受け付けない**ことが判明した
     （option をクリックしても、キーボードで Down×4 → Enter しても `setupG1Forms` のまま）。
     ★ **たまたま滑ったのではなく、この操作系は自動化に対して壊れている。**
2. ⚠️★★ **遠因（本質）**: `setupG1Forms` が**回答の有無を見ずに `clearForm()` を呼ぶ**。
   ★ 「同意記録を消す操作」が**確認なしの 1 クリックで到達できる場所に置かれていた。**

## 4. ★ 対策（実装済み）

| # | 対策 | 状態 |
|---|---|---|
| **A** | `assertSafeToRebuild_()` を追加し、**3 つの `clearForm()` 呼び出し全部**の直前に置いた。回答が 1 件でもあれば **throw して止まる**（fail-closed） | ✅ 実装・Apps Script へ配備済み |
| **B** | 意図した作り直しは `ALLOW_REBUILD_WITH_RESPONSES = true` の**明示フラグ**でのみ可能。★ ログに警告を出す | ✅ |
| **C** | ⚠️ 回答数を**取得できなかった場合も止める**（「確認できない」を「0 件」と読み替えない） | ✅ |
| **D** | 回答を保ったまま文面を更新する `migrateConsentForm()`（**削除しない**・idempotent）と、実物を読んでズレを報告する `checkConsentFormParity()` | ✅ |
| **E** | `Form_G1/guard_test.cjs` — ガードの赤/緑を**スタブで実測**（4 ケース。★ **0 件は通す陽性対照つき**） | ✅ |
| **F** | `run.sh §4` に E を接続。★ **node 不在なら「飛ばす」ではなく赤にする** | ✅ |

### ★ 検査が空回りしていないことの実測

- 正常版: `rc=0`（4 / 4 ケース期待どおり）
- ★ **ガードを骨抜きにした版**: `rc=1`（「回答 3 件 / 既定」「getResponses が例外」の 2 件が NG）
- `run.sh` 経由でも **RED を実測**したのち復元し、`.gs` の SHA-256 が配備物と一致することを確認

## 5. ⚠️ この事故から一般化できること

- ★ **UI の状態が変わったことを確認せずに、次の破壊的操作へ進まない。**
  ⚠️ 「選んだつもり」は状態ではない。**読んで確かめたものだけが状態である。**
- ★ **保存・実行の成否をヘッダー表示で判断しない。**
  ★ 実際、後続の作業で「変更が保存されていません」のまま保存が通っていない事例を踏み、
  **リロードして実体のハッシュを見て初めて**未保存だと分かった。
- ⚠️ ★ **自動化が効かない操作系がある。** 4 回失敗したら**その操作の自動化をやめる**
  （事故を起こしたのと同じ操作を繰り返すのが最悪手）。
- ★ **取り返しのつかない操作には、人間の注意ではなくコードのガードを置く。**
