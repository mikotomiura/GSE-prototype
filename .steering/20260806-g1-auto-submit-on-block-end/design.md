## 0. ★ この要件の本質は何か

`requirement.md` のゴールは「被験者が操作しなくても届く」だが、⚠️ ★ **本当に守るべきものは
そこではない。** 受け入れ条件に 2 回出てくる **「★ データは失わない」** の方である。

★ 背景を見ればはっきりする: P-1 は **2 回とも一次資料が揃わなかった**。
mac 回は生ログが 2 本しか残らず、Windows 回は `.age` が 1 本もできなかった。
⚠️ ★ **どちらも「その瞬間に取るべき動作を取り損ねた」型の失敗**である。

→ ★ したがって設計の中心に置くべき問いは
**「ブロック終了イベントを取りこぼしても復旧できるか」** である。

⚠️★★ **これを「ブロック終了時に送信処理を起動する」と読むと、同じ穴をもう一度掘る。**
イベント駆動は、★ **イベントを取りこぼした瞬間にそのブロックが永久に失われる**:

- アプリが落ちた / 電源が切れた
- 子プロセスの起動に失敗した（PATH・権限・アンチウイルス）
- 送信中に回線が切れ、その回の処理が中断した

`preregistration.md §3.6` は**ブロックの事後除外を禁じている**。
★ **「1 ブロック落とした」は、この研究では回復不能な損失である。**

## 1. ★★ 採用する構造 — 収束型（reconciler）

★ **「いま何をすべきか」をイベントから決めず、毎回ディスクの状態を見て決める。**

```
毎回、以下を突き合わせて「足りない仕事」だけをする（何度走らせても同じ状態に収束する）:

  ① 閉じ終わった NDJSON      … session_end を持つ、いま書いていないファイル
  ② それに対応する .age       … 無ければ作る（匿名化 → 暗号化）
  ③ それに対応する .sent      … 無ければ送る（成功したら .sent を置く）

  未送信 N 件 = ② が在って ③ が無いものの数   ← ★ 別カウンタを持たない
```

### ★ なぜこれが要件を満たすか

| 要件 | この構造での満たし方 |
|---|---|
| ★ データを失わない | ★ **取りこぼしという概念が無い。** 次に走ったときに「まだ ② が無い NDJSON」として必ず拾われる |
| 失敗したら再送 | ★ **再送という特別な処理が要らない。** `.sent` が無ければ送る、それだけ |
| 未送信件数を出す | ★ **状態を数えるだけ。** カウンタを持たないので**ズレようがない** |
| ブロックごとに 1 本 | ①が 1 ブロック 1 ファイルなので自然に 1 対 1 |
| `.age` を消さない | ★ 送信済みの印は**別ファイル (`.sent`)**。`.age` には触らない |
| 送るのは `.age` だけ | ③ の入力は ② の出力に限る。★ **生 NDJSON を読む経路が送信層に無い** |

### ★ 起動のきっかけは「ヒント」でしかない

- ブロックの自動終了時
- アプリ起動時

⚠️ ★ **どちらを取りこぼしても正しさは壊れない**（次の機会に収束する）。
★ これが v1 的なイベント駆動との決定的な差である。

> ### ⚠️★ 訂正（2026-08-08・実装時）
>
> ★ 当初ここには「**何度走っても安全なので二重起動の心配をしなくてよい（べき等）**」と書いた。
> ⚠️ **これは言い過ぎだった。**
>
> `.age` の作成そのものは確かにべき等だが、★ **ブロック番号の採番はそうではない**。
> 2 つの収束器が同時に走ると、`next_block_number` の読み取りと `.age` の作成の間の窓で
> **別々の NDJSON に同じ番号が付く**（`decisions.md` **D-12**）。
> ⚠️ 起こりうる条件は現実にある: 送信が詰まると起動時の 1 回がブロック 1 本（5 分）より
> 長く走りうる（タイムアウト 180 秒 × 未送信本数）。
>
> → ★ 排他ロック（`reconcile.lock`）を置いた。**取れなかったら何もせずに帰る**。
> ★ 収束型なのでやらなかった仕事は次の機会に必ず拾われる = **対処が「帰るだけ」で済む**。
> この点だけは収束型の主張どおりに働いた。

⚠️ ★ **ブロック中には走らせない**（測定中の端末に負荷をかけない）。

## 2. どこに置くか

★ `age` は `package` feature で**盲検アプリ本体から隔離**されている
（`gse-package` / `gse-unpack` / `gse-submit` が `required-features = ["package"]`）。
② が `age` を使う以上、★ **reconciler は `package` 側のバイナリに置くしかない。**

→ **`gse-submit` に `--reconcile` を足す**。アプリ本体はそれを起動するだけ。

| 得られるもの | 中身 |
|---|---|
| 依存の隔離を壊さない | ★ **HTTP クライアントも `package` feature の中**に入れる。盲検アプリ本体の依存は 1 つも増えない |
| CSP を触らない | ★ 送信は Rust の別プロセス。⚠️ フロントから `fetch` すると `connect-src` の追加が要り、`data-privacy` ルール 5 と正面衝突する |
| 止められる | ★ 設定から endpoint を外せば ② までで止まる（**`.age` がローカルに貯まる**状態で成立）。⚠️ **再ビルド不要** |

⚠️ ★ **起動できなかったことを検知する経路が要る。**
「起動したつもりで動いていない」は `silent-failure-in-guard-scripts` の型そのもの。
→ ★ アプリは spawn の失敗をログではなく**画面（未送信件数の隣）に出す**。

## 3. ★ ブロック番号をどう持つか

受け入れ条件は「ファイル名に **ID とブロック番号**が入ること」。

### 採用: **`.age` を作るときに sidecar の manifest へ確定させる**

```
GSE-submissions/
  P012_block01_<stamp>.age
  P012_block01_<stamp>.age.sent      ← 送信済みの印（★ .age は消さない）
  manifest.jsonl                     ← どの NDJSON が何番目だったか（append-only）
```

- ★ 番号は **`.age` を作る時点**で、その参加者の manifest の**次の番号**として確定する。
  ⚠️ ★ **アプリのメモリ上のカウンタを使わない**（再起動で 0 に戻るため）。
- ★ **append-only**。⚠️ **既存の行を書き換えない**（`citation-ssot` と同じ思想）。
- ⚠️ ★ **同じ番号のファイルが既に在るなら上書きせず別名にし、画面に出す。**
  ★ 黙って上書きするのが最悪である（1 本も失えない）。

### ⚠️ 却下した案

- **NDJSON の `session_meta` にブロック番号を足す** — ★ 自己記述的で最も筋がよいが、
  ⚠️ **`schema_dto.rs` の変更＝ JSON Schema の drift** であり、
  受け入れ条件の `emit_schema` byte-equal と **gse-dataset 側の整合**を同時に動かすことになる。
  ★ **今回のタスクが要求していない範囲まで波及する。**
- **ファイルの時刻順で後から研究者が対応づける** — ⚠️ **実施中に「何本目まで届いたか」が分からない**。

## 4. 送信先（GAS）との約束

- ★ **認証情報はヘッダに置けない**（GAS の `e` にヘッダが無い・実測）。→ **本文に入れる**。
  ⚠️ ★ **クエリには入れない**（URL に残る）。
- ★ **302 が返る**（実測）。→ 送信側は**リダイレクト追従が必須**。
- ★ 300 KB が 1.45 s で通る（実測）。→ **分割アップロードは不要**。
- ⚠️ ★ **共有シークレットが守っているのは可用性だけ**である。
  中身は `.age` なので、経路が漏れても読めない。★ **過大評価しない**（security-checker に掛ける）。
- ⚠️ ★ GAS 側は **`.age` 以外を受け取らない**（サイズ上限・拡張子）。

⚠️ ★ **送信の成否は送信先から追えない**（実行数ページはログ本文を出さず Cloud ログも開けない・実測）。
→ ★ **端末側の `.sent` が唯一の真実源**である。これは弱点なので、
★ **未送信件数の表示を「あれば親切」ではなく必須の安全装置として扱う**。

## 6. テスト戦略

★ **収束型なので、テストしやすさが v1 系より上がる**（イベントの再現が要らない）。

- ★ **収束の性質**: 途中で止めて再実行 → 同じ状態に収束すること（**べき等**）
- ★ **取りこぼし復旧**: `.age` が無い NDJSON を置いて走らせ、**拾われること**
- ★ **匿名化**: 生成した `.age` を `gse-unpack` で開き `vk` が無く `category` があること
- ★ **送信失敗**: 送信層を失敗する実装に差し替え → `.age` が残り `.sent` が付かない →
  再実行で送られる（★ **実エンドポイントには投げない**）
- ★ **ID 空で開始できない**ことを**赤で実測**
- ★ **マーカー無し起動の非回帰**

⚠️ ★ **検査を足したら、その場でわざと壊して赤を実測する**（後回しにしない）。
