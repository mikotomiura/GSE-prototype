# GAS Web App の実測（Q-3 / POST 上限 / 所要時間）

⚠️ ★ **ここに書いてあるのは 2026-08-07 に実際に測ったものだけである。** 推測は
「★ 未実測」と明記して分けてある。⚠️ **未実測の行を根拠に同意文書を書いてはいけない。**

## 0. 測り方（再現できる形で）

| 項目 | 内容 |
|---|---|
| 使い捨てスクリプト | `doPost` / `doGet` が `e` の中身の**メタ情報だけ**を `console.log` する。⚠️ ★ **POST 本文 (`postData.contents`) は意図的に log していない** → 実行ログに本文が出たら、それは Google 側が残しているということ |
| スコープ | ★ **0 個**（`Session` / `DriveApp` を呼ばない）→ ★ **デプロイ時に OAuth 同意画面が出ないことを実測** = 測定が「権限付与の副作用」で汚れていない |
| デプロイ | ウェブアプリ / 実行ユーザー=自分 / アクセス=**全員（匿名を含む）** |
| クライアント | ★ **`curl`**（Google のログイン Cookie を一切持たない）= 被験者アプリと同じ「匿名の HTTP クライアント」の立場 |
| 後片付け | ★ デプロイを**アーカイブ**し、★ **エンドポイントが 404 になることを実測**。プロジェクトは**ゴミ箱へ移動済み** |

⚠️ ★ **落とし穴（実測で踏んだ）**: `curl -X POST -L` は **302 のリダイレクト先にも POST を強制する**
ため、GAS の `.../macros/echo` が **405** を返す。★ `-X POST` を外して `--data-binary` だけにすると
正しく 200 になる。→ ★ **実装側の HTTP クライアントも「302 を追う」ことが前提**になる（設計への入力）。

### 1-2. ★ 残っていなかったもの（★ 実測。⚠️ **推測ではない**）

| # | 何 | 実測 |

### 1-3. ★ スクリプトが取得できる情報の全て（= 研究者が意図的に記録しうる上限）

`Object.keys(e)` の実測（POST 時）:

```
contextPath, parameter, parameters, queryString, contentLength, postData
```

- `postData` から取れるのは **`contents` / `length` / `type` / `name`** のみ。
- ★ **`headers` に相当するキーは無い。** → ⚠️ ★ **接続元 IP・User-Agent は GAS 側で取得不能**。
- GET 時は `postData` が無く、残り 5 キーのみ。

### 1-4. ⚠️★ 「実行数ページに `console.log` 本文が出ない」— **陽性対照つきで確認**

⚠️ ★ 否定的な観測なので、**「そもそもログが出ていないだけ」と区別する必要がある**
（`browser-verification` §2.0）。

| | 操作 | 結果 |
|---|---|---|
| ★ **対照（効くはずの場所）** | エディタから `doPost` を実行 → **エディタの「実行ログ」パネル**を読む | ★ **`GSE_PROBE {...}` が出た** = `console.log` は確かに動いている |
| **対象** | 同じ実行を「実行数」ページ側で開く | ★ **本文は出ない**（行は 6 列のまま。クリック / ダブルクリックでも展開しない） |

→ ★ **結論**: この Apps Script UI の「実行数」ページは **ログ本文を表示しない**。
⚠️ ★ したがって「本文が出なかった」は **観測の空回りではない**。

## 2. POST サイズ上限（★ 実測）

`.age` の実サイズは **160〜225 KB**（P-1 の 4 本からの見積り）、base64 なら **約 300 KB**。

| 送ったサイズ | HTTP | 往復時間 | サーバ側処理 (`elapsed_ms`) |
|---|---|---|---|
| 1 KB | 200 | 1.12 s | 7 ms |
| 100 KB | 200 | 1.09 s | 7 ms |
| **300 KB**（★ 想定運用サイズ） | **200** | **1.45 s** | **10 ms** |
| 1 MB | 200 | 1.41 s | 17 ms |
| 5 MB | 200 | 1.83 s | 63 ms |
| 10 MB | 200 | 4.11 s | 213 ms |
| 25 MB | 200 | 5.39 s | 330 ms |
| 50 MB | 200 | 11.48 s | 782 ms |

- ★ **到達したバイト数はサーバ側で一致**（`contents_len` が送信サイズと一致）= 切り詰められていない。
- ⚠️ ★ **上限には到達していない。** 50 MB で打ち切った。★ **「上限は N MB」と書かない。**
  言えるのは ★ **「想定運用サイズの 160 倍以上でも通った」**まで。
- ⚠️ ★ **これは `DriveApp` 保存を含まない測定である。** 本番の `doPost` は Drive への
  書き込みを行うので、★ **実行時間はこの値では見積もれない**（★ **未実測**）。

## 4. ★ 設計への入力（この実測から直接出るもの）

| # | 実測 | 設計への影響 |
|---|---|---|
| **M-1** | POST は **302 を返す**。追わないと本文が読めない | ★ 送信側 HTTP クライアントは**リダイレクト追従が必要**。⚠️ `-X POST` 相当の「メソッド強制」をすると **405 で落ちる** |
| **M-2** | 300 KB は**余裕で通る**（1.45 s） | ★ **1 ブロック 1 本をそのまま送ってよい**。分割アップロードは要らない |
| **M-3** | `e` に**ヘッダも IP も無い** | ★ **認証は本文かクエリの共有シークレットでやるしかない**（ヘッダ認証は不可能）。⚠️ ★ **クエリに置くと URL に残る** → 本文に入れる（security-checker に掛ける） |
| **M-4** | Cookie 無しの匿名クライアントで 200 | ★ 被験者に **Google ログインを要求しない**構成が成立する |
| **M-5** | 実行数ページは**本文を出さない**／Cloud ログは**開けない** | ⚠️ ★ **送信の失敗を研究者が事後に追う手段が乏しい。** → ★ **成否は「アプリ側の未送信件数」で見るしかない**（`requirement.md` E の重要性が上がった） |
