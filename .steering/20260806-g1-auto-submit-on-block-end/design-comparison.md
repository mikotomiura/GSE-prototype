# 設計案比較

## v1 の要旨

ブロック終了イベント（`g1-block-ended` の発火点）で、閉じたばかりの NDJSON のパスを渡して
`gse-submit --input … --block N` を起動する **イベント駆動**。ブロック番号はアプリ側が
`~/.gse/g1_state.json` に永続化して数える。再送は「次のブロック終了時」と「アプリ起動時」に
未送信キューを走査する専用処理として持つ。送信の停止は配布物の
`submit_config.json` の `send_enabled: false`。

## v2 の要旨

「いま何をすべきか」をイベントから決めず、**毎回ディスクの状態を突き合わせて足りない仕事だけをする
収束型（reconciler）**。`{閉じた NDJSON}` → `{.age}` → `{.sent}` の 3 段を照合し、欠けている段を埋める。
ブロック終了とアプリ起動は**ヒントにすぎず**、取りこぼしても次の機会に収束する。
未送信件数は `.age` が在って `.sent` が無いものを**数えるだけ**（カウンタを持たない）。
ブロック番号は `.age` 生成時に append-only の `manifest.jsonl` で確定する。

## 主要な差異

| 観点 | v1 | v2 |
|---|---|---|
| アプローチ | **イベント駆動**（ブロック終了で起動して処理する） | **収束型**（状態を見て差分を埋める） |
| 取りこぼし耐性 | ⚠️ ★ **イベントを逃すとそのブロックが永久に落ちる**（クラッシュ・spawn 失敗・電源断）。復旧には別途リカバリ処理が要る | ★ **取りこぼしという概念が無い。**次に走ったとき「.age が無い NDJSON」として必ず拾う |
| 再送の扱い | 専用の「送信キュー」を別に持つ | ★ **再送という特別処理が存在しない**（`.sent` が無ければ送るだけ） |
| 未送信件数 | キューの状態から算出 | ★ **ファイルを数えるだけ**。カウンタとズレようがない |
| ブロック番号 | アプリが永続カウンタで数える | `.age` 生成時に manifest で確定（★ アプリのメモリ状態に依存しない） |
| 技術選定 | ほぼ同じ（`gse-submit` 拡張・HTTP は `package` feature 内・GAS 本文認証・302 追従） | 同左 |
| 変更規模 | 同程度。⚠️ v1 は「キュー」と「カウンタ」の 2 状態が増える | ★ **増える状態は `.sent` と manifest のみ**（どちらもファイル＝可視・検証可能） |
| テスト戦略 | ⚠️ ブロック終了イベントを再現しないと主要経路を試せない | ★ **ファイルを置いて走らせるだけ**でよい。べき等性・復旧が直接テストできる |
| リスク | ⚠️ ★ **P-1 で 2 回起きた「その瞬間の動作を取り損ねる」型の失敗に、構造的に弱いまま** | ⚠️ 走査コストと、`.sent` を唯一の真実源にすること（送信先から追えないのは両案共通） |

## ★ 決め手

`preregistration.md §3.6` は**ブロックの事後除外を禁じている**。
つまり ★ **1 ブロック落とすことが、この研究では回復不能な損失**である。

そして P-1 の失敗は 2 回とも **「その瞬間に取るべき動作を取り損ねた」型**だった
（mac 回＝生ログが 2 本しか残らず、Windows 回＝`.age` が 1 本もできず）。

⚠️ ★ v1 はこの失敗様式に対して**構造的に同じ弱さを残す**。
イベントを取りこぼした瞬間に、そのブロックは自動では二度と拾われない。

★ v2 は「取りこぼし」を設計から消す。⚠️ しかもそれは**追加の防御機構ではなく、
再送処理を消した結果として得られる**（＝守るべきコードが減る）。

## 推奨案

**v2** — 理由:

1. ★ **要件の中心（データを失わない）に対して構造的に強い。**
   v1 は「イベントを確実に捕まえる」ことに正しさを依存させるが、
   ⚠️ **本タスクはまさにそれに失敗した実績から起票されている。**
2. ★ **状態が減る。** v1 は「キュー」「永続カウンタ」を新設するが、
   v2 は既存のファイル群を突き合わせるだけで、増える状態は `.sent` と manifest に閉じる。
   ⚠️ カウンタは**必ずいつかズレる**（本セッションでも `G1_BLOCKS_STARTED` が
   再起動でリセットされる問題が既に出ている）。
3. ★ **テストしやすい。** イベント再現が要らず、`.age` が無い NDJSON を 1 本置くだけで
   復旧経路を赤/緑で実測できる。

★ **v1 から引き継ぐもの**（v2 でも同じ結論なので明記して残す）:
`gse-submit` 側に置くこと / HTTP を `package` feature に閉じること / CSP を触らないこと /
認証は本文・302 追従 / 送信停止は設定で（＝ローカル生成だけの状態へ縮退できる）。
