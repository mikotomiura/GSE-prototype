# G1 — ブロック自動終了と提出を 1 本につなぐ（ID 登録 → `.age` 自動生成 → 自動送信）

## 背景

★ **2026-08-06 の P-1 Windows 回で、提出物 (`.age`) が 1 本も作られなかった。**
研究者が受け取ったのは**生 NDJSON 4 本**（`~/Downloads/P1_windows/`）であり、
⚠️ **匿名化前**なので `key` 行に `vk`（仮想キーコード）がそのまま入っている。
`consent.md §3` は「どの文字を打ったか（本文）は記録しない」と約束しているので、
★ **生 NDJSON が研究者の手元に平文で渡る形は、そもそも運用として想定されていない。**

⚠️ ★ mac 回（2026-08-04）は**逆**だった: 生 NDJSON が 2 本しか残らず、`.age` 4 本から
`gse-unpack` で復元した（`notes.md §1`）。→ ★ **2 回とも、想定した一次資料が揃わなかった。**
これは実施者の不注意ではなく **設計の穴**である。

### ★ 原因（コードを読んで裏を取った・推測ではない）

1. 提出 UI は **`Dashboard.tsx`（実施中の画面）にしか無い**。
2. G1 モードでは 5 分で `g1-block-ended` が飛び、`App.tsx` が `isStarted=false` にして
   **スタート画面へ戻す** → Dashboard がアンマウントされ、**押す機会が消える**。
3. 仮に次のブロック中に押しても、`gse-submit` は
   **「最新の 1 本」しか見ない**（`submit.rs::find_latest_session_ndjson`）。
   ★ `lib.rs` 自身に「被験者が『提出する』を押すと空の `.age` が出る」というコメントがある。
4. 参加者 ID は**提出時に手で打つ**設計なので、提出しない限り **ID はどこにも付かない**。

→ ★★ **「1 ブロック = 1 セッション」に変えた時点で、「セッション終了 = 提出の機会」だった
前提が壊れていた。** G1 モード実装（`20260805-g1-app-mode-and-log-rotation`）で
**気づかれずに残った穴**である。

## ゴール

★ **被験者が提出の操作を 1 回もしなくても、ID の付いた `.age` が研究者に届く。**

| # | 何 | 到達点 |
|---|---|---|
| 1 | ID の登録 | ★ **起動時にアプリの画面で 1 回だけ入力**し、以後のブロックで使い回す（研究者判断） |
| 2 | `.age` の自動生成 | ★ **ブロックの自動終了ごとに**、そのブロックの NDJSON を指定して匿名化 + 暗号化する |
| 3 | 自動送信 | ★ **GAS Web App → 研究者の Drive**（研究者判断）。ブロック終了ごとに 1 本 |
| 4 | 失敗時 | ★ **ローカルに貯めて自動再送**。未送信件数を画面に出す (fail-loud)。★ **データは失わない** |
| 5 | 同意 | ★ `consent.md` / `participant-guide.md` に**自動送信が起きること**を明記する |

## スコープ

### 含むもの

- **A. ID 登録 UI**: G1 モードのとき、スタート画面に参加者 ID 欄を出し、
  **妥当な ID が入るまで「開始する」を押せない**ようにする。`~/.gse/` に永続化して次回起動で復元。
- **B. `gse-submit` の入力指定**: `--input <path>` を足し、「最新 1 本」以外も包めるようにする。
  ★ 既定（ゼロ引数）の挙動は**変えない**（既存の手動提出経路の非回帰）。
- **C. ブロック終了フックからの自動 package**: `g1-block-ended` を出す経路で、
  **閉じたばかりの NDJSON のパス**を渡して `gse-submit` を起動する。
- **D. 送信キュー**: 生成した `.age` を送信し、失敗したらローカルに残して再送する。
  再送の起点は「次のブロック終了時」と「アプリ起動時」。
- **E. 未送信の可視化**: スタート画面に「未送信 N 件」を出す。0 でなければ研究者に連絡を促す。
- **F. 文書**: `consent.md` §3 / `participant-guide.md` / `protocol.md §4b.2` の更新。
- **G. 送信先の準備**: GAS Web App (`doPost`) の実装と URL / 共有シークレットの配備手順。

- ⚠️ ★ **`ime_state` への session ゲート追加** — `20260805` の `decisions.md` R-9 で

## ⚠️ 環境メモ（このセッションで実測）

★ **`~/.cargo/bin/` の shim が壊れている**（`cargo` → `rustup` の symlink が dangling。
`rustup` 本体が `~/.cargo/bin/` に無い）。→ `run.sh` の
`CARGO_BIN=$(command -v cargo || echo "$HOME/.cargo/bin/cargo")` は `[ -x ]` で落ち、
**kill switch と LogChannel の挙動テストを「飛ばした」と言って素通りする**。

- ★ 実体は `~/.rustup/toolchains/stable-aarch64-apple-darwin/bin/cargo`（**1.97.1・動く**）。
- ★ これを PATH に足して再実行すると **4 本とも走って GREEN (rc=0)** になる。
- ⚠️ ★ `run.sh` は「飛ばした」と**明示している**ので偽の緑ではないが、
  ★ **黙って弱くなる経路**ではある（`silent-failure-in-guard-scripts` の隣接型）。
