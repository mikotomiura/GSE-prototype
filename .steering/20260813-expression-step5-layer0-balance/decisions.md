## ★★ S5-D1: 層 0 の音量つまみは **離散候補 5 段**（1.0 / 0.5 / 0.25 / 0.125 / 0）（研究者判断・grill）

- **決定**: `graph.expr.gain` を動かすつまみを **config 固定の離散候補 5 段**として置く。
  既存の候補ラジオ UI（音色 / 密度の写し方 / 密度の幅 / A/B 条件）と**同じ形**にする。

  | 候補 | 倍率 | 予測コントラスト（幅 100–400） | 予測（幅 100–1200） |
  |---|---|---|---|
  | `l0_full` | **1.0**（現行） | +1.04 dB ← ★ **実測で偶然水準だった** | +1.31 dB |
  | `l0_half` | 0.5 | +2.68 dB | — |
  | `l0_quarter` | 0.25 | +4.53 dB | **+6.82 dB** |
  | `l0_eighth` | 0.125 | — | — |
  | `l0_off` | 0（層 0 なし） | +6.02 dB | +10.8 dB |

  ⚠️★★★ **上表はすべて予測であって実測ではない。** ★ **倍率を変えるたびに①（比の実測）をやり直す**
  （引き継ぎ §4b・AC-4）。★ **予測を実測欄に書かない。**

- **理由**:
  1. ★★ **結果 JSON に候補 id が残り、事後に条件を再現できる**（`reproducibility-discipline` ルール 2）。
     連続スライダだと「どの倍率で測ったか」が浮動小数でしか残らず、★ **盲検の条件を後から特定しにくい。**
  2. ★ **予測表の 3 点（1.0 / 0.5 / 0.25）と両端（0.125 / 0）を覆う。**
     ⚠️ **0 を入れるのは「層 0 なし」が対照だからである** ——
     ★ **層 0 が原因であることを示すには、層 0 を取り去った条件が要る**
     （`browser-verification` §2.0 の対照と同じ思想）。
  3. ★ **UI が既存の型と同じになる**ので、新しい操作の型を研究者に増やさない。
- **却下案 A**: 連続スライダ → ★ **閾値を細かく追えるが、条件が無限にあり結果 JSON の再現性が落ちる。**
  ⚠️ **5 段で「0.5 と 0.25 の間」に閾値が挟まったら、そのとき初めて刻みを足せばよい**
  （★ **必要になってから足すほうが、使われない自由度を先に作るより安い**）。
- **却下案 B**: 離散候補 ＋ 微調整スライダ → 最も柔軟だが、★ **`expr.gain` の書き手が 2 つになる。**
  ⚠️ **S4-D15 が名指しした「書き手を 1 つに絞る」規律**（H2 で実際に踏んだ形）に反する。

## ★★ S5-D2: **総ラウドネスは補正しない**（層 0 を下げたら全体が下がるままにする）（研究者判断・grill）
