# AI 疲労 文献 DB の評価版を読みやすくし、調査不足を issue にまとめる

## 背景

2026-09-28 に、研究者の AI 疲労サーベイ用 文献 DB（34 件）を一次資料で再評価し、
評価版 `AI_fatigue_database_with_AI_appraisal_2026-09-28_claude.xlsx`（元 16 シート＋Claude 10 シート）を納品した
（`.steering/20260928-ai-fatigue-db-appraisal/`・PR #258 で main にマージ済み）。

研究者の依頼（2026-09-29・逐語）:
「先ほどのAI疲労のセッションまでで, こちらを作成していたんだけど, もう少し具体的に理解しやすいようにしてほしいのと,
具体的に調査不足であると考えられる箇所があれば, 調査する価値がありと判断できるものは具体的なさーヴぇい ,issueやＧＳＥでのこれまでの研究あ内容から思いついたアイディアissueなどもこれまでの中であれば、通常のissueなども併せてからまとめてください」

評価版は「中心-A / 中心-B」「E2 / E4」「R-I / C 番号」「JBI 項目」など作業用の記号が多く、
1 件ごとに「何をした研究で、何が言えて、どこまで引用してよいか」を平易に読める面が無い。
また、調査不足の箇所は各シートの「次の確認・作業」欄と `検索漏れ候補` に散らばっており、優先度つきの一覧が無い。

## ゴール

1. 評価版の内容を、記号を知らなくても読める形にする（1 件ごとの平易な要約・用語の読み替え・証拠の地図）。
2. 調査不足の箇所を洗い出し、調べる価値があるものを 3 種類の issue にまとめる:
   - **サーヴェイ issue**（文献を探す・読む）
   - **アイディア issue**（GSE のこれまでの研究内容から出てきた着想。GSE の既決の禁止線に反しないもの）
   - **通常 issue**（全文の入手・照会・DB の更新・人間の判定など、手を動かせば閉じる作業）
3. 1 と 2 を、元を壊さない新しい xlsx（研究者向け）と、repo の記録（`issues.md`）の両方に置く。

## スコープ

### 含むもの
- 評価版 xlsx に「読みやすさ」のシートと「issue 一覧」のシートを追加した新ファイル
  （`C:\Users\johnd\Downloads\AI_fatigue_database_with_AI_appraisal_2026-09-29_claude.xlsx`）
- 「調べる価値がある」の判断材料として、各サーヴェイ issue の主題で **学術 API の件数の目安と種になる文献の実在確認**を行う（本格的なサーヴェイそのものは行わない）
- repo の `issues.md`（xlsx の issue シートと同じデータ源から生成する）

### 含まないもの
- ⚠️ 既存 26 シート（元 16＋Claude 10）の変更（★ 追加のみ。機械で不変を確認する）
- ⚠️ 元ワークブックの人間用の判定欄（判定者 1・2・最終判定）への書き込み
- ⚠️ サーヴェイ issue の実行（本格的な検索・スクリーニング・カード化）と `docs/references.md` への登録（★ 実行時に `/literature-review`・`citation-ssot` で行う）
- ⚠️ GitHub issue の起票・著者への照会の送信（★ 外部に出る操作。issue には下書きまでを書き、送るかは研究者が決める）
- ⚠️ GSE の理論文書・ADR・計測の変更（★ アイディア issue は「検討する」までを書く。GSE の既決の禁止線は変えない）
