## 設計案比較（/reimagine 1 回目・2026-11-03）

v2 は v1 と decisions.md を見せない別のエージェント（Opus）が requirement.md と一次資料だけから作った。v2 の一次の引用のうち、ADR-010 D4/D5・ADR-014 D6・glossary:254 は Claude が開き直して合っていることを確かめた。

### v1 の要旨
MhD で数える単位を 3 層（観測 = 窓・標本 = ラベルの付いた 1 件・まとまり = 日）に分け、Decision Episode を読み出しの単位に戻す。予測のトラックの標本は採った停滞の定義のエピソードで、凍結まで C0 を仮に使う。「約 50 セッション」は申告のある日の数と、詰まりの申告の件数の下限の 2 条件。効果の単位は日で、H4b が通らなければ判定不能。

### v2 の要旨
単位を 4 つの量（U1 効果 = 日・U2 クラスタ = 日・U3 ラベル = 無作為の枠の申告・U4 構造と読み出し = `DecisionEpisode[定義, 束ね方]`）に分け、有効標本数を 3 つ組（d・n_label・n_ep）で報告する。H4b が通らないときのクラスタの後退先（連続日のブロック）を先に決める。glossary の出典の取り違えを記録し、注記する docs を広く取る。

### 主要な差異
| 観点 | v1 | v2 |
|---|---|---|
| 構造 | 3 層（窓・標本・日） | 4 量（効果・クラスタ・ラベル・エピソード）。中身は v1 の 3 層＋効果の単位でほぼ同じ |
| 「約 50」 | 申告のある日＋詰まりの申告の件数の下限（2 条件） | 約 50 日だけ。件数は 3 つ組で報告するが条件にしない |
| H4b が通らないとき | 効果の比べは判定不能。MhD のクラスタは決めていない | クラスタを連続日のブロックに後退（幅は事前登録） |
| エピソードの扱い | 予測のトラックの標本（C0 を仮に・C1/C2 は感度） | 記述と読み出しだけ。件数を N にしない。定義と束ね方を名前に付ける |
| 日の境界 | 触れていない | ADR-014 D6 の機械的セッションと別の量と明記。日をまたぐセッションは事前登録 |
| docs の変更 | ADR・README・glossary | ＋ README の 019/030 行の注記・glossary 3 項・personalization §3.1・出典の取り違え |
| 検証 | レビューと上書き範囲の照合 | ＋ grep の検査・定義の差し替えの机上検査・空回しの受け入れ条件 |
| リスク | 件数の条件で「50 日でも足りない」を拾える | 件数の条件が無く、詰まりの少ない日が続いても「約 50 日」で満ちる |

### 推奨案
ハイブリッド — v1 の判断 1〜5 を骨にし、v2 から次を足す: (1) H4b が通らないときのクラスタの後退先（連続日のブロック・幅は事前登録） (2) 3 つ組の報告の形と、エピソードを `[定義, 束ね方]` 付きで名乗る規則 (3) 日と ADR-014 D6 の機械的セッションの区別・日の境界を事前登録へ (4) glossary の出典の取り違えの記録と、注記する docs の範囲 (5) 検証の grep と机上検査。「約 50」は v1 の 2 条件を保つ（v2 自身が弱みに挙げた「件数が足りない」を条件で拾えるため）。予測のトラックの標本は v1 のまま残し、v2 の「件数を N にしない（不確かさは d で数える）」を併せて書く（両者は矛盾しない）。
