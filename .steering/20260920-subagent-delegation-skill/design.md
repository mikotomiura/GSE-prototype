## ★ Skill の構成（★ なぜこの並びか）

| ルール | 何 | 出所の格 |
|---|---|---|
| 1 | model を明示する | **[SSOT]** `loop-engineering.md:60-76` ＋ ⚠️[未記録]（明示の義務） |
| 2 | 範囲・禁止事項・締切の 5 点 | **[実地]** 25 分ハング ＋ 5 分半で完走した対照 |

★ **出所の格を各規律に付けた**（判断 5）。⚠️ 混ぜると memory 由来まで一次のように読まれる。

## テスト戦略

★ `empirical-prompt-tuning` の **Lite**（判断 4）:

- **Iteration 0**（静的・dispatch 不要）: `description` が謳う範囲と body の乖離を潰す。
  → ★ 実施済み: 初版の description は**入れ子（ルール 4）と渡すかの判断（ルール 5）と
  brief（ルール 7）を謳っていなかった**ので、description 側を body に合わせた。
- **Iteration 1〜2**: 1 シナリオ（中央値 = 実装後のレビュー依頼）を **別エージェント**に渡し、
  ★ 「**Skill を読んで実際のプロンプトを書く**」をやらせる。⚠️ 書けた内容ではなく
  **「詰まった点」の自己申告**を主の信号にする。

### ★ 要件チェックリスト（⚠️ 事前に固定・後から動かさない）

| # | 要件 |
|---|---|
| 1 | `model` を明示している（★ レビューなので Opus） |
| 2 | 範囲を「**コミット済み**の N ファイル」と具体で書いている |
| 3 | 禁止事項（作業ツリー / クローン / 長い検査）を書いている |
| 4 | **締切**（N 分）を書いている |
| 5 | 「読み切れなかった範囲は *読んでいない* と書く」を入れている |
| 6 | `code-reviewer` と `security-checker` を **1 メッセージで並列**に投げると述べている |
| 7 | **入れ子禁止**をプロンプトに書いている |

★ 精度 % = 満たした項目数 / 7。

## ★ 実装後に変わったこと（2026-09-20・検証とレビューを経て）

★ 骨格（Skill が SSOT ／ 他は指すだけ ／ `loop-engineering.md` は引くだけ）は変わっていない。
⚠️ **変わったのは「規律の書き方」で、2 つの型の誤りを潰した**。

| 型 | 何が起きていたか | 直し方 |
|---|---|---|
| ⚠️ **実行不可能な指示** | `allowed-tools` に `Task` が無いのに fan-out を必須化、`Bash` が無いのに `git show` を命じていた（H1 / H2）。★ 範囲の定型が `/review-changes`（未コミットが対象）と正面衝突していた（H3） | ★ `allowed-tools` を揃え、定型を **(a) コミット済み / (b) 未コミット**の 2 版に分けた |
| ⚠️★★★ **格の偽り** | ★ 機構の説明を memory から捏造（H4）／引用 3 件がどれも主張を支えていなかった（H5）／出所の無い実測値（M4）／repo に用例の無い手段名を断定（M5） | ★ 撤回・差し替え・格下げ。⚠️ **撤回した事実も残した** |

★ あわせて **二重管理を 1 件解消**: model 表は `loop-engineering.md:79` 逐語の
「この表は `.claude/agents/*.md` の frontmatter `model:` と一致させる（**L7 が drift を検出する**）」の
**外にある 3 つ目の複製**だった（M2）。→ **表を削除し「どこを見るか」に置換**した。

⚠️★★★ **教訓（★ 本 Skill 自身に効く）**: 出所の格を付ける装置を作りながら、
**その装置を 2 か所で自分で外していた**。→ ★ **装置は、作った本人にも適用する。**

## リスク

- ⚠️ **Skill が増えることの固定コスト**（★ 全 Skill の description が毎セッション読まれる）。
  → ★ description を短く保つ。
- ⚠️ **`docs/loop-engineering.md` の表が動いたとき**、Skill の引用が古くなる。
  → ★ Skill 側に「**ここで再定義しない。表が動いたら表に従う**」と明記した。
- ⚠️ memory を縮めた結果、**別 repo で作業するときの情報量が減る**。
  → ★ ポインタに「どこを見るか」を残した（★ 削除はしない＝判断 3）。
