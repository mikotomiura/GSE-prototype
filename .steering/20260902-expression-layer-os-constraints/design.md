# 設計

## 実装アプローチ

**2 本立てで、依存関係は「調査 → ハーネス」の一方向。**

### 【第 1】OS 制約の調査 —— サブエージェント並列 ＋ メインが直列で統合

★ `feedback_survey_via_subagent` のとおり、探索はサブエージェントへ委譲し、
`docs/references.md` への append だけメインが直列で行う。

⚠️★★★ **証拠規律を各エージェントのプロンプトに埋め込んだ**（★ これをやらないと二次資料が混入する）:
- ✅ 一次 = 公式ドキュメント / API リファレンス / AOSP / RFC / NIST / 査読論文の本文
- ❌ ブログ・まとめ・StackOverflow・**abstract だけ**・AI 生成 SEO ページ
- ★ 各主張に **逐語（英語原文）＋ URL ＋ OS バージョン**
- ★★★ **「一次で確認できなかった」を明記させる**（★ 推測で埋めさせない）

★ **取得手法の実測**（★ これが無いと調査が空振りする）:
⚠️ `developer.apple.com` の HTML は **JS SPA で本文が空**。
→ ★ **DocC JSON API**（`/tutorials/data/documentation/<path>.json`）を直接叩く。

### 【第 2】層 A（視覚）試視ハーネス —— 新規作成

⚠️★★★ **引き継ぎが指定した資材 `step4.html` は音のみだった**（実測・→ `decisions.md` 判断 1）。
★ 視覚の試作は repo に存在しないので新規に作る。

**設計の骨**:
1. **較正を通すまで試行を開かない** —— ★ 「視角 1°」は物理較正なしに意味を持たない
2. **順序を固定する** —— 1a 自由記述 → 1b 盲検（未教示）→ 教示 → 1b' 盲検（教示後）→ 遷移検知
3. ⚠️★★★ **写像をブロック 1b が終わるまで封印する**（blur ＋ 操作不能）—— ★ C7 の実装
4. **未教示 = 他者が読める上限／教示後 = 本人** と読み替える —— ★ **PS-Q5 への写像**
5. **強制選択 ＋ catch ＋ 混同行列** —— ★ 印象ではなく正答率で案を落とす（§7-4）
6. **invitation の符号を 2 つ持つ** —— ★ A-7（振動）と静的代替（環の開口）
