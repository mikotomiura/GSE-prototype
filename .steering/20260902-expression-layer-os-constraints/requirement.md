## 背景

ADR-021 が `.idea` §7 の未決 8 件を裁き、**第一媒体をロック画面に決め**（D1）、
**層 A の設計要件 8 本 A-1〜A-8 を確定した**（D10）。しかしその際に 2 つを先送りした。

1. ⚠️★★★ **OS 制約でアニメーションを載せられない場合がある → 実装時に再検査**（ADR-021 D1 の但し書き）。
   ★ **A-7（振幅 ~1°・1–3 Hz のその場振動）は「色を主符号にしない」（A-6）の唯一の代替であり、
   これが OS で実装不能なら層 A の符号体系ごと作り直しになる。**
2. ⚠️ **PS-Q5（THAT / WHAT / HOW のどの段で止めるか）は試視でしか決まらない**（D2）。
   ★ **3 段の分類学は文献上存在しない**ので、文献では埋まらない。

## ゴール

1. **【第 1】** ロック画面の OS 制約・セキュリティ機構を **一次資料のみ**で確定し、
   A-7 が実装可能かを判定して ADR に落とす。
2. **【第 2】** 視覚の層 A 試視ハーネスを作り、研究者本人の試視で
   **THAT / WHAT / HOW のどの段で止めるか**を判定する。併せて **E-7**（層 0 と `stable` の弁別）を測る。

## スコープ

### 含むもの
- iOS / Android のロック画面に置ける面の全列挙、更新頻度、**アニメーション可否**、色の扱い
- 背景実行・受信経路（ADR-017 D4 制約 1「PC に常設 LAN リスナを置かない」との両立可否）
- secure lock screen の表示制限、初回ロック解除前の挙動
- ペアリングと失効（S1–S6）を OS 既存機構でどこまで満たせるか
- 曝露量の外的妥当性（★ 顔認証時代にロック画面滞在時間が崩れていないか）
- 視覚の層 A 試視ハーネスの新規作成と、研究者による試視の実施・記録
- ADR-022 の起票（または ADR-021 の追補）

### 含まないもの
- ⚠️ **音（研究者の問い 2）** —— ★ **本セッションでは開かない**。
  順序は「PS-Q3 を閉じる → ADR-017 D5 の 4 条件を検討」であり、オプトインの議論はその後。
- ⚠️ **実装**（`src-tauri/**` / `src/**` / Flutter アプリ）—— ★ 表現チャネルは未実装のまま
- ⚠️ **wire protocol の決定（W-1）** —— ★ 実装着手時の別 ADR。本タスクはその**前提となる制約**だけを出す
- ⚠️ **N=12–20 の最小プロトコル（§7.1）の実施** —— ★ 本タスクは試視（N=1・形成的）まで
