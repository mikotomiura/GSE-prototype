# G1 提出レシート UI (送信が成功したことを被験者に明示する)

## 背景

`src/App.tsx` の G1 提出 UI は **3 状態しか出さない**:

| 状態 | 表示 |
|---|---|
| 承認待ち | 緑「このブロックの記録を送信しますか？」(`App.tsx:546`) |
| 未送信 N 件 | オレンジ「まだ送れていない記録が N 件」(`App.tsx:634`) |
| エラー | 赤「自動送信でエラー」(`App.tsx:673`) |
| ★ **送信成功** | ⚠️ **何も出ない**（箱が消えるだけ） |

⚠️★★ 実機ログでは **承認 → 送信完了に 6.2 秒 / 5.7 秒**かかっており、その間も無表示。
→ ★ **「警告が消えた ＝ 成功」と読ませている**。2026-08-09 に潰した silent death
(`hook_health`) と**同じ構造**であり、memory `silent-success-is-not-visible` の型そのもの。

被験者は自分の記録が届いたかを他の手段で確認できない
(送信先 GAS から成否を追えない — `gas-measurements.md` M-5)。
★ **端末側のこの表示が唯一の証拠**である。

## ゴール

送信の成否が、**肯定形**で・**バックエンドの実測**を根拠に画面へ出ている。

## スコープ

### 含むもの
- 送信成功のレシート表示（時刻 + 件数）
- 送信中 (`承認 → 完了` の数秒) の表示
- 未送信 0 件のときの肯定形表示
- 上記に必要なバックエンド配線（収束器の `sent` をフロントへ通す）

### 含まないもの
- 送信先 (GAS) 側の受領確認 — 端末からは追えない (M-5)
- 通常運用 (非 G1) の画面 — 1 バイトも変えない
- キーボードフック生存監視 (`hook_health`) の実機検証 — **別トラック**
- 被験者の `get_hook_status` 表示の変更 — 盲検のため意図的に据え置き

## 受け入れ条件

- [x] レシートの根拠が **「ボタンを押したこと」ではない**
      = 収束器が `.sent` を実際に置いた件数 (`GSE_RECONCILE` の `sent`) から出ている
- [x] 承認直後〜完了までの無表示の空白が無い（`送信しています…` が出る）
- [x] 未送信 0 件が**肯定形**で出る（「警告が無い」に読ませない）
- [x] 文言に**認知状態の手がかりが無い**（盲検維持）
- [x] `cargo test --workspace --features package` が緑
- [x] `tsc --noEmit` が緑
- [x] ★ **実マウント + 対照つきで輝度差を実測**した（memory `ui-changes-need-eyes`）
