## ⚠️★★ 事故 — 実被験者番号 `P009` でテスト送信が 1 本発生した

**何が起きたか**: 手順書は参加者 ID を `P999` (存在しない番号) と指定していたが、
実際には **`P009`** が入力された。`P009` は Drive に `G1課題文_P009` フォルダを持つ
**割り当て済みの番号**である。

**生じた実体**:

```
Drive: P009_block01_gse_20260810_024022.age   (75,432 B・2026-08-10T02:47:12Z)
       id = 1YJB8pjcr7zsEsVWLV5OoM3o_zRpCQCIu
ローカル (研究者の Windows 機):
       ~/Documents/GSE-submissions/ の同名 .age と .sent、manifest.jsonl の 1 行
```

**処置**: 8/09 のテスト送信に対して既に使われていた運用に合わせ、
★ **`(windows_test)` を前置してリネーム**する
(`(windows_test)P009_block02_gse_20260809_053839.age` などと同じ型)。
⚠️ Drive MCP はリネーム/削除ができないため、Drive の UI から人が行う。

### ★ なぜ「事後除外の禁止」に触れないのか (★ 判断を残す)

`preregistration.md §3.6` が禁じているのは **被験者ブロックの事後除外**である。
本件は **被験者が実施したブロックではなく、研究者が装置を検証するために作ったもの**であり、
取り除くのは「データを選ぶ」行為ではなく「装置の試運転を本番データから分ける」行為である。
★ ただし ⚠️ **この区別は自明ではないので、黙って消さずに記録を残す**。

### 番号の消費について — ★ 伝播しない

`next_block_number` (`reconcile.rs:236`) は **その端末のローカル提出物フォルダ**
(`.age` と `manifest.jsonl`) だけを見る。サーバには問い合わせない。
→ ★ **実際の P009 がご自身の端末で始めれば block01 から正しく採番される。**
研究者機での番号消費は participant 側に伝播しない。

⚠️ ただし **サーバ側では同名衝突が起こりうる**: 今回のものを `P009_block01_...` のまま
残すと、実 P009 の提出物と **両方が block01 を名乗る**。`(windows_test)` 前置で解消する。
