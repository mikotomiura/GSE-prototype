# 設計: O1-C の欠けた登録用の設問を戻す

## 根本原因

2 つに分けて書く。

### 1. 設問が欠けた原因（特定できていない）

- 2026-08-29 の構築では `setupO1Forms()` が「構築完了」を出している（`deployment-runbook.md` §3 B-2）。そのときのコード（`d7bc55f3` 以降）は 3 つの設問を作る。例外が出ていれば「構築完了」は出ない。
- 過去 7 日間（10/01 以降）に `setupO1Forms` は走っていない（実行数で確認）。
- コードの中で設問を消すのは `o1ClearForm_` だけで、呼ぶのは `buildO1ConsentForm` / `buildO1PostSurveyForm` の先頭だけ。
- したがって、8/29 から 10/01 までの間に、7 日より前の実行（見えない）か、編集画面での手作業で消えた、のどちらか。どちらとも決められない。
- 修正はこの原因に依存しない（どう欠けても、照合が見つけ、修復が戻す）。

### 2. 欠けたことに誰も気づかなかった原因（コードの欠陥・これを直す）

- `migrateO1ConsentForm()` は 10/03 に「✅ 追加する同意項目はありません（フォームはコードと一致しています）」と出した。しかし見ているのは**同意のチェック項目のタイトルだけ**で、登録用の 4 設問は見ていない。ログの文が、確かめていないことを確かめたと言っていた。
- 実物のフォームの設問をコードの期待と照合する手段が無い（browser-verification §3「実物のスキーマを読んで比べる」が O1-C に無い）。
- 回答を残したまま登録用の設問を戻す手段が無い。`setupO1Forms()` は回答があると止まり、`migrateO1ConsentForm()` は同意項目しか足さない。

## アプローチ

1. 登録用の 4 設問（参加者ID・お名前・メールアドレス・パソコンの種類）を作る処理を `o1AddRegistrationItem_(form, title)` に切り出し、`buildO1ConsentForm` と修復の両方が使う。定義が 1 か所なので、修復で作る設問は構築と同じになる。並びは `O1_REGISTRATION_TITLES` に持つ。
2. `o1ConsentFormShapeProblems_(form)`（読み取り専用）: 見出し以外の設問を上から読み、期待（同意項目すべて＝チェックボックス・必須、続いて登録用の 4 つ＝種類と必須の有無）と比べ、欠け・種類違い・必須の違い・順序違いを文で返す。
3. `checkO1ConsentFormShape()`: 上を実物に対して走らせてログに出す。フォームを変更しない。
4. `repairO1ConsentRegistrationItems()`: 欠けた登録用の設問を末尾に足す。足せるのは「欠けたものが並びの後ろ側にまとまっていて、今のフォームの最後の設問が、残っている登録用の最後の設問（無ければ最後の同意項目か見出し）である」ときだけ。そうでなければ足さずに止まる（順序を壊すので人に返す）。回答には触れない。最後に照合を走らせて結果をログに出す。2 回目は何も足さない。
5. `migrateO1ConsentForm()` の「フォームはコードと一致しています」を、照合の結果に基づく文に改める（照合で問題があればそれを出す）。

`moveItem` で並べ替える案は採らない。今回の形（参加者ID で終わる）は末尾に足せば正しい順になり、並べ替えが要る形は人が見るべき異常なので止める。

## 既存パターンとの整合

- 回答を保って足す経路は `migrateO1ConsentForm` と同じ形（追加のみ・削除しない・冪等）。
- 読み取り専用の確認関数は `checkO1FormConfig` / `checkO1RosterShape` と同じ形（`check…` の名前・ログに出して bool を返す）。
- 照合を実装側に持つのは browser-verification §3 の方針。

## テスト戦略

- 回帰テスト（先に書き、今は赤になることを確かめる）:
  - 参加者ID で終わるフォーム（回答 1 件）に修復を走らせると、3 つがこの順で足され、削除は 0、回答取得が 4 項目取れる
  - 2 回目は 0 件
  - 並びが壊れた形（参加者ID が欠けてお名前がある等）では足さずに止まる
  - 照合: 構築直後は問題 0、欠けたフォームでは「メールアドレス」を含む問題が出る、照合はフォームを変えない
  - `migrateO1ConsentForm` は欠けたフォームで「一致しています」と言わない
- `node Form_O1/o1_form_builder_test.cjs` と `bash Form_O1/o1_form_builder_mutation_test.sh` を緑に
- 実物（Apps Script と Chrome）: 研究者が貼り、`checkO1ConsentFormShape()` で問題を確認 → `repairO1ConsentRegistrationItems()` → もう一度照合 → Chrome で回答用ページを読み取る（送信しない）。関数の選択は押す直前に読み直す
