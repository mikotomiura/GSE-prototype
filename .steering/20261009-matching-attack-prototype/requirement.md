# 合成入力での照合攻撃の試作（ADR-039 D6 の候補 1・【決 6-a】の試作）

## 背景

前のタスク（長さの並びの一意性・PR #337・`experiments/20261009-length-sequence-uniqueness/notes.md`）は、青空文庫の本文から「理想の書き手が打った」長さの並びを合成し、長さだけの照合の当たりやすさを見積もった（5 区間・約 140 打で窓の 97.8% が一意、候補 1,000 本との照合は 5 区間で強い雑音でも 98.6%）。最大の限界は、合成した並びが実機の IME の記録のカテゴリ列と同じになるかを確かめていないことだった。

ADR-039【決 6-a】は、照合攻撃の試作を合成入力（IME 論文の評価一式・送った語句が分かっている・人のデータではない）で作ると決めた。【決 9】（G1 の参加者に知らせるか）は、IME 論文の復元の分析と、この試作の結果がそろったときに決める。引き継ぎ: `.steering/_handoff/next-session-matching-attack-prototype.md`。

## ゴール

IME 論文の Windows のセル（`papers/ime-observation/experiment/runs/windows-msime-tsf-2/`・MS-IME・TSF・2,925 試行）の記録で、次の 3 つを測り、結果を `experiments/20261009-matching-attack-prototype/` と本作業記録に残し、ADR-039 D6 と issue #333 に要点を返す。

1. 照らし合わせ: 前のタスクの手順で語句の本文から合成した長さの並びと、実機の記録のカテゴリ列から数えた並びが一致するか。ずれるなら、どこで・どれだけ・何が原因か（配送・手順・本文の読点・読み）。
2. 照合攻撃: 同じブロックで続く k 試行を 1 つの記録とし、候補 N 本から正解を当てる正答率を偶然の水準 1/N と並べる。攻撃者は 2 つ（前のタスクの長さだけの L1・IME 論文のシミュレーション攻撃）。前のタスクの k の曲線と並べる。
3. 加工の効き目: 長さを粗い区間にまとめる・区切りを落とす・種類をまとめる・順序を捨てる、の加工をかけたとき、偶然の水準にどこまで近づくか。

この試作は合否の判定ではない（【決 6-a】）。分かるのは、合成入力・この攻撃・この加工の範囲での目安で、照合の危険の上限ではない。

## 関連して見つけたこと（2026-10-09・本タスクの外）

IME 論文の `closed_set.py` の `runs="count"`（特徴量の組 `no_runs`・`bin1s_count`・`counts_only`）は、英字の連なりを 1 つのトークンにまとめるが、トークンの個数として連なりの長さを持ち、距離はその個数の差を使う（英字 10 打と 20 打の記録の距離は `counts_only` でも `no_time` でも 10.0。2026-10-09 に実行して確かめた）。事前登録 §6.8 と原稿 `recoverability.tex` はこれらを「連なりの長さなし（no run lengths）」と書いている。凍結されたファイルには触れず、研究者に報告した。本タスクでは「長さを本当に捨てる」条件（加工の w = ∞）を別に測る。
