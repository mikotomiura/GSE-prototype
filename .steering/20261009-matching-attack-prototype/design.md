## 3. 記録の読み方（両方の部で共通）

- `read_obs` で押下の行（`press` が真）を `(t, category)` の列にし、`segment_by_plan(..., markers_in_obs=True)` で計画の試行に割り当てる（IME 論文 §6.8 と同じ。計画と一致しないブロックは採点しない）。IME 論文の実行では 117 ブロックすべてが一致した（`alignment.n_blocks_unscored = 0`）。この割り当てを本タスクでもやり直し、数を記録する。
- 試行の記録 = その試行に割り当てた押下のカテゴリ列。
- 試行の打鍵数 c = 英字（`alphabetic`）＋数字（`numeric`）＋記号（`punctuation`）の押下の数 − BackSpace（`backspace`）の押下の数（前のタスクの「文字キー − BS」と同じ数え方）。Space・Enter・Esc・Tab・矢印は数えない。
- 試行の打った読み = `_typed_reading`（ふつうは語句の読み全体。S10 は前半だけ。S12 は合成のかな）。正解の判定は打った読みで行う（IME 論文と同じ）。

## 4. 照らし合わせ（ゴール 1・攻撃より先に計算する）

採点したすべての試行（S12 を含む 2,925）について、記録から数えた並びと、前のタスクの手順で語句の本文から合成した並びを比べる。

- 記録の側: 試行の押下を区切り（`enter`・`sentence_punctuation`）で切り、区間ごとに上の c の数え方で数える。最後の区切りの後に残る分（区切りで閉じない区間）は「開いた区間」として別に持つ（続けて打つ記録では次の試行の区間とつながる）。
- 合成の側: 語句の本文（`text`）を前のタスクの `segments_of_work([text], Tokenizer)` に通し、B0 の区間（読点・句点で切る）の打鍵数の列を得る。語句の確定の Enter で最後の区間を閉じたものとする（「本文をそのまま打ち、確定した」と仮定した記録）。語句の本文は 1 つで渡すので、前のタスクのように元の行の文脈で読みを付けたものではない（限界に書く）。
- 比べるもの（試行ごと）: (a) 区間の列が同じで開いた区間が無い（並びの一致）、(b) 打鍵数の合計が同じ（合計の一致）、(c) 差 Δ = 記録の合計 − 合成の合計。
- ずれの原因の印（試行ごとに、当てはまるものすべて。計画と本文だけから決まり、記録を見ない）:
  - 配送: 試行の記録のカテゴリ列が計画のカテゴリ列と違う（採点したブロックでは構造上起きない。割り当てで採点しなかったブロックの数として報告する）。
  - 手順: シナリオが「読みを打って Enter で確定する」から外れるもの。S4・S5（Esc で取り消す・Enter が無い）、S6（読みの字数だけ BackSpace・Enter が無い）、S8（数字のキーで候補を選ぶ・数字が 1 打増える）、S10（読みの前半だけ・Tab で予測の候補）、S12（かな入力・合成のかな）、S14（入力モードの切り替えは記録に残らない・Enter が無い）。S1・S2・S3・S7・S13・S15 は手順の印を付けない（Space・矢印は数えない・S15 の窓の切り替えは記録に残らない）。
  - 読点: 本文に「、」があり、合成の側では区切りになるが、executor は読点を打っていない（IME 論文の語句は読点をまたいでつないだもの・読みはかなだけ）。
  - 読み: 前のタスクの手順の読み（読点を除いて連結したもの）が、コーパスの読み（executor が打った読み）と違う。または前のタスクの手順で無効になる。
  - 合成のかな（S12 の語句がコーパスに無い）: 合成の側を作れない。数だけ報告する。
- 報告: シナリオごとの数・並びの一致の割合・合計の一致の割合・Δ の平均と範囲、原因ごとの数と Δ。**どの印も付かないのに一致しない試行**（説明のつかないずれ）は試行の ID を列挙する。これが 0 なら、前のタスクの換算（読み → ローマ字の打鍵数・区切りは Enter と句読点）は、手順と読点と読みの違いを除けば実機の記録と同じになる。

## 5. 長い記録と候補（ゴール 2・3）

### 5.1 記録（窓）

- 各ブロックの中で、計画の順に並ぶ S12 以外の採点した試行の列を作る（S12 は IME 論文と同じく使わない。間に挟まる S12 の試行は飛ばす）。ブロックあたり 20〜25 試行。
- k 試行の窓 = その列の連続した k 個（始まりの位置をすべて取る・重なる窓も使う）。窓はブロックをまたがない。窓の数は k = 1, 2, 3, 5, 8, 12, 20 で 2,700・2,583・2,466・2,232・1,881・1,413・477。
- 正解 = 窓の k 試行の打った読みの組。

### 5.2 候補

- 候補 N 本 = 正解の組 1 本 ＋ おとりの組 N − 1 本。
- おとりの組: 位置 i ごとに、その試行のシナリオ s_i で計画が選びえた語句（`_scenario_pool(recipes, "windows", s_i, _pool_by_reading(corpus))`・Windows の S12 以外では 1,791 句すべて）から一様に 1 つ引く。位置どうしは独立。
- 除くもの: 打った読みの組が正解と全位置で同じ組（見分けられないので不公平）、語句の組として前に引いたおとりと同じ組（候補は互いに異なる）。k = 1 では、これは「正解と打った読みが違う語句から、重複なしに N − 1 個」になり、IME 論文の `_make_candidates` と同じ規則（引き方の乱数は違う）。
- おとりの引き方は、種と k・N・窓（ブロックと始まり）の SHA-256 から作る乱数で決め、攻撃者と加工の間で同じものを使う（比べやすくするため）。乱数は `random.Random` の `random()` だけを使う（版によらない）。
- 正解の組は計画が決めたもの。計画は、シナリオごとに語句の全体を混ぜて順に回して引いている（`generate_plan.plan_rows` の `_Pool`）ので、各語句がほぼ同じ回数だけ正解になる（2,700 試行で異なる語句 1,435・最多 6 回）。

### 5.3 偶然の水準 1/N の前提（結果の前に固定）

- 正解の組とおとりの組は、どちらも語句のほぼ一様な引き方から来る。記録に情報が無ければ、どの候補が選ばれるかは正解と無関係で、期待される正答率は 1/N。
- 採点は候補の並び順によらない（同点は 1/m）ので、正解の位置は意味を持たない。
- 同点: 距離が最小の候補が m 本あり、その中に正解があれば 1/m の得点（一様な無作為の決め方の期待値）。
- 記録は候補の抽選に使わない。
- 確かめ（診断・6.4）: 無作為の予測、記録を使わない予測、記録を入れ替えた陰性対照が 1/N の近くになること。採点と抽選は合成のデータで自己検査する（§9）。

## 6. 攻撃者と加工

どちらの攻撃者も、試行の切れ目を与えられる（IME 論文の攻撃と同じ。切れ目を推す難しさは含まない）。k 試行の記録と候補の組の距離は、位置ごとの距離の和。距離が最小の候補を選ぶ。攻撃者は加工を知っていて、候補の予測にも同じ加工をかける。

### 6.1 長さだけの攻撃者（L・前のタスクの L1）

- 記録の値: 試行ごとの打鍵数 c_i（§3）。
- 候補の予測: 語句の読み全体の標準の打鍵数 R(p) = `len(romaji.to_keys(reading))`（前のタスクの表と同じ）。手順（シナリオ）は知らない（S10 の前半・S6 の BackSpace・S8 の数字は攻撃者にとって雑音）。
- 距離: 位置ごとの差の絶対値の和（L1）。
- 加工（記録と予測の両方にかける）:

| 名前 | 加工 |
|---|---|
| `L_none` | なし |
| `L_bin{w}`（w = 2, 4, 8, 16） | 値を floor(値 / w) にする（長さを粗い区間にまとめる） |
| `L_bininf` | 値をすべて 0 にする（長さを捨てる。候補がすべて同点になり、正答率は 1/N になるはず＝検査を兼ねる） |
| `L_merge{m}`（m = 2, 5） | 続く m 試行ずつ値を足し合わせる（区切りを落とす。最後の組は m より短くてよい） |
| `L_mergeall` | k 試行の値の合計だけ |
| `L_sort` | k 個の値を小さい順に並べ替える（順序を捨てる。多重集合だけが残る） |

k = 1 では `L_merge*` と `L_sort` は `L_none` と同じになる（計算はする）。

### 6.2 シミュレーション攻撃者（S・IME 論文の K2）

- IME 論文の `closed_set.py` と同じ: 攻撃者は候補の語句・シナリオ・OS・速さの水準・生成器・手順・設定を知り、候補ごとに `Predictor`（種 20260929・IME 論文の値）で予測の記録を作る。打鍵の時刻は使わない（`timing = "none"`。合成入力の打鍵の間隔はキーと独立に引かれているため）。
- 距離: `closed_set._distance`（カテゴリのトークンの編集距離）。トークンの作り方を加工ごとに変える:

| 名前 | トークン |
|---|---|
| `S_no_time` | IME 論文の `no_time`（押下 1 つが 1 トークン） |
| `S_counts_only` | IME 論文の `counts_only`（英字の連なりを 1 トークンにし、個数に連なりの長さを持つ。⚠️ 長さは捨てていない・requirement.md の「関連して見つけたこと」） |
| `S_rle{w}`（w = 1, 2, 4, 8, 16） | 同じカテゴリの連なりをすべて 1 トークンにまとめ（英字・BackSpace・Space・矢印などすべて）、個数を ceil(個数 / w) にする（長さを粗い区間にまとめる） |
| `S_rleinf` | 同上で個数をすべて 1 にする（長さを捨てる。連なりの順序と種類だけが残る） |
| `S_mchar` | `S_no_time` で、文字を作るキー（英字・数字・記号・Space）を 1 つのカテゴリにまとめる（issue #333 の B の表の 1 行目） |
| `S_mbound` | `S_no_time` で、区切りのキー（Enter・Esc・Tab・句読点）を 1 つのカテゴリにまとめる |
| `S_mboth` | 上の 2 つを両方 |

- 試行ごとの距離は、採点した各試行 t と、そのシナリオの候補の語句 p すべてについて先に計算する（予測とトークンの組で使い回す）。

### 6.3 計算するセル

攻撃者と加工 21 通り（L が 10・S が 11）× k 7 × N 3（10, 100, 1000）= 441 セル。各セルは §5.1 の窓をすべて使う。

### 6.4 報告する値と診断

- 正答率（窓の得点の平均）と、ブロックを単位にしたブートストラップ（2,000 回・百分位・95%・117 ブロックを復元抽出。すべてのセルで同じ抽出を使う）の区間。正答率 − 1/N と、正答率 ÷ (1/N) も出す。
- k = 1 のシナリオごとの正答率（区間なし・記述）。
- 診断（`L_none` と `S_no_time` について、すべての k・N）:
  - 無作為の予測（候補から種つきの乱数で 1 本）。期待は 1/N。
  - 記録を使わない予測: 予測の打鍵数がコーパスの中央値に最も近い候補（位置ごとの |R(p) − 中央値| の和が最小）。正解が典型的な語句に偏っていなければ 1/N の近く。
  - 陰性対照（記録の入れ替え）: 窓の各試行の記録を、別のブロックにある同じシナリオの試行の記録に入れ替えて同じ候補で採点する（入れ替え先は種つきの乱数で選ぶ）。記録は正解と無関係になるので 1/N の近く。
- k = 1 の再現の確認（`scripts/reproduce_ime.py`・本計算の前）: `S_no_time` と `S_counts_only` の試行ごとの距離を、IME 論文の候補の作り方（`_make_candidates`・試行ごとの種）と同点の決め方（種つきの乱数）で使うと、公開された JSON の `acc_raw`（K = 10, 100, 1000）と正答の数まで一致すること。一致しなければ止まる。
- 前のタスクの値（B0・N = 1,000・理想と強）を、表で横に並べる（前のタスクの `results/matching.json` から読む。計算し直さない）。条件が違う（前のタスクは作品の続いた本文の窓と雑音のモデル、本タスクは独立に引いた語句と実機の記録）ので、同じ量ではない。

## 9. テスト戦略（`scripts/selftest.py`・`run.sh` が本計算の前に回し、落ちたら止まる）

1. 読み込みの守り: SHA-256 が違うファイルを渡すと止まる。
2. 打鍵数 c の数え方: 手で数えられるカテゴリ列（BackSpace・数字・Space・Enter を含む）。
3. 区間の切り方（照らし合わせ）: 開いた区間・Enter が 2 つ続く・区切りが無い試行。
4. 加工: `L_bin`・`L_merge`・`L_sort`・`S_rle`・`S_mchar`・`S_mbound` の手計算の例。`S_counts_only` が長さを持つこと（10 打と 20 打で距離 10）と、`S_rleinf` では持たないこと（距離 0）。
5. 採点: 同点（全候補が同じ距離なら 1/N）・正解だけが最小なら 1・正解を含む m 本の同点なら 1/m。
6. 抽選: 合成の世界（語句の数・シナリオ・k を変える）で、記録に情報が無いときの正答率が 1/N に近い（3 標準誤差以内）・完全な記録で 1・おとりが正解と打った読みで同じにならない・おとりが互いに異なる・同じ種で同じ候補。
7. 陰性対照の入れ替え先が別のブロックの同じシナリオの試行であること。
8. ブートストラップ: 1 ブロックだけなら区間を出さない・同じ種で同じ区間。
9. 前のタスクの表と IME 論文の `to_keys` が、コーパスのすべての読みで同じ打鍵数を返す。

本計算の直前に `reproduce_ime.py`（§6.4）を回す。

## 10. 限界（結果のノートに書く）

- 上限ではない: 試行の切れ目を与えた攻撃で、言語モデル・時刻・本人の過去の文章・同じ書き手の複数の記録の組み合わせを使わない。逆に、切れ目を推す難しさは含まない（実際の記録では Enter・Esc・Space などのカテゴリから切れ目を推せる見込みが高いが、測っていない）。
- 合成入力: 人の打鍵のリズム・推敲・貼り付け・変換のやり直しを持たない。打つ読みはコーパスの読み（SudachiPy）そのもので、読み違いが無い。手順は 13 シナリオを同じ数ずつ混ぜたもので、人の操作の頻度ではない。
- 長い記録は、独立に引いた語句をつないだもの（続いた文章ではない）。候補も同じ規則で作った。前のタスクの k の曲線（作品の続いた本文の窓）とは、区間の長さの分布と候補の作り方が違う。
- 正解は打った読み（取り消した・消した語句も含む）。最終的な文章と突き合わせる照合（取り消した語句は文章に残らない）は測っていない。
- 照らし合わせの読みは語句の本文だけで付けた（元の行の文脈ではない）。
- Windows のセルだけ（macOS のライブ変換では Return が 2 回になり、区切りの数が変わる）。
