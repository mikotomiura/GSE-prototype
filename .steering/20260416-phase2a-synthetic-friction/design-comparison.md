# 設計案比較: Phase 2a Synthetic Friction 再設計

## v1 の要旨

`last_active_features` を保存し、沈黙開始時に φ(F3, β) と φ(F6, β) が閾値 (`THRESHOLD_PHI_F3=0.30`, `THRESHOLD_PHI_F6=0.20`) 以上かで **二値判定**。閾値以上なら既存の摩擦フロアを適用、以下ならフロアをゼロにする。`--scatter` CLI モードで閾値の事前分析を行う。engine.rs に 2 定数追加。

## v2 の要旨

`pre_silence_features` を保存し、沈黙中の合成 F3/F6 を直前の実測値に **比例させる**。F3=0 の clean typing 後は沈黙中も F3≈0、F3=0.5 の修正の多いtyping 後は F3 も中程度にキャリーフォワード。新定数なし、時間とともに緩やかに増幅する連続関数。engine.rs 変更なし。文脈がない場合 (セッション冒頭) は現行ロジックにフォールバック。

## 主要な差異

| 観点 | v1 | v2 |
|------|----|----|
| アプローチ | φ 閾値ゲート (二値) | 比例キャリーフォワード (連続) |
| 技術選定 | φ 正規化後に閾値判定、engine.rs に定数 | 生の F3/F6 を比例反映、engine.rs 変更なし |
| 変更規模 | 4 ファイル (features, loop_step, engine, replay) | 2 ファイル (features, loop_step) |
| 新定数 | `THRESHOLD_PHI_F3=0.30`, `THRESHOLD_PHI_F6=0.20` | なし |
| テスト戦略 | φ 閾値境界テスト + ゴールデン再生成 + GT 回帰 | 比例関数テスト + ゴールデン再生成 + GT 回帰 |
| リスク | 閾値周辺で不連続 (0.29→0.30 で突然切替)、GT 校正必須 | 増幅関数のチューニングが必要だが連続的に振る舞う |
| 「タイポ≠Stuck」 | 閾値以下なら解決するが、中間域では誤分類残る | F3 値に比例するので自然にスケール |
| フォールバック | なし (文脈必須) | セッション冒頭は現行ロジックにフォールバック |
| ONNX 化影響 | engine.rs に定数追加 → 将来考慮必要 | engine.rs 変更なし → 影響ゼロ |
| 追加 CLI 機能 | `--scatter` (散布図分析) | なし |

## 推奨案

**v2 (比例キャリーフォワード)** — 理由:

1. **新定数ゼロ**: GT 校正による閾値決定が不要。n=10 のデータ量で 2 つの閾値を信頼性高く決定するのは困難
2. **連続性**: 閾値の前後で動作が不連続にならない。F3=0.01 の微小摩擦も F3=0.50 の中程度摩擦も適切にスケール
3. **変更最小**: engine.rs に触らない → ONNX 化 (Phase 3) との干渉なし、emission/transition matrix との分離が明確
4. **ユーザー観察との整合**: 「タイポ≠Stuck」が比例関数で自然に解決される
5. **フォールバック安全性**: 文脈がないセッション冒頭で現行動作を維持、リグレッションリスク低減
