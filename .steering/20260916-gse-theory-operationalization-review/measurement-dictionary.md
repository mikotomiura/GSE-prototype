# EVAL-NCC 測定辞書 v0.1

> Status: pre-SSOT measurement draft / 2026-09-17
>
> 本書は `.idea` 理論候補を反証可能にするための作業契約であり、確立尺度、事前登録、実装仕様、SSOT ではない。外部形成的評価 `EH3` で認知インタビューと計器監査を行い、`EH4` の割付前に項目、採点、許容幅を版付きで凍結する。

## 1. 共通単位と記法

| 記号 | 定義 |
|---|---|
| `i` | 参加者 |
| `j` | 招待へ割り付けられた機会。表示成功や応答の有無を問わず母集団へ入れる |
| `k` | 客観的正答または事前固定ルーブリックを持つ判断項目 |
| `A_ij` | 割付条件。主要比較は `Semantic Stop + no residual response duty + minimum support` と対照条件 |
| `B_ij` | 観測された応答分岐。明示の受諾（★ 2026-09-19: 旧「受容」。SSOT の「受容」＝離席が起きたか、と呼び分ける・J-13）、保留、拒否、見逃し、意図的無応答、判別不能無応答。⚠️ 別計器でだけ記録する（J-16） |
| `W0` | 招待提示から expiry までの分岐観測窓 |
| `W1` | expiry 後 5 分の近接窓 |
| `W2` | expiry 後 5-15 分または課題ブロック終了までの後続窓 |

> ⚠️ **2026-09-19**: 本辞書の「**誤採用**」（§3・AI の誤った提案を採用すること。★ **2026-09-20 に旧名「誤受容」から改名した** —— `.steering/20260919-theory-ssot-promotion/decisions.md` 判断 4 #7。§2 の近接概念「採用率」・§3 の「正しい提案の採用」も同じ日に「受容」から改名）と、SSOT の「**受容**」（ADR-018 D5・招待の提示の後に離席が起きたか）・「**受容性**」（Receptivity・Layer 5）は**別の構成概念**である。★ 分岐の意味の旧「受容」は「明示の受諾」と呼ぶ（J-13）。

`W1/W2` は暫定値であり、実データを見て変更しない。形成的試行で課題長と計器分解能を確認し、`EH4` 割付前に固定する。再開は回復、明示の受諾は同意、無応答は拒否を意味しない。

自己報告は原則 7 件法（1=`まったく当てはまらない`、7=`非常によく当てはまる`）とする。以下の項目文は認知インタビュー用の候補であり、確立尺度とは呼ばない。逆転項目は読解負担を増やすため初版では置かず、項目順をランダム化する。

## 2. 判断品質

| 項目 | 契約 |
|---|---|
| 概念定義 | 利用可能な証拠に照らし、正しい選択、適切な保留、誤り訂正、確信の校正を行い、課題目的に適合する判断を得る程度 |
| 含めない近接概念 | 速さだけ、AI との一致率、採用率（★ AI の提案を採った割合。ADR-033 D3 (b) の受容率とは別物）、主観的自信、作業再開、好み |
| 観測単位・対象 | 客観的正答または割付前に固定した採点ルーブリックを持つ `participant x item`。主解析は全割付参加者・全提示項目 |
| 測定時点 | 各項目の最終回答時。確信度は回答直後、正答開示前。訂正は初回回答と最終回答を分けて記録 |
| 主要評価量 | `DQ = mean(s_ijk)`。`s` は課題別に事前固定した `[0,1]` 得点。二値課題では正答=1、誤答=0。保留に価値がある課題では誤答コストと保留コストをルーブリックに明記 |
| 副次評価量 | 正答率、適切な保留率、誤答からの訂正率、Brier score または calibration slope、完了率、意思決定時間 |
| 望ましい方向 | `DQ`、訂正率、校正は高い方。Brier score と過信は低い方 |
| 許容幅の決め方 | 対照群の得点分布を盲検 pilot で確認し、利用者・課題専門家が「負担低減と交換できない最小悪化」を先に決める。標本サイズから逆算しない。尺度 `[0,1]` では候補幅を 0.03/0.05/0.10 として感度表を作り、最終 `delta_DQ` は `EH4` 前に一本へ固定 |
| 主要交絡・効果修飾 | 事前知識、課題難度、AI 経験、Need for Cognition、ベースライン正答率、疲労、言語能力 |
| 媒介候補 | 検証行動、分岐、確信変更、支援利用。主要 ITT で共変量調整しない |
| 欠測 | 未提示は技術欠測、時間切れは観測された非完了、項目不適用は構造的欠測。未回答を正答や誤答へ自動変換せず、非完了率を併記して worst/best-case bounds を出す |
| 判定 | 非劣性 CI が `-delta_DQ` を越えれば品質下限を満たす。越えなければ他の負担指標が改善しても `CORE-NORM` の支持に使わない |

## 3. 誤採用

| 項目 | 契約 |
|---|---|
| 概念定義 | 客観的に誤り、不十分、または課題ルーブリック上で不適合と事前判定されたシステム提案を、最終判断として採用すること |
| 含めない近接概念 | 正しい提案の採用（★ AI の提案を採ること）、根拠付きの暫定採用、低リスクで検証不要と事前指定した採用、単なる閲覧 |
| 観測単位・対象 | 誤った提案をランダムに埋め込んだ `participant x item`。誤提案の割合と種類は条件間で同一 |
| 測定時点 | 最終回答確定時。初回判断、提案閲覧、最終判断を別イベントで記録 |
| 主要評価量 | `EA_cond = accepted_wrong / exposed_wrong`。分母は客観的に誤った提案が提示された項目 |
| 副次評価量 | `EA_ITT = accepted_wrong / all_randomized_items`、誤採用後の訂正率、誤り種別別リスク差、確信度 |
| 望ましい方向 | 低い方 |
| 許容幅の決め方 | 誤採用の損失を課題別に分類し、絶対リスク差の上限 `delta_EA` を先に定める。安全・高影響課題では非劣性ではなく優越またはゼロ許容を要求する。本計画の初回試験は低リスク課題に限定し、最終値は unresolved |
| 主要交絡・効果修飾 | 提案のもっともらしさ、誤り難度、AI 信頼傾向、事前知識、条件ごとの提示時間 |
| 媒介候補 | 検証、確信変更、支援利用、摩擦完遂。主要 ITT で調整しない |
| 欠測 | 条件に誤提案が一件もない参加者の個人率は構造的未定義。試験設計で各参加者へ最低数を割り付け、なお不足時は trial-level model を用いる。技術欠測と無回答を誤採用ゼロにしない |
| 判定 | `EA` が許容幅を超えて増えれば、負担低減があっても棄却。条件差が不精確なら支持ではなく未解決 |

## 4. 無検証依存

| 項目 | 契約 |
|---|---|
| 概念定義 | 検証可能で、かつリスクに照らして検証が必要と事前指定された提案を、利用可能な検証手段を一度も用いず最終判断へ採用すること |
| 含めない近接概念 | 検証不能な提案、低リスクで検証不要な提案、独立に同じ結論へ到達した場合、検証後の採用、単なる自動化利用 |
| 観測単位・対象 | `verification-eligible participant x item`。検証手段、必要性、最低十分な検証行動を割付前に item ごとに宣言 |
| 測定時点 | 提案提示から最終回答まで |
| 主要評価量 | `UVR_risk = accepted_without_check / all_verification_eligible_items`。分母を割付後の採用者へ限定しない |
| 副次評価量 | `UVR_given_accept = accepted_without_check / verification_eligible_acceptances`、検証開始率、検証完遂率、証拠閲覧時間、独立初答からの変更率 |
| 望ましい方向 | `UVR_risk` は低い方。検証回数そのものは多ければ良いとはしない |
| 許容幅の決め方 | 誤採用と同じリスク分類を使い、絶対リスク差 `delta_UVR` を事前指定する。必要以上の確認を増やす設計は verification burden で同時に罰する |
| 主要交絡・効果修飾 | 検証コスト、証拠の可用性、事前知識、時間圧、AI 信頼、NFC、課題難度 |
| 媒介候補 | 摩擦、支援利用、知覚複雑性、分岐 |
| 欠測 | ログ不能は技術欠測。画面外での内的検証をログから推定しない。明示された検証チャネルだけを測るため、自己報告との不一致を感度分析する。採用が一件もない場合、条件付き副次率だけを構造的未定義とする |
| 判定 | `UVR_risk` 増加または `EA_cond` 増加のいずれかが許容幅超なら品質ガード不通過。`UVR_risk` だけ低下し burden が増す場合は GR-H11 の共同判定へ送る |

## 5. 支援到達可能性

| 項目 | 契約 |
|---|---|
| 概念定義 | 利用者が必要と判断した時に、理解可能な経路で支援を要求し、合理的な時間と手順数の範囲で有効な支援または安全なエスカレーションへ到達できる程度 |
| 含めない近接概念 | 支援を実際に使った回数、支援への好意、常時監視、システムの存在だけ、応答を強制すること |
| 観測単位・対象 | `participant x assigned opportunity` と、全条件に置く標準化された support probe |
| 測定時点 | W0 中の可視性、W1 の標準 probe、ブロック後の認知項目 |
| 主要評価量 | `SA_success`: 事前指定された最大手順数・時間内に支援またはエスカレーションへ到達できた割合 |
| 副次評価量 | 発見までの時間、誤経路率、援助要請の自己効力感、支援がまだ利用可能だという理解、支援要求後の解決率 |
| 候補項目 | 「必要なら、どこから支援へ戻れるか分かった」「応答しなくても、後から支援を求められると感じた」 |
| 望ましい方向 | 高い方。利用率の低さ自体は失敗としない |
| 許容幅の決め方 | 対照条件との差の絶対下限 `delta_SA` を、許容できる追加失敗人数で決める。操作確認用の無リスク task でも support path の成功率が 90% 未満なら confirmatory 試験へ進めないという実装ゲート候補を置くが、効果の非劣性マージンは unresolved |
| 主要交絡・効果修飾 | UI 経験、アクセシビリティ需要、言語、実際の支援需要、課題失敗、デバイス |
| 媒介候補 | 分岐、放置不安、支援利用。主要 ITT で調整しない |
| 欠測 | 条件上タスク文脈の支援を提供しない `negligent relinquishment` は構造的に 0 と定義し、通常条件の技術欠測と分ける。研究安全上の緊急連絡は残すが `SA_success` には数えない。probe 未実施は欠測であり成功扱いしない |
| 判定 | target 条件が非劣性を満たさない、または最小支援義務の操作確認に失敗した場合、低罪悪感でも関係的自律を支える協調（★ 旧「非支配的協調」・段 3 判断 1 #1）を支持しない |

## 6. 罪悪感

| 項目 | 契約 |
|---|---|
| 概念定義 | 招待へ応じない、遅らせる、拒否する、または期待されたと感じる行為をしなかったことに対する自己評価的な負の感情 |
| 含めない近接概念 | 一般的不快、失敗課題への後悔、恥、実験者への礼儀、単なる義務認知 |
| 観測単位・対象 | `participant x opportunity`。明示分岐と無応答分岐の双方 |
| 測定時点 | W1 終了時の短い項目と、ブロック終了後の回顧。分岐選択前には測らない |
| 主要評価量 | 2 項目平均: 「この招待に応じなかった／すぐ応じなかったことに、後ろめたさを感じた」「システムの期待を裏切ったように感じた」 |
| 副次評価量 | 自由記述の理由コード、状態罪悪感と課題失敗後悔の弁別項目 |
| 望ましい方向 | 低い方。ただし negligent relinquishment でも低くなりうるため単独成功指標にしない |
| 許容幅の決め方 | 形成的評価では床効果と理解を確認する。EH4 では残存応答義務条件に対する最小効果差を事前指定し、同時に支援到達可能性と判断品質の gate を要求 |
| 主要交絡・効果修飾 | 良心性、社会的望ましさ、実験者期待、課題失敗、介入への好悪、文化・言語 |
| 媒介候補 | 応答義務、不利益予期、分岐。互いを主要モデルで同時調整しない |
| 欠測 | 回答拒否を罪悪感ゼロとしない。選択的無応答として bounds と pattern-mixture 感度分析を行う |
| 判定 | 低下しても品質・支援 gate が不通過なら支持しない。項目が義務感や失敗後悔と弁別できなければ縮小または再設計 |

## 7. 応答義務

| 項目 | 契約 |
|---|---|
| 概念定義 | 招待に対し、何らかの返答、選択、説明、確認をしなければならないという知覚された規範的要求 |
| 含めない近接概念 | 行動したいという動機、支援の有用性、単なる通知への気づき、罪悪感 |
| 観測単位・対象 | `participant x opportunity` |
| 測定時点 | W0 終了直後または W1 内。応答確認 UI を閉じた後 |
| 主要評価量 | 2 項目平均: 「何か返答しないと先へ進めないように感じた」「この招待には反応する義務があると感じた」 |
| 副次評価量 | 不要な確認クリック、説明入力の試行、拒否後の再確認、反応までの時間 |
| 望ましい方向 | target 条件では低い方。命令条件との比較で判定 |
| 許容幅の決め方 | GR-H4/H9 では優越性を要求し、単なる非劣性にしない。最小差は EH3 の分布と認知インタビューを用いて EH4 前に固定 |
| 主要交絡・効果修飾 | 社会的望ましさ、システム擬人化、実験者期待、通知慣れ、課題の切迫性 |
| 媒介候補 | 罪悪感、不利益予期、分岐、主タスク中断 |
| 欠測 | 技術欠測と回答拒否を分離。無応答者を尺度解析から除外した completer-only 結果は主要にしない |
| 判定 | 低下しない、または拒否・無応答時に再要求が生じるなら `no residual response duty` の操作は不成立 |

## 8. 不利益予期

| 項目 | 契約 |
|---|---|
| 概念定義 | 招待へ応じない、遅らせる、拒否することで、将来の支援、評価、アクセス、推薦、研究者からの扱いが悪化すると予想すること |
| 含めない近接概念 | 現時点の罪悪感、一般的なリスク回避、現実に設定された正当な安全制約 |
| 観測単位・対象 | `participant x opportunity` |
| 測定時点 | W1 とブロック終了後。条件説明の理解確認後 |
| 主要評価量 | 2 項目平均: 「応じないと今後の支援が受けにくくなると思った」「応じないことが自分への評価に影響すると思った」 |
| 副次評価量 | 拒否後の支援利用試行、将来利用意図、誤った制度理解の割合 |
| 望ましい方向 | 低い方 |
| 許容幅の決め方 | 理論上は near-zero を目標とする。項目理解後も上位回答が一定割合残る場合は、その割合の上限を EH3 で定め EH4 前に凍結。安全上の実害がある条件は試験対象外 |
| 主要交絡・効果修飾 | 組織内権力関係、実験参加報酬、過去のアルゴリズム評価経験、社会的望ましさ |
| 媒介候補 | 応答義務、分岐、支援利用 |
| 欠測 | 回答拒否を 0 にしない。実際の不利益が発生した場合は欠測処理でなくプロトコル違反として停止・報告 |
| 判定 | target 条件で不利益予期が残る、または実際の分岐が評価・報酬へ回収される場合は GR-H4 を棄却 |

## 9. 放置不安

| 項目 | 契約 |
|---|---|
| 概念定義 | システムが撤退した後、必要時にも支援、説明、是正へ戻れず、判断と帰結を一人で引き受けさせられるという不安 |
| 含めない近接概念 | 一般不安、支援を使わなかったこと、低いシステム依存、応答義務、曖昧さへの単なる嫌悪 |
| 観測単位・対象 | `participant x opportunity` と block-level |
| 測定時点 | W1、支援 probe 後、ブロック終了時 |
| 主要評価量 | 2 項目平均: 「必要になっても支援へ戻れない気がした」「判断の後始末を自分だけに任されたように感じた」 |
| 副次評価量 | support probe 失敗、説明・是正経路の理解、支援探索時間、早期離脱 |
| 望ましい方向 | target 条件では低い方。negligent relinquishment では高くなることを負の対照の操作確認とする |
| 許容幅の決め方 | target と negligent 条件の弁別が成立し、かつ target が active control に対して非劣性であることを要求。最終幅は EH3 後に固定 |
| 主要交絡・効果修飾 | 実際の支援需要、課題失敗、一般不安、過去の支援経験、アクセシビリティ需要 |
| 媒介候補 | 支援到達可能性、分岐、支援利用。主要 ITT で支援利用を調整しない |
| 欠測 | 支援需要がなかったことは構造的欠測ではない。`必要なら戻れる` という認知を測る。回答不能・技術欠測・選択的無応答を分離 |
| 判定 | 低罪悪感と同時に放置不安が上がる場合は放置的返還。target と negligent 条件が弁別できなければ最小支援義務の操作を再設計 |

## 10. 欠測コード

| コード | 意味 | 主要処理 |
|---|---|---|
| `STR` | 設計上そもそも定義されない構造的欠測 | 分母から除く条件を事前明記し、0 代入しない |
| `TECH` | 配信、表示、ログ、入力機器の失敗 | 割付母集団には残し、主要は treatment-policy estimand。per-protocol は副次 |
| `OBS` | 計器では観測できない | 未観測状態を推定で埋めない。範囲または `unknown` として報告 |
| `SEL` | 回答拒否、離脱など転帰依存の可能性がある無応答 | complete-case を主要にせず、MI、pattern-mixture、worst/best bounds を併記 |
| `ADMIN` | ブロック終了など研究運営上の打切り | 打切り規則を固定し、競合転帰と区別 |

## 11. 共同判定規則

`関係的自律を支える協調`（★ 旧「非支配的協調」）は単一尺度や総合点に畳まない。次をすべて満たす場合だけ支持候補とする。

1. 応答義務、罪悪感、不利益予期、または検証負担の事前指定した主要指標が対照より改善する。
2. 判断品質と支援到達可能性が非劣性を満たす。
3. 誤採用と無検証依存が許容上限を超えない。
4. 最小支援義務の操作確認が成立し、negligent relinquishment と弁別できる。
5. 無応答・離脱・技術欠測を成功として数えていない。

1 のみ成立すれば `burden-only improvement`、2-3 が不成立なら `negligent or unsafe relinquishment`、精度不足なら `unresolved` と記録する。
