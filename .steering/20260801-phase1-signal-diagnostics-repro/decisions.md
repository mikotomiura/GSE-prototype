# 設計判断

## D1: 確証実験に追記せず、新しい探索的実験として隔離した

`experiments/20260731-phase1-calibration-analysis/` は Phase1 の**確証判定の記録**で、
`notes.md` は凍結された判定文書。そこへ後付けの探索的分析を足すと confirmatory / exploratory の
境界が曖昧になる。

→ `experiments/20260801-signal-diagnostics/` を新設し、`data.md` で
「入力カットは 0731 と同一」を来歴として明示的に繋いだ。
実際に有効ラベル件数 (P010=103 / P011=21 / P012=35 / P013=7 / P014=34、計 200) が
0731 の記録と**完全一致**することを機械確認している。

## D2: Python 側に β をハードコードせず、Rust から抽出する

φ と β を Python で書き写すと `engine.rs` を変えたときに診断結果が**黙ってずれる**
(二重定義の drift)。これは本セッションで繰り返し踏んでいる「静かな不整合」と同じ族。

→ `extract_constants.py` が Rust ソースから正規表現で抽出し `constants.json` に書き出す。
抽出できなければ `run.sh` は非ゼロ終了 (fail-closed)。
φ の式そのもの (`((x-beta)/(KAPPA*beta)).clamp(0,1)`) が期待形かと、
重み合計が 1.0 かも検査する。`constants.json` は追跡下に置くので Rust 側の変更は差分で見える。

**レビュー指摘で判明した穴**: 当初 `([0-9.]+)` の前方一致で値を取っており、
`= 1_000.0;` → `1.0` / `= 1.0e-1;` → `1.0` を**成功として静かに拾っていた**。
drift を止める層自身が最も危険な静かな失敗を持っていた。
`= ([^;]+);` で切り出してから `^[0-9]+(\.[0-9]+)?$` で厳格検証するよう修正。

## D3: 純 Python で並べ替え検定を回すためのアルゴリズム選択

`numpy`/`scipy` が環境に無い。素朴な O(n²) C-index を並べ替えごとに回すと
120 セル × 10,000 反復で終わらない (実測: 3 分でも終わらず中断)。

→ v の密ランク × q の水準のバケット集計 (`FastCIndex`) にして O(k·R + k·n) に落とした。
v は並べ替えで動かないので密ランクは一度作れば使い回せる。全体 25 秒。

**素朴実装との一致を毎セル `self_check()` で検証**し、ずれたら `AssertionError` で落とす。
高速化のために定義を変えていないことを実行時に担保する。

## D4: `.idea` を正としない

再現値が `.idea` と食い違ったとき、`.idea` を正とせず**両方を記録**した。
結果として `.idea` の記述を 3 箇所訂正することになった:

1. **「f1 項が支配的」→ 指標次第**。相関では 3 番手、標準化寄与では 2 番手。
   相関はスケール不変なので**重みの効果を測れない**という点を見落としていた。
2. **「並べ替え検定 68 件」→ 再現不能**。件数の定義が復元できない。
3. **「`ime_nav`/`ime_abandon` は死んだフィールド」→ 3 層に分解**。
   abandon は死・nav はほぼ死・**P012 と P014 は `ime_shadow` イベント自体がゼロ**。
   3 つ目は `.idea` に無い新事実で、`ime_dwell` の有望性を否定する方向に効く。

逆に **paste の 97 倍・φ の飽和率・keys→Q2 の C-index は完全一致**しており、
`.idea` の中核的な観測は信頼できることも確認できた。

## D5: 「一致しなかった」と思ったものが自分のバグだった

当初 `paste 96.6 倍` を **99.9 倍**と報告し、`.idea` の「97 倍」と不一致だと記録していた。
原因は**丸めた率で比を取っていた**こと (`round(rate, 2)` 後に max/min)。
生値で計算すると 96.6 で、`.idea` と一致する。

→ 教訓: 「先行記述と食い違った」ときは、**まず自分の実装を疑う**。
本件は独立レビューが指摘するまで気づかず、危うく**存在しない不一致**を
ADR の入力として残すところだった。

## D6: 主張の強さを数字に合わせて下げた箇所

レビューを受けて、再現できた数字でも**そのままでは強すぎる**主張を弱めた。

| 主張 | 当初 | 修正後 | 理由 |
|---|---|---|---|
| Bonferroni 通過ゼロ | そのまま | 「**到達可能な 70/103 セルで**通過ゼロ」 | n が小さいセルは p の下限 2/M が閾値を上回り、**構造的に通過しえない** |
| ICC | 点推定 4 桁 (0.0800 等) | 「概ね 0.05–0.30、不確実性大」 | 群 (被験者) が 5 つしかない。LOO 範囲は f4 で 0.112–0.302 と 3 倍近く動く |
| `paste_chars` | 「意味を持たない」 | 「欠測混入の補助指標」 | null は 694 件中 54 件 (7.8%) で、10 セル中 9 セルは算出可能だった |

## D7: 検算を「報告」でなく「ゲート」にした

Python φ ⇔ Rust φ の等価性は当初**残差を報告するだけ**だった。それだと将来
`engine.rs` の合成が変わっても (抽出器の形状チェックを通り抜ける変更なら)
r が 0.9999 → 0.7 に落ちるだけで**実験は緑のまま通る**。

→ 閾値 (r ≥ 0.999 / 残差中央値 ≤ 1e-3 / 残差>0.01 が ≤ 0.5%) を置き、
外れたら非ゼロ終了するようにした。`FastCIndex.self_check` が `AssertionError` を
投げる設計と揃えた。

厳密一致 (< 1e-9) を閾値にできないのは、NDJSON が `f1:.2` / `f5:.1` / `raw_x:.4` に
丸めて記録するため (`logger.rs`)。design.md に書いた当初の期待値は達成不能だった。

## D8: 出力の PII 検査をコードに埋めた

`load()` が当初セッションのファイル名を保持していた。ファイル名
`gse_YYYYMMDD_HHMMSS.ndjson` は**セッション開始の絶対時刻そのもの**で、
`data.md` が「絶対 epoch 時刻なし」と約束している対象。
現時点では出力に出ていなかったが、「セッション別内訳を出したい」と思った瞬間に
1 行で違反が成立する。

→ ファイル名の保持自体をやめ (`sid` に置換)、加えて書き出し直前に
`assert_no_pii()` でファイル名・絶対パス・URL・1e12 以上の整数を検査して落とすようにした。
`.gitignore` にも `experiments/**/*.ndjson` / `*.jsonl` / `**/raw/` を追加した
(既存ルールは「logger 由来のファイル名のまま置いた場合」しか塞いでいなかった)。

**このガード自身が最初に誤検知した**のは、多項係数 (相異なる並べ替え数 M) が
1e33 規模の整数だったため。M は出力に載せる意味がないので `p_floor = 2/M` だけ残した。
