# 決定と根拠 — ESM 監査 criterion のゲート解除

> ★ 確定した裁定は `docs/adr/ADR-031-self-reported-activity-audit-criterion.md`（D1〜D8）。
> ★ 本ファイルは **ADR に載らない作業上の判断**と、⚠️ **本タスクで自分が間違えて直したもの**を残す。

## 判断 1: ⓪①③ を 1 本の ADR にまとめた

- **決定**: ADR を 3 本に割らず ADR-031 の D1〜D8 に束ねた。
- **理由**: ★ どれも「6 択 ESM を O1 の計器に入れる」という**同じ 1 つの判断の構成要素**であり、
  分けると**どれが前提でどれが帰結か**が読めなくなる（★ ADR-029 が D1〜D6 を束ねた先例）。
- **却下案**: ⓪ / ① / ③ で 3 本（★ 起票 11 の表の見た目には忠実だが、相互依存が消える）。

## 判断 2: `participant-setup-guide.md` は **直さなかった**

- **決定**: 逐語は `consent-revision-proposal.md §2` に置き、**適用は ADR-031 M5 と同じリリース**。
- **理由**: ⚠️★★★ **プローブは O1 で構造的に発火しない**（実測）。
  → ★ いま直すと **出ない問いを説明する文書**になる。
  ⚠️ かつ `:105` の記述は**今日の時点では正しい**（現行のワンタップは `user_label` だけ）。
  → ★ **正しい記述を誤った記述に置き換えることになる。**

## 判断 3: `gse-dataset` の schema 同期は **本ブランチのマージ後**にする

- **決定**: `check_schema_parity.py` は drift を検出するが、**いま同期しない**。
- **理由**: ⚠️ 本ブランチは未マージ（ADR-029 / ADR-030 が承認待ち）。
  ★ いま同期すると **dataset が main より先に進む** —— それは parity 検査が防ごうとしている状態そのもの。
- ⚠️ **CI の drift check は repo 内（`emit_schema` vs `schema/current.json`）だけ**を見るので緑のまま。
  → ★ **`/finish-task` の tier-3 で見る**（★ ADR-031 §Migration M8）。
