# 設計

## 何を移し、何を残したか

★ 分け方の原則: **「環境ごとに変わる / 秘密・PII を指す」ものは外へ。
「安全装置」と「同意文書との一致を機械検査しているもの」はソースに残す。**

| 値 | 行き先 | 理由 |
|---|---|---|
| `FORM_ID_O1_CONSENT` / `FORM_ID_O1_SURVEY` | **プロパティ** | ★ 配備ごとに変わる。⚠️ `.gs` 編集は repo と配備物の食い違いを生む |
| `O1_APP_DOWNLOAD_URL` | **プロパティ** | ⚠️ 追跡ファイルに置くと T-15 と同じ形（★ 配布フォルダに秘密が入りうる） |
| `PHASE1_MGMT_SHEET_ID` | **プロパティ** | ⚠️ 参加者 PII への直接ポインタ |
| `G1_FORM_IDS_DO_NOT_TOUCH` | ソース | ⚠️★★★ **未設定＝防波堤が黙って無効**になる（2026-08-07 の事故の再発防止） |
| `O1_CONTACT_*` / 保管上限 / 設問文 | ソース | ★ 同意文書との一致を 98 ケースが照合している |
| `O1_AUTO_SEND` / `O1_ALLOW_REBUILD_WITH_RESPONSES` | ソース | ★ fail-closed の既定値 |

## 実装

- `o1Config_()` を新設（★ 受け口の `config_()` と**同じ形**にそろえた）。
  ⚠️ 未設定は空文字で返し、★ **判定は `o1ConfigProblems_()` に集約**する（fail-closed）。
- 使用箇所 6 か所を `o1Config_()` 経由へ。
- ★ 検査を 1 つ**足した**: `O1_APP_DOWNLOAD_URL` が `https://` で始まらない場合。
  ⚠️ 「フォルダ ID だけ貼る」は実際にやりがちで、★ **未設定と同じ症状**になるため機械で分ける。

## テスト

- 98 ケース（96 → **98**）: URL でない値を報告する / ⚠️ **正しい URL は報告しない**（陽性対照）
- 変異 26 件（25 → **26**）: `https://` 検査を外すと赤
- ⚠️★★ **変異定義が 2 件陳腐化して「当たらなかった」と報告された**（★ ハーネスが正しく検知）。
  → 実体に追随させて 26/26 赤に戻した。
