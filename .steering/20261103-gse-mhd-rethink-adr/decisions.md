## 判断 1: 残す形

- **選択肢**: A 今決められる分だけ Accepted・データ待ちは候補と時期と条件だけ / B 全体を Proposed / C ADR を起こさず地図と steering だけ

- **理由**: 3 状態の名前とラベルの対応づけは段 1 の事前登録の改訂の前に決まっている必要がある。段の順の中身と ROCKET 系の値は本人の探索のデータを見ないと決められない。ADR-044 D3 と同じ作り。
- **見直し**: 本人の探索の後、候補の採否を別 ADR で決める。

## 判断 2: 3 状態の名前

- **選択肢**: A 主張と画面から外し、列名・enum は内部の識別子として残す / B 主張からだけ外す / C 列名も次に HMM_VERSION を上げるときに改める / D そのまま
- **採用**: A（推奨どおり）
- **理由**: 主の対象が停滞になり（ADR-045 D1）、状態を当てる主張をしない。列名を変えると schema と gse-dataset の整合、既存の記録との比べが切れる。
- **影響**: research-positioning の headline・L1、Dashboard.tsx の被験者向けの文（被験者モードでも名前を出す）、glossary。直しは別タスク。

## 判断 3: criterion 直結の段のラベル

- **選択肢**: A 二値の形と D5 の下限の形を残し、対象を「陽性の類」に一般化して事前登録で選ぶ / B 詰まりのまま / C 6 択の多クラス / D 予測のトラック（停滞の転帰）を主にし C4 は記述と監査だけ
- **採用**: A（推奨どおり）
- **理由**: ADR-045 は詰まりを特別扱いしない。多クラスは少ない類が件数を決める。D は ADR-042 D1・D5 の上書きが大きい。
- **影響**: S1-A3（「詰まり」の操作的な定義 → 陽性の類の定義）・S1-E4（下限の対象）・H1〜H3 で同じ定義を使う規則。事前登録の改訂は別タスク。

## 判断 4: 段の順と個人ごとの学習

- **選択肢**: A 1 人ごとを既定にし、個人・タスク適応の段は人をまたぐ部分プーリングと読み、時系列の段の候補に 1 人ごとの EM を足す / B ADR-019 の順のまま / C 順を決めず候補だけ
- **採用**: A（推奨どおり）
- **理由**: ADR-042 D1 は MhD の主張を人の中の推論に限り、段 1 の確認は 2〜4 名で人をまたぐ主張をしない。criterion 直結の段は事実上はじめから 1 人ごとに学ぶ。

## 判断 5: ROCKET 系の条件

- **選択肢**: A 3 条件（昇格ゲートの後・件数が公開データの空回しで過学習しなかった件数以上・設定を使う前にコミット）/ B 当面使わない / C 件数だけ
- **採用**: A（推奨どおり）
- **理由**: 空回しで学習の側 925 件・1,000 特徴・λ=10 で傾き 0.29、実の代理ラベルで 0.07（`experiments/20261103-mhd-pipeline-dryrun/notes.md` §2・§3）。段 1 の件数はそれより少ない見込み。値は決めない。

## 判断 7: /reimagine の採否

- **選択肢**: v1（D1〜D6 を文で）/ v2（2 部・段の表で全候補に入る条件）/ ハイブリッド（v2 の構成で、研究者が選んでいない条件は形も未定）
