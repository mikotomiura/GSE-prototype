## 判断 1: 前提条件 7 の範囲 —— (i)(ii)(iii) を全部含める【Q1】

- **判断日時**: 2026-09-20（研究者）
- **背景**: 事前登録 第 19 版の前提条件 7 は「G1 を途中でやめた人の途中までの記録を、確証解析で
  どう数えるか」を (a) §3.6 の同意撤回に当たるか / (b) n に数えるか / (c) 補充するか の 3 点で
  決めよと課すが、⚠️ **「やめた」以外の止まり方**が範囲に入るかが未定だった。
- **選択肢**:
  - A: (i)(ii)(iii) を全部含めて第 20 版で一度に決める
  - B: (i)（本人の申し出以外で完了しない人）だけ含める
  - C: 前提条件 7 は本人の申し出に限定し、(i)(ii)(iii) は前提条件 8 として別立て
- **採用**: **A**
- **理由**: 収集開始前に穴を残さない。★ 3 つはいずれも「**n と補充**」という同じ出口に効くので、
  別々に決めると計器の挙動（下記）と突き合わせる作業が 3 回に割れる。
- **トレードオフ**: 第 20 版で決める量が最も多い。
- **⚠️ 本タスクでは決めていないこと**: **(a)(b)(c) × (i)(ii)(iii) の中身**は研究者の裁定であり、
  ★ 本タスクでは**起草もしない**（★ 事前登録は §3 凍結・改訂は版で残る契約）。
  → `inventory.md` の **[研究者] G1-1** として、9 マスの表の形で次段へ渡す。
- **⚠️ 決めるときに突き合わせる計器の現在の挙動**（★ 3 つが別々の答えを出している。`evidence.md`）:
  `validate_blocks.py:225-259` は一部だけ実施を **FAIL** ／ `analyze.py:692-704` は 8 本未満を
  **静かに `skipped`** ／ `analyze.py:127-203` の名簿検査は **roster にいれば n に数え**、
  `:874-896` の群判定は **`skipped` を数えない**。
- **⚠️ 契約側の逐語**: §3.6 は「被験者を事後に除外しない（除外規則: **同意撤回のみ**）」と
  「ブロックを事後に除外しない（**技術的なログ欠損・切断のみ**）」の 2 行を持つ。
  `consent.md` §5 は「途中でやめられます」と「後からデータの削除を求められます」が**別項目**で、
  ⚠️ **「やめる＝削除」とは書いていない**。
- **影響範囲**: `preregistration.md` 第 20 版（改訂履歴）・`config.json` の `revision`・
  `validate_blocks.py` / `analyze.py`（⚠️ 挙動を変えるかどうかも第 20 版で決める）。
- **見直しタイミング**: G1 の収集開始の前（★ 締切）。

## 判断 5: cp932 は「呼び出し側で明示」＋「出力エンコーディングの固定」で直す

- **判断日時**: 2026-09-20（Claude・★ 研究者の裁定は不要な機械的修正）
- **背景**: `run.sh` が Windows の既定環境で **exit 1**。FAIL 2 件は**どちらも偽**だった
  （`config.json` は壊れていない／受付メールの開示範囲は守られている）。
- **選択肢**:
  - A: `run.sh` の冒頭で `PYTHONUTF8=1` を export する（1 行で全部直る）
  - B: 壊れている呼び出し側を個別に直す（`open(..., encoding='utf-8')` / `subprocess(..., encoding="utf-8")`）
  - C: B ＋ 出力だけ `PYTHONIOENCODING=utf-8` で固定
- **採用**: **C**
- **理由**: ★ A は **`run.sh` 経由でしか効かない**（研究者が `python3 analyze.py` と直接叩く経路が
  残る）。⚠️ さらに A は**ファイルの読み方まで変える**ので、将来の encoding バグを覆い隠す。
  ★ C は原因を潰したうえで、**出力の見た目だけ**を環境に依らず読めるようにする
  （⚠️ FAIL の理由が文字化けして読めないのは、見た目ではなく**判断**の問題）。
- **トレードオフ**: 直す箇所が 2 か所に増える。
- **実測**: 修正後 `bash run.sh`（`PYTHONUTF8` なし）で **exit 0 / `[GREEN] 全項目通過`**、
  `python3 scripts/check_g1_emails.py` 単体も **exit 0**。
- **影響範囲**: `experiments/20260801-controlled-friction-task/run.sh` / `scripts/check_g1_emails.py`。

## 判断 6: 移植性ゲートは「入れ子の worktree」を別枠にし、必ず note で出す

- **判断日時**: 2026-09-20（Claude）
- **背景**: `check-o1-release-readiness.sh` の赤 3 件目は**違反ではなく検査の故障**だった。
  `git ls-files --others` が入れ子の worktree を**末尾 `/` の 1 エントリ**で返し、
  それを開こうとして OSError → fail-closed（rc=2）。
  ★ 原因は 2026-09-16 の codex-rescue が残した `.worktrees/codex-rescue-20260916-theory-review/`。
- **選択肢**: A: `.worktrees/` を `.gitignore` に足す ／ B: 末尾 `/` を別枠にして note で出す ／
  C: worktree を消す
- **採用**: **B**
- **理由**: ★ 末尾 `/` は git が**入れ子リポジトリにだけ**付ける形であり、「開けなかったファイル」
  とは種類が違う（★ 必ず OSError になるので fail-closed の対象にすると誤報になる）。
  ⚠️ A は「見えなくする」だけで、他の環境で worktree を作った人が同じ罠を踏む。
  ⚠️ C は研究者の作業物を消すので agent が勝手にやらない（→ `inventory.md` の棚卸し項目へ）。
- **⚠️ 黙って除かない**: 走査対象外にしたことを **緑のときにも 1 行出す**
  （★ 「87 本走査して違反 0」だけが残ると、**何を見ていないか**が消える）。
- **★ この修正で 2 つの実害が表に出た**（⚠️ どちらも rc=2 に隠れていた）:
  1. **本物の違反 1 件** —— `.steering/20260914-mhd-feature-offline-tiers/issues/007-acceptance.sh:94`
     の `($OLD・…` → `(${OLD}・…` に修正（★ bash 3.2 で unbound variable になる形）。
  2. **明細が出ない故障** —— VIOL 行の多バイト断片が cp932 で encode できず `UnicodeEncodeError`
     で死に、⚠️ **「違反あり」と言いながら 1 行も出さない**（★ 本スクリプト冒頭が警戒している型）。
     → 走査器の stdout / stderr を UTF-8（`errors="backslashreplace"`）に固定した。
- **実測（3 状態）**: (a) 正常 = rc 0・NESTED の注記が出る ／ (b) わざと壊した入力
  （`tmp/_portability_probe.sh`）= rc 1・**明細が出る** ／ (c) 後始末後 = rc 0。
