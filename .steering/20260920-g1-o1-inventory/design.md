# 設計 — G1 / O1 の残タスクの棚卸し

## アプローチ

「棚卸し」を**文書の読み直し**ではなく**一次の実測**として行う。
引き継ぎ（`.steering/_handoff/next-session-g1-o1-inventory.md`）は未検証メモとして扱い、
そこに書かれた各行を「確かめる対象」に変換した上で、実測結果を `evidence.md` に落とし、
そこから `inventory.md`（台帳）を組む。

### 成果物

| ファイル | 役割 |
|---|---|
| `evidence.md` | 実測した事実と根拠（ファイル:行 / コマンド＋終了コード）だけを置く |
| `inventory.md` | 残タスクの台帳。各行に **[研究者] / [機械] / [ゲート]** の区分と根拠へのリンク |
| `decisions.md` | Q1〜Q4 の研究者判断と、本タスク内で下した設計判断（検査の置き場など） |
| `merge-plan.md` | main への統合計画（★ 実行しない） |

### 区分の定義（★ 台帳の意味を固定する）

- **[研究者]**: 研究の裁定が要り、agent が文言で埋めてはいけないもの。
  → 台帳には「問い」と「一次」と「締切」だけを書き、答えは `decisions.md`。
- **[機械]**: 判断が要らず、実行すれば終わるもの（検査の故障・encoding・記録先の追加など）。
  → 台帳には「Done の判定方法（コマンドと期待する終了コード）」を必ず書く。
- **[ゲート]**: 配布 / 収集の前に必ず止めるもの（ADR-034 D1 の律速 4 点など）。
  → 台帳には「何を満たすと開くか」と「今どれが閉じているか」を書く。

## 進め方（順序）

1. **一次確認**（並列・sonnet の調査エージェント 4 本）→ `evidence.md`
   - G1（前提条件 1〜7・`run.sh`・`config.json`・週の選択・Q1 の材料）
   - O1 / ADR-034（Migration 1〜6・ADR-031/032・release readiness・Q2 の材料）
   - マージ / schema parity / 配布経路
   - Q3 / Q4 の材料（CORE-CS・IDE R-1）
2. **研究者の判断**（Q1〜Q4 を一次つきで提示）→ `decisions.md`
3. **機械的な修正**（cp932・検査の故障）→ 実測で緑を確認
4. **検査の追加**（D6 ほか）→ ★ 壊した入力で赤・正常で緑の両方を実測
5. **台帳と計画**（`inventory.md` / `merge-plan.md`）
6. **レビュー**（`code-reviewer` ∥ `security-checker` = opus）→ `/cross-review` 2 巡

### 触らないもの（★ requirement.md のスコープ外と同じ）

- 配布の実行・タグの push・main へのマージの実行

## テスト戦略

- **機械的な修正**: 修正前に赤を再現 → 修正後に緑を実測（終了コードを記録）。
  ⚠️ 「緑になったはず」で終えない（`verify-before-claiming`）。
- **追加した検査**: ★ **3 状態を実測**する —— (a) 正常な入力で緑 /
  (b) わざと壊した入力で赤 / (c) 検査対象が無いときの挙動（skip なのか赤なのか）。
  ★ 過去 4 回、この自己検査を省いて「検査が空回りしている」のを見落としている
  （`feedback_acceptance_self_test`）。
- **回帰**: `run.sh` / `check-o1-release-readiness.sh` の**赤の本数と理由**を修正の前後で比較し、
  ⚠️ 意図せず赤が消えていないことを確かめる（★ 赤は「今は赤いのが正しい」ものを含む）。

## リスク

| リスク | 対処 |
|---|---|
| ⚠️ 「機械的な修正」のつもりで**検査の意味**を変えてしまう（緑を安く作る） | 修正の前後で赤の**理由**を並べて比較し、`decisions.md` に残す |
| ⚠️ 古い引き継ぎを根拠に台帳へ書き写す | 台帳の行は**根拠のあるものだけ**。根拠が取れない行は「未確認」として別表に隔離 |
| ⚠️ 研究者判断を推測で埋める | Q1〜Q4 は選択肢とトレードオフを示して選ばせる。答えが出るまで台帳では「未決」のまま |
| main とのマージで schema drift が表に出る | `merge-plan.md` に順序（マージ → dataset 同期 → タグ）を書く。★ 実行はしない |
