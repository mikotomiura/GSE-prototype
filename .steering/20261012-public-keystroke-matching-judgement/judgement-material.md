# 判定の材料: 公開データでの照合の論文を、IME 論文の次の論文にするか

2026-10-12。根拠は `docs/literature/20261012-public-keystroke-matching-novelty.md`（カード 1〜5・claim #1〜#22）。判定は研究者。

## 1. 新規性 —— どこが既知で、どこが新しいか

| 項目 | 状態 | 根拠 |
|---|---|---|
| 候補の文章との照合という攻撃 | **既知** | 時刻だけで公開データ（KM・PROSODY）に実施済み [V266]。長さの並びでの照合は打鍵の外で確立 [V268] [V269]。否決 #22 |
| 時刻だけからの本文の復元 | **既知**（強い） | KeyTAR [V267]（IEEE S&P 2026・LLM・Top-5 で 34.9%） |
| 公開された打鍵の記録の**加工**（`q` のマスク・`@` のマスク・キーの種類への縮約・時刻の丸め・長さを粗くする）の効き目を、照合で測ること | **0 件**（新しい） | #10。実際に `q` のマスクで出した記録がある [V265]（目的は逐語 *"To prevent reproduction of the essay text"*）・`@` のマスク [V243] |
| キーの種類だけの記録での照合 | **0 件** | #11 |
| 語長の並びの一意さ | **0 件** | #12（当方の青空文庫の実測は日本語で、未公刊） |
| 日本語 IME の公開データ | **0 件** | #13 |

まとめ: 新しさは「照合できる」ではなく、**「公開の現場で使われた加工が、照合に対してどれだけ効くか」**に置く。これが 0 件であることは、4 本の探索と引用の追跡で確かめた範囲の話で、「存在しない」とは言えない。

## 2. 主張の対応表（ADR-039 で当初言いたかったこと）

| 当初の主張 | 道 2 で | 理由 |
|---|---|---|
| データセットを公開する | **言えない** | 新しい収集をしない |
| 日本語 IME の打鍵 | **条件つき** | 公開の人のデータが 0 件。言えるのは IME 論文の合成入力と青空文庫の推定（既存の 2 つの実測）までで、人の日本語の照合は言えない |
| 照合の危険 | **言える**（英語の人の自由作文） | KLiCKe [V264] の本文で正解が分かる。ただし「照合できる」自体は既知なので、危険の大きさを公開の形式ごとに示す形 |
| 加工の効き目 | **言える**（芯） | 実際の加工（`q`・`@`）と、当方の候補の加工（キーの種類・時刻の丸め・長さを粗くする）を同じ攻撃で比べる |
| 公開前の関門の設計 | **条件つき** | 手順を提案して公開データで示すことはできる。GSE の参加者の記録での検証は言えない |

## 3. 実行の見込み

- **データ**: KLiCKe（約 5,000 本・英語・Google Drive・無料・リポジトリは MIT・データのライセンスは明示なし）。Kaggle の記録 [V265] は学術研究で使える（CC-BY-NC 4.0）が、本文が無いので評価の正解にはならない。
- **攻撃**: 既存のコードを使い回せる。長さだけの攻撃 L（`experiments/20261009-*`）・区切りの乱れを許す攻撃 L_align（`experiments/20261011-g1-copy-self-trial/scripts/align.py`）・加工の関数（前の試作）。新しく要るのは、英語の記録から区間（空白・句読点の間の文字の打鍵数）を作る前処理と、`q` のマスクを再現する加工。
- **おとり**: 同じ課題の別の作文（話題で絞れない難しい候補）が KLiCKe の中に 1,136〜1,329 本ずつある（論文の Table 4・4 課題で計 4,992）。
- **時刻の攻撃**: 査読で「最も強い攻撃」を問われる。[V266] の型（時刻だけで候補を照合）は自前で実装できる見込み。KeyTAR [V267] の公開モデルを使うなら GPU が要る（G-GEAR で回せるかは未確認）。
- **計算**: 長さの攻撃は前の実測と同じく数分〜数十分の見込み（5,000 本 × 候補 1,000）。
- **作業量の目安**: 事前登録 1 セッション → 前処理と攻撃と自己検査 2 セッション → 本計算と notes 1 セッション → 原稿 3〜5 セッション（IME 論文の実績からの推定）。
- **投稿先**: PoPETs（費用ゼロ・会場での発表は掲載の条件でない・倫理の考察の節が必須・プライバシーの計測は範囲に合う [V271]）。BRM（購読型なら無料・既存データでも「国と機関しだい」[V237]）。JoWR（費用ゼロ・範囲が合うか未確認 [V272]）。

## 4. 危険

1. **倫理の承認**: BRM は既存データでも承認が要りうると書き、所属機関に確かめよと求める（[V237]・否決 #20）。研究者は機関の審査を受けられない。→ PoPETs なら承認は条件でないが、倫理の考察の節で「外部の委員会に出していない理由」を書くことになる。日本の生命科学・医学系指針は、本文の照合は定義に当たらない可能性が高い（私の読み・法的判断ではない）[V270]。
2. **データの同意**: KLiCKe の論文は倫理審査の承認と公開への同意を書いていない（#2）。公開したデータに照合を当てた論文は、そのデータの参加者の文章が照合されうることを示すことになる（ただし本文はすでに公開されている）。→ 解析の前に著者へ、同意の文面とデータのライセンスを尋ねるのが安い。
3. **同じ研究が既にある**: 照合そのものは既知（#22）。加工の評価の 0 件は、絞った探索 4 本と引用の追跡で確かめたが、Google Scholar の被引用の追跡と作文研究の著者別の検索は残っている（カードのやり残し）。→ 事前登録の前にもう一度だけ確かめる。
4. **Kaggle と KLiCKe の結び付け**: 同じ作文なら、本文を隠して出した記録の本文が別に公開されていることになる（#5・未確認）。確かめることは隠された本文の照合そのものなので、しない選択がある。KLiCKe の記録に同じマスクを掛ければ、結び付けなしで加工を評価できる。
5. **攻撃が弱いと言われる**: 時刻の攻撃 [V266] [V267] より弱い攻撃だけで「加工が効く」と言うと、上限ではない。→ 時刻の攻撃を参照として並べ、「効く」とは書かず「この攻撃に対して」と書く。

## 5. Claude の推奨

**範囲を絞って採る**。英語の公開データ（KLiCKe）で、公開の現場の加工（`q`・`@`）と候補の加工を照合で評価する論文にする。日本語は既存の合成入力と青空文庫の推定を付録に置く程度。投稿先の第一候補は PoPETs（費用ゼロ・承認を条件にしない・範囲が合う）。解析に入る前に KLiCKe の著者へ同意とライセンスを尋ねる。Kaggle と KLiCKe の結び付けはしない。

（判定の後の追記・2026-10-12）研究者の指示で KLiCKe の条件を調べ直した。データの利用条件は Inputlog のページにあり「自由に使える・研究ではリポジトリを出典に示す」[V273]。§3 の「データのライセンスは明示なし」は、この記述を見つける前のもの。倫理審査と公開への同意の記載は、論文・README の全版・博士論文 [V274] のどこにも無い（§4 の 2 はそのまま）。

理由: 新しさが 0 件の芯（加工の評価）に置け、材料とコードの大半を再利用でき、研究者の制約（審査なし・費用ゼロ・登壇なし）を満たす誌がある。弱みは、データセットの公開と日本語 IME という当初の 2 本の柱を手放すこと。

## 判定の後の訂正（2026-10-12・完了時のレビュー）

- §1 と §2 の「日本語 IME の公開データは 0 件」は誤り。日本語 IME の変換過程を含む公開の翻訳の打鍵ログ ENJA15（[P273] [P359] [P360]・39 人・keydown のみ）が登録済みだった。研究者は判断 5 で、条件つきで日本語の節として入れると決めた。
- §3 の Kaggle のライセンスは、規則の見出し（CC-BY-NC-SA 4.0）と第 7 条（CC-BY-NC 4.0）で食い違う（[V265]）。
- §3 の PoPETs の「承認を条件にしない」は強すぎた。逐語は「倫理の節に外部の委員会に出したかを書く・基準を満たさないと却下されうる」。「発表は掲載の条件でない」も、確かめたのは会場での参加までで、オンライン発表の要否は未確認（[V271]）。
- §5 の「研究者の制約を満たす誌がある」は投稿の規定の話で、研究を実施してよいか（所属機関の規程）は別に確かめる。
