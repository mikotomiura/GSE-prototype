# 重要な設計判断

判断はすべて研究者が AskUserQuestion で行った（2026-10-12）。材料は `judgement-material.md`、根拠は `docs/literature/20261012-public-keystroke-matching-novelty.md`。Claude は 4 問とも推奨を添え、研究者は 4 問とも推奨を選んだ。

## 判断 1: 公開データでの照合の論文を、範囲を絞って IME 論文の次の論文にする

- **判断日時**: 2026-10-12（研究者）
- **背景**: 2026-10-11 に、GSE で新しく集める打鍵データセットの論文を見送った（ADR-039 D1 の注）。代わりの候補（道 2）を、新規性・データ・倫理を調べてから採るかを決めることにしていた。
- **選択肢**:
  - A: 範囲を絞って採る（英語の公開データ KLiCKe [V264] で、公開の現場の加工（`q` [V265]・`@` [V243] のマスク）と当方の候補の加工を照合で評価する。日本語は既存の合成入力と青空文庫の推定を付録に置く程度）
  - B: KLiCKe の著者の返事まで保留
  - C: 採らない（別の候補を探す）
- **採用**: A
- **理由**（Claude の推奨の理由）: 照合そのものは既知（[V266] [V267]・否決 #22）だが、公開の記録の加工の効き目を照合で測った研究は 0 件（#10）で、新しさをそこに置ける。3 つの実測のコードの大半を再利用できる。研究者の制約（審査を受けられない・費用ゼロ・登壇なし）を満たす誌がある（判断 2）。
- **トレードオフ**: ADR-039 の当初の 2 本の柱（データセットの公開・日本語 IME の人の打鍵）を、この論文では手放す（judgement-material.md §2）。
- **影響範囲**: ADR-039 D1 の注（2026-10-12 の注を追記）・次のセッション（事前登録の設計）。
- **完了時のレビューでの補足（2026-10-12・Codex 1 巡目）**: 「研究者の制約を満たす誌がある」は投稿の規定の話で、研究を実施してよいかの条件（所属機関の規程）は別の確認事項であり、未確認のまま。→ 引き継ぎで、データの取得の前に研究者が所属機関の規程を確かめることを開始条件に足した（法的な要否の断定ではない）。
- **完了時のレビューでの訂正（2026-10-12・Codex 1 巡目）**: 材料の「日本語 IME の公開データは 0 件」は誤り。ENJA15（[P273] [P359] [P360]）が登録済みだった → 判断 5。
- **未決のまま残したこと**: G1・O1・研究者本人の記録（`experiments/20261011-g1-copy-self-trial/`）をこの論文に使うか。Claude の提案は「使わない」（審査の論点＝ADR-039 事実 1・D3 に入らない形）だが、研究者は決めていない → 次のセッションで尋ねる。
- **見直しタイミング**: 著者への問い合わせ（判断 4）で、データの利用や照合の研究に制約があると分かったとき。事前登録の前の再検索（Google Scholar の被引用の追跡・作文研究の著者別）で、同じ研究が見つかったとき。

## 判断 2: 投稿先の第一候補は PoPETs

- **判断日時**: 2026-10-12（研究者）
- **選択肢**: A: PoPETs ／ B: BRM ／ C: 事前登録の段で決める
- **採用**: A
- **理由**: APC と投稿料が無い・会場での発表は掲載の条件でない・倫理審査の承認を条件にしない（倫理の考察の節が必須）・プライバシーの計測が範囲に合う（[V271]）。BRM は既存データでも「国の法と指針しだい・所属機関に確かめよ」と書く（[V237]）。
- **完了時のレビューでの訂正（2026-10-12・Codex 1 巡目）**: [V271] の逐語が言うのは「会場での参加は掲載の条件でない」（*"in-person attendance is not strictly required"*）までで、オンライン発表や録画の提出が要るかは書かれていない。→ 「登壇なし」は未確認。投稿の前に確かめる（引き継ぎに入れた）。下のトレードオフの「（必須ではない）」「条件（登壇なし・費用ゼロ）は字面で満たす」は、「会場での参加は必須ではない」「費用ゼロは字面で満たす・登壇なしはオンライン発表の要否が未確認」と読み替える（2 巡目のレビュー）。承認についても、逐語は「倫理の節に外部の委員会に出したかを書く・基準を満たさないと却下されうる」で、「承認を条件にしない」は強すぎた（code-reviewer 1 巡目）。
- **トレードオフ**: PoPETs は発表を *"strongly encouraged"* とする（必須ではない）。diamond OA（費用なし）で、研究者の従来の「購読型の誌」の方針とは形が違うが、条件（登壇なし・費用ゼロ）は字面で満たす。範囲の注意（*"Papers that treat privacy as a superficial application domain … are therefore out of scope."*）に当たらない書き方が要る。
- **見直しタイミング**: 2027 年の募集の締切と規定が変わったとき（投稿の前に規定を読み直す）。

## 判断 3: Kaggle の記録と KLiCKe を突き合わせない

- **判断日時**: 2026-10-12（研究者）
- **背景**: Kaggle の記録 [V265]（本文を `q` で隠した）と KLiCKe [V264]（本文ごと公開）は同じ構成の手順で集められている。同じ作文なら、隠した本文が別に公開されていることになる（claim #5・未確認）。
- **選択肢**: A: 突き合わせない ／ B: 著者に尋ねる ／ C: 突き合わせる
- **採用**: A
- **理由**: 突き合わせることは隠された本文の照合そのもので、論文に要らない。KLiCKe の記録に同じ `q` のマスクを掛ければ、加工の効き目は評価できる。論文では「同じ構成の手順（同じ作文かは未確認）」と書く。
- **影響範囲**: 事前登録で、Kaggle の記録を照合の対象にしないことを明記する。

## 判断 4: 解析の前に KLiCKe の著者へ尋ねる・送るのは研究者

- **判断日時**: 2026-10-12（研究者）
- **背景**: KLiCKe の論文は倫理審査の承認と公開への同意を書いておらず（claim #2）、データのライセンスも明示されていない（論文 CC BY-NC-ND 3.0・リポジトリ MIT）。
- **採用**: 尋ねる。文面は Claude が下書きし（`author-inquiry-draft.md`）、研究者が自分のメールで送る。
- **理由**: 尋ねるのは安く、答えを倫理の考察の節に書ける。
- **影響範囲**: データの取得と解析は、返事を見てから（返事が来ない場合の扱いは次のセッションで研究者が決める）。
- **判断の後の追加の確認（研究者の指示「KLiCKe の件をもう一度具体的に調べて」・2026-10-12）**: GitHub のリポジトリは README と LICENSE（MIT・ソフトウェアの定型文）だけで、README の全 8 版にデータの条件は無い。Drive のフォルダは zip 3 つと人口統計の CSV だけ。論文のページの CC BY-NC-ND 3.0 は論文の条件。**データの条件は共著者 Van Waes の Inputlog のページにあった**（[V273] 逐語 *"These files can be downloaded and used freely. However, if you wish to use them in your research project, please reference this repository as an original"*）。同じ構成の募集の博士論文 [V274] にも倫理審査と同意の記載は無い。→ 問い合わせの主眼は同意の文面と倫理審査の有無に移した（`author-inquiry-draft.md` の問い 1 を、条件の確認に書き換えた）。

## 判断 5: 日本語 IME の公開データ ENJA15 を、条件つきで日本語の節として入れる

- **判断日時**: 2026-10-12（研究者・完了時のレビューの後）
- **背景**: 材料（judgement-material.md）と文献カードは「日本語 IME の公開データは 0 件」と書き、判断 1 はそれを前提に日本語を補いに回した。完了時の `/cross-review` 1 巡目（Codex）が、ENJA15 が登録済みであることを指摘した。ENJA15 は英→日の翻訳の打鍵ログ（39 人・Translog-II・Creative Commons）で、2026-09-13 に生ログで IME の変換過程（`Type="IME"`・`IMEtext`）と確定した文字列が残ることを確かめていた（[P273] [P359] [P360]）。記録は keydown だけで keyup は無い。
- **選択肢**:
  - A: 入れる（条件つき）。KLiCKe に加え、ENJA15 で日本語 IME の記録の照合と加工を評価する節を置く。おとりは同じ原文の他の訳者の訳。事前登録の前にライセンスの種類と利用条件を一次で確かめ、合わなければ外す
  - B: 英語だけにする（ENJA15 は将来の拡張として記録だけ残す）
  - C: 事前登録の段で決める
- **採用**: A
- **理由**（Claude の推奨の理由）: 判断 1 で手放した「日本語 IME」の柱を、人の記録で一部取り戻せる。既存の青空文庫と合成入力の実測とつながる。
- **トレードオフ**: 翻訳は自由作文ではない。keyup が無いので、時刻の加工の一部（保持時間）は評価できない。
- **影響範囲**: ADR-039 D1 の 2026-10-12 の注（追記）・引き継ぎ。判断 1 の「日本語は補いに置く程度」と、判断 1 のトレードオフ「日本語 IME の人の打鍵の柱を手放す」は、この判断で改める: 日本語 IME の人の打鍵は翻訳の記録（ENJA15）の範囲で扱い、自由作文の日本語 IME は引き続き主張しない（判断 1 の本文は書き換えない）。
- **取得の開始条件**（2 巡目のレビュー）: ENJA15 は KLiCKe の著者への問い合わせと関係しない。ENJA15 の取得は「研究者が所属機関の規程を確かめた」＋「ライセンスの種類と利用条件を一次で確かめた」の 2 つで開始する。[P360] で 2026-09-13 に確かめのために取得した `P01_T1.xml` の扱い（版を固定して取り直すか）は事前登録で決める。
- **見直しタイミング**: ENJA15 のライセンスの種類・利用条件が照合の研究に合わないと分かったとき。
