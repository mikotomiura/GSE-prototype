## 0. 結論（先に）

1. ★ **「再開」と「再停止」は、ADR-030 の条件 A（産出）の *辺* だけから定義できる**。新しい定数は要らない（`W` と `net_diff_min` の再利用）。
   - **再開 `r`** = 原点 `o` 以後で、条件 A が **true → false** に落ちる最初の時刻
   - **再停止 `s'`** = `r` 以後で、条件 A が **false → true** に立ち上がる最初の時刻（＝ ADR-030 の `s` と同じ種類の辺）
2. ★ EVAL-NCC 草案の「再停止 = 主課題イベントが連続 30 秒以上途切れる最初の時点」は、**`W` = 30 秒・イベント = 純産出**と読めば同じ形になる。
   → ★ **EVAL-NCC 側は原点 `o` だけを差し替えて同じ定義を使う**（定義は 1 つ）。
3. ⚠️★★★ **この定義を詰める途中で ADR-030 D7 の穴が見つかった**（§2）。「再停止」を定義することは、
   **「1 つの停滞の中の短い再開」と「別の停滞」をどう分けるか**（＝ ADR-030 Consequences **7z2**「束ね方」）を決めることと同じである。→ **J-11**
4. ⚠️ `T1d` は **retrospective な記述量（転帰側）であり、オンラインの推論・介入の入力にしない**（ADR-017 D8 / ADR-024 §Migration「再開後の動態は *アウトカム* であって、決して *入力* にしない」・issue 006 AC7）。
5. `T1c` は 4 項目とも**候補から暫定選択はできる**が、名前（`rewrite` / `loop depth`）が**本文・カーソル位置を持つ先行研究の構成概念**を指しうるため、
   ★ **サーヴェイ S7（content-free な修正の操作化）を先に 1 ラウンド回してから確定する**ことを推奨する（§6）。

## 1. 土台（ADR-030 の逐語と実装）

- **条件 A**（D3）: 因果窓 `W`（右端 = 評価時刻・look-ahead ゼロ）の中で `net = Σ挿入系 press − Σ削除系 press` が `net < net_diff_min`（既定 1）。
- **`s`**: 条件 A が false → true へ**立ち上がった**時刻。**`t0 = s + θ_person`**（条件 A が `θ_person` の間 true を保ったとき）。
- **不応期**（D3）逐語: 「`t0` は 1 つの立ち上がり `s` につき 1 度だけ置く。⚠️ **次の onset は、条件 A が一度 `false` に戻るまで発火しない。**」
- **実装**（`stall_onset.rs:434-465`）: 観測区間ごとに `prev` を持ち、`cond_a[i] && !prev` で立ち上がりを取る。`prev` は**毎評価時刻で更新**される。
- **評価時刻**（D3）: `{key 行の t} ∪ {key 行の t + W} ∪ {s + θ_person}`。
  → ⚠️ 条件 A が true に立ち上がるのは「**最後の純産出から `W` 経過した瞬間**」である（`s` は最後の打鍵より最大 `W` 遅れる・D3 逐語）。

## 2. ⚠️★★★ 見つかった穴: ADR-030 D7 の「次の `t0` は起きえない」は実装上成り立たない

ADR-030 D7 の「`Decision Episode` の終わり」表:

> | ★ **次の `t0` が立った** | ⚠️ 起きえない —— D3 の**不応期**が挟まる（★ 条件 A が一度 `false` に戻らないと次は発火しない） |

⚠️ しかし「条件 A が一度 `false` に戻る」には **`W` 内で純産出が `net_diff_min`（= 1 文字）以上あれば足りる**。
一方、エピソードを閉じる転帰（ADR-029 D2 の `recovery`）は **`progress_proxy` が個人基準を超え、T 秒取り消されないこと**で、はるかに強い。

→ **反例**（`W` = 30 s）: 停滞中（`t0` 済み）に 1 文字だけ打って止まる
→ 条件 A が false に落ち（`r`）、30 秒後に再び true に立ち上がり（`s'`）、`θ` 後に **新しい `t0'` が立つ**
→ ⚠️ **前のエピソードは転帰も打ち切りも起きないまま、次のエピソードが始まる**（D7 の表の前提が破れる）。
→ ⚠️ 停滞中の「1 打鍵」がエピソードを**過剰分割**する —— ★ ADR-030 自身が [V146]（Zou & Godfrey）から受けた警告
（「断片の検出」と「断片を同一タスクへ束ねる」を分けないと過剰分割に落ちる・Consequences **7z2**）がここで現実になる。

⚠️ **ADR-016 D1 により「再停止」を 4 択の第 5 カテゴリ（転帰）にすることはできない。**
→ 選択肢は 2 つ（→ **J-11**）:

| | **E1 連結**（★ 推奨） | **E2 分割**（現行実装のまま） |
|---|---|---|
| 規則 | エピソードは **ADR-029 D2 の転帰（`recovery` / `externalized` / `left_observation`）か打ち切り**でだけ閉じる。**その間の条件 A の再立ち上がりは新しい onset にしない**（不応期を「条件 A が false に戻るまで」から「**エピソードが閉じるまで**」へ延ばす） | 再立ち上がりごとに新しい onset・新しいエピソード。前のエピソードは次の `t0'` の手前で**事象なしに終わる** |
| 短い再開の扱い | ★ **エピソード内の「再開の試み」**として `T1d` が記述する（何回再開し、各試みがどれだけ続き、いつ再停止したか） | 前エピソードの末尾に 1 回だけ現れる |
| ADR との整合 | ★ D7 の表の意図（次の `t0` は起きない）を実装に合わせて**正しくする** | D7 の表を**訂正**する必要がある |
| 生存解析上の代償 | ⚠️ `recovery`（`progress_proxy`）が**未実装**の間は、エピソードは `externalized` / `left_observation` / 打ち切りでしか閉じない（長いエピソードになる） | ⚠️★★★ 前エピソードの終わりが**情報のある打ち切り**になる（「再び止まった」ことで打ち切られる ＝ 転帰と相関）。ADR-029 D3 が退けた「潰す」扱いと同型 |
| 過剰分割（[V146]） | ★ 起きない | ⚠️ 起きる |

★ **推奨は E1**。理由: (i) ADR-030 D7 が書いた意図に一致する、(ii) 情報のある打ち切りを作らない、(iii) 「再停止」を**エピソード内の記述量**に置けるので ADR-016 D1（第 5 カテゴリ禁止）に触れない。
⚠️ **代償**: `recovery` の実装（ADR-009 は Proposed・`ContextBuilder` 未実装）までは、**`T1d` の集計窓の右端は観測区間の右端（打ち切り）**になる。

## 3. 定義案（★ 1 つの定義から 2 つの用途へ）

### 3.1 共通定義（★ 新しい定数ゼロ）

```text
入力      : key 行の (t, category, press)。産出の写像は ADR-030 D3 のまま（挿入系 / 削除系 / どちらでもない）
条件 A    : ADR-030 D3 のまま（W・net_diff_min を再利用）
原点 o    : 用途ごとに与える（§3.2 / §3.3）

再開   r_k : o 以後で、条件 A が true → false に落ちる k 番目の時刻
再停止 s'_k: r_k 以後で、条件 A が false → true に立ち上がる最初の時刻
生成区間    : [r_k, s'_k)  ＝ 条件 A が false であり続けた区間
```

- ★ **`s'_k` は ADR-030 の `s` と同じ種類の辺**である（★ onset と対称。`W` の遅れも同じく含む）。
- ⚠️ **修飾キー規則**（起票 11）: 判断 25 #5 / #12 のとおり **P1 の解析設計までは「規則なし」の極だけ**（＝ 現状）。両極を出す段で `r` / `s'` も両極で出す（★ 独立に報告し、他の極と Cartesian に組まない）。
- ⚠️ **観測区間**（ADR-030 D8 (b-2)）: `r` / `s'` も**同じ観測区間の中でだけ**評価する（★ 区間をまたがない）。区間の右端 `b` に達したら打ち切り。

### 3.2 用途 1: `T1d`（issue 006）—— retrospective な記述量

| フィールド | 定義 | 値が無いとき |
|---|---|---|
| 原点 `o` | **`t0 + B`**（★ ADR-030 D2 の buffer。`B` は `StallOnsetConfig::b_ms` から引く・issue 006 AC4） | — |
| 集計窓 | **E1 なら `[o, エピソードの終わり)`**（★ 起票 17 の候補 **C**）／ **E2 なら `[o, 次の onset の s)`**（★ 候補 **A**）。いずれも観測区間の右端 `b` で打ち切る | — |
| `restop_ms` | **`s'_1 − o`**（原点から最初の再停止まで） | 窓内に `r_1` が無い、または `s'_1` が窓内に無い → **`null`**（⚠️ 0 で埋めない・AC3 の精神） |
| `stable_generation_ms` | **`s'_1 − r_1`**（最初の再開から最初の再停止までの生成区間の長さ） | `r_1` が無い → `null`。`s'_1` が窓外（打ち切り）→ **`null`**（★ 打ち切りを値で埋めない） |
| （導出） | `r_1 − o = restop_ms − stable_generation_ms`（原点から最初の再開までの遅れ）—— ★ 2 フィールドから復元できるので**フィールドを足さない** | — |
| `post_t0_inserts` / `post_t0_deletes` / `post_t0_navigations` | 集計窓内の press を ADR-030 D3 の写像で数えた回数（`navigation` は「どちらでもない」側の `navigation` カテゴリだけ） | 窓が空 → `0` ではなく… ★ **窓があって press が 0 件なら `0`**、onset が無い行は `null`（AC3） |

- ★ 起票 17 の候補表との対応: `restop_ms` = **候補 A**（条件 A の次の立ち上がり・`W` の再利用・onset と対称）。
  `stable_generation_ms` = 候補 A の欠点（「`restop_ms` とほぼ同じ量」）を、**原点を分ける**ことで解消した（`restop_ms` は `o` 起点、`stable_generation_ms` は `r_1` 起点）。
- ⚠️★★★ **役割の制約**: `T1d` は **`t0` の後を見る retrospective な量**であり、
  **同じエピソードの予測にも、オンラインの推論・介入にも入れない**（ADR-017 D8 / ADR-024 §Migration / issue 006 AC7）。
  ⚠️ **ADR-030 D10 の Tier 表は `T1d` を特徴量の Tier に並べているが、中身は転帰側である**（D10 の証拠列「自己発生 stall 後の安定回復を予測できるか」自体が「`T1d` を予測する」と読める）。→ ADR-030 補訂案 **項目 7** で明記する。
- ⚠️ 前のエピソードの `T1d` を**次のエピソードの予測子**に使うこと（[V147] の「過去履歴の統制」）は、**ADR-024 §Migration の「決して入力にしない」に当たるか**が一次で決まっていない。→ ⚠️ **本案では使わない側に倒す**（★ 使うなら別 ADR）。

### 3.3 用途 2: EVAL-NCC の後続転帰（`eval-ncc-analysis-contract.md` §6 の置き換え案）

| 転帰 | 現草案 | ★ 置き換え案 |
|---|---|---|
| 原点 | W0 の終わり（expiry） | ★ **同じ**（`o` = 招待の W0 の終わり） |
| 再開 | 主課題チャネルの最初の有効作業イベント | ★ **`r_1`**（条件 A の最初の立ち下がり）。主課題チャネル = 打鍵課題なら `key` 行 |
| 再停止 | 再開後に主課題イベントが連続 30 秒以上途切れる最初の時点（閾値は課題選定後） | ★ **`s'_1`**（条件 A の再立ち上がり）。「30 秒」は **`W`**（★ 30 秒系列から事前宣言する値そのもの） |
| 外部化 | 事前指定の外部化チャネルへ移る | ★ 語を **`externalized`**（ADR-009 D2）へ。GSE の実体は `paste`（受領） |
| 離脱 | 課題終了・ウィンドウ離脱・明示終了・観測窓末まで戻らない | ⚠️★★★ **分解する**（ADR-029 D5「censoring を `departure` から分離する」を採る）: ウィンドウ離脱 = **`left_observation`**（focus 事象）／課題終了・観測窓末 = **打ち切り**（管理的） |

- ★ 状態図（`eval-ncc-dag.md` §6）の `Resumed → Restopped` はそのまま使える（辺の定義だけが確定する）。
- ⚠️ **非打鍵課題**（GR-H11 の判断課題など）では条件 A が定義できないので、**再開・再停止は `not applicable`（構造的欠測 `STR`）**。
- ⚠️ **ADR-029 D1 の一方向の禁止**: 本定義の量を**予測トラックの入力**に使わないかぎり、報告・評価側の転帰として使ってよい（★ 推定器の出力ではなく時計の事実なので ADR-023 D7 の自己言及は起きない）。

## 4. 採らなかった案

| 案 | 中身 | 採らない理由 |
|---|---|---|
| R-B | 再停止 = **次の onset `t0'`**（`s' + θ_person`） | ⚠️ `θ_person` が `warmup_count` 未満で `None` になる人では再停止が**定義不能**（起票 14）。EVAL-NCC の短い実験では個人分位点が立たない。★ `s'` と `t0'` の差は `θ` の定数ずれであり情報は増えない |
| R-C | EVAL-NCC は「30 秒の主課題イベント途絶」、`T1d` は条件 A（**別定義のまま**） | ⚠️★★★ **研究者判断 25 #9 が禁じた「転帰の定義を 2 つにする」そのもの** |
| R-D | 再停止 = `PAUSE_THRESHOLD_MS` 以上の次の pause（起票 17 候補 B） | ⚠️ 語間ポーズで数秒に退化する。かつ 2 秒閾値は「伝統」であって検証されていない（[P123]・ADR-030 Context-3b (iii)） |
| R-E | 「安定生成」= 窓内で pause を挟まない最長 burst（起票 17 候補 B） | ⚠️ 同上（2 秒閾値への依存）。★ ただし writing research の **P-burst**（pause で終わる産出の塊）と同じ形なので、**サーヴェイ S8 の結果次第で副次指標として足す余地はある** |

## 6. `T1c`（issue 004）—— revision 系 4 項目の算出式

### 6.1 前提（一次）

- ADR-030 **D11**: `delete run` / `rewrite` / `再削除` / `loop depth` / `局所 recurrence` は `key` 行だけで作れる（計器変更不要）。`undo` / `redo` は作れない。
- ADR-030 **D10** 証拠列: 「★ 中〜強（Tier 中で最も強い）。⚠️ **ただし先行研究は本文・カーソル位置を持っている**」／ GSE で未検証「本文なしの delete / rewrite / undo・redo loop」。
- 起票 9: `.idea/survey:189` は**名前の一覧だけ**で算出式は無い（裁定セッションが一次で確認）。
- ★ **「CORE-CS / 修正の理論と突き合わせる」について**: ⚠️ **CORE-CS 契約は修正（revision）について何も定めていない**（停止閉包・非再捕捉の契約）。`T1c` は MEAS 側（Mh-D の特徴量）であり、CORE-CS から来る制約は **content-free（`KeyCategory` と時刻だけ）**の 1 点だけである。
  → ★ 突き合わせるべき「修正の理論」は **writing research の修正分類**（本文・カーソル位置を使う）であり、これは repo に未登録である（[V31] Leijten & Van Waes 2013 が `provisional`、`Conijn et al. (2021) revision detection` は `.idea/survey §13` の未登録リスト）。→ **サーヴェイ S7**

### 6.2 候補と推奨（★ 共通原則: 新しい定数を作らない・burst は既存の pause SSOT で切る・D/I の写像は ADR-030 D3）

| 項目 | ★ 推奨 | 算出式（案） | 理由 | ⚠️ 名前のリスク |
|---|---|---|---|---|
| `delete_run_max` / `delete_runs` | （一意・起票 9 が追認） | 連続する削除系 press の最大長／本数 | — | — |
| `rewrite_count` | **候補 A（隣接再開）** | 削除の走りの**直後の press** が挿入系である回数 | ★ 最小の content-free な「削除 → 書き直し」。pause SSOT にも依存しない | ⚠️ writing research の rewrite は**位置**（先端か既存本文か）を含む。GSE は位置を持たない → 「先端での訂正」と「遡った書き直し」を区別できない |
| `redelete_count` | **候補 A（burst 内の 2 本目以降）** | pause SSOT で切った burst の中で、2 本目以降に現れる削除の走りの本数 | ★ 既存 pause SSOT の再利用。候補 B の「ちょうど 1 件」は恣意的な定数 | ⚠️ 「同じ箇所を再び消した」は位置が無いので言えない |
| `loop_depth_max` | **候補 A（交替回数）** | burst を `{D, I}` の run-length 列に圧縮したときの遷移回数の最大 | ★ 候補 C（push/pop 深さ）は**入れ子**を仮定するが、位置が無いと入れ子は識別できない | ⚠️★★★ 「depth」は入れ子を含意する → **名前を `revision_alternations_max` 等へ変えるべき**（★ AC1 のフィールド名の変更 ＝ 研究者判断） |
| `local_recurrence` | **候補 B（burst 内の bigram 重複率）** | burst 内の `KeyCategory` bigram のうち重複するものの割合を、burst が閉じた tick に帰属 | ★ 候補 A は tick（1 秒）が短すぎて bigram が数個しか入らない。候補 C は `redelete_count` と冗長（起票 9 が却下済み） | ⚠️ 「recurrence」の文献上の定義（recurrence quantification analysis 等）と一致させるかはサーヴェイ次第 |

★ **位置の代理**（★ 本案の追加提案・未検証）: `navigation`（矢印・Home/End 等）や `pointer_bin` の `buttons` が**削除の走りの直前**にあるかで、
