# 様式の並びから「作業」に名前を付ける（auto-context-task-level・auto-context-segmentation の 2 段目）

## 背景

前のタスク（`.steering/20261121-auto-context-segmentation/`）では、文脈の量の 180 秒の窓を人ごとに混合ガウスでまとめ、名前（task-A など）を付けた。本人の振り返り（11-19〜11-21）では、名前は「作業」ではなく作業の中の様式として合った（5 つのうち 4 つ）。

- A: 日本語を打ちつつ画面を行き来する
- B: 日本語で読みながら少し直す
- C: 日本語を続けて打つ
- E: マウスが中心
- D（英字モード・入力少）は合わなかった。研究者の言は「違う PC などでタスクを行なってたかも」。

凍結した基準での判定は、本人が使えない（宣言との照合・状態の写し）、O1 の P006・P011・P013 が判定できない（宣言が 1 値）だった。宣言（`task_kind`）がほとんど変わらないので、宣言との照合は土台が弱い。

## ゴール

様式の名前の列を、より長い窓（30〜60 分）での様式の割合にまとめ、その割合を人ごとにまとめて「作業」の名前を付ける。境界は様式の割合が変わったところにする。

そのうえで、事前に凍結した基準で、人ごとに「使える／使えない／判定できない」を判定する。

## スコープ

### 含むもの

- 2 段目の解析（様式の割合の窓・人ごとのまとめ・境界）を `experiments/<日付>-auto-context-task-level/` に置く。前のタスクの `acs_core.py` の 1 段目をそのまま使う。
- 照合の材料は 2 つ（研究者が決定・判断 3）。
  1. 本人がその場で書く作業の記録。区間を見る前に書く。日は 11-22 から 3 日。
  2. git のコミットの repo と時刻。内容は読まず、repo の名前と時刻だけを使う。
- 「この Mac の外にいる時間」（入力が少なく、時々触れるだけ）は様式の 1 つとして残し、作業の段で「外にいる」と読む（判断 2）。
- 合成の対照には、宣言の経路と振り返りの経路を最初から入れる。陽性・陰性・壊した入力を終了コードで確かめる。
- 判定の基準（`criteria.json`）は、実データを処理するコミットより前に凍結する。
- アプリの識別子が要るかの見積もり（外れ方から数で）を `decisions.md` に残す（判断 4）。
- 本人の入力は、最終の数を出す前に写しを取って固定する（記録が書き足され続けているため）。

### 含まないもの

- 自動の名前を推定・Nudge・介入判定の入力にすること（ADR-010 D3・ADR-014 D4b）。
- 段 1 で配っているアプリの挙動の変更。
- アプリの識別子の記録（計器の変更・data-privacy・ADR-012 D3 の改訂が要る。取るかは結果を見て別のタスクで決める）。
- 他の PC（G-GEAR・職場の PC）の GSE の記録をつなぐこと（記録がこの Mac に無い。集めるなら別のタスク）。
- 記録・特徴行・作業の記録・コミットの一覧を外部（Codex を含む外部 LLM）に送ること。`/cross-review` に回すのはコードの diff だけ。
- 論文化の検討（結果を見て別に行う）。

## 受け入れ条件

- [ ] 合成の対照（様式の列から作業を切り替える記録）で、陽性は終了コード 0、陰性は 0、壊した入力（作業の切り替えを消したもの）は 3 で落ちる。選ぶのに使わなかった seed でも同じ。
- [ ] 合成の対照に、宣言の経路と振り返り（作業の記録）の経路が入っていて、一致する人は「使える」・一致しない人は落ちる・材料の少ない人は「判定できない」になる。
- [ ] `criteria.json` が、実データを処理するコミットより前のコミットに入っている。
- [ ] 本人の作業の記録（11-22〜の 3 日）が、区間を見せる前に書かれている。書き終えた時刻を decisions に残す。
- [ ] 本人と O1 の 3 人の判定を `notes.md` に記録する（入力の SHA-256 の要約値は `data.md`）。
- [ ] 識別子の要否の見積もりを decisions に残す。
- [ ] `/cross-review`（Claude と Codex・diff だけ）と security-checker を通す。
