## 設計案比較

### v1 の要旨

1 段目の 3 分の様式の名前を、重ならない 30 分の作業の窓で割合（加法対数比）と無操作の割合にする。人ごとに混合ガウス（k = 1..6・BIC）でまとめ、最小の滞在長 2 窓（60 分）で平滑化して `work-*` の名前を付ける。1 段目の関数（`select_gmm`・`smooth_labels`）をそのまま使う。

### v2 の要旨

様式の名前の列を観測とする隠れマルコフモデル（状態 = 作業・出力 = 様式のカテゴリ分布・自己遷移は平均 45 分の滞在から固定）を人ごとに当て、Viterbi で区間と名前を同時に出す。窓の格子を置かず、境界は 3 分の解像度で出る。無操作は欠測、長い無操作とファイルの継ぎ目でリセット。

### 主要な差異

| 観点 | v1 | v2 |
|---|---|---|
| アプローチ | 窓 → まとめ → 平滑化（1 段目の形を繰り返す） | 作業を隠れた状態とするモデル 1 つで区間と名前を同時に出す |
| 境界の解像度 | 30 分の格子（境界は窓の端にしか出ない） | 3 分 |
| 事前に決める値 | 窓の長さ T・最小の滞在長・疑似カウント・少ない窓の下限 | 平均の滞在 D・リセットの無操作の長さ |
| 新しく書くコード | 窓の割合だけ（まとめと平滑化は 1 段目を使い回す） | HMM（前向き後ろ向き・Baum–Welch・Viterbi・欠測）を新しく書く |
| データの量（O1） | P006 約 40 窓・P013 約 55 窓（30 分） | 3 分の列をそのまま使うので約 430・570 窓。再現性の半分の下限に届きやすい |
| 短い作業 | 30 分より短い作業は割合に埋もれる | 平均 45 分の事前だが、出方が十分違えば短くても切れる |
| 作業の記録との照合 | 30 分の窓ごと（記録の分の解像度を捨てる） | 3 分の窓ごと |
| テスト戦略 | 1 段目の関数は検査済み。窓の割合の単体テスト | 前向き後ろ向きを総当たりと比べる単体テストが要る |
| リスク | 窓の格子の位置で境界がずれる・窓が少なく O1 で測れない | 自前の HMM の誤り・D の値への依存・各状態が様式 1 つを出すだけになりうる（様式の写しの検査で捕まえる） |

### 推奨案

ハイブリッド（v2 を本体にし、v1 を感度の比べとして並べる）。理由:

- 要件の「境界は様式の割合が変わったところ」を、窓の格子の位置に左右されずに出せるのは v2。作業の記録はその場で分の単位で書くので、3 分の解像度で照合できる方が記録を活かせる。
- O1 の 2 人で、v1 の 30 分の窓は 40〜55 本しかなく、再現性の前半・後半の下限（各 20）にぎりぎり。v2 は様式の窓をそのまま使うので測れる人が減らない。
- v2 の弱み（自前の実装）は、小さな列で総当たりの尤度と比べる単体テストで塞げる。v1 は既存の関数の組み合わせで安く書けるので、同じ合成と同じ照合に v1 も通し、判定は v2 だけで行い、v1 の結果は記述として並べる（判定に使う案を 1 つに凍結し、多重性を作らない）。
