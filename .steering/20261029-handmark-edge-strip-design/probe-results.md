# どける操作の短い試しの結果（2026-10-29）

試作: `probe/strip.swift`（前のタスクの `probe/strip.swift` を写して足した）。足したもの:
- 隠す前と戻した後の層 0 の窓の前後の順番（窓の番号と pid だけ。名前は読まない）を比べる `order_check`。
- `--restore-order`: 戻すとき、元の重なりの奥のアプリから順に `activate(.activateAllWindows)` し、最後に元の前面のアプリを出す（約 0.2 秒おき）。
- `--activate-first` で、自分が前面に出たことを確かめてから隠す（最大 1 秒待つ）。run14 から。

画面は撮っていない。目視は研究者の言葉。どの試しも O1 は止めていない。

読めること:

1. **全画面の中では、どける操作で背景は出せない。** 外から全画面のアプリは隠れず、accessory の自分も前面に出られない（2 回）。全画面の間に背景を見せる面は、下の縁の帯だけになる。
2. **全画面でないときは、前面に出たことを確かめてから隠せば、前面のアプリも隠れる見込み。** run11 では前面のアプリも隠れた（`active_not_hidden=0`）が、待たずに隠した run12・run13 では前面のアプリが 1 つ残った。前面に出るのは非同期で、間に合うかどうかで分かれたと読む（推測）。待つ版は全画面の外ではまだ試していない。
3. **前面に出られないアプリが 1 つ残ることがある**（run11 の 1・run15 の 2 のうち前面でない 1）。研究者は VS Code と見た。原因は見ていない。
4. **戻すときの重なりの順番は、窓の番号では毎回元どおりだった。** run11 で Safari が見えなかったのは再現しなかった（run12・run13）。原因は分からないまま。`--restore-order` は元の前面のアプリを前面に戻す点で効いた（run13）。
5. 帯の負荷は 1 コアの約 7〜11%（60 回/秒）で、前のタスクと同じ。

## 試し 4: regular のまま非アクティブの NSPanel（論点 1 の v2・run16）

条件: `--regular --panel`（GSE 本体と同じ regular・`NSPanel` の `[.borderless, .nonactivatingPanel]`・浮く層・前と同じ振る舞い）。テキストエディットを AXFullScreen で全画面にした約 25 秒の間を読んだ。隠す操作はしていない。

- 記録: 全画面の間（8〜33 秒）ずっと `onscreen=1`・`front_of_layer0=1`・`visible=1`。切り替えの 1 秒（7 秒目）だけ front=0。負荷は 1 コアの約 7〜11%。
- 研究者の目視: 「見えた」。
- 読めること: **regular のアプリでも、非アクティブの NSPanel なら他アプリの全画面の上に帯を出せた**（1 回）。前のタスクで regular の NSWindow が全画面の Space に入らなかったのと分かれたのは、窓の種類（NSPanel・nonactivating）。どちらが効いたか（NSPanel であること・nonactivating であること）は分けて測っていない。テキストエディット以外の全画面では見ていない。
