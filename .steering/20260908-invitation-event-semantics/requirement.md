# 招待（`invitation`）の配送意味論を確定する —— `W-2` を閉じる

## 背景

★ `docs/architecture/expression-channel.md` §8 の **`W-2`**（2026-09-07 起票・`/cross-review` 指摘）は、
表現チャネルの境界契約に **3 点の穴**が空いていると書いている。⚠️ **一次で全部確認した**:

| # | 穴 | ★ 一次（逐語） |
|---|---|---|
| **1** | **発火条件** | ★ `docs/adr/ADR-017-expression-channel-boundary.md:87` 逐語「★ **発火条件**: **`level` が変わったときだけ**。⚠️ **1Hz を流さない。**」／⚠️ **ADR-021 D4（`:184-211`）は `invitation` を独立フィールドにしたが発火条件を改訂していない**（★ **実測**: D4 本文に「発火」「1Hz」は **0 件**）→ ⚠️ **字義どおり読むと `none → present` が届かない** |
| **2** | **初期同期** | ★ ADR-017 D2 再接続の意味論 項目 3 逐語「★ **再接続直後は「現在の `level`」を 1 発だけ送る初期同期を行う**」→ ⚠️ **`invitation` の現在値を送るとは書いていない** ＝ **再接続後に招待が失われる** |
| **3** | **解除の区別** | ⚠️ **`present → none` をどう表し、チャネル断とどう区別するかが一次に無い** |

★ **いま塞ぐ理由は 2 つある**:

1. ⚠️★★★ **招待が届かないと層 A の符号体系が成立しない。**
   ★ **実測**（`expression-channel.md` §3.5.2b / ADR-022 D1）: **A-7（持続振動）は第 1 版の符号から外され、
   代替として `invitation` の符号は「面の縁が開く / 閉じる」（★ 開口＝招待）に確定している。**
   → ★ **発火しなければ縁は永久に閉じたままで、招待は層 A に 1 度も現れない。**
2. ★ **いま決めるのが最も安い** —— ⚠️ **実測（2026-09-08 再確認）: `invitation` は `src-tauri/src/` に 0 件・`src/` に 0 件。**
   ★ **実装が 1 行も無いので、契約を直しても書き換えるコードが存在しない。**
   ⚠️ **順序を逆にすると「招待が届かない実装」が先に固まる**（★ `W-2` 自身の警告）。

## ゴール

★ **`W-2` を閉じる。**★ そのために **ADR-027** を起こし、3 点（発火条件 / 初期同期 / 解除の区別）を確定して
SSOT（`expression-channel.md` / `glossary.md` / `docs/adr/README.md`）へ反映する。
