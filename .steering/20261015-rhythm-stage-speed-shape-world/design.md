### 1.2 world `f(c)` と `d(c)`（`gen_sessions.py`）

- `--world factor --c C` と `--world drift --c C` を足す。区間の設定は揺れの world と同じ `graded_segments(cfg, speed_confound.base_t)`（`g(0.5)`）、`δ` も同じ（`confound_delta`・約 0.3788）。
- `Speed` に成分の選び方 `shape` を足す（`"both"`・`"factor"`・`"drift"`）。
  - `w(k) = δ · (a_u · u + a_d · d(k))`。`both` は (a_u, a_d) = (1, 1)、`factor` は (1, 0)、`drift` は (0, 1)。
  - 実装は、`both` は今の式 `δ * (u + d(k))` のまま、`factor` は `δ * u`、`drift` は `δ * d(k)`（0 を掛けて足す形にしない。`both` の出力をバイト単位で変えないため）。
  - **乱数の引き方は shape に依らず同じ**: `u` → `d(0)` → `ε_0` → … の順に、同じ流れ `derive_rng(seed, "speed", <組>, i)` から引く。`factor` でも `d` の列を作る（使わないが、引く順と延ばし方を変えない）。
  - `--world confound` は `shape="both"` のまま、出力をバイト単位で変えない。
- **seed**: 同じ `SEED`（20261020）を使う。成分の乱数の流れは区間と打鍵の乱数と別なので、`f(c)` の各単位の `u` は `h(c)` の同じ単位の `u` と同じ値、`d(c)` の各単位の `d` の列は `h(c)` の同じ単位の `d` の列と同じ値になる。成分の大きさの引きが world の間で対になり、world の差が成分の引きの違いで説明されることを避ける。
  - ただし打鍵の数が変わるので、区間と打鍵の乱数の位置は world ごとにずれる。区間の構造と打鍵は world の間で対にならない（揺れの design §1.3 の段の間と同じ）。
- **組ごとの扱い**（単位・時刻の起点・D_noobs に掛けない）は、揺れの design §1.3 の表と同じ。
- **D_shuffled の跳び**: `speed_jumps.json` を両方の world で書く。`f(c)` では単位の中で `z` が一定なので、跳びは 0 になる（記述）。`d(c)` では `c·δ·(d(first) − d(last))` である。
- **c = 0 の端**: c = 0 では `z ≡ 0` なので、打鍵と区間（NDJSON・ラベル・`sessions.json`）は、同じ seed の `--world graded --t 0.5` とバイト単位で一致する。`world.json` だけが違う。
- **c の範囲と拒否**は揺れの world と同じ（0 以上 4 以下・`--world factor`・`drift` に `--c` が無ければ拒む・graded や v4 に `--c` を付ければ拒む）。
- **成分の大きさ**: `z` の標準偏差は、`f(c)` と `d(c)` のどちらも `c·δ`（c = 1・2 で約 0.379・0.758）。`h(c)` の全体は `√2·c·δ`。総量はそろえない（判断 2）。
  - 漂いの 60 s の増分の標準偏差は `d(c)` で `h(c)` と同じ（約 `0.60·c·δ`）。`f(c)` では 0。
- **段**: `config.json` の `ceiling.steps` を `{"f100": 1.0, "f200": 2.0, "d100": 1.0, "d200": 2.0}` に、新しく `ceiling.worlds` を `{"f100": "factor", "f200": "factor", "d100": "drift", "d200": "drift"}` にする。
  - `checks.world_problems`・`ceiling.py`・`pilot_check` は、`world.json` と `pilot.json` の world と c を、段の `worlds[step]` と `steps[step]` に照らす。
  - `run.sh` の `--step` は `[fd][0-9][0-9][0-9]` の形だけを受け、`ceiling.worlds` の値を `--world` に渡す。

### 1.3 `r` の側の陽性の対照 PCr（`stage.py`・判断 6・判断 7）

PC-stall は、停滞の割合のブロックの値を `a` の側の駆動に入れ、`r` の側を 0.5 の定数にする（第 1 回 design §1.4）。PCr はその左右を入れ替え、`r` の側にだけ手がかりを入れる。2 つの形を作る。

- **ブロック**: PC-stall と同じ作り。60 s のブロックごとに `U`・`N` を引き、`q` = 前の 300 s の停滞の割合、値 = `U < λ` なら `q`、そうでなければ `N`。乱数の流れは PC-stall と別にする: `SeedSequence([seed, key_seed & 0xFFFFFFFF, 43])`（PC-stall は 37）。`pc_blocks` に流れの番号の引数を足し、既定は 37 のままにする。
- **PCr-level** `PCrl-<候補>`: 駆動 `u_a ≡ 0.5`、`u_r` = ブロックの値（10 Hz の点ごとに繰り返す）。
- **PCr-var** `PCrv-<候補>`: 駆動 `u_a ≡ 0.5`、`u_r = 0.5 + s · v_b · e_j`。
  - `v_b` はその点のブロックの値、`s` = `pc_r.var_sd` = 0.2。
  - `e_j` は点ごとに独立な標準正規で、流れ `SeedSequence([seed, key_seed & 0xFFFFFFFF, 47])` からセッションの点の数だけ一度に引く。
  - 水準の平均は 0.5 のままで、ブロックの値が揺れの大きさ（`r` の窓の中の標準偏差と隣の点との差）だけを動かす。`v_b ≤ 1` なので、0 と 1 での切り落としは点の約 1 % 以下。
- **土台**: `PCrl0-<候補>`・`PCrv0-<候補>`（λ = 0・値は常に `N`）。
- **`a` は λ に依らない**（`/cross-review` 1 巡目）: PCr の `a` は「0.5 の定数」と候補の止まり方だけから作られ、λ にも family にも依らない。したがって `r` の量をすべて落とすと、PCr とその土台の特徴は同じになる。止まり方を通じた停滞の漏れ（止まっている間に `a`・`r` が凍る・0 になる・減衰する）は、λ に依らないので、土台の `upper_max` が拾う。
- どれも、候補の止まり方の判定（`drive(inp, res)` の `stopped`）と、候補の写像・止まり方・（`jitter` なら）揺れ・切り落としを通す（`shape`）。PC-stall と同じ原則である。
- **写像との関係**（宣言・推論）:
  - `smooth`（30 s の指数平滑）は、点ごとに独立な揺れをほとんど消す（標準偏差が約 0.04 倍）ので、`smooth` の候補の PCr-var はほぼ働かないと見込む。
  - `rank` は値を順位に替えるので、揺れの大きさの手がかりは一部だけ残る。
  - 働かないことも、その写像では揺れの型の手がかりが描画を通らない、という結果として書く。
  - 止まり方が `hold` で止まっている間は `r` が凍り、揺れが消える。止まっていることは停滞と相関しうるので、この漏れは土台（λ = 0）が拾う。
- **λ の較正（下見 1 の第 3 の部分 L300r）**:
  - 下見 1 の列（`SEED + 1`・P 240）の L300 で、family（level・var）ごと・候補ごとに `[0] + pc_r.pilot_grid` の λ で当てはめる。
  - `pc_r.pilot_grid` は、PC-stall の格子（0.025〜0.3 の 12 点）に 0.4・0.5・0.6・0.8・1.0 を足した 17 点（判断 10）。固定の前の試作（P 40）で、λ = 0.3 では PCr も PC-stall もほとんど帯に届かなかったため。
  - 選び方は PC-stall と同じ `select_lambda`（`aim` 0.055・帯 (0.03, 0.08]・L300 の天井の分類器を外した攻撃者の最大・第 2 回 design §3.9）。`pilot.json` に格子（`rule_r`）を書き、本番と読みはそれを `config.json` と照らす。
  - L300r は L300 の部分が止まらなかったときだけ回す（強い対照 PC1 の条件は L300 の部分が見ている）。
  - 有限の点推定が 1 つも無い候補は、その family の λ を `null` にする（段は止めない）。項目 1 の判定は PCr を使わないので、PCr の較正の失敗は項目 1 に効かない。
- `config.json` に `pc_r` を足す: `{"var_sd": 0.2, "pilot_grid": [...], "lam": {}}`。`--apply-pilot` が `pc_r.lam.<段>` に `{"level": {候補: λ か null}, "var": {…}}` を書く。
  - `var_sd` の値そのものは `stage.py` の定数 `PCR_VAR_SD` にあり、`config.json` の値は宣言である。自己検査が 2 つの一致を確かめる（config だけを変えても描画は変わらず、指紋だけが変わる）。
  - `cfg_fingerprint` は `pc_r.lam` も除く（下見の後に書くので）。
  - 本番と読みは、`pilot.json` から選び直した値と `config.json` の値が一致することを確かめてから使う（PC-stall と同じ・`main_lams`）。
- PCr の名前は `checks.kind_of` で `descriptive` とし、項目 1 の判定・帰無・73 本の論理積には入れない。PCr を当てはめるのは、下見 1 の L300r と、本番の後の読み（§1.4）だけである。

- **(i) 成分の読み**（このタスクの主な問い・記述・検定しない）。同じ c で `h(c)`・`f(c)`・`d(c)` の L300 の判定を並べ、world の状態（§1.5: 赤あり・赤なし・決まらない・走っていない）で次のように読む。候補ごとの判定も並べる。

| `f(c)` | `d(c)` | 読み（この試行で言えること） |
|---|---|---|
| 赤なし | 赤あり | この試行では、`d(c)` でだけ赤が出た。`h(c)` の赤は漂いの成分と同じ側に出た |

| 赤あり | 赤あり | この試行では、どちらの world でも赤が出た |
| 赤なし | 赤なし | この試行では、どちらの world でも赤が出なかった。`h(c)` の赤が 2 つの成分の組によるのか、揺れの総量（`√2·c·δ` と `c·δ`）によるのかは分けられない |

  - 読みを作るのは、`h(c)` に赤があり、`f(c)` と `d(c)` がどちらも「赤あり」か「赤なし」のときだけである。どちらかが「決まらない」か「走っていない」なら、その c の読みは作らず、状態をそのまま書く（`/cross-review` 1 巡目: 判定できなかった world を「赤が出なかった」と読まない）。

  - c が同じでも、`f(c)`・`d(c)` は `h(c)` より揺れの総量が小さい（標準偏差が `1/√2`）。AUC(A_speed) の高さも違いうるので、AUC(A_speed) を必ず並べる。
- **(j) 切り分けの読みと PCr**:
  - 候補の読み（残る・消える・決まらない・読めない）は、切り分けの design §3.1〜§3.4 と同じ。
  - PCr の読みは、変種ごと・family ごと・候補ごとに、`PCr*` の 2 攻撃者（full・small）の最大で決める。最大の作りは切り分けの design §3.1 と同じ（NaN を含めば NaN）。

| PCr の読み | 条件 |
|---|---|
| `not_calibrated` | その family と候補の λ が `null` |
| `unreadable` | `PCr*` か `PCr*0` の最大に NaN がある、または `PCr*0` の `upper_max` が 0.03 以上 |
| `works` | `lower_max` > 0.03 かつ `gain_max` ≤ 0.08 |
| `over` | `lower_max` > 0.03 かつ `gain_max` > 0.08 |
| `fails` | `upper_max` < 0.03 |
| `unclear` | ほか |

  - 境目は切り分けの design §3.6 と同じく、0.03 ちょうどはどれにも入らない（`unclear`）。
  - **読み方**（`R2` を落とした変種で、候補が「消える」とき）。PCr の `R2` の読みは、**同じモデル・同じ family の `none` で `works` か `over`** のときだけ使う。`none` で働かない対照は、`R2` での結果を何も示さない（`/cross-review` 1 巡目）。
    - `PCrl`（水準）が `R2` でも `works` か `over`: その攻撃者は、`R2` を落とした後も、この大きさの `r` の水準の型の手がかりを拾えた。候補の上乗せが消えたことを、「`R2` を落とすと `r` の側が何も見えなくなる」ことでは説明できない。
    - `PCrv`（揺れ）が `R2` でも `works` か `over`: この大きさの揺れの型の手がかり（点ごとに独立な揺れ）は、`R2` を落としても残りの量（例えば `r_p10`・`r_p90`）で拾えた。それでも候補の上乗せが消えたなら、候補の手がかりは PCr-var の揺れとは違う形で `R2` の 2 量に偏っていたか、PCr-var より小さかった（どちらかは分けない）。
    - `PCrv` が `R2` で `fails`: この対照の上乗せは、`R2` を落とすと 0.03 未満になった。これは「揺れの型の手がかりは `R2` を落とせば常に消える」ことを示すものではない（この形・この大きさの対照について言えるだけ）。候補が消えたことと、この対照が消えたことは並べて書くが、候補の手がかりが `R2` だけにあったとは読まない。
    - `unclear` は読まない。
  - `Rall` では PCr を当てはめない（§1.4）。止まり方を通じた漏れは、λ に依らないので、土台（`PCr*0`）の `upper_max` が 0.03 以上になる形で現れ、そのときの読みは `unreadable` になる。
  - 本番の L300 で天井だった分類器（`main_ceiling_kinds_L300`）の変種では、PCr の λ はその分類器を外して較正されている。その変種で PCr が `fails` か `unclear` でも、天井のために余地が無かった可能性があるので、`R2` の読みには使わない（`none` の値は並べる）。
  - `none` での PCr は、較正の確かめ（下見 1 とは別の列なので、帯の外に出うる）。
  - PCr は `smooth` の候補では働かないと見込む（§1.3）。
  - PCr の読みも記述で、判定（緑・赤）の語は使わない。
- **(k) 結果の前の見込み**（推論・固定の時点で書く）:
  - `f(c)`: セッションの中で速さが揺れないので、A_speed の前の窓との比べ（L60 の前の 4 窓、L300 の直前 L 秒）で相対的な遅れを読める。揺れの総量も `h(c)` より小さい。AUC(A_speed) は `h(c)` より高く、`f100` は天井（`ceiling`）になりうる。窓ごとの `r` の揺れの量は、倍率でセッションの間の水準が変わるだけなので、赤は出にくいと見込む。ただし倍率は窓の打鍵の数を通じて `r_sd` の水準も変えうるので、確かではない。
  - `d(c)`: 漂いは窓の中・隣り合う窓の間で揺れるので、`h(c)` に近い赤が出うる。AUC(A_speed) は `h(c)` と `g(0.5)` の間と見込む。
  - 読みでは、`d(c)` で赤が出れば、`R2` を落とすと消えると見込む（原因の切り分けと同じ型）。
  - PCr: `none` では `works`、`R2` では `PCrl` が `works` か `over` のまま、`PCrv` は `works` か `unclear` と見込む。
  - 見込みと違っても、それも結果として書く。

## 9. Claude が足した細部（研究者が変えてよい）

研究者が決めたのは判断 1〜8（ブランチ・成分を抜くだけ・c100 と c200・読みを入れる・並べて回す・PCr を作る・水準と揺れの 2 本・`/reimagine` を使わない）。次は Claude が足した細部で、固定の前に研究者が変えてよい。

1. `SEED` を `h(c)` と同じ 20261020 にし、成分の引きを world の間で対にしたこと（§1.2）。
2. 段の名前を `f100`・`f200`・`d100`・`d200` にし、world を `ceiling.worlds` に置いたこと。
3. 段の順を `d100` → `d200` → `f100` → `f200` にしたこと（値には効かない）。
4. PCr のブロックを PC-stall と同じ作り（60 s・前の 300 s の停滞の割合・`U < λ`）にし、乱数の流れを別（43・47）にしたこと。
5. PCr-var を点ごとに独立な正規の揺れ（標準偏差 `0.2 · v_b`）にしたこと。AR(1) などの遅い揺れにはしなかった。
6. PCr の λ を PC-stall と同じ規則で選び、格子を 1.0 まで延ばしたこと（判断 10）。較正の失敗で段を止めないこと。
7. PCr を全 24 候補で作ったこと（`res=sub` の 12 本だけにすれば、段あたり約 2 h 減る）。
8. PCr を当てはめる変種を `lr`・`hgb`・`lrbin` × `none`・`R2` に限ったこと（`Rall` では土台と同じになるので当てはめない・`A2`・`lrbin2` も当てはめない）。

11. 並べる表を `compare.py` で一次の JSON から作り、前のタスクのファイルを SHA-256 で照合すること。
