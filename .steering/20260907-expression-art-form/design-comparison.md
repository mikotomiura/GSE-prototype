# 設計案比較 — (a)「層 A に数値を添えるか」の裁定の形

## v1 の要旨（★ 局所裁定）

★ **「数値を添えるか」を Yes/No で答える前に「*何の* 数値か」を問う。**
★ 添えうる量の候補を全数（`p_stuck` / 経過時間 / 回数 / 累計 / `level` の数字化）挙げ、
**ADR-021 D4・ADR-018 D2/D3・ADR-020・ADR-009 D2 に 1 つずつ照合すると、許される量は 0 個**になる。
→ ★ **「添えない」は美学的選好ではなく既決の連立の帰結**である、という形で ADR-025 を閉じる。
★ 加えて **[P324] 系（行動が動く）と [P77]（享受・継続が下がる）は矛盾ではなくトレードオフ**だと整理する。

## v2 の要旨（★ 横断規則 ＋ 検査点）

★ **6 本の既決（§4.1 / ADR-018 D2 / D3 / ADR-020 / ADR-021 D4 / ADR-009 D2＋ADR-024）は
別々の理由で置かれたが、指している機序は 1 つ**である ——
**「本人が自分の状態を *量* として追跡できるようにすると、その量の最適化が目的になる」**
（★ **[P77]** ＋ **[P163]** の機序 3 ＋ **[P243]**）。
→ ★ ADR-025 は **「GSE は本人に *自分の量* を返さない」という横断の規則**を立て、
**層 A に数値を添えないのはその帰結**と位置づける。
★ さらに **§7.5 に受け入れ観点 A17 を追加して規則を検査可能にし**、
⚠️ **[P243] により「自己定量化そのものは防げない」限界を同時に書く。**

## 推奨案

★★★ **ハイブリッド（v2 の機序統一 ＋ v1 の射程限定）を推奨する。**

★ **理由**:

1. ★★★ **v2 の「6 本は同じ機序を指している」は、v1 の「候補が 0 個」より*壊れにくい*** ——
   ⚠️ v1 は既決の連立に依存するので、**ADR が 1 本動くと裁定ごと揺れる**。
2. ⚠️★★★ **しかし v2 の全面適用は `requirement.md` の Out（層 B の仕様を決めない）を超える** ——
   ★ かつ **層 B は「任意閲覧・数十秒」で曝露の性質が層 A と違う**ので、
   **同じ規則が同じ強さで当たるとは限らない**（★ ⚠️ ただし **[P77] は opt-in でも害が残ると実験 2 で示している**ので、
   「任意だから安全」も**言えない**）。
3. → ★★★ **規則は v2 の形で立てるが、`Accepted` の射程は *層 A* に限る。**
   ★ **層 B・オンボーディング・結果返却への適用は §8 に *新しい未決* として残す。**

★ **ハイブリッドの具体**:

| # | 採る | 出典 |
|---|---|---|
| 1 | ★ 機序の統一（6 本 → 1 本）と、その根拠 3 本（[P77] / [P163] / [P243]） | **v2** |
| 2 | ★ 候補の量の全数照合表（「許される量は 0 個」） | **v1**（★ v2 の規則を層 A で*実際に効かせる*のはこの表） |
| 3 | ★ 「添える」側の論拠 5 本の明示的却下 | **v2** |
| 4 | ★ **`Accepted` の射程を層 A に限定**し、層 B 等への波及は §8 の未決へ | **v1 の射程** |
| 5 | ★ §7.5 に **A17** を追加（★ 検査可能化） | **v2**。⚠️ ただし **層 A に限定した文言**にする |
| 6 | ★ `:72` / `:712` のねじれを閉じる（★ 「確定」の根拠を ADR-025 に置く） | ★ **両案に無かった追加**（サブエージェント実測） |
