# 設計判断 — 未踏提出文書の整合性修正と提案書の整理

## D1. PC 上の表現は「提案書の記述だけ役割で整理」する。設計は変えない

- **決定**: ADR-017 既決 **D21「PC 画面内の表現層は常時リアルタイム（案 α）」は覆さない。**
  提案書の `【PC上の表現】` 節を廃し、表現の配置を役割で書き分ける:
  - 常時の状態表示 → スマートフォンの任意閲覧面（ADR-021 D1 が層 A の第一媒体をロック画面に決定）
  - 招待の提示面 → PC（ADR-021 **D6**）
  - Nudge → PC（現行唯一の稼働介入）
- **理由**:
  1. D21 は ADR-017 の「生きている既決（本 ADR はこれらを覆さない）」表に載っており、
     `docs/architecture/expression-channel.md:32` の媒体ツリーにも
     「PC 画面内表現（既存。既決 D17 / D21 で常時リアルタイム = 案 α）」として現存する。
     **提案書だけ先に書き換えると docs と食い違う。**
  2. ADR-015 / 017 / 018 / 021 / 022 と `expression-channel.md` を grep しても、
     「PC 上の表現を削除する」「スマホのみにする」という決定は **1 件も無い**（実測）。
     削除されたのは Wall のみ。
  3. ただし `expression-channel.md:543-548` は [P267]（同一面の周辺表示は主課題を
     最良でも 26% / 連続で 43% 低下）を引いて逐語
     「同じ一次が、表現を PC の作業面に置かずスマホへ分離する設計そのものを支持する」と書く。
     → **方向は支持されているが、決定されていない。** 記述の整理はこの範囲で行える。
  4. ADR-021 D6 は招待を PC 側に置くと決めている。理由は
     `intervention.rs:229` の `record_dismiss` が PC にのみ実在し、
     スマホ側だと受容も拒否も自己申告になり ADR-017 D5 の評価基準を満たさないため。
     → **一律の「PC 表現削除」は D6 に抵触する。**
- **却下案**:
  - *新規 ADR で D21 を覆す*: 設計としては筋が通るが、スコープが倍になる。
    提案書の 10 ページ制約対応と同時にやると両方が中途半端になる。**別タスクへ送る。**
  - *現状維持*: 提案書 `【PC上の表現】` が「画面端の線や形の変化」を書いており、
    ADR-021 D1 でロック画面を第一媒体に決めた後の設計と読者に誤解を与える。
- **残る宿題**: D21 を降ろすかの判断。降ろすなら新規 ADR が要る。

## D2. 技術設計書 §8 の日本語 IME 主張を、出典のある形へ弱める

- **決定**: 逐語「日本語の多段階変換プロセスを記録した公開データセットは**国際的に存在しない**」を、
  `docs/literature/20260703-intervention-content-and-ml-grounding.md:184-185` にある
  出典つきの版（「日本語 IME 込みの pause 位置分類は世界的に空白。Hylog [V5] が唯一の隣接」）
  に沿う形へ弱める。**主根拠は自前実測 2 本に移す。**
- **理由**:
  1. 当該断定は `docs/` 全体で **技術設計書 :597 の 1 箇所のみ**（`.steering/` は 0 件・実測）で、
     **出典が無い**。同ファイルの他の主張は `[n]` を付ける形式である。
  2. **技術設計書 §0 が自分に課した規約に抵触する。** 逐語:
     「特に、**「先行研究が無いこと」を「有望であること」の根拠として使わない。**」
  3. 「唯一の隣接」とした **[V5] Crotti et al. Hylog に精読カードが無い**（実測）。
     存在否定を支える最低限の裏取りが済んでいない。
  4. `docs/glossary.md:246` が「不便益を測定可能にした」を禁じたのと**同じ型**の断定である。
- **代わりに前へ出す自前実測（出典不要）**:
  - `docs/architecture.md:104-112`: IME 変換セッションは候補リスト表示ではなく
    ローマ字入力〜確定の全体を覆い、pause すると **日本語論述の推定窓が約 56〜60%**
    （実データ fixture `phase1_ime_heavy` では **94%**）消える。
    → `HMM_VERSION` 0.4.0 → 0.5.0 の設計変更が実際に起きた。
  - `src-tauri/src/analysis/heads/writing.rs:16-36`: `β_writing` F1 = **100ms**（日本語 IME・実測較正）
    に対し `β_writing_latin` F1 = **150ms**（Dhakal et al. 2018 の一般母集団中央値由来）。
    → 英語圏コーパスの中央値をそのまま当てると日本語窓を誤採点する。
- **却下案**:
  - *強いまま残し `/literature-review` を 1 ラウンド回す*: 筋は通るが本タスクが倍になる。
    **別タスクへ送る**（[V5] の精読カード ＋ `references.md` への登録）。
  - *触らない*: §0 の自己規約違反が提出物に残る。査読者が §0 と §8 を並べて読む可能性がある。

## D3. 整合性修正（A）と提案書の整理（B）はコミットを分ける

- **決定**: A を先に 1 コミット、B を別コミットにする。
- **理由**: `docs/development-guidelines.md` §2 の「1 コミット 1 論理単位」。
  A は他文書・指示書・書誌にまたがる回帰修正、B は 1 ファイルの内容改訂であり、
  revert の単位が違う。
