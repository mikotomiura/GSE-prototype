# 要件 — 未踏提出文書の整合性修正と提案書の整理

## 背景

2026-09-03 のレビューで、未踏提出文書とリポジトリ SSOT の間に、
提出前に潰すべき不整合が見つかった。あわせて、詳細資料（提案書）に
実装より狭い記述・撤回済み枠組みに読める記述・出典を超えた断定が残っている。

発見の経緯は本セッションのレビュー。一次資料での検証済み事項のみを扱う。

## ゴール

### A. 整合性修正（本タスクの必須部）

1. `docs/mitou_submission/README.md` の再生成コマンドが `--compact` を欠く。
   実測: 付けないと 15 ページ / 付けて 10 ページ（LibreOffice 実測 2026-09-03）。
   README のとおりに再生成すると規約ページ数を黙って超える。
2. 技術設計書 §3.2 が「CANDIDATING 状態を検出した時点で推論を一時停止する」と書くが、
   実装は `analysis/loop_step.rs:314` 逐語「2026-08-23: ここでの `set_paused` を外した
   (研究者判断)」で止めない。提出物が撤回済みの挙動を現行仕様として記述している。
3. Dhakal et al. (2018) が `docs/references.md` に未登録（実測 0 件）。
   コード `heads/writing.rs:29` と未踏文書 `[51]` では引用済み。citation-ssot 違反。
4. `CLAUDE.md` / `docs/agent-shared.md` の「ADR-001〜018」が stale。実際は ADR-022 まで。
   現行裁定である ADR-021 / ADR-022 を指示書が指しておらず、
   本セッションでも実際に取り違えが起きた。

### B. 提案書の整理（余力で実施・A とは別コミット）

対象: `docs/mitou_submission/mitou_docs/[提案プロジェクト詳細資料]GSE_proposal.docx.md`

1. 対象者をナレッジワーカーへ拡張する。ただし「問い」だけ広げ、確証主張（論述 / L0）は据え置く
   （`research-positioning.md:52-54` の「問いと主張を分ける」に従う）。
2. 「Markdown エディタを基準環境として」を削除する。repo 全体で当該記述は提案書 1 箇所のみで、
   実装・ADR・被験者向け文書のいずれにも対応物が無い。
3. 日本語 IME の主張を、出典のある形へ弱め、自前実測 2 本を主根拠に据える。
4. モデル昇格を ADR-019 D1 の 4 段（固定 baseline / criterion 直結 / 個人・タスク適応 / 時系列）で書く。
   現行は HMM → MultiROCKET の 2 段で、ADR-019 D5 が明示的に降ろした
   「モデルの複雑さの梯子」に読める。図 2 も同じ問題を持つ。
5. フェイルセーフの記述が 2 節に分かれているのを 1 節へ統合し、
   技術設計書 §8 の撤退設計 A/B/C/D を入れる。
6. PC / スマホの表現を役割で書き分ける（下記 D1）。
7. スマホ側 OS 制約（ADR-022）と、それへ向き合う計画を追記する。
   あわせて §6 に APNs 経由の留保を書く。
8. 学術的貢献を拡充する（受容性の実測など、検証レポートにあって提案書に無いもの）。

- **[V5] Hylog の精読カード作成 / サーヴェイ 1 ラウンド**。別タスク。
- **実装コードの変更**。本タスクは文書のみ。
- 図 1 / 図 3 の作り直し（図 2 のみ B-4 に伴い対象）。
- 提出 PDF の最終ページ数確定。レンダラ依存（LibreOffice 10p / Drive 7p）であり、
  提出経路が確定してから別途実測する。
