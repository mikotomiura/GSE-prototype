# 設計: 本計算のコード

## 方針

- 行の形は Kaggle の列名（`event_id`・`down_time`・`up_time`・`action_time`・`down_event`・`up_event`・`activity`・`text_change`・`cursor_position`・`word_count`）に正規化する。合成の記録（`synthetic_logs.py`）と同じなので、加工の関数をそのまま使う。KLiCKe の列名の対応は取得の後の検査 2 で書く（`load_klicke.py`）。
- 費用は「小さいほど良い」に揃える（A3 は負の対数尤度）。正解の取り分は `align_ext.credit`（同点 1/m・全 ∞ は 1/N）。
- 計算量: 全文の揃えは、1 記録について同じ課題の候補の全員（約 1,200 本）との費用を **一度だけ** 計算し、抽選はその添字を引くだけにする。陰性対照（記録を B に入れ替える）は B の費用の列をそのまま使い、正解の添字だけを元の書き手にする（追加の計算なし）。
- 揃えの DP は群の p がどれも 1 以上なので、行 i は行 i−1〜i−3 だけに依る。候補を束ね、行ごとに (候補 × 本文の位置) の配列で numpy で計算する（`align_vec.py`）。同点の規則（`ORDER` の先・厳密に小さいときだけ置き換え・終点は本文の位置の小さい方）は、`argmin` が先の要素を返すことで保つ。型の `align.py` と `align_ext.align` との一致を自己検査で確かめる。
- A3 には群の対応（バックトラック）が要るので、候補の塊ごとに後ろ向きの指し示しを持つ。
- 並列: 記録ごとに独立なので、記録の単位でプロセスに分ける（16 コア）。乱数はすべて事前登録の種の式から引くので、並列の順に依らない。

## 新規作成するファイル（`experiments/20261012-public-keystroke-matching/scripts/`）

- `align_vec.py` — 候補を束ねた揃えの費用（全文・窓の終点・R7 の群）とバックトラック
- `seeds.py` — 種の式（`SEED` と `use`・`prompt`・`writer`・`N`・`k`・`draw`）
- `corpus.py` — 書き手の正規化（能動的に書いた時間の切り出し・除外・本文の区間）と、検査用の合成のコーパス
- `forms.py` — 公開の形（`synthetic_logs.py` の関数を書き手の行に当てる）
- `attackers.py` — A0・A1・A1'・A2・A2-b・A3 の費用の列
- `matching.py` — 課題での分割・500 人の抽選・おとり・窓・正解の窓・陰性対照・正答率のセル
- `bootstrap.py` — 書き手の単位の層別ブートストラップと最も強い攻撃者
- `utility.py` — 有用性の 10 指標
- `run_main.py` — 本計算の入口（集計だけを `results/` に書く）
- `selftest_main.py` — 自己検査と変異
- `run.sh`・`requirements.txt`・`env.md`

## テスト戦略

- 揃え: 無作為の 1,000 例で `align_ext.align`（全文・窓・R7 の群）と費用と群が一致。
- 攻撃者: 合成の記録の「編集なし」で、R0 の A1 と R3 の A1' が正解を 1 位にする（陽性対照）。記録を別の書き手に入れ替えると正答率が 1/N の近く（陰性対照）。
- 変異: 正解の添字を常に 0 にする・おとりに正解を混ぜる・ブートストラップで層別しない・A3 の尤度の符号を逆にする、などが狙った検査で落ちる。
