# 設計判断

## 判断 1（2026-10-11・研究者が結果の前に選んだ）— 区切り・k と N・止まった位置・加工と同意文

Claude が記録の種類の分け方を確かめたうえで、4 つの問いに推奨と理由を添えて出し、研究者は 4 つとも推奨を選んだ（AskUserQuestion）。

| 問い | 決定 | 却下した案 |
|---|---|---|
| 区切りとおとり | 記録は `other` の押下で区切り、英字＋数字 − BackSpace を数える（Enter・Space は数えない）。原文とおとり（前の実測と同じ青空文庫 1,500 作品）は同じ規則（、。ー・と記号のキーを区切り、数字と英字は 1 打）で SudachiPy から作り直す | 前の B0 の派生データを「ー」で切り直して流用（記号を 1 打と数え、記録の形とずれる）／Enter も区切りにする（変換の確定の位置は本人しだいで雑音が大きい） |
| k と N | 前と同じ k = 1, 2, 3, 5, 8, 12, 20・N = 10, 100, 1000 | k を 12 までにする |
| 止まった位置と打ち直し | 最後の `other` の後の区間（途中で止まった区間）は使わない。記録と原文の区間は分割と結合を許す動的計画法で揃え、正解の窓は記録の窓の先頭が揃った原文の位置から k 区間。窓は除外しない。主は L（掃除なし）、副に「`other` の直後の BackSpace の組を区切りにしない」L_clean | 揃えが 1 対 1 の窓だけ使う（有利な方に偏る） |
| 加工と同意文 | 前の試作の L の加工をかける。結果は第 3 層の「起こりうること」1 の一文を「研究者本人の記録で試したところ」と書き直す材料に使う（文面は結果の後に研究者が決める） | 加工なし／同意文に使わない |

理由（記録の確かめ）: G1 のアプリは P009 が v0.1.29、P010 がそれより古い版（`hmm_version` 0.3.0・`app_version` なし）で、どちらも `KeyCategory` に Punctuation と SentencePunctuation が無い（`git show v0.1.29:src-tauri/src/analysis/anonymize.rs` の `from_vk`。OEM のキーは `_ => Other`）。「、」「。」「ー」「・」は同じ `other` になり、前の実測の区切り（読点・句点と改行）は記録から取れない。日本語入力では Enter が変換の確定にも使われ、改行と区別できない。
