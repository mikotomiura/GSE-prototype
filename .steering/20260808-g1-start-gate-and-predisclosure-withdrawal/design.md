# 設計

## 実装アプローチ

### 1. 課題ページをゲート化する（`writing-pad.html`）

**開始前**（既定・ページを開いた状態）:

```
┌────────────────────────────────┐
│ G1 記入パッド        ブロック 3 │  ← ★ ヘッダは出す（どのファイルを開いたか確認できる）
│                                │
│  このページを開いただけでは      │
│  何も始まりません。            │
│  下のボタンを押すと、課題と      │
│  記入欄が出て 5 分を数えます。  │
│                                │
│    [ 課題を表示して始める ]     │
└────────────────────────────────┘
```

**押した瞬間に**、`.task`（課題文パネル）・`textarea`・`footer`（文字数・消去）が
**同時に**現れ、`setTimeout(timeIsUp, BLOCK_MS)` が走り出す。

- ★ タイマー起動を**トップレベルからボタンの中へ移す**のが変更の本体
  （`writing-pad.html:292` の `setTimeout` を `startBlock()` の中へ）。
- ★ `pad.focus()` も `startBlock()` の中へ。開始前はゲートボタンにフォーカスする。
- ★ **押し直しても再スタートしない**（`started` フラグで 1 回きり）。ボタンは押した時点で消える。
- ★ **保存しない性質は維持する**（`localStorage` 等を使わない）。
  → 誤って押しても、閉じて開き直せば最初の状態に戻る。これが唯一の安全弁なので**明記する**。

#### ⚠️ ラベルを「開始する」にしない理由（2 つ・どちらも実測に基づく）

1. **アプリ側にも「開始する」がある。** `protocol.md §4b.2-4` で被験者が押すのは
   アプリの「開始する」であり、同名のボタンが 2 つになると取り違えが起きる。
2. ⚠️ ★ **`build_task_pages.py` の `NAV_PROMISE_WORDS` に「開始する」が既に入っている**
   （`build_task_pages.py:180`）。ラベルだけ変えて検査を素通りさせるのは
   `promise_check` の趣旨に反するので、**検査の側も拡張する**（下記 2.）。

→ ラベルは **「課題を表示して始める」**。押すと実際に課題が表示されて 5 分が始まるので、
ラベルが実装を超えていない。

#### ⚠️ アプリの「開始する」との順序は変えない

`src-tauri/src/lib.rs:2455` が順序保証を明記している:

> 手順は「ページを開く → 開始する」の順に統一したので、**ページの 5:00 が先に来る
> = 打鍵の取りこぼしが構造的にゼロ**になる

★ ゲートは「ページを開く」を「ページのボタンを押す」に**置き換えるだけ**で、
順序（ページが先・アプリが後）は `protocol.md §4b.2-3/4`（第 10 版）のまま維持する。

| 順序 | 結果 |
|---|---|
| ★ **ページ → アプリ**（採用） | アプリの記録窓がページの 5 分を**完全に包む**。取りこぼし 0 |
| ⚠️ アプリ → ページ | アプリが先に終わる → **末尾 δ 秒の打鍵が落ちる**（確定的に発生） |

★ 開始後の画面上部に **「⚠️ アプリの『開始する』を押してから書き始めてください」** を出す。
（今日の版にはこの注意が**無い**ので、ゲート化は head 側のリスクも減らす。）

### 2. `promise_check` を「開始の約束」まで見るように拡張する（`build_task_pages.py`）

現行は **遷移の約束**だけを見ている（`NAV_PROMISE_WORDS` / `NAV_IMPL_TOKENS`）。
ゲートボタンは遷移しないので、そのままでは
「始める」と名乗るのに何もしないボタンを**検出できない**。

→ `START_PROMISE_WORDS = ("始める", "開始")` / `START_IMPL_TOKENS = ("setTimeout", "BLOCK_MS", "hidden")`
相当を足し、`_nav_scope_for()` と同じ **ボタン単位のスコープ**で判定する。
⚠️ ★ **ページ全体を見ない**（既存の cross-review HIGH 指摘を踏襲）。
⚠️ ★ **空回り検査も足す**（ラベルだけ残して実装を消したページが赤になること）。
