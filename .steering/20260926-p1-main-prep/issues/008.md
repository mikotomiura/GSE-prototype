# Issue 008: `feat` 行が 0 本の入力では `T1a` の pause 分位点を `null` にする（未裁定の非対称を onset 側へ揃える）
verify_level: parse

## Goal

ADR-030 補訂 2 項目 6 の「⚠️ **未裁定の非対称**」—— `feat` 行が 1 本も無い入力で、onset は**立てない**（補訂 1 項目 2）のに、
`T1a`（`dispersion.pause_p50_ms` / `pause_p90_ms` / `pause_max_ms`）は窓を**切らずに値を返す** —— を、**onset 側（観測できないものは値で埋めない）へ揃える**。
あわせて、この挙動に依存していた過去の acceptance 2 本を、**検査力を落とさずに**張り直す。

## Background

- ADR-030 補訂 2 項目 6（`docs/adr/ADR-030-stall-onset-and-decision-episode.md`・★ 補訂 1 項目 1・2・5 と補訂 2 項目 6 を**全文**読むこと）:
  「⚠️ 未裁定の非対称: `feat` 行が 1 本も無い入力では、穴を検出する手段が無いので `T1a` の窓を**切らない**（値を返す）。これは項目 2（補訂 1）の onset の扱い（立てない側に倒す）と**向きが違う**。」
- 研究者裁定（`decisions.md` 判断 9 と再確認）: **`null` に揃える**。旧検査は張り直す。ADR への記録は issue 010。
- 実装位置: `src-tauri/src/analysis/feat_offline/dispersion.rs` の `pause_ms_by_window`（doc 逐語「★ `observed` が空（`feat` 行が 1 本も無い）なら穴の情報が無いので、**窓を切らない**」）。
  呼び出しは `src-tauri/src/analysis/feat_offline/mod.rs`（`stall_onset_inputs.feat_ts` から観測区間を作って渡す）。
- ⚠️ `iki_cv` / `surprise` には窓を掛けない（補訂 2 項目 6）。→ **本 issue も `iki_cv` / `surprise` を変えない**。
- 実測（2026-09-26）: `src-tauri/tests/fixtures/` 19 本中 11 本が `feat` 行 0 本。過去の acceptance のうち次の 2 本が 0 本の入力で `T1a` の値を検査している:
  - `.steering/20260914-mhd-feature-offline-tiers/issues/003-acceptance.sh`（`deep_silence.ndjson` / `instrument_rich.ndjson` で `pause_max_ms` が全行 null でないこと・`--set t1a_window_ms=1000` の退化の陽性対照）
  - `.steering/20260921-p1-prereg-cli-poles/issues/003-acceptance.sh` AC6（`feat` 行を取り除いた「穴なし版」で `pause_max_ms == 25000`）
- ★ 張り直しの方針（研究者裁定）: fixture 本体とゴールデンは**変えない**。検査の中で fixture を一時コピーし、**1Hz の `feat` 行を足した版**で値の検査を残す。
  0 本の入力では**全行 `null`** になることを新しい検査にする。⚠️ 「穴なし版」は「`feat` 行を全部消した版」ではなく「**穴の無い `feat` 行を敷き詰めた版**」に作り直す（検査の意図 = 穴で切らなければ巨大 pause が出る、を保つ）。
- ⚠️ O1 の実ログが `feat` 行を必ず持つかを、**コードから**確かめる（logger の `feat` 行の書き出し経路・O1 モードで止まる条件が無いか）。持たない経路が見つかったら**止めて報告**する（実データは開かない）。

### AC6: O1 の実ログが `feat` 行を持つか（★ コードから確認・実データは開いていない）
- **`feat` 行は 1Hz ゲートが毎 tick 出す**（打鍵の有無に依らない・沈黙経路でも出る）: `src-tauri/src/analysis/loop_step.rs` の 1Hz ゲート（`if now_ms < state.next_engine_update_ms { return out; }` 以降）→ `out.feat = Some(FeatSnapshot {…})`。
  → `src-tauri/src/lib.rs` の分析スレッド `if let Some(f) = out.feat { … log_tx_analysis.try_send(LogEntry::Feat {…}) }`（`lib.rs:3528` 付近）。
- **O1 は分析の門を外して常時回す**: `lib.rs` の分析スレッド冒頭 `o1::analysis_gate_open(o1_always_on, …)`（ADR-016 判断 4b-0）。
- **`feat` が出ない条件は `engine.get_paused()` だけ**（`loop_step.rs` の 2 か所で `return out`）だが、**本番は IME で `set_paused` を呼ばない**（2026-08-23・D-10。`lib.rs` の該当コメント）ので発火しない。
- **録画の一時停止中は `key` も `feat` も同じ書き出し入口で落ちる**（`logger.rs` の `recording_paused` ゲート → `recording::is_writable_while_paused`）。→ 「打鍵は書かれるが `feat` は書かれない」区間は作らない。停止区間は観測区間の穴になる（＝従来どおりの扱い）。
- **残るのは 3 つ（いずれも「全行 null」を誤って出すのではなく、値を出さない側に倒れる）**: (a) `try_send` が満杯で `feat` の 1 行が落ちる（穴になる）／(b) ファイルの回転（`Rotate` 制御エントリ）の境目に 1 秒未満の断片ができうる（★ 回転の条件は**未確認**・可能性として挙げるだけ）／(c) 古いログ・合成 fixture（19 本中 11 本）。
- **結論**: **O1 の実ログが `feat` 行を系統的に持たない経路は見つからなかった**（Stop Condition に該当しない）。⚠️ ただし (b)(c) の入力では `T1a` は全行 null になる —— 研究者裁定（判断 9）どおりの帰結である。
