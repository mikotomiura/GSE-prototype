# Issue 003: episode 表を DuckDB に載せ、`ime_overlap` と転帰側の量を `t0` のビューから外す
verify_level: recheck

## Goal

3 極の出力（issue 002 のレイアウト）から **極ごとの episode 表**を作り、`sessions.csv`（参加者・OS・phase）と結合した
**使い捨ての DuckDB**（repo の外・共有しない）を作る CLI `scripts/build_p1_episode_db.py` を作る。
★ v1.1 の規則 (e)「`ime_overlap` を `t0` の時点の特徴量に使わない」を、**スキーマの分離**で守る。

## Background

- 事前宣言 v1.1 冒頭 (1): `ime_overlap` は **retrospective**（`t` は変換の終端なので `t0` より後の行に依りうる）→ **`t0` の時点で使える特徴量としては使わない**。
- ADR-030 補訂 1 項目 7: `restart`（`T1d`）は**転帰側の retrospective な量**で、同じエピソードの予測にも、オンラインの推論・介入の入力にも使わない。
- `decisions.md` 判断 10: 結合するのは episode 表と `sessions.csv` だけ（metrics・probe・survey とは結合しない）。
- 既存の流儀: `scripts/build_analysis_db.py`（使い捨ての DB・duckdb が無ければ exit 5・PII を入れない・FULL OUTER で「無い」と「0」を区別する）。★ 実装前に全体を読むこと。
- `sessions.csv` の列は `participant_id,session_id,os,phase`（`scripts/gen_sessions_manifest.py` の契約）。★ 本 issue では **`session_id` = レイアウトの `<session>` ディレクトリ名**として結合する。
- 読み込みは issue 002 の `scripts/p1_features_io.py`（`discover` / `load_envelope`）を使う。⚠️ `project_pg1` は PG-1 専用なので**使わない・変えない**。
