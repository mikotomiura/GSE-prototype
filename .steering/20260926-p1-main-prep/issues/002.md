### 残課題・既知の制約
- Stop Conditions に該当なし。ただし issue の記述に**無い**ところを次のとおり補った（食い違いではなく、書かれていない部分の補い）:
  - `hmm_version` は `provenance`（収集時）と `config`（解析時）の 2 か所にあるので**両方**を極間で照合する。
  - `sessions` は「全セッション数（適用可 + 非適用）」と定義した（issue は `sessions` の意味を書いていない）。
  - 事前宣言の版・sha が**セッション間**で混在したら exit 4 にした（issue は極間の一致だけを exit 3 と定めている。混在は「凍結既定でない出力が混ざっている」の一種と読んだ）。形の不備（exit 3）は非凍結（exit 4）より先に拒否する。
  - `--out` が既にあれば exit 2（上書きしない）。PG-1 は 1 回だけ通すゲートで、出し直しで forking paths を作らないため。まだ無いディレクトリの下に書くときは、実在する最も近い祖先で git 判定し、拒否するときはディレクトリを作らない。git 判定の子プロセスからは `GIT_DIR` / `GIT_WORK_TREE` / `GIT_CEILING_DIRECTORIES` を外し `LC_ALL=C` にした（`GIT_CEILING_DIRECTORIES` があると作業ツリーの中でも「管理外」に見えるため）。
  - root 直下・参加者直下・セッション直下の**契約に無いエントリ**（余計なファイル・`.DS_Store` 等）も `LayoutError` にした（fail-closed を広めに取った。`--root` に置く前に消せば通る）。
- ⚠️ **3 極が同じ入力から出たか**は `source_sha256_prefix` で照合できるが、issue の列挙（5 キー）に無いので照合していない。3 極は `run-features-all-poles.sh` が 1 回の実行で（入力を staging へ固定コピーして）出すので通常は崩れないが、手で組んだレイアウトでは崩れうる。必要なら 003 以降で足す（1 行）。
- `test_out_inside_git_rejected` は `git init` を一時ディレクトリで回す（git が要る）。Windows では `.git` の読み取り専用ファイルが消せないことがあるので `ignore_cleanup_errors=True` にした。
