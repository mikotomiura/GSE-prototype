# Issue 007: `--feature-config` の `id` / `version` を検証してから封筒へ写す（起票 P1-G）
verify_level: recheck

## Goal

`gse-replay --features --feature-config <path>` が、外部 JSON の `id` / `version` を**形式の検証なしに**封筒 `config.prereg_id` / `config.prereg_version` へ写している（起票 P1-G・security LOW）のを閉じる。
形式に合わない値は **exit 非 0 で拒否し、出力を 1 バイトも書かない**。

## Background

- 起票元: `.steering/20260921-p1-prereg-cli-poles/decisions.md` の起票表 P1-G（逐語「security LOW: `--feature-config` の `id` / `version` を検証せず封筒へ写す（★ `config_source` / sha / `overrides` で区別は可能）」）。
- 実装位置: `src-tauri/src/bin/replay.rs` の `resolve_feature_config`（`--feature-config` の枝で `parse_prereg_text(text)?` の結果の `id` / `version` をそのまま `ResolvedFeatureConfig` に入れている）。
- `decisions.md` 判断 16（本タスク）: 検証は**形式だけ**。凍結 JSON の `id` / `version` との**一致は求めない**（別の config を使うこと自体は正当で、区別は `config_source` / sha / `overrides` が担う）。
  - `id`: `^[a-z0-9][a-z0-9-]{0,63}$`
  - `version`: `^[0-9]+\.[0-9]+\.[0-9]+$`（各部の長さは 1〜9 桁に抑えてよい）
  - ⚠️ `regex` crate を**足さない**（新規依存は Stop）。文字の走査で書く。
- 既存の fail-closed の約束（関数 doc）: 「未知のキー・型の不一致・範囲外は**すべて `Err`**（呼び出し側は exit 1）」「出力を 1 バイトも書く前に呼ぶこと」。
