# Issue 009: 凍結既定の config のまま restart の非退化（`restop_ms` 非 null）を測る統合テスト（起票 P1-A）
verify_level: parse

## Goal

起票 P1-A「凍結既定 config（`warmup_count=100`）では restart の非退化検査（旧 `006-acceptance.sh` AC6）が走らない」を閉じる。
**`--set` を 1 つも使わず**、凍結既定のまま `gse-replay --features` を回して **`restart.restop_ms` が非 null になる onset が少なくとも 1 本**出ることを、`cargo test` で固定する。

## Background

- 起票元: `.steering/20260921-p1-prereg-cli-poles/decisions.md` 判断 19 と起票表 P1-A。
  - 経緯: 旧 `.steering/20260914-mhd-feature-offline-tiers/issues/006-acceptance.sh` の AC6（`restop_ms` が 1 つでも非 null）は、
    凍結既定（`warmup_count=100`）では**原理的に成立しない**（残る onset が観測区間の右端で右側打ち切りになる）ため、呼び出しに `--set warmup_count=1` を足して旧前提を再現した。
  - ⚠️ 副作用: restart の非退化検査は**凍結既定 config では走っていない**。→ 既定 config で restop が測れる入力が要る。
- 用語（ADR-030 補訂 1 項目 7・★ `docs/adr/ADR-030-stall-onset-and-decision-episode.md` の該当節と D3 を読むこと）:
  原点 `o = t0 + B`、再開 `r_k` = 条件 A が true→false、再停止 `s'_k` = `r_k` 以後に条件 A が false→true。区間の右端 `b` に達したら打ち切り（`restop_ms = null`）。
- 凍結既定: `w_ms=30000` / `q=0.99` / `b_ms=30000` / `hole_gap_ms=2000` / `warmup_count=100` / `t1a_window_ms=30000` / `net_diff_min=1`（`src-tauri/prereg/p1-episode.json`）。
  → 入力は「θ の標本が 100 以上たまる打鍵 → 30 秒超の沈黙（onset）→ `t0 + 30 s` 以後に打鍵再開 → 再び 30 秒超の沈黙（再停止）→ 観測区間はさらに先まで続く（`feat` 行を 1Hz で最後まで敷く）」の形が要る。
- ★ 既存の生成の先例: `.steering/20260914-mhd-feature-offline-tiers/issues/008-acceptance.sh` の AC18（`awk` で打鍵列を生成）。行の形は `src-tauri/tests/fixtures/stall_onset_observed.ndjson` を読んで合わせる。
- ★ 入力は**テストの中で生成して一時ファイルに書く**（大きな fixture をコミットしない）。
