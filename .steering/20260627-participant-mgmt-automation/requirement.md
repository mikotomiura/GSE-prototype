# 被験者管理の自動化（F1→P-ID自動発番＋自動メール ＋ 管理シート拡充）

## 背景

現状の P-ID 付与フロー＝「被験者 F1 提出 → 研究者が手動で `addParticipant()` →
本人へ手動メール」。手動運用は (1) 採番の取り違え、(2) 連絡漏れ・誤送信、
(3) フォーム回答とロスターの突合が手作業で属人化、というリスクを抱える。
パイロット (n=3-5) の運用負荷を下げ、P-ID を単一キーにした管理を半自動化したい。

## ゴール

被験者番号(P-ID)付与と被験者管理を **手動運用から半自動運用へ** 引き上げる。
1. F1 同意フォーム提出をトリガに、適格者へ P-ID を自動発番し、本人へ通知メール（下書き）を作成。
2. 管理スプレッドシートでフォーム回答(F2/F4/F5)を P-ID キーで取り込み、進捗を可視化。

## スコープ

### 含むもの
- `Form_Phase1/GSE_Phase1_Form_Builder.gs` への GAS 関数追加:
  - `installF1Trigger()` / `onF1Submit(e)`（適格性判定→P-ID発番→ロスター転記→通知メール下書き）
  - `refreshRosterStatus()`（F2/F4/F5 回答を P-ID で集計しロスター更新）
  - `buildDashboardTab_()`（進捗ダッシュボード：完了率・未提出者・無回答フラグ）
  - ロスターのデータ検証（condition/OS/撤回 ドロップダウン、P-ID 形式・重複チェック）
- 手順書・検証チェックリストの提示（GAS 実行・トリガ設定・下書き確認はユーザー）

### 含まないもの
- アプリ本体 (Rust/TS)・HMM・schema の変更（不変）
- 完全自動メール送信（既定は下書き作成。ユーザー決定 2026-06-27）
- condition の動的割付（Phase1 単群のため全員 baseline 固定。ユーザー決定 2026-06-27）

## 受け入れ条件

- [ ] `node --check` で .gs が構文エラーなく通る
- [ ] `onF1Submit` が適格者のみ発番し、不適格・非同意は発番せずログのみ
- [ ] P-ID は `P###` 連番（既存 `nextParticipantId_` 再利用）で英数字16字以下を維持
- [ ] 同一メールの二重発番を冪等にスキップ
- [ ] 通知は **下書き作成**（GmailApp.createDraft）。送信先は F1 のメール設問の値のみ
- [ ] `refreshRosterStatus` が F2事前/F4回答(計)/セッション数/F5事後 を P-ID で自動更新
- [ ] ダッシュボードに完了率・未提出者・無回答フラグを表示
- [ ] ロスターに condition/OS/撤回 のドロップダウン、対応表の研究者限定注意書き
- [ ] PII を .gs にハードコードしない（フォームID/Dropbox URL/公開鍵置き場の記入は可）
