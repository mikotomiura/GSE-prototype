## 判断 1: 事前宣言文書は「運用値」と「探索手続き」を**両建て**で凍結する

- **判断日時**: 2026-09-21（★ 研究者裁定）
- **背景**: ⚠️★★★ **一次が食い違っていた。**

    「**P1 開始前に事前宣言**する」。

    検索空間・seed・budget・選択 metric を先に記録する。選ばれた一式を freeze し、
    G-next / O-holdout では探索しない**」。

  新設になる。→ ★ A は「P1 は再現可能に回る（運用値がある）」と
  「WP2 の freeze は事前に登録した探索空間の内側でしか動けない」を同時に満たす。

  ⚠️ 運用値と探索の**選択結果**が食い違ったときの読み方を文書に書く義務が生じる。

## 判断 3: 両極は **別モード（`--pole`・1 実行 1 極）** で出す

- **判断日時**: 2026-09-21（★ 研究者裁定）
- **背景**: 起票 13（`blockers.md:510`）逐語「⚠️ `--features` は **1 tick 1 行**・`stall_onset` は **1 列**である。
  ★ 両極を出すには**列を 2 本にする**か**別モードにする**かを決める必要がある
  （★ どちらも出力形状の変更 ＝ 全 acceptance の前提に触る）」。
  ★ ADR-030 D3 の囲み逐語「★★★ **合成規則**: ⚠️ **他の極と Cartesian に組まない。独立に報告する。**」
  → ★ 出す組は **baseline(A, M−) / pointer_b(B, M−) / modifier_m_plus(A, M+)** の 3 つ。
  ⚠️ 補訂 1 項目 7 逐語「★ 修飾キーの極（項目 3）を出す段では、`r` / `s'` も両極で出す」
  なので **`restart`（`T1d`）も極ごとに変わる**。
- **選択肢**:
  - A: **別モード** —— `--features --pole <name>`。1 実行 1 極。極は封筒 `config` だけが持つ
  - B: **行に列を足す** —— `rows[].poles.pointer_b` / `.modifier_m_plus`
  - C: **封筒に疎なイベント列** —— `rows` は baseline のまま、封筒に `poles: [{name, applicable, onsets, restarts}]`
- **採用**: **A（別モード）**
- **理由**:
  1. ★ **出力形状が不変**なので、起票 13 が警告した「全 acceptance の前提に触る」が起きない。
  2. ★ 極が **enum** なので、**Cartesian を構造的に作れない**（ADR-029 D3 帰結 3「極を混ぜない」を
     設計で強制する）。
  3. ★ `not_applicable` を**封筒 1 か所**で表現できる（⚠️ 行ごとに `null` を撒かない）。
- **トレードオフ**: ⚠️ **3 回実行が要る**（★ `T0` / `T1a` / `T1b` / `Q` のように極に依らない列も 3 回計算する）。
  ⚠️ **実行漏れ**が起きうる → ★ **スクリプト側で 3 極を回すことを担保する**（→ `design.md`）。
- **影響範囲**: `bin/replay.rs`（引数・封筒 `config`）／ `feat_offline/`（極の分岐）／ 検証 runbook
- **見直しタイミング**: 極が 3 つを超えたとき（⚠️ そのときも Cartesian にはしない）。

## 判断 5: `warmup_count = 100`（= ⌈1/(1−q)⌉）を課し、**θ の標本数 `n` を出力に載せる**

- **判断日時**: 2026-09-21（★ 研究者裁定）
- **背景**: 起票 14 の実測 ——「nearest-rank で `n <= 99` なら `ceil(0.99n) = n` なので **θ は常に最大値**」。
  ★ 実装（`stall_onset.rs:172` `quantile_nearest_rank`）は `rank = ceil(q·n)` を `[1, n]` にクランプする
  1-indexed の nearest-rank である。
  → ★ `ceil(0.99n) < n ⟺ 0.99n ≤ n−1 ⟺ n ≥ 100`。**`100 = ⌈1/(1−q)⌉` は
  「分位点が max に退化しない最小の標本数」**であり、任意の数値ではない。
  ⚠️ ADR-030 D4 #2 の fallback `cold_start`（集団 prior）は**未実装**で、P1 前には作るデータも無い。
- **選択肢**:
  - A: **100 を課し、下回る間は onset を立てない ＋ `n` を出力**
  - B: `None` のまま（下限を課さない）＋ `n` を出力
  - C: 100 を課し、下回る間は `cold_start`（集団 prior）へ退く
- **採用**: **A**
- **理由**: ★ 値が**構造から導かれる**（`q` を決めれば一意）。★ 「既定値で埋めない」（issue 005 Stop
  Condition）のまま。⚠️ C は集団 prior の中身を**推測で埋める**ことになる（P1 前に集団データが無い）。
  ★ `n` を出すのは、⚠️ B を採らなくても**退化の判定を解析側でできるようにする**ためである
  （★ `warmup_count` を将来変えたときに、過去の出力を読み直せる）。
- **トレードオフ**: ⚠️ **短いセッションで onset が 0 件になり episode yield が落ちる**。
  → ★ **それを P1 で実測する**（roadmap WP1 完了条件「一人あたり episode 数」に直接効く）。
- **影響範囲**: 凍結 JSON ／ `StallOnsetConfig` ／ `StallOnset`（`n` フィールド追加）／ 封筒 `config`
- **見直しタイミング**: `q` を変えるとき（★ `warmup_count` は `q` の従属変数である）／
  集団 prior が作れるようになったとき（WP2 以降）。

## 判断 6: CLI 注入は **凍結 JSON を既定 ＋ 個別上書き**にする

- **判断日時**: 2026-09-21（★ 研究者裁定）
- **背景**: 起票 16 —— ★ `StallOnsetConfig` は `build_feature_rows` の引数だが、
  ⚠️ `gse-replay` の本番経路は `Default` を渡す。→ ★ 値を宣言しても**注入できない**。
  ⚠️ 判断 1（両建て）を採った以上、「凍結値で回す」と「探索空間を振る」の**両方**が要る。
  ⚠️ かつ**文書の値とコードの値が drift すると事前登録が無意味になる**。
- **選択肢**:
  - A: **凍結 JSON を既定 ＋ `--feature-config <path>` ＋ `--set <key>=<value>`**
  - B: CLI フラグのみ（`--w-ms` / `--q` / …）
  - C: 設定ファイルのみ
- **採用**: **A**
- **理由**: ★ 凍結値の **SSOT が repo の JSON 1 か所**になり、**文書↔コードの drift を検査で固定できる**。
  ★ 封筒に「**既定から外れた値**」を明示的に刻むので、⚠️ **事前登録から外れた出力が自己申告する**。
  ⚠️ B は既定値がコードの `Default` に残り、文書との一致を機械で確かめる手段が無い。
  ⚠️ C は感度分析で 1 値振るたびにファイルを作ることになる。
- **トレードオフ**: ⚠️ `--set` のパーサ（キー名・型・範囲の検証）を書く必要がある。
  → ★ **未知のキー・範囲外の値は fail-closed**（⚠️ 黙って無視しない）。
- **影響範囲**: `bin/replay.rs` ／ 凍結 JSON ／ 封筒 `config`（`overrides` の記録）／ 一致検査スクリプト
- **見直しタイミング**: 凍結値が WP2 で置き換わるとき。

## 判断 7: 極 B の「抑制」は **観測区間と同じ構造で切る**

- **判断日時**: 2026-09-21（★ 研究者裁定）
- **背景**: ⚠️ ADR-030 D3 は抑制を「**条件 A を評価しない区間**」としか書いておらず、
  **連続を切るかどうかを定めていない**。★ 一方 ADR-030 は極 B を「**ポインタ活動区間を抑制する
  ＝ onset 少なめ**」の側と呼んでいる。
  ★ `pointer_bin` は **1 秒ビン・ゼロ抑制**（`analysis/pointer_bin.rs` の `is_empty`）なので、
  **行があれば活動あり**と読める（⚠️ ただし `capabilities` に `pointer_bin` がある場合に限る ——
  `schema/current.json:349` 逐語「無ければ『計器が無かった』である」）。
- **選択肢**:
  - A: **観測区間と同じ構造で切る** —— 活動秒の極大連続を抑制区間とし、条件 A の連続を切り、
    区間の頭の `W` も評価せず、**θ の標本からも除く**
  - B: 評価だけ飛ばす（連続は切らない）
  - C: 活動秒を「産出あり」とみなす
- **採用**: **A**
- **理由**:
  1. ⚠️ B は**活動の直後の評価時刻で onset がそのまま立つ**ので、極 A とほとんど差が出ず、
     「両極で挟む」が名目化する（★ ADR-030 が極 B を「onset 少なめ」と呼んだ前提を満たさない）。
  2. ⚠️ C はポインタを「**産出**」と呼ぶことになり、ADR-030 D3 の純産出（挿入系 − 削除系）の定義と
     ADR-014 D4c 逐語「**新しい量を作らない**」に触る。
  3. ★ A は **ADR-030 D4 の標本規則と一致する** —— 逐語「★ **D8 の抑制・除外区間をまたぐ gap**
     （⚠️ 入れると `θ_person` が過大になり **episode yield が落ちる**）」は入れない、とある。
  4. ★ **新しい機構がゼロ**で、補訂 1 項目 1 の `observed_intervals` をそのまま再利用できる。
- **トレードオフ**: ⚠️ **ポインタをよく使う人で onset が大幅に減る**。→ ★ **それが上下界の幅である**
  （ADR-030 A9 逐語「★ 両極の幅が広すぎて G2 に落ちるなら、**それが所見である。**」）。
- **影響範囲**: `feat_offline/stall_onset.rs`（`observed_intervals` の合成）／ `bin/replay.rs`（collector）／
  封筒 `provenance.observed_intervals`（⚠️ 極 B では**区間が変わる** → `design.md` で扱いを決める）
- **見直しタイミング**: `pointer_bin` のビン幅かゼロ抑制の規則が変わったとき。

## 判断 8: 削除幅の制約は **(b) 入口で広げて消す ＋ (a) 定数比較の検査**の両方を置く

- **判断日時**: 2026-09-21（★ 研究者裁定。★ 補訂 1 項目 5 が (a)/(b) の選択を実装タスクへ回していた）
- **背景**: 起票 15 の実測 —— 穴の判定は `隣接差 > hole_gap_ms` なので、**`feat` 行が 1 本だけ欠ける幅の
  削除は穴にならない**。★ 1 秒おきの feat 行の中で `[30,900, 31,500]` を削除すると消える feat 行は 1 本で、
  **元に無い onset が丸ごと削除区間の内側に出た**。
  ★ 現状では起きない（`RecordingControls.tsx` の削除入力は `datetime-local`＝秒なし）が、
  ⚠️ **`delete_time_range`（`lib.rs`）は任意の ms を受ける**（検査は `from_ms > to_ms` の拒否だけ）。
- **選択肢**:
  - A: **(b) 最小幅未満を最小幅まで広げて消す ＋ (a) 定数比較の検査**
  - B: (a) 定数比較の検査だけ
  - C: (b) 最小幅未満を**拒否**する ＋ (a) 検査
- **採用**: **A**
- **理由**: ⚠️ B は `delete_time_range` が任意の ms を受けたままなので、**UI 以外の呼び出し
  （将来の秒単位 UI・テスト・外部ツール）で穴が開く**。
  ⚠️ C は被験者が「消してくれ」と言ったのに**消えない**ことになる。
  ★ A は補訂 1 項目 5 の逐語「★ **削除は広げる側に倒す。被験者への約束は『その時間帯が消える』ことである**」
  と一致する。
