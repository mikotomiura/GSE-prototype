# Issue 001: 凍結した事前宣言値を `--features` へ注入し、θ の標本数を出力に載せる
verify_level: recheck

## Goal

`gse-replay --features` が **`src-tauri/prereg/p1-episode.json` を既定として読む**ようにし、
`--feature-config <path>` と `--set <key>=<value>` で上書きできるようにする。
**既定から外れた値は封筒に明示的に刻む**。あわせて `θ_person` の**標本数 `n`** を行に載せる。

## Background

★ `docs/preregistration-p1-episode.md`（2026-09-21・本タスクで新設）が P1 の解析パラメータを
事前宣言し、`src-tauri/prereg/p1-episode.json` が**値の SSOT** である。

⚠️★★★ **ところが `gse-replay` はその JSON を読まない。**
`bin/replay.rs` の `--features` 経路は逐語 `let stall_onset_config = …::StallOnsetConfig::default();`
であり、値を宣言しても**注入できない**（`.steering/20260914-mhd-feature-offline-tiers/blockers.md`
**起票 16**）。

★ 研究者判断（同 `blockers.md:549`・逐語）:
> ★ **事前宣言文書を作るときに CLI 注入を作る（★ 値より先に作らない）。**

→ ★ **文書と JSON は既に在る**（commit `1cd25ce`）。本 issue はその**注入口**を作る。

### ⚠️ `theta_sample_n` を同時に足す理由

★ 凍結値の `warmup_count = 100` は **`q` の従属変数** `⌈1/(1−q)⌉` であり、
「分位点が `max` に退化しない最小の標本数」である（`decisions.md` 判断 5）。
→ ⚠️ **将来 `warmup_count` を変えたとき、過去の出力を読み直せない**（標本数が出力に無いため）。
★ そこで `θ_person` を算出した時点の**標本数 `n`** を onset 行に載せる。

⚠️ `θ_person` は**設定ではなく結果**である（ADR-030 D4）。`n` も同じ扱いにする ——
**行が持ち、封筒 `config` には入れない**。

### ⚠️★★★ `warmup_count = 100` を効かせると **既存 acceptance が 3 本赤くなる**（★ 実測・2026-09-21）

★ `tests/fixtures/stall_onset_observed.ndjson` を実測した（⚠️ 推測ではない）:

| | 実測 |
|---|---|
| 原点 `T` | `1700000000200` |
| press 総数 | **353** |
| **第 1 onset**（`s` = `T`+37,560）**時点**の press 数 | ⚠️★★★ **12**（＝ 隣接対 **11**） |
| 第 2 onset（`s` = `T`+185,000）時点の press 数 | **353**（＝ 隣接対 **352**） |
| `feat` 行の隣接差 > 2,000ms | **0 件**（＝ 観測区間は 1 本・穴なし） |

→ ★★★ **第 1 onset は消える**（標本 11 < `warmup_count` 100 なので θ を出さない）。
★ これは**バグではなく `warmup_count` の目的そのもの**である ——
⚠️ 第 1 onset の θ = 2,600 は **11 件中の max** であり（nearest-rank で `ceil(0.99×11)=11`）、
★ ADR-030 D4 の囲み逐語「⚠️ 高分位点は **小標本では実質 `max`** になり、★ 昼休み・時計跳躍・
未検出の穴に強く引かれる」が名指しした退化そのものである。

⚠️ **赤くなるのは次の 3 本**（★ いずれも onset の本数か値を pin している）:

- `.steering/20260914-mhd-feature-offline-tiers/issues/005-acceptance.sh` — onset が 1 本以上（★ 残る 1 本で**通る**が、注記が古くなる）
- 同 `006-acceptance.sh` — ⚠️ 逐語「onset が 2 本立つ（t0 = +40160 / +187600）」を前提にしている
- 同 `008-acceptance.sh` — ⚠️ **AC1 が `[s,t0,θ]` の 2 組を厳密に pin している**

→ ★ **本 issue はこの 3 本を同時に直す**（⚠️ 直さないと Loop が「原因不明の赤」で止まる）。
⚠️ **古い期待値を消さず、「なぜ変わったか」を各スクリプトのコメントに残す。**

### ⚠️ `t1a_window_ms` は「器だけ」足す

★ `T1a` の 30 秒窓の**実装は issue 003** である。本 issue は `StallOnsetConfig` に
`t1a_window_ms` を**設定として持たせるだけ**にする。
★ 先例: 同じ構造体の `b_ms` が逐語「★ 本モジュールは tick 単位の出力のみで期 (episode) を
