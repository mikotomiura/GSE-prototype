# Issue 007: IME 変換中に立つ onset を**数える**（⚠️ 抑制はしない）
verify_level: parse

## Goal

onset 行に **`ime_overlap`** を足し、「onset の `[s, t0]` が `ime_shadow` 行の
`[t − dwell_ms, t]` と重なるか」を記録する。⚠️ **抑制はしない。数えるだけである。**

## Background

### ★ ADR-030 補訂 1 項目 4（D3 抑制表 2 行目を上書き・研究者判断 25 #7）

> - ★ **決定**: **いまは抑制しない**。P1 で「IME 変換中に立つ onset」の頻度を数えてから、
>   抑制の要否と形を決める。
> - ★ P1 で数えるための**暫定の数え方**を先に宣言する（⚠️ 抑制の定義ではない。数え方だけである）:
>   **onset の `[s, t0]` が `ime_shadow` 行の `[t − dwell_ms, t]` と重なる件数。**

⚠️★★★ **この計器が無いと、判断 25 #7 を P1 で実行できない** ——
★ 「頻度を見てから決める」は、頻度を数える手段が出力に無ければ**回してから気づく**ことになる。

### ⚠️ 既知の偏りを先に書く（★ 補訂 1 項目 4・そのまま持ち込む）

1. ⚠️ **macOS の `dwell_ms` は「1 変換分とは限らない」**（`schema_dto.rs` の `ime_shadow` の doc）
   → 区間が長めに出ることがある。
2. ⚠️★★★ **20 秒を超えた変換は行が出ない**（両 OS 共通・同じ doc）
   → **偽の onset を作りうる長い変換ほど数えられない**。
3. → ★★★ **P1 の頻度は「下限」として読む。**

### ★ 入力は既に届いている

`build_feature_rows` は既に `ime_events: &[ImeShadowEvent]` を受け取っている
（★ issue 002（前タスク）が `collect_all_ime_shadow_events` を足した）。
→ ⚠️ **`bin/replay.rs` を触る必要が無い**（★ 配線は `feat_offline/mod.rs` の中で閉じる）。

### ⚠️ 極との関係

★ `ime_overlap` は **どの極でも同じように**計算する（⚠️ 極の数を増やさない）。
★ onset 集合が極ごとに違うので、**重なりの件数も極ごとに変わる**。それでよい。
