# Issue 005: 極 M+（修飾キー規則あり）を開通させ、計算できないログは `not_applicable` と報告する
verify_level: parse  # ★ 2026-09-25 recheck → parse（判断 21: watchdog が空応答で fail-closed するため。メインが独立検証＋レビューで締める）

## Goal

`--pole modifier_m_plus` を開通させる。**`modifier` の押下区間中の文字キー press を挿入系に数えない**。
⚠️ 修飾キーの行が 1 本も無い入力では **`pole_applicable = false`** と理由を封筒に刻み、
**値で埋めない**。

## Background

### ★ ADR-030 補訂 1 項目 3（D3 を上書き）

> - **極 M+（規則あり）**: `modifier` の押下区間中の文字キー press を挿入系に数えない
>   （★ Shift を含むので onset が多めに出る側）
> - **極 M−（規則なし）**: 修飾キーの押下を無視し、D3 の基本の写像だけで数える
>   （★ `Ctrl+Z` などが +1 になるので onset が少なめに出る側）
> - ★ **両極は独立に報告する**。⚠️ **ポインタの両極・ADR-016 D3 の極・ADR-029 D4 の極と
>   Cartesian に組まない**。

⚠️ 逐語どおりに実装すると **Shift で打つ大文字・記号まで産出から外れる**
（`anonymize.rs` の `KeyCategory::from_vk`: `0x10 | 0x11 | 0x12 | 0x5B | 0x5C | 0xA0..=0xA5 => Modifier`）。
★ **それが極 M+ の定義である**（⚠️ Shift を除く案は匿名化の写像を変えるので採らない —— 補訂 1 項目 3）。

### ⚠️★★★ `--features` の収集経路は **release を捨てている**（★ 実測・2026-09-21）

`bin/replay.rs::collect_key_events` 逐語:

```rust
if let ReplayEvent::Key { t, vk, category, press } = ev {
    if press { … out.push(KeyPress { timestamp: t, vk: resolved_vk }) … }
}
```

★ `KeyPress`（`analysis/metrics.rs:186`）も `timestamp` と `vk` しか持たない。
→ ⚠️★★★ **押下区間を復元する材料が `--features` 経路に届いていない。**

★ **計器は足りている** —— ADR-030 D3 逐語「★ 復元できる: `key` 行は press と release の**両方**が出る」。
欠けているのは**オフラインの収集側**である。

→ ★ **`collect_modifier_intervals` を足す**（★ `collect_all_feat_timestamps` /
`collect_all_ime_shadow_events` と同じ形 ＝ 専用 DTO ＋ 1 パス ＋ 形の合わない行は捨てて件数だけ `warn`）。
⚠️★★★ **`KeyPress` を変えない** —— `metrics.rs` は HMM 経路と共有で、変えると
`--snapshot` / `--metrics` / `--calibration` の全経路に波及する。

### ⚠️★★★ 押下区間は **カウント方式**で作る（★ press/release の対応づけをしない）

⚠️ `category:"modifier"` は **`Ctrl` と `Shift` と `Win` を区別しない**ので、
`Ctrl+Shift+X` のような**入れ子**では、どの release がどの press に対応するかが**原理的に読めない**。

★ **規則**:
- `modifier` の press で `depth += 1`、release で `depth -= 1`（⚠️ **0 未満へ下げない**）
- **`depth > 0` の極大区間**を押下区間とする
- ⚠️ 観測区間の右端に達しても `depth > 0` のままなら**そこで閉じる**（打ち切り。★ `t0 <= b` と対称）
- ⚠️ 孤立した release（`depth == 0` で来たもの）は**区間を作らない**（件数だけ `warn`）

### ⚠️★★★ **削除系（`−1`）は外さない**

★ D3 の逐語は「**修飾キーが押されている間の *文字キー* は挿入系に数えない**」であり、
**削除系には触れていない**。
→ ⚠️ `Ctrl+Backspace`（単語削除）まで外すと `net` が上振れし、**逆向きの系統誤差**が入る。
★ 外すのは `key_net_delta` の **`+1` の側だけ**である。

### ★ 適用可否の判定（`decisions.md` 判断 13）

⚠️ 極 M+ が計算できないログが 2 種類ある —— **2026-08-23 より前のログ**（修飾キーの行が無い）と
**macOS のログ**（tap の mask が `KeyDown` / `KeyUp` だけで、修飾キーは `FlagsChanged` で来る）。

⚠️★★★ **どちらも入力からは識別できない**（★ 実測）:
1. **OS が読めない** —— `meta` 行に `os` が**無い**（`FeatureProvenance` の doc 逐語・2026-09-20 実測）
2. **`capabilities` でも割れない** —— `capabilities.rs::unconditional()` は `"key"` を挙げるだけで、
   **修飾キーの計器を表す項目が無い**
3. **`key.mod`（ADR-032 D9）は未実装** —— `schema_dto.rs` / `schema/current.json` / `logger.rs` に
   1 件もヒットしない

→ ★ **判定単位は入力ファイル（セッション）、判定式は「解決後の `KeyCategory` が `Modifier` の
`key` 行が 0 本」**。
⚠️ これは**過剰拒否である**（計器はあるのに押さなかっただけのセッションも `not_applicable` になる）。
★ **しかし情報を失わない** —— 修飾キーの行が 0 本なら押下区間が 1 つも無く、
**極 M+ は構造的に極 M− と恒等**である。上下界の幅への寄与はゼロなので、落としても幅は 1 ms も変わらない。
★ 逆に、測っていないものを「測れた」と主張しない側に倒せる
（⚠️ 補訂 1 の禁止 **14**「極 M+ を macOS のログでも計算した」を構造的に防ぐ）。

⚠️ **実測**: `tests/fixtures/` の既存 fixture は**すべて旧形式（`vk`）で `category` を持たず**、
`stall_onset_observed.ndjson` / `instrument_rich.ndjson` は **修飾キーの vk が 0 本**である。
→ ★ それらでは `pole_applicable = false` になる（★ AC の陰性対照に使える）。
