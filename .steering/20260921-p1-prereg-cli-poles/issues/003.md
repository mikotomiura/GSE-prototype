# Issue 003: `T1a` の pause 分位点を 30 秒ローリング窓で集約し、構造的退化を解く
verify_level: recheck

## Goal

`pause_p50_ms` / `pause_p90_ms` / `pause_max_ms` を **`t1a_window_ms`（= 30,000ms）の
因果的ローリング窓**で集約し、**3 値が同値になる構造的退化**を解く。
⚠️ あわせて **窓が観測区間をまたがない**ようにして、`T1a` 側の起票 11 を閉じる。

## Background

### ⚠️★★★ 現状は「未確定」ではなく **壊れている**（★ 証明 ＋ 実測）

`.steering/20260914-mhd-feature-offline-tiers/blockers.md` **起票 7**（`code-reviewer` HIGH-1）:

- `features::PAUSE_THRESHOLD_MS` = **2000ms** > `loop_step::ENGINE_TICK_MS` = **1000ms**
- pause は**再開側の press が属する tick** に帰属する
- ★ 同じ tick に終わる pause が 2 本あると仮定すると、再開時刻 `t1 < t2` は同一 tick なので
  `t2 − t1 < 1000`。`t2` で終わる pause の開始は `t1` 以降の press なので
  `gap(t2) <= t2 − t1 < 1000 < 2000` となり **`gap(t2) >= PAUSE_THRESHOLD_MS` に矛盾する**
- → ★★★ **1 tick に pause は高々 1 本。3 値は常に同値。**
- ★ **実測**（`tests/fixtures/` の **14 本すべて**）: `activity.pauses > 1` の tick は **0 件**、
  `p50 != max` の行も **0 件**

⚠️ その結果、`issues/003.md` AC3 の不変式 `p50 <= p90 <= max` は
**等号でしか成立せず検出力がゼロ**である（★ 緑に見えて何も検査していない）。

### ★ 裁定（`decisions.md` 判断 4 —— 起票 7 の選択肢 (a)）

**`T1a` だけ 30 秒ローリング窓で集約する。**
★ 因果的（後ろ向きにしか見ない）で **1 行 1 tick が保たれる**ので、判断 2 も他 issue も壊れない。
★ `W` / `B` と同じ 30 秒系列に揃う。

⚠️ 却下: (b) `p50` / `p90` を落とす（★ ADR-030 D10 が名指しした項目を削る）／
(c) 出力単位（1Hz tick）の見直し（★ 影響が全 issue に及ぶ）。

### ⚠️★★★ 窓を広げるなら **観測区間をまたがせてはならない**（★ 起票 11 が悪化する）

起票 11（`blockers.md:195`〜）逐語:

> ⚠️ `T1a` も同じ `extract_pause_resumptions` を素通しで使うので、
> **削除後の NDJSON を入力にすると削除区間の前後が 1 本の巨大 pause として接続され、
> その長さが `pause_max_ms` に出る**。

★ 起票 11 は「**issue 005 が『穴の有無で条件 B の連続を切る』を実装するとき、`T1a` にも同じ扱いが
要るかを判断する**（★ 005 の設計が決まってから）」と保留していた。
→ ★ **005 の設計は決まった**（観測区間 ＝ ADR-030 補訂 1 項目 1）。
→ ⚠️★★★ **窓を 1 tick から 30 秒へ広げると、またぐ穴の数が増えるので悪化する。**
→ ★ **本 issue で閉じる**: 窓に入れる pause を**同じ観測区間の中のものだけ**に限る。

⚠️ **原因ラベルを作る方向で直さない**（起票 11 逐語 ／ ADR-030 却下リスト 9）。
★ 使うのは `feat` 行の**存在**だけである。

### ⚠️ 窓が掛かるのは 3 値だけである

★ `docs/preregistration-p1-episode.md` §1 逐語:
「`T1a` の **pause 分位点**（`pause_p50_ms` / `pause_p90_ms` / `pause_max_ms`）の集約窓。
⚠️ **`iki_cv` / `surprise` には掛からない**」。
→ ⚠️ `iki_cv`（tick ローカル）と `surprise`（セッション相対）は**現状のまま**にする。

### ★ 命名リファクタが先に要る

⚠️ `features.rs:129` の `let cutoff = last_ts.saturating_sub(30_000);` の `30_000` は
**名前の無い生リテラル**である（実測）。
→ ★ **`pub const FEATURE_WINDOW_MS: u64 = 30_000;` を先に切り出す**（⚠️ **振る舞いを変えない**）。
★ これは `decisions.md`（前タスク）判断 7 と同じ型のリファクタである。
