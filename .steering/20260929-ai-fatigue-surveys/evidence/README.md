## 流用するとき

★ 実行した版をそのまま動かさない。`common.py` の関数で直した新しいスクリプトを作る。

| 関数（`common.py`） | 何を防ぐか | 実行した版で起きたこと・起きうること |
|---|---|---|
| `merge_abstract` | 後の情報源の空の抄録が、取れている抄録を消す | ★ **S-05 で実際に起きた**（6 件が抄録なしで抽出に渡った・判断 16）。S-04 は、複数の情報源で当たって抄録が空になった記録が 0 件だった |
| `ensure_outside_repo`（`repo_root`・`is_inside`） | 抄録・本文の置き場が repo の中になる | `S-12/abstract_filter.py` だけに柵があったが、比べる先が repo の根ではなく `.steering/` で、大文字小文字も見ていなかった。ほかのスクリプトには柵が無かった。2026-09-29 の実行では、置き場はすべて scratchpad だった |
| `open_exclusive` | 既存の書誌・抄録のファイルを上書きする | 書誌の JSON は上書きしない作りだったが、抄録のファイルは `"w"` で書いていた。2026-09-29 の実行では、`S-12/abstract_filter_body.py` を直して再実行したとき（判断 2）に、前の実行の抄録（切り出しを誤った方）を上書きした。ほかは 1 度だけ |
| `write_pair`・`same_run` | 書誌と抄録が別々の実行のものと組み合わさる（`open_exclusive` だけでは防げない） | 実行した版は、書誌と抄録に同じ実行の印を持たせていなかった。★ `write_pair` は両方を排他的に開けてから書き（片方が既にあれば、どちらも書かない）、両方に同じ `run_id` を入れる（判断 17） |
| `allowed_url`・`guarded_opener` | 入力の URL（`file://`・別のホスト・`https://許したホスト.evil/`・`https://許したホスト@evil/`）や、リダイレクトの先をそのまま開く | `S-12/abstract_filter*.py` は、J-STAGE の検索結果の URL だけを開いた。★ `allowed_url` はスキーム・ホスト・ポートを分けて完全一致で比べ、パスは区切りの単位で見る。利用者情報の付いた URL は通さない。リダイレクトの先は `guarded_opener` で確かめる（判断 17） |
| `slice_between` | 抄録の枠を固定の文字数で切り、前後の本文が混ざる・途中で切れる | `S-12/abstract_filter_body.py`（6 件）。切り出した抄録は、抄録の枠の中の見出し（引用文献の数など）を含んだが、疲労の語は含まなかった |

テスト: このディレクトリで `python -m unittest test_common`（17 件）。★ `merge_abstract` を単純な上書きに、`is_inside` を前方一致に、`slice_between` を固定の文字数に戻す変異で、いずれも赤になることを確かめた（2026-09-30）。★ ホストの比較をポートの無視・利用者情報の許可・パスの文字列の前方一致に戻す変異、`write_pair` の片付けを外す変異、リダイレクトの柵を外す変異でも赤になる（判断 17）。
