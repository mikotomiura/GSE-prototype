# 重要な判断

## 判断 1: 抄録の全文を repo に置かない（2026-09-29）

- **背景**: 引き継ぎは「論文の本文・PDF・尺度の全項目文はコミットしない」と定める。抄録は本文ではないが、著作物の全文であることに変わりはない。前回の `archive/evidence/*.json` は題名だけを保存していた。
- **採用**: 検索結果として repo に置くのは書誌（題名・著者・年・収録先・DOI/URL・当たった検索式）だけ。抄録は scratchpad に置き、事実のファイルには要点を自分の言葉で書く（逐語は 1 引用 40 語以内）。
- **検査**: `check_survey_files.py` が evidence の JSON・TSV に抄録・本文の鍵が無いことを確かめる（design §0.3）。

## 判断 2: S-12 の抄録ふるいで、`<meta name="abstract">` の無い 6 件は本文側の抄録の枠から取る（2026-09-29）

- **背景**: `abstract_filter.py` は 145 件のうち 139 件で `<meta name="abstract">` から抄録を取れたが、6 件はこの meta が無かった（J-STAGE の論文ページに抄録そのものはある）。
- **採用**: 補いのスクリプト `abstract_filter_body.py` で、論文ページの本文側の抄録の枠（`article-overiew-abstract-wrap` から `id="author-information-wrap"` の手前まで）を取り、同じ正規表現を当てた。5 件が通過。
- ⚠️ 初回は切り取りの終点を `author-information-wrap` の最初の一致にしたため、目次のリンク（`href="#author-information-wrap"`）で切れて抄録が空になり、6 件とも不通過になった。空の抄録で「不通過」と出る空振りを、保存した抄録の長さを見て見つけた。終点を `id="…"` に直し、初回の出力を消して再実行した（出力は同じファイル名）。
- **教訓**: ふるいの不通過は「抄録を読めた上での不通過」と「読めなかった」を分けて数える（`fetch` 欄）。

- **採用**: 見出しの時刻を「どの実行（executed の時刻）の前に固定したか」の形に直した。手順の中身は変えていない（固定した節の書き換えにはあたらない。直したのは見出しの時刻の誤りだけ）。

## 判断 9: S-04 のふるいの順番を変えた（design §4.4 からの逸脱）（2026-09-29）

- **背景**: S-04 の検索（21:58）の和は重複を除いて 2,319 件。OpenAlex は `search` の AND・OR・引用符を期待どおりに解釈せず（総件数 124,279・上位は AI の一般的な総説）、Semantic Scholar も「cognitive load」「intervention」などの広い語で 1,119 件を返した。design §4.4 の「1 段目＝メインが題名で外す」は、この量では丁寧にできない。
- **採用**（通った記録を見る前に固定）:
  1. **0 段目（機械）**: 題名＋抄録に AI の語・疲労や負荷の語・比較のデザインの語の 3 つが当たる記録だけ（`evidence/S-04/stage0_filter.py` の正規表現）→ 993 件。
  2. Europe PMC の 3 本（医療の記録支援・下書き返信・一般）で当たった記録は全部残す（157 件）。Semantic Scholar・OpenAlex だけで当たった記録は、題名＋抄録に `burnout|fatigue|exhaust` がある記録だけ残す（110 件）。→ 267 件。
  3. **抽出（Sonnet 2 本）を先に**、1 段目（メインの題名の判断）と 3 段目（メインの確認）をその後にまとめて行う。
- **理由**: S-04 の問いの中心は疲労・燃え尽き・消耗で、作業負荷・認知負荷だけの研究（医療以外）は §4.2 の条件でも従（負荷は疲労の尺度ではない）。医療の 3 本は問いに直接あたるので全部残した。
- **失うもの**: 医療以外で、作業負荷・認知負荷だけを測った比較研究（例: 教育での AI と認知負荷の実験）。S-04 の事実のファイルに、この範囲を書かないことを明記する。

## 判断 11: 抄録の前処理の誤り（不等号の後ろの文が消える）を見つけ、影響した 34 件を抽出し直した（2026-09-29）

- **見つけ方**: S-04 の歯学の RCT（R195）の抄録を確かめたとき、結果の文が途中で切れていた。抄録から HTML のタグを取る `re.sub(r"<[^>]+>", " ", …)` が、「p < .001」の `<` から次の `>`（タグや「>1.33」）までを消していた。
- **影響**: サブエージェントに渡した抄録で 40 字以上が消えたもの: S-04 31 件（バッチ A 12・B 15・補い 4）・S-05 3 件（P092・P169・P191）。S-12 の英語の抄録では 2 件（AI-Echo・BMJ Open 2023）で、どちらもメインが本文か欠けの無い抄録で確かめ直し、事実のファイルの記述は変わらなかった。S-02 の抄録（`fetch_meta.py` の `clean`）も同じ処理だが、判定に使った 4 件は本文で確かめている。
- **採用**: タグの名前を限った除去（`h1〜h6・p・b・i・sub・sup` など）で作り直した抄録を、S-04 の 31 件はサブエージェントに抽出し直させ（前回の結果を見せない）、S-05 の 3 件はメインが読み直す。表は抽出し直した行で置き換える。
- **教訓**: 抄録の前処理を変えたら、元と後の文字数の差で「消えすぎ」を検査する。

## 判断 12: S-02 の書誌の JSON から著者のメールアドレスを取り除き、push の前に履歴からも消す（2026-09-29）

- **指摘**（security-checker MEDIUM）: `evidence/S-02/s02_meta_2026-09-29.json` の `epmc_affiliation`（Europe PMC の所属の文字列）に、#2・#3 の著者のメールアドレス 2 件が入っていた。論文に載っている公開の情報だが、書誌の記録には要らず、同じ 2 本に「同一標本の疑い」を書いた判定案と並ぶ。
- **一次の確認**: `git grep` で、メールアドレスはこのファイルの 2 行だけ・入ったのはコミット `801a81d5` だけ。
- **採用**: (1) 作業ツリーの JSON から取り除いた（所属の名前は残した）。(2) ★ ブランチはまだ push していないので、**push の前に `681f51a0..HEAD` の履歴からも取り除く**（`git filter-branch --tree-filter` でこのファイルだけを書き換える。書き換えの前に元の先端をローカルの退避ブランチに残す）。force push は要らない（一度も push していない）。(3) `check_survey_files.py` が evidence の値のメールアドレスと、md のメールアドレスを赤にする（判断 13）。(4) `fetch_meta.py` は実行した版の記録なので変えず、`evidence/README.md` に注意を書いた。
- **理由**: 一度 push すると GitHub の履歴に残り、消すには force push が要る（git-workflow ルール 6 で使わない）。push の前なら、ローカルの書き換えだけで済み、退避ブランチで元に戻せる。
