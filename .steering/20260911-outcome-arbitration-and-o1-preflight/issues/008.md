# Issue 008: macOS で IME の確定 / 放棄を判別できるようにする（P1・O1 配布前に手遅れ）
verify_level: recheck

## Goal

macOS で IME の変換セッションが**確定で終わったか ESC で放棄されたか**を NDJSON から
判別できるようにする。Windows に既にある `ime_shadow` 行と同等の情報を macOS でも出す。

## Background

⚠️★★★ **O1 の収集器を配布した後では、この情報は原理的に復元できない。**

- 現行 NDJSON には `ime_shadow` 行が定義済みだが（`t` / `dwell_ms` / `nav` / `abandon`）、
  **送出しているのは Windows だけ**。`src-tauri/src/input/ime_macos.rs`（226 行）に該当ロジックが無い。
- macOS 側にあるのは `ime_state` 行（`t` / `on` / `active`）の **on/active 2 値ポーリングのみ**。
  これだけでは「変換が確定で終わった」のか「ESC で放棄された」のかを**後から区別できない**。
- ★ **`ime_shadow` は schema に既に存在する**ので、**schema 変更は不要**と見込まれる。
  macOS 側が同じ行を送出するようにするだけ。
  ⚠️ ただし実装の結果フィールドを足す必要が出たら ADR-005（additive versioning）に従う。
- ⚠️ `src-tauri/src/capabilities.rs`（収集能力の自己記述・ADR-013）の更新が要る。
  「このビルドが何を記録できたか」を NDJSON の `meta` 行に書く仕組みなので、
  macOS が `ime_shadow` を出せるようになったらここに反映しないと、
  **解析側が「macOS は IME 情報なし」と誤判定し続ける**。
- ⚠️★★★ **フックコールバック内では Atomic 操作 + channel send のみ。ブロッキング禁止**
  （`docs/agent-shared.md` 技術的制約 4）。`.claude/skills/hook-constraints/SKILL.md` を参照する。
- ⚠️ **GCD `dispatch_sync_f` をメインスレッドから呼ばない**（デッドロック・制約 5）。
- ⚠️ 他プロセスの TSF composition は観測不可（制約 7）だが、これは **Windows の話**。
  macOS 側の制約は `.steering/20260821-workspace-behavior-triage/survey-input-channels.md §7` に
  「公開 API が存在しない」と記録されている。⚠️ **この記録を先に読み、何が観測可能かを確認すること。**
  観測不能なら「macOS では判別しない」ことを**明示的に記録して配布する**判断もありうる。
