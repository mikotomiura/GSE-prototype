# Issue 009: 修飾キー同時押下を記録し `Ctrl+Z` を通常打鍵と区別できるようにする（P3・O1 配布前に手遅れ）
verify_level: recheck

## Goal

キーイベントに**修飾キーの同時押下状態**を記録し、`Ctrl+Z`（undo）と通常打鍵を
NDJSON から区別できるようにする。`revision topology`（修正の構造）の観測に必要。

## Background

⚠️★★★ **O1 の収集器を配布した後では、この情報は原理的に復元できない。**

- 現行 NDJSON の `key` 行は `{t, category, press}` のみ。`category` は `KeyCategory` の 14 値
  （`alphabetic` / `numeric` / `punctuation` / `sentence_punctuation` / `tab` / `backspace` /
  `delete` / `space` / `enter` / `navigation` / `modifier` / `function` / `escape` / `other`）。
- ⚠️ **各キーが独立イベントで記録され「同時押下」のフラグが無い**ため、
  `Ctrl` の押下と `Z` の押下が別々に並ぶだけで、**`Ctrl+Z` という組み合わせだったのか
  たまたま連続して押されたのかを後から判別できない**。
- ★ この結果、`revision topology` のうち「BS/Del の件数・タイミング・バースト」は復元できるが、
  **undo による修正が検出できない**。`revision topology` を Mh-D の主要アウトカムに
  据えるなら、配布前にフラグを足す必要がある。
- ⚠️★★★ **content-free 境界を破らないこと。** 記録するのは
  「**このキーイベント時に修飾キーが押されていたか**」という**真偽値の組**であって、
  どの文字がどう編集されたかではない。`docs/agent-shared.md` の技術的制約と
  `.claude/skills/data-privacy/SKILL.md` のルール 1（VK コードのみ・Unicode 文字は絶対禁止）を守る。
- ⚠️ **schema 変更が必要**。ADR-005（additive versioning）に従い **additive に追加**する
  （既存フィールドを変えない・新フィールドを足す）。`emit_schema` の出力が変わるので
  `schema/current.json` を**意図的に再生成**し、diff の意図を `.steering/` に記録する。
- ⚠️★★★ **フックコールバック内では Atomic 操作 + channel send のみ。ブロッキング禁止**
  （技術的制約 4）。修飾キーの状態は Atomic フラグで保持する。
  `.claude/skills/hook-constraints/SKILL.md` を必ず読む。
- ⚠️ **Windows / macOS の両方**に入れる。OS ごとに規則が違うロジックは**両 OS に対のテスト**を置く。

  → 記録するのは修飾キー状態のみ。解釈は解析側（`analysis/`）で行う
- macOS IME の確定 / 放棄判別（issue 008）
