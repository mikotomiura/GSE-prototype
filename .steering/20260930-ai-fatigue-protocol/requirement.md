# AI 疲労 文献 DB: N-05 スコーピングレビューのプロトコル（日本語の草稿）と、S-11・S-09 の決定の反映

## 背景

- 引き継ぎ `.steering/_handoff/next-session-ai-fatigue-after-theory-usage.md` §2 の 3 つの論点を聞いた（2026-09-30・AskUserQuestion・すべて推奨どおり。`decisions.md` 判断 1）:
  1. **サーベイの定義文（S-11）**: 案 A（利用の疲労）を定義文に、案 C（傘の語）を DB の範囲の語に分けて使う。
  2. **DB の『尺度・理論』に理論の文献を足す（S-09）**: 「理論」の区分を足し、「疲労の仕組み」「自動化」「職場のストレス」の 3 群で載せる。★ DB は書き換えず、貼れる形のファイルを作る。
  3. **次の段**: (a) N-05（プロトコル）。
- N-05 の範囲の論点を続けて聞いた（判断 2）。ユーザーは判定者 1 の立場で答え、**判定者 2 以外は確定**とした。**判定者 2 の人選は研究者が決める**（ユーザーの逐語「判断者２などは研究者に聞かないとわからない.そもそも私は判定者1としての立場なので」）。
- issue の定義（SSOT は `../20260929-ai-fatigue-db-readable-and-gaps/scripts/issues_data.py`）:
  - **N-05**: スコーピングレビューのプロトコルを確定し、事前登録する（OSF など）。PCC と中心-A / B の規則、除外理由コード、情報源、検索式、二重スクリーニング、抽出フォーム、品質評価の扱いを 1 本の文書にする。完了条件は「登録番号（DOI）が付き、以後の変更は逸脱として記録される」。
  - **S-11** の完了条件の後半「サーベイの定義文が決まる」、**S-09** の完了条件の後半「DB の『尺度・理論』に理論の文献が加わる」。

## ゴール

1. **プロトコルの日本語の草稿**（`protocol-ja.md`）: 汎用の系統的レビュー登録様式（GSRR・van den Akker ほか 2023・65 項目）の節立てに合わせ、次を 1 本にまとめる。
   - 問い・PCC・定義文（案 A）と範囲の語（案 C）・中心-A / B・用法の区分（U1〜U4）を抽出の項目として持つこと。
   - 情報源（無料だけ・判断 3 の前例）・検索式（本検索 S-01 と、その検索ブロック S-07・S-10、S-06 の扱い）・検索の検証（既知の記録の再現）。
   - スクリーニング（段・除外理由コード・判定者・AI の役割・一致の測り方・不一致の調整）・抽出・品質評価（合計点を付けない）・まとめの計画。
   - ★ **登録前の段の開示**: 2026-09-18 の探索版から今日までに行ったこと（検索・AI の評価・範囲の決定・候補の追加・判定者 1 が判定の前に AI の評価を読んだこと）を、ノートとコミット時刻で全部洗って書く。
2. **定義文の決定の反映**: 決定を `decisions.md` に記録し、プロトコルの「概念」に書く。
3. **理論の文献の貼れるファイル**: S-09 の提案の文献の書誌を Crossref で確かめ、元の DB の『文献DB』『研究情報』『書誌・出典』と同じ列で並べた xlsx（repo の archive と Downloads の写し）を作る。
4. issue の状態（N-05・S-09・S-11）を `issue-status.md` に書く。

## スコープ

### 含むもの
- 検索式の下書きの、無料の学術 API での**件数の試し**と、既知の記録（DB と追加候補の中心の記録）を再現できるかの確かめ（件数と DOI の一致だけ。題名・抄録で判定しない）。
- 方法論の文献（JBI・PRISMA-ScR・PRISMA-S・GSRR・PRESS）の書誌の確かめ（無料の版があるものは本文）。
- `protocol-ja.md` に AI の 1 件ずつの判定案が混ざらないことの検査（判定者 2 も読むため）。

### 含まないもの
- **登録（OSF）そのもの**・英語の登録版・attack-me（プレ査読）: 次の段（研究者の確認 → プレ査読 → 英語 → 登録は研究者）。
- **判定者 2 の人選**（研究者が決める。プロトコルには役割と条件だけを書く）。
- 本検索（S-01）の実行・スクリーニング・判定・判定者用ファイルと評価版の作り直し・判定中のファイル（Downloads の judge1.xlsx）への接触。
- 元の DB（xlsx）の書き換え（貼れるファイルを作るまで）。issue の SSOT（`issues_data.py`）の再生成（評価版が作り直されるため。前タスクと同じ）。
- 有料のデータベース・有料の本文。著者への照会・フォームなど外部に出る操作。学術 API への研究者のメールアドレスの送信。本文・PDF・抄録の全文のコミット。
- GSE の文書（`docs/`）の書き換え。
