# context B（意図の監査役にだけ渡す）

## 主張の外枠
- 新しいと言える芯: 公開された打鍵の記録に施される加工（`q` のマスク・カテゴリ化・時刻の丸め・長さを粗くする・間引き）を、本文の分かる公開データで、
  記録を本文に照合する攻撃によって評価すること。照合の攻撃そのもの・加工の手法そのものは新しくない（事前登録 "What is not concluded" の最後の項）。
- Section 3 の役目: 事前登録で固定した脅威モデルを、現実の公開の慣行と、本文を持つ者の実例で動機づける。結果の前に書き、結果に合わせない。

## 想定読者
第一に PoPETs の査読者（プライバシー・匿名化の研究者）。第二に、打鍵の記録を公開する側（作文研究・教育データの研究者）。

## 持ち帰ってほしいこと（メインが書いた・未実測の数値なし）
1. 打鍵の記録を本文を隠して公開する慣行は実在し（文字のマスク）、マスクは長さと時刻を残す。その構造は研究の有用性に使われており、同じ構造が照合の手がかりになりうる。
2. 照合に要る候補の本文は、同じ種類の公開コーパス・採点者や教員や製品・書き手自身のところに現実にある。
3. 既存の公開の議論は「同じ人の打鍵のラベル付きの標本」を想定しているが、この研究の脅威は「本文」という別の補助情報である。

## 既知の限界（事前登録 "What is not concluded" と "Threat model" より）
- 閉じた世界（正解は常に候補にある）。開いた世界は診断としてだけ見る。
- 安全の証明・危険の上限は主張しない。試した攻撃者に限る。書き手の特定は主張しない。
- Kaggle のデータと KLiCKe が同じ作文を含むかは調べない。
- 攻撃者は書き手の以前の本文・言語モデルの生成文・複数の公開物の結び付けを使わない。

## 関連する判断
- 事前登録の Threat model・Attackers は凍結済みで変えない。査読の指摘は動機の書き方と限界の節に返す。
- 投稿先の順は PoPETs → JPC か TDP → JEDM（PoPETs で落ちたら、公開する側への手引きとして書き直す）。
- 原稿は 12 頁。必須の 3 節は頁数に数えない。
