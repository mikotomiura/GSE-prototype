## Background

- 設計は既に研究者裁定済み（`.steering/20260927-o1-receipt-ledger/t3-person-ledger-design.md`・2026-09-27）:
  **方式 = 状態ログ＋導出**（§2.2 のとおり）／**O1 参考列 = 手で写す**（結合ゼロ・`IMPORTRANGE` 不採用）。
- 何のための台帳か（設計 §0 逐語）: 第 20 版は人単位の数え方（**登録 k・解析 m**）と
  「やめた」「削除の求め」「未実施」の扱いを固定したが、**その内訳は公表しない**
  （n=3 では人数の公表が個人を指す）ので、**研究者手元の台帳にだけ**残す必要がある。
  ⚠️ O1 受領台帳（`Form_O1/GSE_O1_Ledger.gs`）は「**届いたか**」だけを言い、**人の状態は言えない**。
- 一次で確かめた制約（設計 §1 の 9 件）のうち、⚠️ **絶対に落とせないもの**:
  1. **「やめた」は本人の申し出で確定する**。時刻と**文言**を記録し、**理由は聞かない**
     （第 20 版 語の表 / `ADR-034 D4-2c`）。技術的な中断・連絡の途絶・研究者の推測では「やめた」としない。
  2. **「中断」と「やめた」は別**。曖昧な発言は「中断」。取り消しは**申し出から連続した同一セッションの内に限る**。
  3. **「削除の求め」は「やめた」とは別の申し出**（やめても削除を求めないことができる）。
  4. **O1 に先に参加した人を G1 に入れない**（不可逆・`ADR-034 D4-2`）。G1 → O1 は G1 の完了
     （か本人の「やめた」）後・翌日以降・別の同意・**同じ P-ID**。
  5. **O1 と G1 の記録は結合しない**（`ADR-034 D4-6 / D4-7`）。
- 研究者裁定（2026-09-27・本タスクの grill）: 設計 §3 の残り 3 件は次で確定。
  | 設計 §3 | 扱い |
  |---|---|
  | 3. 未実施のまま長期の期限の日数（第 20 版で未決） | ★ **経過日数の表示だけ**・判定はしない |
  | 4. G1 の受領も台帳化するか | ★ **スコープ外**（G1 の受け口は別プロジェクト） |
  | 5. 名簿から外す判断の記録書式 | ★ 機械可読な自己申告は `config.json` の `recruitment_closed.decided_before_seeing_results`（issue 002）／人単位の内訳は**本台帳の状態ログ**の出来事「名簿から外した」＋根拠＋日時 |

## Scope

### In
`docs/person-lifecycle-ledger-template.md` に次を**逐語で作れる形**で書く:

1. **置き場と閲覧**（設計 §2.1）: 別スプレッドシート・**研究者のみ閲覧・共有しない**・
   氏名/メール/連絡先の列を持たない・⚠️ **シートの ID・URL を repo に書かない**。
2. **タブ 1「状態ログ」**（追記のみ・行は消さない・訂正は行を足す）の 7 列と入力規則
   （設計 §2.2 の表のとおり。出来事は**限定リスト**: 案内 / 登録 / 配布 / 開始 / 中断 /
   やめた（申し出）/ 取り消し / 削除の求め / 完了 / 未実施のまま据え置き / 名簿から外した）。
   ★ 「やめた」「削除の求め」の行は**申し出の文言を逐語**で必須にする（⚠️ 理由は書かない）。
3. **タブ 2「現在の状態」**（導出・**数式のみ・スクリプトなし**）: (P-ID, 研究) ごとの
   最新の出来事・日時・開始済みか・完了か・**未実施の経過日数（表示のみ）**。
   ★ 数式は**そのまま貼れる逐語**で書く（`SORT` / `FILTER` / `QUERY` / `ARRAYFORMULA` のいずれでもよいが、
   ⚠️ **1 つに決めて逐語で書く**。「適宜」と書かない）。
4. **タブ 3「数える」**: 公表用の **2 数だけ**（登録 k・解析 m）。⚠️ **内訳を出す欄を作らない。**
5. **矛盾検知 4 件**（設計 §2.4）を条件付き書式の**条件式の逐語**で書く:
   - `D4-2b` 違反（O1 の「開始」が G1 の「案内/登録」より前）→ **赤**
   - `D4-2` 違反（G1 が完了でも「やめた」でもないのに O1 の「案内」がある）→ **黄**
   - `D4-2c`（「やめた」の行の文言が空）→ **赤**。「取り消し」は申し出との**時刻差を表示**（判断は人）
   - 「削除の求め」の行があれば **`docs/g1-deletion-ledger.md`（G1）／`docs/o1-deletion-ledger.md`（O1）
     へ誘導する注記**を出す（⚠️ 破棄の実体は本台帳の仕事ではない）
6. **O1 参考列**（最終受領日・受領本数）は **手で写す**。⚠️ **状態には影響させない**
   （「途絶」「未受領」→「やめた」の自動変換を**しない**）。
7. **引き渡し前に研究者と行う確認手順**: ダミー P-ID（例 `P900`〜`P902`）で
   矛盾検知を **赤・黄・緑の 3 状態**で実際に出す手順（★ `verify-before-claiming` 5b の型）。
   ⚠️ **本タスクでは未実施であることを文書に明記する**（★ 隠さない）。
8. **やらないこと**（設計 §2.5）: 自動遷移・メール送信・被験者への連絡・氏名/メール/理由の記録・
   `results/` にラベルを置くこと・G1 と O1 のデータの結合。

### Out
- ⚠️ **実物のスプレッドシートの作成**（Chrome での作成と赤/黄/緑の実測は**別タスク**・要研究者同席）。
- ⚠️ **実 P-ID の入力**。
