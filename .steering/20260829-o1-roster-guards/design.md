## T-23 の判定（★ 実行時は先頭 4 列だけ）

```
1. シートが空 → 拒否
2. 列が 4 列に足りない → 拒否
3. 先頭 10 行から「A 列 = P-ID」の行を探す → 無ければ拒否
4. その行の 1〜4 列目が P-ID / 氏名/ニックネーム / メール / OS でなければ拒否
5. P-ID 形式（`/^P\d+$/`）のデータ行が 1 行も無ければ拒否
```

⚠️ **14 列すべての一致は要求しない**（★ 列を 1 つ足しただけで登録が止まるのを避ける）。
★ 14 列の一致は **テスト**が `Form_Phase1/GSE_Phase1_Form_Builder.gs` の `ROSTER_HEADER` と照合する。

⚠️★★ 配備されている Phase1 の `ROSTER_HEADER` を**実物で確認済み**（GAS 上の 3,095 行版）。
★ repo の定数と一致していた（→ `decisions.md` G-4 の精密化）。

## T-24 の位置（★ ロックの外で読み返す）

⚠️ ロックは**自プロジェクト内でしか効かない**ので、ロック中に読み返しても
★ G1 / Phase1 の書き込みは捕まえられない。→ **ロックを出てから読み返す**。

- 重複あり（2 行以上） … ⚠️ **送らない**。★ 行番号・提出者（マスク）・OS をログに残す

⚠️ **どちらの行を残すかは自動で決めない**（★ 研究者判断）。
