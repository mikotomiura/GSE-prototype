# 重要な設計判断

## 判断 1: 3 名の配る前の準備は、どけた回数から始める

- **判断日時**: 2026-11-23（研究者・AskUserQuestion・推奨どおり）
- **背景**: 配る前の残りは (a) 同意の画面の文と終了後の説明、(b) どけた回数、(c) 台帳と管理シート、(d) フォームの配備。
- **選択肢**: A (b) から／B (a) から／C (c) から／D (d) から
- **採用**: A
- **理由**: 実装するか同意から外すかで同意文書の版が決まり、(a) と (d) がそれに左右される。研究の計器として先に固める。
- **トレードオフ**: いちばん大きい変更（Rust・schema・両 OS）から始める。
- **見直しタイミング**: 3 名の開始までに入らない見込みになったとき（同意の判断 3 の見直しタイミング）

## 判断 2: どけた回数は、日ごとの行の累計の 1 項目にする

- **判断日時**: 2026-11-23（研究者・推奨どおり）
- **選択肢**: A `handmark_day` の累計の 1 項目／B 1 回ごとの時刻つきの行／C 両方
- **採用**: A
- **理由**: 同意文書の「ほかの窓をどけた回数」の範囲に収まり、同意を取り直さずにすむ。区間の削除は、今ある「前後の行の差を引く」仕組み（predist-fixes 判断 1）にそのまま乗る。
- **トレードオフ**: 1 回ごとの時刻は 5 分の粒度でしか分からない。どけていた長さは読めない。
- **却下案**: B・C は時刻が「回数」を超えるので、同意の文を直して承認を取り直す必要がある。

## 判断 3: Windows は、見えている窓を最小化して、その窓だけを戻す

- **判断日時**: 2026-11-23（研究者・推奨どおり）
- **選択肢**: A 見えていた窓を覚えて最小化し、元の重なり順で戻す／B デスクトップの表示（Win+D 相当）／C Windows では入れない
- **採用**: A
- **理由**: macOS の「押した時に見えていたアプリだけを戻す」（window-boundary 判断 5）と同じ意味になり、両 OS で刺激がそろう。
- **トレードオフ**: 管理者として動く窓は最小化できないことがあり、その窓は残る。
- **却下案**: B は途中で別の窓を開くと切り替えの状態がずれ、「見えていた窓だけ戻す」を守れない。C は両 OS で刺激がずれ、同意の文を OS ごとに直す必要がある。

## 判断 4: 項目は表示が出ている間だけ出し、文言は「ほかの窓をどける」「窓を戻す」

- **判断日時**: 2026-11-23（研究者・推奨どおり・2 問）
- **出すとき**: あり の日と後期の初日で、「やめる」を押していないときだけ。なしの日は項目も出さない。どけている間に表示をやめた・日が変わった・入口の門が閉じた・終了するときは、窓を自動で戻す。
  - 却下: 後期の間はいつでも出す（なしの日にどけた回数が割付の効果と混ざる）。
- **文言**: 同意文書の語にそろえる。
  - 却下: 「表示を見る」「戻す」（窓が消えることが文から読めない）・「ほかを隠す」「すべてを表示」（もともと隠していたアプリも戻すように読める）。

## 判断 5: コードとテストは今、Mac の実機は 12-09 以降、Windows の実機は G-GEAR

- **判断日時**: 2026-11-23（研究者・推奨どおり）
- **背景**: この Mac では本人の段 1 の後期（11-24〜12-08）の gse-next が動いている。開発版でどけると gse-next の窓（背景の層・帯）も隠れ、後期の表示と記録を乱す。
- **採用**: このタスクでは純関数・記録・削除のテストと両 OS のコードまで。Mac の実機は 12-09 以降、Windows の実機は G-GEAR 向けの引き継ぎに書く。
- **トレードオフ**: 実機で確かめるまで、どける・戻すの OS の呼び出しは CI のコンパイルとテストでしか縛れない。
- **却下案**: 今この Mac で短く確かめる（本人の記録を乱す）・別の Mac（無い）。

## 判断 8: Windows の CI で落ちた本文読みのテストを CRLF に強くし、main（#434）を取り込む（2026-11-26・Mac）

- 発見: repo を一時 public にして CI を回し直した run 45137837991 で、Windows の check だけが赤
  （1444 passed・1 failed）。`handmark_wiring_tests::the_driver_thread_guard_returns_revealed_windows` が
  `lib.rs:8530:67` の `expect("end of impl")` で panic。G-GEAR の checkout は改行が CRLF で、テストが探す
  `"\n}\n"` が `"\n}\r\n"` になって当たらない。Mac は LF なので緑だった。
- 決定: `production_code()` と同じく `include_str!("lib.rs").replace("\r\n", "\n")` にしてから探す。
  同じファイルのほかの本文読み 2 か所は `"\n}"` を探すので CRLF でも当たり、直さない。
- 確かめ（Mac で CRLF を再現）: lib.rs を CRLF にして、直す前は CI と同じ `lib.rs:8530:67` で panic（陽性対照）、
  直した後は緑。LF に戻しても緑。
- main の取り込み: #434（止まりの層）の `Effect::Stopped` と、この枝の `Effect::Reveal`・`RevealItem` が
  `handmark_driver.rs` の `destination` と `lib.rs` の効果の振り分け・テストの並びで競合した。両方を残す足し算で解いた
  （非対象 OS の空の腕は main の 4 つ、Reveal と RevealItem の腕はこの枝のまま）。
  解いた後に fmt・clippy（-D warnings）・`cargo test --workspace`・emit_schema の一致・replay（15 snapshots）が緑。
