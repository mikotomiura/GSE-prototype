# GSE 技術改善ロードマップの策定

## 背景

`GSE_改善分析_開発ロードマップ.md`（2026-04 作成、未踏 IT 2026 落選を受けた分析）に、複数の技術的改善提案が列挙されている。ただしこれらの提案は：

1. **現状実装の誤認**を含む（Synthetic Friction の挙動記述が実コードと不一致）
2. **実装スコープの過小評価**がある（IME 追加特徴量は「カウンタ追加」では済まず HMM 全体の再設計を伴う）
3. **ML 段階移行の前提条件**が非現実的（100 セッションで XGBoost など）
4. **致命的な前提タスクの欠落**がある（テスト基盤ゼロ、パラメータ外部化なし、セッションリプレイ不在）

提案をそのまま採用することは、工数浪費と既存機能の破壊を招く恐れがある。

## ゴール

- 元ロードマップの技術提案を厳密にジャッジし、採用可否と優先順位を明確にする
- 現状コードベース（commit 74889a3）を前提とした、**実行可能で順序付けされた改善計画**を作成する
- 企画戦略・未踏提案準備に関する部分は対象外（純粋に技術的改善に絞る）
- Phase ごとの Go/No-Go 判定基準を明示し、無根拠な Phase 移行を防ぐ

## スコープ

### 含むもの
- HMM エンジン / 特徴量抽出 / Synthetic Friction のロジック改善
- Ground Truth 収集基盤（リアルタイム GT ボタン、UserLabel ログ）
- テスト基盤の構築（ユニット / 統合 / スナップショット）
- セッションリプレイツール（NDJSON オフライン再実行）
- IME 追加特徴量のシャドーモード収集
- Logistic Regression 統合（重みを Rust 定数として埋め込み）
- Lv3 Thought Scaffold UI（固定テキスト版）
- 沈黙パスの二重構造の統一

### 含まないもの
- 未踏 2027 提案文書そのものの作成
- テスター募集・謝礼・実地データ収集の運用
- XGBoost / 1D-CNN / TCN 等の高度 ML モデル（データ不足で時期尚早）
- Physical Anchor（Flutter / 地図 API 連携）
- 日本語 KS データセットの匿名化公開
- 学術シンポジウム投稿

## 受け入れ条件

- [ ] 元ロードマップの技術提案ごとに「採用 / 条件付き採用 / 却下」の判定と根拠が記録されている
- [ ] Phase 0 〜 Phase 4 の順序と依存関係が明確で、各 Phase に Go/No-Go 基準がある
- [ ] 変更対象ファイルと規模（S / M / L）が全タスクに付与されている
- [ ] 元ロードマップが見落としている欠落タスク（テスト、パラメータ外部化、リプレイ）が含まれている
- [ ] `/reimagine` で v2 案を独立に生成し、v1 と比較したうえで採用案が選ばれている
