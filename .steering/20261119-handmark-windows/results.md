# 確かめの結果（手跡の Windows 版・§1）

- 日付: 2026-11-19
- 機械: G-GEAR・Windows 10.0.26300（24H2 より新しいビルド）・画面 1 枚 1920x1080・倍率 100%・昇格なしのシェル
- 試作: `spike/`（windows 0.58・GDI・debug ビルド）。手順と生の数は `runbook.md`。
- 24H2・25H2 の機械では確かめていない（判断 5）。

## 1. ADR-050 の条件 (a): 位置とクリックの読み

| 条件 | 結果 |
|---|---|
| 読みの速さ | 16ms ごとに 61 回/秒。`GetCursorPos` の失敗 0 |
| 権限 | 昇格なしで読めた（Per-Monitor DPI aware v2・座標は物理ピクセル） |
| ふつうのクリック 10 回 | 押下 11（10 回＋焦点を合わせるクリック 1 回の見込み） |
| 素早いクリック 10 回 | 押下 11・取りこぼしなし。押下 1 回の長さは平均 3.5 読み（約 57ms） |
| 昇格した窓（タスク マネージャー）が前面 | 位置は読めるが、クリックは 0（UIPI） |
| 画面のロック中 | 測っていない（ロックすると VS Code が消えて Claude Code のセッションが落ちる） |
| CPU | 20 秒で 16〜47ms（ほぼ 0） |

- 読んだのは `VK_LBUTTON` だけ。キーボードの仮想キーは渡していない。
- 起動直後の最初の読みで「前回から押された」ビット（最下位）が立つことがある。本番では最初の読みを捨てるか、このビットを使わない。

**結論**: 条件 (a) は満たせる見込み。昇格した窓の前ではクリックが取れないが、表現の入力の取りこぼしは許す（ADR-050 D6）。他人の昇格した窓の入力を読まない性質としても書ける。

## 3. 下の縁の帯（最前面・クリック透過・高さ 14・作業領域の下端）

| 条件 | 結果（研究者の目と試作の出力） |
|---|---|
| ふつう | タスクバーのすぐ上に出た |
| タスクバーを上端へ移す | 作業領域の読み直しで、画面の下端へ置き直せた |
| タスクバーを自動で隠す | 自動で隠す設定は `ABM_GETSTATE` で読めた。作業領域が画面全体になり、帯は画面の下端。タスクバーが出てきても帯は下端のまま（タスクバーの所に重なる） |
| 全画面（ブラウザの F11） | 全画面の上にも出たが、置き場は「タスクバーがあった所の上」のまま。本番では、前面の窓が主画面の全体を覆ったら下端へ寄せる（Mac 版と同じ）。全画面かは窓の大きさで読めた |
| 最大化した窓と全画面の区別 | 自動で隠す設定のとき、最大化した窓も「全画面」と読まれた。どちらでも帯を下端に置けばよいので困らない |
| 多画面 | 画面が 1 枚なので確かめていない |
| 画面共有の除外 | できる（0x11） |
| CPU | 0.86〜1.09% |

**結論**: 帯は成り立つ。全画面のときの置き場の寄せと、多画面の確かめが残る。

## 4. 背景の層の推奨（研究者が選ぶ・判断 3）

### 4.1 B5（両方の良い所を取る・2026-11-19 に足した）

研究者は B1 と WL の二択を退け、両方の良い所を求めた。B5 はトップレベルの窓のまま（画面共有に写さない）、アイコンを模様の上に描き直すことで「アイコンの裏で模様が流れる」見え方を作り、Win+D の後も毎コマの置き直しで戻る。研究者の目で 4 項目とも満たした（`runbook.md` 4 回目）。

- **B5 を推す**（Claude の推奨・下の 4.2 の旧推奨を置き換える）。
- 引き受けるもの:
  - デスクトップのアイコンの矩形と画素（名前の文字を含む）を読む。記録・送信はせず、画面に描くだけ。ADR-050 は入力（位置とクリック）を記録しないと定めるが、アイコンの画素はそこに書かれていない新しい読みなので、研究者の了承と追記が要る。
  - Progman と SysListView32 を名前で探す（構造は 24H2 で変わった前例がある [V284]。見つからなければ B1 と同じ見え方に落ちる）。
  - アイコンの取り直しは 2 秒ごとなので、アイコンを動かした・増やした直後の 2 秒は古い絵が出うる。
  - 本番は WebView2 で描く。アイコンの重ね方（WebView2 の上に別の層を置くか、画素を渡すか）と CPU は §2 で決めて測り直す。

### 4.2 旧推奨（B1 か WL か・B5 の前）

論点は、**Mac 版と同じ層（WL）**と、**画面共有に写さない（B）**のどちらを取るか。
画面共有に写さないのは ADR ではなく研究者の選択（`20261108-handmark-stage1-late-pr1` 判断 9）なので、ここで選び直せる。

- **B1 を推す**（Claude の推奨）。
  - 公開の API だけで作れ、OS の更新で壊れる心配が小さい。画面共有に写さない、という Mac 版の選択を守れる。
  - 失うもの: アイコンの上に出る（模様の無い所は透けるのでアイコンは見える）。Win+D でデスクトップを出すと隠れる。
  - B1 と B2 の見え方は同じだったので、Progman を探さない B1 のほうが簡単。
- WL を選ぶなら、次を受け入れることになる。
  - 画面共有・収録・スクリーンショットに写る。
  - 非公開の構造に頼る。
  - アプリ全体のマニフェストを差し替える。
- T（他の窓の上に重なる）と S（動かない）は、手跡の性質が変わるので推さない。
