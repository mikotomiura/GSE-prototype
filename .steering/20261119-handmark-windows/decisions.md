# 重要な設計判断

## 判断 1: 範囲は確かめと本番の実装の両方（main に merge まで）

- **判断日時**: 2026-11-19（grill・研究者）
- **背景**: 引き継ぎの入口は「実現の確かめ」だった。
- **選択肢**:
  - A: 確かめだけ（実装は別のタスク）
  - B: 確かめと本番の実装
  - C: 条件 (a) だけを先に
- **採用**: B
- **理由**: 研究者の選択。
- **トレードオフ**: タスクが大きくなる。途中に研究者が候補を選ぶ停止点を置く（判断 3）。
- **影響範囲**: requirement.md のスコープ・受け入れ条件。
- **見直しタイミング**: 確かめの結果、どの候補も成り立たないとき（その時点で止めて研究者に戻す）。

## 判断 5: 確かめは G-GEAR で、研究者の手を借りる。OS の版はこの機械のものを記録する

- **判断日時**: 2026-11-19
- **採用**: G-GEAR（Windows 10.0.26300）で測る。クリックの陽性対照・画面共有・タスクバーの自動で隠す設定・多画面は研究者の手で行う。24H2・25H2 では未確認として残す。
- **背景**: 引き継ぎには「G-GEAR は 11 月いっぱいふさがっている」とあるが、2026-11-19 の時点で計測のプロセスは動いておらず、研究者がこの機械で進めると決めた。
- **補足**: 引き継ぎの「Windows 機の Claude Code には収集だけを頼む」は、文脈を持つ Mac の側で直す前提の運用だった。今回は Windows の側で文脈（steering・ADR）を読んだうえで直接進める。

## 判断 7: 確かめの段の design を承認・候補 B を足す

- **判断日時**: 2026-11-19（研究者・Step C）
- **背景**: 取り込みの除外（`WDA_EXCLUDEFROMCAPTURE`）はトップレベルの窓だけで、子の窓には FALSE が返る（[V283]）。WorkerW の子（候補 W）は画面共有から外せない見込みで、Mac 版の fail-closed（`handmark_stage.rs` の `prepare()`）を守れない。
- **採用**: 引き継ぎの 3 候補（W・T・S）に、トップレベルの窓を z 順の最下に保つ候補 B を足して 4 つを測る。試作は `.steering/` の下の小さな Rust の crate で、GDI で描き WebView2 は使わない。
- **却下案**: 引き継ぎの 3 候補だけを測る。

- **背景**: start-task の Loop の節は「grill は main のチェックアウトで」とする。`C:\GSE-prototype` は別の枝（`docs/ime-release-1.0.2-published`）で、コミットしていない変更がある。

## 判断 9: 背景の層は B5（両方の良い所を取る）

- **判断日時**: 2026-11-19（研究者・停止点）
- **背景**: 確かめの推奨（B1）に対し、研究者は二択を退け「アイコン問題を何とか解決して、いいとこどりができたら最高」「アイコンの裏では模様が流れる感じが好ましい」と求めた。B3・B4（アイコンの矩形を穴にする）は「アイコンの表示に重なって見える」だった。
- **選択肢**:
  - B5: トップレベルの窓・Progman のすぐ上に毎コマ置き直す・アイコンの画素を `PrintWindow` で取り、模様の上に描き直す
  - WL: Progman の子（Mac 版と同じ層・画面共有に写る・非公開の構造・マニフェストの差し替え）
  - B1: `HWND_BOTTOM`（アイコンの上に重なる・Win+D で隠れる）
- **採用**: B5
- **理由**: 研究者の目で、アイコンの後ろを流れる・窓の下・Win+D の後に戻る・アイコンにずれやちらつきなし、の 4 項目を満たし、画面共有に写さない（0x11）という Mac 版の選択（`20261108-handmark-stage1-late-pr1` 判断 9）も守れる。
- **トレードオフ**: アイコンの読み（判断 10）・Progman と SysListView32 を名前で探す・アイコンの絵の取り直しの遅れ（試作は 2 秒）・全画面の合成の CPU（試作 5.78%）。
- **影響範囲**: design.md §2・本番の背景の層の実装・ADR-051 D1 補訂。
- **見直しタイミング**: 本番（WebView2）で CPU が大きすぎるとき、または Progman・SysListView32 が見つからない Windows の版が出たとき（そのときは B1 と同じ見え方に落とし、理由を 1 行残す）。

## 判断 10: デスクトップのアイコンの矩形と画素を読むことを了承する（記録・送信・蓄積をしない）

- **判断日時**: 2026-11-19（研究者・停止点）
- **背景**: B5 はデスクトップのアイコンの矩形（UI Automation の `BoundingRectangle`）と画素（`PrintWindow`・名前の文字を含む）を読む。ADR-050 は手跡の入力（位置とクリック）を記録しないと定めるが、アイコンの画素はそこに書かれていない新しい読み。
- **選択肢**: 了承して ADR-050 に追記する／画素は読まず矩形だけ（B3・B4 型・アイコンの上に重なって見える）
- **採用**: 了承・ADR-050 に追記する
- **条件**: 記録しない・送信しない・取り直したら古い絵は捨てる（ADR-050 D4 の「溜めない」と同じ型）。名前（文字列）は読まない（UI Automation から取るのは矩形だけ）。画素は画面に描くためだけに使う。
- **影響範囲**: ADR-050 の補訂・本番の検査（読んだ画素が記録や IPC の経路へ出ないこと）・security-checker の観点。
