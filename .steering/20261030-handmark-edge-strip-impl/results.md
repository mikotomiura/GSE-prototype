## run7（2026-10-30 2:08〜・帯を出さない起動 `GSE_HANDMARK_EDGE_STRIP_OFF=1`・判断 4）

- 起動の前に、run6 の vite（ポート 1420）が残っていて起動に 1 回失敗した。自分が起動したものなので止めて起こし直した。
- (a) 打たない 60 秒を 2 回測ったが、本体が 1 コアの 78.8%・42.8%（run6 は 3〜6%）で比べられない。トレイは「停止中」のまま（run6 は起動から約 2 分で「記録中」になっていた）。
- 原因（`sample` で確かめた）: 本体の CPU の多くが記録のスレッドの `crossbeam` の待ち（`Backoff::snooze`・`LogEntry` の `recv`）。`logger.rs` の書き出しの待ちは `recv_timeout(flush_interval - last_flush.elapsed())` で、書くものが無い（`dirty=false`）まま 5 秒を過ぎると `last_flush` が更新されず、待ち時間が 0 のまま回り続ける見込み（コードを読んだ推測・直していない）。同じ行は main（`origin/main` の `logger.rs:1927`）にもある。O1 の収集アプリ（記録中）は 6.6 日で CPU 81 分（平均 約 0.9%）で、記録中は書くものが絶えず来るので目立たない見込み。
- 比べる条件を揃えるため、帯ありの run6 と同じ「記録中」で測り直す。
- 研究者が開発版の主窓で「開始する」を押して記録中にした（2:35:09）後に測った。

| 条件（記録中） | 本体 | WebKit GPU | WebContent 3 つ | Networking | 合計 |

| 帯なし (b) 打つ 60 秒 | 3.77 | 7.43 | 0.00 / 0.00 / 3.97 | 0.03 | 15.20 |

### 帯の分（run6 − run7）

| | 帯あり（run6） | 帯なし（run7） | 差（帯の分） |
|---|---|---|---|
| 打たない（10 回/秒） | 10.97 | 8.79 | 約 2.2 |
| 打つ（30 回/秒） | 22.35 | 15.20 | 約 7.2 |

- 1 回ずつの比べで、打つ速さ・量は回ごとに違う（研究者が打った）。差の桁を見る程度の数字。
- Swift の試作（線だけ・60 回/秒・7〜11%）と比べると、打たない間はかなり小さく、打つ間は同じくらい。打つ間の帯の分の多くは GPU のプロセスに出ている。
