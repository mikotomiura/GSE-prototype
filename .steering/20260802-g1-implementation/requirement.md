# G1 統制タスク実験の実施準備（事前登録の改訂・プロトコル・課題文・解析）

## 背景

G1（統制タスク実験）の**事前登録は凍結済み**（`6013104`）。しかし実験を実際に回すための資材が
何一つ存在しない——課題文も、実施手順も、解析スクリプトもない（`run.sh` は停止スタブ）。

さらに前セッションで、凍結文書に**書かれていない／誤っている**ことが 8 件判明した
（`.steering/_handoff/next-session-prompt-g1-implementation.md` §0）。主なものは:

1. ★★ **`§5-3` の「Tier 0/1 は凍結解除後でなければ着手できない」は誤り**。
   NDJSON は打鍵 1 打ごとのレコードを持つため Tier 0/1 は**すべてオフラインで計算できる**。
2. ★★ **題材↔条件の交絡が未対処**。「題材 1–4 は LO・5–8 は HI」と作ると、
   分離できても摩擦でなく題材の書きやすさを見ている可能性を排除できない。
3. ★ **P014 型（9 press しかないブロック）の再発リスクが未対処**。
4. ★★ **「なぜ論述なのか」の論理が書かれていない**。現行 §2.1 は論述を代表例と読ませかねない。
5. ★ **n=5 は power 計算ではなく慣例値**であり、必要な n は結果の向きで変わる。

## ゴール

**G1 を「明日から回せる」状態にする。** 実験そのものは実施しない。

- 事前登録を**判定を厳しくする方向にのみ**改訂する（合格しやすくする変更を 1 つも含めない）。
- 実施プロトコル・課題文・解析スクリプトを揃え、`run.sh` が実施前チェックとして緑／赤を返す。

## スコープ

### 含むもの

- **T-A** `preregistration.md` / `config.json` の改訂（9 項目・§3 の判定基準は変えない）
- **T-B** `protocol.md`（新規）— ブロックの切り方・ラベル対応表・操作チェック用紙・進行台本
- **T-C** `materials/`（課題文）— パイロット用 1 題材 × 2 版 ＋ copy task 定型文 ＋ 検証スクリプト
- **T-D** Tier 0/1 を含むブロック単位特徴量のオフライン実装（`analyze.py`）
- **T-E** 解析パイプライン（L2 ロジスティック・被験者内 CV・並べ替え全数列挙）と `run.sh` 実施前チェック
- **T-F** 倫理・同意（`consent.md`）
- `env.md` / `data.md` の訂正（Tier 0/1 は凍結解除を待たない）

### 含まないもの

- **実験の実施**（パイロットを含む）。実施可否は研究者判断。
- `docs/preregistration-v0.3.md` の変更（Phase1 の凍結契約）
- `preregistration.md §3` の判定基準・しきい値・特徴量セット・検定の変更
- `src-tauri/` / `src/` のコード変更（G1 はコード変更ゼロで実施できる）
- 本番用 8 題材 × 2 版の作成（パイロット後でよい）

## 運用メモ

- /reimagine 適用: **No**
- 理由: 設計判断は凍結済み事前登録と引き継ぎ書で確定しており、選択肢の再生成ではなく
  **凍結を守ったまま実装に落とす**タスクであるため。ただし残った設計自由度
  （ブロックの切り方・FS-A の算出元・最小打鍵しきい値）は `decisions.md` に選択肢と却下理由を残す。
- Loop Engineering 適用: **No**
- 理由: 成果物が相互依存する文書群（事前登録 ↔ プロトコル ↔ 課題文 ↔ 解析）であり、
  Allowed Files を非交差に切れない。また AC↔test 対応が付くのは T-C/T-D/T-E のみで、
  縦切り issue にすると分解コストが実装コストを上回る。
