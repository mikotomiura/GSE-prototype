# 設計案比較（`/reimagine` 1 回目）

## v1 の要旨

`stall onset` を**新しい独立した検出器**として設計する。3 条件（産出低下 / 持続 / 検出時点＝t0）を
自前で定義し、`θ_person` を個人内分位点で決める。オフライン側に置いて `HMM_VERSION` を守る。
`phase` は `unspecified` に collapse、`task_kind` は O1 で分散ありと訂正する。

## v2 の要旨

同じ結論に到達するが、**出発点が違う**。`metrics.rs` に**既にある** `StuckTrigger`（3 値）と
`segment_stuck_episodes` を一次で発見し、`stall onset` を **「4 つ目の `StuckTrigger`」**として位置づける。
そのうえで **既存 3 トリガがなぜ予測トラックの原点に使えないか**（循環 / 較正限定 / 介入駆動）を
本 ADR の核心に据える。新しい定数も作らず、既存 `OutcomeConfig::net_diff_min` を対称に再利用する。

## 主要な差異

| 観点 | v1 | v2 |
|---|---|---|
| **出発点** | 概念定義（`personalization:336`）から演繹 | ★ **既存コード（`metrics.rs:122-129`）から接続** |
| **「新設しない」の深さ** | ADR レベル（受け皿の名前） | ★★★ **コードレベル**（`StuckTrigger` の 4 値目・`net_diff_min` 再利用） |
| **`t0` を検出時点に置く理由** | 窓の重なり（1 本） | ★ **不死時間バイアス ＋ 窓の重なり（2 本）**。⚠️ v1 は統計的な理由を落としていた |
| **既存の `p_stuck` 経路の扱い** | ⚠️ **言及なし** | ★★★ **循環として明示的に却下**（`criterion §1.1`） |
| **新しい定数** | `net` の個人基準を新設 | ★ **既存 `net_diff_min`（既定 1）を再利用**。回復側と対称 |
| **`ADR-014 D4c` との関係** | ⚠️ 未検証 | ★ 逐語確認し「判定量は増えない」と明示 |
| **66 倍の根拠の格** | そのまま引用 | ⚠️ **F5 = ポーズ *回数* であって pause 長でないと訂正**し、間接証拠として引く |
| **壁時計の非単調性** | ⚠️ 未検討 | ★ 前方跳躍＝偽 onset を**未決として起票**（閾値は決めない） |
| **変更規模** | ADR 1 本 ＋ README 1 行 | 同じ |
| **リスク** | ⚠️ 既存 `StuckTrigger` と**二重定義**になる（実装時に衝突） | ★ 既存に接続するので衝突しない |

## 推奨案

**v2** —— 理由:

1. ★★★ **v1 は既存のエピソード分割器を見落としていた。** そのまま実装へ渡すと、
   タスク 2 で `StuckTrigger` と**二重定義**が生まれる（★ 引き継ぎ §8b が
   「契約の二重定義は `--dry-run` では観測できない」と警告した型そのもの）。
2. ★★★ **v1 は `PStuckThreshold` が既定であることを知らないまま書いていた。**
   ⚠️ 何も言わずに ADR を通すと、実装者は**既定のまま**（＝ 推定器の出力で criterion の原点を作る
   ＝ 循環）に落ちる。**明示的な却下が要る。**
3. `t0` の置き方の根拠が **1 本 → 2 本**になり、統計的に本筋の理由（不死時間バイアス）が主になった。
4. 新しい定数を 1 つも作らずに済む（★ `net_diff_min` の対称利用）。

⚠️ v1 固有で残す価値のあるものは**無い**（v2 は v1 の結論をすべて含む上位互換）。
