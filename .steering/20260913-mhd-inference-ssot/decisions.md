# 設計判断の記録

## 判断 1: `/reimagine` は **v2 を採用**する

- **判断日時**: 2026-09-13（研究者判断）
- **根拠**: v1 は `metrics.rs` の既存 `StuckTrigger` / `segment_stuck_episodes` を見落としており、
  そのまま実装へ渡すと **契約の二重定義**が生まれる。かつ既定 `PStuckThreshold` が
  **推定器の出力で criterion の原点を作る（＝循環）**ことを明示的に却下できない。
- 詳細は `design-comparison.md`。

## 判断 2: ADR-030 は **ADR-029 ブランチから分岐**する

- **判断日時**: 2026-09-13（研究者判断）
- ⚠️ ADR-029 は `docs/adr-029-outcome-role-arbitration` に在り **未 push / 未 PR**、AC 1〜3 は承認待ち。
- ★ ADR-030 は ADR-029 D1/D2/D3/D5/D6 に依拠するので、同じツリーに置く。
- ⚠️★★★ **帰結: マージ順序が ADR-029 → ADR-030 に固定される。**

## 判断 3: `phase` は **`task-adaptation-and-scope-gating.md §3.6` の暫定案を確定**する

- **判断日時**: 2026-09-13（研究者判断）
- ★ `phase` := 直前の `task phase change` 境界からの区間（構造的定義のみ）。
  自然セッション（O1）は `unspecified` に collapse、構造化セッションでのみ block id を使う。
- **根拠**: 鍵 `user × task_kind × phase` の濃度を上げると鍵あたりのデータが減る一方、
  ⚠️ **意味的分割を検証する正解ラベルが存在しない。**
- → ★ **ADR-030 D5**。`personalization §11-1` の未解決 1 が閉じた。

## 判断 8: ⚠️★★★ `security-checker` の HIGH（区間指定削除の無標識の穴）を **構造で受ける**

- **指摘（2026-09-13）**: D8 の除外リストに **被験者の区間指定削除**が無い。
  → ★ 条件 A/B を素直に実装すると **削除区間が「産出ゼロの継続」と読まれ、
  被験者が「消してくれ」と言った位置に必ず onset が立つ**。
  ⚠️ かつ **素直な修正（削除区間を NDJSON に標識する）が約束を破る**。

### ★ 一次で検算した（正しい）

| 事実 | 出所 |
|---|---|
| `retain_outside_range` は区間内の行を落とし、**残すのは `meta` 行だけ** | `redaction.rs:82-90`（`line_timestamp` が `meta` を `None` にする） |
| 一時停止は `recording_pause` と `meta` を通すので **両端に標識が残る** | `recording.rs:64-66` |
| ⚠️ → **削除区間だけが無標識** | ★ 上の 2 つの差 |
| `feat` は **沈黙中も 1Hz で出続ける**（打鍵ゼロの 43 秒で **44 行連続**） | `loop_step.rs:159`・`tests/snapshots/deep_silence.json` |
| 一時停止中は **1Hz ゲートを skip** する | `loop_step.rs:21` |

### ★★★ 採った解 —— **原因を列挙せず、構造で受ける**

> ⚠️★★★ **1Hz の `feat` 列に穴がある区間では、条件 B の連続を切る。★ 原因は問わない。**

- ★ **自然な沈黙には穴が開かない**ので、削除区間・一時停止・計器の欠損を **区別せずに**受けられる。
- ⚠️★★★ **原因ラベル（`redacted` 等）を作らない** —— ★ 作った瞬間に
  `redaction.rs` の約束（逐語「何を消したかは書かない」）を破る。
- ★ **D9（壁時計の前方跳躍）の一部も同じ機構で受かる。**
