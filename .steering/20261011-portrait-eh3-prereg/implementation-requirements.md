# 実装の要件 — EH3 のための招待・肖像・記録・配布

> 別タスク（実装）の requirement の材料。決定は本タスクの `decisions.md` 判断 1・2 と親の判断 1〜15。値の多くは実装で決め、事前登録の稿 `experiments/20261011-portrait-eh3/preregistration-draft.md` §10 に戻す。
> 実装の前に読む ADR: 026（Accepted）・033（Proposed）・035（Proposed。Migration 1 の逐語は「Physical Anchor の PC 面を実装するときに、D1〜D6 を acceptance に入れる」）・013（Accepted）・024（Accepted）・021 D4（Accepted）・027 D4（Accepted）。

## 1. 現状（一次・2026-10-11）

- 招待（`invitation`）の実装は `src-tauri/src` と `src` に 0 件（ADR-026 の 240 行・292 行。本タスクで grep して再確認した）。
- 肖像・壁紙の実装も、本体には 0 件。試作は `experiments/20261010-portrait-eh1-round5/scripts/portrait.py`（Python: `Generator` の `raw` / `lattice`、`Sched` の `clock` / `recent`）と `experiments/20261009-portrait-eh2/`（Windows は `IDesktopWallpaper` の PowerShell、macOS は `NSWorkspace.setDesktopImageURL` の Swift）にある。
- Nudge の契機は `intervention.rs` の `decide()` で、`p_stuck`（`clean_score`）が 0.60 以上、`idle_ms` が `AWAY_IDLE_MS`（180 s）未満、機会のスコアが 0.35 以上のときに出す。持続の条件は無い。cap は 6/日（UTC の日）、cooldown は 10 分、dismiss の後は 20 分控える。
- `INTERVENTION_ENABLED`（`lib.rs:113`）が偽なら `safe_default`。O1 では常に偽（`lib.rs:3360`）。

## 2. 招待の PC 面（R-I）

| # | 要件 | 由来 |
|---|---|---|
| R-I1 | 文字を置かない図像にする。状態も理由も言わない。図像は提示ごとに不変（大きさ・動き・色・出ている時間で強度や回数を表さない）。図像から説明と設定へ辿れる。その操作は応答として記録しない | I-1・ADR-021 D4・ADR-035 D2 |
| R-I2 | 提示から一定の時間 T で、応答の有無に依らず `invitation: none` に下げる。PC 面だけを隠さない。失効のタイマーは招待 1 回ごとに結び付け、古い失効が新しい招待を消さない。境界に ID を足さない。タイマーは実時間で数えるのを候補にする | I-2・ADR-027 D4・ADR-035 D1 |
| R-I3 | 本人が止めた瞬間と、本人が決めた時間帯が終わった瞬間は、即時に `none` へ下げる | 親の判断 11 |
| R-I4 | 閉じた後の間隔は応答に依らず時間だけで決める。閉じた理由・回数・見逃しを本人に示さない（系は PC-6 のために数える） | I-2・I-3 |
| R-I5 | 招待の提示回数の上限を Nudge の cap と別に決める（値は未決） | ADR-026 PC-6 |
| R-I6 | 出す時点は推定の停滞を契機にする（判断 1 #6）。値（`p_stuck` の閾値・持続の有無・機会のスコアを使うか・離席候補の中では出さないか）は実装で決め、決めた根拠を書く。これにより時期の範囲の中の時点は系が状態から選ぶことになるので、ADR-035 却下した主張 #1 の懸念（[P386]）が残る。説明・設定・論文で「本人が選べるので非支配的」と書かない | 判断 1・ADR-035 却下した主張 #1 |
| R-I7 | 停滞の 1 区間あたりの回数（U-3）を決める。候補は「1 区間に 1 回」 | 親の判断 10 U-3 |
| R-I8 | 本人の統制: 有無と時期の範囲を N 択で変えられる。既定は「出す」・時期と上限は狭い側。初回に設定を強いない。設定の画面に本人の量を置かない。D4 の経路独立性（同じ設定なら変更の履歴が出す量を変えない・広げた後は最初から広い設定を超えない・設定の変更で抑制が解けない）を陽性対照つきのテストで固定し、内側の制約が設定より内側で効くことを、最大に広げた設定で確かめる | ADR-035 D1〜D6・Migration 1 |
| R-I9 | 明示の応答（受諾・保留・拒否）のボタンを置かない | 判断 2 #2・ADR-033 D1 |
| R-I10 | 応答を成功として学習・評価・報酬に戻さない。応答で控えを解かない。単調性の検査（応答の列だけを変えても頻度と強度の上限が上がらない）を acceptance に入れる | ADR-033 D3・D4・D6 |
| R-I11 | 招待面に量・文字を置かない無条件の露出削減。共有・録画の状態を検出しない | ADR-026 PC-8・D4 |
| R-I12 | 「提示されていること」を最低要件にする（`present` の間に招待面が空でない）。no-op を合格にしない | ADR-026 PC-12 |
| R-I13 | ADR-026 M11 の検査（禁止語・量の静的検査／共有検出の API を呼ばない／PC-12／引用と未決の参照の解決）を、招待面の最初のコードと同じコミットで入れる | ADR-026 M11 |
| R-I14 | 招待を肖像の上に重ねない・肖像の一部に見せない | I-5 |
| R-I15 | 統制的な語を使わない（初回の説明・設定の文） | I-4 |

## 3. 肖像（壁紙）（R-P）

| # | 要件 | 由来 |
|---|---|---|
| R-P1 | 材料は F 系列の時間関係だけ。推定（`level` / `p_stuck` / X・Y）を材料にも契機にも使わない。招待とその応答を生成器に渡さない | E1-1・E1-6 |
| R-P2 | 形の文法は研究者が見本で選んだ 1 つ（`raw` か `lattice`） | 判断 1 #3 |
| R-P3 | 更新は U-4 の型（`recent`・60 s。打鍵の最中は次の予定の時刻へ飛ばす・60 s 以上の不在の中では更新しない・スリープ中は更新しない）。間隔と窓は EH1 の既定（300 s・5 s）を候補にし、変えるなら理由を書く | 親の判断 5・13・E1-2 |
| R-P4 | 停滞・不在を萎み・暗さ・減り・達成に写さない。観測が足りないときの中立はセッションの始まりにだけ当てる | E1-4・E1-7 |
| R-P5 | 量・凡例・比較・「良い形」を作る方法を置かない | E1-5 |
| R-P6 | 終わりの扱い: none と seed を日ごとに切り替えられる（A ブロックの中で交互）。seed の畳み方の具体を決める。seed の印は次の始まりまで壁紙に残るので、「終わり」と「始まり」の時点（R-7）と、翌朝に印が見える区間を定義する | 親の判断 12・判断 2 #1・判断 3 |
| R-P7 | D（日替わりの地模様）の生成器: 打鍵を材料にせず、日付と種から作る | 判断 2 #1 |
| R-P8 | 元の壁紙を必ず戻す。戻せない背景（スライドショー・単色・スポットライト・動く壁紙など）では動かさない。戻した後は、OS から設定を読み戻したパスと、元のファイルの SHA-256 の両方を確かめる（ファイルが変わっていないだけでは、表示が戻った保証にならない）。受け入れの試験に、異常終了・再起動・スリープからの復帰・複数のモニタ・本人が期間中に壁紙を自分で替えた場合を入れる。本人が自分で替えた後に上書きしない。EH2 の試験（`experiments/20261009-portrait-eh2/`）を引き継ぎ、足りない場合を足す | EH2 README の安全節・台帳 肖14・判断 3 |
| R-P9 | 本人の操作（止める・戻す・その回の形を消す）を記録しない。時刻という横の経路でも記録しない: 壁紙を実際に書き込んだ時刻をログに出さない（R-L1）。受け入れの試験に「肖像を止めた前後で、出力される行の種類と数が操作の有無で変わらない」を入れる | 台帳 肖13・判断 3 |
| R-P10 | 壁紙の更新は `analysis/` の外（`input/` か OS 依存の層）に置く。`analysis/` に OS API を入れない | 技術的制約 11・`architecture-rules` |

## 4. 記録（R-L）

| # | 要件 | 由来 |
|---|---|---|
| R-L1 | content-free の NDJSON に足す行種（案）: 日ごとの条件の割り当て（空 / D / A-none / A-seed）と、招待の提示の時刻（理由を載せない）。壁紙を実際に書き込んだ時刻と、招待の解除の時刻は記録しない（本人の操作が時刻から読めるため。更新の時刻は解析の側で打鍵の記録から組み直す）。止めた後に提示が出なくなることは避けられないので、ADR-035 D4 の条件で扱い、同意文書に書く | 判断 1 #7・判断 3 |
| R-L2 | 新しい行種は additive-only・`Option`。`schema_dto.rs`・`logger.rs`・`schema/current.json`（`emit_schema`）・`capabilities.rs`（送出元に合わせた群）・`check_schema_parity.py`・`capabilities_gate.py` を同時に直す | ADR-013 D1〜D3・ADR-005 |
| R-L3 | 同意文書の記録項目と participant-guide に載せ、配布した同意フォームと突き合わせてから収集を始める | ADR-013 D5 |
| R-L4 | 招待の設定の値を記録するなら、R-L3 と同じ手順を踏む。集計は ADR-035 D4 の条件の中だけで行う | ADR-035 D4 |
| R-L5 | `meta` に EH3 のモード（O1 の `o1_mode` と同じ形）を足し、O1・G1 の記録と混ざらないようにする | 判断 1 #8 |
| R-L6 | O1 の通常運用の NDJSON は byte 同一のまま（EH3 のモードでないときに新しい行を出さない） | `schema_dto.rs` の注記 |
