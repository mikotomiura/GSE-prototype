## 判断 2: ADR-032 の計器（undo/redo の行種・Ctrl/Cmd の 1 ビット）は 3 名の版に入れない

- **判断日時**: 2026-11-14
- **背景**: ADR-043 D9 は、計器を入れるかを段 1 の同意文書を書くときに決めるとした。今のコードにはどちらも無い。計器は 3 名の開始で固定し、採択後の群でも変えない（ADR-052 D1）。
- **選択肢**:
  - A: 両方入れる
  - B: 修飾キーの 1 ビットだけ
  - C: 入れない
- **採用**: C（研究者・推奨どおり）
- **理由**: 段 1 の推論は個人の中で、各人の OS は通して同じなので、macOS で Cmd+Z が産出に数えられる偏りは個人の中の比べを歪めにくい。事前登録の草案も ADR-032 の量を使っていない。入れると ADR-014 D4 の禁止表を部分的に解き、同意の「記録するもの」が増え、本人の探索の計器ともずれる。
- **トレードオフ**: この事前登録の系統（3 名と採択後の群）では undo/redo と修飾キーの量を使えない。
- **影響範囲**: ADR-032 の状態（Accepted にするか Proposed に残すかは後の判断で決める）
- **見直しタイミング**: 段 2 以降で OS をまたぐ比べが要るとき

## 判断 13: 消した時間帯の手跡の表示の量も残さないと約束する

- **判断日時**: 2026-11-14
- **背景**: `redaction.rs` は消した時間帯の中の `handmark_day` の行を落とし、外の行から区間に入る `toggles` などを消す。ただし行はその日の累計（`shown_ms`・`visible_ms`）を持つので、消した時間帯の前後の行の差から、その時間帯にアプリが動いていた量と画面がロックされていた量が読める（`schema_dto.rs` の `HandmarkDay` の doc が書いている）。ADR-052 D2 はこの扱いを 3 名の配布の前にテストで縛るとした。
- **選択肢**: A 消した時間帯の量も消える（割付は残る）と書き、後の行の累計から消した分を引いて書き直す実装を配布の前の必須条件として手跡の PR に渡す／B 累計は残ると書く（今のコードのまま）／C 重なった日の行を全部落とす
- **採用**: A（研究者・推奨どおり）
- **理由**: 参加者が消してと言った時間帯の在席の手がかりを残さない方が、約束として強い。C は割付が欠けて ITT の分母から落ちる。
- **トレードオフ**: 手跡の PR に実装が 1 つ増える。5 分ごとの行の粒度で引くので、引き方（区間の端の 5 分をどう扱うか）を PR で決める。
- **影響範囲**: 同意文書の削除の節。手跡の PR（ADR-052 D2 のテスト）。3 名の配布の門
- **見直しタイミング**: —
