# データ → 社会的メディア表現の変換理論 — 採否の切り分けと制約の確定

> 2026-09-06 / 入力: `.idea/20260905-data-to-social-media-expression-theory.md`
> （⚠️ **追跡外 = SSOT ではない**。ADR-020 が `.idea` を入力として扱った先例に倣う）

## 背景

`.idea/20260905` が、GSE の表現層を「状態表示」から
**「変化するデータ → 社会が解釈できるメディア表現」への一般理論**へ拡張する構想を出した。

本タスクは **その構想を実装・昇格させるためのものではない**。
構想を **(i) いま採れるもの / (ii) 既に決定済みで再発明なもの / (iii) 現行契約と衝突するもの /
(iv) 文献を見るまで判断できないもの** に切り分け、**(iii) を制約として固定する**ことが目的である。

### なぜ切り分けが先に要るか

⚠️★★★ **`.idea` の中間表現（Temporal Expression State）は、一度提案されて降格済みの形と同型である。**
`.idea/20260806` §6 が `p_stuck / pause / correction / burst / recovery proxy → ローカル WebSocket または OSC
→ ESP32 / LED / e-ink / スピーカー` を提案し、**PM-D4「常時流し続けるのは一段大きい」で離散イベントへ降格**、
その結果が **ADR-017 D2 の「抽象状態イベント」**である。

→ ★ **`.idea/20260905` §3 が降格を免れる理由は 1 つだけで、メモはそれを書いていない** ——
**PM-D4 が退けたのは「境界を跨いで流し続けること」であって「表現を中間表現に置くこと」ではない。**
IR が PC ローカルに閉じるなら、退けられた理由に当たらない。★ **本タスクはこれを明文化する。**
