### ★★ 前セッションで判明したが**まだ文書に反映していない**こと（本セッションで書く）

1. ★★ **FS-B は凍結解除を待つ必要がない。** NDJSON は既に `Key { t, vk, press }`＝
   **打鍵 1 打ごとのタイムスタンプと vk** を持つため、`keys` / `bs_rate` / silence・burst 分布 /

   凍結されているのは **Tier 0/1 を実行時の推論経路（`feat` 行・HMM）へ配線すること**であって、
   **オフライン解析には無関係**である。
   → ⚠️ `preregistration.md §5-3` と `env.md` の「凍結解除後でなければ着手できない」は**誤り**。訂正する。
   → ★ 帰結: **G1 は Phase1 の凍結解除を待たずに実施できる**（コード変更ゼロなので Phase1 の再現性を壊さない）。
   ⚠️ ただし `ADR-009 D7` / `personalization-and-online-learning.md §8.2` は
   「G1 は**凍結解除後の最初のタスク**」と書いている。**順序決定に触れるので研究者判断**。
2. ★★ **題材↔条件の交絡**（未対処）。「題材 1–4 は LO・5–8 は HI」と作ると、
   被験者の中で**条件と題材が完全に交絡**する。分類器が分けているのが摩擦なのか
   「題材 5–8 がたまたま書きにくかった」だけなのか区別できない
   （§2.2 が語彙制約を却下したのと**同じ種類の誤り**）。
   → **各題材に LO 版と HI 版の両方を作り、題材↔条件の対応を被験者間で釣り合わせる。**
   個人内では原理的に外せない（同題材を両条件で出すと 2 回目は内容を知っている）。
   被験者間で釣り合わせれば、**題材由来のアーティファクトは配置 A/B で向きが逆になり Fisher 統合で打ち消える**。
3. ★ **P014 型の再発リスク**（未対処）。同コホートには **9 press しかないセッション**が実在した。
   5 分の HI ブロックで 4 分読んで 1 文しか書かなければブロックの特徴量が退化する。しかも **HI で系統的に起きやすい**。
   除外すると HI4/LO4 の釣り合いが崩れ **C(8,4)=70 の前提ごと壊れる**。残すと分類器が
   「打ったか/打たなかったか」＝実質は読解時間を分離する。
   → 現行の除外規則は「**技術的なログ欠損のみ**」なので、**9 press はそのまま残る**。ルールが要る。
4. ★ **生態学的妥当性の限界が事前登録に書かれていない。** 「実験者が作った対比を分離できた」は
   「実作業中の状態を分離できる」を意味しない。G1 は**測定可能性の下限チェック**であることを明記する。
5. ★ **n=1 なら並べ替えは C(8,4)=70 を全数列挙できる**＝**厳密検定**（乱択不要・seed 依存なし）。
   positive control は C(10,2)=45。
6. ★★ **「なぜ論述なのか」の論理が事前登録に書かれていない**（研究者から指摘）。
   現行 §2.1 は「停滞が最も濃く出る／交絡が減り検出力が最大化される」としか書いておらず、
   **論述が代表的な作業だという主張と読まれかねない**。実際には逆で、
   ★ **論述は代表例ではなく「打鍵にとってのベストケース」**である:
   VibeCoding は「AI 操作主体で**連続打鍵が薄い**」（ADR-006 #3）、Creative は
   「**打鍵希薄で無音と idle が区別できない**・長い無打鍵が正常」（同 #3 / Adapter C）。
   → **打鍵が最も濃い土俵で決着をつける**ための選択であり、G1 は**最良条件での下限チェック**である。
   ⚠️ **被験者自身の証言と整合**: P011 は F4 で「純粋に記述し続けることはあまりない」と明記しており、
   **論述は実利用から遠い**。この事実は G1 の正当性を損なわない（代表性を主張していないため）が、
   **Phase2 以降のドメイン選択には直接効く**。
7. ★ **n=5 を再考する**（研究者から指摘）。n=5 は power 計算ではなく
   「Phase1 と同規模」という**慣例値**（`decisions.md` 判断 8）。G1 の主判定は**個人内**で
   C(8,4)=70 → **n=1 でも最小 p ≈ 0.014 < 0.05 に到達できる**。
   ★ **必要な n は結果の向きで変わる**——分離できたら「少なくとも 1 人で可能」で
   `✗/✗ → 軸を疑う` の分岐が消えるので少なくて足り、分離できなかったら
   「その人の特異体質」を排除できないので多く要る。**向きは事前に分からない。**
8. ★ **実施プロトコルが未設計**。`App.tsx` は `argumentative` ロック（凍結対象）なので
   **HI/LO ラベルをアプリ内に記録できない**。ブロックの切り方は
   (a) ブロックごとにアプリを起動し直し 1 ブロック＝1 セッション / (b) 通しで録り実験者の記録時刻でオフライン分割。
   **どちらもコード変更は不要**だが、**ラベル対応表の取り違え防止**を手順として決める必要がある。
