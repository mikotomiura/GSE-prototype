## やること

0. 研究者に 3 つ尋ねる（AskUserQuestion・日本語・推奨と理由を添える）:
   - 研究を実施してよいかを所属機関の規程で確かめたか（投稿先の規定とは別の確認事項。データの取得の開始条件にする。法的な要否は Claude が断定しない）。
   - 著者への問い合わせ（2026-10-12 に研究者が送った・`decisions.md` の記録）に返事が来たか（返事が来ない場合にどこまで進めるか・宛先不明で返ってきたか）。
   - G1・O1・研究者本人の記録（`experiments/20261011-g1-copy-self-trial/`）をこの論文に使うか（判断 1 で未決のまま残した。Claude の提案は「使わない」＝ADR-039 事実 1・D3 の審査の論点に入らない形）。
1. 事前登録の前の再検索（`/literature-review` の手順・前のカードの「やり残し」）: [V266] [V268] [V267] の被引用の追跡（OpenAlex）、作文研究の著者別（Leijten・Van Waes・Conijn・Tian・Crossley）、Kaggle の上位解法の discussion の一次（Chrome）。同じ研究が見つかったら判断 1 を研究者に戻す。
2. `/start-task` でタスクを作り、worktree を切る。設計で決めること（研究者に問う論点を先に列挙する・数値はデータを見る前に決める）:
   - 記録から区間を作る規則（英語: 空白・句読点の間の文字の打鍵数・BackSpace と貼り付けと移動の扱い）。
   - 加工の組（`q` のマスク・`@` のマスク・キーの種類への縮約・時刻の丸めの幅・長さを粗くする幅）と、各加工の後に残る情報の表。
   - 加工した列が、公開する他の列（イベントの数・`cursor_position`・`text_change`・`word_count` など）から再計算できないかの検査（削除・置換・貼り付け・移動を含む合成の記録で、公開予定の全列から長さを取り戻せないかを確かめる。完了時のレビューの指摘）。
   - 攻撃者: L・L_align に加え、時刻の攻撃を参照として並べる（[V266] の型を自前で実装する／[V267] の公開モデル（Zenodo records/17254163）を使うかは条件と GPU を確かめてから）。「加工が効く」とは書かず「この攻撃に対して」と書く。
   - 候補（おとり）: 同じ課題の別の作文（課題ごとに 1,136〜1,329 本）・N・k・偶然の水準の書き方（[V244] の書き方が先例）。
   - 有用性の側（作文研究の指標がどこまで残るか）を測るか。
   - 倫理の考察の節に書くこと（審査を受けていない理由・公開データであること・参加者を識別しないこと・著者への問い合わせ・所属機関の規程の確認）。
   - ENJA15 の節（判断 5）: 区間の規則（確定した文字列と `IMEtext`）・keyup が無いので評価できない加工・ライセンスの確認。正解を本文（訳文）で定義するか記録（訳者）で定義するか、同じ訳文が複数ある場合・同点・候補の数の扱い（本文の照合の成功と訳者の識別の成功は一致しない）。
   - IME の経路の検査: 未確定の文字列の更新・変換の取り消し・確定を含む記録で、加工の後のどの列（`IMEtext`・`Value` など）にも文字列が残らないことを確かめる（2 巡目のレビューの指摘・実装の前の設計の項目）。
   - PoPETs のオンライン発表や録画の提出の要否（採録論文の案内か PC chairs への問い合わせで確かめる）。
3. 事前登録の下書きの後、凍結の前に `attack-me`（stage `prereg`）を回す。

## 守ること

- 応答は日本語（AskUserQuestion の問い・選択肢も日本語）。★・⚠️ を多用しない。
- `/start-task` から始める。docs を先に読む。必須 Skill（`reproducibility-discipline`・`citation-ssot`・`verify-before-claiming`・`subagent-delegation`）を参照してから手を動かす。
- データの取得の開始条件はデータセットごとに分ける（判断 5 の取得の開始条件）。KLiCKe: 研究者が所属機関の規程を確かめた ＋ 著者への問い合わせの返事を見て研究者が進めると決めた。ENJA15: 研究者が所属機関の規程を確かめた ＋ ライセンスの種類と利用条件を一次で確かめた（ENJA15 の著者には問い合わせない）。2026-09-13 に確かめのために取得した `P01_T1.xml`（[P360]）の扱いは事前登録で決める。人口統計のファイルは使わない（判断 4 の問い合わせの下書きでの約束）。
- 打鍵の記録・本文を外部 LLM（Codex を含む）に送らない。Codex に渡すのはコードと文書の差分だけ。
- 有料の DB と有料の本文は使わない（[V266] の本文は無料の版が無い → 入手不可と書く）。
- 「新規」と書く前に、同じ語で既存のカードと references を全文検索する。
- `git add -A` や `git add <dir>` を使わず、ファイルを明示してステージする。並行セッションがあるので git worktree で作業する。
- 公開する論文の成果物（`papers/`）は学術的な英語で、GSE に言及しない。
- 完了時は `/cross-review` を 2 巡し、commit → push → PR → CI → merge → main の CI を確かめる。Codex の予算は、回す前に origin/main の台帳も見る。
