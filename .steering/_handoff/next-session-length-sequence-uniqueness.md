# 引き継ぎ: 公開テキストで「長さの並び」がどれだけ一意かを見積もる（ADR-039 D6 の関門の最初の実測）

作成 2026-10-09（Windows の機・`C:\GSE-prototype`）。新しいセッションで `/clear` の後に始める。
返答・記録では絵文字や記号（★・⚠️）を多用しない（研究者の指摘）。応答は日本語。

## 1. 何をするか

ADR-039 D6（公開前の関門）の攻撃のうち「照合」（公開した打鍵の記録を、候補の文章と突き合わせて、その文章を書いたときの記録かを当てる）について、
**長さの代理の並び**（記録に残る境界の間の打鍵の個数）が、公開テキストの中でどれだけ一意になるかを見積もる。最初は**句読点（、。）と改行の間の打鍵数だけ**を扱う（§3。文節・変換の Space の位置は使わない）。
人のデータは使わない。研究者が 2026-10-09 に「最初の一歩はこれ」と決めた（`.steering/20261009-release-deidentification-survey/decisions.md` 判断 7）。

分かるのは「長さだけを、正確に使える攻撃者」の場合の目安であって、照合の危険の上限ではない。時刻の癖や本人の過去の文章を使う照合は含まず、結果はコーパスと分け方に依存し、打鍵の個数は本文の長さと同じではない（判断 8・ADR-039 D6 の注）。結果を「上限」と書かない。

## 3. 始め方

1. `/start-task` から入る（CLAUDE.md）。作業記録は `.steering/<日付>-length-sequence-uniqueness/`、実験は `experiments/<日付>-length-sequence-uniqueness/`（`reproducibility-discipline` Skill: 乱数の種・依存の固定・コーパスの版の固定）。
2. 設計は研究者が 2026-10-09 に決めた（AskUserQuestion・`.steering/20261009-release-deidentification-survey/decisions.md` 判断 9）。この 4 点は聞き直さない:
   - コーパス: **青空文庫から始める**（本家 aozora.gr.jp・版は zip の SHA-256 で固定）。英語は後で足す。研究者や参加者の文章は使わない。注意: 文語体の小説が多く、参加者が書く文章（メール・レポート）とは文体が違う → 結果の限界として書く。
   - 「長さ」の定義: **句読点と改行の間の打鍵数から始める**。実装の注意: 記録の句読点（`SentencePunctuation`）は仮想キー 0xBC と 0xBE だけ（日本語入力では「、」「。」・`src-tauri/src/analysis/anonymize.rs` の `from_vk`）。「！」「？」「」」は境界にならない（Numeric や Punctuation に入る）。本文をかなに直し、かな → ローマ字の打鍵数に換算して、句読点（SentencePunctuation に当たるもの）と改行（Enter）の間の打鍵数の並びを作る。文節の区切り（変換の Space の位置）は使わない（書き手の変換の癖で変わり、テキストだけでは決まらないため）。**読みを取る道具は SudachiPy と SudachiDict-core（どちらも Apache-2.0）**を `experiments/` の実験の依存だけに入れ、読みだけに使う（研究者が 2026-10-09 に決めた・判断 9 の追記）。版は固定する。かなへの直し方（読みの取り方）とローマ字の換算表は、実装の前に作業記録に書く。
   - 指標: **(1) 長さを k 個並べたとき、コーパスの中で位置が一意に決まる割合（k の関数）と、(2) 候補の文章 N 本から正解を当てる照合の正答率を偶然の水準 1/N と並べたもの**の両方。(2) は ADR-039【決 6】の形（攻撃ごとに偶然の水準と区別できないことを合格とする）につながる。
   - 雑音: **理想の条件（推敲なし・打鍵数が正確）と、雑音ありの条件の両方**。雑音は、打鍵数のずれ・入力の揺れ（「ん」の nn など）・BackSpace の混入。雑音の大きさは、データ（結果）を見る前に決めて作業記録に書く。
   - k・N・雑音の大きさ: **合格の基準ではない実験の値として扱い、Claude が推奨と理由を添えて出し、研究者が結果を見る前に選ぶ**（研究者判断 2026-10-09・判断 10）。ADR-039【決 6】の数値（許す差・信頼の水準・本番の N）は、この実測では決めない。
   - 改行の扱い: 記録の Enter には、改行だけでなく IME の変換の確定も混ざる（`src-tauri/src/input/ime_compose.rs` の遷移表: 変換中の Enter は確定して終了）。**実装の前に、記録の項目（IME の状態など）から確定の Enter と改行を見分けられるかを、コードと仕様で確かめる**（NDJSON は読まない）。見分けられなければ、雑音の種類に入れる（研究者判断 2026-10-09・判断 10）。
   - 照合の偶然の水準 1/N の前提を固定する（Codex の指摘・判断 10）: 正解が必ず候補に入ること、候補の選び方（作品・長さ・抽出の窓）、同点の扱い、重複する作品や同じ並びが複数の候補に出る場合の扱いを、結果を見る前に作業記録に書く。採点の処理は、候補の大きさが不揃いな例と、同じ並びが複数の候補に出る例の合成データで、偶然の水準が出ることを先に確かめる。
   - まだ決まっていないこと（実装の中で出たら AskUserQuestion で推奨と理由を添えて聞く）: 作品の選び方と数、読みの誤りの扱い（SudachiPy の読みと青空文庫のルビが食い違うときにどちらを採るか）。
3. この実測は合否の判定ではなく、照合攻撃の試作（次の一歩）を設計するための見積もり。合格の基準（ADR-039【決 6】・同等性の判定）の数値は、本番の関門の設計で研究者が決める（Claude は出さない）。

## 4. してはいけないこと

- O1・G1・Phase1 の記録（NDJSON）を読まない・使わない。打鍵の記録や参加者の情報を外部の LLM（Codex を含む）に送らない（`data-privacy` Skill）。
- 研究者や参加者の書いた文章をコーパスにしない。
- 承認された SudachiPy と SudachiDict-core のほかに、新しい依存を承認なしに入れない。
- 見積もりを「照合の危険の上限」「安全の証明」と書かない。
