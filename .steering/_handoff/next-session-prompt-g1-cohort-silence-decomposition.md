## §2 ⚠️★★★ 最初にやること — **対象ログの行種を数える**

★ **これを解析より先に、必ず、最初に置く。**

```bash
# ★ 生 NDJSON は repo の外に置く（§6-5）
export GSE_G1_NDJSON=<G1 の生 NDJSON を置いたディレクトリ>   # ⚠️ repo 外
```

## §3 ⚠️★★ 実行前に知っておくべき実測（★ 期待値を下げておく）

| 実測 | 出所 |
|---|---|
| ⚠️ **ローカルの NDJSON 76 ファイル（P000 13 + Phase1 63）すべてで `hook_health` が 0 行** | ★ 2026-08-19 に直接計数 |
| ⚠️★★★ **G1 P010 は 10 ブロック中 9 ブロックで `hook_health` が 1 件も出ていない** | `experiments/20260801-controlled-friction-task/notes.md:1808` 逐語「★ **他の 9 ブロックは `hook_health` 行が 1 件も出ていない**（＝ 30 秒の閾値にすら一度も届いていない）」 |
| ⚠️ G1 は **確証標本 1/3 名**・**1 ブロック 5 分** | `controlled-friction-task/data.md:4` |

→ ⚠️★★★ **`C_write ≈ 0` になる可能性が高い。** 意味論上、
**沈黙のうち *入力を伴った累積時間* が 30 秒未満なら `hook_health` 行が出ない**からである（★ `step()` は入力ありの tick だけ加算する）。⚠️★★★ **60 秒の沈黙中に 25 秒マウスを動かしていても 0 行になる。**

→ ★ **その場合の扱いは事前登録で決めてある**（勝手に決めない）:

- ⚠️ 事前登録 **§9 の下限**（≥20 沈黙区間/人・≥30 分/セッション・n≥3）を満たさなければ
  → ★ **「Stage 0 では θ を出せなかった」と `results/` に記録し、`θ = θ_floor = 0.20` を使う。**
  ⚠️★★★ **下限を緩めない。**
- ⚠️★★★ **`C_write ≈ 0` を「打鍵タスクの沈黙はほとんど入力皆無だった」と読まない。**
  ★ **30 秒未満の入力エピソードが多数あっても同じく 0 になる**（＝ **左打ち切り**）。
  → ★ 報告は **「下界は X。上界は本計器では出せない」** の形にする（事前登録 §12-3b）。
  ⚠️ **「情報が無かった」とも書かない。**

## §4 ★ 実行手順

```bash

export GSE_PHASE1_NDJSON="$GSE_G1_NDJSON"   # ★ 入力を差し替えるだけ
bash run.sh
```

⚠️★★★ **「新規実装ゼロ」ではない（★ code-reviewer HIGH で訂正）。**

| 出す量 | 既存実装 | 新規実装 |
|---|---|---|
| 沈黙の 2 成分分解（`presence_ratio` 等） | ★ **あり**（`extract.py` / `describe.py`） | — |
| ★ **`C_write`（被覆率）と θ** | ⚠️ **無い** | ★ **要る**（事前登録 **§2.1** の `被覆率_L-a` を実装する） |

★ ただし **`被覆率_L-a` は既存の `presence_ratio` と同じ量**なので、
**新規実装は「集計して 1 つの比にする」層だけ**である（⚠️ 抽出は既存のまま）。
⚠️ **事前登録 §2.1 の式をそのまま実装すること。自分で定義し直さない。**

⚠️ `run.sh` は **自己検査 → 抽出 → manifest 照合 → L1/L2 → L3 → 漏洩検査**の順で走り、
**どこかで落ちたら結果を書かない**。

★ ⚠️ **`manifest_sha256` は Phase1 の既知値（`120e1a5e…`）と一致しない**（別コホートなので当然）。
→ ★ **G1 用の manifest を新しく記録する**。⚠️ **Phase1 の値に合わせようとしない。**
⚠️ **Phase1 の結果と G1 の結果を混ぜない**（別コホート・別条件）。

⚠️★★★ **`C_write` の算出は事前登録 §2.1（`被覆率_L-a`）に従う。**
★ **§2 の `[t−w, t+w]` 定義は *イベント型チャネル*（L-b/L-c）用であり、L-a には当てられない**
（`starved_ms` はイベント列ではなく**エピソードのピーク持続時間**である）。
⚠️ **定義を自分で作り直さない。**

⚠️★ **漏洩検査のスコープを足す**: `run.sh` が呼ぶ `leakcheck.py` の `--root` は
**前タスクの steering ディレクトリ**を指している。
→ ★ **新タスクの `.steering/[YYYYMMDD]-g1-silence-decomposition/` と
`experiments/20260819-nonkeystroke-silence-coverage/` を `--root` に足す**こと。
