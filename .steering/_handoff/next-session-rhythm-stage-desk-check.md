## 3. 検査で測りたいこと（案・設計で研究者と決める）

リアルタイムの写像（打鍵の F 系列 → 毎フレームの描画のパラメータ）が、次をどれだけ写すか:

1. **停滞**（EH1 と同じラベル・直近 300 s ほか）。相関だけでなく識別の検査（台帳 T1・親タスクの判断 5 の理由 2）。EH1 の検査器（攻撃者・陽性対照・神託）を使い回せるかを先に確かめる。
2. **打鍵の有無**（止まった瞬間と再開の瞬間に、動きの様子が変わるか）。調査 §1.1 の推論: リズムへの追従は、動きの「開始」に近い変化を本人の打鍵に合わせて作る。
3. **速さ**（打鍵の速さを量として読めるか・ADR-025 の「自分の量」。ステージへの適用は未決で `PS-Q8` の側・survey C8）。
4. **止まっている間の振る舞い**: 特徴量が据え置かれる間（`.steering/20261012-eh3-windows-device-rest/decisions.md` 判断 3）、描画をどうするか（据え置く・時間で減衰する・地へ戻る）。減衰させると「止まった時間」を写す（親タスクの判断 5 の代償 3 の型）。
5. 写像の候補を複数用意して比べる（例: 生の追従・強く平滑化・順序だけを使う・揺らぎを足す）。

6. **時間の解像度**: EH1 の型は秒ごとの F 系列を使うが、リアルタイムの描画は秒未満の打鍵の間隔を写しうる。描画の入力を秒ごとの集計に限るのか、秒未満を使うのかを先に決める。秒未満を使うなら、秒ごとの集計が同じで打鍵の間隔だけが違う列と、止まりと再開の境界を検査に足す（`/cross-review` 1 巡目・Codex の指摘）。
   - 秒未満を使う代償: ステージは画面の取り込みから外せない見込み（survey C6）なので、打鍵の間隔が画面共有・録画に映る。間隔の列は内容の推定に使われうる情報で、`data-privacy` の対象である（推論）。採るかは研究者が `data-privacy` と合わせて決める。
   - 道具の制約: EH1 の型（`gse-replay` → 秒ごとの F 系列）では秒未満の入力を作れない。秒未満を使うなら、合成の NDJSON の打鍵の時刻から直接写す別の道具が要る。

判定は項目ごとに分ける（`/cross-review` 2 巡目）: 打鍵のリズムへの追従は打鍵の有無と速さを写すことが目的なので、2・3 は「写らないこと」を合格にしない（写る量を記録する）。合否の形を取るのは 1（停滞を、打鍵の有無・速さを超えて識別できるか）だけで、その許容の値は結果の前に研究者と決める。

測らないこと:
- 作業中に注意を奪うか（`E-14`）は机上では測れない。
- 人が描画を状態計として読むか・描画を動かすために打鍵を変えるか（ゲーム化）も机上では測れない。机上の検査で言えるのは「描画から停滞・打鍵の有無・速さを識別できるか」までで、1 が合格しても台帳 T1 は閉じない。
- ゲーム化は自己申告だけでは見逃しうる（本人が自覚せずに打鍵を変える）。人の段では、表現あり／なしで打鍵の行動（速さ・間隔・止まり方）が変わるかを観察する検証を、T1 を閉じる条件に入れる（`/cross-review` 2 巡目・Codex の指摘）。
- 机上の検査の結果を見て、試作と二重課題の器・人に聞く段を起こすかを決める。

## 3.5 新規性を確かめる検索（机上の検査と並べて 1 ラウンド・研究者の指示 2026-10-12）

調査 S-RM（`.steering/20261012-portrait-rhythm-motion/survey-results.md` §1.1）は「背景の全面が動き続ける表示を作業中に評価した研究は 0 件・動く壁紙の査読論文も 0 件」としたが、angle ごとに数回の検索で網が粗い。研究の空白と主張する前に、`/literature-review` で 1 ラウンド回す。

- 主眼は**反証側**（既にあった、を探す側）を厚くすること。0 件のままなら「この範囲で見つからなかった」と範囲を書いて記録する。
- angle の候補:
  1. 動く壁紙・デスクトップの背景（animated / live / dynamic wallpaper・desktop background・screen background）の評価。
  2. 作業中の ambient visualization・peripheral display の連続アニメーションと主課題の代償（2000 年代の ambient display の評価研究を含む。Shen・Plaue & Stasko ほか、既登録の [P247] [P261] [P90] の引用網を辿る）。
  3. 本人の動き・打鍵・生体のリズムを写す背景や環境の表示（self-representation・biofeedback の ambient 表示・KeyStrokes（EuroVis 2007）の原文）。
  4. 持続運動と注意の基礎（Abrams & Christ 2003・Franconeri & Simons 2003 の原文。S-RM では二次の引用でしか読めていない）。
- 問いの切り分け: 「動く背景が作業を妨げるか」だけでは 2000 年代の ambient display の研究の延長に見られうる。GSE で問う価値が出やすいのは、(1) 本人の打鍵のリズムで動く、(2) それが状態計として読まれるか・打鍵を変えるか（ゲーム化）、(3) 作業中の注意の代償と再着手での出会いを分けて測る、の組み合わせである（2026-10-12 の研究者との会話での Claude の見立て・決定ではない）。検索の結果をこの 3 点ごとに当てる。
- 出典の登録はメインが直列（`citation-ssot`）。有料の本文は使わない。

## 4. 守ること

- 合成の列だけを使う。実在の人の打鍵・gse-dataset のログは使わない。キーストロークの内容・NDJSON の生ログを外部の LLM（Codex を含む）に送らない。
- `reproducibility-discipline`（`experiments/<YYYYMMDD>-<name>/`・SEED・`run.sh`・`HMM_VERSION` の刻印）。
- 実装（`src-tauri/` の描画やデスクトップの層の窓）はしない。描画の試作は別タスクで研究者の了承を得てから。
- この機械は G-GEAR（self-hosted の Windows CI の runner を兼ねる）。`gse-replay` は release の build が遅いので、debug 版を絶対パスで使う（memory: G-GEAR の release は遅い）。
