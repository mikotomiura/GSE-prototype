## §1 ⚠️★★ 【A】最優先 — 在宅の被験者が G1-M / G1-S に**たどり着けない**

### 何が起きているか（2026-08-08 実測）

★ **受付メール・`README_先に読む.txt`・`blockNN.html` のどれにも
G1-M / G1-S のリンクが 1 つも無い。**

- `protocol.md:711` の「G1-M / G1-S の回答 URL」は**研究者の持ち物リスト**（来所前提）
- `protocol.md:453` は「操作チェックは **§3 の用紙へ**」＝ **紙が既定**、
  フォームは「3.1b フォームで取る場合」という選択肢扱い
- ⚠️ ★ **無人在宅では紙が使えない。** 代わりの導線が用意されていない

→ ★ **在宅の被験者は 10 ブロック完走しても G1-M に 7 回とも答えられず、G1-S にも答えられない。**
`§2.6` の操作チェックが**データ 0 件**になる。
（実証: P009 の行が `G1-M 回答数(/7) = 0`）

### ★ 決めてあること（研究者判断 2026-08-08）

**受付メール 1 通に全部入れる。** 短縮 URL は**既にある**:

| | 短縮 URL | 使うタイミング |
|---|---|---|
| G1-M 強制比較 | `https://x.gd/X2T95` | ★ **ブロック 3〜9 の直後**（計 7 回） |
| G1-S 終了後アンケート | `https://x.gd/MgdXf` | 全 10 ブロックが終わったあと 1 回 |

⚠️ ★ **リンクを貼るだけでは足りない。** 研究者の指摘は
「**1 ブロックごとの記述フォームの説明や、フォーム全体の位置づけの説明が足りていない**」だった。
→ ★ **3 つのフォームの関係**（G1-C = 登録と同意 / G1-M = 各ブロック直後 / G1-S = 最後に 1 回）と、

## §6 ⚠️★★ 今日踏んだ落とし穴（★ 同じ失敗を繰り返さない）

1. ★ **タイムゾーン**: `git log --date=short` は JST。Drive のメタデータは UTC。
   ⚠️ 混ぜて比較して「デプロイが 1 日古い」と**誤診した**。→ ★ **UTC で揃えてから比べる。**
2. ★ **文字数の単位**: JS の `length` は **UTF-16 単位**、Python の `len()` は**コードポイント**。
   ⚠️ BMP 外の絵文字（`🧹📧📝` 等）1 個につき 1 ずれる。実際に 16 文字ぶん誤差が出て
   「デプロイ先が改変されている」と**誤診しかけた**。
3. ★★ **否定的テストは「落ちたこと」ではなく「狙った理由で落ちたこと」を見る。**
   `/Applications` ガードを丸ごと外しても selftest が緑だった
   （ガードが無くてもファイルが無いので別の理由で NG になっていた）。
4. ★ **ガードは壊して赤を見るまで信じない。** 今日この作法で 3 件の空回りを発見した。
5. ★ **`[ -f ]` ガードと件数チェック**が無い bash ループは、
   ファイルが開けないと**黙って「✓ 不変」と出す**（実際に踏んだ）。
6. ⚠️ ★ **「他が全部緑」は「被験者が完走できる」を意味しない。**
   機械検査・文書検査・zip 検査・Drive 照合・GAS がすべて緑でも、
   端から端まで 1 回通したら**全員が提出できない状態**だった（`SHARED_SECRET`）。
   → ★ **通しのリハーサルを、実物の配布経路で 1 回やる。**
7. ★ **`codesign --verify` の rc で Finder のダイアログを予測しない。**
   署名が valid でも quarantine ＋ 未公証なら「壊れているため開けません」が出る。
