## §2 ⚠️★★★ 絶対に守る制約（★ ここを外すと成果物が使えなくなる）

| # | 制約 | ⚠️ 理由 |
|---|---|---|
| 1 | ⚠️★★★ **アプリ識別子・ウィンドウタイトル・URL・full path・プロジェクト名を取得しない** | ★ `data-privacy` 禁止事項。⚠️ **[P117] が落ちた穴そのもの**（アプリ識別子→カテゴリ写像に依存して、なお base rate ≈0.5 に対し +0.07） |
| 2 | ⚠️ **ポインタは座標を捨て、量（移動距離・速度のバケット）だけ持つ** | ★ 座標列は画面内容の代理になりうる |
| 3 | ⚠️ **`src-tauri/` に触れない・`HMM_VERSION` を動かさない・ゴールデン/schema に触れない** | ★ G1 実施中（ADR-012 D7） |
| 4 | ★ **出力は Layer 2 `EventEnvelope` 互換にする** | ★ 後で本体へ **additive** に移植できるようにする（ADR-005） |
| 5 | ★ **計測器自身が `meta` に `capabilities` と `app_version` を刻む** | ⚠️★★★ **計器がコホートを跨げない失敗は既に 2 件**。★ 3 件目を計測器で作らない（ADR-013） |
| 6 | ⚠️ **観測と宣言を融合しない** | ★ 宣言は block 単位のラベルのみ。**「真の操作種別」を作らない**（ADR-010 D3 の写し） |
| 7 | ⚠️ **画面録画を計測器の機能にしない** | ★ 録画は**検証用サブサンプルのみ・研究者 PC の暗号化領域・コード化直後に破棄**（ADR-012 D12）。**計測器の責務ではない** |

## §3 ★ 実装の順序（★ 層を飛ばさない）

| 層 | 何を取るか | ★ いつ作るか |
|---|---|---|
| **L-a** | 「何らかの入力があった」の 2 値 | ★ **既存 `starved_ms` と同じ意味論**で作る（⚠️ Stage 0 と同じ土俵で読むため） |
| **L-b** | ポインタ移動量 / ボタン押下 / ホイール | ★ **モダリティが決まってから** |
| **L-c** | フォーカス遷移**回数**（⚠️ 識別子なし） | ★ **L-b で覆えないと実測で分かってから** |
| **L-d** | アプリ内の操作種別（プラグイン方式） | ⚠️ **本タスクの射程外**。★ L-c まで覆えないと分かってから別タスク |

⚠️★★★ **前の層で θ を超えたら次の層を作らない**（ADR-012 D4）。
★ 「あると便利そうだから全部」の反対側に「**実測で不要と分かったから作らない**」を置く。

## §5 ⚠️ 落とし穴（★ 実測）

1. ⚠️★★ **`Cargo.toml` は repo 直下に無い**（`src-tauri/`）
2. ⚠️★★ **Windows コンソールは cp932** → Python は `PYTHONUTF8=1`
3. ⚠️★★ **bash の heredoc は長い日本語で壊れる** → `Write` でファイルにしてから実行する
4. ⚠️★★★ **生ログを repo の中に置かない**（★ 2026-08-19 に security-checker が CRITICAL）
5. ★ CI は `push: [main, "feature/*"]`
6. ⚠️ **`analysis/` に OS API を直接呼ばない**という既存規約は**本体の話**。
   ★ 別計測器は別プロセスだが、⚠️ **同じ規律で書く**（後で移植するため）
