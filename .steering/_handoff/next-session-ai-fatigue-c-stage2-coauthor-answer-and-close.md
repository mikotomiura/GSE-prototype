## 2. やること（『最終…』まで書き終えた表から、この順）

1. 戻った表の控えを読み取り専用で取り、SHA-256 を記録する。判断 113 の控えと比べ、違いが『著者 2 の同意』『著者 2 のコメント』『最終…』の欄だけであることを確かめる（著者 1 の案が変わっていれば研究者に聞く）。
2. 全件を確かめる（`final_row` と同じ決まり）:
   - 『最終』が空・選び肢の外・「未判定」のまま、の記録が無い。「合意できない」ならほかの『最終…』は空。
   - 除外には理由、含めるには『最終の中心』、保留は E6 か理由なし、E5 なら相手の ID、E5 でないのに相手がある記録は無い。
   - 『著者 2 の同意』が空の記録が無い。同意したのに『最終…』が案と違う記録、同意しなかったのに『最終…』が案のまま（話した結果かもしれない）の記録を数え、あれば研究者に聞く。
   - 段 3 は『最終の中心』が中心-A・中心-B・合意できない のどれか。
3. Excel が閉じていること、DB が最後の版であることを SHA-256 で確かめ、DB の控えを読み取り専用で取る。『段2・3』の『最終』『最終の除外理由』『最終の中心』『同じ標本の相手（E5）』だけを写す（案と同意の欄は写さない）。S04-21・CS05713 の『同じ標本の相手（E5）』を消す（判断 103）。控えとの違いがその欄と行だけであること、入力規則・条件付き書式・固定・フィルタが同じことを確かめ、Drive に置いて API で大きさを確かめる。
4. 束ごとに `export-final --stage 2 --batch bNN` → 出た CSV（`screening/s2/bNN.final2.csv`）を名指しでコミット → 最後に push。止まりの文が名指しする記録があれば研究者に伝える。
5. `differences --stage 3 --batch bNN` の名指しが、表の『段3』と、段 2 で新しく含めた記録（2 人の中心が違う・一方にしか中心が無いもの）と合うかを確かめる → `export-final --stage 3 --batch bNN` → コミット → push。
6. 判断 114 以降に、表の SHA-256、写しの控えと照合、締めのコミット、同意・不同意・合意できないの件数を書く。値（どの記録を誰がどう判定したか）は書かない。
