## 2. いまの事実（2026-10-16 に確かめた・根拠つき）

- 小面（手跡の案 A）: 試作 `.steering/20261016-handmark-a-surface-spike/`（枝 `spike/handmark-a-surface`・worktree `/Users/johnd/GSE-prototype-handmark-a` は残す）。見た目は仮で、14 px の灰色の丸が打鍵ごとに白く光るだけ（`src/components/HandmarkSurface.tsx`）。遅れ・フォーカス・クリック透過・取り込みを測るためのもの。光る長さ・続けて打ったときの重なりは未決（親タスクの判断 12）。
- 取り込み: Mac では、会議の画面共有の既定（Chrome・Zoom の自動）では小面は写らず、標準のスクリーンショットと Zoom のフィルタリングなしでは写る（試作の `results.md` §2.1）。親タスクの判断 30 で、範囲を限って写るのを許した。理由の一つは「手跡は他人にも状態として読めないことを要件にしている」。
- 案 C（出会いの再生）: 文章だけ。小面にカーソルを乗せる・押すと、その回の形が打った順に数秒で描き直される。形・色・大きさ・時間の具体案は無い（親タスクの判断 13・`idea-section13.md`）。
- 案 D（手触りの写像）: 材料の定義だけ。全体の速さを割り引いた打鍵の間隔の比などを形に写す（仮説・判断 14）。描き方の案は無い。停滞と速さを写さないかは G-GEAR の机上の検査で測る（`next-session-tangibility-relative-timing-desk-check.md`・未着手）。
- EH3 の肖像の壁紙: 300 秒ごとの時計で更新し、直前 5 秒に打鍵があれば飛ばす（`src-tauri/src/analysis/portrait/schedule.rs`）。打鍵の最中に更新しない（肖6）。推定（p_stuck・招待）を受け取る口を作らない。Windows は `IDesktopWallpaper`、macOS は `NSWorkspace.setDesktopImageURL`。
- 介入（招待）: 右上の透明な always_on_top の窓に 40×40 の図像（`src/components/Overlay.tsx`・`InvitationGlyph.tsx`）。画面共有からは `set_content_protected` で外す設定。肖像（背景）と招待は分ける（親タスクの判断 2・16）。招待を背景で出さないと理由つきで決めた判断は見つからなかった。
- 背景の層で動き続ける表現は、2026-10-12 に一度検討し、研究者が「EH3 の後に回す」と決めた（`.steering/20261012-portrait-rhythm-motion/decisions.md` 判断 1・EH4 などの候補）。理由: (1) 作業中に背景の全面が動き続ける表示を評価した研究が 0 件で、近い証拠は「動きは無視しにくい」側（[P469] [P470]）。(2) 状態計として読まれるかに文献の答えが無い。(3) Windows では非公開の WorkerW に頼り、24H2 で Lively が作り直しを要した（[V284]）。(4) 取り込みからの除外の API はトップレベルの窓だけ（[V283]）。
- ADR-026 は、PC の画面の中の常時リアルタイムの表現（D21）を裁かず、撤回するかを未決（PS-Q8）にしている。ADR-025 は層 A に数値を添えない。
- Windows で、背景の層の表現の実現可能性を確かめるタスクは無い（2026-10-16 時点）。

## 3. 議論すること（順番は研究者と決める）

1. 小面の見た目と中身: 白く光るだけでよいか。何を返すか（一打ごとの反応・その回の形の断片・案 D の写像の一部など）、大きさ・位置・色・動きの長さ。手跡の 2 条件（本人には自分の手のものと分かる・本人にも他人にも状態としては読めない）に照らしてどうか。
2. 案 C と案 D の形: 何をどう描くか。EH3 の形の文法（F-1・`raw` / `lattice`）とどうつなぐか。
3. 背景の層で動く表現（研究者の案）: 何を動かすか、打鍵とどう結ぶか、作業の邪魔にならないか、状態計として読まれないか。判断 1（2026-10-12）を見直して前に出すか、EH4 の候補のままにするか。
4. 介入を背景で表すか: 背景を打鍵に合わせて変えるだけなら判断 2・16 の分け方に収まる。「行き詰まりの推定で背景を変える」と、分け方と ADR-026 PS-Q8 の見直しになる。どちらを考えているかを研究者に確かめる。
5. 必要なら、見本のページ（artifact）で動きを見比べる。合成の打鍵列だけで作る（研究者の打鍵を使うなら、そう決めてから）。
