## 1. 問い（なぜこれをやるか）

揺れの world `h(c)` では、L300 の `res=sub` の候補が赤になった。原因の切り分け（`experiments/20261015-rhythm-stage-speed-cause-split/notes.md`）で分かったことは次のとおり。

- A_speed の特徴を加法の非線形で使う基準（`lrbin`）でも、赤の多くは残る。
- c100 の `lr`・`lrbin` と c200 の `lrbin` では、`raw`・`jitter` の赤の上乗せは `r_absdiff`・`r_sd`（描画の `r` の揺れの大きさの量）に集まっていた。
- それでも、どちらの読みかは決まっていない。
  - 読み 1: 描画が、A_speed に無い停滞の手がかりを運んでいる。
  - 読み 2: A_speed の中の手がかりを、取り出しやすい形で運び直しているだけ。

揺れの world の速さの揺れは、2 つの成分の和である（揺れの world の design §1.3・`gen_sessions.py` の `Speed`）。

- z(τ) = c · δ · (u + d(⌊τ / 1000⌋))
- u ~ N(0, 1): セッションごとの倍率。
- d: 時定数 `tau_s` = 300 s の、定常な単位 OU の漂い（秒ごと）。

このタスクの問い（案・grill で確定する）:

- 赤（とくに `r_absdiff`・`r_sd` が運ぶ上乗せ）は、倍率の成分から来るのか、漂いの成分から来るのか。
  - 倍率だけの world: z = c · δ · u。セッションの中では速さが揺れない。
  - 漂いだけの world: z = c · δ · d(k)。セッションの間の倍率の差が無い。
- 見込み（推論・design に書く）: 倍率はセッションの中で一定なので、窓ごとの `r` の揺れの量にはほとんど入らない。漂いは秒ごとに変わるので、`r_absdiff`・`r_sd` に入りうる。漂いだけの world で赤が残り、倍率だけの world で消えるなら、赤は「漂いが窓の中で作る揺れ」と結びついていることになる。それが停滞の手がかりの運び直しなのか（読み 2）は、さらに次の問いになる。この見込みは Claude の推論で、確かめていない。

## 2. 設計で決めること（grill と design）

- world の数と段。
  - 例えば 2 つの world × 揺れの幅 c の段。前と同じ c100・c200 にするか、下見 0 で天井を見て決めるか。
  - 漂いだけの world で、u を抜いた分だけ揺れの総量が減る。総量をそろえるか（c を調整する）、成分を抜くだけにするかを決める。
- 本番の入れ物を、揺れの world と同じ（項目 1〜6・判定・検査器）にするか、原因の切り分けの読み（`lrbin`・`R2` を落とす）も最初から入れるか。
  - 後者にすると、1 回の本番で (a)・(b) の読みまで得られる。
  - その分、計器と selftest が大きくなる。
- 新しい world なので、第 1 回からの手順を踏む: design → `/cross-review` 2 巡 → 固定 → 下見 0 → 下見 1（λ）→ スモーク → 本番。
- 所要の目安: 揺れの world の本番は 1 段で 4.9〜5.3 時間（17567 s・19121 s・双子を含む）。ほかに下見 1 が 1 段で約 2.4 時間。原因の切り分けの本番は 1 段で約 1.7 時間。world と段の数に掛けて見積もり、研究者に示す。
- 計器は、揺れの world の `experiments/20261014-rhythm-stage-speed-confound-world/` から写して直す。
  - `gen_sessions.py` に `--world` の選択肢を 2 つ足すのが最小の変更。
  - 前のタスクの計器は書き換えない（写した先で直す）。
