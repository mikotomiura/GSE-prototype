## §3 ★ このセッションで閉じる問い（`.idea` §6）

1. ★★ **ドローンを α（常時）/ β（セッション後）/ γ（空間）のどれで作るか**
   → **β がリスクで支配的だが、主アウトカム（HIR）を失う**。
     研究の問いを「介入を減らせたか」に置くなら α、「作品として自己観察が起きたか」なら β。
2. **マッピングを M1（状態を 2 軸で写す）/ M2（介入の必要性を 1 次元で写す）のどちらにするか**
   → M1 は TSRI で測る問い、M2 は HIR で測る問い。**問いを先に選ばないと決まらない**。
3. **媒体の実体**（e-ink か画面内か）。⚠️ ハードウェア調達は依然スコープ外。
4. **表現層と Physical Anchor の統合評価**をどう設計するか（反芻の逆向き経路・単独評価では見えない）。
5. **試作の置き場所**——`experiments/` は `reproducibility-discipline` が重い。
   `.idea/prototypes/` かリポジトリ外か。⚠️ `.idea` は現状 git 管理外。

### ★ §3b Codex 第二意見で増えた問い（`decisions.md` **D12** に全文・採否付き）

6. ★★★ **状態を「複数の肯定可能な語彙」に分散するか**——密度・動き・荒さは
   **受け手が勝手に「悪い状態」と読む**（非評価的マッピングは統制できない）。
   ★ GSE は既に **Flow / Incubation / Stuck** の 3 状態を持ち、**Incubation は肯定的に読める**。
   [P45]「断定しない」の実装として `.idea` §2.6.2 より強い。
7. **提示頻度**を設計変数に加えるか——毎回 / 停滞が長引いたセッションのみ / 週次要約のみ。
   慣化対策は「段数 3 以内」だけでは弱い。
8. **提示タイミング**を条件化するか——**終了直後 vs 翌日開始前**。
   セッション後表現は**最後の印象や成果物の良し悪しで解釈が汚染される**。
9. **副次指標を先に決める**——`停滞後の復帰速度` / `休止後再開までの時間` / `翌日再開率`
   （★ 案 B で主アウトカム HIR を失う場合の代替。ADR-009 の person-period 形式に乗る）。
   ⚠️★★ **編集距離は使わない**（本文比較が必要で content-free 違反）。
10. 歩行を**表示入力に使わず分析用ログに限定する条件**を比較対象に入れるか——
    **二値でも「歩かなかった日」の意味づけが残る**（記録版の定義自体が監視感の源になりうる）。
