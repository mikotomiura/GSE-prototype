## §3 やり方（★ 2026-09-28・09-29 の実地で分かったこと）

- **判定の規則**は 09-28 の評価プロトコル v1.0（`.steering/20260928-ai-fatigue-db-appraisal/design.md`）を使う。中心-A / 中心-B の 2 段、除外理由 E1〜E6、「迷ったら含める」。★ 規則を変えるなら判断記録に逸脱として書く。
- **学術 API の癖**（件数は目安。PRISMA の件数ではない）:
  - OpenAlex の匿名検索は 2026-09-29 に 429（検索クラスタが高負荷）で途中から使えなかった。`Retry-After` を守っても解けなかった。
  - Europe PMC は既定の検索が本文まで拾って件数が膨らむ → `TITLE_ABS:` に限定する。
  - Semantic Scholar の一括検索は語の一致が粗い（`"AI fatigue"` でアスファルトの疲労、`Copilot` で副操縦士）→ 上位を必ず目で見てから件数を採る。
  - CiNii Research の OpenSearch は、空白を `+` で送ると 404 → `quote_via=urllib.parse.quote`。J-STAGE の API はそのまま使える。
  - 取得スクリプトの例: `.steering/20260929-ai-fatigue-db-readable-and-gaps/archive/evidence/*.py`（実行した版の記録）。
- **本文の入手**: ScienceDirect・Springer・IEEE はスクリプトを弾く。★ 研究者の許可があればブラウザで読む（`browser-verification` Skill を先に読む）。医中誌 Web・機関の購読は研究者のアクセスが要る → **[研究者]** として一覧にして渡す。
- ⚠️ **WebFetch の要約を経た「逐語」は逐語ではないことがある**（09-28 に AF005 の項目文で実際に起きた）。引用符で書く文言は HTML・PDF から直接取る。逐語の引用は 1 引用 40 語以内。
- **サブエージェント**: 抽出は Sonnet（model を明示）・判定はメイン。範囲・禁止事項・締切（10〜15 分）・「読んでいない範囲は読んでいないと書く」を必ず書く。入れ子にしない。戻ってきた主張は一次で裏取りしてから使う。
- **出すもの**: 新しいタスクの steering に `survey-S-xx.md`（検索記録・候補の表・判定案・限界）を 1 本ずつ。DB への追加・修正は**提案の表**にまとめる（DB の xlsx は変えない）。
- GSE の `docs/references.md` への登録・文献カードは、**GSE の文書で引くと決めたときだけ**行う（アイディア issue の採否の後）。
