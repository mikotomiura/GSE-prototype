# 次のセッション: 公開データでの照合の論文 —— 新規性と使えるデータセットの調査

作成 2026-10-11（`.steering/20261011-paper2-defer-dataset/decisions.md` 判断 1）。

## 背景（これだけ読めば始められる）

研究者は 2026-10-11 に、GSE で新しく集めて日本語 IME の打鍵の記録を出す論文を、共同研究者が見つかるまで見送った（所属大学で倫理審査を通せず、費用を出せない・ADR-039 D1 の 2026-10-11 の注）。次の候補は、新しい収集をしない論文である。本文の分かっている公開の打鍵データセットに、照合の攻撃（長さの並びで候補の文章から正解を当てる）と加工を当て、「公開された打鍵の記録から本文がどれだけ照合されうるか・どの加工が効くか」を測る。

材料はそろっている: `experiments/20261009-length-sequence-uniqueness/`（青空文庫での一意さ）・`experiments/20261009-matching-attack-prototype/`（合成入力での照合と加工）・`experiments/20261011-g1-copy-self-trial/`（人の記録での試し・区切りの乱れを許す攻撃 L_align）。

「2 本目の論文」は `_handoff/README.md` では EMSE の [P321] の論文を指すので、この候補は「公開データでの照合の論文」と呼ぶ。

## やること

1. `/start-task` でタスクを作る（例: `public-keystroke-matching-survey`）。`/literature-review` の手順で、探索はサブエージェント・`docs/references.md` への追記はメインで直列に行う（`citation-ssot` Skill）。
2. 調べること:
   - (a) 本文の分かっている公開の打鍵データセット。与えた文を打ち写すもの、自由に書いた本文つきのもの。日本語（IME を通したもの）があるか。利用条件（再解析・論文での利用・再配布の禁止）と、無料で取れるか。
   - (b) 先行研究: 打鍵の時刻や長さの並びから本文を照合・推定する研究。キーの種類だけに減らした記録での研究。公開前の加工（匿名化）の効き目を本文の照合で測った研究。2026-10-09 のサーヴェイ（`docs/literature/20261009-keystroke-release-reidentification.md`。カード 3 と #8・#10 のやり残し）の続きとして行う。
   - (c) 投稿先: 公開データの二次利用で倫理の承認が要るか（BRM [V237] ほか）。
3. 結論として、新規性の見立て（どこが新しく、どこが既知か）、使えるデータセットの表、研究者に尋ねる問い（進めるか・投稿先・G1 や本人の記録の結果を使うか）を出す。決定は研究者が行う。

## 守ること

- 応答は日本語。★・⚠️ を多用しない。AskUserQuestion は推奨と理由を添える。
- このタスクは調査まで。データセットを取って解析するのは、利用条件と、二次利用に倫理の承認が要るかを確かめ、研究者が進めると決めてから。
- 有料の DB と有料の本文は使わない。無料の版は OpenAlex などで確かめ、無ければ入手不可と書く。
- 打鍵の記録・NDJSON を外部 LLM に送らない。この調査では記録を開かない。
- `git add -A` や `git add <dir>` を使わず、ファイルを明示してステージする。並行セッションがあるので git worktree で作業する。
- 公開する論文の成果物（`papers/`）は学術的な英語で、GSE に言及しない。
- 「新規」と書く前に、同じ語で既存の文献カードと references を全文検索する（`verify-before-claiming`）。
- 完了時は `/cross-review` を 2 巡し、commit → push → PR → CI → merge → main の CI を確かめる。
