## やること

1. `/start-task` でタスクを作る（例: `public-keystroke-matching-judgement`）。worktree を切る。
2. 調べる（`/literature-review` の手順。探索はサブエージェントに model を明示して並列で投げ、`docs/references.md` への追記はメインで直列・`citation-ssot` Skill）:
   - (a) 本文の分かっている公開の打鍵データセット: 打ち写しか自由な作文か、言語（日本語・IME の有無）、規模、記録の中身（キーの識別子・時刻）、利用条件（再解析・論文での利用・再配布）、無料で取れるか。
   - (b) 先行研究: 打鍵の時刻や長さの並びから本文を照合・推定する研究、キーの種類だけに減らした記録での研究、公開前の加工（匿名化）の効き目を本文の照合で測った研究。2026-10-09 のサーヴェイの続きとして行う。
   - (c) 投稿先: 公開データの二次利用で倫理の承認が要るか（BRM [V237] ほか）。登壇なし・費用ゼロ（APC なし）の学術誌か。
3. 判定の材料を 1 枚にまとめる:
   - 新規性: どこが新しく、どこが既知か（文献で裏取りしたもの・カードの番号つき）。
   - 主張の対応表: ADR-039 で当初言いたかったこと（データセットの公開、日本語 IME、照合の危険、加工の効き目、関門の設計）のそれぞれを、道 2 で言えるか・言えないか・条件つきか。
   - 実行の見込み: 使えるデータセット、要る計算、IME 論文の材料（合成入力・実験のコード）をどこまで再利用できるか、おおよその作業量。
   - 危険: 倫理の承認が要る場合、データセットが見つからない場合、既に同じ研究がある場合。
4. 研究者に AskUserQuestion で判定してもらう。選択肢の例: 道 2 を IME 論文の次の論文にする／範囲を変えて採る（例: 英語のデータだけ）／採らない（別の候補を探す）。推奨と理由を必ず添える。
5. 判定を記録する（タスクの `decisions.md`、必要なら ADR-039 D1 の注）。採るなら、次のセッションの引き継ぎ（事前登録の設計）を作る。

## 守ること

- 応答は日本語。★・⚠️ を多用しない。
- このタスクは調査と判定まで。データセットを取って解析するのは、利用条件と、二次利用に倫理の承認が要るかを確かめ、研究者が進めると決めてから。
- 有料の DB と有料の本文は使わない。無料の版は OpenAlex などで確かめ、無ければ入手不可と書く。出版社のページが人間の確認で止まったら、Chrome でタブを開いて研究者に通してもらう。
- 打鍵の記録・NDJSON を外部 LLM に送らない。この調査では記録を開かない。
- 「新規」と書く前に、同じ語で既存の文献カードと references を全文検索する（`verify-before-claiming`）。
- `git add -A` や `git add <dir>` を使わず、ファイルを明示してステージする。並行セッションがあるので git worktree で作業する。
- 公開する論文の成果物（`papers/`）は学術的な英語で、GSE に言及しない。
- 完了時は `/cross-review` を 2 巡し、commit → push → PR → CI → merge → main の CI を確かめる。Codex の予算は、回す前に origin/main の台帳も見る。
