## §1 ★ やること（★ 4 つ。⚠️ 依存順に並べてある）

### A. ⚠️★★★ **O1/R3 モードのマーカーを作る**（★ ここだけ Opus で設計してよい）

- ⚠️ **現状 R3/O1 用のモードマーカーは存在しない**（★ 2026-08-25 に grep して 0 件）。
- ★ **`g1.rs` の 2 経路をそのまま写す**: 実行ファイルを包むフォルダのマーカーファイル ＋ 環境変数。
- ⚠️ **G1 と同時に立つことを許さない**（★ 相互排他をテストで固定する）。

### B. ★ **(B) 常時収集にする**（→ ADR-014 D6・ADR-016 判断 4b-0）

1. ⚠️★★★ **`session_active` の門を O1 モードで外す** —— `lib.rs:2713` の
   `if !session_active_for_thread.load(...) { while rx.try_recv().is_ok() {} ... }`。
   ★ **O1 モードでは門を通す**（⚠️ G1 / Phase1 の挙動は 1 バイトも変えない）。
2. ⚠️★★★ **稼働中インジケータの判定を `session_active` から切り離す** ——
   `tray.rs::measure_state` は `session_active == false` で逐語「**GSE — 停止中（記録していません）**」を出す。
   ★ **記録しているのに「記録していません」と出る**のは、⚠️ **同意文書 §4 の逐語と正面から矛盾する**。
   → ★ `recording::is_paused` ベースへ移す。⚠️ **`tray_labels_never_leak_cognitive_state` は緑のまま保つ**。
3. ⚠️ **`liveness.rs:93` の `!session_active` で `starved_ms` を 0 に落とす経路**を、O1 でどう扱うか決めて
   **テストで固定する**（★ 事前登録 §7 E1 が「実装 acceptance で確定させること」と書いている）。

### C. ★ **宣言 UI**（→ ADR-016 判断 4 / 4b-1 / 4b-2 / 4b-3）

- ★ **`App.tsx` の lock を O1 モードでのみ解除**（⚠️ **G1 は論述固定のまま**・ADR-014 判断 5）。
- ★ 選択肢は **既存 4 値**。ラベルは **「論述 / 通信文 / デザイン・映像・制作作業 / vibe coding」**。
  ⚠️ **新 enum 値を足さない**（★ schema 変更ゼロで済む設計になっている）。
- ★ 表示は **`RecordingControls.tsx`**（★ 3 点セットが既にここにある）に 1 行足す形:
  「**記録中 · 作業の種類: ○○**」。★ 未宣言は「**未設定**」と出す。
- ⚠️★★★ **未宣言のあいだ `session_meta` を書かない**（★ 行の**不在**で未宣言を表す = 判断 4b-3）。
- ★ **宣言の変更 1 回 = 1 アクションで 3 つ**: **`session_meta` 出力 → ログのローテート → `engine.reset()`**。
  - ⚠️ ローテートしないと **`gse-replay` が `Err`**（`replay.rs:1740` —— 1 ファイルに相異なる `task_kind` が 2 つ）。
  - ⚠️ reset しないと **新ファイル先頭 30 秒の `feat` 行が前ファイルの状態に依存**し、replay が本番を再現しない。
  - ★ `start_session` が既に 3 つともやっている。⚠️ **非 G1 はローテートしない**（`g1.rs:376` が `NotG1` を返す）
    ので、★ **`decide_start_action` に O1 の枝**を足す（⚠️ G1 のブロック数は数えない）。

### D. ★ **日次ローテート ＋ 48 時間後の自動提出**（→ ADR-014 D8 の上書き・判断 O1-2）

1. ★ **日次ローテート** —— ⚠️ `write_meta_end`（`session_end`）は **Rotate / BlockEnd（G1 限定）/ アプリ終了**
   でしか書かれない（`logger.rs:1865/1893/1935`）。★ **閉じないファイルは提出候補にならない**。
2. ★ **O1 用の「閉じた」述語** —— ⚠️ `is_closed_g1_session()` は `session_end` **かつ `g1_mode`** を要求する
   （`reconcile.rs:205-228`）ので、★ **O1 は構造的に拾われない**。
3. ⚠️★★★ **48 時間の猶予を実装する** —— ★ `delete_time_range` → `redact_dir` は
   **ローカルの `gse_*.ndjson` だけ**を書き換え `.age` は対象外（`redaction.rs:174-181`）。
   → ★ **猶予は「送信前なら被験者が消せる」を守るための機構である**（判断 3 の根拠 3）。
   ⚠️ **48 時間は恣意的な値**なので、**定数に理由をコメントで書く**。
