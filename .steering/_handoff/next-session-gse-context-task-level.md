# 次のセッション: 様式の並びから「作業」に名前を付ける（auto-context-segmentation の 2 段目）

## ここまで（2026-11-21・`.steering/20261121-auto-context-segmentation/`・枝 `feature/auto-context-segmentation`）

- `gse-replay --features` に文脈の量 `context` を足し、`experiments/20261121-auto-context-segmentation/` で、180 秒の窓を人ごとに混合ガウスでまとめて task-A などの名前を付けた。
- 本人の振り返り（11-19〜11-21）では、名前は「作業」ではなく作業の中の様式として合った（A: 日本語を打ちつつ行き来・B: 日本語で読みながら少し直す・C: 日本語を続けて打つ・E: マウス中心）。D（英字モード・入力少）は合わず、研究者は「違う PC などでタスクを行なってたかも」と答えた。
- 凍結した基準での判定は、本人が使えない（宣言との照合・状態の写し）、O1 の P006・P011・P013 が判定できない（宣言が 1 値）。宣言がほとんど変わらないので、照合の土台が弱い。

## 次にやること（案）

1. 2 段目の設計: 様式の名前の列を 30〜60 分の窓で数え（様式の割合）、その割合を人ごとにまとめて「作業」の名前にする。境界は様式の割合が変わったところ。
2. 照合の材料: 宣言はほとんど変わらないので、本人の振り返り（作業の名前を区間ごとに付ける）を主にする。基準は実データを見る前に凍結する（今回は凍結の後に 3 回直したので、合成の対照に宣言の経路も最初から入れる）。
3. 他の PC: 研究者は複数の PC を使う（G-GEAR・職場の PC）。他の PC の記録を同じ人としてつなぐか、この Mac の「外にいる時間」を様式の 1 つとして扱うかを決める。
4. アプリの識別子: 様式の段では要らなかった（外れた D は別の PC の問題で、識別子では分けられない）。作業の段で要るかを見積もる。取るなら data-privacy と ADR-012 D3 の改訂が要る。

## 注意

- 本人の記録は書き足され続けている。最終の数を出す前に入力の写しを取って固定する。
- O1 の提出物は時刻がファイルごとの相対 ms（`anonymize.rs`）。解析はファイル名の時刻の順に置き直している。
- P009 は研究者本人の O1 参加分（本人の記録と同じ）。数えない。
- 匿名化の取りこぼしは別の引き継ぎ（`next-session-gse-anonymize-recall-window.md`）。
