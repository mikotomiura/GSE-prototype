# 重要な設計判断

## 判断 1: ★★★ config が **1 件でも**止める（2026-09-21・研究者裁定 / grill）

- **決定**: ★ `--task` / `LOOP_TASK` / `LOOP_BASE_BRANCH` のいずれも無く、
  `.steering/*/_loop-config.json` が **1 件以上**あるなら **非 0 で止まる（fail-closed）**。
- **理由**: ⚠️★★★ **起票 23 の事故は config が 1 件の状態で起きた**（★ 実測）。
  → ★ 起票の文面は「**複数ヒット・不一致なら止める**」だが、⚠️ **それでは報告された事故そのものが直らない**。
  ★ 起票のもう 1 行「**`tail -1` で黙って選ばない**」を額面どおり取れば、**1 件でも黙って選ばない**が正しい。
- **却下案**:
  - ❌ **1 件なら使い、大きく警告する** —— ⚠️ 同じ事故が「警告つきで」再現する。
    ★ 無人モードC では**誰も警告を読まない**（＝ 起票 23 の 2 つ目の論点そのもの）。
  - ❌ **使われていない config を無視する**（`issues/` や `_loop-events.jsonl` の有無で判定）
    —— ⚠️ **「完了済み」の判定規則を新しく発明する**ことになり、
    ★ **その判定自体が黙って間違うクラスを新設する**。
- **代償（★ 受け入れた）**: ⚠️ モードA の人間は今後 `--task` を書く。
  ★ 緩和: die メッセージが**候補一覧**と**そのまま打てる 2 つの書き方**を出す。
  ★ かつ **config が 0 件なら従来どおり**なので、ad-hoc な worktree 生成は影響を受けない。

## 判断 2: 承認は **記録に残すだけ**（2026-09-21・研究者裁定 / grill）

- **決定**: ★ provenance ＋ **既定ブランチからの乖離コミット数**を **stderr** に出し、
  `loop-run.sh` が **run ログへ記録**する。⚠️ **確認プロンプトは置かない。**
- **理由**: ⚠️ 無人モードC は tty を持たないので、**プロンプトは「止まる」と同義**になる。
  ★ 承認は **`--task` を書いたこと自体**で成立していると見なす（＝ 判断 1 が承認の門である）。
- **却下案**:
  - ❌ **乖離が N コミット以上なら die** —— ⚠️ **N の閾値を決める必要**があり、
    ★ 正当な長期ブランチを誤って止めうる。
  - ❌ **tty があるときだけ y/N を聞く** —— ⚠️ 分岐が 2 つになり、
    ★ **回帰テストが tty を偽装する**必要が出て CI で flaky になりやすい。
- ★ **出力先を stdout ではなく stderr にした理由**: ⚠️ `--no-exec` の契約は
  「**stdout の最終行 = worktree の絶対パス**」で、`loop-run.sh` が `tail -1` で掴む。
  ★ 旧実装は base 行を **stdout** に出していたため、⚠️ `... 2>/dev/null | tail -1` が
  **パイプに吸わせて捨てていた**。★ `loop-worktree-deny.sh:37` 逐語「stdout は使わない」と同じ作法に揃えた。

## 判断 3: ★★★ **`jq` を捨てる**（2026-09-21・レビュー担当の判断）

- **決定**: ★ `resolve_base` から `jq` 依存を**外し**、`awk` の狭い抽出器 `json_top_value()` に置き換える。
- **背景（⚠️ 起票 23 には書かれていなかった 3 つ目の穴）**: 旧実装の逐語

  ```bash
  b="$(jq -r '.base_branch // empty' "$cfg" 2>/dev/null || true)"
  ```

  → ⚠️★★★ **jq 不在 / 壊れた JSON / 不正な値のどれでも `b` が空になり、黙って `main` へ落ちる。**
  ★ つまり **config を書いたのに pin が無言で消える** —— ⚠️ これは
  `loop-spawn.sh:49-52` の注記が警告する「**pin し忘れ → 全 issue 即死**」と**同じ帰結**である。
- **理由（★ 3 つ）**:
  1. ★ **CI の性質を壊さない** —— `ci.yml:651` 逐語「本テストは **jq を要らない**」。
     ⚠️ jq を残すと「pin が効く」ことのテストが jq を要求し、この性質が壊れる。
     ★ skip フラグで逃げる手は採らない（⚠️ memory「skip フラグの 3 状態テストが自己矛盾を隠した・**4 回再発**」）。
  2. ⚠️ **macOS の self-hosted runner に jq があるか未検証**である（★ `ci.yml` が deny gate を
     macOS に配線していない理由として**逐語で**書いている）。
     → ★ jq 依存のままでは **macOS のモードA で pin が無言で消える**（＝ 穴が OS ごとに違う顔で残る）。
  3. ★ 読む値は **git のブランチ名 1 つ**で、config は repo が `_template/loop-config.json` から
     生成する**機械可読なファイル**である。→ ★ 汎用 JSON パーサは要らない。
- **却下案**:
  - ❌ **jq を残し、不在なら die** —— ⚠️ 上記 1 と 2 が解けない。
  - ❌ **テストに jq の stub を置く** —— ⚠️ 「選択の正しさ」ではなく
    **stub の正しさ**を試すことになり、★ 実際の JSON 解釈を 1 つも検証しない。
  - ❌ **python で読む** —— ⚠️ Windows runner に python が見えるかは別問題
    （★ memory「Win runner tool PATH」）。
- ⚠️ **代償と、その閉じ方**: ★ 自作パーサは**汎用ではない**。
  → ★ **キー出現数 `n_key` と値の出現数 `n_val` を別に数えて 4 状態を区別**し、
  ⚠️ **想定外の形は必ず die** させる（★ 黙って fallback しない）:

  | `n_key` | `n_val` | 扱い |
  |---|---|---|
  | 0 | — | ★ キー無し → fallback（⚠️ 従来と同じ・die しない） |
  | 1 | 1 | ★ 値を採る（`null` なら fallback） |
  | 1 | 0 | ⚠️★★★ **die**（★ 数値 / 配列 / エスケープ入り = **読めない**） |
  | ≥2 | — | ⚠️★★★ **die**（★ 入れ子に同名キー。**推測で 1 つ選ばない**） |

### 6-3. ⚠️★★★ `security-checker` 固有の最も鋭い 2 件（★ 他系統は挙げなかった）
