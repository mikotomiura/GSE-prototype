# 設計 — 確認の進め方

## アプローチ

★ **配る実体そのものを確認対象にする。** dmg から `.app` を取り出して別途組むのではなく、
`make-common-app-zip.sh --tag v0.1.25` で **配布 zip を先に作り**、その zip を展開したものを
目視確認に使う。→ 【B】の成果物が【A】の被験対象になり、
「確認したものと配るものが違う」が構造的に起こらない。

## 目視をどう成立させたか (⚠️ 制約)

⚠️★ **エージェント側から画面を撮れない。** `screencapture` は
`could not create image from display` で失敗する (画面収録の権限が、セッションのホストである
Visual Studio Code に無い。付与には VS Code の再起動が要り、セッションが落ちる)。
★ 合成キー (`Command + Shift + 3`) も **システム側が受け付けない**ため撮影は代行できない。

→ **操作はエージェント (osascript / AX API)、撮影と目視は人**、という分担にした。
★ 撮影した PNG はデスクトップに落ち、**エージェントが `Read` で直接読む**ので、
貼り付けの往復が要らない。

## ⚠️★ 参加者 ID の取り違えを構造的に防ぐ

前セッションの事故 (手順書は `P999` なのに `P009` が入力された) を繰り返さないため、
★ **`開始する` を押す前に、AX API で入力欄の実体値を読み、`P999` でなければ中断する**
ようにした (目視の申告ではなく機械的な値で門を作る)。

```applescript
if idv is not "P999" then return "ABORT: 参加者 ID が P999 ではありません -> [" & idv & "]"
click (UI element 18 of wa)
```

## 検算の方針

⚠️★ **スクリプトの自己申告 (`✅` の出力) を根拠にしない。** zip の中身は
`unzip -Z1` で独立に数え、版番号は **バイト列で** 検索した。

★ 版文字列の検査では、最初 `strings -a | grep -c -F '0.1.25'` が **0 件**を返した。
これは **測定器の偽陰性**である (Windows の VERSIONINFO は UTF-16LE で、macOS の
`strings` に `-el` が無い)。→ ★ **必ず在るはずの文字列 (`gse-next`) を対照に取って**
測定器を検算し、Python のバイト列検索に切り替えて `0.1.25` × 2 / `0.1.24` × 0 を確認した
(memory `measurement-instrument-false-positives`)。
