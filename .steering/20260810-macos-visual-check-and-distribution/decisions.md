# 設計判断

## D-1: 配布 zip の共有範囲は `anyone: reader` のままにする

**判断** (研究者・2026-08-10): アプリの zip は **リンクを知っている全員が閲覧可**にする。
被験者にダウンロードさせるために必要であるため。

**踏まえていること**: ⚠️ zip の中の `g1-submit.json` には Apps Script の endpoint と
シークレット (33 文字) が平文で入っている。→ リンクが流出すると、第三者が提出先へ
偽のデータを投げられる。★ この性質を知った上で受け入れている。

**将来的に狭めるなら**: シークレットを zip から外し、初回同席時に研究者が配置する形にする
(設計変更が要る)。★ いま急ぐ話ではない。

---

## D-2: 確認対象は「配る実体そのもの」にする

dmg から別途 `.app` を取り出して確認キットを組むのではなく、
**先に配布 zip を作り、その zip を展開したもの**を目視確認に使った。
→ ★ 「確認したものと配るものが違う」が構造的に起こらない。

---

## D-3: 参加者 ID は目視でなく AX API の実体値で門にする

前セッションの事故 (手順書は `P999` なのに `P009` が入力された) を踏まえ、
`開始する` を押す前に入力欄の値を機械的に読み、`P999` でなければ中断するようにした。
★ 目視の申告を根拠にしない。

---

## D-4: 「ブロック未開始のセッションが提出される」欠陥は**今日直さない**

**判断**: v0.1.25 をそのまま配る。修正は別タスク。

**理由**: 直すと `packaging.rs` の条件とテストに手が入り、再ビルド → 再リリース →
再検証 → 再配布が必要になる。⚠️ 一方で **データは失われない** (本物のブロックは
block02 以降として全部届く)。

⚠️ ★ **運用で埋める**: 研究者は、**480 B 程度の極端に小さい `.age` を「ブロック未開始」
として読み飛ばす**こと。macOS 参加者は初回の権限付与で再起動するため、
ほぼ全員が余計な block01 を作る。詳細は `verification.md`。
