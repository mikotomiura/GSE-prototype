# macOS の上で手跡の表現を置ける場所の地図（2026-10-23）

議論（引き継ぎ §4）の前に、置ける場所と、それぞれの覆われ方・要るもの・根拠を並べる。設計の判断はしていない。

- 機械: Mac（macOS 27.0.1・画面 1470×956 の 1 枚）。SDK は CommandLineTools の MacOSX.sdk（ヘッダに macos(27.0) の記述あり）。
- 根拠の印: 〔ヘッダ〕SDK のヘッダの逐語 /〔文書〕developer.apple.com /〔実測〕本タスクの試作（`probe/`）/〔未確認〕確かめていない。
- 一次資料の調べはサブエージェント（Sonnet）に渡し、引用のうち CollectionBehavior・occlusionState・toggleFullScreen の行は私がヘッダで照合した。それ以外の引用は照合していない。

## 1. まず分かったこと（実測・2 回・各 1 回きり）

試作: 色のついた 60×60 のクリック透過の窓を、層と collectionBehavior を変えて画面中央に並べ、別のプロセス（`fsapp`）の窓を「画面いっぱいに広げる → 全画面（`toggleFullScreen`）→ 戻す」と動かし、0.5〜1 秒ごとに `occlusionState`（見えているか）と `CGWindowListCopyWindowInfo` の画面上の順位を書いた。画面は撮っていない。ソースと記録は `probe/`。

| 窓（層・振る舞い） | 普通の窓が覆う | 他アプリの全画面（試作が accessory のとき・1 回目） | 他アプリの全画面（試作が regular のとき・2 回目） |
|---|---|---|---|
| A デスクトップの層・今の作り（AllSpaces・Stationary・IgnoresCycle） | 隠れる | 全画面の Space に入るが、全画面の窓の下で隠れる | Space に入らない（画面上の一覧から消える） |
| B A ＋ FullScreenAuxiliary | 隠れる | A と同じ | 入らない |
| C 浮く層（floating・AllSpaces） | 見える | 全画面の上に見える | 入らない |
| D C ＋ FullScreenAuxiliary | 見える | 全画面の上に見える | 入らない |
| E status の層 ＋ Aux | 見える | 見える | 入らない |
| F screenSaver の層 ＋ Aux | 見える | 見える | 入らない |
| G 浮く層 ＋ CanJoinAllApplications（2 回目だけ） | 見える | （測っていない） | 入らない |
| H 浮く層・振る舞いなし（2 回目だけ） | 見える | （測っていない） | 入らない |

読めること:

1. **他アプリの全画面の Space に窓を出せるかは、層でも FullScreenAuxiliary でもなく、アプリの扱い（activation policy）で分かれた。** Dock に出ない扱い（accessory）だと AllSpaces の窓はどれも全画面の Space に入り、regular だとどの窓も入らなかった。CanJoinAllApplications も regular では効かなかった（ヘッダの逐語は「when eligible」で、条件は書かれていない）。
2. GSE は activation policy を設定していない（`spike/handmark-stage` の `src-tauri/` を grep して 0 件）ので regular である。**今の作りのまま全画面にすると、背景の窓は全画面の Space にそもそも居ない**（「下に隠れる」ではなく「居ない」）。
3. accessory にしても、デスクトップの層は全画面の窓の下になるので見えない。全画面の上に見せるには、浮く層以上に上げることになる（論点 3 の「前に出る」）。
4. **全画面でなくても、研究者のいつもの配置ではすでに隠れていた。** 測った時点で、画面中央の帯に層 0 の窓が 4 枚重なっていた（左右に並べた窓が画面の上端 33px から下端近くまでを覆う・`probe/run1-baseline-cover.txt`。アプリの名前は書いていない）。A・B は試作を動かす前から「見えていない」だった。課題は全画面だけではなく、窓を並べて画面を埋める使い方全般にある。

確かめていないこと（この節の限り）:

- 1 回ずつしか測っていない。素の実行ファイル（.app でない）で、全画面役も自前の小さな窓。普段使うアプリ（ブラウザ・エディタ）の全画面で同じかは見ていない。
- accessory にした GSE 本体が、トレイ・設定の窓・O1 の動きで困らないかは見ていない。背景の窓だけを別の小さなプロセス（accessory）に分ける手もある。
- 全画面の Space に入った窓が `occ` になったのは、全画面の窓が不透明で全面を覆うためと読んだ（順位が全画面の窓より後ろ）。
- Mission Control・デスクトップを表示・ステージマネージャの間の振る舞いは測っていない。
- 窓の一覧で他の窓の位置と名前が読めたのは、この端末が画面収録の許可を持っているため（`probe/perm-check.txt`: `screen_capture_preflight=true`）。許可のないアプリで何が読めるかは測っていない。

## 3. 論点（引き継ぎ §4）への効き方（事実の範囲で）

- 論点 1（覆われるのを性質と見るか）: §1 の 4 のとおり、いつもの配置で背景はほとんど見えていない。のぞく機会が少ない前提で考えることになる。
- 論点 2（境界に出す）: 窓の位置を読むには窓の一覧が要り、許可なしで読めるかが未確認。読めても ADR-040 の範囲（D1 はカーソル・クリック・ホイール）の外の新しい入力。
- 論点 3（前に出る）: 浮く層以上 ＋ accessory で全画面の上にも出せた。GSE 本体を accessory にするか、背景だけを別のプロセスにするかの選択が付いてくる。
- 論点 4（背景と小面の分担）: 切り替えの合図に `occlusionState`（10）が使える。他の窓の位置は読まない。
- 論点 5（見えないときに描くか）: 10 がそのまま使える。逐語が「見えない計算を止めて電力を節約」を勧めている。ただし「透明な窓は見えている扱いになることがある」とも書かれている（背景の窓は透明な部分が多い）。
- 論点 7（Windows）: macOS の地図ができたので、収集だけの依頼に回せる。

## 4. 下の縁の帯とどける操作の実測（判断 5 の試作・2026-10-25 まで）

試作: `probe/strip.swift`。accessory・浮く層・`canJoinAllSpaces` / `stationary` / `ignoresCycle` / `fullScreenAuxiliary`・クリック透過の、下の縁の 14 点の帯。線は合成の風で揺らし、打鍵は読まない。描画は 60 回/秒。1 秒ごとに、画面上にあるか・層 0 のどの窓より前か・`occlusionState`・自分の CPU（getrusage の差分・1 コア基準）・見えているアプリと隠れているアプリの数を書く。アプリの名前は書かない。画面は撮っていない。記録は `probe/run3`〜`run10`。

| 確かめたこと | 結果 | 根拠 |
|---|---|---|
| (1) 普段のアプリの全画面の上に帯が出るか | 出た。テキストエディットを AXFullScreen で全画面にした約 20 秒の間、onscreen=1・front=1・visible=1。切り替えのアニメーションの 1 秒だけ front=0。研究者も目で「見えた」 | 〔実測〕run7・run8（2 回）。ブラウザ・エディタの全画面は見ていない |
| (2) 帯の負荷 | 1 コアの約 9〜11%（60 回/秒）。全画面の有無で変わらない | 〔実測〕run3〜run10 |
| (3) どける操作が全画面の中で効くか | 測っていない（試し 3 は未実施） | — |
| (4) 見えていたアプリだけを戻せるか | 戻せた。隠す前 見えている 12・隠れている 1 → 戻した後 12・1。研究者が前から隠していたアプリは隠れたまま | 〔実測〕run9・run10 |

分かった癖:

- `NSRunningApplication.hide()` と `unhide()` の戻り値は、実際に隠れた・戻ったときも常に false だった。成否は `isHidden` を読み直して確かめることになる。
- 隠した後も見えているアプリが 2〜3 残った（run9 は 2、run10 は 3）。層 0 の窓は隠す前後とも 2 枚のままで、背景はどかせていない見込み。前面のアプリ（端末など）は外から `hide()` しても隠れないのではと見ている（推測）。直す候補として、先に自分を前面に出してから隠す `--activate-first` を足し、1 秒後に隠れずに残った数を書くようにした（ビルドのみ・未実行）。研究者の目で窓が残ったかは聞けていない。
- `full_size_layer0` は全画面の間も 0 だった。ノッチのある画面で全画面の窓が画面の高さより低いためと見ている（未確認）。全画面の判定に窓の大きさは使えない。

まだ確かめていないこと: (3) 全画面の中でどける。`--activate-first` で前面のアプリも隠れるか。帯が Dock（画面下端に出ているとき）と重なったときの見え方。描画の回数を下げたときの負荷と見え方。帯を本物の打鍵につないだときの負荷。
