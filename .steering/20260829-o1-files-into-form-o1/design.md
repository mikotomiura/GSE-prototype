## ⚠️★★★ `.gitignore` について（★ 実測して主張を訂正した）

★ 移す前に `.gitignore` の `Form_O1/` を **`Form_O1/Drive関連情報.md`** に変えた。

⚠️ ただし当初「そのまま移すとソースが git から消える」と書いたのは**言い過ぎ**だった。
★ 2026-08-29 に実測した挙動:

| 実験 | 結果 |
|---|---|
| A: 無視されたディレクトリに **新規**ファイルを `git add` | ⚠️ **拒否される**（`The following paths are ignored`）。★ `git add -A` は黙って飛ばす |
| B: **既に追跡されている**ファイルに `.gitignore` を足す | ★ **追跡は外れない**（→ `git mv` で移したものは残る） |

→ ★ 実際に危ないのは **(a) 無視されたまま新しい O1 ファイルを足す** ときと、
**(b) `git mv` ではなく素の `mv` ＋ `git add -A` で移す**ときである。
⚠️ どちらも**手元にはファイルがある**ので、`[ -f ... ]` 型の検査は**全部緑のまま通る**。

## ⚠️★★★ レビューで見つかった **秘密の露出寸前**（2026-08-29）

★ code-reviewer と security-checker が**独立に同じもの**を見つけた:

> `Form_O1/o1_submit.json` —— **実 endpoint（デプロイ ID 72 文字）＋ 実 secret（60 文字）**が
> ⚠️ **無視対象から外れており、`git add -A` の対象になっていた**。

★ 私の `.gitignore` 変更（ディレクトリ無視 → 手控え 1 本だけ無視）が原因である。
⚠️ 直後に研究者が受け口をデプロイして設定を置いたため、**網の外に落ちた**。

### ★ 実測で確かめたこと（⚠️ 推測ではない）

| 確認 | 結果 |
|---|---|
| index に入っていたか | ✅ **入っていない**（`git ls-files --error-unmatch` が rc≠0） |
| 履歴に入ったことがあるか | ✅ **無い**（`git log --all -S<secret>` / `-S<id>` とも **0 件**） |
| `git add -A` で入るか | ⚠️ **入る**（dry-run で `add 'Form_O1/o1_submit.json'`） |

→ ★ **漏れていない。コミット前に止めた。** ⚠️ したがって secret のローテートは不要である。

### ★ 直し方（deny-by-default へ）

⚠️ 「危ないものを列挙する」方式は**次に置かれる 1 本**を必ず取り逃がす。
→ ★ `Form_O1/*` を既定で無視し、**ソース 5 本を名前で通す**。

⚠️ 名前列挙は「`!` 行の足し忘れ」を生むので、★ ゲート側の追跡検査を
**ディスク走査**（`Form_O1/*.gs` / `*.cjs` / `*.sh` を全部照合）に変えて受け止める。
★ `!` 行を 1 本消すと**実際に赤くなる**ことを実測で確認した。

### ★ ゲートに検査を 1 本追加

「**提出設定（endpoint / secret）が git に入っていないか**」:

- (a) `[go]1[-_]submit*.json` が追跡されていないか
- (b) **実物の**デプロイ ID（40 文字以上）が追跡ファイルに無いか
  ⚠️ 閾値の根拠: 本 repo のプレースホルダ `DRYRUN_NOT_A_REAL_DEPLOYMENT` は **28 文字**、
  実物は 57〜72 文字（★ 2026-08-29 に実測して 40 で分離できることを確認）。

⚠️★★ **1 度目に書いた正規表現は `\.json$` で、literal のバックスラッシュを要求していた**
（= **絶対に発火しない**）。★ 実際に秘密入りファイルを追跡させて**赤にならないこと**で気づいた。
⚠️ これは同じ日に `tr -cd '\r'` で踏んだのと**同型の間違い**である
（★ 教訓: **生成した検査は必ず「陽性が赤になるか」を実物で撃って確かめる**）。

## ★ `--ack-filtered` を使った根拠（⚠️ 自動では付けない規則の記録）

★ `/cross-review` が `secrets-filter` で **exit 2（fail-closed）**になった。
⚠️ `run-codex-review.sh` は「人が差分の該当行を目で見て『実体のある機密は無い』と確認し、
その根拠を `.steering` に残した時だけ」`--ack-filtered` を付けてよいと定めている。

★ **トリガー行**（`check-o1-release-readiness.sh` の selftest）:

```
sed -i "s/^var MAX_BYTES/var SHARED_SECRET = 'abcdefghijklmnopqrstuvwxyz012345';\nvar MAX_BYTES/"
```

- ★ これは **ゲート自身が「秘密直書きを検知できるか」を試すために注入する偽の秘密**である
  （アルファベット順 26 文字 ＋ `012345`）。
- ⚠️ 今回の diff に出たのは、**パスが `Form_G1/` → `Form_O1/` に変わったから**であり、
  行そのものは以前から存在する。
- ★ **実シークレットは diff に含まれない**: `Form_O1/o1_submit.json` は**未追跡**なので
  `git diff` にも出ない（★ 実測で確認）。

→ ⚠️ **研究者判断 2026-08-29: 誤検知と確認したうえで `--ack-filtered` を付けて実行**。
