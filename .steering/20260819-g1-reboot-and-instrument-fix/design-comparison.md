## 設計案比較

### v1 の要旨

handoff §2 の記述を出発点に、変更対象を列挙して順に埋める形。G-1 は「`was_active` の枝で
`Rotate` を送る」まで到達したが、**失敗時に触った状態を巻き戻す**という既存パターンの延長で
書いており、⚠️ `engine.reset()` 等が `swap` より前にあるため**巻き戻せない副作用が残る**ことを
「未解決 (v2 で潰す)」と自認していた。`meta` 行に足すとゴールデンが壊れるかを「要確認」の
まま設計している。

### v2 の要旨

「設計の主題は機能追加ではなく**非回帰の証明経路**」と framing し直し、**設計前に 4 件を実測**して
不安を潰した (ゴールデンに `meta` は無い / 読み手は JSON パース / `Rotate` が既に閉じて開く /
`Cargo.toml` は粗い semver)。その結果 G-1 は **「触る前に断る」(guard-first)** ＝ 状態を
1 つも触る前にチャネル残量を検査して弾く形になり、巻き戻し問題が**消える**。分岐は純関数
`decide_start_action` に出して両 OS でテストする。加えて `validate_blocks.py` の既存検査を
**解析側からの独立ゲート**として acceptance に組み込む。

### 主要な差異

| 観点 | v1 | v2 |
|---|---|---|
| **アプローチ** | 変更対象を列挙して埋める | **先に実測で不安を潰し**、非回帰の証明経路から逆算する |
| **G-1 の失敗処理** | 触ってから**巻き戻す** (⚠️ `engine.reset()` は巻き戻せないと自認) | ★ **触る前に断る** (容量ガード) → 巻き戻し不要 |
| **分岐の表現** | `if` のネスト (lib.rs 内) | ★ 純関数 `decide_start_action` + 4 行の表 → **両 OS でテスト可** |
| **技術選定** | `meta` 行に追記 (⚠️ ゴールデン影響は「要確認」) | ★ 同じ (⚠️ ただし**実測で確認済み**)。別行案は却下として記録 |
| **変更規模** | 同等 (7 ファイル群) | 同等 + 純関数 2 個ぶん増える |
| **テスト戦略** | 8 本 (ADR-013 D3 中心) | ★ **12 本**。純関数テスト 3 本と、`validate_blocks.py --selftest` という**解析側の独立ゲート**を追加 |
| **リスク** | ⚠️ 失敗時に解析状態だけリセットされた中間状態が残りうる | ★ その状態が**構造的に発生しない**。残るリスクは `Disconnected` のみ (＝どの道記録不能) |

### 推奨案

**v2** — 理由:

1. ⚠️★★★ v1 が「未解決」と自認した点 (巻き戻せない副作用) を、**回避ではなく消去**している。
   要件の Stop 条件が「既存の意味論を動かすな」である以上、**中間状態を作らない**設計が正しい。
2. ★ v1 で「要確認」だった前提 (ゴールデン / 読み手 / `Rotate` の中身 / semver 粒度) を
   **設計前に 4 件とも実測**しており、`verify-before-claiming` の要求を満たしている。
   ⚠️ 実測の結果 **handoff §2 の「3 手順が要る」が不要**と判明し、変更面積がむしろ減った。
3. ★ `validate_blocks.py` の既存検査を独立ゲートに使う点は v1 に無い。
   **Rust のテストと解析側の検査が独立に同じ性質を主張する**形になり、
   「テストが無ければ ADR は失敗を防げない」(ADR-013 D3) の要求に対して二重化になる。

⚠️ v1 の要素で v2 に**引き継いだ**もの: 変更対象表 / `dropped_at_last_line` の分離 /
`continue` より前に窓集計を置く罠の指摘 / `th.log_after_ms` を直書きしないこと。
→ ★ これらは v1 固有の発見であり、v2 に取り込んである (ハイブリッドではなく**吸収済み**)。
