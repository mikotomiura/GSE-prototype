## 判断 E-1: D-5 は **(b) — void 規則を `test_can_reject_at_all` で分岐させる**

- **判断日**: 2026-08-02（研究者判断）
- **背景**: `§2.5` は「positive control ✗ → **G1 を無効とする**（計器故障の疑い）」と凍結していた。
  しかし前ラウンドの実測で、**計器が完全に健全（AUC=1.0）でも p<0.05 に到達できない被験者が実在する**
  ことが分かった（Phase1 実データの疑似ブロックで **4 例中 1 例**が
  `attainable_min_p = 0.067 > 0.05`）。⚠️ **n=1 では Fisher 統合による救済も無い。**
- **選択肢**:
  - (a) 現状維持（承知のうえで凍結）
  - **(b) `✗` を分岐**: `✗ かつ true` → **G1 無効**（不変）／`✗ かつ false` → **判定保留**
  - (c) positive control の特徴量を FS-A に減らす
- **採用**: ★ **(b)**
- **理由**:
  1. ★ **判定を緩めない。** `✗` の 2 枝は**どちらも `§3.3` の判定を読まない**。
     「分離できた」と言える経路は **1 本も増えていない**。
  2. ★ **分岐変数がラベル非依存**（帰無分布の形だけで決まる・`§5.2`）なので、
     **結果を見てから枝を選ぶことが構造的にできない**。実験者の自由度にならない。
  3. ★ **`§3.4` を触らずに済む。** 見る順序と停止挙動（不合格ならそこで止まり `§3.3` を読まない）は
     両枝で同一であり、`§2.5` が細分するのは**止まったあとの診断名と次の行動**だけである。
  4. (c) は `§3.2`（特徴量セット）に触れるため、凍結の趣旨に反する。
     (a) は「4 例中 1 例」という無視できない確率で**健全な計器を故障と誤診する**。
- **トレードオフ**: `✗ かつ false` の場合、G1 は「無効」でも「分離できない」でもなく
  **判定保留**という第 3 の状態で終わる。次の行動は
  **到達可能性を上げた設計（ブロック数を増やす等）での再実施**であり、追加コストが発生する。
- **影響範囲**: `preregistration.md` 第 3 版 §2.5 ／ `config.json` `positive_control.decision_rule` ／
  ★ **`analyze.py`（下記の訂正）**。
- ⚠️ ★ **訂正（`/cross-review` の指摘で判明）**: 当初「`analyze.py` の変更は不要」と書いたが**誤り**だった。
  `test_can_reject_at_all` は被験者ごとに出力されていたが、
  **コホート水準の結論文字列（`main()`）が `passed` だけで分岐しており**、
  `✗ かつ false` でも無条件に `"G1 IS VOID"` を出していた。**E-6 で修正した。**
- **見直しタイミング**: 確証データを 1 件でも取る前のみ。以後は事後改訂になる。

## 判断 E-2: `§3.7` に **`✗` の証拠力の前提条件**を追加する

- **判断日**: 2026-08-02（研究者判断）
- **背景**: 主判定（C(8,4)=70・FS-B）の**帰無分布 95 パーセンタイルが AUC ≈ 0.94** である。
  すなわち **p<0.05 に到達するには実質 AUC ≈ 1.0 が要る**（補助基準の 0.70 は全く拘束的でない）。
  設計は保守的（偽陽性を出さない）だが、**AUC 0.75–0.85 の「本物だが中程度」の効果は
  『分離できない』と報告される**。
  ⚠️ これは `§3.7` の「`✗` は**打鍵という計測手段への否定的証拠**であり**全ドメインに効く**」という
  強い解釈と正面から衝突する——**検出力不足で `✗` になったものを「世界の性質」と読むことになる**。
- **選択肢**: 補強する / 変更しない
- **採用**: ★ **補強する**
- **規約**: **`✗` かつ `test_can_reject_at_all = false` の被験者は、
  「打鍵という計測手段への否定的証拠」として数えない。**
  その被験者は `✗` ではなく **「判定に到達しなかった（検出力不足）」**と報告する。
- **理由**:
  1. その被験者では**分離が完全でも `✗` になる**。これは**世界の性質ではなく検定の性質**であり、
     「打鍵が最も濃い土俵で負けたのだから全ドメインに効く」という論証を支えない。
  2. ★ **判定を緩めていない。** これは `✗` から**何を主張してよいかを狭める**規約であり、
     `✓` を出しやすくするものではない。**`✓` 側は 1 文字も変えていない**
     （p<0.05 に到達したこと自体が、到達可能性があったことを含意する）。
  3. `§3.3` のしきい値も `§2.5` の合否も動かしていない。
- **トレードオフ**: n=1 でこれが起きると **G1 全体が「判定保留」**になり、
  軸を疑う行動（`personalization-and-online-learning.md §8.2 G1`）に接続しない。
  ★ **negative result を得るコストが上がる**。しかしそれは誠実な代価である。
- **影響範囲**: `preregistration.md` 第 3 版 §3.7 ／
  `config.json` `asymmetry_of_conclusions.negative_result_precondition_v3`。

## 判断 E-3: 本番用 8 題材 × 2 版を **パイロット P-1 より先に作る**

## 判断 E-5: 確証標本の n は **凍結しない**（`§2.4-1` の予定を維持する）

- **背景**: 引き継ぎは「n を本ラウンドで凍結する」ことを求めていたが、
  `preregistration.md §2.4-1`（凍結文書）は「**確証標本の n は、パイロット（§2.8）の結果を見てから凍結する**」
  と定めている。両者は `§2.4-2`（**確証データを 1 件も取る前に**凍結する）を共通の下限としている。
- **採用**: ★ **`§2.4-1` の予定どおり P-1 の後に凍結する**（`config.json` は
  `TO_BE_FROZEN_AFTER_PILOT` のまま）。
- **理由**:
  1. P-1 は**資料の量とブロック長を変えうる**（`§2.8` が許容）。それらは 1 人あたりの実施コストを変え、
     **現実的に集められる n を変える**。今決めると、その情報を捨てることになる。
  2. ★ **optional stopping のリスクは生じない。** 凍結は依然**確証データ 1 件目より前**である。
  3. 凍結文書が定めた手順を、引き継ぎメモの都合で前倒しする理由が無い。
- **代わりにやったこと**: ★ **凍結の手続きを `notes.md` に書き下した**
  （P-1 実施 → 値を `config.json` に記入 → **日付とコミットハッシュ**を `notes.md` に追記 →
  以後 `§2.4-4/5/6/7` により増減・補充・「有意になるまで足す」を禁止）。
  ⚠️ **時刻は記録しない**（本 repo は一時 public 化の運用がある）。
- ★ **n=1 を選ぶ場合の既知の限界**（研究者に提示済み・`notes.md` に記録）:
  被験者は研究者本人不可 / counterbalance が成立せず題材交絡を排除できない /
  Fisher 統合の救済が無い / **分離できなければ何も解決しない**。

## 判断 E-6: `analyze.py` の判定分岐を **`interpretability()` に切り出して §2.5 第 3 版を実装する**

- **判断日**: 2026-08-02（`/cross-review` の指摘 → 一次確認して採用）
- **背景**: ★ **文書だけ第 3 版に直して、実装が第 2 版のままだった。**
  `analyze.py` の `main()` は `pc_ok = all(p["passed"] for p in pcs)` だけで分岐し、
  `test_can_reject_at_all` を**一度も参照していなかった**。
  そのため `✗ かつ false`（判定保留であるべき場合）でも
  出力は無条件に **`"positive control FAILED: G1 IS VOID"`** になっていた。
  ⚠️ **第 3 版の改訂目的（健全な計器を故障と誤診しない）をそのまま無効化するバグ**である。
- **選択肢**:
  - A: `main()` の `elif` 連鎖に条件を足す
  - B: **判定順序と分岐を関数 `interpretability()` に切り出す**
- **採用**: **B**
- **理由**:
  1. ★ **テストできるようになる。** 旧構造は `main()` の中に埋まっており、
     `selftest()` は低レベル関数しか検証していなかった（だからバグが通った）。
     切り出せば `selftest()` から直接叩ける。
  2. `§3.4` の見る順序（操作チェック → positive control）と `§2.5` の分岐が
     **1 か所に集まる**ので、事前登録との対応を目で追える。
- **実装した規則**（`preregistration.md §2.5` そのまま）:

  | positive control | `test_can_reject_at_all` | `decision_status` | `interpretable` |
  |---|---|---|---|
  | ✓ | — | `INTERPRETABLE` | **true** |
  | ✗ | **true** | `G1_VOID` | false |
  | ✗ | **false** | `VERDICT_WITHHELD` | false |

  ★ 落ちた被験者が複数いる場合、**1 名でも `true` で落ちていれば `G1_VOID`**（保守側）。
- ★ **判定を緩めていないことの実装上の担保**: `selftest()` に
  「`✗` のどちらの枝でも `interpretable=False` になる」ことを**回帰テストとして固定した**。
  実装が将来ここを緩めたら selftest が赤になる。
- **併せて入れたもの**（`/cross-review` の Codex 指摘）:
  - 出力に **`preregistration_revision: 3`** と **`decision_status`**（値の意味の辞書つき）を追加。
    結果ファイルだけを見て「どの版の規則で判定されたか」が分かる。
  - `--out` 実行時、`interpretable=False` なら**理由を標準出力にも出す**。
- **影響範囲**: `analyze.py`（`interpretability()` 新設 / `main()` / `selftest()` / 出力 JSON）。
  ★ **判定基準は変えていない**（`§3.3` の 3 条件・`§2.5` の合否は不変。実装を文書に合わせただけ）。
