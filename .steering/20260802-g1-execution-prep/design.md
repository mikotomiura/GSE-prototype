# 設計 — G1 実施直前準備

## アプローチ

本ラウンドの成果物は **文書と課題文だけ**である（コード変更ゼロ）。
判断が要る 4 件を**先に研究者へ提示して確定させ**、確定した内容だけを文書に落とす。
⚠️ **推測で事前登録を書き換えない。**

### 順序（依存関係）

```
[判断] E-1 (D-5) ─┐
[判断] E-2 (§3.7) ─┼→ preregistration.md 第 3 版 → config.json 同期
[判断] E-3 (題材)  ─┼→ materials/topic02..08 × 2 版 → validate_materials.py --strict
[判断] E-4 (順序)  ─┘→ notes.md（n の凍結手続き・実施順序）
                      → run.sh GREEN 確認 → /cross-review
```

**E-1〜E-4 はすべて研究者判断であり、決まるまで文書に手を入れない。**

## 判定を緩めていないことの担保（第 2 版と同じ方式）

事前登録の信頼性は「**改訂が合格しやすくする方向を含まない**」ことで担保されている。
第 3 版でも同じ検査を通す:

1. **`✗` の 2 枝はどちらも `§3.3` の判定を読まない** → 「分離できた」と言える経路が **0 本増加**。
2. **分岐変数 `test_can_reject_at_all` はラベル非依存**（帰無分布の形だけで決まる）
   → **結果を見てから枝を選べない**（実験者の自由度にならない）。
3. **`§3.4`（見る順序と停止挙動）は不変** → 細分するのは「止まったあとの診断名と次の行動」だけ。
4. `§3.7` の追加は **`✗` の射程を狭める**方向のみ。**`✓` 側は 1 文字も変えない。**

## 課題文の設計方針（T-3）

- **手本は `topic01`**（LO = 施設の事実を並べた資料 1 本を指定の読み手向けに要約 /
  HI = **同じ問いに食い違う答え**を与える資料 3 本を統合）。
- **題材は市井の行政・学校・地域サービス**に限る（専門知識不要・感情を強く動かさない・実在団体を出さない）。
- **資料の総文字数**は題材内で **±5% 以内**（`validate_materials.py` が検査）に加え、
  **題材間もほぼ揃える**（結果は 451〜490 字）。題材間のばらつきはブロック間の読解量差になるため。
- ★ **HI の 3 本は必ず対立させる**（3 つの別々の話題を並べない）。
  典型形: ①賛成側の調査・要望 ②実施してみたら効果が薄かった事例 ③別の自治体で
  「効いたように見えるが実は別のことが起きていた」事例。**統合しないと 1 つの主張にならない**構造。
