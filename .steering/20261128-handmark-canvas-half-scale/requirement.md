# 手跡の帯と背景の canvas が半分の大きさで描かれる不具合の修正

## 背景

2026-11-28 01:19（JST）、本人の段 1 の後期（v0.1.42・11-26 01 時から起動したまま）で、研究者が「線が急に半分だけになった」と気づいた。画面を 1 枚撮って確かめたこと（画像は確かめた後に消した）:

- 下の縁の帯の線が、画面の左からちょうど 735 pt（主画面の幅 1470 pt の半分）で切れている。
- 帯の窓は層 4 で、2 枚の VS Code（層 0）より上にある（CGWindowList）。右の VS Code に隠されたのではない。
- 帯の窓も、その中の WebView（AX の AXScrollArea）も 1470×14 で全幅。
- 線が帯の高さの真ん中（帯の上端から 7 pt）ではなく、上の端の近くにある。

横も縦も半分なので、canvas の拡大（`ctx.setTransform(dpr, …)`・dpr = 2）が既定（単位行列）に戻ったまま描かれていると見る。今のコードは拡大を `resize` のときにしか設定しないので、何かの理由で文脈の状態がリセットされると、窓の大きさが変わるまで半分の大きさで描き続ける。リセットの理由（スリープ明け・GPU のプロセスの作り直しなどで WebKit が 2D の文脈を作り直すこと）は確かめていない（推測）。背景（`HandmarkStage.tsx`）も同じ作りなので、同じことが起きうる。

## ゴール

帯と背景の canvas が、文脈の状態のリセットや、届かなかった `resize` の後でも、次に描くときに正しい大きさと拡大へ戻ること。

## スコープ

### 含むもの
- `src/components/HandmarkEdgeStrip.tsx`・`src/components/HandmarkStage.tsx` の描く前の大きさと拡大の確かめ
- その判定を純関数にして node のテストで確かめる
- 直した版（タグ）を作り、本人の段 1 の配布のフォルダの gse-next を入れ替える（判断 6・研究者の指示 2026-11-28）

### 含まないもの
- Windows のアイコンの写しの層（`handmarkStageIcons.ts` のオフスクリーンの canvas・変換を使わない・Windows だけ）
- リセットの原因の特定（WebKit の内部）
- 描画の見た目・写像の変更（机上の道具 `pixels.mjs` の写像は変えない）

## 受け入れ条件

- [ ] 単位行列に戻った文脈・`width`/`height` がずれた canvas から、描く前の処理で正しい大きさと拡大に戻ることを node のテストで確かめる（変異で外すと赤になる）
- [ ] 大きさも拡大も合っているときは canvas の `width`/`height` を代入しない（代入は中身を消すので毎回はしない）ことをテストで確かめる
- [ ] `npm run test:handmark`・`npx tsc --noEmit` が緑
- [ ] 入れ替えた版で帯が全幅に描かれることを画面で見る（UI は画面を見るまで完了ではない）
