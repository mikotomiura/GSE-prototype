# Windows 実機の検証依頼 — キーボードフックの「静かな死」を検知できているか

**対象**: GSE_フック検証 の `gse-next.exe`（CI が作った本番バイナリ）
**所要**: 約 20 分（T-A〜T-C）＋ 任意で終日の T-D
**前提**: これは **G1 の本番実施ではない**。参加者 ID も提出も要らない。

---

## §0 ⚠️★ この検証が何を確かめるのか（読み飛ばさない）

2026-08-09、Windows 実機で **5 分間まったく打鍵の無いブロックが「正常」として自動提出された**。
原因は、アプリの「フックは生きている」判定が
★ **「設置に成功した」しか意味していなかった**ことである。
OS が低レベルフックを黙って外しても（silent unhook）、表示は「● 計測中」のままだった。

そこで **1 Hz の生存監視**を足した:

```
OS は入力を見ている（GetLastInputInfo の値が動いた）
      かつ
GSE のフックは 1 回も呼ばれていない        → ★ starvation として累積する
```

| 累積 | 何が起きる |
|---|---|
| **30 秒** | `gse-app.log` に ERROR が 1 回（画面は変わらない） |
| **120 秒** | トレイが `⚠ 計測できていません` ／ フックを 1 回だけ再設置 ／ NDJSON に `alive:false` |

⚠️★★ **OS に「フックを黙って外せ」と命令する手段は無い。** だから
★ **分解して確かめる**。特に **T-B は「既知の誤検知」をわざと起こして陽性対照にする**
（マウスだけ動かす＝OS は入力を見ているのにキーのフックは呼ばれない）。
これで **`GetLastInputInfo` が Windows で本当に動くのか**（★ 一度も実行していない）も同時に分かる。

---

## §1 準備

1. ZIP を展開し、`gse-next.exe` を **ダブルクリックで起動**する。
   - ⚠️ `g1.mode` は**入っていない**（意図的）。参加者 ID 欄は出ない。それで正しい。
2. 「開始する」を押す。
   - ⚠️★★ **これを押さないと検証にならない。** 生存監視は
     **計測中だけ** starvation を数える（止まっている間に数えたら全員が誤検知になるため）。
   - ⚠️ `g1.mode` が無いので **5 分で自動終了しない**。手動で終わるまで測り続ける。
3. ログの場所（★ 2 つとも後で使う）:

```
%USERPROFILE%\Documents\GSE-sessions\gse-app.log          ← アプリのログ
%USERPROFILE%\Documents\GSE-sessions\gse_YYYYMMDD_HHMMSS.ndjson  ← セッション記録
```

⚠️★ **NDJSON の中身を人に見せるときは「行の型と件数」だけにする。**
打鍵の内容（`vk`）は本文に貼らない（`data-privacy`）。

---

## §2 検査（★ この順で。T-B の直後に T-C を続ける）

### T-A 陰性対照 — 打ち続ける（2 分）

**やること**: 2 分間、**キーボードを打ち続ける**（何を打ってもよい。メモ帳等）。
途中で 10 秒以上手を止めない。

**見るもの**:

| 期待 | 確認方法 |
|---|---|
| `hook_health` 行が **1 行も出ない** | NDJSON を `hook_health` で検索して **0 件** |
| トレイが `● 計測中` のまま | トレイのアイコンにマウスを乗せて tooltip を読む |

⚠️★ ここが 0 件でなければ、**平常時に誤検知している**ということ。以降のテストより先に報告する。

---

### T-B ★ 陽性対照 — マウスだけ動かす（2 分）

**やること**: 2 分間、**キーボードに一切触れず**、マウスだけを動かし続ける
（円を描くように動かす。クリックはしてよい）。⚠️ ★ **途中で 1 打でもしたらやり直し。**

**見るもの**（★ 全部そろって合格）:

| 時点 | 期待 | 確認方法 |
|---|---|---|
| 約 30 秒 | `gse-app.log` に `keyboard hook may be dead` が **1 回** | ログを検索 |
| 約 120 秒 | トレイが **`⚠ 計測できていません`** に変わる | tooltip を読む（★ **見た瞬間にスクリーンショットを 1 枚**） |
| 約 120 秒 | `gse-app.log` に `keyboard hook is NOT delivering events` | ログを検索 |
| 約 120 秒 | NDJSON に `"alive":false` の `hook_health` 行 | 行をそのまま 1 行貼る（★ 打鍵内容は含まれない） |
| 同上 | その行の `"rehook":true` | 同上 |

⚠️★★ **30 秒でも 120 秒でも何も起きないなら、`GetLastInputInfo` が効いていない**
（＝生存監視そのものが Windows で空振り）。★ これは検知機構の全損なので、必ず報告する。

---

### T-C ★★ 復帰と二重フック — 直後に **20 打ちょうど**

**やること**: T-B の直後（トレイが `⚠` のまま）に、**キーを 20 回ちょうど**押す。
数えられるように、ゆっくり 1 秒に 1 打で打つ。

**見るもの**:

| 期待 | 確認方法 |
|---|---|
| トレイが `● 計測中` に戻る | tooltip |
| `hook_health` に `"alive":true` の行が出る | NDJSON |
| `gse-app.log` に `keyboard hook is delivering events again` | ログ |
| ★ 打鍵が記録されている | `"type":"key"` の行数を数える（★ **押下と解放で 2 倍前後になる**。0 でなければよい） |
| ⚠️★★ **同じ `t` の重複した `key` 行が無い** | 下のコマンドで **重複 0 件**であること |

⚠️★★ **ここが落ちたら、私たちの「復旧」が生きているフックを壊している**ということである
（再設置でフックが二重に掛かり、1 打が 2 回記録される）。
→ その場合は再設置機能そのものを止める判断をする。**最優先で報告してほしい。**

---

### T-D 自然発生（任意・終日）

`g1.mode` を入れずに GSE を起動したまま、**普通に一日作業する**。
2026-08-09 は 3 回中 2 回で本物のフック失効が起きている。

- 1 日の終わりに `gse-app.log` と NDJSON を送る。
- ★ 「何も起きなかった」も立派な結果である（★ ただし **T-A/T-B の結果とセットで**報告する）。

## §3 Windows 側で Claude Code に手伝ってもらう場合の依頼文

⚠️★ **Claude Code には「収集」だけを頼む。** 直させない（直すのは母艦側でやる）。
以下をそのまま貼ればよい。

```text
あなたは Windows 実機での「収集専任」です。★ コードの修正・原因の推測はしないでください。
以下を実行し、出力を**そのまま**（要約せずに）返してください。

0) まず、探す文字列が実在することを確認してから数えてください。
   ★「0 件」を報告するときは、必ず「陽性対照が非 0 だったこと」を添えてください。
   陽性対照が無い 0 件は、検査が空振りしただけかもしれません。

1) $L = "$env:USERPROFILE\Documents\GSE-sessions\gse-app.log"
   $N = 直近の gse_*.ndjson （更新時刻が最新のもの。フルパスを報告に含める）

2) gse-app.log から次の各語の**件数と該当行**を出す（行はそのまま貼る）:
   - "app log file opened"
   - "keyboard hook may be dead"                  ← 30 秒側
   - "keyboard hook is NOT delivering events"     ← 120 秒側
   - "keyboard hook is delivering events again"   ← 復帰
   - "tray state ->"                              ← 全部（遷移の並びを見たい）
   - "events were dropped"
   - "[applog]"

3) NDJSON から**行の型ごとの件数**だけを出す（★ 打鍵の内容は出さない）:
   Select-String -Path $N -Pattern '"type":"(\w+)"' | … で type ごとに数える

4) hook_health の行だけを**全文そのまま**貼る（この行に打鍵内容は含まれない）。

5) ★★ 同じ t を持つ "type":"key" の重複を数える:
   key 行の t を全部取り出し、同じ値が 2 回以上出るものの件数を報告する。
   ⚠️ 0 件が期待値。非 0 なら**その t を 3 つだけ**例示する。

6) 最後に、次の 3 つを**別々に**書いてください:
   - 実測でわかったこと
   - ★ 試していないこと
   - ⚠️ 依頼と食い違った点／うまくいかなかった点（★ 隠さない）
```
