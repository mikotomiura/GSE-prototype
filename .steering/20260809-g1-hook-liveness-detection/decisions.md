# 設計判断（grill 2026-08-09）

## D-1: 検知の厳しさ — **二段（ログ短め / トレイ長め）**

- **決定**: ログの `ERROR` は短い窓、トレイの `⚠ 計測できていません` は長い窓で出す。
  閾値は**定数ではなく引数**にして、純関数のテストで両方の境界を固定する。
- **理由**: `GetLastInputInfo()` は ★ **マウスも含む**ので、「マウスだけで考えている人」を
  誤検知しうる。★ 研究データの毀損（0 打が正常提出される）の方が重いので**見逃しを減らす**が、
  ⚠️ 被験者の目に入る警告は慎重に出す。
- **却下**: 単一窓 60 秒で両方（実装は小さいが、マウス中心の作業で被験者に警告が見えうる）／
  ログのみ（★ その場で誰も気づけない運用が残る）。

## D-2: 提出物への痕跡 — **新しい NDJSON 行型を刻む**

- **決定**: `.age` に入る NDJSON に、フックの生存状態を表す**新しい行型**を出す。
- **理由**: ★★ 今回の最大の問題は **「提出物だけを見ても 0 打の理由が分からない」**ことだった。
  行型があれば `analyze.py` / `validate_blocks.py` が**機械判定**できる。
- **確認済みの前提**: `validate_blocks.py:67` の `FORBIDDEN_LINE_TYPES` は
  **probe 3 種だけ**で、★ **許可リスト方式ではない** → 新しい型を足しても弾かれない。
- **コスト（受け入れる）**: `schema_dto.rs` の `LogEntryDto` に variant 追加 →
  `emit_schema` 再生成 → `schema/current.json` と byte-equal 検証 → gse-dataset との parity。
- **却下**: アプリログのみ（提出物から判別できないまま）／`feat` にフラグ追加
  （1 Hz 全行に付いてファイルが膨らみ、結局 schema 変更は要る）。

## D-3: 自動復旧 — **試みる（バックオフ付き）**

- **決定**: 検知したら **既存の「ループ先頭に戻って再設置」経路**を使って re-hook する。
  ★ 新しい復旧経路を書かない（経路を増やすと、どれか 1 つが静かに壊れる）。
- **理由**: ブロックの残り時間を救える可能性がある。★ 既存経路は `HOOK_ACTIVE=false` /
  `LAST_KEY_MS=0` のリセットと `WARN` ログまで**既に書いてある**（`hook_windows.rs:229-236`）。
- **却下**: 検知のみ（回帰リスクは最小だが、死んだブロックは 0 打のまま終わる）。
- ⚠️ **注意**: 再設置の間の数百 ms は取りこぼす。★ 連続再設置を防ぐバックオフを必ず入れる。

## D-4: macOS の扱い — **純関数は共用・配線は次タスク**（★ 私の判断）

- **決定**: 判定ロジックは **OS 非依存の純関数**として書き、Windows だけ配線する。
- **理由**: macOS には `CONSECUTIVE_TAP_FAILURES` による別の失効検知が既にあり
  （memory `macos-tap-idle-away-probe-bug`）、同時に触ると**どちらが効いたのか分からなくなる**。
  ★ macOS 側の情報源は `CGEventSourceSecondsSinceLastEventType` で、Windows とは別の実測が要る。

## ★ 実装中に**変わった**判断（レビューで潰れたもの・2026-08-09）

### D-1b: 再設置は「時間バックオフ」ではなく **1 エピソード 1 回**（⚠️ cross-review 両者一致 HIGH）

- **当初**: `Down` の間、60 秒ごとに再設置を試みる。
- ⚠️★★ **却下された理由**: 誤検知（マウスのみ / 読書中心）のあいだ、**生きているフックを
  60 秒おきに壊し続ける**。しかもそれが起きるのは**無打鍵で読んでいる時間**＝
  Incubation/Stuck 相当の、研究上いちばん重要な区間である。
  ★ 本当に死んでいるなら 1 回で直るか直らないかで、繰り返しても得るものが無い。
- **決定**: `rehook_done_this_episode` で 1 回に限定。★ 本物の復帰（`starved_ms == 0`）で解除。

### D-2b: 新しい行型は `gse-replay` にも足す（⚠️ HIGH・★ **私の断定が誤っていた**）

- ⚠️★★ 私は design.md に「`gse-replay` は未知 type を `continue` で読み飛ばす」と**書いた**が、
  **それは `--metrics` 経路だけ**だった。`run_replay`（`--snapshot`）は未知タグを `Err` で**中断する**。
- ★ **実測で確認**: `hook_health` を 1 行入れた fixture → `parse error at line 2:
  unknown variant 'hook_health'`。対照（元 fixture）は `OK: 15 snapshots match`。
- **決定**: `ReplayEvent::HookHealth`（読み飛ばし）を追加 ＋ 回帰テスト
  `hook_health_line_is_skipped_by_run_replay` を追加。★ serde タグを壊して**赤も実測**。
- ⚠️★ **教訓**: ゴールデン fixture は全部旧形式なので、**ゴールデンが緑でもこの事故は検出できない**。

### D-3b: 再設置の前に **必ず Unhook する**（⚠️ 両レビュー HIGH）

- ⚠️ 既存の再設置経路は `UnhookWindowsHookEx` / `UnhookWinEvent` を**一度も呼んでいなかった**。
  従来は「OS が既に外した後」しか走らなかったので露見しなかったが、
  ★ 生存監視は**生きているフックにも**再設置を起こすため、二重に積まれる。
  → 1 打鍵で `hook_callback` が 2 回 → **同一時刻の key 行が重複** → IKI≈0 が量産され特徴量が壊れる。
- **決定**: `unhook_all()` を追加し、脱出直後に必ず呼ぶ。既に外れていれば Err が返るだけで無害。

### D-3c: 起こし方は `WM_QUIT` ではなく **Atomic フラグ**（⚠️ security-checker MEDIUM）

- ⚠️ Windows のスレッド ID は**終了後に再利用される**。stale な ID へ `PostThreadMessageW(WM_QUIT)`
  を投げると、★ **他プロセスのスレッド**のメッセージループを畳みうる。
- **決定**: `REINSTALL_REQUESTED: AtomicBool` をフックスレッドの `PeekMessageW` ループが `swap` する。
  ★ 宛先の曖昧さが原理的に消え、既存経路を起こすという方針（D-3）はそのまま保てる。
  ⚠️ フラグは**インストール成功の直後**にクリアする（自然失効と競合した要求を持ち越さないため）。

### D-3d: 再設置で `LAST_KEY_MS` を **0 に戻さない**（⚠️ security-checker MEDIUM）

- ⚠️ 0 は `probe_scheduler::driver_idle_ms` から「離席」に見え、**次の打鍵までプローブが抑止される**
  （Phase1 で GATE2 を落とした形と同型）。★ macOS は既にリセットしない方針（F4・`hook_macos.rs:684/724`）。
  → Windows だけ古い挙動が残っていたので統一した。

### D-6: 被験者の画面（`get_hook_status`）は **変えない**。診断（`get_diagnostics`）にだけ出す

- ⚠️ 誤検知がある以上、被験者の画面にバナーを増やすと**盲検と介入規制**に触れる（D-5）。
- **決定**: `hook_starved` / `callback_count` は `get_diagnostics`（研究者向け）に出し、
  被験者側はトレイ表示までに留める。★ トレイの文言は既存の 3 状態から増やしていない。

## D-5: 事前登録・プロトコルとの関係（★ 触らない線を明示）

- ⚠️★★ **ブロックの自動やり直しはしない。** `protocol.md:1082` が
  「打鍵数が閾値を下回ったブロックを**その場でやり直さない**」（結果を見た後の介入になる）と
  明文で決めている。★ **検知と記録が上限**である。
- ⚠️★★ **被験者向けの新しい文言を増やさない。** トレイの 3 状態の文言は既存のものを使う。
- HMM の挙動は変えない → `HMM_VERSION` の bump は **しない**。ゴールデン回帰は byte-equal のまま。
