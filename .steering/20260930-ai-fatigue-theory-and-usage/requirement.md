# AI 疲労 文献 DB のサーヴェイ B 群: S-09 理論の節・S-11 語の用法

## 背景

- 判定者 1（研究者）が、DB 34 件と追加候補 225 件を判定している（`../20260930-ai-fatigue-candidates-appraisal/`・PR #273）。その間に Claude は B 群のサーヴェイを進める（引き継ぎ `.steering/_handoff/next-session-ai-fatigue-after-appraisal.md` §2）。
- 研究者の決定（2026-09-30・AskUserQuestion・すべて推奨どおり。`decisions.md` 判断 1）:
  1. 次の段は **S-09（理論の節）と S-11（語の用法）**。どちらも依存先（S-05・S-02）が済んでいて、N-05 の範囲の決定を待たずに始められる。S-01 は N-05 が先、S-06 も形式上は N-05 に依存する。
  2. タスク名は `ai-fatigue-theory-and-usage`。
  3. S-09 の範囲は **issue の 4 本（機会費用・補償的制御・能動／受動的疲労・自我消耗の再現性問題）＋ DB と候補の研究が依拠する枠組み**（JD-R・資源保存・テクノストレス など）。
  4. S-11 の対象は **DB 34 件と追加候補 225 件のうち、題名・抄録で AI に向けた疲労の語を使う記録すべて**（AI の見立て E1〜E3 で絞らない）と、サーヴェイで記録した用法の例。
  5. /reimagine は使わない。
- issue の定義（SSOT は `../20260929-ai-fatigue-db-readable-and-gaps/scripts/issues_data.py`）:
  - **S-09**: DB の『尺度・理論』は尺度の原著だけで、疲労が生じる仕組みの理論が無い。AF004 は自我消耗理論に依拠するが、事前登録の大規模な追試では効果がほぼ零から小さい。完了条件は「理論の節（出典つき）ができ、DB の『尺度・理論』に理論の文献が加わる」。
  - **S-11**: DB の文献は「AI 疲労」を少なくとも 3〜4 通りの意味で使う。サーベイ論文の定義を決めるには用法を分けておく必要がある。完了条件は「用法ごとの定義の表ができ、サーベイの定義文が決まる」。

## ゴール

1. **S-11**: 259 件の記録について、AI に向けた疲労の語（語形）を使う記録と、一般の構成概念の語だけで書く記録を、事前に固定した正規表現で数える。語を使う記録それぞれで、語に意味を与える文（定義・言い換え・構成要素）を抄録から（抄録に無く無料の本文があれば本文から）逐語で抜き出す。用法ごとの定義の表と、サーベイの定義文の案（複数）を作る。★ 定義文そのものは研究者が決める（Claude は案を出すまで）。
2. **S-09**: issue の 4 本の理論の原典が何を言うかを一次（抄録・無料の本文）で確かめ、259 件の記録が抄録で依拠する枠組みを事前に固定した正規表現で数え、件数の多い枠組みの原著を一次で確かめる。それらを材料に 1〜2 頁の理論の節の草稿と、DB の『尺度・理論』に足す理論の文献の提案を作る。

## スコープ

### 含むもの
- 259 件（判定者用ファイルの archive の写し・SHA-256 `6984472e…`）の抄録の取り直し（DOI で Europe PMC・Semantic Scholar・OpenAlex・Crossref。repo の外に置く）。
- 語形・枠組みの機械のふるい（正規表現は design.md に固定してから回す）と、その件数・記録の一覧（書誌だけ）を repo に置く。
- プロンプト疲れの概念分析（検索漏れ候補 No.128・129 の Zenodo の補足資料）の本体を辿る。
- 理論の原典・枠組みの原著の抄録（無料の本文があれば本文）を読む。
- サーヴェイごとに 3 つのファイル（事実・AI の判定案・GSE の含意）と `evidence/S-09`・`evidence/S-11`（スクリプトと書誌だけの結果）。事実のファイルは前タスクの検査器（`check_survey_files.py`）を通す。

### 含まないもの
- 判定そのもの・判定者用ファイルや評価版（xlsx）の作り直し・判定中のファイル（Downloads）への接触。
- 候補の追加（★ 語の用法の調べで DB と候補に無い一次研究が見つかったら、事実のファイルと `db-proposals` 相当の節に記録するまで。別の判定者用ファイルと評価版にするのは別タスク）。
- 元の DB（xlsx）の『尺度・理論』の書き換え（提案のファイルに書くまで。DB は研究者の成果物）。
- サーベイの定義文の決定（研究者が決める）。N-05（プロトコル）・S-01・S-06。
- GSE の文書（`docs/`）の書き換え・中央書誌（`docs/references.md`）への登録（GSE の文書が引くときに citation-ssot で登録する。`-gse.md` に候補として書くまで）。
- 著者への照会・フォームなど外部に出る操作。有料のデータベース・有料の本文。学術 API への研究者のメールアドレスの送信。本文・PDF・抄録の全文のコミット。
