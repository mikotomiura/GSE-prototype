## 実装アプローチ

「作った量」ではなく「**なぜその装置が要るか**」を書く。判断は次の 3 本に絞る。

| # | 装置 | 何を担保するか |
|---|---|---|
| 1 | **Replay-as-Truth** — ゴールデン NDJSON を CLI で再実行し `FeatSnapshot` 列の byte-equal で回帰を守る。推論を変えたら版数を上げてゴールデンを再生成する規約とセット | **後から結果を都合よく動かせない**。事前登録と同じ機能を果たす |
| 2 | **収集能力の自己記述 (ADR-013)** — 「信号が無かった」と「計器が無かった」を **0 行の意味として区別**する | Phase1 の原因分析 (§10.2) が成立した理由そのもの |
| 3 | **削除保証台帳** (`docs/o1-deletion-ledger.md`) | 同意文書が逐語で約束した「記録に残します」の実体 |

### なぜ §4 の直後で、§5 ではないか

§5 (腕前) に置くと自己 PR に読まれる。§4 (検証ワークフロー) の直後に置けば
「**この検証計画が実行可能である根拠**」として機能する。同じ内容でも機能が変わる。

### 文書の分担

- **詳細資料 §4**: 概要。250〜350 字。装置の名前と、それが担保するものだけ。
- **検証レポート**: 具体。到達点を「動いている / 未実装 / 未検証」で書き分ける。

## 実測で分かったこと (2026-09-04・本セッション)

**README のページ数表が古い。**

| 経路 | README の記載 | 本セッションの実測 |
|---|---|---|
| `--unescape --compact` → LibreOffice | 10.0 ページ | **15 ページ** |
| `--unescape` のみ → LibreOffice | 15 ページ | **22 ページ** |

注: この行は当初 **21** と書いていた。21 は**追記前**の本文での実測であり、
追記後は **22** である (fact-check が検出)。README には 22 を載せた。

原因: README の「10.0」は `df96d9e` 時点 (本文 15,460 字) の測定である。
その後 `b934bf3` で **19,958 字 (+29%)** へ伸びたが表を更新していない。

**併せて**、README は「現在コミットされている詳細資料 `.docx` は LibreOffice で開いて再保存されている」
と書いているが、`--compact` で再生成した `.docx` と**コミット済み `.docx` の md5 が一致した**。
この記述も現状と合わない。

注: 当初はここに具体的なハッシュ値を書いていたが、**本文を 1 文字足すたびに変わる**ので消した。
README にも書かない方針にした (→ `decisions.md` D4)。

→ **ページ規約 (10 ページ以内・逐語「審査対象外」) の判断は Google 側の実測だけを根拠にする。**
LibreOffice の数字は規約判定に使わない。**実測は 10 ページちょうどだった** (→ `decisions.md` D5)。
