# 設計判断の記録

## D1: 追記は §5（腕前）ではなく §4（検証ワークフロー）へ置いた

**決定**: 詳細資料への約 300 字は §4【検証ワークフロー】の直後に、
`**この計画が実行可能である根拠**:` という見出し語で挿入した。

**理由**: 同じ内容でも置き場所で機能が変わる。§5（腕前）に置くと自己 PR に読まれる。
§4 に置けば「この検証計画が実行可能である根拠」になる。
また §5 は「測定設計が成立しなかった実測を原因分析へ戻せること」を積み上げており、
そこに装置の自慢を足すと**その像を薄める**。

**却下案**: 新規に `## **【検証を支える仕掛け】**` という h2 を立てる。
→ 見出し 1 行ぶんページを食う。**規約 10 ページに余白がゼロ**（下記 D5）なので、
既存の `**開発場所・時間帯・時間数**:` と同じインライン太字の作法に合わせた。

## D2: 書くのは「設計判断」であって「数」ではない

**決定**: 「Rust テスト 637 個」「CI 6 ジョブ」「experiments 12 本」の類は**一切書かなかった**。
代わりに 4 つの設計判断を書いた。

| 何 | なぜ書く価値があるか |
|---|---|
| 事前登録の改訂ごとの「なぜ緩めでないか」記載義務 | 不変量が「合格を宣言できる経路の数が増えていないこと」であり、**後から基準を動かせない**ことの担保 |
| 判定の封印（`--unseal` は放棄印） | 操作が真に効いていても操作チェックは 18〜35% で落ちる。**そこで数値を見ると再実施しても確証的でなくなる** |
| 収集能力の自己記述（ADR-013） | 0 行の意味を「信号が無かった」「計器が無かった」「判定できない」に切り分ける。Phase1 の原因分析が成立した理由（★ 3 分岐に直した経緯は D7）|
| 自然作業に固有の再識別リスク | 統制実験（IME 論述）では読みまでしか戻らないが、自然作業（英数直接入力）ではほぼ 1:1 で復元可。**収集の形が変わるとリスクが変わる**実例（★ 表現の訂正は D7）|

**理由**: 未踏の審査は工数ではなく設計判断を見る。数を並べると
「よく作り込んでいる学生」になり、§5 の像を薄める（発注元プロンプトの明示指示）。

## D3: 内部呼称 `G1` は落として実体名にした（`(G1)` の併記もしない）

**決定**: 提出文書に残っていた裸の `G1` 3 箇所を実体名へ置換した。

|---|---|---|
| 検証レポート §7.2 見出し | `Phase A: 統制タスク実験（G1）` | `Phase A: 統制タスク実験` |
| 検証レポート §7.2 本文 | `G1 は GSE 本体が…` | `統制タスク実験は GSE 本体が…` |

検証レポート §10.4 が既に `Phase A（統制タスク実験）` と書いており、**その用法に揃えた**。

**却下案**: 初出で「統制実験（G1）」と併記する。→ 併記の対象が社内 ID なので、
審査員には「説明されていない略号」がひとつ増えるだけである。

## D4: README のページ数表が古かったので直した（スコープを少し広げた）

**決定**: 当初スコープ外だったが `docs/mitou_submission/README.md` を訂正した。

**理由**: README は運用の SSOT であり、**規約（10 ページ以内・逐語「審査対象外」）の
判断に直接使われる**。古い数字を残すと提出事故に直結する。

| 記述 | 旧 | 実測（2026-09-04） |
|---|---|---|
| `--compact` → LibreOffice | 10.0 ページ | **15 ページ** |
| `--unescape` のみ → LibreOffice | 15 ページ | **22 ページ** |
| コミット済み `.docx` | 「LibreOffice で開いて再保存されている」 | **`--compact` 生成物と byte 一致**（再保存されていない） |
| 「規約超過（約 0.7 ページ）」 | 未解決の課題として記載 | **取り下げ**（レンダラ非特定のレイアウト計算に依っていた） |

**原因**: 「10.0」は `df96d9e` 時点（本文 15,460 字）の値。その後 `b934bf3` で
**19,958 字（+29%）**へ伸びたが表を更新していなかった。

**併せて**: md5 の具体値は README に書かない方針にした。
**本文を 1 文字足すたびに変わり、古い値が残ると「一致しない」という偽の警告になる**ため
（実際、本タスク中に 1 度この罠を踏み、fact-check で検出された）。

## D5: ページ規約の判定は Google 側の実測だけを根拠にする

**決定**: LibreOffice の数字を規約判定に使わないと README に明記した。

**実測（2026-09-04・同一ファイル）**:

| 経路 | ページ数 |
|---|---|
| LibreOffice（`--compact`） | 15 |
| **Google ドキュメントへ変換** | **10** |
| Google Drive のプレビュー表示 | 8（2026-09-03・研究者確認） |

**理由**: 同じファイルが経路ごとに 8 / 10 / 15 と開く。換算は当てにならない
（2026-09-03 に「Drive 換算 9.1」と予測して実測 8 で外している）。

⚠️ **余白がゼロである。** Google ドキュメント変換で**ちょうど 10 ページ**。
規約は 10 ページ以内なので通るが、**1 行増えたら落ちる**。
本タスクの追記の**前後で両方測り、どちらも 10 ページ**だった
（追記前 17,964 字 / 追記後 18,270 字。追記はページ境界を跨いでいない）。

**測定手順を確立した**（README に記載）: `docs.google.com/document/u/0/` →
「ファイル選択ツールを開く」→「アップロード」→ 自動変換 → `Ctrl+Shift+C` にページ数が出る。

## D8: cross-review の HIGH 1 件は「2 種類の文字数の混同」だった

**決定**: README に**どちらの文字数か明示する注記**を足した。数値はどちらも正しかった。

**内容**: Claude と Codex が独立に「19,958 字と 17,964 字が食い違う」と指摘した。
実測すると**別のものを測っていた**:

| 何の文字数か | 追記前 | 追記後 |
|---|---|---|
| `.docx.md`（markdown 正本・記法を含む） | 19,958 | 20,270 |
| Google ドキュメント変換後の本文（記法を含まない） | 17,964 | 18,270 |

差の約 2,000 字は `**` や `|` などの markdown 記法ぶんであり、**両者とも追記ぶんは約 +300 字で一致する**。
→ **食い違いではなく、ラベルの欠落だった。** README に「どちらの数字か明示せずに書かない」と明記した。
