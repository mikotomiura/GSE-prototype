# Issue 007: `Q`（evidence quality — capability / missingness reason / logger・IME health / observability mask）
verify_level: recheck

## Goal

特徴行に `quality` を足し、**その行の証拠がどれだけ信頼できるか**を計器側の事実だけで記述する。

## Background

⚠️★★★ **`Q` は状態特徴ではない。**
★ `.idea/survey:194` 逐語「**欠測を 0 として入力せず、推論の抑制・abstention に使う**」。
★ `ADR-030 D10` の囲み逐語「`Q` は **`none` / `defer` へ退く根拠**であって、
**認知状態の説明変数ではない**」。

★ D10 の Tier 表での位置づけ: 「性能天井が低い以上（precision 0.57・偶然 +0.07 [P117] ／
外的再現は majority を超えず [V83]）、**退く根拠を先に持つこと自体が設計上の要請**」。

### ⚠️★★★ 欠測理由は **計器側の事実に限る**（★ `security-checker` MEDIUM 指摘・ADR-030 D10）

> ★ 入れてよいのは `capabilities` / `hook_health` / `dropped` のような **計器側の事実**だけである。
> ⚠️★★★ **被験者由来の停止・削除を理由カテゴリにしない。**
> ★ 理由: `gse-replay --metrics --json` の出力（`metrics.json`）は
> **`gse-dataset` の `metrics/P*/<os>/` へ共有される**。
> → ⚠️ 欠測理由に被験者由来が入ると、**端末内で完結すると約束した削除の事実と位置が、
> 研究者側の共有物に現れる。**

→ ★★★ **`recording_pause`（一時停止）と区間削除（redaction）を欠測理由のカテゴリにしない。**
⚠️ `schema_dto.rs` に `RecordingPause` 行型は在るが、**`quality` の理由として書き出さない。**

★ 参照すべき一次: `docs/o1-deletion-ledger.md`（★ 削除保証の台帳）／ `data-privacy` Skill。
