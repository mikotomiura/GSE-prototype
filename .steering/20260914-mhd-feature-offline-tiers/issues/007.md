> ⚠️★★★ **2026-09-15 に `recheck` から `parse` へ落とした**（★ `decisions.md` **判断 11**）。
> ★ 理由は `loop-run.sh:243-246` 自身の逐語「`recheck` の watchdog は現状まだ完全に信頼できる
> gate ではない。空応答を返すことがある」。
> ⚠️★★★ **data-privacy の門を下げたのではない** —— ★ 本 issue は merge 前に

## Goal

特徴行に `quality` を足し、**その行の証拠がどれだけ信頼できるか**を計器側の事実だけで記述する。

## Background

⚠️★★★ **`Q` は状態特徴ではない。**
★ `.idea/survey:194` 逐語「**欠測を 0 として入力せず、推論の抑制・abstention に使う**」。
★ `ADR-030 D10` の囲み逐語「`Q` は **`none` / `defer` へ退く根拠**であって、
**認知状態の説明変数ではない**」。

★ D10 の Tier 表での位置づけ: 「性能天井が低い以上（precision 0.57・偶然 +0.07 [P117] ／
外的再現は majority を超えず [V83]）、**退く根拠を先に持つこと自体が設計上の要請**」。

### ⚠️★★★ 欠測理由は **計器側の事実に限る**（★ `security-checker` MEDIUM 指摘・ADR-030 D10）

> ★ 入れてよいのは `capabilities` / `hook_health` / `dropped` のような **計器側の事実**だけである。
> ⚠️★★★ **被験者由来の停止・削除を理由カテゴリにしない。**
> ★ 理由: `gse-replay --metrics --json` の出力（`metrics.json`）は
> **`gse-dataset` の `metrics/P*/<os>/` へ共有される**。
> → ⚠️ 欠測理由に被験者由来が入ると、**端末内で完結すると約束した削除の事実と位置が、
> 研究者側の共有物に現れる。**

→ ★★★ **`recording_pause`（一時停止）と区間削除（redaction）を欠測理由のカテゴリにしない。**
⚠️ `schema_dto.rs` に `RecordingPause` 行型は在るが、**`quality` の理由として書き出さない。**

★ 参照すべき一次: `docs/o1-deletion-ledger.md`（★ 削除保証の台帳）／ `data-privacy` Skill。

### ★★★ 規範となる定義（★ 2026-09-18・`decisions.md` **判断 21** で裁定済み。⚠️ ここを勝手に変えない）

⚠️ ★ `ADR-030 D10` と `.idea/survey:192` は `Q` の 4 項目を**名前でしか**持っていない。
★ 本 issue は**新しい研究上の定義を作らず**、既存の SSOT を組み合わせて定める:
**ADR-013 D1 の判定表**（`capabilities` × 行数 → 結論）／**ADR-016 D4・ADR-029 D3 の除外規則**
（`hook_health{alive=false}` / `dropped_delta > 0`）／**issue 008 の観測区間**（`feat` 行の穴・原因を問わない）。

```text
tick k は区間 [t_k, t_k + ENGINE_TICK_MS) （★ FeatureRow.t_ms と同じグリッド）。

capabilities       : meta 行の capabilities を **そのまま**（★ 加工しない・並べ替えない）全行に載せる。
                     meta に capabilities が無ければ全行 null（⚠️ 空配列・空オブジェクトで埋めない）。

hook_health        : tick 内に t が入る hook_health 行の集約。1 本も無ければ null。
                     { alive: 全行の AND, starved_ms: 最大値, rehook: いずれかが true, dropped_delta: 合計 }
                     ⚠️ 累積の dropped は載せない（行をまたぐ量なので tick に割れない）。

observability_mask : { "feat": bool, "hook": bool | null }
                     feat = tick がある観測区間 [a, b] と交わる（t_k <= b かつ t_k + ENGINE_TICK_MS > a）。
                            ★ 観測区間は **issue 008 の stall_onset.rs::observed_intervals をそのまま使う**
                            （★ hole_gap_ms も StallOnsetConfig の値。⚠️ 独自に穴を判定しない）。
                            feat 行が 1 本も無ければ全行 false。
                     hook = t < t_k + ENGINE_TICK_MS を満たす最後の hook_health 行の alive（★ 状態の持ち越し）。
                            そういう行が無ければ null（★ ADR-013 D1: threshold_gated の 0 行は「判定不能」）。
                            ★ 持ち越す理由: hook_health は**状態が変わったときにしか出ない**（capabilities.rs の THRESHOLD_GATED doc）。

missing_reasons    : 次の 3 語だけから成る昇順・重複なしの配列（★ 許可リスト）。当てはまらなければ []。
                     "capability_undeclared" … meta に capabilities が無い（★ ADR-013 D1「計器の宣言が無い」）→ 全行
                     "hook_dead"             … observability_mask.hook == false、または tick 内に alive=false の行がある
                     "dropped_events"        … tick 内に dropped_delta > 0 の hook_health 行がある
```

- ⚠️★★★ **`feat` の穴は `missing_reasons` に入れない** —— ★ 穴の原因（削除・一時停止・計器欠損）は区別できず、
  区別してはいけない（ADR-030 D8 (b-2)）。★ **`observability_mask.feat = false` とだけ書く**（★ 理由を付けない）。
- ⚠️ `starved_ms > 0` は理由にしない —— ★ 打鍵が無いこと（利用者が手を止めた）と計器の不調を区別できないため。
- ★ `capabilities` の中身には `"recording_pause"` という**行種名**が入る（`capabilities.rs::unconditional`）。
  ⚠️ これは「このビルドはその行種を書ける」という**宣言**であって欠測理由ではない。★ `007-acceptance.sh` の
  被験者由来語の grep は **`capabilities` を除いた出力**に掛ける（★ 判断 21 で直した。旧検査は原理的に通らなかった）。

#### ⚠️★★★ 2026-09-18 改訂（★ `decisions.md` **判断 24**・レビュー 2 本の実測を受けて。⚠️ 上の定義より**こちらが優先**）

```text
hook の持ち越しを観測区間で切る（★ security-checker MEDIUM）:
  ★ feat 行を 1 本以上持つファイルでは:
     - observability_mask.feat == false の tick では observability_mask.hook = null（★ 見えていない間の状態を主張しない）
     - mask.feat が false → true に変わる tick（k >= 1）では、その tick の行を読む前に持ち越しを null に戻す
       （★ 穴の前の状態を穴の後へ持ち込まない。⚠️ 停止中にフックが死ぬと alive=false が NDJSON に出ない経路が実在する）
  ★ feat 行を 1 本も持たないファイルでは区間で切らない（★ 従来どおり。instrument_rich の正解表は変わらない）
  ★ 判定は feat 行の存在だけに依存する（★ 原因を区別しない・プライバシー中立）

dropped_delta の欠測を 0 で埋めない（★ code-reviewer M1・判断 14 と同じ規律）:
  hook_health.dropped_delta : tick 内の行がすべて dropped_delta を持つときだけ合計（★ 飽和加算）。1 本でも欠けていれば null
  "dropped_events"          : dropped_delta を持ち、かつ > 0 の行が tick 内にあるときだけ立つ

capabilities の形（★ security-checker LOW-3）:
  meta の capabilities が JSON オブジェクトでない、または直列化して 4096 バイトを超える → --features は Err（exit 1）
  （★ null に倒すと「宣言が無い」と誤報になるので倒さない。★ 上限は bin/replay.rs が所有する）
  出力は JSON 値として等価（⚠️ オブジェクトのキーは serde_json の既定で辞書順に正規化される。「並べ替えない」ではない）
```
