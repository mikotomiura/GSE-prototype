# Issue 001: `gse-replay --features` と `T0`（基本 activity）
verify_level: recheck

## Goal

`gse-replay --features <ndjson>` を新設し、**1 Hz tick 単位の特徴行**を JSON で出力する。
その行に `activity`（`T0` = 基本 activity）のフィールドが載っており、手計算と一致する。

## Background

⚠️★★★ **一次資料は `docs/adr/ADR-030-stall-onset-and-decision-episode.md` の D1 / D10 / D11。**

- **D1** 逐語「検出器は **オフライン側**に置く（⚠️ `features.rs` / `engine.rs` を触らない）」。
- **D10** の Tier 表で `T0` は「keys / delete / paste / mean IKI / 単純 pause / net production」。
  ⚠️ 併せて逐語「**平均打鍵間隔は課題間で安定＝判別に効かない** [P36]」——
  ★ **効くから作るのではなく、比較の土台（block ablation の基準）として作る**。
- **D11** で `T0` は **計器変更が不要**と実測されている（`key` 行が 1 打鍵ごとに `t` を持つ・`logger.rs:1634-1638`）。

### ★★★ pause 閾値の SSOT は **`features.rs::PAUSE_THRESHOLD_MS`**（★ 2026-09-15 改訂）

⚠️★★★ **初版は「`features.rs` の既存定数を参照する」と書いていたが、その定数は存在しなかった。**
★ 1 回目の実行（2026-09-14）はこれで **6 attempt 空振りして `abandoned` になった**。
→ ★ **`decisions.md` 判断 7** で裁定し、**本セッション側で命名済み**である:

```rust
// src-tauri/src/analysis/features.rs
pub const PAUSE_THRESHOLD_MS: u64 = 2_000;   // ★ F5 / F6 共通・「単純 pause」の SSOT
```

- ★ **使い方**: `use crate::analysis::features::PAUSE_THRESHOLD_MS;`
  （⚠️ **`features.rs` を変更するのではない。`use` するだけ**。★ Out 節は据え置き）。
- ⚠️★★★ **`2000` を直書きしない**（★ `001-acceptance.sh` が `feat_offline/` 配下の
  `2000` / `2_000` リテラルを検出して落とす）。
- ⚠️ 値が同じ `2000` でも **`features.rs:133`（F1 Flight Time のキャップ）/ `:281`（その飽和値）は別 knob** である。
  ★ `intervention.rs::SHORT_PAUSE_MIN_MS`（Nudge のバケット下限）も**転用しない**。

★ 本 issue は **最初の単独ウェーブ**である。⚠️ `bin/replay.rs` にモードを 1 本足すので、
**pin 済み verify の前提（ゴールデン replay）に触れる唯一の issue**でもある。

### ⚠️★★★ 命名の衝突に注意

★ ADR-030 は **`t0` を `stall onset` の時刻**の意味で使い、**`T0` を Tier 名**として使う。
→ ⚠️ **フィールド名に `t0` を使わない。** ★ Tier はブロック名で呼ぶ
（`.idea/survey §6.1` の呼称: `T0`=activity / `T1a`=分布 / `T1b`=境界 / `T1c`=revision topology /
`T1d`=restart / `Q`=evidence quality）。

### レビューで見つかり、修正した 3 件

1. ⚠️★★★ **AC 6 の実質違反**: `feat_offline/mod.rs` が `pub const TICK_MS: u64 = 1000;` を宣言していた

   → `use crate::analysis::loop_step::ENGINE_TICK_MS;` に置換。
   ⚠️ **acceptance の AC 6 検査が `activity.rs` しか見ていなかったので緑で通っていた**（★ 検査の穴を塞いだ）。
2. ⚠️★★★ **時刻スパンに比例した確保**: tick 数が入力サイズでなく時刻スパンに比例し、`MAX_SESSION_BYTES` で防げない。

   `minimal.ndjson:22` の paste が 1 件も数えられていなかった。→ `collect_all_paste_timestamps` を追加。
