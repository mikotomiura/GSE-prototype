# Issue 004: `T1c`（revision topology — delete run / rewrite / 再削除 / loop depth / 局所 recurrence）
verify_level: parse

## Goal

特徴行に `revision` を足し、**削除の走り・書き直し・再削除・ループの深さ・局所的な再帰**を載せる。

## Background

⚠️★★★ **`T1c` は「丸ごと計器変更が要る」ではない。**
★ `ADR-030 D11` の表（★ 2026-09-13 に `code-reviewer` の指摘で訂正された行）:

| 範囲 | 計器変更 |
|---|---|
| ★ **`T1c` のうち `delete run` / `rewrite` / `再削除` / `loop depth` / `局所 recurrence`** | ✅ **不要** —— ★★★ **`key` 行だけで今日作れる** |
| ⚠️ **`T1c` のうち `undo` / `redo` 往復だけ** | **要** |

→ ★★★ **本 issue は「不要」の 5 項目だけを作る。**

### ⚠️★★★ `undo` / `redo` を実装しない

★ 理由（D11 逐語）: 「**ADR-014 判断 6** で生 VK を `KeyCategory` へ量子化済みなので、
★ **`Ctrl+Z` と `Ctrl+A` が同じ（`modifier` ＋ `alphabetic`）になる**」。
⚠️ かつ D11 の囲み逐語「**これは *費用* の裁定ではない。*禁止* の再審である**」——
`T1c` の `undo`/`redo` を作るには **同意文書の再開封**が要る。

★ `ADR-032 D1` が「解く」と裁定したが、⚠️ **まだ Proposed であり、§Migration **M4**（同意 §3 の改訂）は
研究者承認待ち**である。→ ⚠️★★★ **本 issue では 1 バイトも触らない。**

⚠️ さらに `ADR-030 D10` の囲み: `.idea/criterion §2.1` を見て実装する人は
`undo`/`redo` を **`T2` に入れてしまう**（2 メモで帰属が食い違う）。★ 本 ADR は `survey` の `T1c` を採る。
