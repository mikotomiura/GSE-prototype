# Issue 006: `T1d`（restart — `t0` 後の生成/削除/移動・再停止時間・安定生成時間）
verify_level: parse

## Goal

特徴行に `restart` を足し、**`stall onset`（`t0`）の後**に何が起きたか
—— 生成 / 削除 / 移動、再び止まるまでの時間、安定して生成が続いた時間 —— を載せる。

## Background

### ★★★ 算出式（2026-09-19 確定・研究者判断）

★ 出典: `.steering/20260918-theory-critical-review/decisions.md` **判断 1 #5**（再停止 = 条件 A の辺）・**判断 2 #7 / #8**（研究者の回答）・
`definitions-restop-t1d-t1c.md` §3（算出式）・`docs/literature/20260919-resumption-restop-and-bout-segmentation.md`（S8 サーヴェイ）。
★ このタスク側の記録は `decisions.md` **判断 26**。
★ 「再開」「再停止」の定義は **EVAL-NCC の後続転帰と同じ 1 つ**である（★ 判断 25 #9 の「定義を 2 つにしない」）。

```text
条件 A    : ADR-030 D3 のまま（W・net_diff_min を再利用。★ 新しい定数ゼロ）
原点 o    : t0 + B（B = StallOnsetConfig::b_ms）
生成区間  : 条件 A が false である極大区間を [o, b] で切ったもの（★ 2026-09-20・V6 の裁定）
再開   r_k : k 番目の生成区間の開始時刻（★ o より前に始まっていれば o にクリップする）
             ⚠️ o の時点で条件 A が true なら、これは「o 以後で true → false に落ちる k 番目の時刻」と一致する
再停止 s'_k: その生成区間が閉じる時刻（条件 A が false → true に立ち上がる時刻。★ onset の s と同じ種類の辺）
⚠️ r / s' は ADR-030 D8 (b-2) の観測区間の中でだけ評価する（区間をまたがない。区間の右端に達したら打ち切り）
```

| ★ フィールド | 算出式 | 値が無いとき |
|---|---|---|
| `restop_ms` | `s'_1 − o` | `r_1` か `s'_1` が無い（打ち切り）→ **`null`** |
| `stable_generation_ms` | `s'_1 − r_1`（最初の再開から最初の再停止までの生成区間の長さ） | `r_1` か `s'_1` が無い → **`null`**（★ 打ち切りを値で埋めない） |
| ★ `stable_generation_net_presses`（**2026-09-19 追加**・判断 2 #7） | `[r_1, s'_1)` の純産出（挿入系 press − 削除系 press・`net_production` 共有ヘルパ） | `stable_generation_ms` が `null` なら **`null`** |
| ★ `resumption_count`（**2026-09-19 追加**・判断 2 #8） | 集計窓の中の再開 `r_k` の個数 | 窓があって再開が 0 回なら `0` |
| `post_t0_inserts` / `post_t0_deletes` / `post_t0_navigations` | 集計窓の中の press を ADR-030 D3 の写像で数えた回数（`navigation` は「どちらでもない」側の `navigation` カテゴリだけ） | 窓があって press が 0 件なら `0` |

- ★ **導出**: `r_1 − o = restop_ms − stable_generation_ms`（★ 2 フィールドから復元できるのでフィールドを足さない）。
- ★ **束ね方に依存しない量**: `restop_ms` / `stable_generation_ms` / `stable_generation_net_presses` は、**E1（連結）でも E2（分割）でも同じ値**になる。`r_1` と `s'_1` は観測区間の中の条件 A の辺だけで決まるためである。
  → ⚠️ **集計窓に依存するのは `post_t0_*` と `resumption_count` だけ**である（下記 V1）。
- ⚠️ **`stable_generation_ms` は打鍵速度と交絡する**（S8: burst 長は速い群 11.6 s ／ 遅い群 7.7 s [V164]、時間で測ると課題間で不安定 [V152]）。→ ★ 解析では `stable_generation_net_presses` と**必ず対で読む**。
- ⚠️ **新しい操作化である**。窓内の純産出で再開・再停止を定義した先例は S8 で **0 件**だった。→ `W` は事前宣言し、ablation で値を振る（ADR-030 D10）。
- ★ **E2 の併報**（判断 2 #8）: E1 で連結した結果と並べて、**E2（再立ち上がりごとに分割）で数えた `post_t0_*` / `resumption_count` を感度分析として併報する**（★ E1 は過剰結合の側へ誤りうる [V167]）。

### ⚠️★★★ 「pause 後」ではなく「`t0` 後」である

★ `ADR-030 D2` が **検出窓（`t0` 以前）と転帰窓（`t0` 以後）を分けた**のは、
`.idea/criterion:66` 逐語「**stall onset の検出窓と転帰判定窓を重ねない。**」を満たすためである。
→ ⚠️★★★ **`restart` は転帰側なので、必ず `t0` を原点にする。**
★ 単純 pause を原点にすると **検出窓と転帰窓が重なる**（＝ leakage）。

⚠️ さらに `ADR-030 D2` は **`t0` 直後の buffer `B`** を置いている。
→ ★ `B` の扱いを `stall_onset` の設定から引く（⚠️ 本 issue で値を決めない）。

### ⚠️ 「回復」と書かない

★ `docs/glossary.md` の禁止用語: 認知リソースの**消耗 / 回復 / 補充**は
**限定資源モデル（ego depletion）の語彙**であり、その枠組みは事前登録された検定で否定されている。
→ ★ フィールド名・コメントに `recovery` / `回復` を使わない。
⚠️ **例外は `打鍵再開 / typing_resumption`** で、これは「停滞エピソードからの自力での前進」の意味である。
