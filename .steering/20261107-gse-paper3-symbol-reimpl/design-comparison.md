## 設計案比較（/reimagine 1 回目・2026-11-07）

### v1 の要旨
純 Python で、生データから obs までを 1 本の離散時間の模擬として書き直す。照合は、手元の実データで feat 行の t・obs・ewma_x・ewma_y の bit を比べる。合成の selftest は少数の手作りの列で、期待値は replay の出力。

### v2 の要旨
適合器（データごと）・記号器（データに依らない）・定数の表（JSON）の 3 層に分け、層ごとに照らす。合成の押下の列を数百本作って元の実装の出力を「期待の痕跡」として固定し、公開 repo に置く。読者は元の実装なしで一致を確かめられる。補足資料 S2 の表は定数の表から生成する。

### 主要な差異
| 観点 | v1 | v2 |
|---|---|---|
| アプローチ | 1 本の模擬 | 3 層（適合器・記号器・定数の表）で、層ごとに照らす |
| 技術選定 | Python 標準ライブラリ | 同じ。定数は JSON |
| 変更規模 | 小（5 ファイル） | 中（適合の検査のデータとその生成の道具が増える） |
| テスト戦略 | 手作りの合成数本＋実データの照合 | 層 2 の単体＋合成数百本の適合の検査（公開）＋層ごとの実データの照合 |
| 読者の確かめ | 実データの一致の件数を信じるしかない | 合成の適合の検査を自分で回せる |
| 不一致の局所化 | 変換か模擬かを分けにくい | 層 1 と層 2 を別々に照らすので分かる |
| リスク | 合成が薄く、境界の取りこぼしを実データの照合まで見つけにくい | 期待の痕跡を作る道具（公開しない）が増える。合成の分布が実データの癖を覆わない（層 1 の実データの照合で補う） |

### 推奨案
v2 — 理由: 論文 3 の再現性の主張（読者が記号を作り直せる）を、実データの件数という自己申告ではなく、読者が回せる適合の検査で支えられる。層を分けると、不一致が出たときに変換と記号器のどちらかがすぐ分かる。増える規模は合成のデータと生成の道具だけで、記号器そのものは v1 と同じ大きさ。
