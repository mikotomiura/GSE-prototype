# 設計案比較（/reimagine 1 回目・2026-09-28）

- v1 = `design-v1.md`（初版に判断 10 の訂正 4 点・較正パイロット・BRM 規程を入れた版）
- v2 = `design.md`（`requirement.md` だけから再生成）

## v1 の要旨

- 正解 = 自作の参照入力欄が自プロセス内で受けた IME イベント（判断 2）。凍結前に較正パイロットで正解の定義を決める（判断 11）。
- 評価は**事象レベル**（1 変換ごとの検出 F1・`dwell_ms` 誤差・`abandon` κ・`nav` 一致）。OS ごとの母数の違いを 2 通りの正解で示す。
- 入力 = 青空文庫の句、キー間隔は公開分布からのサンプルと固定間隔の 2 条件。n = 200 / セル × シナリオ。
- E2 = 開集合の復元（文字誤り率 vs 事前分布）と閉集合の同定（K = 10/100/1000）。E3 = 観測部だけ再計測（判断 12）。

## v2 の要旨

- 評価を **L1 事象の一致 / L2 測度の一致 / L3 漏洩** の 3 層に分け、★ **L2（書字研究者が実際に使う集計量の一致）を主評価に格上げ**する。
- ★ **三者照合**: oracle（シナリオの意図）・正解（ホストが受けた IME の状態）・観測を同時に取り、oracle は**正解の検証だけ**に使う。正解ログは content-free。
- ★ **IME の学習・予測の状態をリセット・固定**する（試行の独立性）。★ 打鍵の速さを **3 水準の要因**にして精度曲線を出す。★ 実アプリでの**転移確認**を足す。
- E2 は攻撃者の知識を段で定義し、★ **シミュレーション攻撃**（候補文から予想ログを作って照合）と★ **特徴の除去実験**（公開粒度の推奨につなげる）。★ 現代文のコーパスを足す。
- ★ 解析の検査に**パラメータ回復テスト**（既知の誤りを注入して回復できるか）。論文に★ **研究者への推奨**の節を足す。

## 主要な差異

| 観点 | v1 | v2 |

| **評価の単位** | 事象（1 変換）だけ | ★ 事象 ＋ **測度（テキスト単位の集計量・ICC と Bland–Altman）** ＋ 漏洩 |
| **正解** | 参照入力欄（Windows は IMM / TSF の 2 経路を試す） | 同じ ＋ ★ **oracle で正解を検証**。★ 正解ログを content-free にする |

| **公開物** | 観測部・参照入力欄・実行器・解析・データ | 同じ ＋ ★ **逐語コピーの manifest（GSE の commit と SHA-256）を CI で照合** ＋ Phase 0 の生ログ |

## 推奨案

**ハイブリッド**（v1 を土台に v2 の 8 点を取り込む）— 理由:

v1 は判断 1–13 と整合しているが、⚠️ **2 つの妥当性の穴**（L2 が無い・IME の学習で試行が独立でない）を持つ。どちらも**凍結後には直せない**。一方、v2 の全部を入れると判断 7（2026 年内）に対して重い。

★ **取り込む**（凍結前でないと入れられないもの・工数が小さいもの）:
1. **L2 測度の一致**を主評価に（解析だけの追加。計測は増えない）
2. **IME の学習・予測・辞書のリセット／固定**（妥当性の穴）
3. **打鍵の速さを 3 水準の要因**に（試行数の合計は v1 とほぼ同じ）
4. **oracle による正解の検証**と **content-free な正解ログ**（Phase 0 に統合）
5. **パラメータ回復テスト**と陰性対照（解析の検査）
6. E2 の**シミュレーション攻撃**と**特徴の除去実験**（オフラインで回せる）
7. **逐語コピーの manifest**（公開物と GSE の乖離検出）
8. 論文の「**Validation framework**」「**Recommendations for researchers**」の節

★ **任意に落とす**（縮退順の先頭に置く）:
- 実アプリでの**転移確認** → 時間が余れば macOS のテキストエディットだけ。やらなければ限界に書く
- **現代文コーパス** → E2 だけで使う（E1 は青空文庫のみ）。間に合わなければ限界に書く

★ **縮退順（遅れたとき）**: 転移確認 → Google 日本語入力 → 現代文コーパス → マウス確定（S9）を「評価できなかった」とする → E2 の開集合の復元
