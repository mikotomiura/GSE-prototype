## 前書き

このデータシートは、データセット「Logging Japanese IME conversion without recording text: Records of the
synthetic-input validation」（DOI 10.5281/zenodo.23183438）を説明する。Gebru ら（2021）の節立て（動機・中身・収集の過程・前処理・使い道・配布・保守）に従う。データと一緒に寄託し、`FORMATS.md` と合わせて寄託物のすべてのファイルを説明する。細部は事前登録・論文・コードの repo に譲る。寄託のときにしか決まらない値には「（寄託のときに埋める）」と印を付ける。

## 動機

**目的。** 日本語の入力メソッドが変換したことを、変換セッションの長さ・その間の矢印キーの押下の数・取り消されたかとして、文字を一切記録せずに記録するロガーの、事前登録した検証の記録を収める。ロガーの行を参照（入力メソッドから受け取った呼び出しを記録する入力欄）と比べた。生成した計画からのスクリプトの打鍵が両方を動かした。登録した解析を寄託物から回し直せるように、また打鍵から変換を推す別の規則を新しい計測なしに同じ参照に対して評価できるように公開する。

**作成者と資金。** 作成者は Mikoto Miura（独立の研究者・広島・ORCID 0009-0000-4196-0508）。この研究は、公的・商業・非営利のいずれの資金提供機関からも特定の助成を受けていない（原稿の Funding と同じ文）。

## 中身

**単位。** データセットの単位は run（1 つの計画を、計測機で runner が 1 回再生したもの）。計画はブロックから、ブロックは試行からなる。試行は、1 つの句の読み（または生成器が作ったかなの列）を、シナリオ S1〜S15 のどれか（例: 変換して確定・取り消し・候補を巡る・別のアプリを前面に出す）で、3 つの速さのどれかで打つ。S9 は回さず、S11 は macOS のライブ変換オンだけなので、計測の計画は 14 か 13 のシナリオ（登録 2.3・10.5）。パイロットの計画にはもっと短いものがある。どの単位も人を表さない。

**run のファイル。** 各 run は 5 つのファイル（runner が中止した run はログを欠くことがある）。4 つのログは `FORMATS.md` の形式に従う。

| ファイル | 形式 | 中身 |
|---|---|---|
| `plan.jsonl` | `plan/1` | 計画のブロックと試行: シナリオ・速さ・句の識別子・意図した結果・キーの予定。生成器の設定・手順・コーパスの SHA-256 |
| `oracle.jsonl` | `oracle/1` | executor が送った押下と解放のすべて（キー名・壁時計と単調時計）。ブロックと試行の境目。ブロック始めのマーカーの押下ごとに 1 行 |
| `gt.jsonl` | `gt/1` | 参照の入力欄が入力メソッドから受け取った呼び出し: 種類・長さ（UTF-16 の単位）・選択と置き換え範囲の位置・コマンドと入力メソッドの窓の種類（決まった名前）・時刻。キーダウンのキーコード。フォーカスの変化。文字なし |
| `obs.jsonl` | `obs/1` | ロガーのヘッダ、キー行（14 分類・キー名なし・押下と解放）、セッション行（長さ・矢印キーの押下の数・取り消し）。文字なし |
| `run.json` | run の manifest（`run/1`） | 下で説明 |

各ブロックの前に、executor ではなく runner が、参照の入力欄を前面に出し、入力メソッドを日本語にするキー（macOS はかなキー・Windows は `VK_IME_ON`）を押す。これらの押下は executor の記録に無い。manifest の欄: `cell`（run の設定。入力メソッドの名前と版、プログラムを起動した命令を含む）・`plan_sha256`・`git_commit` と `git_dirty`（runner を置いた git の checkout の commit と、変更があったか。git の checkout から回していなければ `null`）・`host`（プラットフォームの文字列・プロセッサの種類・OS の版・Python の版）・`started` と `ended`・`outputs`（各ログのファイル名・SHA-256・行数）・`children`（各プログラムの終了の状態・止められたか・エラー出力のファイル名〔そのファイルは寄託しない〕）・`resets`（ブロックごとに、入力メソッドのリセットを回したか飛ばしたかと理由）・`focus`（ブロックごとに、前面に出す命令の結果と、前面にあるかの確かめの結果）・`aborted`・`abort_reason`。manifest を書く前に、すべての文字列でホームと checkout の根を `~` と `<repo>` に置き換える。Windows の計測の run の `git_commit` は `null`、ほかの run は（寄託のときに埋める）。そこに入る commit は著者の作業 repo（非公開）のもので、凍結のタグのコードはコードの repo にある。

**実行コストの標本。** 各条件に `samples.tsv`（ロガーの CPU・常駐メモリ・スレッドの 1 回の読み取りごとに 1 行）と `conditions.txt`（条件・OS と版・論理プロセッサの数・測ったプロセスの名前・ロガーの実行ファイルの SHA-256・開始前のそのプロセスの数・設定した長さと間隔・開始と終了の UTC）。間隔は 30 秒に設定したが、1 回の読み取りはそれより長くかかる（macOS では試しの run で周期が約 39 秒）。macOS の CPU は間隔の平均で、メモリは `top` のメモリ欄。Windows の CPU は読んだ時点の約 1 秒の標本で、メモリは working set。値は系の中で比べ、系の間では比べない。macOS の標本はバッテリーの残量とエネルギーの指数も記録するが、要約しない。

**部。** データセットは 2 つの部に分け、混ぜない。

1. *計測の run*（登録の凍結の後に、登録した計画から）:
   - `macos-standard-live-on`: macOS の日本語入力・ローマ字入力・ライブ変換オン。3,150 試行・126 ブロック。
   - `macos-standard-live-off`: 同じでライブ変換オフ。2,925 試行・117 ブロック。
   - `windows-msime-tsf`: Microsoft IME（日本語）・ローマ字入力・TSF のクライアントである参照の入力欄。2,925 試行・117 ブロック（試み 2）。
   - 各系の実行コストの `working` 条件（runner が `macos-standard-live-on`〔macOS〕または `windows-msime-tsf`〔Windows〕の計画を再生する間、ロガーが動く）。そのログは計測の run の規則で寄託する（寄託のときに埋める）。
   - 各系の `idle` と `working` の標本。
2. *較正パイロットの run*（凍結の前に、別の計画から、仮の設定で作ったもので、登録した寄託の基準を満たすもの。コードの repo の `pilot-macos.md`・`pilot-windows.md` の「Raw logs」）。候補は、macOS の `pilot-1`・`verify-1`・`verify-s5`・`pilot2-on`・`pilot2-off`・`verify-off`・`short-1` と、最初の macOS パイロットの前の runner の run。Windows の TSF の入力欄の `short-tsf`・`pilot-tsf`・`verify-tsf`・`toolcheck-tsf` と、runner が中止した Windows のパイロットの 3 つの試み。この部には同じ基準で、Windows の計測の前の確かめ（登録 10.8）も入る: Windows のパイロットの 39 試行の計画 `verify` を、計測の版で、最初の試みの前に計測機で回したものと、その最初の開始（runner が鍵を送る前に中止）。基準を通る候補は（寄託のときに埋める）。

両方の部に共通: 句のコーパス（`phrases.jsonl`）・計画の生成器の設定（`plan_config.macos.json`・`plan_config.windows.json`）・シナリオの手順（`recipes.json`・`recipes.macos-live-off.json`）・seed（`SEED`）・形式の仕様（`FORMATS.md`）・このデータシート。

**寄託しないもの。** 停止規則が捕まえた完了した run は寄託しない（ログに人の打鍵が入りうるため）。runner が中止した run は、同じ確かめを通るか、参照のログも観測のログも残していないときだけ寄託する。試行の途中で中止したものは通らない。したがって寄託しないもの: Windows の最初の試み（runner の外から試行の途中で止めた）・両方の系の `idle` の観測ログ（標本を始めた打鍵を含む。標本だけ寄託する）・もう 1 つの参照の入力欄の Windows のパイロットの run（入力メソッドを入れる押下をキーダウンとして受け、停止規則が外からの押下と数える）。管理者権限で runner が最初の試行の前に拒んだ Windows の計測の開始を寄託するかは（寄託のときに埋める）。プログラムのエラー出力は計測機に残し、参照の入力欄に手で打った確かめは runner の run ではないので寄託しない。論文の試みの表が、計測の計画のすべての run のすべての開始について寄託したかを示す。

**寄託物のファイル。** run ごとに 1 つの書庫（束ねる命令で作る）、実行コストの標本、共有のファイル。書庫の SHA-256 はコードの repo の `data.md`（macOS）と `data.windows.md`（Windows）にも記録する。表（ファイル名・部・中身・SHA-256）: 計測の 3 つの書庫の SHA-256 は記録済みの値。`working` の run と標本・パイロット・共有のファイルのファイル名と SHA-256 は（寄託のときに埋める）。`phrases.jsonl` は `c8f890cb…`。

**ラベル。** 参照のログが正解。参照の変換セッションは、系ごとに違う登録の規則で呼び出しから組む（`gt_rules.json`）。計画は各試行の意図した結果を示す。ロガーのセッション行は試験の対象で、ラベルではない。

**欠け・誤り・ノイズ。** 計測の 3 つの run の計画した試行はすべて測った。記録は直していない。既知の逸脱は論文と run の記録に run ごとに報告している。`macos-standard-live-off` の run で、参照の入力欄が計画の外で一度、2.7 秒フォーカスを失った。操作者の報告では別の窓へのポインタのクリックで、ログでは確かめられない。ログはその間に送った以外の押下を示さず、その間に executor が送った 11 回の押下は参照に届かなかった。押下は注入で、時刻は機械のスケジュールに左右される。計測機ではほかのソフトも動いていた（macOS は CI のランナー〔`env.md`〕、Windows はイベントログが示すもの〔`data.windows.md`〕）。参照の定義は系で違うので、違う定義の量は系の間で比べない。

**ファイルの間の関係。** 試行とブロックは識別子で計画と executor の記録をつなぐ。参照のログとロガーのログは試行の識別子を持たない。登録の解析はそれらを executor の記録と壁時計の時刻で、時計の補正なしに突き合わせる（登録 4.4・6.9）。3 つのプログラムの時計の差は、ブロック始めのマーカーでブロックごとに測って報告するが、突き合わせの補正には使わない。マーカーは、計測と Windows のパイロットの計画では矢印キー 4 回（左・右・左・右）、macOS のパイロットの計画では 3 回（`pilot-1` では F13・F14・F13 でロガーのログに行を残さない。その後は左・右・左）。文の復元の解析は、マーカーでロガーのキー行を試行に割り当てる。

**分割。** データセットとしては定めない。登録の文の復元の解析はコーパスを分ける: seed で引いた順に作品ごと評価に取り分け、句の 5 分の 1 以上になるまで（12 作品のうち 3）。2 つ目の攻撃者は句ごとに分ける（登録 6.8）。

**自己完結。** すべてのファイルの欄は、`FORMATS.md` とこのデータシートで、寄託物だけから読める。解析にはコードのリリース（DOI 10.5281/zenodo.23183441・別に保管）が要る。

**人と個人のデータ。** 参加者は募っておらず、計測機は著者が操作した。研究の間に人が打った文字を持つファイルは無い。文字はパブリックドメインの句のコーパスだけで、その読みを計画と executor の記録がキーごとに綴る。すべての run の押下はプログラムが作った。参照のログもロガーのログも、run の間に人が押したキーを記録しうる（参照はキーコードで、ロガーは分類で）。計測の run は、プログラムが送っていない押下が無いかを、登録の停止規則（3.4・10.8）で run の直後に確かめた。パイロットの run は凍結の前に確かめた（macOS は一部を前の形の規則で、Windows は macOS で登録した形で）。寄託するすべての run は寄託のときに登録の形でもう一度確かめる。規則が捕まえた run は寄託しない。規則には死角があるので、人の打鍵が無いことは保証できない: 届かなかった送信の押下と入れ替わった人の押下は検出しない／ロガーが行を取りこぼした送信の押下の 20 ms 前から 300 ms 後までの押下は検出しない／参照にもほかのアプリにも届かない押下（系が消費するショートカットなど）は捕まえない／参照の入力欄からキーウィンドウを奪わずにキーを受ける入力欄への押下は捕まえないことがある。規則が人の押下を捕まえることは、コードのテストで作った場合でしか確かめていない（登録 7 の「The stopping rule counts presses, not keys」）。規則を逃れた押下は、参照のログにキーコードとして、ロガーのログに分類として現れ、文字としては現れない。そうした押下を含む `idle` の観測ログは寄託していない。

束ねる命令は、ドライブ文字・UNC・`/Users/`・`/home/`・`/Volumes/`・`/root/`・`/mnt/`・MSYS のドライブ・`file:` で始まるパス、命令を回すユーザーと渡されたユーザーのホームとログイン名、repo のパスを含む run を拒む。ホスト名・メールアドレス・ほかの個人的な文字列は探さない。2 文字以下のログイン名や、英数字・`_`・`.`・`-` に接した名前は見つからない。ほかで始まるパス（`/tmp/` など）は認識しない。うっかりの防ぎで、匿名であることの証明ではない。実行コストの標本（`samples.tsv`・`conditions.txt`）は束ねる命令が束ねず、確かめもしない。中身は数値・OS の版・測ったプロセスの名前・その実行ファイルの SHA-256 で、パスは無い。

**不快な内容。** 句は、著作権の切れた文学作品の節を、読みが一定の長さに達するまでつなぎ、読みと本文の字種で選んだもの。内容では選ばず、確かめてもいないので、読者によっては不快な表現を含みうる。【確かめてほしい点: 方針として「このまま」を選んだ文】

## 収集の過程

**記録の作り方。** 計画の生成器が、句のコーパス・シナリオの手順・設定・seed から各計画を作った。runner が計画を再生した: executor が OS のインタフェースを通して押下を参照の入力欄に注入し、入力欄が参照のログを書き、同時に単独のロガー（コードの repo の `kit/logger`）がログを書いた。すべてのファイルは run の間にこれらのプログラムが書いた。

**機械と版。** macOS: JIS キーボードの Apple Silicon のノート。パイロットは macOS 27.0、計測は 27.0.1（26A434）。macOS の日本語入力のローマ字入力（計測ではローマ字入力の部品の版 6.3）。Windows: JIS キーボードの x86-64 のタブレット、Windows 11 Home 25H2、Microsoft IME（日本語）のローマ字入力。パイロットは build 26200.8875 と `IMJPTIP.DLL` 10.0.26100.8875、10.8 の確かめと計測は build 26200.9457 と `IMJPTIP.DLL` 10.0.26100.9278。入力メソッドの学習はリセットしていない。各 run の版は manifest にある。機械は `env.md`（macOS）・`data.windows.md`（Windows）・登録 2.2・10.4 に書いてある。

**抽出。** 登録した設定と seed で計画を生成した。計画・その無作為化・シナリオと速さごとの試行の数は登録 2.4・3.3（Windows は 10.6）と生成器の設定にある。句は生成器がコーパスから引いた。パイロットの計画は仮の設定と別の seed を使った（登録 3.1）。

**関わった人。** 計測機は著者が操作した（run の記録の「操作者」）。【確かめてほしい点: 記録の「operator」が著者であること】AI のコーディング支援が、著者の指示のもとで計測の run を始めて見守り、run の確かめと束ねを回した（論文の AI 宣言）。報酬を払って参加した人はいない。【確かめてほしい点】

**時期。** macOS のパイロットは macOS のセルの登録の凍結（2026 年 10 月 2 日）の前に、Windows のパイロットはその後で Windows の追補の凍結（10 月 3 日）の前に回した。macOS の計測と実行コストの run は 2026 年 10 月 2 日 16:03 から 10 月 5 日 01:04（UTC）、Windows の run は 10.8 の確かめから `working` の終わりまで、10 月 3 日 15:27 から 10 月 4 日 23:35（UTC。日本時間では 10 月 4 日 00:27 から 10 月 5 日 08:35）。

**倫理審査。** 該当しない。参加者を募っていない。

## 前処理・掃除・ラベル付け

**ログ。** 無い。寄託するログはプログラムが書いたファイルそのもので、値を変えも消しも足しもしていない。パイロットの間、観測のログは封印した（読まずに脇へ移し、キー行の写しだけを解析した）。寄託のときに封印を解き（ロガーが書いたとおりのファイルに戻る）、まるごと寄託する。そのセッション行は解析していない。寄託のとき、束ねる命令（コードのリリースの `pipeline.py --pack`）は run の manifest と 4 つのログだけを束ね、ログが manifest の SHA-256 と合わなければ止まり、「人と個人のデータ」の確かめ・停止規則・文字を持たない形式の確かめを当て、通らないか確かめられない run を拒み、決まった順と決まった時刻でファイルを書き（2 回束ねても同じ書庫になる）、書庫の SHA-256 を出す。実行コストの標本はサンプラが書いたとおりで、要約はコードの repo にある。

**句のコーパス。** 「配布」に挙げた元のファイルから 1 度だけ作った。各ファイルから、題と著者の行・記号の説明・奥付（底本を記す行から後）・注記・ルビを除いた（ルビの下の漢字は残す）。文と節に分け、読みがひらがなの節を、読みが 6 文字に達するまで（30 文字を超えずに）つないだ。読みか本文にほかの字を持つ句は落とし、作品ごとに seed と句の識別子の SHA-256 の順で最大 150 句を残した。読みは SudachiPy 0.7.0 と sudachidict-core 20260723.1 で付けた。結果は 1,800 句（12 作品から 150 ずつ・読みは 6〜30 文字・中央値 16）。40 句の抜き取りで、読みは打てるキーの列だった。いくつかは作品の著者が意図した読みと違い、9 つの読みは別の句の識別子で 2 回現れる。手順はコードのリリースの `build_corpus.py`、設定は `data.md`。

## 使い道

**これまでの使い道。** この研究の登録した解析（変換セッションの検出・長さと矢印キーの押下の数と取り消しの、参照とのセッションごと・文ごとの一致・キー行がどれだけ打った文を明かすか・ロガーの実行コスト）と、そう断った探索的な解析。結果のファイルはコードの repo（`experiment/results`）にある。研究を報告する論文は準備中。

**寄託物だけで支えられる使い道。** (a) 系と設定ごとに、入力メソッドが入力欄に出す呼び出しを調べ、変換の定義を見直す土台にする。(b) 打鍵からセッションを推す別の規則を、executor の記録かロガーのキー行に当てて、同じ参照に対して評価する（この研究の予測が実例）。(c) 打った句が分かった状態で、文字の無いキーのログがどれだけ文字を明かすかを調べる。

**ほかの使い道を限るもの。** 入力は合成: 誤りも訂正も無い決まった句をプログラムが打ち、キーの事象は注入で、系ごとに 1 台の機械、計測では入力メソッドごとに 1 つの版（Windows のパイロットは前の版）、系ごとに 1 種類の参照の入力欄、入力メソッドの学習はリセットしていない。入力メソッドの窓などほかの信号を要るロガーの評価は、データセットではなくコードの使い道で、キットを回し直すことになり、学習と版が違うので同じ参照は再現されない。

**向かない使い道。** 人の書く行為の記録として、自然な打鍵のベンチマークとして、書き手についての推論に。
