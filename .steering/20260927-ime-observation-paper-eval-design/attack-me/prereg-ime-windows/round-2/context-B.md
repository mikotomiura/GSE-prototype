## 既知の限界（意図の側で認めているもの）

- TSF の参照入力欄は IME が消費したキーを受け取らない → 停止規則の「外からの押下」は Windows では人の打鍵をほとんど見られない（焦点の規則は観測のログで働く）（判断 139）。
- 「長い試行」の定義が OS で違う（macOS は予測・Windows は oracle の送出の幅）。Windows のロガーの打ち切りの規則（cloak の経路だけ・窓の表示から）とも違う（判断 139・141 の D3）。境界の帯と感度の分析を報告する。
- Windows のロガーのセッションは IME の窓が見えている区間で、参照のセッション（合成）とは別の構成概念（判断 141）。どちらの経路が MS-IME で動くかは凍結の前に分からない。
- 逸脱 D4（観測の key 行が送った押下で説明されなければ中止）は、ロガーの重複行でも中止になり、ロガーが記録しないキーは捕まえない（判断 141）。
- IME の学習はリセットしない（判断 133・138）。1 台の機械・1 つの版。
- S15 は前面を外れた時点で確定する。S7 は TSF の入力欄では → が文節を超えるとその場で確定する（判断 137 の所見）。
- 計画は LF の公開物から作る必要がある（この機械の作業コピーは CRLF）（判断 139）。
- 追補の凍結の印は `sha256:` が macOS と同じ値になる（`gt_rules.json` を変えないため）（判断 138）。
- パイロットの IMM の run は、凍結の k = 0 では中止に当たる（`VK_IME_ON` が参照に key-down を残す）→ 預ける基準は経路ごとに書いた（判断 139）。
