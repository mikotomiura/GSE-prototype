## 「一致」の定義（原稿の `method.tex` §5 より）

- 一致 = ロガーが書いた変換セッション行が、**参照入力欄が IME から受けた呼び出しから固定の規則で組んだセッション**と、どれだけ重なるか。IME の内部状態・人が見た変換・物理キーから画面までとの一致ではない（外部装置では測っていない）。
- 突き合わせは時間の交差が大きい順の 1 対 1。検出（再現率・適合率）と値（dwell の差の Bland–Altman）の 2 種類。
- Windows は別の構成概念を記録する（ロガー＝IME ウィンドウの表示期間／参照＝composition）ので、一致に構成概念の差が含まれる。OS 間は比べない（§3 末尾・推奨 (a)）。

## 提案する筋（1 本の柱）

**「一致が不完全な場所は、構造で予測できた場所と、できなかった場所に分けられる」**（貢献 2 を中心に、貢献 1 と 3 が支える）。

1. 何が一致したか: プールは 0.9 前後・層ごとの下端は 0.3〜0.4。この差が分解の動機。
2. 不一致を予測可能性で分ける。
   - (a) 規則が予測した不一致: 20 秒の打ち切り・記号キーによる分割（S6・S10）。登録が先に宣言していた＝規則が働いたことの確認。
   - (b) 構成概念の差: Windows の分割（S2・S8）・dwell の偏りが全部負。
   - (c) 予測しなかった不一致: dwell の裾。**説明を保留**し、原因は今後の課題。
3. 観測可能性（§3）へつなぐ: (a)(b) は「macOS は変換を外から知らせる公開 API が検討した範囲に無く打鍵推論」「Windows はウィンドウ表示を見る」という構造から説明できる。**原因を言うのは (a)(b) に限る。(c) には及ぼさない。**
4. 書字研究への含意: 時間誤差（裾を含む）を書字研究のポーズの尺度と並べる。評価の語は使わない。KT1 と物理経路の 8 ms の並置は外部装置で測っていないと断って。
5. プライバシーは 1 段落: 時刻なしでも 10 候補なら約 90% で当たる＝「テキストを記録しない」と「分からない」は別物。規則はプライバシーの基準ではなく、時刻付きは判定していない。
