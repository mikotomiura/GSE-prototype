# Issue 009: 参照入力欄 Windows (b) TSF 直受け —— 自スレッドの TSF の composition と候補一覧を content-free な `gt/1` で記録する
verify_level: parse

## Goal

IMM 互換層を**経ずに**、TSF の composition の開始・更新・終了と、候補一覧などの UI 要素の表示を
**自分のプロセス・自分のスレッドの中で**受け、`gt/1`（`src: "win_tsf"`）で記録する bin `refinput_tsf` を足す。
⚠️★★★ **文字列を取得しない**（範囲の長さは `ITfRangeACP::GetExtent` の `cch` で得る。`GetText` を呼ばない）。

## Background

- design.md §1.1（Windows (b) TSF 直受け）: 参照入力欄を TSF 対応アプリにし、composition の通知（`ITfContextOwnerCompositionSink`・逐語 "implemented by an application to receive composition-related notifications"）と候補一覧（`ITfUIElementSink`）を受ける。★ MS-IME は TSF の IME なので翻訳層を挟まない。
- ⚠️ `ITfContextOwnerCompositionSink` を受けるのは**コンテキストの所有者**（テキストストア `ITextStoreACP` を実装したアプリ）である。→ 実装の道は 2 つある:
  - **道 1（推奨・小さい）**: TSF 対応のコントロール（RichEdit `MSFTEDIT_CLASS`）を載せ、自スレッドの `ITfThreadMgr` から**フォーカス中のコンテキスト**を取り、`ITfTextEditSink::OnEndEdit` で `ITfContextComposition::EnumCompositions` を見て開始・更新・終了を判定する。候補一覧は `ITfUIElementMgr` 経由の `ITfUIElementSink`（`BeginUIElement` / `UpdateUIElement` / `EndUIElement`）。
  - **道 2（設計の文言どおり・大きい）**: 自前の `ITextStoreACP` ＋ `ITfContextOwnerCompositionSink`。
  - ★ **どちらを採ったかを README と Execution Result に書く**（preregistration が「正解の経路」を記すため）。道 1 は design.md の `ITfContextOwnerCompositionSink` という名前と違うので、⚠️ その違いを README に明記する。
- 判断 2 / `architecture-rules` ルール 5: 禁じられているのは**他プロセス**の TSF の観測とグローバルフック。★ 本 issue は**自スレッドの TSF だけ**を使う（`ITfThreadMgr::Activate` は逐語 "Activates TSF for the calling thread"）。
- `core.rs`（issue 008）に `TsfStart` / `TsfUpdate` / `TsfEnd` / `UiBegin` / `UiUpdate` / `UiEnd` のバリアントが既にある。★ 足りなければ Stop（`core.rs` の形は 008 が決めた）—— ただし `core.rs` への**追加だけ**は Allowed Files に入れてある。
- ⚠️ `UiBegin` の `kind` は、UI 要素が `ITfCandidateListUIElement` を問い合わせて得られれば `candidate`、`ITfReadingInformationUIElement` なら `reading`、それ以外は `other`。
