# Issue 017: 照合器と検出の指標 —— IoU ≥ 0.5 の 1 対 1・分割 / 併合・誤りの注入・パラメータ回復・陽性 / 陰性対照
verify_level: recheck
runs_on: any

## Goal

正解側の変換セッション（issue 010 の `sessions.json`）と観測側の `ime_shadow` 行（`obs/1`）を**時間区間の重なり**で照合し、
検出の指標（適合率・再現率・F1・分割率・併合率）を Wilson 95% CI つきで出す `match.py` と、
**既知の誤りを注入した偽の観測ログ**を作る `inject.py` を作る。
★ 最重要の検査は**パラメータ回復テスト**（design.md §7）: 注入した誤りの率を、解析が区間内で回復できること。

## Background

- design.md §1.2: 照合 = 時間区間の重なり（**IoU ≥ 0.5**）で 1 対 1。**1 対多は分割、多対 1 は併合**として別に数える（macOS のマウス確定は併合になる見込み）。§1.3: 適合率 / 再現率 / F1、分割率 / 併合率はセル別に Wilson 95% CI。
- design.md §7: パラメータ回復（例: 取り逃し 5% / 分割 3% / 併合 3% / 時間の偏り +20 ms・ばらつき σ = 50 ms）・照合器の 5 型（完全一致 / 分割 / 併合 / 取り逃し / 偽検出）・陽性対照（1 行消す・ずらすと悪化）・陰性対照（大きくずらす・シャッフルで偶然水準へ）・seed 固定で 2 回走らせてバイト一致。
- 判断 22（一次で確認済み）: `ime_shadow` の `t` は **drain した時刻**（`lib.rs:3216-3243`）。→ ★ 観測区間の既定は `[t − dwell_ms, t]`、設定 `obs_end_offset_ms` で終端をずらせるようにする。⚠️ 終端の遅れ（0〜100 ms の一様分布）を注入しても回復できることを確かめる。
- 入力の形（issue 010 の出力）: `sessions.json` = `{"src", "rules_sha256", "definitions": {"all": [...], "macos_def": [...], "windows_def": [...] | null}, "oracle_agreement", "excluded": [...]}`、セッション 1 件 = `{"trial_id", "start_wall_ms", "end_wall_ms", "start_mono_ns", "end_mono_ns", "outcome", "candidate_shown", "nav_true"}`。★ 時刻は**壁時計の ms**（観測側の `t` と同じ系）で照合する。時計の差はパイロット（M1）で測った**ブロックごとの補正**を設定 `clock_offsets_ms`（`block_id` → ms）で受け取る。
- 統計は issue 016 の `stats.py` を import して使う（★ 再実装しない）。

## Scope

### In
- `papers/ime-observation/kit/analysis/match.py`（新規）
  - `match(gt_sessions, obs_rows, iou_min=0.5, obs_end_offset_ms=0) -> {"pairs", "split", "merge", "miss", "false_pos"}`（**決定的**: IoU の降順で貪欲に 1 対 1。同点は開始時刻の昇順）。
    - ★ **形の固定**（018 / 019 / 020 がこの形に依存する）: `gt_sessions` は**セッションの配列**（`sessions.json` の `definitions[<定義>]` の中身。ファイル全体ではない）。`obs_rows` は `ime_shadow` 行の配列。戻り値の `pairs` = `[{"gt": <セッション>, "obs": <行>, "iou": float}]`、`split` = `[{"gt": <セッション>, "obs": [<行>…]}]`、`merge` = `[{"obs": <行>, "gt": [<セッション>…]}]`、`miss` = `[<セッション>…]`、`false_pos` = `[<行>…]`。
  - 分割 = 1 対 1 で対にならなかった正解 1 件に、観測 2 件以上が重なり、その**和集合**との IoU が `iou_min` 以上。併合 = その逆（観測 1 件に正解 2 件以上）。取り逃し / 偽検出 = どれにも入らない残り。
  - `detection_metrics(result, strata) -> [...]`: 層（セル × シナリオ × 速さ）ごとに件数・適合率・再現率・F1・分割率（分割になった正解 / 正解）・併合率（併合になった観測 / 観測）と Wilson 95% CI。
  - CLI: `match.py --sessions <json> --definition all|macos_def|windows_def --obs <obs> --plan <plan> --oracle <oracle> --config <json> --out <json>`（層は plan / oracle から試行ごとに引く）。
  - ⚠️ `excluded` の区間に入るセッション・観測は照合から外し、件数を出力に残す。
- `papers/ime-observation/kit/analysis/inject.py`（新規）: `inject(gt_sessions, rates, timing, seed) -> (obs_rows, truth)`（★ 戻り値は**この 2 要素のタプル**）。`obs_rows` は `obs/1` の `ime_shadow` 行（`{"type":"ime_shadow","t","dwell_ms","nav","abandon"}`）の配列、`truth` は注入した**実際の値**（何件を落とし・分け・併せたか）。`rates` = `{"miss", "split", "merge", "false_pos"}`、`timing` = `{"bias_ms", "sd_ms", "end_lag_ms_max"}`。乱数は `random.Random(seed)` だけ。
- 両ファイルに `--selftest`（目印 `# kit: selftest`）:
  - `match.py`: 5 型（完全一致 / 分割 / 併合 / 取り逃し / 偽検出）の手作りの例 ／ 同点の決定性 ／ ⚠️ 陽性対照（観測を 1 行消すと再現率が下がる・1 行を 2 s ずらすと対が 1 つ減る）／ ⚠️ 陰性対照（観測を 60 s ずらす・時刻をシャッフルすると対の数が**偶然水準**＝ほぼ 0 になる）／ 同じ入力で**バイト一致**。
  - `inject.py`: ★ **パラメータ回復**: 正解 2,000 件に取り逃し 5% / 分割 3% / 併合 3% / 偽検出 2% と時間の偏り +20 ms・σ 50 ms・終端の遅れ 0〜100 ms を注入し、`match` → `detection_metrics` の推定の Wilson 95% CI が注入した率（実際の件数から計算した値）を**含む**こと。seed を 5 つ変えて 5 回とも含む。
