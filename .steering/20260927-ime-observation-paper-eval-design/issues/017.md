## Goal

正解側の変換セッション（issue 010 の `sessions.json`）と観測側の `ime_shadow` 行（`obs/1`）を**時間区間の重なり**で照合し、

★ 最重要の検査は**パラメータ回復テスト**（design.md §7）: 注入した誤りの率を、解析が区間内で回復できること。

## Background

- design.md §1.2: 照合 = 時間区間の重なり（**IoU ≥ 0.5**）で 1 対 1。**1 対多は分割、多対 1 は併合**として別に数える（macOS のマウス確定は併合になる見込み）。§1.3: 適合率 / 再現率 / F1、分割率 / 併合率はセル別に Wilson 95% CI。
- design.md §7: パラメータ回復（例: 取り逃し 5% / 分割 3% / 併合 3% / 時間の偏り +20 ms・ばらつき σ = 50 ms）・照合器の 5 型（完全一致 / 分割 / 併合 / 取り逃し / 偽検出）・陽性対照（1 行消す・ずらすと悪化）・陰性対照（大きくずらす・シャッフルで偶然水準へ）・seed 固定で 2 回走らせてバイト一致。
- 判断 22（一次で確認済み）: `ime_shadow` の `t` は **drain した時刻**（`lib.rs:3216-3243`）。→ ★ 観測区間の既定は `[t − dwell_ms, t]`、設定 `obs_end_offset_ms` で終端をずらせるようにする。⚠️ 終端の遅れ（0〜100 ms の一様分布）を注入しても回復できることを確かめる。
- 入力の形（issue 010 の出力）: `sessions.json` = `{"src", "rules_sha256", "definitions": {"all": [...], "macos_def": [...], "windows_def": [...] | null}, "oracle_agreement", "excluded": [...]}`、セッション 1 件 = `{"trial_id", "start_wall_ms", "end_wall_ms", "start_mono_ns", "end_mono_ns", "outcome", "candidate_shown", "nav_true", "nav_true_cand", "excluded_by", "n_start_while_open"}`（★ 後ろの 3 つは 2026-09-28 の判断 27 / 28 で追加。`excluded` の各要素は `trial_ids` を持つ）。★ 時刻は**壁時計の ms**（観測側の `t` と同じ系）で照合する。時計の差はパイロット（M1）で測った**ブロックごとの補正**を設定 `clock_offsets_ms`（`block_id` → ms）で受け取る。

### 設計判断（issue に書いていない選択・M3 / 018〜020 が知るべき点）
1. **観測区間**: `[end − dwell_ms, end]`、`end = t + obs_end_offset_ms`（区間**全体**を平行移動する。`dwell_ms` は長さ）。issue の「終端をずらす」をこう読んだ。遅れが 0〜100 ms の一様分布なら平均を打ち消す `obs_end_offset_ms = -50`。
2. **`clock_offsets_ms` の符号**: 「観測側の時計 − 正解側の時計」（`kit/pilot/clock_sync.py` の `obs − gt` と同じ）で、照合の前に観測の `t` から引く。CLI 出力の各観測行は補正後の `t` と `t_raw`（元の値）を持つ。観測のブロックは「補正後の `t` が oracle の `block_begin`〜`block_end` に最も近いブロック」で決める（⚠️ 補正がブロックの間隔より十分小さい前提）。
3. **分割 / 併合の確定**: 対にならなかった項目を「重なりで繋がる成分」ごとに、IoU の高い候補から 1 つずつ確定し、使った項目を外して作り直す。和集合の IoU は区間の**集合の測度**（隙間は数えない・はみ出しは和に数える）。
4. **F1 の区間**: F1 = 2 x 対 /（正解 + 観測）= 対に入った項目の割合として Wilson を当てた（項目は独立でないので近似。`stats.py` に F1 用の区間は無い）。
5. **追加した指標**: 取り逃し率 = 取り逃し / 正解、偽検出率 = 偽検出 / 観測（パラメータ回復に必要）。併合は先頭の正解の層、偽検出は観測の層に数える。
6. **`inject` の追加引数と前提**: `iou_min=0.5`（省略可）。注入する誤りは「照合の定義で検出できる型」に限る（分割は 3 断片以上・併合は不均衡でない組・最悪のずれでも検出できる長さのときだけ）。条件に合わない引きは正解のまま出して `truth["skipped"]` に数える。`truth["risk"]` = 前提を破る件数（`short` / `crowded`）で、0 のとき件数の厳密な回復が保証される。
7. **除外**: `open_at_end`（`end_wall_ms` が null）のセッションは、`excluded_by` が空でも理由 `open_at_end` で外す（`trial_id` が null だと `excluded_by` が付かないため）。`sessions.json` に `excluded_by` / `excluded[].trial_ids` が無い古い出力は拒否する（黙って除外なしで走らせない）。

### ⚠️ 研究者への報告（★ 定義は凍結の対象。直していない・M3 で判断）
**Stop 条件には該当しなかった**（パラメータ回復は長さ 1.5 s 以上の合成セッションで通る）。ただし IoU ≥ 0.5 の定義には次の性質がある（selftest「定義の性質」「IoU 定義の感度」で固定）:
- **隣り合う 2 断片への分割は「分割」と数えられない**: 大きい方（≥ 50%）が 1 対 1 になり、残りは**偽検出**になる。分割として数えられるのは、各断片が単独で IoU < 0.5 のとき（3 断片以上、または隙間のある 2 断片）だけ。**併合も同様**（一方が併合区間の ≥ 50% を占めるとその正解が対になり、もう一方は**取り逃し**になる）。→ 分割率 / 併合率は「定義で見える型」の率であり、実際の分割・併合の総数の推定ではない。
- **短いセッションは時刻のずれで対にならない**（長さ L の対は平行移動が L/3 以下のとき）。実測（`inject` の既定 timing = 偏り +20 ms・σ 50 ms・遅れ 0〜100 ms・最悪のずれ 321 ms・各 1,000 件）: 再現率は L = 200 ms で 0.466（offset -50 で 0.749）・400 ms で 0.877（0.982）・600 ms で 0.989（0.998）・1,000 ms 以上で 1.000。→ 速いシナリオで短いセッションが多い層は、**検出の失敗と時刻のずれが分離できない**。`obs_end_offset_ms` の値（既定 0）と、報告の層ごとの読み方を M3 で決めること。
- 偶然水準: 観測を 60 s ずらすと対は 300 件中 6 件（2%）。時刻を全区間へ一様に置き直した場合も 5% 以下（selftest の閾値）。⚠️ 時刻を**行の間で並べ替えるだけ**では終端時刻の集合が正解と揃ったままで対が 86% 残り、陰性対照にならない（最初の実装で踏んだ）。
