# Issue 004: 実行器の核（計画 → 送出 → oracle）と dry-run・macOS（CGEventPost）のバックエンド
verify_level: parse
runs_on: macos

## Goal

`plan/1` を読み、各ステップを**計画した時刻に**送出し、**実際に送った時刻**を `oracle/1` に記録する `emit.py` を作る。
バックエンドは `dryrun`（送らない）と `macos`（`CGEventPost`・`ctypes`）。
⚠️★★★ **既定は送らない**: 実バックエンドは明示フラグ `--i-understand-this-sends-keys` が無ければ exit 2 で止まる。

## Background

- design.md §1.1: シナリオ実行器は macOS = `CGEventPost`（合成キーは IME を実際に駆動する）、Windows = `SendInput`（scan code）。
- design.md §1.1〔v2〕: oracle は試行ごとの**意図**と**実際に送った時刻**。★ 正解の検証だけに使う。
- 判断 22: Python 標準ライブラリだけ。OS への送出は `ctypes`。
- ⚠️ 合成キーの送出は**前面のアプリに入力が入る**危険な操作である。テスト・selftest・acceptance は**一度も送出しない**（`--probe` はイベントを作るが送らない）。
- ★ `focus_away` / `focus_back` は擬似キー（`FORMATS.md`）。macOS ではバックエンドが別アプリを前面に出し（例: `osascript -e 'tell application "Finder" to activate'`）、`focus_back` で元のアプリ（設定で渡すバンドル ID）を前面に戻す。
- ★ 時刻: `t_wall_ms = time.time_ns() // 1_000_000`、`t_mono_ns = time.monotonic_ns()`。★ 送出の直前まで `time.perf_counter()` で待ち、最後の 2 ms は busy-wait にする。

## Scope

### In
- `papers/ime-observation/kit/emit/emit.py`（新規・核）
  - `emit.py --plan <plan> --out <oracle> --backend dryrun|macos|windows [--i-understand-this-sends-keys] [--backend-opt k=v ...]`（★ macOS の `focus_back` で戻る先は `--backend-opt focus_app=<バンドル ID>`）
  - ブロック行ごとに `block_begin` → マーカーのキー列を送って `marker`（`seq` 付き）→ 試行ごとに `trial_begin` → `sent`（各ステップ）→ `trial_end` → `block_end`。★ IME のリセットは本 issue の範囲外（issue 006 が `reset` 行を書く API を呼ぶ）→ `Emitter` クラスに `write_reset(block_id, exit_code)` を公開する。
  - 他のモジュール（issue 006）から使えるよう、`Emitter(backend, out, ...)` と `run_block(block, trials)` を**関数/クラスとして公開**する（CLI はその薄い包み）。
  - ★ **バックエンドの境界**（★ ここで固定する。005 / 026 は核を触らずにこの形で差し込む）:
    ```python
    # backend_<name>.py が公開するもの
    SUPPORTED_KEYS: frozenset[str]          # そのバックエンドが送れる keyname（擬似キーを含む）
    class Backend:
        def __init__(self, opts: dict[str, str]): ...   # --backend-opt k=v を受け取る（未知のキーは無視せず例外）
        def open(self) -> None: ...          # 送出の前に 1 回（例: Windows の timeBeginPeriod(1)）
        def send(self, key: str, down: bool) -> None: ...   # 1 ステップを送る（待ちは核が持つ）
        def close(self) -> None: ...         # 送出の後に 1 回。例外のときも核が必ず呼ぶ（try / finally）
    ```
  - ★ 核は計画の keyname が `SUPPORTED_KEYS` に無ければ**送る前に**止める（exit 2・その keyname を出す）。→ `mouse_click` は既定のどのバックエンドにも入れない（issue 026 が `backend_macos.py` の `SUPPORTED_KEYS` に足す）。
  - ★ 待ち時間は核が計画から取る: 試行の先頭の前に `gap_before_ms`、マーカーのキーの間に `marker_gap_ms`、試行の中は `at_ms`（`FORMATS.md` の `plan/1`）。★ 核は自分で待ち時間を決めない。
  - `--backend-opt k=v`（複数可）をそのまま `Backend(opts)` に渡す。
  - バックエンドは名前で読み込む（`backend_<name>.py` を import）。★ `backend_windows.py` は issue 005 が置くので、**本 issue では作らない**（無ければ「未実装」で exit 2）。
  - `--validate <oracle>`: `oracle/1` の検査（ヘッダ・`kind` の列挙・時刻が整数・`trial_begin`〜`trial_end` の入れ子・`sent` の `down`/`up` の対）。違反で exit 1。
  - `--selftest`（目印 `# kit: selftest`）: `dryrun` だけを使い、テストの中で作った計画から次を確かめる:
    - oracle が `--validate` を通る ／ ⚠️ 壊した oracle（`trial_end` 欠落）を拒否する
    - 実際の送出時刻と計画の時刻の差の 95 パーセンタイルが 20 ms 未満（dryrun の待ち方の検査）
    - ⚠️ 実バックエンドを**フラグなし**で指定すると exit 2（送らない）
    - `mouse_click` を含む計画を `dryrun` で渡すと、核が**送る前に** exit 2 で止める（`SUPPORTED_KEYS` に無いため・★ S9 は issue 026）
    - ★ バックエンドの `close()` が、送出の途中で例外が起きても呼ばれる（`dryrun` に例外を起こす試験用の opts を用意してよい）
- `papers/ime-observation/kit/emit/backend_dryrun.py`（新規）: 何も送らず、送ったことにして時刻だけ返す。
- `papers/ime-observation/kit/emit/backend_macos.py`（新規）
  - `ctypes` で `/System/Library/Frameworks/ApplicationServices.framework/ApplicationServices` を読み、`CGEventSourceCreate(kCGEventSourceStateHIDSystemState)` → `CGEventCreateKeyboardEvent(src, keycode, down)` → `CGEventPost(kCGHIDEventTap, ev)` → `CFRelease`。
  - `keyname` → macOS の keycode は `keymap_macos.json` から（`ime_on` = かな `0x68`、`ime_off` = 英数 `0x66`、`f13` = `0x69` ほか）。
  - `--probe`: フレームワークを読み、`a` のイベントを**作って解放するだけ**（送らない）。exit 0。
  - ⚠️ `check.sh` は Windows の機械でも回る。→ ★ `backend_macos.py` に selftest の目印を付けるなら、**macOS 以外では「対象外」と出して exit 0** にする（★ import の時点で CoreGraphics を読まない）。

- `papers/ime-observation/kit/emit/README.md`（新規）: 使い方、⚠️ 送出の安全規則（前面のアプリ・フラグ・Accessibility 権限）、oracle の読み方。
