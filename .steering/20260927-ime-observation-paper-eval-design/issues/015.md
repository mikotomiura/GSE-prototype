# Issue 015: 較正パイロットの道具 —— 呼び出し列の型・時計の対応・フックへの到達・ImeShadow の封印
verify_level: recheck
runs_on: any

## Goal

較正パイロット（design.md §1.1a・マイルストーン M1 / M5）で使う 4 つの道具を作る。

1. `call_types.py`: 試行ごとの**呼び出し列の型**（例: `set_marked+ → insert_text`）を数え、シナリオ × src ごとの分布と 1 試行の実時間を出す（★ 正解の定義を決める材料・n の見直しの材料）。
2. `clock_sync.py`: ブロックごとの**同期マーカー**から、正解側・観測側・oracle の時刻差の**分布とドリフト**を出す。
3. `reach.py`: 合成入力が**観測部のフックに届くか**を、観測側の **`key` 行だけ**で確かめる。
4. `seal_obs.py`: 単体ロガーの出力から **`key` 行と `meta` 行だけ**を取り出し、元のファイルは**開かずに封印**（`sealed/` へ移し SHA-256 を記録）する。

⚠️★★★ **境界（判断 11）**: パイロットは ImeShadow 行を**見ない・数えない・突き合わせない**。★ `ime_shadow` を読んでよいのは `seal_obs.py` の**捨てる規則**だけである。

## Background

- design.md §1.1a: やること = (1) 参照入力欄だけを動かし S1〜S15 の呼び出し列を記録（Windows は IMM / TSF の両経路・両者が同じ区間を返すか）、(2) oracle ↔ 正解の一致率（★ issue 010 が出す）、(3) 合成入力が観測部のフックにも届くかを**生の打鍵行だけ**で、(4) 同期マーカーをブロックごとに打ち、時刻差の分布とドリフト。出力は preregistration に「正解の定義の根拠」として載せ、生ログも公開する。
- ⚠️ `obs/1` の `key` 行は **category（14 種）だけ**なので、マーカーは「category の並び ＋ 間隔」で見つける。★ マーカーのキーは M1 で決める（観測側の `key` 行に出ること・IME の状態を変えないこと。⚠️ GSE の macOS は `is_observed_key` の外のキーを `key` 行に出さない）→ ★ 道具は**マーカーの仕様を設定で受け取る**。
- 判断 22: Python 標準ライブラリだけ。

## Scope

### In
- `papers/ime-observation/kit/pilot/call_types.py`（新規）: `--gt <gt> --oracle <oracle> --plan <plan> --out <json>`。試行の区間（oracle の `trial_begin`〜`trial_end`）に入る `ev` を、同じ `ev` の連続を `+` に畳んで型の文字列にする（`do_command` は `cmd` を、`notify` は `imn` を、`ui_*` は `ui_kind` を添える）。シナリオ（plan から）× 型の件数と、試行の実時間の中央値・95 パーセンタイル。
- `papers/ime-observation/kit/pilot/clock_sync.py`（新規）: `--oracle <oracle> [--gt <gt>] [--obs-keys <keys-only obs>] --marker <json> --out <json>`。マーカーの仕様 = `{"oracle_keys":[…], "gt_vks":[…], "obs_categories":[…], "max_gap_ms": int}`。ブロックごとに 3 者の時刻差、分布（中央値・範囲）、ブロック番号に対する線形のドリフト（ms / 時）、見つからなかったブロック。
- `papers/ime-observation/kit/pilot/reach.py`（新規）: `--oracle <oracle> --obs-keys <keys-only obs> --out <json>`。試行ごとに「送った押下の数」と「その区間の `key` 行（press=true）の数」を比べ、到達率とずれの分布。
- `papers/ime-observation/kit/pilot/seal_obs.py`（新規）: `--obs <file> --keys-out <file> --sealed-dir <dir>`。`meta` と `key` の行だけを `keys-out` に書き、元のファイルを `sealed-dir` へ**移し**、`seal.json` に元の SHA-256・バイト数・封印時刻を書く。⚠️ 標準出力・`seal.json` に **`ime_shadow` 由来の情報（行数・値）を出さない**。`keys-out` が既にあれば止める。
- 各ファイルに `--selftest`（目印 `# kit: selftest`）: テストの中で作ったログで、
  - `call_types`: 既知の列が期待する型になる・畳み込み・シナリオ別の件数
  - `clock_sync`: 既知のずれ（+37 ms）とドリフト（+10 ms / 時）を回復する ／ ⚠️ マーカーが無いブロックを「見つからない」に出す
  - `reach`: 到達率 100% と、⚠️ `key` 行を半分消すと 50% になる（陽性対照）
  - `seal_obs`: `keys-out` に `ime_shadow` が 0 行・元のファイルが `sealed-dir` に移る・`seal.json` の SHA-256 が一致・⚠️ 標準出力と `seal.json` に `ime_shadow` の文字列が無い
- `papers/ime-observation/kit/pilot/README.md`（新規）: パイロットの手順（M1 / M5 で使う順）、⚠️ 境界（ImeShadow を見ない・封印を開けるのはプロトコル凍結の後）、出力の読み方。
