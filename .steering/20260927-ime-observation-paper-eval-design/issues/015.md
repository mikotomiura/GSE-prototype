# Issue 015: 較正パイロットの道具 —— 呼び出し列の型・時計の対応・フックへの到達・ImeShadow の封印
verify_level: recheck
runs_on: any

## Goal

較正パイロット（design.md §1.1a・マイルストーン M1 / M5）で使う 4 つの道具を作る。

1. `call_types.py`: 試行ごとの**呼び出し列の型**（例: `set_marked+ → insert_text`）を数え、シナリオ × src ごとの分布と 1 試行の実時間を出す（★ 正解の定義を決める材料・n の見直しの材料）。
2. `clock_sync.py`: ブロックごとの**同期マーカー**から、正解側・観測側・oracle の時刻差の**分布とドリフト**を出す。
3. `reach.py`: 合成入力が**観測部のフックに届くか**を、観測側の **`key` 行だけ**で確かめる。
4. `seal_obs.py`: 単体ロガーの出力から **`key` 行と `meta` 行だけ**を取り出し、元のファイルは**開かずに封印**（`sealed/` へ移し SHA-256 を記録）する。

⚠️★★★ **境界（判断 11）**: パイロットは ImeShadow 行を**見ない・数えない・突き合わせない**。★ `ime_shadow` を読んでよいのは `seal_obs.py` の**捨てる規則**だけである。

## Background

- design.md §1.1a: やること = (1) 参照入力欄だけを動かし S1〜S15 の呼び出し列を記録（Windows は IMM / TSF の両経路・両者が同じ区間を返すか）、(2) oracle ↔ 正解の一致率（★ issue 010 が出す）、(3) 合成入力が観測部のフックにも届くかを**生の打鍵行だけ**で、(4) 同期マーカーをブロックごとに打ち、時刻差の分布とドリフト。出力は preregistration に「正解の定義の根拠」として載せ、生ログも公開する。
- ⚠️ `obs/1` の `key` 行は **category（14 種）だけ**なので、マーカーは「category の並び ＋ 間隔」で見つける。★ マーカーのキーは M1 で決める（観測側の `key` 行に出ること・IME の状態を変えないこと。⚠️ GSE の macOS は `is_observed_key` の外のキーを `key` 行に出さない）→ ★ 道具は**マーカーの仕様を設定で受け取る**。

### issue の記述との差・解釈（研究者が確かめてほしい）

1. **`keys-out` の `meta` 行は作り直す**: AC 3 は keys-out に `ime_shadow` の文字列が 0 件であることを求めるが、単体ロガーの `meta` の `capabilities.config_gated` には名前 `ime_shadow` が載る。
   → `meta` を許可リスト（ヘッダのキーと、`capabilities` の名前のうち `key` だけ）で作り直す。元の `meta` は封印した側に残る。作り直した `meta` は `obs/1` の検査器を通る（selftest で確認）。
2. **keys-only の強制**（issue に無い足し）: `reach.py` / `clock_sync.py` は、観測側の入力に `meta` と `key` 以外の行が 1 行でもあれば、内容に触れず拒否する（exit 2）。封印していないファイルを渡す事故を止める。
   `call_types.py` は観測側を読まない。
3. **`call_types.py` の区間に余裕**（`--pre-ms` 50 / `--tail-ms` 500・`--clock` wall / mono）: 正解側の記録は送出の後に出るので、最後のキーの結果（`insert_text` など）は `trial_end` の後に来る。
   区間そのままだと確定の呼び出しを取りこぼす。既定の `--skip-ev key_down`（打鍵は oracle と重なる）と、`+` を 2 回以上の連続にだけ付ける（1 回だけなら付けない）のも解釈。
4. **`clock_sync.py` のドリフト**: issue は「ブロック番号に対する線形のドリフト（ms / 時）」。単位が時間なので、x は**oracle のマーカーの時刻（時間）**にした（ブロック間隔が一定ならブロック番号と同じ傾き）。
   差は**遅延と時計のずれの和**で、分けられない（README に明記）。
5. **`reach.py` の区間**も同じ余裕（`--pre-ms` 20 / `--tail-ms` 300）。観測側は壁時計（Unix ms）だけ（`logger.rs` の `now_ms` で確認）。
6. **`seal_obs.py` が記録するバイト数**: 元のバイト数と keys-out のバイト数の差から、捨てた行の**バイト数の合計**は逆算できる（行数・値は分からない）。issue が `seal.json` にバイト数を求めるので残した。README に書いた。
