# Issue 023: E3 の実行と集計 —— 公開する単体ロガーだけを、作業中 / 無操作の 2 条件で、既存の計器で測る
verify_level: parse
runs_on: any

## Goal

E3（判断 12）の**器**を作る: 単体ロガー（`ime-observation-logger`）のプロセスだけを、**作業中**（実行器が合成の打鍵を流し続ける）と
**無操作**の 2 条件で、`experiments/20260903-o1-runtime-cost/` の**直した計器**で測り、集計する。
★ 計測そのもの（数時間 × 2 条件 × 2 OS）はマイルストーン M10 でメインと研究者が行う。

## Background

- 判断 12 / design.md §3: 公開する観測部だけを単体の常駐プロセスとして両 OS で測り直す。⚠️ `_summary.txt` の CPU 平均 0.98% は**無効**（旧計器 `top -l 2` の過小報告）。★ 直した計器（macOS = `ps -o cputime` の増分 / 実時間）を流用する。⚠️ 短い窓でレート系を代表させない（`notes.md:906-907`）。⚠️ **バッテリーは外す**。
- `notes.md:1000` 逐語「GSE の CPU は N % と単一の数字で言わない」→ ★ 2 条件で出す。
- 一次（2026-09-28 に確認）: `experiments/20260903-o1-runtime-cost/scripts/sample-macos.sh:41` は `pgrep -x 'gse-next'`、`sample-windows.sh:8` は `Get-Process -Name "gse-next"` で、**プロセス名が決め打ち**。
- ⚠️ 境界（`papers/README.md`）: `papers/` は GSE の `experiments/` を**実行時に参照しない**。→ ★ 計器は `kit/e3/` に**写し**、元のパスと SHA-256・**変えた行**（プロセス名を環境変数 `E3_PROC` から取る 1〜2 行）を README に表で書く。
- 作業中の打鍵は段取り（issue 006 `run_cell.py`）で流す。★ 本 issue は**コマンドの組み立てと集計**だけを持つ。

## Scope

### In
- `papers/ime-observation/kit/e3/sample-macos.sh` / `sample-windows.sh` / `calibrate-cpu.sh`（新規・**写し**）: 元との差は**プロセス名の行だけ**（`E3_PROC`・既定 `ime-observation-logger`）。
- `papers/ime-observation/kit/e3/run_e3.sh`（新規）: `run_e3.sh <idle|working> <duration_s> <interval_s> <out_dir>`。OS を見てサンプラを選び、`working` のときは `run_cell.py` のコマンドを**表示するだけ**（★ 実際に打鍵を流すかは研究者が別端末で起動する。`run_e3.sh` 自身は送出しない）。bash 3.2 で動くこと。
- `papers/ime-observation/kit/e3/summarize_e3.py`（新規）: サンプラの出力（`samples.tsv`）から CPU の平均・中央値・95 パーセンタイル、RSS の傾き（MB/h）を出す。★ 校正（`calibrate-cpu.sh` の結果）を掛け合わせる手順は元の `summarize.py` と同じ式にする（⚠️ 式を写したことを README に書く）。`--selftest`（目印 `# kit: selftest`）: 既知のサンプル列（例: CPU 時間が 1 秒ごとに 0.02 秒増える → 2.0%）を正しく集計し、⚠️ サンプルが 0 行・プロセスが見つからない列（全部 0）を「測れていない」と出す（陰性対照）。
- `papers/ime-observation/kit/e3/README.md`（新規）: 手順（M10）、写しの表（元のパス・SHA-256・変えた行）、⚠️ バッテリーを測らない理由、2 条件で出す理由。

### Out
- ⚠️ `experiments/20260903-o1-runtime-cost/` を**変えない**。
- 実際の計測（M10）。
