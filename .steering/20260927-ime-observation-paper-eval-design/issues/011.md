## Goal

  - ★ `symbol`: 関数・型の抜粋では、その名前（例: `"macos_vk_to_vk"`）を入れる（`--against-gse` が範囲の中に `fn <symbol>` / `enum <symbol>` / `struct <symbol>` があることを確かめる）。
  - ★ `sha256` は、`file` = ファイル全体、`excerpt` = 範囲のバイト列、`new` = ファイル全体。
- `papers/ime-observation/kit/logger/check_manifest.py`（新規）
  - `--self`: `kit/logger/` にある `manifest*.json` を**すべて**読み、各エントリの SHA-256 が一致（★ 公開 repo でも回せる。GSE を読まない）。
  - `--against-gse`: `file` は GSE の `gse_path`、`excerpt` は GSE のファイルからアンカーで切り出した範囲の SHA-256 が manifest と一致。★ シムの定数の値が GSE の `hook.rs` の `pub const` と一致。
  - ★ **抜粋の範囲の決め方**（⚠️ コピー側に終了アンカーの行を置けないことがある —— 例: 宙に浮いた doc comment は Rust のコンパイルエラー）:
    - **GSE 側**: 開始アンカーの行（**行全体の一致**・行末の空白と改行を除いて比べる）を含み、終了アンカーの行を含まない範囲。アンカーは**ファイルの中でちょうど 1 回**現れること（0 回・2 回以上は赤）。
    - **コピー側**: 目印のコメント行 `// @excerpt-begin <id>` と `// @excerpt-end <id>` の**間**（目印の行は含まない）。★ `<id>` は manifest の `id`。前置きの `use` などは目印の外に置く。1 つのファイルに複数の抜粋を置いてよい。
    - 両者のバイト列（改行は LF に揃える）の SHA-256 が manifest の `sha256` と一致。
  - `--update --manifest <file> --entries <spec.json>`: **指定した 1 つの manifest だけ**を書き直す（★ 他の `manifest*.json` を書かない —— 012 は `manifest.macos.json`、013 / 014 は `manifest.windows.json` だけを持つ）。`<spec.json>` はエントリの `kind` / `id` / `path` / `gse_path` / アンカー / `symbol` / `reason` の配列で、SHA-256 と `gse_last_commit`・その manifest の `gse_repo_commit` は照合器が計算して埋める。
  - `--selftest`（目印 `# kit: selftest`）: 一時ディレクトリで、コピーを 1 バイト変えると `--self` が赤、GSE 側を 1 バイト変えると `--against-gse` が赤、アンカーが見つからない・2 回現れると赤、`symbol` が範囲に無いと赤、`--update --manifest A` が manifest B を書き換えない（陰性対照 6 種）。
