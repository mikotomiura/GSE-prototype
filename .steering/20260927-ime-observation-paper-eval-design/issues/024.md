# Issue 024: 公開 repo への書き出し —— 除外・秘匿の検査・manifest の自己照合・CITATION と Zenodo の記述・2 回でバイト一致
verify_level: recheck
runs_on: any

## Goal

`papers/ime-observation/` を、**新しい公開 repo の中身**として一時ディレクトリへ書き出す `export.py` を作る（判断 20）。
書き出しは (1) 生ログ・ビルド生成物・封印したログを**除外**し、(2) GSE の内部の情報（被験者 ID・`.steering/`・`gse-dataset`・メール・絶対パス）が**混ざっていない**ことを検査し、
(3) 単体ロガーの manifest を**書き出した側だけで**照合でき（`check_manifest.py --self`）、(4) 2 回の書き出しが**バイト一致**する。
★ 公開 repo の作成・push・Zenodo の DOI はマイルストーン M12（外部への操作なので研究者が行う・または承認を得て行う）。

## Background

- 判断 20: GSE で開発し、公開時に新しい repo へ書き出す。⚠️ GSE の履歴は公開できない（`ci.yml:169`）→ 公開 repo は新しい履歴で始まる。★ GSE とのずれの検出は GSE 側（`check_manifest.py --against-gse`）、公開 repo の CI は `--self` だけ。
- 判断 15: コード = **Apache-2.0**、データ・シナリオ・文書 = **CC BY 4.0**。design.md §4: 置き場は DOI の付く信頼できるリポジトリ（Zenodo / OSF）。BRM は TOP Level 2（逐語 "all relevant information must be placed in a trusted repository"）・データ引用は DOI（逐語 "Data citations should include a persistent identifier (such as a DOI)"）。
- ⚠️ ライセンスの**全文**（`LICENSE-CODE` / `LICENSE-DATA`）は公式の原文を M12 でメインが取得して置く（★ worker は全文を記憶から書かない）。→ `export.py` は**無ければ止まる**。
- ⚠️ 秘匿の検査で見るもの（最低限）: 被験者 ID（`P` ＋ 3 桁。★ ただし文献番号 `[P269]` / `[V5]` のように**角括弧で囲んだもの**は許す）、`.steering/`、`gse-dataset`、`@` を含むメールアドレス、`C:\Users\` / `/Users/` の絶対パス、`gse_YYYYMMDD` 形の GSE セッション名。★ 例外は**明示した許可リスト**でだけ通す:
  - manifest の `gse_path`（`src-tauri/...` の相対パス）
  - ★★ **`kit/logger/manifest*.json` に載った逐語コピー（`kind` が `file` のファイル全体と、`excerpt` の `@excerpt-begin` 〜 `@excerpt-end` の範囲）の中の `.steering/`**（2026-09-28 に一次で確認: `ime_compose.rs:17`・`ime_cloak.rs:16-17`・`anonymize.rs` の抜粋・`hook_macos.rs:247`・`hook_windows.rs:164` がコメントに `.steering/` を持つ。逐語なので変えられない）。⚠️ 被験者 ID・メール・絶対パスは逐語コピーの中でも**許さない**。
