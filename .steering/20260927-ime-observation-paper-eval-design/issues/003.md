### 契約の解釈・issue との差（研究者が見て、意図と違えば直してほしい）

1. **ブロック数**: issue は「ブロックは速さで揃える」と「ブロック数 = `ceil(件数 / block_size)`」を同時に求めるが、シナリオ数 × n が `block_size` の倍数でないと両立しない。→ **速さごとに `ceil(シナリオ数 × n / block_size)` を数えて合計**する。倍数のとき（本番の macOS = 14 × 75 / 25・windows = 13 × 75 / 25）は issue の式と一致する。倍数でないと端数のブロックが速さごとに増える。selftest は両方（一般式と、割り切れるときの一致）を確かめている。
2. **間（`pause`）は置き換え**: 手順の `think` / `pause_ms` は、前のキーの押下から次のキーの押下までの間を**置き換える**（足さない）。S13 は space の押下から enter の押下までが 21000 ms ちょうど、S15 は focus_away → focus_back が 1000 ms ちょうど。
3. **キー間隔は「押下から次の押下まで」**で、下限は `key_hold_ms + 1`（キーは直列・重ならない）。
4. **`think_ms`**: 思考の間を使う手順の試行に、使った値を書く。使わない手順（S3 など）は 0。
5. **`intent` の既定値**（recipes のデータ・仮説）: `expect_session` は全シナリオ `true`（全 composition の定義）。S4 / S5 / S6 = `commit: none`・`abandon: true`。S10 / S11 = `cand_index: null`（候補を選ばない）。S14 = `commit: none`・`ime_toggle_mid: true`。S8 の `cand_index` は 0〜8（数字キーで選べる 1〜9 番）に頭打ち。S2 は `cand_index` を 1 以上で抽選（0 だと S1 と同じ）。
6. **試行ごとの乱数は `(seed, trial_id)` から導く**（`trial_rng`）。issue の「`build_trial` を直接呼んだ結果と CLI の出力の該当行が一致する」を、乱数の状態を再現せずに確かめるため。乱数は `random()` だけを使う（`shuffle` / `choice` / `lognormvariate` は Python の版で変わりうるので使わない）。
7. **設定**: issue の指定に加えて `assumed_reading_len`（既定 12・issue 記載）と、S12 の合成かな列の長さ `kana_len_min` / `kana_len_max`（既定 4 / 8・**issue に無い追加**）を持つ。既定があるのは `n_per_cell_scenario_speed`（75）・`block_size`（25）・上の 3 つだけで、速さ・思考の間・間隔・マーカーなどは**必須**（本番の値を黙って決めない）。設定の未知のキーは警告して無視、`_` で始まるキーはメモ。
8. **S12 の句**: かな配列だけで読みが書ける句を優先し、足りなければ `kana-<通し番号>` の合成かな列。通し番号はその計画の中だけの番号（読みは `steps` から復元できる）。
