# Issue 003: シナリオ生成器 —— seed 固定で試行計画（S1–S15 × 速さ 3 水準 × n・思考の間・ブロック・同期マーカー）と意図を出す
verify_level: parse

## Goal

`corpus/1` と OS ごとの**キーの手順（recipes）**から、1 セル分の試行計画を `plan/1`（`kit/formats/FORMATS.md`）で出す
`generate_plan.py` を作る。★ 同じ入力・同じ seed で**バイト一致**。★ 実行器（issue 004/005）はこの計画だけを見て送出する。

## Background

- design.md §1.4（シナリオ S1–S15）・§1.5（速さ 3 水準・思考の間 0.2〜20 s・n = 75 / セル × シナリオ × 速さ・1 試行 ≈ 8 s の見積もり）・§1.1b（ブロックの先頭で IME の学習をリセット）・§1.1（同期マーカー）。
- design.md §1.1〔v2〕: oracle（意図）は**正解の検証だけ**に使う。→ 計画の `intent` はその材料。
- ⚠️ **キーの手順は OS・IME で違い、較正パイロット（M1 / M5）で直る見込み**。→ ★ 手順は**コードではなくデータ**（`recipes.json`）に置き、パイロットの後はデータだけを直せばよい形にする。
- ⚠️ **速さの値（キー間隔の分布）はまだ決めない**。M3 の凍結で出典（`[Pn]`・例: [P269] Dhakal et al. 2018）と一緒に `experiment/config.json` に入れる。→ 本 issue は**設定から読むだけ**。テストは設定をテストの中で作る。
- 判断 22: Python 標準ライブラリだけ。

## Scope

### In
- `papers/ime-observation/kit/gen/romaji.py`（新規）: ひらがな → ローマ字のキー列（`keyname` の列）。
  - 決定的な 1 つの表（ヘボン式寄り）。`ん` は常に `nn`、促音 `っ` は次の子音を重ねる（次が母音・`ん`・語末なら `xtu`）、小書き `ゃゅょぁぃぅぇぉ` は拗音でなければ `x` 接頭、`ー` は `minus`、`、` `。` は `comma` `period`。
  - `--selftest`（目印つき）: 表の網羅（`ぁ`〜`ゖ` と `ー` のすべてに写像がある）、逆写像で**元のひらがなに戻る**（一意性）、`がっこう` → `g a k k o u` などの既知例。
- `papers/ime-observation/kit/gen/recipes.json`（新規）: OS（`macos` / `windows`）× シナリオの手順テンプレート。要素は `{"type_reading":true}` / `{"key":…}` / `{"repeat":…,"times":"cand_index+1"|"nav_count"|"reading_len"}` / `{"pause":"think"}` / `{"pause_ms":<int>}`。意図（`intent`）の既定値もここに書く。
  - 既定の手順（★ 仮説。パイロットで直す）: S1 = 読み → `space` → think → `enter` ／ S2 = 読み → `space`×(cand_index+1) → think → `enter` ／ S3 = 読み → `enter` ／ S4 = 読み → `space` → think → `esc` → `esc` ／ S5 = 読み → `esc` ／ S6 = 読み → `backspace`×reading_len ／ S7 = 読み → `space` → `right`×nav_count → think → `enter` ／ S8 = 読み → `space` → `space` → think → 数字キー（cand_index+1）／ S9 = **既定で無効**（issue 026）／ S10 = 読みの前半 → `tab` → think → `enter` ／ S11 = macOS のみ（ライブ変換 ON のセルで使う）読み → `enter` ／ S12 = かな入力（下記）→ `space` → `enter` ／ S13 = 読み → `space` → `pause_ms` 21000 → `enter` ／ S14 = 読み → `space` → `ime_off` → `ime_on` ／ S15 = 読み → `space` → `focus_away` → `pause_ms` 1000 → `focus_back` → `enter`。
  - S12 用の `kana_layout`（JIS かな配列で `keyname` だけで打てるかな → キー）: `q`=た `w`=て `e`=い `r`=す `t`=か `y`=ん `u`=な `i`=に `o`=ら `p`=せ `a`=ち `s`=と `d`=し `f`=は `g`=き `h`=く `j`=ま `k`=の `l`=り `z`=つ `x`=さ `c`=そ `v`=ひ `b`=こ `n`=み `m`=も `1`=ぬ `2`=ふ `3`=あ `4`=う `5`=え `6`=お `7`=や `8`=ゆ `9`=よ `0`=わ `minus`=ほ `comma`=ね `period`=る。読みがこれだけで書ける句を選び、足りなければ seed 固定の**合成かな列**（`phrase_id` が `kana-` で始まる）で埋める。
- `papers/ime-observation/kit/gen/generate_plan.py`（新規）
  - `generate_plan.py --corpus <file> --recipes <file> --config <json> --os macos|windows --seed <int> --out <plan>`
  - 設定のキー（★ 名前はこのとおり）: `n_per_cell_scenario_speed`（既定 75）/ `block_size`（既定 25）/ `scenarios`（有効なシナリオの配列）/ `speeds`（`slow` `mid` `fast` ごとに `iki_median_ms` と `iki_sigma` = 対数正規）/ `key_hold_ms` / `think_ms`（`min` `max`・対数一様）/ `cand_index_max` / `nav_count_max` / `inter_trial_ms` / `marker`（`keyname` の配列）/ `marker_gap_ms` / `reset_ime_every_block`。
  - 出力: `plan/1`。★ **ブロックは速さで揃える**（1 ブロック = 1 つの速さ。ブロック行に `speed` を書く）。ブロックの中の試行順（シナリオの並び）は seed で並べ替え、ブロックの並びも seed で並べ替える。各キーは `down: true` と `down: false`（`key_hold_ms` 後）の 2 ステップ。`at_ms` は**試行の先頭からの相対**。★ 試行行に `gap_before_ms`（= 設定の `inter_trial_ms`）、ブロック行に `marker_gap_ms`（= 設定の `marker_gap_ms`）を書く（実行器はこの値だけで待つ）。
  - ★ **公開する関数**（issue 021 が import して攻撃者の予想ログを作る・★ 名前と引数はこのとおり）: `build_trial(phrase: dict, scenario: str, speed: str, os_name: str, recipes: dict, config: dict, rng: random.Random, trial_id: str, block_id: int) -> dict`（`plan/1` の試行行 1 つを返す）と `load_recipes(path) -> dict`。★ CLI は内部でこの関数を使う（同じ入力で CLI と関数の出力が一致する）。
  - `--validate <plan>`: `plan/1` の検査（ヘッダ・`block_id` の参照・`scenario`・`speed`・`keyname` の列挙・`at_ms` の単調非減少・`down`/`up` の対）。違反で exit 1。
  - `--estimate --config <json> --recipes <file> --os <os> [--corpus <file>]`: 1 セルの所要時間（全ステップ ＋ 試行間）を秒で出す（★ design.md §1.5 の 7.5 時間の見直しに使う）。`--corpus` が無ければ読みの長さを 12 字と仮定する（設定 `assumed_reading_len` で変えられる）。
  - `--selftest`（目印つき）: テストの中で小さなコーパスと設定を作り、次を確かめる:
    - 同じ入力・同じ seed で**バイト一致** ／ ⚠️ seed を変えると試行順が変わる（陰性対照）
    - 件数 = シナリオ数 × 速さ 3 × n、ブロック数 = ceil(件数 / block_size)
    - 速さの水準でキー間隔の中央値が**順に**並ぶ（slow > mid > fast）
    - ★ 各ブロックの試行の `speed` がブロック行の `speed` と一致する（ブロックが速さで揃っている）
    - ★ `build_trial` を直接呼んだ結果と CLI の出力の該当行が一致する
    - `--validate` が正しい計画を通し、壊した計画（未知の keyname・`at_ms` の逆行）を拒否する
    - S9 が既定で出ない / S11 が `windows` で出ない
- `papers/ime-observation/kit/gen/README.md`（新規）: 使い方・設定のキー・recipes の書き方・「パイロットの後に直すのはデータだけ」。
