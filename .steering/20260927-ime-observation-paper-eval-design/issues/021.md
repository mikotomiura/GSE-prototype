# Issue 021: E2 閉集合のシミュレーション攻撃と特徴の除去実験
verify_level: parse
runs_on: any

## Goal

公開・提出される形のログ（`key` 行の category と時刻・`ime_shadow` 行）から、**候補文 K 個のどれを打ったか**を当てる
閉集合の攻撃（K2）を作る。★ 攻撃者は各候補文を**同じシナリオ生成器に通して予想ログを作り**、観測ログに最も近い候補を選ぶ（現実的な最強の閉集合攻撃）。
あわせて**特徴の除去実験**（時刻を消す / `alphabetic` の連続長を消す / 1 秒ビンに粗くする）で、同定率がどれだけ下がるかを出す。

## Background

- design.md §2: 攻撃者が見るもの = 公開される形の NDJSON（`key` 行の category と時刻、`ime_shadow` 行）。⚠️ 生 `vk` は含まない（ADR-014 判断 6）。`KeyCategory` は 14 種で英字は `alphabetic` 1 つに畳まれる。攻撃者の知識の段 K0 / K1 / K2。A2（K2）= 候補文 K 個（K = 10 / 100 / 1000）・指標 = 正解率 vs 偶然 1/K。★ 除去実験 → **公開粒度の推奨**（design.md §5 の 10 節）。
- ⚠️ decisions.md 判断 6: **同定はかなりできる見込み**なので、**結果が悪くてもそのまま報告する**。⚠️ 攻撃の強さの上限は主張しない（「この攻撃では」と限定）。
- 攻撃者のモデル（予想ログ）: 計画のステップ（`keyname`）→ category の写し。★ `keyname` → category の表は GSE の `KeyCategory::from_vk`（`src-tauri/src/analysis/anonymize.rs:59` ・単体ロガーでは `kit/logger/src/key_category.rs` に逐語の抜粋）に**合わせる**。⚠️ Python に写すので、写し間違いは攻撃を弱める方向に働く（保守的）—— ★ それでも写しの根拠（どの VK をどの category にしたか）を README に表で書く。
- 生成器（issue 003）の**公開関数** `build_trial(phrase, scenario, speed, os_name, recipes, config, rng, trial_id, block_id)` と `load_recipes(path)` を import して予想ログを作る（★ 再実装しない）。統計は `stats.py`（issue 016）の `wilson`。
- ⚠️ データ: E1 と同じ合成入力（青空文庫の句）。人のデータは使わない。★ 本 issue の検査は**合成の観測ログ**（計画から作ったもの）だけで行う。

## Scope

### In
- `papers/ime-observation/kit/e2/simulate_obs.py`（新規）: `simulate(plan_trial, keycat, timing="exact"|"none"|"bin1s", runs="exact"|"count") -> [(t, category)]`。`keycat` = `keyname` → category の表（このファイルに定数で持つ）。
- `papers/ime-observation/kit/e2/closed_set.py`（新規）
  - `attack(observed, candidates, scenario, os, recipes, config, features, seed) -> {"chosen", "rank_of_true"}`: 候補ごとに予想ログを作り、category 列の編集距離（＋ `features` が時刻を含むなら打鍵間隔の差）で最も近い候補を選ぶ。同点は `random.Random(seed)` で決める。
  - `evaluate(trials, corpus, K, features_list, seed) -> {features: {"acc", "acc_ci", "chance": 1/K, "n"}}`。
  - CLI: `--obs <obs>... --plan <plan>... --corpus <corpus> --recipes <json> --config <json> --K 10,100,1000 --out <json>`。
  - `--selftest`（目印 `# kit: selftest`）: 合成の観測（計画から `simulate` で作り、時刻に σ 30 ms の揺らぎ）で、
    - 全特徴では正解率が偶然 1/K を**大きく超える**（K = 10 で ≥ 0.5）
    - ⚠️ 陰性対照: 観測を**全部同じ category 列・同じ時刻**にすると正解率が 1/K の Wilson CI に入る
    - 除去実験: 特徴を減らすと正解率が**単調に下がらない場合もそのまま**出す（★ 期待に合わせて並べ替えない）
    - 同じ seed で**バイト一致**
- `papers/ime-observation/kit/e2/README.md`（新規）: 攻撃者の知識の段、攻撃の手順、`keycat` の表と根拠、⚠️「この攻撃では」の限定、公開粒度の推奨をどう導くか。

### 設計上の判断（残課題・限界を含む）
- 攻撃の固定値 `PAUSE_MS=600` / `TAU_MS=1000` / `W_TIME=0.5` は設計として先に決め、結果を見て調整していない。
- 予想ログの乱数は全候補で共通（common random numbers）。攻撃者が選んでよい設計。
- 攻撃者に試行の境界・シナリオ・OS・速さの水準を与える（強める方向）。境界の推定は含めない。`ime_shadow` は読むが使わない。
- 合成の selftest の世界では `no_time`（0.833）・`counts_only`（0.840）が `all`（0.787）以上になった（K=10・seed 固定の 1 世界）。時刻の特徴が句に依らない長い間の大きさだけを見るため。**期待に合わせて並べ替えず、そのまま出す**（README に明記）。
- ⚠️ `KEYCAT` の None（ime_on / ime_off / f13〜f19）が「ロガーが行を作らない」ことは**実機のログで未確認**（較正パイロットで確かめる）。README に前提として書いた。
- ⚠️ CLI の `--obs` / `--plan` は押下数と category の列が計画と一致しないと止まる（fail-closed）。実データでマーカーの押下が観測に出るかは未確認なので `--markers-in-obs` で切り替える。実データでの実行は凍結の後（M8）。
- attempt 数は loop-run.sh が events に記録する（worker 側では数えない）。

### merge ゲートの直し（2026-09-28）

merge 前レビューの指摘（HIGH ×2）と判断 39 を受けて、`closed_set.py` / `simulate_obs.py` / `README.md` を直した。

1. **除去実験の逆転（判断 39・HIGH）**: `evaluate()` の `acc` を「その特徴集合と、そこから作れる粗い集合（`coarser_or_equal` の包含関係）の生の正解率の最大」に変更（`acc_source` が出所を示す）。生の値は `acc_raw`/`acc_ci_raw` として併記。公開粒度の推奨は `acc` を根拠にする（README に明記）。selftest に単調性の検査（`acc(F) >= acc(G)` for `G in coarser_or_equal(F)`）を追加。
2. **窓を使う特徴の距離（判断 39・HIGH）**: (a) 予想ログの `timing="bin1s"` 判定に位相探索を追加（`PHASES` = 0〜900ms を 100ms刻み・`Predictor.tokens` が位相ごとの候補を持ち `attack()` が最小を取る）。(b) `runs="count"` の集約を「1秒窓ごと」から「区切り（delimiter）の間」に変更（`simulate_obs.apply_features`）。(c) `_gap()` に `timing` を渡し、`bin1s` の場合は 1 窓分を割り引いてから `PAUSE_MS` と比較（境目 1 つ分は「間」として罰しない）。
3. **囮の選び方（判断 39・HIGH）**: `_scenario_pool()` を追加し、そのシナリオ・OS で計画生成器が実際に選べる句（かな入力なら kana_layout で打てる句だけ・recipes の reading_len の範囲）だけから囮を引くようにした。selftest の世界に S12（かな入力）を追加し、かな入力に使う読みは kana_layout の文字だけから合成するように直した。陰性対照（情報の無い観測で偶然水準）に S12 を含めて確認。
4. **S10 の正誤判定（MEDIUM）**: `_typed_reading()`（`generate_plan.typed_reading` のラッパ）を追加し、`_make_candidates()` の重複除去と `evaluate()` の正誤判定を「打った読み」基準に変更（S10 の前半一致・S12 の合成かな列も対象）。
5. **シナリオ別内訳（MEDIUM）**: `evaluate()` の返り値に `by_scenario`（特徴集合ごとにシナリオ→{acc, n}）を追加。
6. **markers/ime-toggle スイッチ（MEDIUM）**: `--ime-toggle-in-obs`（既定オフ）を追加し、`--markers-in-obs` と対称にした。両方とも既定は「観測に行が出ない」。根拠（Windows の `is_observed_key` の外）を README の 1 箇所（キー表の直後）にまとめた。022 も同じ名前・同じ既定に揃える必要がある（未着手、022 側の issue で対応）。
7. **security（LOW）**: `read_obs`/`--config` の JSON 読み込みに `object_pairs_hook` で重複キー拒否、`RecursionError` を捕捉して深い入れ子でも Traceback でなく exit 2 に。`--out` は `open(path, "xb")` にして try の中へ（既存ファイルを上書きしない）。obs ヘッダの `os` を検査し、plan の `os` と一致しないと `segment_by_plan` が拒否する。`ime_shadow` 行の値の型（`dwell_ms`/`nav` は非 bool の int、`abandon` は bool）を検査。
