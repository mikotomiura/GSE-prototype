# Issue 013: 単体ロガーの Windows ドライバ (1) —— 低水準キーボードフック（`key` 行・nav・abandon）と IME 窓の表示/非表示の WinEvent
verify_level: parse

## Goal

issue 011 の差し込み口 `driver_windows.rs` に、Windows のドライバの**前半**を実装する。

1. `WH_KEYBOARD_LL` のフックで打鍵を受け、`key` 行の材料 `(t, vk, press)` を核へ送る。IME の変換中（`IME_ACTIVE`）は矢印で `IME_CANDIDATE_NAV_COUNT` を増やし、ESC で `IME_SHADOW_ABANDON` を立てる（GSE と同じ判断）。
2. `SetWinEventHook`（**`WINEVENT_OUTOFCONTEXT`**）で IME の窓の表示・非表示（`EVENT_OBJECT_IME_SHOW` / `HIDE` / `CHANGE`）を受け、変換セッションの開始・終了を Atomic に書く（GSE の `win_event_callback` と同じ判断）。

★ これで Windows の単体ロガーが**旧来の経路**で `ime_shadow` 行を出せる。DWM cloak の経路（Windows 11 の新しい候補窓）は issue 014。

1. **実機で打鍵して `key` 行・`ime_shadow` 行が出ることは未確認（M5・Out of Scope）。** 特に `t` はコールバックの実行時刻で、ポーリング間隔（1 ms sleep）だけ実イベントより遅れうる。`MsgWaitForMultipleObjects` に替える案（security-checker LOW）は、実機で配送を確かめられないまま参照実装の実績ある形から外れるので採らなかった。M5 で時刻のずれを測ってから決める。
