# Issue 013: 単体ロガーの Windows ドライバ (1) —— 低水準キーボードフック（`key` 行・nav・abandon）と IME 窓の表示/非表示の WinEvent
verify_level: parse
runs_on: windows

## Goal

issue 011 の差し込み口 `driver_windows.rs` に、Windows のドライバの**前半**を実装する。

1. `WH_KEYBOARD_LL` のフックで打鍵を受け、`key` 行の材料 `(t, vk, press)` を核へ送る。IME の変換中（`IME_ACTIVE`）は矢印で `IME_CANDIDATE_NAV_COUNT` を増やし、ESC で `IME_SHADOW_ABANDON` を立てる（GSE と同じ判断）。
2. `SetWinEventHook`（**`WINEVENT_OUTOFCONTEXT`**）で IME の窓の表示・非表示（`EVENT_OBJECT_IME_SHOW` / `HIDE` / `CHANGE`）を受け、変換セッションの開始・終了を Atomic に書く（GSE の `win_event_callback` と同じ判断）。

★ これで Windows の単体ロガーが**旧来の経路**で `ime_shadow` 行を出せる。DWM cloak の経路（Windows 11 の新しい候補窓）は issue 014。

## Background

- 一次（2026-09-28 に確認）: `src-tauri/src/input/hook_windows.rs` —— `is_observed_key`（`:118`）/ `classify_ime_nav_key`（`:146`）/ `win_event_callback`（`:191`）/ `start`（`:327`・フックの登録 `:367`・WinEvent の登録 `:384-391` は `WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS`）/ `hook_callback`（`:563`・nav と abandon は `:612-617`）。
- ★ 抜粋の逐語コピー（`manifest.windows.json`）にするもの: `is_observed_key` と `classify_ime_nav_key`（と、それが返す列挙型）—— **純粋関数**。★ 2026-09-28 追記（判断 35・attempt 1 の Stop を受けた 011 の追補）: `is_observed_key` の本体の先頭が呼ぶ `crate::analysis::key_gate::is_feature_key` は、**核に逐語コピー済み**（`src/analysis/key_gate.rs`・`main.rs` の `mod analysis;`・`manifest.json` の `key_gate`）。→ 抜粋はそのまま `crate::analysis::key_gate` を呼べる（`main.rs` は変えない）。⚠️ コールバックと登録は `crate::logger` / GSE の Atomic に絡むので**新規に書く**（同じ判断を同じ順で）。
- ★ 抜粋の書き方（issue 011 の `check_manifest.py` の規則）: コピー側は `// @excerpt-begin <id>` と `// @excerpt-end <id>` の**間**に逐語で置く（前置きの `use` は目印の外）。GSE 側は開始アンカー（行全体の一致・ファイルの中で 1 回だけ）〜終了アンカーの前。★ 関数の抜粋には **`symbol`（関数名）** を必ず入れる。★ manifest は `check_manifest.py --update --manifest manifest.windows.json --entries <spec.json>` で**自分の manifest だけ**を書く（`manifest.json` を書き換えない）。
- ⚠️ `hook-constraints` Win-1: フックのコールバックで許されるのは **Atomic 操作と channel の送信だけ**。Win-2: `CallNextHookEx` を**必ず**呼ぶ。共通-3: イベントの取りこぼしは許容（ブロックしない）。
- ⚠️ `architecture-rules` ルール 5 / `docs/agent-shared.md` 制約 7: **DLL 注入を伴うグローバルフック（`WH_GETMESSAGE` / `WH_CALLWNDPROC`）は禁止**。★ 使ってよいのは `WH_KEYBOARD_LL` と `WINEVENT_OUTOFCONTEXT` の WinEvent だけ（コールバックの引数に文字列が 1 つも無い）。
- ⚠️ 合成入力（`LLKHF_INJECTED`）を**捨てない**（GSE も捨てない・design.md §1.1a の手順 3。実行器の合成キーを観測するため）。
- ドライバの Atomic のうち 011 のシムに無いものは `driver_windows` の中に置く（★ シムは 011 の Allowed Files）。`main.rs` は触らない。サブモジュールは `src/driver_windows/` に置く。
