# Issue 005: 実行器の Windows バックエンド（SendInput・scan code）
verify_level: parse
runs_on: windows

## Goal

issue 004 の核（`emit.py`）に、Windows の送出バックエンド `backend_windows.py` を足す。`user32!SendInput` を `ctypes` で呼び、
文字キーは **scan code**（`KEYEVENTF_SCANCODE`）で送る。⚠️★★★ 既定は送らない（核の規則をそのまま使う）。

## Background

- design.md §1.1: Windows = `SendInput`（scan code）。
- 判断 18: Windows 専用の issue は G-GEAR でループを回す。判断 22: Python 標準ライブラリ ＋ `ctypes`。
- 核（issue 004）はバックエンドを名前で読み込む（`backend_<name>.py`）。★ **核のファイルは触らない**。
- ⚠️ Windows の既定のタイマー分解能は 15.6 ms。★ `Backend.open()` で `winmm!timeBeginPeriod(1)`、`Backend.close()` で `timeEndPeriod(1)`（★ 核が try / finally で `close()` を必ず呼ぶ —— 境界は issue 004 が固定した `SUPPORTED_KEYS` / `Backend(opts)` / `open` / `send` / `close`）。
- `ime_on` / `ime_off` は `VK_IME_ON`（`0x16`）/ `VK_IME_OFF`（`0x1A`）を仮想キーで送る（★ パイロットで効くか確かめる。効かなければ M5 で keymap を直す）。矢印は拡張キー（`KEYEVENTF_EXTENDEDKEY`）。
- `focus_away` / `focus_back`: 別の窓を前面に出して戻す。★ 手段は worker が選んでよいが、**決定的**であること（同じ計画で毎回同じ窓に移る）と、README に書くこと。

## Scope

### In
- `papers/ime-observation/kit/emit/backend_windows.py`（新規）
  - `INPUT` / `KEYBDINPUT` の構造体を `ctypes` で定義し、`SendInput` を呼ぶ。送出後の戻り値（送れた件数）を確かめ、0 なら例外。
  - `--probe`: `user32` と `winmm` を読み、`a` の `INPUT` を**作るだけ**（送らない）。exit 0。
  - `--selftest`（目印 `# kit: selftest`）: ⚠️ **送らない**。`keymap_windows.json` の網羅・構造体の大きさ（`ctypes.sizeof(INPUT)` が 64bit で 40）・`timeBeginPeriod` の対が例外時にも戻ることをモックで確かめる。★ Windows 以外では「対象外」と出して exit 0（`check.sh` を他 OS で赤にしない）。
- `papers/ime-observation/kit/emit/keymap_windows.json`（新規）: `keyname` → `{"scan": int, "ext": bool}` または `{"vk": int}`。`mouse_click` / `focus_*` を除く全 keyname。

### Out
- ⚠️ `emit.py` / `backend_dryrun.py` / `backend_macos.py` / `keymap_macos.json` / `README.md` を**触らない**（issue 004 の Allowed Files）。Windows の注意書きは `backend_windows.py` の冒頭の docstring に書く。
- ⚠️ 実際の送出を伴う試験（M5 のパイロット）。
