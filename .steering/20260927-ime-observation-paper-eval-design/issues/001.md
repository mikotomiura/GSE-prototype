**(2) ログ形式の契約** `papers/ime-observation/kit/formats/FORMATS.md`（新規）

共通: JSON Lines・UTF-8・1 行 1 オブジェクト。**1 行目はヘッダ**。時刻は整数（`t_wall_ms` = Unix ms・`t_mono_ns` = 単調時計 ns）。
★ **区切りに空白を入れない**（`{"a":1,"b":2}` の形。Python は `json.dumps(obj, ensure_ascii=False, separators=(",", ":"))`）。⚠️ 後続の検査は `"kind":"sent"` のような空白なしの文字列で行を探すので、空白を入れると検査が素通り・誤って赤になる。★ `validate_logs.py` は `gt` / `obs` の行に `": "` / `", "`（文字列の外）があれば拒否する。

- **`gt/1`**（参照入力欄が出す正解の生ログ・issue 007/008/009）
  - ヘッダ: `{"kind":"header","format":"gt/1","src":<"mac_nstic"|"win_imm"|"win_tsf">,"app_version":<str>,"os":<"macos"|"windows">}`
  - イベント: `{"kind":"ev","t_wall_ms":int,"t_mono_ns":int,"ev":<enum>, ...}`
  - `ev` と付随フィールド（**付随フィールドは整数か真偽値だけ**。`cmd` / `ui_kind` のみ列挙型の文字列）:

    | src | ev | 付随フィールド |
    |---|---|---|
    | 共通 | `key_down` | `vk`（OS のキーコード）|
    | 共通 | `focus_in` / `focus_out` | なし |
    | `mac_nstic` | `set_marked` | `len`, `sel_loc`, `sel_len`, `rep_loc`?, `rep_len`? |
    | `mac_nstic` | `insert_text` | `len`, `rep_loc`?, `rep_len`? |
    | `mac_nstic` | `unmark` / `first_rect` | なし |
    | `mac_nstic` | `do_command` | `cmd` ∈ {`insertNewline:`, `cancelOperation:`, `deleteBackward:`, `deleteForward:`, `moveLeft:`, `moveRight:`, `moveUp:`, `moveDown:`, `insertTab:`, `insertBacktab:`, `noop:`, `other`} |
    | `win_imm` | `start_comp` / `end_comp` | なし |
    | `win_imm` | `comp` | `flags`（GCS_* のビット）, `comp_len`, `result_len` |
    | `win_imm` | `notify` | `imn`（IMN_* の値）|
    | `win_tsf` | `tsf_start` / `tsf_end` | `tsf_end` のみ `result_len`? |
    | `win_tsf` | `tsf_update` | `len` |
    | `win_tsf` | `ui_begin` / `ui_update` / `ui_end` | `ui_kind` ∈ {`candidate`, `reading`, `other`} |

    長さはすべて **UTF-16 のコード単位数**。`?` は省略可。
  - ⚠️★★★ **content-free の規則**: 文字列を値に持てるのは `kind` / `format` / `src` / `app_version` / `os` / `ev` / `cmd` / `ui_kind` だけ。`app_version` は正規表現 `^[0-9A-Za-z.+-]{1,32}$`、他は上の列挙のどれか。**未知のキーは拒否**、整数の位置に文字列・配列・オブジェクトが来たら拒否。
- **`obs/1`**（単体ロガーの出力・issue 011–014）★ GSE の NDJSON 行と**同じ名前**
  - ヘッダ: `{"type":"meta","format":"obs/1","os":<"macos"|"windows">,"logger_version":<str>,"manifest_sha256":<64 hex>,"capabilities":<object>}`
  - ★ `capabilities` は GSE の `meta.capabilities` と**同じ形**（一次: `src-tauri/src/capabilities.rs:319-332` の `capabilities_json()`）= `{"unconditional":[<名前>…],"threshold_gated":[<名前>…],"config_gated":[<名前>…]}`。**3 つのキーはすべて必須**で、値は**文字列の配列**（空でよい）。名前は正規表現 `^[a-z][a-z0-9_]{0,39}$`（行の種類の名前）。★ 単体ロガーでは名前は `key` と `ime_shadow` の 2 つだけが現れる（issue 011）。
  - `{"type":"key","t":int,"category":<14 種>,"press":bool}` —— category は `alphabetic` / `numeric` / `punctuation` / `sentence_punctuation` / `tab` / `backspace` / `delete` / `space` / `enter` / `navigation` / `modifier` / `function` / `escape` / `other`（`schema_dto.rs:121-126`）
  - `{"type":"ime_shadow","t":int,"dwell_ms":int,"nav":int,"abandon":bool}`
  - ⚠️ 上以外の `type`・未知のキー・列挙外の文字列は拒否。
- **`plan/1`**（生成器の出力・issue 003）: ヘッダ `{"kind":"header","format":"plan/1","os":…,"seed":int,"generator_version":str,"config_sha256":<64 hex>}`、`{"kind":"block","block_id":int,"speed":"slow"|"mid"|"fast","reset_ime":bool,"marker":[<keyname>…],"marker_gap_ms":int}`、`{"kind":"trial","trial_id":str,"block_id":int,"scenario":"S1"…"S15","speed":"slow"|"mid"|"fast","gap_before_ms":int,"think_ms":int,"phrase_id":str,"reading_len":int,"steps":[{"key":<keyname>,"at_ms":int,"down":bool}…],"intent":{…}}`。★ `gap_before_ms` = 前の試行の終わりからこの試行の先頭までの待ち、`marker_gap_ms` = マーカーのキーの間隔（実行器はこの 2 つの値だけで待つ・自分で決めない）。★ **ブロックは速さで揃える**（1 ブロック = 1 つの速さ。ブロック行の `speed` と、その中の試行の `speed` は一致する）。`intent` のキーは `commit`（`enter`/`digit`/`mouse`/`none`）・`cand_index`・`nav_count`・`abandon`・`predictive`・`ime_toggle_mid`・`focus_switch_mid`・`expect_session`。★ 計画は刺激（公有の文の読み）なので content-free の対象ではない。
- **`oracle/1`**（実行器の出力・issue 004/005）: ヘッダ `{"kind":"header","format":"oracle/1","plan_sha256":…,"os":…,"emitter_version":…,"backend":<"dryrun"|"macos"|"windows">}`、`{"kind":"sent","trial_id":…,"step":int,"key":<keyname>,"down":bool,"t_wall_ms":int,"t_mono_ns":int}`、`trial_begin` / `trial_end` / `block_begin` / `block_end`（`trial_id` または `block_id` ＋ 2 つの時刻）、`{"kind":"marker","block_id":int,"seq":int,…時刻}`、`{"kind":"reset","block_id":int,"exit_code":int,…時刻}`。
- **`corpus/1`**（句と読み・issue 002）: ヘッダ `{"kind":"header","format":"corpus/1","source":"aozora","tokenizer":str,"dict":str}`、`{"kind":"phrase","phrase_id":str,"work_id":str,"text":str,"reading":str,"reading_len":int}`。`reading` は**ひらがなだけ**（`^[ぁ-ゖー]+$`）。
- `keyname` の列挙: `a`–`z`, `0`–`9`, `space`, `enter`, `esc`, `backspace`, `tab`, `left`, `right`, `up`, `down`, `minus`, `comma`, `period`, `ime_on`, `ime_off`, `f13`–`f19`, `shift`, `mouse_click`, `focus_away`, `focus_back`（最後の 2 つは実キーではなく、実行器のバックエンドが OS の手段で前面のアプリを切り替える擬似キー・S15 用）。

**(3) 検査器** `papers/ime-observation/kit/formats/validate_logs.py`（新規）
- `validate_logs.py --kind gt|obs FILE...` → 規則違反を行番号つきで出して **exit 1**、違反なしなら exit 0。
- ★ 本 issue が機械検査するのは **`gt` と `obs` だけ**（content-free が要るもの）。`plan` / `oracle` / `corpus` の検査は生産側の issue（003 / 004 / 002）が自分の selftest で持つ。
- `--selftest`: 陽性対照と陰性対照を**両方**持つ。最低限:
  - 正しい `gt`（3 つの `src` それぞれ）と正しい `obs` が通る
  - ⚠️ `gt` の行に**文字列の本文**（例: `"text":"日本語"` / `"len":"3"` / `"cmd":"insertText:"`）→ 拒否
  - ⚠️ 未知のキー → 拒否 / ヘッダが無い → 拒否 / `format` が違う → 拒否
  - ⚠️ `obs` の `category` が 14 種の外 → 拒否 / `ime_shadow` に `text` キー → 拒否
  - `obs` の `meta` が GSE と同じ形の `capabilities`（3 キー・配列）なら通り、⚠️ 配列の中に名前の正規表現に合わない文字列（例: `"日本語"`）・キーの欠落 → 拒否
  - ⚠️ 空白入りの区切り（`{"kind": "ev", …}`）→ 拒否
- ファイル先頭付近に目印のコメント `# kit: selftest` を置く（`check.sh` が拾う）。

**(4) 検証の入口** `papers/ime-observation/kit/check.sh`（新規）
- 既定: `kit/` 配下で `# kit: selftest` を含む `.py` をすべて探し、`python3 <file> --selftest` を順に回す。1 本でも赤なら exit 1。⚠️ **1 本も見つからなければ exit 1**（空振りの緑を出さない）。
- 各 selftest の所要時間を出し、**1 本が 30 秒を超えたら警告**を出す（止めない）。★ verify で毎回・各 acceptance でも回るので、後続の issue の selftest は**速い既定**（重い検査は `--selftest --full` などに分ける）で書く —— この規則を `check.sh` の冒頭のコメントと README に書く。
- `--compile`: `kit/` 配下の全 `.py` を `python3 -m py_compile`。
- `--self-test`: 一時ディレクトリに「緑になる selftest」と「赤になる selftest」を作り、入口が**赤を赤として返す**ことを確かめる（陰性対照）。
- `python3` が無ければ `python` を使う。`PYTHONUTF8=1` を付ける。⚠️ bash 3.2 で動くこと（変数は `${VAR}` で括る。多バイト文字の直前に括らない変数を置かない）。

### 契約の解釈（仕様を足したのではなく、issue の文言を機械で判定できる形にした所）

研究者が見て、意図と違えば直してほしい。`FORMATS.md` にも書いてある。

1. **区切りの空白**: issue は「`": "` / `", "`（文字列の外）」を拒否と書く。実装は**文字列の外の空白すべて**を拒否する
   （`"kind" :"sent"` のような形も、後続の検査が空白なしの文字列で行を探すことを素通りさせるため）。
2. **整数の範囲**: `obs` は GSE の型に合わせて `t` / `dwell_ms` が 0〜2^64−1・`nav` が 0〜2^32−1、`gt` は −2^63〜2^64−1。
   巨大な整数に本文を詰められないようにするため。あわせて小数・指数表記・`NaN`・`Infinity`・1 行内の重複キーを拒否する。
3. **`logger_version`**: issue は `<str>` としか書かない。content-free のため `app_version` と同じ正規表現で縛った。
4. **行末**: LF。CRLF は許す（Windows の生産側が text mode で書いても赤にしない）。
5. **見ていないもの**: `src` と `os` の対応（`mac_nstic` ↔ `macos` など）・時刻の単調性・`comp` の `flags` の意味。issue の仕様に無いので足していない。
