# Issue 002: 青空文庫の本文から句を切り出し、ひらがなの読みを付ける前処理（辞書は注入可能にし、テストは辞書なしで回す）
verify_level: parse
runs_on: any

## Goal

青空文庫のテキスト（ローカルのファイル）から、シナリオが要求する長さの**句**を切り出し、**ひらがなの読み**を付けて
`corpus/1`（`kit/formats/FORMATS.md`）で書き出す `build_corpus.py` を作る。
★ 読みの付与は SudachiPy（判断 19）だが、**トークナイザは差し替え可能**にし、selftest は辞書なしで回す。

## Background

- 判断 19: 読みは `sudachipy` ＋ `sudachidict_core`（どちらも Apache-2.0）を**前処理だけ**に使う。1 回走らせて句 ＋ 読みを確定し、SHA-256 を `experiment/data.md` に記録する。以降の実行は辞書に依存しない。
- design.md §1.5: 「青空文庫（著作権切れ）の文から、シナリオが要求する長さの句を seed 固定で抽出する」。
- ⚠️ **E1 の正解は変換事象**なので、読みが原文と違っても打鍵列として妥当なかなであれば足りる。**E2 の正解は「打った読み」**（原文ではない）。
- 青空文庫のテキストは Shift_JIS（cp932）で、注記の記法がある: ルビ `《…》`、ルビの始まり `｜`、注記 `［＃…］`、作品末尾の底本情報。
- ⚠️ ループの worker は**ネットワークにも pip にも触れない**。辞書の導入と本番の実行はマイルストーン **M0**（`_issue-plan.md`）でメインが行う。

### 残課題・M0 と後続 issue への申し送り

- ⚠️ **Sudachi の経路は偽の `sudachipy`（`sys.modules` に差す）でしか確かめていない**（呼び出しの形 `dictionary.Dictionary().create()` /
  `tokenizer.Tokenizer.SplitMode.C` / `reading_form()`・カタカナ→ひらがな・版の取得名 `SudachiPy` / `SudachiDict-core`）。worker はネットワークにも pip にも
  触れないので、**本物の辞書での初回の実行は M0**。M0 では出力の読みを目で見ること（固有名詞・旧字体・歴史的仮名遣いの作品）。
- **「句」の定義は issue に無かったので決めた**: 節（`、`・空白で区切った単位）を、読みの合計が `--min-reading` に届くまで隣と束ねて 1 句にする
  （届いた時点で止める・max は超えない）。読みの長さの分布は自然な節の長さに従う。★ 異論があれば `phrases_of()` の 1 関数だけを直す。
- `--per-work` の既定（100）は仮の値。本番の値は M0 で決め、`experiment/data.md` に seed とともに書く。
- **同じ読みの句の重複を除去していない**（別 `phrase_id`・同じ `reading`）。E2 の閉集合（K = 1000）で問題になるかは issue 021 で確かめる。
  issue に無い挙動を足さないため、ここでは入れていない。
- `--validate` は `phrase_id` を `<work_id>-<n>-<m>`（作品名が `work_id` と一致）だけ受ける。合成かな列 `kana-<n>` は生成器（issue 003）が計画に直接埋めるので、corpus ファイルには出ない前提。
- この worktree は Windows・Python 3.11.9 で実行した。macOS 標準の python3（3.9 想定）でも動くよう 3.8 互換の構文だけを使ったが、**3.9 では未実測**。
