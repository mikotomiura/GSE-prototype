# 設計 — 非打鍵区間をどう受けるか

## ★ 結論の骨格（★ 3 つの穴は 1 つの設計で 2 つ閉じる）

```
7-c（判定量が空欄）  ─┐
                      ├─→ ★ 新しい量を作らない。既存判定量（G2 の上下界の幅）を
7-a（空白の受け方）  ─┘     打鍵密度で層別して読むだけ（NK-5）。
                            ⚠️ そのために必要なのは「非打鍵区間を上下界の中に入れる」規則だけ。
7-b（2 計器の突合）  ───→ ⚠️ 閉じない。★ ただし「重ならない」の理由付けが誤りだったので訂正する。
```

## 1. ⚠️★★★ 先に見つけた事実 — **非打鍵区間は `still_stalled` へ構造的に吸い込まれる**

★ ADR-009 D2 / `personalization §3.2-3.3` の**定義から導かれる**（⚠️ 実装は存在しない —
`grep -rn 'left_observation\|still_stalled' src-tauri/src/ src/` → **0 件**）:

| 期 k の結果 | 定義 | ⚠️ 打鍵ゼロの区間で起こりうるか |
|---|---|---|
| `recovery` | 外部化を挟まず **`progress_proxy`** が個人基準を超えて回復 | ❌ **定義上ありえない**（`progress_proxy` = 窓内の**挿入打鍵 − 削除打鍵**） |
| `externalized` | `paste` | ★ ありうる |
| `left_observation` | focus 喪失・アプリ切替 | ⚠️ **同一アプリ内の非打鍵作業では起きない** |
| `still_stalled` | **何も起きず次の期へ**（参照カテゴリ） | ★★★ **必ずここに落ちる** |

→ ★★★ **同一アプリ内で打鍵せずに作業している区間は、`paste` が起きない限り期ごとに `still_stalled` になる。**
⚠️ ★ **`recovery` だけが定義上ありえない**ので、`recovery` のハザードが**系統的に下方へ**ずれる
（★ `externalized` は起こりうるが **競合イベント**であり、`recovery` の代わりにはならない）。

★ **同型の指摘が既に repo にある**: ADR-014 D4 は `secure_input` について逐語
「**『打鍵ゼロ』と『打鍵が見えない』を混同すると、…系統的バイアスが入り、
`left_observation` の内訳を割るという R3 の目的そのものを壊す**」と書き、
**段 1 に区間フラグを入れて受けた**。→ ⚠️ **非打鍵作業には対応する受け皿が無い。**

## 2. ⚠️ 「打鍵が無い」は 3 種類あり、段 1 で受かっているのは 1 つだけ

| # | 中身 | ★ 段 1 での受け皿 |
|---|---|---|
| (a) **非打鍵作業**（CAD / 動画 / スライド / 図） | ⚠️ **無い** ← ★ 本タスクの主題 |
| (b) **macOS `secure_input`** | ✅ **区間フラグ・特徴量は欠損扱い**（段 1） |
| (c) ⚠️ **Windows の昇格プロセスへの打鍵** | ⚠️ **無い**。★ ただし**未知ではない** —— `.steering/20260821-workspace-behavior-triage/survey-input-channels.md §3.6` に記録済み（§4 表 8 =「実機確認事項・自動テスト不可」）。⚠️ **段 1 にも `workspace-behavior-observation.md` にも伝播していない** |

⚠️★★★ **O1 は (a) と (c) を区別できない**（★ どちらも「打鍵 0 かつポインタ活動あり」に見える）。
★ 区別するには**前面プロセスの整合性レベルを in-memory で読む**ことになり、
それは §2.4 の「**アプリ指紋を in-memory で読むことを許すか**」と**同じ class の判断**である。
→ ⚠️ **§9.3 の禁止 2（役割カテゴリで埋めない）に触れるので、今は入れない。**
→ ★★★ **分類できないなら、挟むしかない。**

## 3. ★ 採る形 — **`left_observation` と同じ作法（上下界）で受ける**

- **下界側**: 当該期をすべて `still_stalled` として算入（＝ **現行の素の読み方**）
- **上界側**: 当該期をすべて `recovery` として算入（＝ **見えないところで前進していた**と読む）
- ⚠️ **risk set から外す扱いは第 3 の選択肢**であり、**上下界の *中* に入る**
  （★ 独立打ち切り仮定を置くことに等しい）。→ ⚠️ **点推定として採らない。**
- ⚠️★★ **上下界のために推定器を 2 本学習しない**（ADR-009 D2 逐語）。★ **読み出し段階**で切り替える。

★ **なぜ「一律除外」にしないか**: ⚠️ **情報のある打ち切りになる。**
「詰まったので打鍵しない作業へ移った」が起きうる以上、ADR-009 D2 が `left_observation` について
**拒んだ独立打ち切り仮定を、別の入口から持ち込む**ことになる。

## 4. ★ 区間の印は 段 1 の派生量だけで作る（⚠️ チャネルを 1 本も足さない）

```
非打鍵区間 := 打鍵イベントが 1 つも無く、かつ ポインタ活動がある連続区間
              ★ 素材は 段 1 の「打鍵（カテゴリ量子化済）」と「ポインタ 1 秒ビン」のみ
              ⚠️ macOS は secure_input 区間を先に除く（段 1 の区間フラグ）
```

⚠️★★★ **段 1 に候補を足していない**（§9.3 の禁止 1 / ADR-014 Migration 3 を守っている）。

## 5. ★ 判定量は新設しない（⚠️ ADR-014 D4c 逐語「新しい量を作らない」）

★ O1 の判定量は **G2 の上下界の幅**のまま。非打鍵の扱いは
**同じ幅を打鍵密度で層別して読む**（＝ `§9.4` の **NK-5**）。

⚠️ **層別は `task_kind` の推定ではない。** 打鍵密度は観測量であり、層別するのは**記述の読み出し**であって
**種別依存モデルへ流さない**（ADR-010 D3 の閉ループを作らない）。
→ ★ **報告では「CAD」と書かず「打鍵が薄い区間」と書く。**

## 6. ⚠️ 7-b — 「重ならない」の理由付けが誤っていた

★ ADR-012 D7 制約 4 逐語:「**被験者が開始 / 停止でき、宣言ブロック外では走らない**（★ 常駐させない）」
→ ★ これは **別計測器の稼働条件**だけを拘束する。⚠️ **O1（GSE 本体）の同時稼働を禁じていない。**
★ ADR-014 §Alternatives が却下したのは「**R3 を別計測器で常駐させる**」であって、
「宣言ブロック中に O1 も走っていること」ではない。

→ ⚠️ **本当の障害は 3 つ**（コホートの非同一 / 二重記録の同意 / 同時稼働の実機未確認）。詳細は `§9.5`。

## 7. ★ 事前登録に何を書けるか（★ G1 を待たずに進む部分）

| 項目 | ★ 書ける | ⚠️ 書けない |
|---|---|---|
| **合格基準** | ★ G2 =「上下界の幅が**介入判断を反転させない**」の operational 化（★ **反転率**・分母 = Decision Episode 数） | ⚠️ **反転率の閾値の数値**（→ 研究者判断） |
| **除外規則** | ★ **計器の欠損だけ**（`secure_input` / フック失効 / `dropped_delta > 0` / セッション境界） | ⚠️ **非打鍵区間を除外規則に入れない**（§3） |
| **Stop 条件** | ★ 幅が反転させる → **「目的変数として使えない」と報告**（ADR-009 D2 逐語）→ ★ **役割カテゴリの入口が順序どおり起動する** | — |
| **分割条件** | ★ **subject / session / 日** | ⚠️★★★ **task 分割は R3-a では成立しない**（`task_kind` 分散ゼロ）→ **限界として書く** |
| **Δ（期の幅）** | ★ **振る値の集合と感度判定の基準**（`personalization §11-7` の「決め方だけ先に固定」） | ⚠️ **Δ の値そのもの**（★ P1 の実測が要る） |

**G1 の収集完了後**になる」。→ ★ **ドラフトは `.steering/` に置き、凍結時に
