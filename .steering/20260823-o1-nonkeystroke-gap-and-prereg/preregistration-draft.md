## 2. 定義（★ 凍結対象）

### 2.1 `left_observation` の上下界（★ 既決・ADR-009 D2）

```
下界側 : left_observation を すべて 競合イベント とみなす
上界側 : left_observation を すべて 独立打ち切り とみなす
         ⚠️ どちらも「両極端の仮定」であって、どちらかが真であると主張しない
```

### 2.2 ⚠️★★★ 非打鍵区間（★ **ADR-016 D5**・⚠️ Proposed）

```
非打鍵区間 := 打鍵イベントが 1 つも無く、かつ ポインタ活動がある 連続区間で、長さ ≥ L_nk
              ★ 素材 = 段 1 の「打鍵（カテゴリ量子化済）」と「ポインタ 1 秒ビン」だけ
              ⚠️ macOS は secure_input 区間を先に除く（段 1 の区間フラグ）
              ⚠️ L_nk = 180 秒  ★ 2026-08-25 に研究者が凍結（実データは 1 バイトも見ていない）
```

★ **`L_nk = 180 秒` の根拠**（⚠️ **恣意性の残り方まで書く**）: `intervention.rs:10` の
`AWAY_IDLE_MS = 180_000` と **同値**にした。★ 「離席とみなす長さ」と「非打鍵作業とみなす長さ」の
**境界を 1 本に揃える**ことで、⚠️ **新しい数字を増やさない**。
⚠️ **代償**: **3 分未満の非打鍵作業は拾えない**（★ 短い非打鍵区間は `still_stalled` のまま残る）。

⚠️★★★ **段 1（ADR-014 D4）にチャネルを 1 本も足していない。**

### 2.3 ★★★ 非打鍵区間の上下界（★ **ADR-016 D3**・**研究者判断 1 で確定・2026-08-23**）

```
下界側 : 当該期を すべて still_stalled として算入する   ★ = 現行の素の読み方
上界側 : 当該期を すべて recovery として算入する       ★ = 見えないところで前進していたと読む
⚠️ risk set から外す扱いは 第 3 の選択肢 であり、上下界の 中 に入る（＝ 独立打ち切り仮定）
   → ⚠️ 既定値にしない
```

★ **採用理由（研究者判断・2026-08-23）**: ★ **最も強い上界**を採り、**仮定を 1 つも置かない**。
⚠️ 弱めると幅は狭まるが、**狭めた分だけ仮定を置いたことになる**。

⚠️ **2.1 と 2.3 は独立に切り替える。** ★ 報告する幅は **2 × 2 の組合せの最小〜最大**である。

### 2.4 打鍵密度の層（★ 記述の読み出しのための層別）

```
層     := 各 Decision Episode を、その期間の 打鍵イベント数 / 時間 で 3 分位に切る
          ⚠️ 分位の境界は 被験者内 で取る（★ 個人差を層の定義に持ち込まない）
```

⚠️★★★ **これは `task_kind` の推定ではない**（ADR-010 D3 の閉ループを作らない）。
★ **報告では種別名（CAD 等）を書かず「打鍵が薄い区間」と書く。**

### 2.5 期の幅 Δ（⚠️ **値は凍結しない。決め方を凍結する**）

★ `personalization §11-7` の 2026-08-16 決定（研究者）逐語
「**Δ を複数値で振り、係数が実際に動くかを実測してから決める**」に従う。

```
凍結するもの : ★ 振る Δ の集合 と、「動いた」と判定する基準
凍結しないもの: ⚠️ Δ の値そのもの（★ P1 の実測が要る）
```

#### ★★★ 凍結（★ 2026-08-25・研究者）

```
振る Δ の集合 : { 30 秒, 60 秒, 120 秒 }
「動いた」の基準: 同一係数の 符号が変わる、または 大きさが 2 倍以上動く
```

★ **根拠**: **30 秒 = 特徴量窓と同値**（`features.rs:104` の `cutoff = last_ts - 30_000`）、
**120 秒 = その 4 倍**。⚠️★★★ **「2 倍」は repo に無い数字であり恣意的である。**
★ 恣意的であることを実データを見る前に宣言し、**後から動かさない**（★ 反転率 0.10 と同型の作法）。

## 5. 合格基準（★ 凍結対象）

> ★ **G2 の逐語**（ADR-009 D2）:
> 「⚠️ 上下界の幅が **介入判断を反転させる** なら、**目的変数として使えない**と報告する」

```
反転     := 同一の Decision Episode について、下界側の読み出しと上界側の読み出しで
            意思決定層の出力が変わること
            ⚠️ 現行の介入は Lv1 Nudge のみ（ADR-015 で Lv2 Wall と Monk Mode は削除済み）
            → 出力の値域は { none, defer, nudge }
反転率   := 反転した Decision Episode 数 / 全 Decision Episode 数
            ★ 分母は「沈黙時間」ではない ＝ 打鍵密度の両端で退化しない
```

**報告は必ず 3 つ揃える**（★ ADR-012 D8 の「2 基線併記」と同じ作法）:

1. **全体の反転率**
2. ★ **打鍵密度 3 層別の反転率**（＝ **NK-5**。⚠️ 層別は記述の読み出しであって種別推定ではない）
3. ⚠️ **上下界の 2 × 2 の内訳**（`left_observation` 由来 / 非打鍵区間由来を分けて出す）

⚠️★★★ **判定は「全員一致」で行う**（★ GATE3 / ADR-012 D9 と同型。**中央値だけで判定しない**）。

#### ★★★ 閾値（★ **研究者判断 3 で確定・2026-08-23**）

```
合格 := n 名 全員 で 反転率 ≤ 0.10
```

⚠️★★★ **この値は実データから導いたものではなく恣意的である。**
★ **恣意的であることを明示し、実データを見る前に宣言する**ことで forking paths を避ける
（★ ADR-012 の `θ_floor = 0.20` と**同型の作法**）。⚠️ **後から動かさない。**

★ **大小関係の根拠だけは書ける**（⚠️ 値そのものの根拠ではない）:
`θ_floor = 0.20` は「**覆えた**」と言うための**床**（＝ 緩い側）だが、
**反転率は「使えない」と言うための天井**であり、⚠️ **同じ値では緩すぎる。**

⚠️ **併記必須**: `§5` の 3 点（全体 / 打鍵密度 3 層別 / 上下界 2 × 2 の内訳）を
**どの層で 0.10 を超えたか**が分かる形で出す（★ ADR-012 の `theta_source` と同じ作法）。

## 6. Stop 条件（★ 凍結対象）

| 条件 | 帰結 |
|---|---|
| `capabilities` が無い / 非打鍵行種が無い | ⚠️ **Stop**（`instrument_absent`）。★ 計器を直してから収集し直す |
| ⚠️ **反転率が閾値を超える** | ★★★ **「`self_directed_recovery` は目的変数として使えない」と報告する**（ADR-009 D2 逐語）。→ ★ **ADR-009 D2 の入口（役割カテゴリ）が *順序どおり* 起動する**（⚠️ 順序を飛ばさない） |
| ⚠️ 反転が **非打鍵区間由来だけ**で起きる | ★ **その事実をそのまま書く。** ⚠️ **「非打鍵を除外すれば通る」と読まない**（★ 除外は情報のある打ち切り・ADR-016 D4） |
| Decision Episode が下限未満の被験者がいる | ★ 除外し、**除外数を必ず報告する**（⚠️ n が 3 未満になったら **Stop**） |
| ⚠️ `task_kind` の分散がゼロ | ★ **想定内**（R3-a）。⚠️ **task 分割を作らない**（§8）。★ Stop ではない |
| 入力の manifest 不一致 | ⚠️ **exit 非 0 で停止** |

⚠️★★★ **Stop は失敗ではない。** ★ **幅が広いと分かることも成果である**
（★ ADR-009 D2 が「主張を縮めるのは弱さではない」と書いているのと同じ）。

## 7. 除外規則（★ 凍結対象）

> ⚠️★★★ **非打鍵区間は除外規則に入れない**（★ **ADR-016 D4**）。
> ★ 一律除外は **情報のある打ち切り**であり、ADR-009 D2 が `left_observation` について
> 拒んだ独立打ち切り仮定を、**別の入口から持ち込む**ことになる。

| # | 除外 | ★ 理由 |
|---|---|---|
| **E1** | ★ **宣言境界をまたぐ区間**（＝ 宣言変更に伴うローテート ＋ `engine.reset()` の境界。★ 旧: セッション境界） | ★ `step()` は `!session_active` で `starved_ms` を 0 に落とす（`liveness.rs:93`）。⚠️★★★ **2026-08-25 注**: O1 は **(B) 常時収集**（ADR-016 判断 4b-0）なので、⚠️ **`session_active` はもはや境界を意味しない**。★ O1 で境界になるのは **宣言変更（4b-1）**であり、そこで engine が reset される。→ ⚠️ **`starved_ms` / `session_active` の扱いは実装 acceptance で確定させること** |
| **E2** | ⚠️ **macOS `secure_input` 区間** | ★ **計器の欠損**（段 1 が区間フラグを置き、特徴量を欠損扱いにしている） |
| **E3** | ⚠️ **フック失効の区間**（`hook_health` / `CGEventTapIsEnabled` の失効） | ★ **計器の欠損**。⚠️ O1 は数日〜数週間走るので **必ず起きる**前提で書く |
| **E4** | `dropped_delta > 0` を含む区間 | ★ ログキュー溢れ＝記録の欠落。⚠️ **`dropped` は累積カウンタである**（`hook.rs:140`） |
| **E5** | 装置由来の沈黙を含む区間（プローブ提示等） | ⚠️ O1 は主経路にプローブを置かない（§4.1 L-B）が、**入っていたら除外する** |

★ **各除外の件数を必ず結果に出す**（⚠️ **黙って落とさない**）。

## 9. n と期間の下限（★ 凍結対象）

**n ≥ 3 名**（★ ADR-014 判断 1 / ADR-012 D9 と同型・**新しい原則を持ち込まない**）。

#### ★★★ Decision Episode の下限（★ 2026-08-25 に研究者が凍結）

```
Decision Episode ≥ 30 件/人
```

★ **根拠（★ 導出できる床にした）**: **NK-5 は打鍵密度の 3 分位で層別して反転率を読む**（§5 の報告 3 点の 2）。
→ ★ **3 層 × 10 件 = 30**。⚠️ 各層に最低限の件数が無いと、**層別の反転率がそもそも読めない**。

⚠️★★★ **プローブ件数の床（≥20 件/人・`research-positioning §8`）は流用していない** ——
★ あちらは**プローブ件数**、こちらは **Decision Episode** で**単位が違う**。
⚠️ **代償**: 下限を上げたぶん**除外が増え**、★ **n が 3 を割れば Stop**（§6）。

## 11. ⚠️ 事前に認めている限界（★ 隠さない）

1. ⚠️★★★ **非打鍵区間は (a) 非打鍵作業 と (c) Windows の昇格プロセスへの打鍵 の混合である。**
   ★ O1 は**両者を分離できない**（ADR-016 Context-3）。⚠️ **分離するには「アプリ指紋を in-memory で読むか」の
   判断が要り、それは ADR-009 D2 の順序に従う。**
2. ⚠️ **`progress_proxy` は「対象作業をしている」ことを暗黙の前提にしている**
   （`personalization §3.2` 逐語・未解決 §11-11）。★ 打鍵が**多すぎる**側（写経・タイピング練習）は
   既に自認されており、⚠️ **打鍵が無い側は本事前登録が上下界で受ける**。
3. ⚠️ **`Δ` の任意性は消えていない**（`personalization §11-7`）。★ 決めたのは **決め方**である。
4. ⚠️★★★ **task 分割が作れないので、O1 は ADR-009 D4（潜在状態モデルの採用ゲート）の
   held-out 要件を満たさない**（§8）。★ **O1 の判定量（幅）はそれとは別である。**
5. ⚠️ **O1 は非打鍵タスクの沈黙被覆率に答えない**（ADR-014 D9）。★ それは **ADR-012 Stage 1 の問い**であり、
   **判定量も母集団も違う**。
6. ⚠️★★★ **形成的トラックであり確証主張に使わない**（適格性ゲート `keydown ≥ 100` を適用しない）。
7. ⚠️ **O1 は「在席の連続タイムライン」を作る**（ADR-014 D5）。★ **同意文書と保管の要求が R1 / R2 より重い。**
8. ⚠️★★★ **O1 は ADR-012 Stage 1 と *同一被験者・同一区間* で同時に走る**（★ 研究者判断 2・ADR-016 D9）。
   → ★ **同一区間の対照が取れる**が、⚠️ **前提 3 件が未了である**:
   ① **同時稼働の実機確認 2 件**（Win: `WH_KEYBOARD_LL` 連鎖＋Raw Input ／ mac: tap 2 系統）
   ② **二重記録の同意文書**（★ 倫理審査の根拠 3 を **2 系統ぶん**）
   ③ **ADR-012 D12 の画面録画と O1 の重なりの明示**（⚠️ **D12 は同時に走る O1 を想定していない**）。
   ⚠️ **① が落ちたら「同一被験者・別時点」へ降り、降りたことを記録する。**
9-b. ⚠️★★★ **宣言の *陳腐化* は原理的に検出できない**（★ 2026-08-25 追加・ADR-016 判断 4b-3）。
   ★ O1 は **(B) 常時収集**であり、宣言は被験者が任意のタイミングで変更する。
   → ⚠️ **実際にタスクが変わった時刻と、被験者が宣言し直した時刻のズレ**には**古いラベルが載る**。
   ⚠️★★★ **観測から推定して埋めることはしない** —— ★ それは **ADR-010 D3 が禁じている閉ループ**である。
   ★ **未宣言そのもの**は `session_meta` 行の**不在**として機械判定できるが、**陳腐化は区別できない。**

9-c. ⚠️ **宣言変更の直後 30 秒の `feat` 行は、他と同列に読めない**（★ 2026-08-25 追加）。
   ★ 宣言変更で `engine.reset()` が走り、**30 秒の特徴量窓が空から埋め直される**
   （`features.rs:104`）。⚠️ reset しないと **新ファイル先頭の `feat` 行が前ファイルの状態に依存し、
   replay が本番を再現しない**ので、reset する側を選んでいる。
   ★ **本事前登録の判定量は `feat` 行を使わない**（★ `progress_proxy` は打鍵由来）ので影響は限定的だが、
   ⚠️ **`feat` 行を副次的に見るときは除外するか、warm-up と明示すること。**

9-d. ⚠️★★★ **`buttons`（クリック押下数）は macOS では恒常的に 0 である**（★ 2026-08-25 追加・D-5）。
   ★ 段 1 の mac 側マスクは `MouseMoved`/`*Dragged`/`ScrollWheel` であり **`*MouseDown` を含まない**。
   ⚠️ 段 1 は凍結済みなので**足さない**（研究者判断・2026-08-25）。
   → ★ **`buttons` を使う読み出しは Windows 限定**である。⚠️ **両 OS を混ぜて集計しない。**

9-e. ⚠️★★★ **本研究は「送信済みデータの削除」を被験者に保証しない**（★ 2026-08-25 追加・判断 O1-2）。
   ★ ログは **日次ローテートで閉じ、48 時間後に自動提出**される（ADR-014 D8 の上書き）。
   ★ **提出前なら区間指定削除がそのまま効く**が、⚠️ **提出後は研究者側の削除手続き**に移る
   （★ 台帳に載せる・ADR-014 D8 制約 3）。⚠️ **48 時間という値は恣意的である。**

9. ⚠️ **本事前登録は「ゲートを割った計器」を前提にする**（★ ADR-016 D8）——
   ★ 操作語彙（修飾 / F1–F12 / Escape / 矢印 / テンキー）は **`Key` 行として記録されるが特徴量には流れない**。
   → ⚠️ **HMM 出力は変わらない**が、★ **記録の粒度は G1 のログと異なる**。
   ⚠️ **`meta.capabilities` / `app_version`（ADR-013 D1）で機械判別できることを前処理で確認する**（§4）。
