## ★★★ S3-D11: **B1 は通過。ただし「芸術的親和性」に否定的所見が出た**（研究者の耳・2026-08-12）

  - 「基音や低音の減衰や揺らぎなども時々で変異していくと面白い気がした」
  - 「この音以外にも多種多様な音などを掛け合わせるとさらに面白いのでは」

  | # | 問い | 結果 |

  | **B3** | 離席復帰は carry / restart か | ⚠️ **開いたまま**（実データを読み込んだ試聴が未実施） |

- ★★ **「芸術的親和性への疑問」を欠陥として扱わない、が無視もしない** ——
  `spec` §2 は層 0 を **「基層 (bed)」＝「自分の通常」の参照点**と定義しており、
  ★ **層 0 は作品ではない。** 芸術性を担うのは層 2（粒子）以降である。
  → **したがって「層 0 が芸術的でない」ことは仕様どおりでもある。**
  ⚠️ ★ **ただしこれで片付けない** —— 所見が指しているのは

- ⚠️★ **n=1 の自己申告である。** `spec` §5 要件 3（**主観指標だけで go を出さない**・

  ★ **「気にならなかった」を「壊していない」と読み替えない。**

## ⚠️★★★ S3-D12: **`spec` §2 の「層 0 は動かさない」を改訂する**（耳が選んだので仕様を直す）

> ★ S3-D10 が「**もし耳が『ゆらぎ有』を選んだ場合、それは `spec` §2 の改訂を意味する。
> その場合は spec を直す（実装だけ先に進めて仕様を放置しない）**」と予告した通りに実行する。
> 研究者の所見は**さらに踏み込んでいる**——ゆらぎだけでなく**減衰も時間変異させたい**。

- ★★ **「動かさない」という 1 つの制約が、実は 2 つの別々の要求を束ねていた**:

  | | 内容 | 転換後 |
  |---|---|---|
  | **(a)** | ★ **状態に応答しない**（層 0 が状態信号にならない） | ★★ **維持する。これが `spec` §2 の構造的な要（かなめ）である** |
  | **(b)** | 一切変化しない（完全な定常音） | ★★ **改訂する**——**状態と無関係な自律的・超低速の変異を許す** |

- **理由**: `spec` §2 が (b) を要求していた根拠は
  **「状態由来の層は常にこの上で聴かれるので、並置が構造的に成立する」**である。
  ★ **並置を成り立たせているのは (a)（層 0 が状態を語らないこと）であって、(b)（不動であること）ではない。**
  → **(a) を守れば並置は壊れない。**
- ⚠️★★★ **ただし、ここに未解決の技術的衝突がある（S3-D13）。** 改訂は無条件ではない。

## ⚠️★★★ S3-D13: **層 0 の自律変異と「状態の波」が同じ帯域に入る** — ★ 未解決として Step 4 へ渡す

> ★ **S3-D12 を書いていて気づいた衝突。実装を進める前に出しておく。**

- **問題**: `spec` §1.1 は **状態の波を 0.001–0.02 Hz** に置くと定めている。
  ★ **現在の「ゆらぎ有」候補は 0.005 / 0.0031 Hz ——まさにその帯域の中にある。**
  → **層 0 の自律的なゆらぎと、層 1–3 が運ぶ状態の変化が、聴取上ほぼ同じ速さになる。**
- ★★ **何が壊れるか**: 聴き手が **「基層が勝手に揺れただけ」と「自分の状態が変わった」を区別できない。**
  ★ **表現層における偽陽性**である。GSE が HIR（有害介入率）を最重要安全指標に置いている以上、
  **「何も起きていないのに状態が変わったと読ませる」ことを軽く見ない。**
- ⚠️ **Step 3 の段階では実害が無い**——**層 1–3 がまだ存在しない**ので、混同する相手がいない。
  ★ **だから今回の試聴結果は有効である。** 問題になるのは **Step 4 で層 2 を足した瞬間**である。
- **決定**: ★ **ここでは解かない。選択肢を並べて Step 4 の入口に渡す。**

  | 案 | 内容 | 代償 |
  |---|---|---|
  | **A: 周波数で分ける** | 層 0 の自律変異を状態帯より **1 桁以上遅く**（≤ 0.0005 Hz ＝ 周期 33 分以上） | ⚠️ **1 セッション内でほとんど変化しない**——研究者が求めた「時々で変異していく面白さ」が体験されない可能性 |
  | **B: 次元で分ける** | 層 0 は**音色・減衰**だけを動かし、状態は**密度・帯域・空間**が担う（速さは分けない） | ⚠️ **耳が次元で分離できる保証が無い**（未検証の想定。§4 の「Incubation は肯定的に読める」と同型の危うさ） |
  | **C: 両方** | 遅くしたうえで次元も分ける | 最も安全だが、体験される変化が最も乏しい |

- ★ **推測で A を採らない。** ★★ **これは耳で決める問い**（層 2 と並べて聴かないと分からない）。
  → **Step 4 で「層 0 の自律変異 × 層 2 の状態応答」を同時に鳴らし、混同が起きるかを聴いて決める。**

## S3-D14: **音の幅は「合成音の範囲」で広げる。実物音の引用禁止は維持**（研究者判断）

- **決定**（研究者が選択）: 「多種多様な音を掛け合わせる」は
  **ノイズ帯・グラニュラー粒子・残響・帯域フィルタなど、合成で作る音色**の範囲で広げる。
  ★ **`spec` §2 の禁止事項「✗ 実物音の引用（水・鳥・機械音）」は維持する。**
- **理由**: 実物音は **指示対象を断定する** [P63]——「川の音」と読まれた時点で、
  **[P45]（断定しない）に正面から反する**。★ **spec の改訂を要さない範囲で所見に応えられる。**
- ★★ **所見「ブラウンノイズなどを主にしたものを感じた」は、この方向と整合している** ——
  ⚠️ **実際に鳴っていたのはノイズではない**（55 Hz の基音 ＋ 整数次倍音 8 本、最高でも 440 Hz の正弦の和）。
  ★ **それが「ブラウンノイズのように」聴こえたということ自体が発見である**——
  **低域に密集した倍音列は、耳にはノイズ帯として体制化されている。**
  → ★ **Step 4 で実際にノイズ帯成分を足す余地は大きい**（研究者の直感と実装が同じ方向を指している）。
- ⚠️ **どの減衰則で聴いたかは記録されていない**（既定は `1/n²`）。
  ★ **`1/n` のほうが「ブラウンノイズらしさ」は強いはず**だが、**これは未確認の推論である。**
  → **Step 4 の試聴で `1/n` / `1/n²` を明示的に聴き比べてもらう。**

## ★★★ S3-D1: 試聴媒体は **ローカル HTML + Web Audio の実時間合成**（研究者判断・grill）

- **決定**: 層 0 を聴ける形にする媒体は **ブラウザで開くローカル HTML 1 枚**とし、
  **Web Audio API で実時間合成**する。引き継ぎ §3a が想定していた
  **Python `wave` での WAV 書き出しは採らない。**
- **選択肢と判定**:

  | 案 | 利点 | 欠点 | 判定 |
  |---|---|---|---|
  | **A: HTML + Web Audio** | ★ **無限長**（10 分でも 1 時間でも同じ）／★ **ループ継ぎ目が原理的に存在しない**／★ **停止・音量を実装として満たせる**（[P71] 要件 1）／Step 3b の「1Hz 目標値 → 連続追従」を**本当にリアルタイムで**通せる | 凍結物が HTML になる → ★ **S3-D5 で解決**（凍結物は JSON） | ★ **採用** |
  | B: WAV 書き出しのみ | 依存ゼロ／成果物が不変ファイル | ★ **オフスイッチ要件を「実装として」試せない**（OS プレイヤー任せ）／10 分 = 52 MB／長時間試聴に巨大ファイルが要る | 却下 |
  | C: 両方 | — | ★ **同じ音を 2 実装で出すことになり、「どちらが正か」が不定になる**（§5 落とし穴 2 の silent pass と同型） | 却下 |

- ★★ **B を却下した決め手は [P71] である**——要件 1（**ユーザーが止められる／音量を変えられる**）は
  **交渉不可**と `spec` §5 が書いており、引き継ぎ §3a も
  「★ **同時に [P71] のオフスイッチ要件も試す**」と指示している。
  **OS のプレイヤーで止めることは「表現層が止められること」の検証にならない。**
- ★ **ループ点の問題も決め手になった**: WAV を短く作ってループ再生すると、
  **継ぎ目が周期的な段差になる** = `spec` §2 の禁止事項「**拍・リズム（周期的な無音・周期的な強弱）**」に
  正面から当たる。実時間合成にはこの穴が**原理的に存在しない**。
- ⚠️ **境界に触れていないことの確認**: 落とし穴 6 が禁じているのは
  **GSE 本体（Rust / TS）の変更**と **OSC / WebSocket の実装**である。
  本件は `experiments/` 配下の**独立したローカル HTML** であり、**本体を 1 行も触らず、通信も発生しない。**
  ⚠️ ★ **`file://` から CSV を `fetch` すると CORS で落ちる**のが既知の形なので、
  **データは JS として埋め込むか、ローカル HTTP で配る**。→ **どちらになるかは実測して決める**（推測で書かない）。

## ★ S3-D2: 候補の軸は **基音 / 倍音の減衰則 / 超低速ゆらぎ** の 3 つ。左右デチューンは**採らない**

- **決定**（研究者が grill で選択）: 層 0 の候補は次の 3 軸で振る。

  | 軸 | 水準 | 何を確かめるか |
  |---|---|---|
  | **基音** | 55 / 73.4 / 82.4 / 110 Hz | `spec` §2 の「55–110 Hz 帯」を端から端まで。最も体感差が大きい |
  | **倍音の減衰則** | 1/n / 1/n² / 低次のみ | ★ **sharpness**（`spec` §2 が「低」を要求）。1/n² が安全側、1/n が上限側の確認 |
  | **超低速ゆらぎ** | 無 / 有（0.005 Hz 前後） | 完全な定常音が「死んだ音」に聞こえるか。★ 0.005 Hz は禁止帯（0.5–20 Hz）の **2 桁下** |

- ⚠️★★ **層 0 は状態に応答させない**ので、上表の「超低速ゆらぎ」は
  **状態由来ではなく固定周期の自律ゆらぎ**である。**ここを取り違えると Step 3 の趣旨が壊れる。**
- ⚠️ **却下: 左右のデチューン（ステレオの広がり）** —— 私が反対意見として提示し、研究者も選ばなかった。
  **左右を数 Hz ずらすと「うなり」= 周期的な強弱が生まれ、`spec` §2 の禁止事項に正面から当たる。**
  0.1 Hz 以下まで下げれば禁止帯（0.5–20 Hz）の外だが、**周期的強弱であること自体は変わらない。**
  → ★ **Step 3 では作らない。** 空間の広がりが要るなら **層 3（空間）で残響として作る**（`spec` §2）。
- ★ **組合せは 4 × 3 × 2 = 24 通りだが、24 本の素材は作らない**——
  実時間合成なので **UI で軸を切り替えれば済む**（S3-D1 を採った利得がここに出る）。

## ★ S3-D3: **試聴時間は 10 分**を設計の前提にする（研究者判断・grill）

- **決定**: 「ずっと鳴っていて気にならないか」を確かめる 1 候補あたりの試聴時間を **10 分**とする。
- **理由**（研究者の選択）: **G1 の 5 分ブロック × 2 に相当**し、慣れと苛立ちの両方が出始める長さ。
- ★ **これが設計を拘束する点**: 10 分の連続再生に耐えるには
  **(a) メモリが増え続けない**（ノードを作り捨てし続けない）
  **(b) 位相が飛ばない**（パラメータ変更で不連続を作らない = オンセット禁止）の 2 つが要る。
  → ★ **10 分放置して破綻しないことを実測する**（「たぶん大丈夫」と書かない）。

## ★★ S3-D4: 機械検算は **本番と同じ合成グラフ**を `OfflineAudioContext` で測る（二重実装しない）

- **決定**: 4 Hz 近傍のエネルギー検算は、**Python で別に信号を作って測るのではなく**、
  **HTML が実際に鳴らしているのと同じ合成グラフ**を `OfflineAudioContext` でレンダリングし、
  **JS 側で Hann 窓 DFT を計算**して報告する。
- ★★ **理由**: Python で別実装を測ると **「測った信号」と「鳴っている信号」が別物になりうる**。
  それは `verify-before-claiming` が繰り返し警告している「**主張と実体のずれ**」そのものである。
  ★ **S3-D1 で案 C（両方作る）を却下した理由と同じ論理**なので、検算だけ二重実装に戻すのは一貫しない。
- ⚠️★★★ **窓なし DFT を判定に使わない**（**S0-D8**）——実測で**符号が逆になった**前科がある
  （窓なし: 「平滑化すると 4 Hz が増える」という誤結論 / Hann 窓: −63.5 dB で解析解と一致）。
  **一様に刻んだ「帯域 RMS」も使わない**（線スペクトルを跨ぐ）。★ **線の位置（3.995 / 4.0 / 4.005 Hz）で比べる。**
- ★ **Python 側の検算を捨てるわけではない**——`expr_smooth.py --selftest`（51 検査）は
  **平滑化の主張**を守るものとして引き続き回す。**新しく足すのは「音になった後」の検算**である。

## ★ S3-D5: 凍結物は **HTML ではなく JSON**。`EXPR_VERSION` は **`0.2.0-step3`** へ上げる

- **決定**:
  1. 合成パラメータ（基音 / 倍音数 / 減衰則 / ゆらぎ / ゲイン）を **`layer0.config.json` に外出し**し、
     HTML は**それを読むだけ**にする。→ ★ **「耳で決めた版」の凍結物は JSON である。**
     これは `spec` §7 Step 7（「気に入った設定を JSON に書き出し、EXPR_VERSION を刻んで凍結」）と同じ形。
  2. **`EXPR_VERSION` を `0.1.0-step2` → `0.2.0-step3` に上げる**（引き継ぎ §4 の指示「音を足したら上げる」）。
- ⚠️ **版が 2 箇所に散らないようにする** —— `EXPR_VERSION` の定義は
  **`expr_smooth.py:59` の定数のまま**（既存の SSOT を動かさない）とし、

## ⚠️★★ S3-D10: 「超低速ゆらぎ有」の候補は **spec §2 の「層 0 は動かさない」から意図的に逸脱している**

> ★ **実装中に気づいた齟齬。黙って実装せず、逸脱として明示する。**

- **事実**（一次資料の逐語）: `media-expression-spec.md` §2 の層 0 の箱には
  **「★ 動かさない = [P48] が要求する『自分の通常』の参照点」** と書かれている。
  さらに全層共通の禁止事項に **「✗ 拍・リズム（周期的な無音・周期的な強弱を作らない）」** がある。
- ⚠️ **したがって、grill で研究者が選んだ「超低速ゆらぎ（0.005 Hz）有」の候補は、
  文字どおり読むと spec §2 に反する。** 振幅のゆらぎは **周期的な強弱**そのものだからである。
- **決定**: ★ **逸脱を消さない。逸脱として明示したうえで作る。**
  1. `layer0.config.json` の各候補に **`spec_compliant` フラグ**を持たせる
     （`none` = `true` / `slow` = `false`）
  2. ★ **既定は `none`（spec 準拠の完全な定常音）**。逸脱側を既定にしない
  3. ゆらぎは **通約できない 2 波の和**（0.005 / 0.0031 Hz）にして反復周期を **6200 s（103 分）**へ延ばす
     —— 試聴 10 分（S3-D3）の **10 倍以上**なので、試聴中に「繰り返し」として聴こえない
  4. ⚠️ ★ **「だから非周期である」とは書かない**——有理比なので数学的には周期的である。
     **「試聴時間内では繰り返さない」までしか言えない**（`verify-before-claiming`）
- ★★ **なぜ却下しないか**: この候補が答えようとしている問いは
  **「spec §2 の『動かさない』という制約が、10 分の実聴に耐えるか」**である。
  ★ **仕様を検査する候補を、仕様に反するという理由で作らないのは循環である。**
  Step 3 の趣旨（「基層だけで耐えられるかを先に確かめる」）に照らせば、**むしろ作るべきものである。**
- ⚠️ **研究者への申し送り**: **もし耳が「ゆらぎ有」を選んだ場合、それは `spec` §2 の改訂を意味する。**
  ★ **その場合は spec を直す**（実装だけ先に進めて仕様を放置しない）。

## S3-D9: 平滑化 CSV は **ファイル選択（`FileReader`）で渡す**。JS への変換スクリプトは作らない

- **決定**: `design.md` 初稿にあった `csv_to_js.py`（CSV → JS 埋め込み）を **作らない。**
  HTML 側に `<input type="file">` を置き、**研究者がその場で smoothed CSV を選ぶ**形にする。
- **理由 1（技術）**: `file://` から `fetch` すると CORS で落ちるという問題は、
  **`FileReader` なら最初から発生しない**（ローカル HTTP サーバも要らない）。
- ★★ **理由 2（こちらが本質）**: **実データがリポジトリに入る経路を最初から作らない。**
  `csv_to_js.py` を作ると **`sm.data.js` という追跡候補ファイルが生まれる**——
  S0-D9 が `.gitignore` で塞いだのは `*.smooth.csv` 等**であって `.js` ではない**ので、
  ★ **`git add -A` で実打鍵由来の 1 秒刻み系列が紛れ込む穴が新設される。**
  → **穴を塞ぐより、穴を作らない。**（`data-privacy` / S0-D9 と同じ論理）
- ★ **層 0 単体（Step 3a）は CSV を必要としない**ので、**データ未選択が既定の正常状態**である。
