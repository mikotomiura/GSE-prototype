## 設計案比較（/reimagine 1 回目・2026-11-09）

### v1 の要旨（design-v1.md）
草 270 本の押しと粒 140 個のずれを、1 つずつ Rust が 16ms の固定刻みで持つ。距離を測るため、草と粒の配置・粒の動きの式・fbm のノイズを Rust に写す（配置は Rust から窓へ送り、ノイズと粒の式は Rust と TS の両方に持って照合の表で縛る）。粒の位置は打鍵の `phase` に依るので、ポインタの刻みは 0.5 秒遅れた打鍵の状態を読む。駆動役のスレッドを 16ms に速めて、両方を 1 つのロックの下で進める。

### v2 の要旨（design.md）
跡を、正準の箱の 16 × 10 の格子の「場」（マスごとに草を倒す量と粒を寄せる 2 成分・どれも 0 へ戻る）として Rust が持つ。草と粒は窓の側で場を補間して読むだけ。Rust は配置もノイズも打鍵の状態も知らない。ポインタは専用のスレッドで進め、駆動役とは Atomic（窓の開閉・入れ切り・世代）でつなぐ。

### 主要な差異
| 観点 | v1 | v2 |
|---|---|---|
| アプローチ | 要素ごとの跡（試作の式をそのまま写す） | 格子の場（要素は場を読む） |
| 打鍵との結合 | あり（粒の位置が `phase` に依る・遅れの規則を跨ぐ） | なし（独立の 2 つの積分器） |
| 二重の実装 | 配置・ノイズ・粒の式を Rust と TS に持つ（照合の表で縛る） | なし（Rust は場、TS は描き方） |
| 窓の描き方を変えたとき | Rust の関数も変わる（配置が状態の入力） | Rust の関数は変わらない |
| 状態の大きさ・送る量 | 410 値（f32）を毎秒 30 回 | 480 値（i8 に量子化）を毎秒 30 回・全部 0 なら止める |
| PR 4 の特徴 | 配置に結びついた 410 値（種ごとに意味が変わる） | 配置に依らない 480 値（場のまま特徴にできる） |
| スレッドとロック | 駆動役を 16ms に速める・`HANDMARK_DRIVER` のロックが 15 倍 | 専用のスレッド・ロックを共有しない |
| 見た目の忠実さ | 試作と同じ（近くの草だけ・粒は追い越さない） | 格子の粗さで落ちうる（隣の草がそろう・追い越しの上限は写せない） |
| 変更規模 | 大（world・noise の移植・照合の表・駆動役の作り替え） | 中（場・スレッド・Atomic） |
| テスト戦略 | 決定性・戻る・切り・再生・配置の Rust↔TS 照合・記録の検査 | 決定性・戻る・溜めない・切り・再生とライブの一致・補間・記録の検査 |
| リスク | 二重の実装のずれ・ロックの競合・遅れの規則の跨ぎ | 格子の粗さが見た目に出る（画面で判定。足りなければ 32 × 20） |

### 推奨案
**v2** —— 理由:
- 要件の芯（ライブと再生が同じ Rust の関数を通り、描画の回数に依らない）を、打鍵とも配置とも独立な小さな関数で満たす。v1 は同じことを満たすために、配置とノイズの二重の実装と、打鍵の遅れの規則を跨ぐ結合を抱える。
- PR 4 は関数の出力から特徴を作る。v2 の場は種に依らず同じ意味を持つので、日を跨いで特徴をそろえやすい。
- 専用のスレッドなので、16ms の仕事がトレイ・区間の削除・終了と同じロックを取らない（影響調べの MEDIUM を避ける）。
- 代わりに見た目の忠実さが落ちうる。これは画面の確かめで研究者の目で判定し、足りなければ格子を細かくする（関数の形は変わらない）。
