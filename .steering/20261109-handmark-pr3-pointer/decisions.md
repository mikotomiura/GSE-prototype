# 重要な設計判断

## 判断 1〜4: 始める前に研究者が選んだこと（2026-11-09）

1. **ポインタの跡の置き場**: 戻っていく値（草の押し・粒のずれ）は Rust の固定刻み（16ms）の状態で計算する。打鍵の積分器（「今 − 0.5 秒」まで進める・PR 1 判断 7-3）とは別にし、ポインタには遅れを入れない。波紋の 6 枠は ADR-050 D4 のとおり窓の側に置き、年齢は時刻で決める（描画の回数に依らない）。
   - 採らなかった案: 波紋の枠も Rust に入れる（ADR-050 D4 の「枠は窓の側だけ」の読み替えか補訂が要る）／試作どおり窓の側で減らす（跡が描画の回数に依り、PR 4 の再生の道具が TSX の処理を写すことになる）。
   - ADR-051 D3 の判定がどの写像についてのものか: 打鍵の状態と、ポインタの戻っていく値（Rust の関数）の写像。波紋は窓の側なので、再生では押下の時刻と合成の位置から PR 4 が描き直す（波紋の式を Rust に写すかは PR 4 で決める）。
2. **再生の近似**: `pointer_bin` の 1 秒の量から、描画の種で決めた起点を、その秒の移動量のバケットの代表の距離だけ等速で動く合成の軌跡と、秒の中に等間隔に置いた押下を作り、ライブと同じ関数に入れる。位置は再現できない（ADR-051 D3 の限界）。`pointer_bin` の押下はどのボタンも数えるので、左だけのライブより押下が多めに出る（限界として記録する）。
   - 採らなかった案: 画面の中心に固定／位置を使わない量だけ（ライブと別の経路になる）。
3. **入力ごとの入れ切り**: トレイにカーソル・クリックの入れ切りを入れ、切った・戻した時刻を `handmark_day` に記録する（schema の変更・gse-dataset の同期）。
   - 採らなかった案: 入れるが記録しない／PR 3 では入れない。
4. **タスク名**: `handmark-pr3-pointer`（枝 `feature/handmark-pr3-pointer`・worktree `/Users/johnd/GSE-prototype-handmark-pr3`）。

## 判断 5: トレイの文言（研究者が選んだ・2026-11-09）

- 入力ごとの入れ切りの項目は「カーソル」「クリック」。チェックの印つきで、入っていると印が付く。「やめる」の上に置く。
- 採らなかった案: 「背景: カーソル」「背景: クリック」（試作）／「動きで描く」「クリックで描く」（全体の「描く」と紛れうる）。

## 判断 6: 設計の第 1 案を承認（研究者・2026-11-09）

- design.md の第 1 案（草・粒の 1 つずつの跡を Rust が 16ms で持つ・配置とノイズを Rust に写す・16:10 の正準の箱）を承認し、/reimagine で第 2 案と比べる。

## 判断 7: /reimagine で v2（格子の場）を採る（研究者が選んだ・2026-11-09）

- 跡は、正準の箱（縦 1・横 1.6）の 16 × 10 の格子の場（マスごとに `bend`・`pull_x`・`pull_y`・どれも 0 へ戻る）として Rust が持つ。草と粒は窓の側で場を補間して読む。ポインタは専用のスレッドで進め、駆動役とは Atomic でつなぐ。
- 判断 1 の「戻る値は Rust」の具体はこの場になる。ADR-051 D3 の判定の写像は「打鍵の状態（`replay_live`）と、ポインタの場（`replay_trace`）」。
- 採らなかった案: v1（草・粒ごとの跡。試作と同じ見た目だが、配置・ノイズ・粒の式の二重の実装、打鍵の遅れとの結合、駆動役のロックの競合を抱える）。
- 見直しのきっかけ: 画面の確かめで格子の粗さが目に見えたとき（まず 32 × 20 にする）。

## 判断 8: A1〜A4 の実装役の報告を確かめる（2026-11-09）

- fmt・clippy（`-D warnings`）・`cargo test --workspace`（lib 1222 件）を自分で走らせ直して緑。`TraceField::step` の刻みの中で pow・exp・三角関数を呼ばないことをコードで確かめた。
- 変異: 一時停止を見ない → 1 件赤／`reset` で場を消さない → 2 件赤／開いたとき押しっぱなしを押下とみなす → 1 件赤。止まっているかの判定（`is_idle`）から場の値の条件を外す変異は緑のままだが、等価である（場に値を足すのは速さが 0 でないとき＝点が動いた後で、そのとき `last_input` が立つ。`last_input` が消えるのは場を 0 にするときだけ）。場の条件は重ね掛けとして残す。

## 判断 10: 実装 B の実装役の報告を確かめる（2026-11-09）

- fmt・clippy・`cargo test --workspace`（lib 1254 件）・emit_schema の byte-equal・`tsc --noEmit`・`npm run test:handmark`（14 件）を自分で走らせ直して緑。
- `lib.rs` の配線をコードで読んだ: ポインタのスレッドは `HANDMARK_DRIVER` のロックを取らず、門は `AtomicU8`、駆動スレッドの終わり（`HandmarkWindowGuard`）で門も閉じる。
- 窓の TS は場の定数（`BEND_MAX`・`MOTE_MAX`・格子の大きさ・`BOX_W`）を手で写していて、機械で照らしていなかった。Rust の定数と TS の `export const` を照らす検査を足した（`the_window_copies_the_field_constants_exactly`・陽性対照つき・0fad9062）。
- 変異: TS の `BEND_MAX` だけ変える → 1 件赤／跡を `emit`（全窓）で送る → 1 件赤／窓の TTL で消さない → node の 1 件赤。
- 実装役が決めた細部（blockers.md の 27〜40）はそのまま採る。payload の欄名は試作に合わせて camelCase、送った時刻 `tMs` を足した（窓が遅れた値を捨てるため）。CI の node は step の先頭で 22.18 未満なら理由を言って落とす。
- 確かめていないこと（画面の確かめで見る）: 実機の読み・窓の描画・格子の粗さ・トレイの押下（`CheckMenuItem` の自動反転と言い直し）・一時停止で跡が消えること。Windows の clippy は CI で見る。
