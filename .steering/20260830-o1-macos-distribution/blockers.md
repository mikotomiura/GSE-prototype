# blockers — 詰まりと解決

## B-1 ⚠️★★★ 本番欠陥: O1 の macOS 初回セットアップが **必ず NG になる**

**状態**: 発見 2026-08-30 / 修正 → 後述

### 症状 (★ 実測。推測ではない)

配布物そのものを展開し、README 【1】の手順どおりに実行した:

```
$ bash "/Users/johnd/Desktop/O1_実施用_macOS/初回セットアップ_mac.sh"
NG: g1.mode がこのフォルダにありません（/Users/johnd/Desktop/O1_実施用_macOS）。
    ★ フォルダの中身を移動していないか確認してください
exit=1
```

⚠️ README 【1】手順 5 の「OK: 準備できました…」は **O1 では絶対に出ない**。
→ ★ O1 の macOS 被験者は初回セットアップを 1 人も完了できない。

### 真因

`初回セットアップ_mac.sh:28` が `MARKER="g1.mode"` の**決め打ち**。
O1 の配布物には `o1.mode` があり `g1.mode` は無い (⚠️ 両方あると `lib.rs:3150` が起動を拒否するので、
混ぜて回避することはできない = 正しい設計)。同 script は他にも G1 前提が残っていた:

| 行 | 何 |
|---|---|
| 2 | ヘッダが「G1 実験 — macOS の初回セットアップ」 |
| 28 | `MARKER="g1.mode"` |
| 46 | NG 文言が「「G1_実施用_macOS」フォルダ」を名指し |
| 69 | OK 文言が「画面に「G1 モードで動作しています」と出ることを確認」★ O1 にその表示は無い |

★ O1 の実際の表示は `RecordingControls.tsx:334` の **「記録中 · 作業の種類: ○○」**
(同意文書 §2 の逐語)。⚠️ O1 はスタート画面を飛ばす (`App.tsx:339`) ので G1 の帯は出ない。

### ⚠️★★ なぜゲートが 1 つも捕まえなかったか (★ ここが本題)

`make-common-app-zip.sh` は 2 か所でセットアップを検査しているが、**両方 `--selftest`** である:

- `:422` 同梱直後に `bash "$M/初回セットアップ_mac.sh" --selftest`
- `:503` 展開後にもう一度 `--selftest`

★ `--selftest` は `初回セットアップ_mac.sh:97` で **自前の fixture に `: > "$fixture/g1.mode"` を作る**。
⚠️ つまり検査は「配られる実体」を 1 度も見ておらず、**自分で用意した世界の中でだけ緑**だった。

→ ★ memory の 2 つの型にそのまま当てはまる:
- `name-lookup-only-works-within-one-source` — 検査が「どちら側を見ているか」を問うていない
- `measurement-instrument-false-positives` — 自己完結した測定器は実体のズレを構造的に見られない

⚠️ `--selftest 17/17` も `make-common-app-zip` 本体の「セットアップ自己検査 ✅」も、
**この欠陥を持ったまま緑だった**。★ 緑は「配布物が動く」を意味していなかった。

### Windows 側は無事

`launch-o1-windows.bat:51` は `o1.mode` を正しく見ている。★ **macOS 固有**の欠陥。
⚠️ これは memory `windows-only-code-needs-ci` の逆向き
(「片方の OS だけ規則が違い、対の検査が無い」型)。

### 直し方 → `decisions.md` 判断 1 / 2

## B-2 ⚠️★★★ **O1 を含むリリースが 1 つも存在しない**（★ 本セッション最大の発見）

**状態**: 発見 2026-08-30 / ⚠️ **未解消（研究者の作業が要る）**

### 症状 (★ 実測)

修正済みの配布物を実機で起動し、`~/Documents/GSE-sessions/` を見た:

participant_id=P02165e17b7b1 source="fallback (Documents/GSE-sessions)"

```

★ `meta` 行にも O1 の痕跡なし。⚠️ **黙って通常モードで動いていた。**

### 真因 — ★ **配ろうとしていたバイナリに O1 の実装が無い**

| 検査 | 結果 |

| `git tag --contains 7a062cc` | ⚠️ **空 = O1 を含むタグは 1 つも無い** |
| `v0.1.29..main` | **103 コミット** |

配布バイナリ（`v0.1.29` の dmg から取り出した `gse-next`）の `strings`:

| 文字列 | 出現数 |
|---|---|
| `o1.mode` | ⚠️ **0** |
| `GSE_O1_MODE` | ⚠️ **0** |
| `gse_o1_` | ⚠️ **0** |
| `g1.mode` | 3 |
| `GSE_G1_MODE` | 1 |
| `gse-submit` の `--o1` | ⚠️ **0** |

→ ★ **マーカーを置いても読む側のコードが存在しない。**

### ⚠️ なぜ危険か（★ 画面上は何も壊れて見えない）

- ⚠️ ファイル名が `gse_o1_*` にならない → `reconcile --o1` の対象にならない
- ⚠️ 日次ローテートも 48 時間猶予も動かない → **提出候補にならない**
- ⚠️★★★ **ランダムプローブが復活する**（preregistration.md §5.4-5 /
  `初回セットアップ_mac.sh` 冒頭が警告している事故そのもの。★ 実測で確認）
- ★ 署名は有効・実行ビットも正常・`o1.mode` も入っている ＝ **配布物としては完全に正常に見える**

### ⚠️★★ 引き継ぎメモの前提が誤っていた

メモ §1-B は「★ 実在する最新タグは `v0.1.29`、その release 資産に dmg がある
→ O1 では `--tag v0.1.29` を明示的に渡す」と書いていた。
⚠️ ★ **「タグが新しい」しか見ておらず「O1 の機能が入っている」を見ていない。**
→ ★ ゲート化した（`decisions.md` 判断 3）。⚠️ 人が気をつける対策にしない。

### ★ 解消に必要なこと（⚠️ 研究者の作業）

1. `main`（O1 実装入り）から **新しいタグを切る**（例 `v0.1.30`）
2. CI でリリース資産を作る（⚠️ `aarch64` の dmg ＋ Windows の `.exe`）
   - ⚠️ memory `build-ci-and-pilot-distribution`: private のままだと Actions 分数枯渇で
     run が即 fail する。★ 一時 public にする運用がある
3. `--mode o1 --tag v0.1.30 --config Form_O1/o1_submit.json` で作り直す
   → ★ 新ゲートが通れば「O1 を知っているビルド」であることが機械で保証される
4. ⚠️ そのあとで §1-D（実機通し確認）と §1-E-4（送信 timeout 実測）を**やり直す**

⚠️★ **本セッションで §1-E-4 は実施できない**（★ 研究者は「実施してよい」と承認したが、
`gse-submit` に `--o1` が無いので **O1 の規則で包むこと自体ができない**）。

## B-3 ⚠️★★★ 配布フォルダの実測（★ 2 つとも実害）

```
permissions: [{"role":"reader","type":"anyone"}, {owner: <研究者>}]
中身: {"endpoint":"<省略>", "secret":"<省略>"}   ← ★ 実値は書かない（下記）

> ⚠️★★★ **本ファイルの旧版に O1 の実 secret の先頭 45 文字を書いてしまった**

⚠️★ **経緯は判明した（2026-08-30・研究者に確認）: 意図して置いたものである。**

(`make-common-app-zip.sh` の macOS 側 / Windows 側の `cp "$CONFIG"`)。

⚠️★★ **生置きと zip 同梱では露出の質が違う**（★ 「どうせ zip にも入る」で済ませない）:

| | zip の中 | ★ 生置き（現状） |
|---|---|---|
| 取得に要る手順 | ダウンロード → 展開 | ⚠️ **クリック 1 回で本文が見える** |

| 誤って別の相手にリンクを渡したとき | 気づく余地がある | ⚠️ 即座に読まれる |

- ⚠️ **読み出しは不可能**。`doGet` は `use POST` を返すだけで、`doPost` は Drive から読まない。

  → ★ **既提出 `.age` の閲覧・上書き・削除はできない**（`saveWithoutOverwriting_` が上書きを構造的に禁止）。
  ★ **被験者への同意の約束は破られていない。**
- ⚠️★★★ **書き込みは完全にできる**（`secretMatches_` は共有シークレット一致のみで認可。

  - ★ **データ捏造**: `pubkey.txt` は Windows 配布物に同梱＝公開情報。任意の NDJSON を

    ★ これは**プライバシーではなく研究データの完全性 (provenance) の問題**である。
  - ★ **可用性**: 1 POST あたり 48 MB。反復で Drive 容量や日次クォータを枯渇させると、
    ⚠️ 以後の正当な提出が落ち、`.gs` のコメント自身が認めるとおり「その日は永久に届かない」。
