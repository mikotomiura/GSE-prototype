# 重要な設計判断 — Windows self-hosted ＋ 30 秒フォールバック

## 判断 1: 自動フォールバックは「前段ジョブ ＋ PAT」以外に手が無い ★ 実測で 1 つに絞られた

- **判断日時**: 2026-08-15
- **背景**: ★ 研究者の要求は **「30 秒程度ずっと応答なかったら従来に戻る」**。
- **選択肢と却下理由**:

| 案 | 判定 | 根拠（★ すべて実測） |
|---|---|---|
| 短い `timeout-minutes` を付けたプローブジョブ | ❌ | ⚠️★★★ **`timeout-minutes` はジョブの実行時間にしか効かず、キュー待ちには適用されない** |
| `continue-on-error` の self-hosted ジョブ ＋ 後段 hosted | ❌ | ⚠️ **offline 時は「失敗」ではなく「滞留」**（★ 24〜48 時間）なので後段が発火しない |
| `if: failure()` で hosted に再実行 | ❌ | ⚠️ 本物のテスト失敗でも再実行され、**Windows は 2 倍課金** → ★ **目的（課金削減）と衝突** |
| repository variable による手動切替 | ❌ | ⚠️ 落とす前にフラグを戻す運用が要り、**忘れると 24 時間滞留**（★ 研究者が自動側を選択） |
| ★ **前段 `decide` ジョブ ＋ PAT** | ✅ | ★ **唯一成立する**。⚠️ ただし **`GITHUB_TOKEN` ではランナー一覧を取得できない**ため PAT が要る |

- **採用**: ★ **前段 `decide-win-runner` ＋ fine-grained PAT**
- **トレードオフ**: ⚠️ **secret が 1 つ増える**（★ 当 repo のみ・`Administration: Read`・期限付きに絞る）。
  ⚠️ **mac 側も `needs` で最大 30 秒待つ**ようになる。
- **影響範囲**: `.github/workflows/ci.yml` の `check` / 新規 `decide-win-runner`。
- **見直しタイミング**: ★ GitHub が hosted への自動フォールバックを提供したら、この前段は不要になる。

## 判断 2: 失敗側は必ず hosted（fail-safe）★ これが設計の核

- **判断日時**: 2026-08-15
- **背景**: ⚠️★★★ **最悪の結果は「CI が 24 時間滞留して気づかれないこと」**である。
- **採用**: ★ **PAT 未設定・API エラー・タイムアウトのいずれでも `["windows-latest"]` を返す。**
- **理由**: ★ **secret を置く前でも CI は壊れない**（★ 常に従来動作へ落ちるだけ）。
  → ★ **手順 1（ランナー登録）と手順 2（PAT）の順序を問わない**という運用上の利点も出る。
- **実測**（★ workflow の `run:` を YAML から取り出して直接実行）:

| 経路 | 期待 | 実測 |
|---|---|---|
| ランナー online | self-hosted | ✅ **attempt 1 で即決**（⚠️ `gse-win` は未登録のため、実在する `gse-mac` にラベルを差し替えて検算） |
| 未登録 / offline | 30 秒後に hosted | ✅ `["windows-latest"]` |
| PAT 未設定 | **即** hosted | ✅ ポーリングせず即決 |

- **トレードオフ**: ⚠️ **「本当は self-hosted で走ってほしかったのに hosted で走った」を見逃しうる**。
  → ★ `::notice::` でログに必ず理由を出す形にした。

## 判断 3: `build-windows` は hosted のまま残す

- **判断日時**: 2026-08-15
- **理由**: (a) ★ **タグ push / 手動発火でしか走らない＝恒常的な支出ではない**（★ 目的は課金削減）。

  ★ 割り当ては**ジョブ開始時に確定**するのでフォールバックが効かない。
