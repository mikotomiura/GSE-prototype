## 設計案比較（/reimagine 1 回目・2026-11-21）

### v1 の要旨
外に出るもの（照会・検索の手順）を先に出す → 調べもの → 解析を足す → 本文を指摘ごとに直す → 最後に組版を elsarticle へ移す、という一本道。凍結を壊さない（既存のキーは不変）・数字は機械生成・外延を絞る、を柱にする。JSS の規程の事実（§0）と、指摘と節の対応表（§4）を持つ。推薦の査読者の用意を、JSS の 20 件の上限への備えとして挙げた。

### v2 の要旨
照会を 0 日目に出し、待つ 2 週間に並行で進める。順は「枠 → 数 → 名前 → 本文 → 外枠の文」。組版の移行を最初に、本文の差分 0 で切り離す。本文を `body.tex` に分けて雑誌ごとの枠から読み、JSS で査読に回らなければ IST へ枠だけ替える。名前は辞書を先に作る。本文は内側から外側へ書く。受け入れの検査を規程の数値・禁止する文言・凍結した節のハッシュまで機械化する。

### 主要な差異
| 観点 | v1 | v2 |
|---|---|---|
| アプローチ | 指摘の順（verdict §5）に直し、組版は最後 | 枠を最初に移し（本文の差分 0）、本文は内側 → 外側。要旨・題・Highlights は最後 |
| 技術選定 | elsarticle に移す（`main.tex` 1 本のまま） | elsarticle ＋ `body.tex` と雑誌ごとの枠に分ける（IST への替えが軽い） |
| 照会 | 段 1 で文面 → 送る | S0 で journal 版の数字を一次で確かめてから文面 → 送る（誤った照会を防ぐ） |
| 名前（C） | 本文を直す中で用語をそろえる | 辞書を先に作って研究者が選ぶ → 一括で置き換え（`metrics.json` のキーは不変） |
| 変更規模 | 同程度（どちらも major・minor を全部） | 同程度 ＋ ファイルの分割・検査の追加がやや多い |
| テスト | `run.sh`・`build.sh` 緑・既存のキーの byte 一致・要旨の語数・Highlights・キーワード・陰性対照 | v1 のすべて ＋ 頁数・申告の節の位置・禁止する文言・要旨の符号と metrics の一致・凍結した節のハッシュ・派生表からの再計算・tasklist の閉じ方の grep |
| リスク | 組版の移行が最後に来るので、頁数と見た目の崩れが本文の改訂と同じ差分に混ざる。照会が数字の確認の前に出うる | ファイルの分割が `build.sh`・`/cross-review` の差分を大きくする。検査が増えたぶん、検査自体の誤り（常に真）が増えうる → 変異で潰す前提 |
| v2 だけが挙げた論点 | — | 「DF3 を除く」と「DF3 を解決に数え直す」は別の量（名前を分ける）／ 補助の区間が「役に立たない」結論も選べるようにする／ 生成 AI の申告は研究者の手入れが前提／ `NOTES.md` の "other project" |
| v1 だけが挙げた論点 | 推薦の査読者で 20 件の上限に備える（v2 も懸念 1 で同じ点に触れた）／ D1 の元データは CC BY 4.0（`DATA.md`）で派生表は帰属表示で出せる見込み・URL を入れない | — |

### 推奨案
**v2 を土台にしたハイブリッド** —— 理由:
- v2 の「枠を先に、本文の差分 0 で」は、v1 のリスク（組版の崩れと内容の誤りが混ざる）を直接消す。`body.tex` の分割は、JSS で査読に回らなかったときの次の手（IST）を安くする。JSS にも 20 件の上限があるので、この備えには実利がある。
- v2 の S0（照会の前に journal 版の数字を確かめる）と、懸念 2・3・5 は、v1 が見落とした誤りの種である。
- v1 から引き継ぐのは 2 点。§0 の JSS の規程の事実（v2 は事実を受け取っただけで、出典の記録を持たない）と、K の具体（CC BY 4.0・URL を除く）。指摘と節の対応表は v2 の §4 に既に入れた。
