# 要件: メディア表現における聴覚モダリティの接地と、制作ツール連携

- タスク ID: `20260810-media-sound-modality-and-creative-tooling`
- 起票日: 2026-08-10
- 種別: 研究トラック（サーヴェイ 1 ラウンド）＋ 開発ツーリング設計

## 背景

`.idea/20260806-media-self-reflection-and-behavioral-intervention.md`（第 2 版）と、
それを支える `docs/literature/20260807-self-state-externalization-and-ambient-media.md` は
**「音を足す」について次の判定で止まっている**:

- `[P52]` の配分則（触覚＝低複雑度 / 聴覚＝高複雑度）に照らすと、GSE が伝えたいのは
  `p_stuck` という **1 次元・低複雑度の信号**であり、**聴覚は過剰なチャネル**である。
- したがって **「音を足す」を文献で正当化できない**。採るなら「設計判断」として書くしかない。
- 追補で未着手 3 として、**「聴覚は閉じられないので無視のコストが上がる」は文献確認できていない推論**
  であることが明記されている（周辺視覚 vs 聴覚の「無視に要する行動」を扱った研究が未探索）。

この「未着手 3」が本タスクの直接の入口である。ここが埋まると
`[P46]` の帯域（強制的でないが簡単に無視・上書きできない）に音が届くかが判定でき、
`.idea` §3.7 の「音は既に介入側の道具である」という主張の温度が確定する。

同時に、実機（Windows・本タスクの作業機）に **TouchDesigner 2025.33070 / Adobe Substance 3D 一式 /
After Effects / Audition / Blender / Cinema 4D** が揃っていることが判明した。
表現の候補を紙の上だけで決めずに済む条件が既にあるため、
**試作を高速に回すための Claude Code 連携**を設計に含める。

## ゴール

1. **サーヴェイ 1 ラウンドを `docs/` に landing させる**
   - `docs/literature/20260810-*.md`（落合フォーマット・敵対的 3 票検証）
   - `docs/references.md` に `[Pn]`/`[Vn]` を **append-only** で登録（P53 / V78 の次番号から）
   - `docs/literature/_index.md` に行を追記
   - 既存 gate 判定（`de-risk 先行` / 音は第 1 版に入れない）を **更新するか維持するかまで結論を出す**
2. **音の主語を 2 層に分けて書く**
   - 主軸 = **制作者の設計語彙**（どの音がどう感じ取られるかを正確に扱う）
   - 別枠 = **被験者の感性が育つか**（★ 無接地の探索仮説として明示的に隔離。
     `research-positioning §7`「過大主張の自制」に抵触させない）
3. **TouchDesigner / Adobe を「試作・デザイン探索の専用ツール」として連携の**選択肢**を出す**
   - GSE 本体は Rust のまま。被験者に配る成果物には含めない
   - Claude Code から回せる形（CLI / スクリプト / ファイル生成）を、**実機で確認した事実**に基づいて提示する

## ★ 本タスクの温度（2026-08-10 追記・ユーザー指示）

**本件はまだアイディア段階である。具体的な設計は随時・段階的に検討する。**

したがって本タスクが確定させてよいのは以下に限る:

| 確定させる | 確定させない（次以降で随時） |
|---|---|
| **文献の判定**（何が支持され、何が無接地か） | 音のパラメータの最終仕様 |
| **アイディアの選択肢と、その各々が背負うリスク** | 採用する媒体・音色の決め打ち |
| **実機で何ができるか**（TD/Adobe の事実確認） | TD パッチの本実装・GSE 側 OSC/WS の実装 |
| **既存 SSOT と衝突する箇所の特定** | `research-positioning` / ADR の改訂 |

→ 成果物は「**決定**」ではなく「**判断材料と選択肢**」として書く。
  設計を 1 案に絞る書き方をしない（絞るのは実装着手時の別タスク）。

## 運用メモ

- /reimagine 適用: **No**
- 理由: 本タスクの主成果はサーヴェイ（文献の判定）と外部ツールの連携設計であり、
  複数の実装案が競合するアーキテクチャ判断を含まない。TD 連携も「試作専用」に限定した時点で
  GSE 本体の設計に食い込まない。ただし **サーヴェイの結果が gate 判定を覆した場合**
  （音が `[P46]` の帯域に届くと判定された場合）は、介入層の設計判断になるため
  その時点で `/reimagine` を再検討する。
