# 設計判断（2026-08-29）

## D-1: T-25 は **既存の運用ステータス トグルに相乗りする**（新トグルを作らない）

- **決定**: `phase1Frozen_()` を足し、`PHASE1_CONTROL_TAB` /「実施中」「終了」という
  **既にある**真実源を読む。凍結時は `refreshRosterStatus` / `buildDashboardTab_` /
  `buildReminderPlanTab_` が `countByPid_` より前に抜ける。
- **理由**: ★ `.steering/20260829-o1-roster-guards/decisions.md` G-1 を書いた時点では
  **GAS の中身が読めていなかった**。⚠️ 取り込んだら運用トグルが既にあり、
  `sendReminders` が既にそれを読んでいた。→ **2 つ目の真実源を作るほうが害**である
  （★「送信は止まったが集計は動いている」というちぐはぐが起きる）。
- **却下案**:
  - 定数で恒久的に凍結（`var PHASE1_ENDED = true`）… ⚠️ 再開に**コード変更と貼り直し**が要る。
    ★ 貼り直しは今回まさに事故りかけた操作であり、研究者に踏ませたくない。
  - 「研究」列をロスターに足して Phase1 行だけ数える … ⚠️ `Form_G1/` を触れないので
    G1 由来の行が空欄になり、★ 空欄の意味が二義的になる（G-1 で既に却下済み）。

## D-2: 凍結時は **集計値を 1 つも表示しない**

- **決定**: 凍結タブには理由・再開手順・更新時刻だけを書き、到達率 / 完了率 /
  平均セッション数 / 要フォロー一覧は**出さない**。検査で禁止ラベルの不在を固定した。
- **理由**: ⚠️★★★ **凍結後に出せる数字は「古い」のではなく「誤り」である。**
  ロスターは 3 研究の共用で、集計は全行を Phase1 の母数に数える
  （`readRoster_` → `active = data.filter(!excluded)`）。
  → G1 / O1 の行が増えるほど**分母だけ増えて**完了率が下がる。
  ★ 最後に計算できた値も、既に G1 / O1 の行が入った後の値であり、同じ理由で誤っている。
- **却下案**: 直前のスナップショットを残して「更新停止」の帯だけ付ける …
  ⚠️ **誤った数字を保存する**ことになる。★ 見た人は正しい Phase1 の実績だと読む。

## D-3: 凍結判定は **fail-closed**（`phase1Status_` と逆に倒す）

- **決定**: ステータスを読めない / 管理シートを開けない場合は**凍結する**。
  ★ ただし「コントロール未設置（＝初期段階）」は凍結しない（初回構築を妨げないため）。
- **理由**: ★ 読めないときに集計を続けると D-2 の「誤った数字」をそのまま出す。
  ⚠️ 一方で凍結側に倒しても、出るのは「凍結中」の表示だけで**復帰可能**である。
  → 非対称なので、害の小さい側へ倒す。既存 `reminderSendingAllowed_` と同じ思想。
- **却下案**: `phase1Status_` をそのまま使う … ⚠️ あれは**表示用の fail-open** であり、
  ★ コメントに「送信可否の判定には使わない」と明記されている。転用は設計意図に反する。

## D-4: ⚠️ 取り込みコミットを **GAS と 1 箇所だけ違う形**でコミットした

- **決定**: `REMINDER_WEBAPP_URL` の実デプロイ URL 直書きを、
  スクリプト プロパティ（`GSE_REMINDER_WEBAPP_URL`）読み出しに変えてからコミットした。
  → ★ 取り込みコミット時点では **repo と GAS は一致しない**（貼り戻しで一致する）。
- **理由**: ⚠️ そのままコミットすると `check-o1-release-readiness.sh` が
  **「秘密が git に入る（実 endpoint）」で赤**になった（実測: 通過 15 / 未達 2）。
  ★ この検査は「入る前に止めるしかない」という前提で書かれている
  （`.gitignore` 自身が「一時 public 運用がある」「履歴からは消せない」と記す）。
  ⚠️ **まだ push していなかった**ので、履歴に残す前に直せた。
  さらに実害の中身も確認した: この URL は `?pid=P0xx&action=will_do|rest` を叩けば
  **ロスターに実在する P-ID の応答を偽装できる** capability URL である
  （`doGet` → `reminderConfirmPage_` → `reminderRecordResponse`）。
- **却下案**:
  - 忠実に取り込んでから次のコミットで直す … ⚠️ **履歴に実 URL が残る**。
    ★ 検査が守ろうとしているものを、検査を通した上で破ることになる。
  - `gate:allow-id` で例外にする … ⚠️ これは**正当な例外ではない**。
    ★ 配備ごとに変わる値であり、まさにスクリプト プロパティへ移すべき類のもの。

## D-5: ⚠️ 取り込みは「私が書き写す」のではなく **ページから直接転送**した

- **決定**: `monaco.getValue()` を 15,000 文字 × 9 回で `127.0.0.1` のローカル受け口へ POST し、
  全文の SHA-256 で突き合わせた。★ 私は本文を 1 文字も転記していない。
- **理由**: ⚠️ 引き継ぎの想定（分割して 1 回ずつファイルに追記）だと、
  **120,825 文字を私が打ち直す**ことになる。★ 写し崩れは**無音で起きる**。
  → 転送経路から私を外すのが最も確実。⚠️ ハッシュ照合はそれとは独立に行う。
- **却下案**: `clasp clone` … ⚠️ 未インストール・未ログインで、
  ★ **OAuth の付与は勝手に進めない**（`browser-verification` §4）。研究者の手を止める。
