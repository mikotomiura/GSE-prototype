## 設計案比較（PR 1 の再生）

### v1 の要旨

駆動役 `S1Driver` ごと記録から回し、行への写し方も本物と同じコードを通す。開いているカードは再生の発火から作り、閉じる時刻だけ記録から借りる。`--utc-offset-secs` を必須にする。分類は `matched・missing・extra・boundary・debug・outside_state`。

### v2 の要旨

調停器 `Arbiter` だけを回し、開いているカードは記録から作って渡す（不一致を後ろへ波及させない）。記録に無い情報（tick の位相・枠の動き出し・時差・前日の状態・スリープの復帰・起動・取り消し）を洗い出し、照合できないものを `unverified` の 5 種に分ける。tick の位相を 4 通り回して割れたものを境目にする。`first_divergence_ms` と回答率の内訳を出す。

### 主要な差異

| 観点 | v1 | v2 |
|---|---|---|
| 回すもの | 駆動役ごと（写し方の再利用） | 調停器だけ（開いているカードは記録から） |
| 不一致の波及 | 再生の発火で開いたカードが後ろの判定を変え、1 件のずれが連鎖する | 記録のカードを渡すので連鎖しにくい。中の状態のずれは `first_divergence_ms` で見る |
| 記録に無い情報 | 時差・前日の状態の 2 つだけ。⚠️ スリープの復帰（行が無い）を見落とし、毎日ウォームアップで不一致が出る | 7 つを洗い出し、照合できないものを `unverified` に分ける |
| 時差 | 必須 | 任意（no_ask は既定で無効なので無作為は照合できる）。`--day-questions` は必須 |
| tick の位相 | 鍵を位相に依らないものにするだけ | 加えて 4 通りに振り、割れたものを `boundary_tick` に |
| 判断 2 の窓 | 2 秒 | 2 秒は変えず、割れうる 3 秒目を `near_pause_outside_window` で別に出す |
| 変更規模 | `s1_replay.rs` ＋ 印 | 同じ ＋ `lib.rs` の写しを純関数に切り出す（往復の検査のため） |
| テスト | 往復・消すと欠け・足すと余り・届く遅れ 0〜1900 ms | 往復・欠け・余り・seed を変えると一致がほぼ 0・境目の 1 秒前と 4 秒前 |
| リスク | 写し方を本物と共有するので写し方の誤りを再生が見逃す（同じ誤りを両側で犯す） | 写し方を再生に書かないぶん、行と Action の対応（抑制の `t` を鍵にしない等）を照合の側で正しく書く必要 |
| 誤った推測 | なし | 「起動とローテートを `session_start` で分けられる」は外れ（G1 のブロックだけ・`lib.rs:4631`）→ `unverified.app_start` に直した |

### 推奨案

ハイブリッド（v2 を土台に v1 の 1 点を足す）— 理由:

- v2 の「開いているカードを記録から渡す」は、照合の目的（記録が判定どおりか）に合い、1 件のずれで全体が崩れない。スリープの復帰を拾うのも v2 だけで、v1 のままだと実の記録で毎日不一致が出る。
- v1 から足すもの: 往復の検査で、押下の届く時刻を 0〜1900 ms 遅らせても一致し、2100 ms 以上で割れうることを見る陽性対照（2 秒の遅れが効いていることの検査。v2 の `lag_check` は実の記録の必要条件しか出さない）。
- v2 の `unverified.tail`（取り消し）は、取り消しの後に同意し直すと枠が作り直されるので、枠の切れ目で区切れば足りる。過剰な推定はしない。
