# 設計

## アプローチ

1. 今の GSE の研究の資産を客観的に棚卸しする（判断 4）。不採択コメントで評価された点は根拠に数えず、「何が弱いと読まれたか」の点検にだけ使う。
2. 強さが実測で言える資産から、一言の候補を 3〜5 つ組む。
3. /reimagine で別案を独立に出し、codex-consult の第二意見と合わせて比べる。
4. 研究者が採否を決める。位置づけが変われば新しい ADR と research-positioning.md、変わらなければ decisions.md に記録。
5. 派生の素材（未踏向け）を書き、attack-me で攻めさせる。
6. スライドに変わった所だけ反映する。

### 1.2 弱い所（外の読み手が突く所）

- 中心の主張（申告で見分けの範囲を測る・保留・招待）を支える人の申告は 0 件。設計の層（手跡・段 1・段 2）は全部データ 0。
- 人のデータは実質 n=1（H4a は D=5）。
- 否定の結果は 1 つの推定器についての否定。
- 「本文を保存しない」はプライバシーの保証ではない（R2 の照合）。
- 新規性は組み合わせについての「見つからなかった」で、探索は浅い。

### 1.3 現行の research-positioning と一次の食い違い（改訂で直す）

1. §1.4「AUC 0.49〜0.52 で、手前の信号は見えなかった」: KLiCKe は「検出できるがごく小さい」、学習器は 0.54〜0.57。「推定器の上がりは契機の根拠にならない」と書くのが一次に合う。
2. §1.4「停滞は短く（半分は十数秒以内）」は公開データの値。O1 では t0 から再開まで中央値 90 秒（`experiments/20261102-stall-decomposition/notes.md` S4）。
3. §11 の基盤「稼働」: CPU MARGINAL・総合 DataInsufficient を添える。

### 1.4 読み

客観的に強いのは、どれも「本文を保存しない打鍵の観測で、何が言えて何が言えないか」を実測した資産（R1 否定・R2 漏れ・R3 定義の揺れ）である。今の headline の中心（申告での見分け・保留・招待）は、データ 0 の設計の側にある。尖りを強い側に寄せるか、設計の側に置いたまま強い資産を「なぜこの設計か」の根拠に使うかが分かれ目になる。

## 2 一言の候補（初案・/reimagine の前）

| 案 | 一言 | 根拠の資産 | 強み | 弱み |
|---|---|---|---|---|
| C1 観測の限界を先に測る | 本文を保存しない打鍵の観測で、言えることと言えないことを先に測り、言えない所では系に判断させない | R1・R2・R3（すべて実測あり） | 尖りの全部が実測で支えられる | 計測の研究に見え、系（手跡・招待）が後ろに下がる |
| C2 否定の結果から組む | 打鍵からは先回りの契機が立たないと事前登録で確かめた。だから先回りせず、停滞の中身を本人の申告で測り、見分けられない所では判断を返さない | R1 ＋ 段 1 の設計（ADR-047） | 核の入れ替えが「逃げ」でなく根拠のある転換として前に出る | 前半は 1 つの推定器の否定、後半はデータ 0 |
| C3 本文なしの観測の両面 | 本文を保存しない観測が何を見分け、何を漏らすかを両方測ってから、系に判断させる範囲を決める | R1・R2（見分けの否定と漏れの実測） | 「本文なし＝安全」と「打鍵で状態が分かる」の両方の通念を実測で崩す | 停滞・招待との結び付きが一段遠い |
| C4 判断を控える系と手跡の対 | 系が判断を控える所では、判断ではなく本人の手の痕跡だけを返す | 設計（ADR-048） | 一言として短く、像が浮かぶ | データ 0。保留の要素は先行がある（§8） |
