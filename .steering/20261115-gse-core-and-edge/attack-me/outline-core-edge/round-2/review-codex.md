指摘は優先度順。fatal は認めない。

1. **major｜§1「同じ観測の上で測る」「どちらもそのままでは成り立たなかった」**  
   予測は公開データ、漏れは合成IME入力であり、同一の観測仕様について有用性と漏れを同時評価したとは読めない。限定された推定器の失敗も、状態推定という前提全体の反証ではない。  
   **解消条件：** 現成果を別々の検証として記述し、共通の観測仕様で両者を測ることを開発目標にする。**自信：高**

2. **major｜§3「どちらも同等の帯 [0.45, 0.55] の内」**  
   後付けという限定とは別に、この帯が実用上無視できる差を表す理由がない。全体AUCが小さくても、低頻度の招待に使う閾値付近の性能は別問題。区間が書き手内の依存を扱ったかも読み取れない。  
   **解消条件：** 誤招待の許容負担に基づく評価と、書き手単位の不確実性を併記する。**自信：高**

3. **major｜§4「停滞の始まりからの経過時間」「出す・出さないを無作為に割り付ける」**  
   長さで定義する停滞なら、始まりは事後確定になりうる。さらに招待が休止を変えるため、介入後に停滞例を選ぶと比較が歪む。  
   **解消条件：** 過去情報だけで適格時点を固定し、割付後の全例を追う。定時・本人起動も比較候補にする。**自信：中〜高**

4. **major｜§3「10 候補で 0.902」「100 候補で 0.421」**  
   句・入力生成条件・反復試行の分割次第で、未知の入力への照合と既知テンプレートの再認が混ざる。候補数だけでは攻撃難度を規定できない。  
   **解消条件：** 攻撃者の学習情報、候補の選び方、分割単位を示す。文字数など単純な照合との比較、棄却ありの評価を加える。**自信：高**

5. **major｜§1「公開の道具」「4 面の地図」**  
   読める／漏れるは排他的でなく、非有意と読めないも異なる。分類図だけでは、観測を粗くした際の精度・漏れ・負担の交換条件が隠れる。  
   **解消条件：** 条件付きの連続値と不確実性を出す監査レポートも検討する。外部データへの適用可能性と設計変更の判断可能性を完成条件に置く。**自信：高**

**総合推奨：major**  
限定の記述は改善されているが、冒頭に証拠を束ねすぎた主張が残る。  
介入と照合の評価条件を固定すれば、解釈上の大きな穴を減らせる。  
道具が可能にする具体的な設計判断を示すと、未踏向けの尖りが明確になる。
