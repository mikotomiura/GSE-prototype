# 検討メモ: 招待の出し方を本人が選べるか（2026-09-19）

## 1. 既にある「本人が選べる」仕組み（★ 一次で確認）

| 仕組み | 何を選べるか | 出所 |
|---|---|---|
| 介入の有効 / 無効 | セッションが宣言する（★ 研究の条件として。本人の設定ではない） | `session_meta.intervention_enabled`（`lib.rs:108` / `App.tsx:101`）。⚠️ O1 は判断 O1-5 で介入を出さない |
| 表現層のオフスイッチ | 止める・音量を変える（★ **交渉不可の要件**） | `docs/glossary.md`「オフスイッチ要件」・ADR-022 D7 |
| 自動開始型の機能を再開するときの必要条件 | 事前オプトイン・**内容ごとの選択的無効化**（[P134]: 78.6% が要求）・開始前 cue・行動側の対照 | ADR-017 D5 |
| 配色テーマ | 本人が選ぶ（★ 層 B へ移した） | ADR-021 D3 → ADR-022 D3 |
| Physical Anchor | 初期は opt-in | RP §9 |

## 2. 既決が退けた「選ばせ方」

- ⚠️ **完了条件を本人に設定させる**（self-set goal）は ADR-018 の Alternatives で却下 —— [P99] 逐語 *"anticipated evaluation … d = −0.40"* は**評価が予期されること自体**を毀損要因にしている。
  → ★ 本人が選ぶのは**系の振る舞い**（いつ・どれだけ招待されるか）であって、**本人の目標**ではない、という線を引く必要がある。
- ⚠️ ADR-026 PC-6 は招待の提示回数の上限を Nudge の cap と別に決める（★ 値は未定）。PC-5 は提示を作業の切れ目まで遅らせることを要件にしない。

## 3. 選択肢

| 案 | 中身 | ★ 利点 | ⚠️ 代償 |
|---|---|---|---|
| **A. 原則だけの ADR（Proposed）を起こす** | 「招待の有無と時期の範囲を本人が統制できる」を要件にする。★ 原則: (1) **既定値を置き、選ばなくても成り立つ**（[P386] の選択の負担）、(2) 選択肢は少数（有無・時間帯・上限）、(3) **設定の変更を「応答」として扱わない**（ADR-033 の非再捕捉）、(4) **本人の目標にしない**（ADR-018 の self-set goal の却下）、(5) 数値で返さない（ADR-025）。★ UI と値は Physical Anchor の実装時に決める | ★ S2 の含意（[P380]）を設計の制約として先に固定できる。RP §3 が「GSE の招待を非支配的とは言えない」と書いた穴に、答える経路が SSOT に立つ | ⚠️ 実装が無いうちに要件を立てる。⚠️ 原則 (1)〜(5) の一部は既決の言い換えになる |
| **B. 起票しない** | 既存の仕組み（オフスイッチ・事前オプトイン・内容ごとの選択的無効化・PA の opt-in）で足りるとする | ★ SSOT が増えない | ⚠️ 「時期」を本人が統制する経路は既存の仕組みに無い（★ オプトインは「有無」だけ） |
| **C. 延期** | Physical Anchor の実装の設計タスクで決める。`docs/architecture/expression-channel.md` §8 に未決として起票する | ★ 実装の制約（PC 面の要件 12 本）と一緒に決められる | ⚠️ 実装の設計が始まるまで、S2 の含意が未決のまま残る |

## 4. 推奨

- ★ **A（原則だけの Proposed ADR）**。理由: (i) RP §3（2026-09-19）が「招待を出す時期と有無を系が決め、本人が統制できないかぎり非支配的とは言えない」と書いたので、それに答える設計の経路が SSOT に要る、(ii) 原則は既決（ADR-017 D5・018・025・033）と矛盾せず、それらを招待の出し方へ写すだけで立つ、(iii) UI と値を決めないので、実装の設計を先取りしない。
- ⚠️ ただし、A を採っても「GSE の招待は非支配的である」とは書かない（★ 統制の経路が実装されるまで）。
