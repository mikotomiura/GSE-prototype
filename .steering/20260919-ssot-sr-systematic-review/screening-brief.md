# ふるい分けの手順書（サブエージェントへ渡す）

> ★ 採否基準は `protocol.md` §4 のとおり。**変えない**。迷ったら段 1 では採る。
> 入力: `$CLAUDE_JOB_DIR/tmp/sr/merged_C<n>.jsonl`（1 行 1 件: `sid` / `doi` / `title` / `year` / `venue` / `hits` / `abstract`）。

## 手順

1. **段 1（題名と抄録）**: 入力の**全件**を読み、各件を「採る / 採らない」に分ける。
   - 採る: (i) 対象が対話的・適応的・自動化・アルゴリズムの系（HCI・HRI・自動化・推薦・通知・介入）であり、**かつ** (ii) その候補（下の定義）を**明示的に**述べる・提案する・操作化する・実測する。
   - 採らない: 語が出てくるだけ／法的・組織上の権限で系と関係しない／候補と逆向きの主張しかない（★ 逆向きの主流の例として別に記録してよい）。
   - ★ 抄録が無い件は題名で判定し、迷ったら採る。
   - 判定を `$CLAUDE_JOB_DIR/tmp/sr/stage1_C<n>.jsonl` に全件（`sid` / `decision` = include|exclude / `reason` 一行）書く。
2. **段 2（本文）**: 段 1 で採った件について、公開本文（OA・著者版・arXiv・出版社の HTML）を WebFetch で開き、候補の定義に当たる**逐語**を探す。取れなければ抄録で判定し「抄録のみ」と書く。
   - 判定: **該当**（定義に当たる逐語あり）／**部分**（一部の要素だけ）／**非該当**。
3. 出力: `.steering/20260919-ssot-sr-systematic-review/screening-C<n>.md` に次を書く。
   - 件数（入力・段 1 で採った・段 2 の該当 / 部分 / 非該当）
   - 段 1 で採った全件の表（`sid`・題名・年・DOI・採った理由）
   - 段 2 の判定表（`sid`・判定・**逐語**（英語のまま・頁や節）・どの要素に当たるか・本文を読めた範囲）
   - 逆向きの主流の例（あれば・数件）
   - 候補ごとの結論（「該当あり」「部分的に既出」「本プロトコルの範囲で該当 0 件」）。⚠️ 「先行研究が存在しない」とは書かない。

## 守ること

- ⚠️ `docs/` と `docs/references.md` は編集しない（登録はメインが行う）。
- ⚠️ 逐語は本文で確かめたものだけを書く。要約を逐語として書かない。
- ⚠️ NDJSON・キーストロークの内容は扱わない（本件は文献だけ）。
- 応答は日本語。最後にメインへ返す報告は、件数・該当 / 部分の一覧（逐語つき）・結論だけに絞る。
