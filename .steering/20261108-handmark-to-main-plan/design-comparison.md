## 設計案の比べ（/reimagine 1 回目・2026-11-08）

### v1 の要旨
- 試作は rebase せず、main の上に書き直す。PR は部品の種類で横に切って 6 本にする。
  - 文書 → OS 非依存（風・割付・行種・再生・種）→ macOS の背景・帯・トレイ（打鍵・カーソル・クリック）→ 条件 (b) の実測 → ホイールと「背景を見る」→ 机上の道具 → 日の問いの項目。
- 決定性は「描画の種を記録する」として OS 非依存の PR に入れ、描き直しの道具は後に置く。

### v2 の要旨
- 書き直すのは同じ。PR は、後期を始められる最小の縦の切れ端を先に入れる形にする。
  - 割付・行種・入口の門・状態の純関数・背景（打鍵だけ）・切る／戻す・記録の検査を 1 本にする。
- 帯・カーソルとクリック・机上の道具・ホイール・「背景を見る」・日の問いは、その上に 1 本ずつ足す（PR 0〜7 の 8 本）。
- 決定性を「状態は入力の列と種の純関数」という約束として最初に入れる。描画の回数は状態に影響させない。
- 段 1 のモードで、かつ表のファイルがあるときだけ動く門を置く。O1 と本人の前期には何も起きない。表を消せば戻る。

### 主な違い
| 観点 | v1 | v2 |
|---|---|---|
| 切り方 | 部品の種類で横に切る（OS 非依存／macOS） | 後期の 1 日が成り立つ縦の切れ端を先に入れ、残りを足す |
| 後期を始められる時点 | PR (3) の後（文書・OS 非依存・macOS の 3 本が要る） | PR 1 の後（文書を除けば 1 本） |
| 決定性 | 種を記録する。描き直しの道具は後 | 状態は純関数という約束を PR 1 に入れ、性質のテストで縛る。道具は PR 4 |
| main の他の利用者への影響 | 明示していない | 段 1 のモードと表のファイルの門。fail-closed・表を消せば戻る |
| 条件 (b) の実測 | ホイールの PR の前に、別に行う | PR 3 が入った main のビルドで、開発用の設定で入れ切りして比べる（本人の段 1 の Mac で別ビルドを並べない） |
| PR の数 | 6 本 | 8 本（文書を含む。2・3・6 は順を入れ替えられる） |
| 1 本目のコードの PR の大きさ | 中（OS 非依存のみ・画面なし） | 大きめ（背景の層と配線を含む・画面を見る） |
| テスト | 単体・画面 | 決定性の性質・門の陽性と陰性・記録が増えない・割付の持ち越し・画面 |
| リスク | 描画を後で作り直す恐れ（決定性が描画の作りしだい）。後期を始めるまでの PR が多い | 1 本目が大きく、レビューが重い。状態から特徴を作れば十分かは推測（PR 4 で画素と比べる） |

### 推奨
ハイブリッド（v2 を土台にする）。理由は 3 つある。
1. 後期を始められる時点が早い。後期の始まりの日は R4・R6′・R7・R8 しだいで動くが、1 本入れば始められる。
2. 決定性を約束として先に縛れば、判断 2 の漏れの確かめが、後で描画を作り直すことに引っ張られない。
3. 門があるので、main に入れた時点で O1 や本人の前期を壊さない。

v1 から取るもの: 1 本目が大きすぎるときは、v1 のように OS 非依存の部分（割付・行種・門・状態の関数・記録の検査）を PR 1a、背景の層と配線を PR 1b に割ってよい。どちらも後期を始めるのに要るので、1a と 1b は続けて出す。
