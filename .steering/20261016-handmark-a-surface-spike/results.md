# 結果 —— 手跡の案 A の小面が Mac で成り立つ条件

実測の環境: MacBook Air（Apple Silicon・画面 1470×956 論理 px）・macOS（Darwin 27.0.0）・開発版（`npx tauri dev`・debug ビルド）・2026-10-16。

## 1. 遅れ（Claude が測った・アプリ内の時刻）

区間: フックが打鍵の時刻を取る → channel → 分析スレッド → `emit_to` → WebView → 描画の後の 2 つ目の `requestAnimationFrame`。画面に光が出るまで（合成・ディスプレイ）と、キーが沈んでから CGEventTap までは含まない。

| 列 | n | 最小 | 中央値 | 95 パーセンタイル | 最大 | 200 ms 超 | 250 ms 超 |
|---|---|---|---|---|---|---|---|
| 間隔 0.2 秒（予備） | 10 | 21 | 37 | 52.3 | 55 | 0 | 0 |
| 間隔 0.15 秒 | 200 | 28 | 50 | 66.0 | 67 | 0 | 0 |
| 間隔 0.06 秒（光る動きが重なる速さ） | 100 | 17 | 52 | 54.0 | 55 | 0 | 0 |
| 合計 | 310 | 17 | 52 | 65.0 | 67 | 0 | 0 |

- 欠測の照合: 窓へ送った通知は通し番号で 0〜314 の 315 件、CSV の行も 315 行で、欠けも重複もなかった（範囲外として捨てた値は 0 件）。外した 5 件は次の項。
- 判定: アプリ内の区間では、合格の線（95 パーセンタイル 200 ms 以内・全回 250 ms 以内）を満たした。生データは `latency-run1.csv`（通し番号と遅れだけ）。
- 合成の打鍵は `synthetic-keys.applescript`（TextEdit に a〜z を 1 文字ずつ）。
- 外した 5 件: 計測の途中で、合成ではない打鍵が 5 件入った（種類は navigation・約 150 ms 間隔・合成のスクリプトは a〜z しか打たない）。研究者かほかのプロセスの打鍵と見て、判断 4 に従い CSV から外した（seq 10〜14）。打鍵の時刻と種類を持つ NDJSON（scratchpad）は集計の後に消した。
- 未: 画面に光が出るまでの抜き取り（研究者のスローモーション撮影・`manual-check.md` §3）。

## 2. 取り込みからの除外

- `set_content_protected(true)` の後に NSWindow の `sharingType` を読み返し、`None` を確かめてから窓を出している。実機の起動で読み返しは通った（`surface shown` のログ）。
- 未: 実際に写らないかの目視（研究者・`manual-check.md` §1）。読み返しが通っても写る経路がありうるので、ここが本当の判定になる。

## 3. fail-closed（判断 6）

- 模擬の失敗（`GSE_HANDMARK_SPIKE_FORCE_PROTECT_FAIL=1`）で起動すると、`surface NOT shown (fail-closed)` の警告が出て、窓の一覧（AX）は本体の窓 1 枚だけになった。アプリは動き続けた。模擬の失敗なので、本物の設定の失敗は起こしていない。
- アプリの終了: 小面を出したままトレイの「GSE を終了」で終わらせても落ちなかった（致命的な誤りのログも、新しいクラッシュレポートも無し）。窓に閉じる要求が来た場合も、壊さずに隠すだけの経路に流すようにした（判断 9）。
- 途中で見つけた欠陥: 最初の実装は、失敗したときに NSPanel にした窓を `destroy()` していた。その直後に `fatal runtime error: Rust cannot catch foreign exceptions` でアプリ全体が落ちた。隠す（`order_out`）だけに直して落ちなくなった。トレイから閉じる処理も同じ形に直した。本体に入れるときは、NSPanel にした窓を壊さないこと。

## 4. クリックの透過・フォーカス・位置

| 項目 | 方法 | 結果 |
|---|---|---|
| 大きさ・位置 | AX で窓を読む | 48×48、(1406, 805)。主画面の作業領域の右下の端から 16 px |
| フォーカスを奪わない | TextEdit を前面にして合成の打鍵 310 回、前後で前面のアプリを読む | ずっと TextEdit |
| クリックを奥へ通す | 小面の下に TextEdit を敷き、Finder を前面にして CGEvent のクリックを出す | 陽性対照（小面の外の TextEdit）で TextEdit が前面に来た。小面の中心・角の近くのクリックでも TextEdit が前面に来た。gse-next は前面にならなかった |
| すぐ閉じられる | トレイの「小面を閉じる」を AX で押す | 小面だけが消え、アプリは動き続けた。閉じたことはログに出ない |

- System Events の `click at` は陽性対照でも前面のアプリを変えなかったので使っていない。
- 未: 他の窓・全画面のアプリ・別の Space の上に出続けるか（研究者の目視・`manual-check.md` §2）。

## 5. 規則（親タスク判断 16）

| 規則 | どこで守っているか |
|---|---|
| 推定を使わない | `handmark_spike.rs` は `engine`・`invitation`・`FeatSnapshot`・`p_stuck` を use しない。分析スレッドでの呼び出しは、推定の前に、打鍵の時刻を渡す 1 行だけ |
| 本人の操作を記録しない | 窓はマウスを受けない。トレイから閉じても記録しない。計測の CSV は `GSE_HANDMARK_SPIKE_MEASURE=1` のときだけ・通し番号と遅れだけ |
| 持ち越さない | 状態はプロセスの中の 1 つの動きだけ |
| すぐ閉じられる | トレイの「小面を閉じる」（§4） |
| 数値・良し悪しを載せない | 描くのは灰色の丸 1 つだけ |
