# 重要な設計判断

## 判断 1: 試作の置き場と形

- **判断日時**: 2026-10-16（研究者・AskUserQuestion・推奨どおり）
- **採用**: `origin/docs/tangibility-design` から `spike/handmark-a-surface` を切り、別の worktree で、既存アプリの中の別窓として作る。環境変数で有効にしたときだけ開く。本線には入れない。
- **理由**: 既存の CGEventTap と打鍵の時刻を使えるので、打鍵から描画までの実際の経路で遅れを測れる。Input Monitoring の許可を取り直さなくてよい。
- **却下案**: 独立した最小のアプリ（本体に触れないが、許可を取り直す必要があり、測れる遅れが本体の経路と別物になる）。
- **影響範囲**: `src-tauri/src/analysis/portrait/`・`eh3.rs`・`wallpaper*.rs` は触らない（F-1 のセッションが触る）。

## 判断 2: 小面は仮の最小のものにする

- **判断日時**: 2026-10-16（研究者・推奨どおり）
- **採用**: 画面の右下の端に 48×48 px ほど。打鍵のたびに小さな印が約 120 ms 明るくなって消える。数値・文字は載せない。変化中に次の打鍵が来たら打ち切って最初からやり直す。キーリピートは数えない。
- **理由**: 成り立つ条件（遅れ・除外・クリック）を先に確かめる。見た目はその後。
- **却下案**: 見た目も先に決める。
- **含み**: 親タスク判断 12 の未決（速く打つと動き続ける表示になる）は、この試作では「打ち切ってやり直す」で仮に置く。連続して動いている時間の検査は本体への実装のタスクで決める。

## 判断 3: 遅れの測り方と合格の線

- **判断日時**: 2026-10-16（研究者・推奨どおり）
- **採用**: 合成のキー入力 約 200 回で、CGEventTap の打鍵の時刻から、小面の描画の直後のフレームのコールバックまでを測る。合格は 95 パーセンタイルが 200 ms 以内、かつ全回が 250 ms 以内。画面に光が出るまでは含まないので、研究者のスローモーション撮影で数回を抜き取って差を確かめる。
- **理由**: 評定の主体感は 200 ms を超えると下がる（[P486]）。250 ms は承認した文面の値（親タスク判断 12）。
- **却下案**: 線を 250 ms の 95 パーセンタイルにする／アプリ内の時刻だけ。

## 判断 4: 研究者の打鍵は試視だけ

- **判断日時**: 2026-10-16（研究者・推奨どおり）
- **採用**: 計測は合成のキー入力の列だけで行う。研究者は最後に自分で打って見た目と邪魔さを確かめるが、何も記録しない（時刻も残さない）。
- **却下案**: 本人の打鍵の時刻も測る／合成だけ（試視もしない）。

## 判断 5: 取り込みの確認の経路

- **判断日時**: 2026-10-16（研究者・推奨どおり）
- **採用**: 標準のスクリーンショット（全画面・窓の指定）・画面収録・研究者が普段使う画面共有 1 つ。撮影と目視は研究者の手順（この Mac では Claude が画面を撮れない）。
- **理由**: macOS の画面の取り込みの方式によって、窓の共有の種別の設定が効かない可能性がある（未確認）。方式の違う経路を含める。
- **却下案**: 標準の撮影だけ。

## 判断 6: 除外の設定が失敗したら小面を出さない（fail-closed）を合格の条件に含める

- **判断日時**: 2026-10-16（研究者・推奨どおり。親タスクの判断 12 で未決だった項を閉じる）
- **採用**: 設定の戻り値が失敗なら窓を出さない。失敗を人為的に起こして、窓が出ないことを確かめる。
- **トレードオフ**: 「設定は成功したが実際には写る」は戻り値では分からない。その経路は判断 5 の目視の結果として書く。

## 判断 7: /reimagine は使わない

- **判断日時**: 2026-10-16（研究者・推奨どおり）
- **理由**: 本線に入れない試作で、形はヒアリングで決まった。

## 判断 8: Step G のレビューの指摘への対応

- **判断日時**: 2026-10-16（HIGH は規約で対応・MEDIUM は研究者・AskUserQuestion・推奨どおり）
- **HIGH（code-reviewer）**: Windows では macOS 専用の定数・static・構造体が使われずに残り、CI の clippy `-D warnings` が赤になる。macOS 専用の項目に `#[cfg(target_os = "macos")]` を付けた。Windows を対象にコンパイルできないので、試作の cfg を存在しない OS 名に一時的に書き換えて macOS で clippy を回した。修正前のコミットでは dead_code の誤りが 6 件出て（陽性対照）、修正後は通った。
- **MEDIUM 1（security-checker）**: 記録の一時停止中も小面への通知と計測の CSV が止まらなかった。通知の条件に `!recording::is_paused()` を足し（EH3 の `lib.rs:4274` と同じ）、CSV に書く直前にも一時停止を見る。
- **MEDIUM 2（code-reviewer）**: design.md の「持ち越さない」と、終了後も残る計測の CSV の文面が合わなかった。CSV を例外として書き足した。
- **そのままにしたもの**: トレイの「小面を閉じる」が閉じた後も残る（押しても害はない・試作）。sharingType の読み返しは「設定が入った」ことしか示さない（results.md は既にそう書いている。「写らない」は研究者の目視で判定する）。LOW（emit_to が target Any の JS リスナーにも届く・CSV の作り方・環境変数の毎回の読み出し・invoke の戻り値の型）は記録だけ。emit_to の性質は、本体に入れるときに窓の側から取りに来る形にするかを決める材料にする。
