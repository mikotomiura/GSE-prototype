# O1 送信 timeout の実測

## 背景

⚠️★★★ `scripts/check-o1-release-readiness.sh` の**唯一の赤**が「送信 timeout が未実測」だった。
★ `reconcile.rs` の `HttpUploader` は `from_secs(180)` を置いていたが、
⚠️ その根拠は「300 KB が 1.45 s」という **Drive 保存を含まない**旧実測の外挿だけだった。

★ 記録票 (`experiments/20260801-controlled-friction-task/o1-upload-timeout-measurement.md`) は、
⚠️ 「数字を書き換えるだけで緑になる検査」を避けるため、**(a) 票が埋まっている** かつ
**(b) `from_secs(180)` が消えている** の**両方**でだけ緑になる作りになっている。

## ゴール

★ 稼働中の受け口へ実際に送って **Drive 保存を含む所要時間**を測り、timeout を根拠つきで決める。

## スコープ

### 含むもの
- ★ 合成ランダムバイトを段階的なサイズで実送信し、client 実時間とサーバ `elapsed_ms` を記録
- ★ `reconcile.rs` の timeout を実測にもとづく値へ変更
- ★ 記録票を埋める

### 含まないもの
- ⚠️ **`.gs` (受け口) は変えない** —— 再デプロイが研究者の手作業なので、
  source だけ変えると「直したつもり」になる (decisions.md D3)
- ⚠️ 分割アップロード / Drive 直 upload などの設計変更 (★ `/reimagine` 規模)

## 受け入れ条件

- [x] ★ **計測器の検算を先に**やる (⚠️ 名前が規則外なら弾かれることを確かめる)
- [x] ★ 記録票の「状態」が **実測済み** になり、ゲートが緑になる
- [x] ⚠️ 採用値の根拠が**不変条件と矛盾しない**ことを検査で確かめる
- [x] ⚠️ **外界に触った操作**（実送信の回数と残ったファイル）を報告に書く
