# 設計 — G1-M / G1-S の導線と管理シート

## 【A】受付メールに 3 フォームの位置づけを書く

### アプローチ

`g1RegisterAckBody_()` に「■ ご回答いただくフォーム（3 つ）」節を足す。
⚠️ **両分岐（課題ページ用意済み / 未用意）で同じ節を出す** — 分岐に入れると片方だけ緑になる。

書く内容（★ いつ・何回・なぜ を全部書く）:

| フォーム | いつ | 回数 | 本文で言うこと |
|---|---|---|---|
| G1-C 登録・同意 | 済 | — | 「このメールが届いた時点で完了。再提出は要らない」 |
| G1-M ブロック直後の 1 問 | ブロック 3〜9 の**直後** | 7 | 参加者ID とブロック番号を選ぶ / ★ **別のタブか別の端末**で開く（記入中の画面を切り替えない）/ 1 ブロック 1 回（二重送信しない）/ 2・10 の後は答えない |
| G1-S 終了後アンケート | 全 10 ブロックの後 | 1 | 5 分ほど / 正解は無い |

### URL の引き方（⚠️ 3 段のフォールバック）

`g1FormLink_(key, formId)`:
1. `SHORTURL_<key>`（`shortenFormUrls()` が作る）
2. `FORMURL_<key>` の `publishedUrl`（`recordFormUrl_` が保存する）
3. `https://docs.google.com/forms/d/<id>/viewform`（★ プロパティが 1 つも無くても**空にしない**）

⚠️ ★ 空文字を本文に出さないことが要件である（リンクの無い案内は導線が無いのと同じ）。

### 検査（`scripts/check_g1_emails.py`）

- 両分岐の本文に **G1-M / G1-S の URL が実在すること**（`http` で始まる文字列であること）
- 「ブロック 3〜9」「7 回」「別のタブ」等の**位置づけの言葉**があること
- 短縮モードでは**短縮 URL が出る**こと（`g1ShortOr_` を通していない箇所を捕まえる）
- ⚠️ ★ 追加した検査は**壊して赤を見てから**採用する

## 【B】管理シート

### 列の変更（20 → 19 列）

| 変更 | 列 | 理由 |
|---|---|---|
| 削除 | `実施予定日` | 在宅では日程を握らない。常に空 |
| 削除 | `配置(A/B)` | `assign.py` が P-ID から決定的に出す（`protocol.md §2.1`）。シートに持つと二重真実源 |
| 改名 | `課題文リンク送信日` → `課題ページ送付日` | ⚠️ **削除しない**: `g1AutoSendPendingMaterials` の**冪等キー**であり、消すと 2 通目が再送されうる |
| 改名 | `GSE_DISABLE_PROBES=1` → `G1モード確認` | launcher 時代の言い方。今は `g1.mode` マーカー判定 |
| 追加 | `配布URL(短縮)` | ⚠️ `配布フォルダURL` は **生のままでなければならない**（`G1_MATERIALS_URL_RE` と `g1FolderIdFromUrl_` が読む機械入力）。短縮は**別の導出列**で見せる |
| 選択肢 | `実施形態` → `来所` / `在宅（初回起動のみ同席）` | 第 13 版（§2.14） |

### 移行（`migrateRunSheetToV14()`）

⚠️ ★ `runCol_` は**コード側の配列しか見ない**ので、実シートとずれると静かに間違った列へ書く
（memory: `name-lookup-only-works-within-one-source`）。→ 実シートを名前で引いて直す:

1. 改名: 実ヘッダ行から**旧名**を探して新名に書き換える
2. 削除: 削除対象の値を**全部ログに出してから** `deleteColumn`（黙って捨てない）
3. 追加: 左隣の列名を探して `insertColumnAfter` + ヘッダ書き込み
4. 値の移行: `実施形態` の `無人在宅` → `在宅（初回起動のみ同席）`
5. 最後に `assertRunHeader_` で**実シートと突き合わせる**（合わなければ例外で止まる）
6. `applyRunValidation_` を張り直す（列がずれた後の古い規則を消すため）

冪等: 2 回目以降は「旧名が無い / 新列が既にある」で何もしない。

### レイアウト（Phase1 `rebuildRosterTab_` に合わせる）

バナー（赤・行高 46）/ ヘッダ（ネイビー地・白文字・中央・折返し・行高 36）/
`setFrozenRows(2)` + `setFrozenColumns(1)` / 交互背景 / 列ごとの幅 / 中央寄せ /
条件付き書式（`撤回/除外` に値 → グレーアウト、`完了ブロック数 = 10` → 緑）。
⚠️ 型付き列の衝突を避けるため **クリア → 書式 → 検証**の順（Phase1 のコメント参照）。
