# 背景のステージの机上の検査 —— 窓の速さの要約が停滞を分けない世界（速さの倍率と漂いの 3 段）

## 背景

第 1 回・第 2 回（world v4）では、停滞は訂正の率と区間の構造にだけあり、打鍵の時刻には出ない。v4 の緑は「停滞が打鍵の時刻に出るときにステージがそれを写さない」ことを言わない。中間の world（`.steering/20261014-rhythm-stage-graded-world/`）では、STRUGGLE の打鍵の間隔を v4 と v2 の間で 3 段（t = 0.25・0.5・0.75）に補間したが、下見 0 で 3 段とも基準のモデル A_speed の天井（L300 の AUC(A_speed) の小さいほう 0.995〜0.997）に当たり、項目 1 は 3 段とも判定不能（`ceiling`）だった。

同タスクの notes の「親タスクへの材料」（推論）: 打鍵の多い窓の速さの要約は中央値を精密に測るので、1 打鍵ずつの間隔の分布が重なっていても STRUGGLE を分ける。間の世界を作るなら、段の強さを細かくするより、窓の速さの要約が STRUGGLE を分けない作り（セッションごとの速さのばらつきなど）が要る見込み。

「停滞が打鍵の時刻に出るときに、ステージが A_speed の要約を超えて停滞を写すか」は未検証のまま。L1800 の専用の対照（PC1-1800・PCl）は一度も使われていない。

研究者の決定（2026-10-14・`decisions.md` 判断 1）: 停滞の強さは g(0.5) に固定し、セッションごとの速さの倍率とセッションの中の状態に依らない速さの漂いを足す。揺れの幅を 3 段にして結果の前に固定し、段ごとに下見 0 を回す（前のタスクと同じ天井の規則）。

引き継ぎ: `.steering/_handoff/next-session-rhythm-stage-after-graded-world.md`。

## ゴール

1. 設計（`design.md`）を書く。中間の world の design から変えるのは、world（速さの倍率と漂いの式と 3 段）・seed だけにする。固定の前の `/cross-review` に通し、どの結果（下見 0 を含む）よりも前に計器とともにコミットして固定する。
2. 計器を `experiments/20261014-rhythm-stage-speed-confound-world/` に写して直す。段ごとに、下見 0 → 下見 1 → スモーク → 本番を回し、notes を前の 3 回と同じ型で書く（固定の後の段）。
3. notes を `/cross-review` に通す。

## スコープ

### 含むもの
- world の段: STRUGGLE の打鍵の間隔は g(0.5)（中央値 219.08902300206645 ms・σ 0.3）。FLOW と STRUGGLE の両方の打鍵の間隔に、セッションごとの速さの倍率と、セッションの中で状態に依らずゆっくり揺れる速さの漂いを掛ける。揺れの幅を 3 段にする。
- 段ごとの下見 0 と、天井の段を先へ進めない規則（中間の world の design §3.0 と同じ）。
- L1800 の専用の対照（中間の world の design §1.4 のまま）。
- `SEED` = 20261020（下見 0 と下見 1 は +1・スモークは +2）。段どうしで同じ seed を使う。

### 含まないもの
- 揺れの幅や段の位置を、下見 0 の値を見て動かすこと（第 1 回の判断 16）。
- 停滞の強さを g(0.5) から変えること。
- L300・L60 の対照の範囲を変えること。端から端までの赤の検査。
- 第 1 回・第 2 回・中間の world の入れ物・判定・notes を変えること。
- `src-tauri/`・EH3 のファイル。
- 実在の人の打鍵。キーストロークの内容・NDJSON の生ログ（合成も）を外部の LLM（Codex を含む）に送ること。
