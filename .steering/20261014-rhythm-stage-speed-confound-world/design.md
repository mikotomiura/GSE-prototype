### 1.3 揺れの world `h(c)`

- **区間の設定**: `g(0.5)` と同じ（`graded_segments(cfg, 0.5)`・STRUGGLE の `flight_median_ms` 219.08902300206645・`flight_sigma` 0.3、ほかは v4）。停滞の強さを対数の尺度で `δ = ln(m_S / m_F)` と書き、計器は `graded_segments` の 2 つの値（STRUGGLE と FLOW の `flight_median_ms`）から計算する（`0.5 × ln(320 / 150)` と最後の桁が違いうるので、どちらで計算するかをここで固定する。値は約 0.3788・自己検査で直接の数と 1e-12 以内で照合する）。
- **打鍵の間隔の揺れ**: FLOW と STRUGGLE の打鍵の間隔（バーストの中の 1 打鍵ずつの間隔）を、`lognormal(ln(m_kind) + z(τ), σ_kind)` の形で引く（`lognormal(ln m, σ) × exp(z)` の形にはしない。c > 0 で丸めが違う）。τ は、その間隔を引く直前の押下の時刻（区間の起点 ＋ 区間の中の相対時刻・切り捨てる前の浮動小数・ms）。`z` は、
  - `z(τ) = c · w(⌊τ / 1000⌋)`、`w(k) = δ · (u + d(k))`
  - `u ~ N(0, 1)`: 単位（セッションか対）ごとの倍率の元（倍率は `exp(c δ u)`）。
  - `d(k)`: 1 秒ごとの定常な単位の Ornstein–Uhlenbeck の列。`d(0) ~ N(0, 1)`、`d(k+1) = ρ d(k) + √(1 − ρ²) ε_k`（`ρ = exp(−1 / tau_s)`・`tau_s` 300 s・`ε_k ~ N(0, 1)`）。
  - `z` の倍率の分と漂いの分の標準偏差はどちらも `c δ` で、全体は `√2 · c δ`（c = 0.5・1・2 で約 0.268・0.536・1.071）。漂いの 60 s の増分の標準偏差は `c δ √(2(1 − e^{−0.2}))` ≈ `0.60 c δ` で、窓の中・隣り合う窓の間でも揺れる。
- **掛けないもの**: バーストの長さ（時間で終わる・v2 と同じ）・バーストの後の間（`gap`・中央値 1500 ms・σ 0.6）・訂正の率・押下の長さ・区間の構造。バーストが時間で終わるので、`z` が大きい（遅い）ほど窓あたりの打鍵の数は減る。`gap` の約 7 割は 2000 ms 未満なので、A_speed の「短い間隔」（`speed.short_ms` 2000 ms 未満）は、倍率のかかる打鍵の間隔とかからない間の混合になる。
- **乱数**: `u` と `d` は区間と打鍵の乱数とは別の流れ `derive_rng(seed, "speed", <組>, i)` から、`u` → `d(0)` → `ε_0` → `ε_1` → … の順に 1 つずつ引く。列は読まれた秒まで遅延して延ばす（`markov` は最後の区間を切る前に全長で作るので、打鍵はセッションの長さを最大 900 s 超えうる。順に引くので、どこまで延ばしても `w(k)` は同じ）。`<組>` はセッションを作る単位（下の表）で、同じ単位の 2 つのセッションは同じ `w` を共有する。`w` は c に依らず、`z` は c に比例する（`z` の形は段の間で共通で、大きさだけが違う）。ただし打鍵の数が変わるので、区間と打鍵の乱数の位置は段ごとにずれ、区間の構造と打鍵は段ごとに違う列になる（段の間で対になるのは `w` だけで、区間と打鍵は対にならず、独立でもない）。
- **組ごとの扱い**（`gen_sessions.py` の組）:

| 組 | `z` の単位 | 時刻 τ の起点 |
|---|---|---|
| P | セッションごと（`"P", i`） | セッションの始まり（最後の FLOW `fin` は `duration − fin` から） |
| O（`Oa`・`Ob`）と J | 対ごと（`"O", i`）。前半（a・b それぞれ）は起点 0。共有の末尾は 1 回だけ作るので、a と b で同じ打鍵になる。J は a の写し | 共有の末尾は `prefix_s` から |
| D_shuffled（`Dsh`・`Jsh`） | 対ごと（`"Dsh", i`）。区間を作った時刻（a の並び）の `z` が区間の打鍵に入り、並べ替えた b では区間とともに動く（b の `z` は時刻について滑らかでない） | a の並び |
| D_diffend | 対ごと（`"Dde", i`）。共有の前半と、a・b それぞれの後半が同じ `w` の列を使う | 前半は 0、後半は `shared_prefix_s` から |
| D_continuous | セッションごと（`"Dco", i`） | セッションの始まり |
| D_sleep | セッションごと（`"Dsl", i`） | セッションの始まり。眠りの区間も時刻を進め、眠りの後は `sleep_start_s + sleep_s` から |
| D_noobs | 揺れを掛けない（手で置いた打鍵） | — |

- そのために `markov`・`gen_segment`・`gen_typing`・`flow`・`continuous` に、区間の起点の時刻（ms）と速さの列（`None` なら今までと同じ）を渡す。速さの列が `None` のときは、乱数の引き方も出力も今までとバイト単位で同じにする。`--world confound` では c = 0 でも速さの列を作って渡す（`None` に落とさない）。`--c 0` は受け付ける（自己検査のため。段には置かない）。c は 0 以上 4 以下に限る（大きな c では間隔が 0 に潰れてバーストが終わらない・Codex 2 巡目）。打鍵の間隔が時刻を進めないときは生成を止める。
- **c = 0 の端**: c = 0 では `z ≡ 0` で、打鍵と区間（NDJSON・ラベル・`sessions.json`）は同じ seed の `--world graded --t 0.5` とバイト単位で一致する（`u` と `d` は別の流れなので、区間と打鍵の乱数に触れない）。`world.json` は world ごとに違う（confound は `{"world": "confound", "c": c}`、ほかは今までどおり `{"world": …, "t": …}`）。この一致は時刻の起点の誤りを捕まえない（`z ≡ 0` なので）ので、c > 0 の配線は別の検査で見る（§3.7 への追加）。
- **宣言**（推論）: 揺れは、窓の速さの要約（打鍵の数・短い間隔の中央値・連なりの長さ）と停滞の関係を薄める。ただし (1) A_speed は L60 で前の 4 窓の量 1・2（打鍵の数と短い間隔の中央値）を持ち、L300・L1800 ではそれに直前 L 秒の 5 量が加わる。前の窓は 60〜240 s 前で、漂いとの相関は約 0.82〜0.45 なので、前の窓との比べで相対的な遅れを部分的に読みうる。(2) STRUGGLE は σ も 0.25 → 0.3 と大きくなり、その差は短い間隔の広がり（四分位範囲）に残る。ただし短い間隔には倍率を掛けない `gap` が混ざり、2000 ms・200 ms の閾値もあり、漂いは窓の中でも動くので、広がりは揺れに対して不変ではない。この 2 つのため、揺れの幅を大きくしても A_speed が天井に残りうる。それも下見 0 の結果として受け入れる。

  - **c > 0 の配線（時刻の起点）**: 速さの列をテスト用の決定的な列に差し替え（セッションの絶対の時刻 `[X, Y)` でだけ `w` が大きく、ほかは 0）、生成した打鍵の間隔が絶対の時刻 `[X, Y)` でだけ延びることを確かめる。`X` を P の最後の `fin`、O の共有の末尾の側、Dde の後半、Dsl の眠りの後に置いた例を作る。Dsh の b では、a で延びた区間が打鍵ごと並べ替えた位置へ動く（a の窓で延びた間隔の 8 割以上が、b の間隔の多重集合に同じ値で現れる。区間の境目をまたぐ間隔は並べ替えで変わるので全部ではない）。D_noobs の打鍵は変わらない。
  - **列の引き方**: `w` の最初のいくつかの値が、`derive_rng(seed, "speed", <組>, i)` から `u` → `d(0)` → `ε` の順に手で計算した値と一致する。遅延して延ばしても、先に長く延ばしても、同じ秒の `w` は同じ。組の名前（`"O", i`・`"Dde", i` など）で a と b が同じ列を使い、P の別のセッションでは違う。
  - 生成した記録の P のセッションごとの、FLOW の区間の中の 1 s 未満の押下どうしの間隔の中央値の対数の、セッションの間の標準偏差を、c = 0・0.5・1・2 で出す（スモークの大きさ）。これは診断として記録するだけで、自己検査の合否には使わない（1 s 未満に限るので選択の偏りと標本の揺れが入る）。
  - `--c` の拒否: `--world confound` で `--c` が無い・graded や v4 に `--c`・負の c・有限でない c・4 を超える c。
  - **z の位置と大きさ**: `z(k 秒 + f ms) = c · w(k)` が f = 0・999.9 で厳密に成り立ち、次の秒で変わる（時刻の単位と、δ を二重に掛ける誤りを捕まえる）。
  - **掛けるもの・掛けないもの**: 乱数を記録する代理の生成器で 1 区間を作り、z を常に K にした列では、バーストの中の間隔の `lognormal` の平均だけが `ln m + K` で、`gap` の平均とバーストの長さ・始まりの `uniform` の引数は速さの列が無いときと同じ。z を読む時刻は、直前の押下の時刻（区間の起点 ＋ 相対時刻）。
  - **単位ごとの列**: 生成の中で作られた速さの列の名前と長さの集合が、組ごとの単位（P i・O i・Dsh i・Dde i・Dco 0・Dsl 0）とちょうど一致し、どれも 1 回だけ作られ、c が `--c` の値。
  - **窓の外**: テスト用の列で、最初の窓より前の押下が c = 0 の同じセッションと完全に一致する（区間の外を遅くする誤りを捕まえる）。窓の中の 400 ms 未満の間隔は割合 2 % 以下とする（遅くしなくても、バーストの残りと遅くしない `gap` の和や区間の境目をまたぐ間隔で短くなりうる・code-reviewer 2 巡目）。Dsh の窓に最後の FLOW（5340〜5400 s）も入れる。D_shuffled の a の `z` の跳びが、テスト用の列では 0 か K になる。
  - `world.json` の `world`・`c` が `--step` の段と一致しない作業の場所では、`checks.py` と `run.sh` が止まる。陰性対照として、graded t = 0.5 の作業の場所（値が同じ 0.5）は c050 として拒まれる。
- 中間の design §3.7 の「段の world」の検査（設定・t = 0 → v4・t = 1 → v2・中央値の単調性・`--t` の拒否）は、段の表（`ceiling.steps`）から切り離して graded の値を直接与えて残す。L1800 の対照・判定・下見 0 の規則・`--apply-pilot` の検査は、段の名前と値を c に読み替えて回す。

## 9. Claude が足した細部（研究者が変えてよい）

研究者が決めたのは判断 1（倍率 ＋ 漂い・停滞の強さ `g(0.5)`・幅の 3 段・段ごとの下見 0 と天井の規則）。次は Claude が足した細部で、固定の前に研究者が変えてよい。

1. 幅の単位を停滞の強さ `δ` に合わせ、倍率と漂いの標準偏差をどちらも `c δ` にしたこと。3 段を c = 0.5・1・2（倍ずつ）にしたこと。
2. 漂いを 1 秒ごとの定常な OU 過程にし、時定数を 300 s にしたこと（区間の長さ FLOW 180〜900 s・STRUGGLE 120〜600 s と同じ桁・L300 の範囲と同じ）。300 s でも 60 s の増分の標準偏差は約 0.60 c δ で、窓の中・隣り合う窓の間でも揺れる。時定数がもっと短いと窓の中の揺れが大きくなり、もっと長いと倍率と見分けにくい。
3. 揺れを打鍵の間隔（バーストの中）だけに掛け、バーストの後の間・バーストの長さには掛けないこと。
4. 組 O・Dsh・Dde で `z` を対ごとに共有し、Dsh の b では区間とともに `z` が動く（時刻について滑らかでない）こと。D_noobs には掛けないこと。
5. `SEED` = 20261020（判断 1）。
