## 判断 3: 固定の前の `/cross-review` 2 巡目（計器を含む）の結果と対応（2026-10-14）

  - 区間の外が遅くなる変異を捕まえない（M）→ 最初の窓より前の押下が c = 0 と完全に一致することを足した。Dsh の最後の FLOW の起点（M）→ 窓に足した。窓の中の 400 ms 未満が 0 なのはこの seed の巡り合わせ（M）→ 割合 2 % 以下にした。`gap` とバーストの長さに掛けない・`× exp(z)` の形にしない（M）→ 乱数を記録する代理の生成器で、引数を照合する検査を足した（z を読む時刻もここで確かめる）。
  - 大きな c で間隔が 0 に潰れて生成が止まらない（Codex P2）→ c を 0〜4 に限り、間隔が時刻を進めないときは止める。跳びの量の名前（Codex P3）→ `z` の跳びとして欄の名前と `quantity` に書き、design §3.3 (h) を直した。テスト用の列で a の跳びが 0 か K になることを確かめる。
  - `speed_jumps.json` が無いと黙って写さない（L）→ 止める。写し元の SHA-256 は改行を LF にそろえて比べる（L）。写し元との一致に graded t = 0.25・0.75 を足した（L）。graded の `pilot.json` を同じ値で拒む検査（照合の節）。名前の残り 2 か所（L）。
- 直さなかったもの: Dsh の b の多重集合の検査は、速さの配線については実質恒真（Claude L）。区間が打鍵ごと動く記録として残し、配線の検査には数えない。
- 直した後: 自己検査は 316 項目・0 件の失敗。生成器の変異は、前の 9 通りに、指摘で挙がった 8 通り（z を ms で読む・δ を二重・P が全部同じ列・O の b に別の列・O の b の前半を `prefix` から・`gap` にも掛ける・`× exp(z)` の形・Dsh の最後の起点を 0）を足した 17 通りをすべて捕まえた。
