# 設計判断 (decisions)

本タスクは設計議論。以下はユーザー承認済み (2026-06-19)。

## D1: 参加者 ID はランダム採番
- **判断**: `P###` 書式は維持しつつ、連番ではなくシャッフルした候補プールから無作為に割り当てる。
- **根拠**: 連番は登録順 (募集チャネル・日付・研究者との関係と相関しうる) を漏らす擬似匿名化上の弱点。
  書式維持は `scripts/run-calibration-cohort.sh` / gse-dataset `metrics/P*/` の `P*` glob 依存のため。
- **付随**: アプリ自己生成は不可 (重複排除・同意紐付け不能)。研究者が事前採番し被験者へ個別配布。
- **前提実装**: `logger.rs:920` `default_log_path()` の `P000` ハードコード解消 (参加者 ID を設定可能化) が必要。別タスク。
- **対応表 (実名↔P-ID) はデータ本体と物理分離**、研究者のみアクセス可。

## D2: 送付チャネルを機微度で2分離
- **チャネルA (調査票, 低機微)**: 同意 / スクリーニング / 尺度理解ゲート (PreReg-1) / デモグラ /
  事後デブリーフ / (c) GSE。Google フォーム可 (キーストローク由来データを含まない)。
- **チャネルB (セッション NDJSON, 高機微)**: Google フォーム/Drive 不可。ローカルで anonymize →
  共有は集約 `metrics.json` のみ (agent-shared.md の唯一の共有アーティファクト)。
- **根拠**: data-privacy Skill「生 NDJSON 外部送信禁止」「外部被験者データは暗号化ローカル保管、GitHub 経路不可」。

## D3: (c) 自己効力感 = Schwarzer & Jerusalem (1995) GSE
- **尺度**: Generalized Self-Efficacy Scale (10項目・4件法・得点 10-40)。提案書 参考文献 [15]。
- **運用**: **検証済み公式日本語版を自前翻訳せず使用**。pre (利用前) / post (利用後) の2時点、P-ID 紐付け。
  出典明記。利用条件は Schwarzer 公式配布ページで最終確認。採点法・仮説をプレレジで事前固定。
- **注意**: 文献番号は提案書と技術設計書で別体系 (提案書 Mehta=[11]/GSE=[15]、技術設計書 Mehta=[10]/Raichle=[15])。
  引用は提案書番号で統一。

## D4: クリップボード監視 (a) は回数のみ・中身禁止
- **判断**: (a) AI依存度はペースト「イベント/回数」のみ記録。クリップボードの「中身 (テキスト)」は記録しない。
- **根拠**: data-privacy Skill 直撃。(b) の Mehta KS メトリクスは打鍵動態で検出しテキストを見ないため整合。

## D5: 収集〜DB 保存はファイル真実源 + 再生成可能な分析 DB
- **判断**: サーバ DB は不要規模 (N=3-10)。NDJSON/JSON/CSV を一次ソースとし、分析時に
  **DuckDB** へ読み込んで P-ID join。`analysis.db` は使い捨て (消せば再生成)。
- **3 ストリーム (P-ID で結合)**: ① セッション NDJSON (高機微) / ② フォーム CSV (低〜中) /
  ③ 派生メトリクス `gse-replay --metrics` (集約)。
- **DuckDB 採用理由**: JSON/CSV/Parquet を直接クエリでき、ファイル真実源を崩さず分析だけ DB 化。

## D6: 被験者端末からは「匿名化 NDJSON を暗号化して」出す
- **判断**: 端末で `anonymize.py` (VK→カテゴリ・時刻相対化) → **研究者の公開鍵宛に age 暗号化** → 転送。
  Replay-as-Truth を維持しつつ機微度を下げる。metrics-only より方法論の自由度 (特徴量再計算) を確保。
- **転送経路の含意**: 送るのは復号不能な暗号塊。よって転送経路は**信用不要**。
  平文は被験者端末と研究者の暗号化領域にのみ存在。data-privacy「生 NDJSON 外部送信禁止」と整合。
- 非技術者代替: 7-Zip AES-256 + 強パスフレーズ (鍵は別経路)。

### 転送経路 = Dropbox ファイルリクエスト (アップロード専用)
- **判断**: 被験者は Mac/Windows 混在のため **Dropbox の「ファイルリクエスト」** を採用 (両 OS で同一動作)。
  被験者は **アカウント不要・他人のファイル不可視・アップロードのみ** のリンクに `.age` をドラッグするだけ。
- **チャネル分離の維持**: 調査票フォーム (チャネルA) とは**別リンク**にする。Google フォームのファイル
  アップロードは使わない (Google サインイン要求でチャネルが混ざるため)。
- **真正性 (任意)**: age は機密性のみ保証。厳密化するなら被験者が SHA256 を別経路で報告し改竄検知。
  N=数人なら省略可。
- **被験者手順 (3 step)**: ①`package-session` を1回実行 → `P###_<date>.age` 生成 →
  ②Dropbox リクエストリンクを開く → ③ドラッグ&ドロップ。研究者 age 公開鍵はスクリプト同梱 (配布安全)。

## D7: (a)(b)(c) 精密定義と (b) diff量の供給源 = 案A (ユーザー承認 2026-06-20)

提案書の定義を真実源として確定 (文献番号は提案書体系):
- **(a) AI依存度**: GSE Editor のクリップボード監視ログ等から、**1 セッションあたりの AI 参照
  (ペースト) 回数**を自動計測し、導入前後での依存低下を比較。
- **(b) 自力解決率**: **diff量 と総打鍵数の比率**から、自らの手で試行錯誤して書き進めた割合を定量化。
  Mehta et al. (2025) [11] の **LLM 使用検出 KS メトリクス**を「AI コピペか否か」の客観的**補助指標**として
  併用 (テキスト内容ではなく打ち方で AI 支援を検出 → 自力解決の純度証明)。
- **(c) 自己効力感**: 一般性自己効力感尺度 [15] による主観的変化 (system 外・アンケート、D3 既出)。

**(b) diff量 の供給源 = 案A (成果物由来・content-free)**:
- **判断**: キーストロークログからは diff量 を復元できない (中身を記録しない設計の必然) ため、
  **セッション成果物から解析時に diff量 を算出**する。コーディング (vibe-coding) = `git diff --stat`
  の追加行/文字数、文章 = 完成テキストの文字数/変化量。**保存するのは数値 (文字数) のみ・中身は保存しない**。
- **却下**: 案B (GSE Editor 実体化で文字数を NDJSON 送出) は実装コスト大・現状エディタ実体なし。
  案C (正味文字数=文字生成キー−backspace の代理) は**ペースト挿入分を取りこぼし (b) の主旨と逆行**。
- **含意**: diff量 は NDJSON の外 (成果物) から来るため、D5 の 3 ストリームに**第4入力「diff量」**を
  P-ID×session で join する形になる。Mehta KS (補助) は打鍵タイミング=既存データで算出可能。
- **根拠**: data-privacy (中身禁止) を保ったまま「diff量小×大量テキスト=AIコピペ」を paste回数+KS で裏取りでき、
  自力解決の純度証明が成立する。

## 下流の実装タスク (本設計の punch list、各々別タスク)

   git diff/文字数)÷総打鍵数＋Mehta KS 補助。`gse-replay --metrics` 拡張 or 解析スクリプト。
   → handoff: `handoff-ab-metrics.md`
