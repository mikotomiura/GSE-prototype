# 設計判断: `IME_ACTIVE` の Ordering

## 判断 1: **7 箇所を一度に**閉じる (⚠️ 片側修正をしない)

- ★ mac が 判断 5b で踏んだ罠を繰り返さない ——
  **store だけ `Release` にしても読み手が `Relaxed` なら happens-before は成立しない**。
- ⚠️ 片側だけの修正は「直したつもりで**何も保証していない**」＝ silent no-op であり、
  ★ **「規則に合わせた」という記録だけが残る**のが最も悪い。
- → ★ store 4 箇所 / load 3 箇所を**同一コミットで**閉じた。

## 判断 2: フックコールバック内 (`hook_windows.rs:603`) も `Acquire` にしてよい

- ★ 共通-1 の禁止リストは **Mutex / ブロッキング send / I/O / ヒープ確保 / ログ / sleep** であり、
  ⚠️ **atomic load は入っていない** (★ 共通-1 はむしろ「Atomic 操作 + channel send **のみ**」と定める)。
- ★ `Acquire` load は **x86-64 では `Relaxed` と同一命令**でフェンスを生まない。
  → ⚠️ コールバックのレイテンシ要件に影響しない。
- ⚠️ **ここを `Relaxed` のまま残す方が危険である** —— ★ 共通-2 が名指しで対を要求しており、
  例外にする根拠がどこにも無い。

## 判断 3: ⚠️★★★ **回帰テストを足す** (★ mac は実測しただけだった)

- ⚠️ mac は `IME_OPEN` を閉じたあと「実測して 0 件」と記録したが、
  ★ **実測はその時点の写像にすぎず、次に書く人を止めない**。
  → ⚠️ 現にその**同じ日**に `IME_ACTIVE` が 7 箇所 `Relaxed` のままだと判明している。
- **決定**: `capabilities.rs` と同じ様式で **ソースの実物**を `include_str!` で走査する
  (`guarded_atomics_never_use_weak_ordering`)。
- ★ **型では表せない**理由: 共通-2 の規則は「**どの変数か**」に依存する
  (⚠️ `LAST_KEY_MS` / `CONSECUTIVE_TAP_FAILURES` は `Relaxed` で**正しい**)。
  → `AtomicBool` という型は両者を区別しない。

### ⚠️★★★ 判断 3a: **`#[cfg]` を付けない**

- ★ 文字列として読むので、`hook_windows.rs` が **1 行もコンパイルされない macOS でも中身を検査できる**。
- ⚠️ `#[cfg]` を付けると**相手側 OS の CI が素通り**し、
  ★ **今回まさに起きた「片 OS でしか見ていない」状態に戻る**。
  (★ `docs/agent-shared.md`: 「OS ごとに規則が違うロジックは両 OS に対のテストを置く」)

### ★ 判断 3b: 針を `concat!` で割る

- ⚠️ **本ファイル自身も走査対象**なので、割らないと**テストのリテラルが自分に引っかかる**。
- ★ コードにその理由をコメントで残した (⚠️ 後から「なぜ分かりにくく書くのか」と直されないように)。

### ★ 判断 3c: コメント行は除外する (⚠️ 既知の限界)

- ⚠️ 規則を説明する文章そのものが引っかかるため。
- ★ **「落ちすぎない」方向の限界**であり、⚠️ **実コードの見落としは生まない**。
  (★ `capabilities.rs` が「過大側に振れるが見落とす方向ではない」と書いたのと同型の判断。
   ★ 本件は向きが逆なので、⚠️ **限界を doc に明記**した)

## 判断 4: ⚠️ **変異テストで赤を実測してから**完了とする

- ⚠️★★★ **「足したら緑だった」は検査が効いている証拠にならない。**
  ★ 走査対象のパスを 1 文字間違えただけでも「緑」になる。
- ★ **実測** (2026-09-12): `hook_windows.rs:603` を `Relaxed` に戻すと

  ```
  hook-constraints 共通-2 違反: 保護対象の static に弱い Ordering が使われている。
  input/hook_windows.rs:603 | if is_press && IME_ACTIVE.load(Ordering::Relaxed) {
  test result: FAILED. 0 passed; 1 failed
  ```

  ★ **行番号と該当行を名指しで返す**ことまで確認し、復元後は緑に戻ることも確認した。

## 判断 5: `HMM_VERSION` は bump しない

- ★ `Release` / `Acquire` は `Relaxed` より**強い**制約であり、**緩めていない**。
  → ⚠️ 可視性が保証されるだけで、観測される値の系列は変わらない。
- ★ ゴールデン **6 fixture / 226 snapshot が byte-equal** (⚠️ replay は単一スレッドなので
  そもそも Ordering を踏まない —— ★ **この回帰は「変えていないこと」しか言えない**点に注意)。
