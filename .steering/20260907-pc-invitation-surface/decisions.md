## 判断 4: ⚠️★★★ 「画面共有・録画時の露出」の要件は、**共有状態を検出しない**形で書く

- **判断日時**: 2026-09-07（★ `security-checker` の MEDIUM 指摘 M-1 を受けて）
- **背景**: ★ 初稿の **PC-8 / A19 / E-13** は「**共有中に** 招待面が何を露出するかを仕様に書く」と書いていた。
  ⚠️★★★ **これは「共有・録画が起きていることを検出せよ」とも読める。**
- **⚠️ 一次で検算した**（★ 指摘を鵜呑みにしない）:
  - ★ `.claude/skills/data-privacy/SKILL.md` **ルール 7** 逐語:
    「★ 記録してよいのは以下**だけ**である（⚠️ **1 本も足さない**。足すなら別 ADR）」
  - ★ 同ルールの**フォーカス遷移の行**が逐語で禁じているもの:
    「⚠️ **HWND / PID / アプリ識別子 / ウィンドウタイトル / ウィンドウ通し番号**」
  - → ★★★ **共有の検出は他プロセスの識別（PID / HWND / capture セッションの列挙）を伴うので、
    凍結表の外である。**★ **指摘は妥当だった。**
- **選択肢**:
  - A: 「共有中に何を露出するか」のまま残す（★ 実装者の良識に委ねる）
  - B: **要件から共有の話ごと落とす**
  - C: **「共有状態に依存しない *無条件の* 露出削減」で満たすと明記し、検出を明示的に禁じる**
- **採用**: **C**
- **理由**: ★ A は **`verify-before-claiming` ルール 6**（主張を書いたらそれを検査するものを一緒に置く）に反する
  —— ⚠️ **明文が無ければ実装者は検出側に読める。**
  ★ B は **PC 面固有の露出経路（PC-8 の主題）を丸ごと落とす**ので `PS-Q7` の穴が残る。
  ★ C は **受動的除外の実在する経路**（Windows `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` は
  **自窓に印を付けるだけで共有の有無を問い合わせない**）で満たせる。
- **トレードオフ**: ⚠️ **共有中だけ表現を弱めるといった適応ができなくなる**（★ 常に弱い側に倒す）。
- **影響範囲**: `expression-channel.md` の **PC-8 / A18 / A19 / PS-Q9 / E-13** ／ ADR-026 の **PC-8 / M10**。
- **見直しタイミング**: ★ **検出が要ると判断したとき** —— ⚠️ その場合は
  **ADR-014 D4 の凍結表を改訂する別 ADR が先**である。
