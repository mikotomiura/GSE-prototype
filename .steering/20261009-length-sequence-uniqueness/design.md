# 設計

結果を見る前に固定する。ここに書いた値と手順を変えるときは、変えた理由と時刻を `decisions.md` に足し、結果のノートに逸脱として書く。

## 1. 実装アプローチ

人のデータを使わず、公開テキスト（青空文庫）を「理想の書き手がそのまま打った」と仮定して、記録に残る長さの並びを合成する。攻撃者は候補の文章から同じ並びを計算し、記録と突き合わせる。

- 記録に残るもの: `key` 行の `category`（`src-tauri/src/logger.rs` の key 行・`anonymize.rs` の `KeyCategory`）。境界は `SentencePunctuation`（仮想キー 0xBC と 0xBE だけ ＝ 日本語入力では「、」「。」）と `Enter`。境界の間で数えるのは文字を作るキー（`Alphabetic`・`Numeric`・`Punctuation`）の押下の数から `Backspace` の数を引いたもの。`Space`（変換）・修飾キー・`Navigation` は数えない。
- 依存は SudachiPy 0.7.0 と SudachiDict-core 20260723.1（Apache-2.0・研究者が承認・IME 論文の `kit/corpus/requirements.txt` と同じ版）だけ。ほかは Python の標準ライブラリ。numpy は使わない（承認されていない）。
- 実験は `experiments/20261009-length-sequence-uniqueness/`。取得した zip と派生データは `raw/`（git に入らない）に置き、zip の SHA-256 を `results/corpus_manifest.json` に書く。

## 2. 確定の Enter と改行を、記録の項目から見分けられるか（実装の前の確認）

コードと仕様で確かめた（NDJSON は読んでいない）。

- `key` 行は `{"type":"key","t":…,"category":…,"press":…}` だけで、押したときの IME の状態を持たない（`logger.rs` の key 行の書き出し）。
- `ime_state` 行（`on`・`active`）は、IME の開閉が変わったときにポーリングで出る（`ime_windows.rs` / `ime_macos.rs` の `emit_ime_state`）。キーごとではない。
- `ime_shadow` 行（`dwell_ms`・`nav`・`abandon`）は変換のセッションごとに 1 行で、`t` はポーリングの時刻。Windows では候補ウィンドウが出た変換だけ、macOS では打鍵から推した「かな入力の一区切り」ごと（`ime_compose.rs` のモジュール doc）。`capabilities` では `config_gated`（環境によって丸ごと出ない）。`anonymize_ndjson` はこの行も残す。
- → 記録の項目に、Enter ごとの「確定か改行か」を示すものは無い。`ime_shadow` の時刻と `dwell_ms` で一部の確定を推せる可能性と、キーの順序（前の Enter のあとに文字キーが無い Enter は改行）で推せる可能性はあるが、IME の設定（句読点で確定する等）・マウスでの確定・BackSpace で崩れ、保証されない。
- よって、研究者判断（判断 11 の追記）どおり、**雑音とは別に「確定の Enter も区切りに入る条件」を並べて測る**（§5 の B1・B2）。キーの順序で推す攻撃は今回は作らない（結果のノートの限界に書く）。

- 参照用: IME 論文の 12 作品（`papers/ime-observation/experiment/data.md` の表）を別のコーパスとして測る（指標 1 だけ）。zip の SHA-256 を IME 論文の記録と照らす。

## 4. 前処理とかな化

### 4.1 本文の切り出し（IME 論文の `kit/corpus/build_corpus.py` の `body_lines` と同じ規則）

先頭の題名・著者の行と記号の説明の枠（破線 2 本）を捨て、末尾の `底本：` 以降を捨てる。枠が無ければ最初の空行までを捨てる。注記 `［＃…］` を消す。

### 4.2 ルビ

- 攻撃者の本文（以下 P）: ルビ `《…》` と `｜` を消し、親字を残す（IME 論文と同じ）。
- 書き手の本文（以下 W・雑音ありの条件でだけ使う）: ルビの読みがかな（ひらがな・カタカナ・ー）だけなら、親字をその読み（ひらがなに直す）で置き換える。親字は `｜` があればそこから《まで、無ければ《の直前の漢字（々〆〇ヶ仝を含む）の連続。漢字の連続が無ければルビを捨てる。
- 理想の条件では書き手も P を打つ（読みは両側とも SudachiPy）。雑音ありの条件では書き手だけ W の読みを使う（研究者の選択 2026-10-09）。ルビの読みと SudachiPy の読みが食い違う区間の割合を報告する。

### 4.3 読みと打鍵の単位

行ごとに SudachiPy（`SplitMode.C`・`Dictionary(dict="core")`）で形態素に分ける（行が 40,000 バイトを超えたら「。」で切って分ける）。形態素ごとに次の順で打鍵の単位の列にする。

1. 表層がすべて空白 → 何も打たない（Space は数えない）。
2. 表層のすべての字が「字ごとに扱う字」（下の表・数字・英字・境界の字・空白）なら、字ごとに扱う。
3. そうでなく、表層のすべての字が語の字（Unicode の文字のカテゴリ L・`〇`。数字・英字は除く）で、読み（`reading_form`）がカタカナ・ひらがな・ー だけなら、読みをひらがなに直したもの（ァ〜ヶ → ぁ〜ゖ）を打つ。
4. どれでもなければ**無効**（その形態素が入る区間を無効にする）。表にない記号（SudachiPy は `※` や `―` に「キゴウ」という読みを付けるので、読みだけでは判定しない）、置換文字、数字・英字と漢字・かなが混ざる形態素（「第1」など。打ち方が「dai1」か「daiichi」かで決まらない）はここに落ちる。

字ごとに扱う字:

| 字 | 打鍵 | 記録のカテゴリ |
|---|---|---|
| 、，, | 境界（読点） | SentencePunctuation |
| 。．. | 境界（句点） | SentencePunctuation |
| 0〜9・０〜９ | 1 | Numeric |
| A〜Z・a〜z（全角も） | 1 | Alphabetic |
| 「」『』〔〕［］【】〈〉｛｝{}[] | 1 | Punctuation（括弧のキー → 変換） |
| （）() | 1 | Numeric（Shift ＋ 8・9。Shift は数えない） |
| ！! | 1 | Numeric（Shift ＋ 1） |
| ？? | 1 | Punctuation（Shift ＋ /） |
| ・／/ | 1 | Punctuation（/ のキー） |
| ―─—－‐-ー〜～ | 1 | Punctuation（- のキー → 変換） |
| ：:；;＝=＋+＊*＃#＆&＠@％%＿_＾^＼\｜\|"“”'‘’ | 1 | Punctuation か Numeric |
| 空白（半角・全角） | 0 | Space（数えない） |

- 省略記号 `…` `‥` は**無効**とする。打ち方が書き手で大きく違い（「...」で句点を 3 回打つ・「・・・」を変換する・「てん」を変換する）、打ち方によって境界の数そのものが変わるため、打鍵の数だけでなく区切りを作り出してしまう。ダッシュ（―）はほとんどの打ち方で - のキーなので 1 打とする。
- `※`（外字の跡）・`〃`・`ゝゞヽヾ`・表にない記号・読みがかなでない形態素は無効。
- 単位の列は、ひらがなと、記号・数字・英字の 1 打を表す `#` と、長音の `ー` からなる文字列で持つ。

### 4.4 ローマ字の打鍵数（標準の換算表）

IME 論文の `kit/gen/romaji.py`（Apache-2.0・同じ研究者のコード）の表をそのまま写して使う（`scripts/romaji_table.py`。写した元の SHA-256 を `env.md` に書く）。要点:

- ヘボン式に近い 1 つの表。`ん` は常に `nn`。`っ` は次の子音を重ねる（次が母音・ん・小さいかな・記号・終わりなら `xtu`）。小さいかなは `x` を前に付ける（拗音・ふぁ行の組み合わせを除く）。`ー` は - の 1 打。
- `#` は 1 打。区間の打鍵数 ＝ 区間の単位の列を表で打鍵に直した長さ（境界の字は含めない）。
- 攻撃者は常にこの標準の表で候補を計算する。

### 4.5 書き手の癖（雑音の「揺れ」・書き手ごとに固定・攻撃者は知らない）

| 癖 | 標準 | 癖のある書き手 | 打鍵数の差 |
|---|---|---|---|
| ん | nn | 次のかなが子音で始まる（n・y で始まるもの・母音を除く）同じ区間の中なら n | −1 |
| し | shi | si（しゃ行は sha のまま） | −1 |
| ち | chi | ti（ちゃ行は cha のまま） | −1 |
| つ | tsu | tu（っつ は ttu） | −1 |
| じゃ・じゅ・じょ | ja・ju・jo | jya・jyu・jyo | +1 |

## 5. 区切りの定義（記録の側と攻撃者の側で同じ位置）

位置は P の上で決め、W には位置の対応表で写す（境界の字と改行はルビの外にあるので位置はずれない。ルビの親字の中に落ちる区切り（B2 の文節の切れ目だけで起きる）は、置き換えた読みの中の比例した位置に写す。書き手の形態素は、始まりの位置が入る区間に数える）。

| 記号 | 区切り | 攻撃者 |
|---|---|---|
| B0（主） | 読点・句点（SentencePunctuation）と改行（Enter） | 確定の Enter を改行と見分けられると仮定（理想） |
| B1 | B0 ＋ 確定の Enter（文ごとに確定する癖） | 癖を知っている（同じ規則で候補を計算する） |
| B2 | B0 ＋ 確定の Enter（文節ごとに確定する癖） | 同上 |
| B3 | 読点・句点だけ（Enter はすべて無視し、前後の区間をつなぐ） | 確定の癖を知らない攻撃者がとれる頑健な手 |

- 確定の Enter の置き方: B1 は句点の直後（後ろに閉じ括弧 」』）〕］ が続けばその後）。B2 は文節の終わりごと（読点・句点・閉じ括弧はその前の文節に含め、その後に置く）。どちらも、改行の直前に、前の確定のあと何か打っていれば確定を 1 回置く（変換中の文字を確定しないと改行できないため）。区間の長さ 0 も区間として数える。⚠️ 2026-10-09 にレビューを受けて実装を直した: 確定は、前の確定（または行頭）のあと何か打ったときだけ置く（すべての確定に当てる）。旧実装は、字下げの空白の後の最初の文節の前（行頭から何も打っていない位置）にも B2 の確定を置いており、ほぼすべての段落の頭に長さ 0 の区間が増えていた（code-reviewer の指摘）。
- 文節（B2 だけで使う・近似）: SudachiPy の品詞で、自立語（名詞・代名詞・動詞・形容詞・形状詞・副詞・連体詞・接続詞・感動詞・接頭辞）から新しい文節を始める。ただし、前が接頭辞・開き括弧のとき、名詞・形状詞・接尾辞が名詞の後に続くとき、品詞の細分類が「非自立可能」のときは始めない。開き括弧（補助記号・括弧開）は新しい文節を始める。助詞・助動詞・接尾辞・補助記号・空白は前の文節に付く。
- B3 は改行で区間を切らないので、区間が行をまたぐ。

## 6. 指標 1: 位置が一意に決まる割合

- 作品ごとに区間の打鍵数の列（攻撃者の側・標準の表）を作る。k 個の連続した区間（窓）は、作品の中で、k 個すべてが有効なものだけを数える（作品をまたがない）。
- 一意 ＝ その窓の並び（k 個の整数の組）が、コーパスの有効な窓すべての中で 1 回だけ現れる。割合 ＝ 一意な窓の数 ÷ 有効な窓の数。
- k ＝ 1〜30 のすべて（研究者の選択）。区切り B0〜B3 × コーパス（参照 12・先頭 100・1,000・1,500）。
- 理想の条件だけ（雑音のある並びの一意さは指標 2 で見る）。

## 7. 指標 2: 候補 N 本からの照合

### 7.1 偶然の水準 1/N の前提（結果の前に固定・判断 10・11）

- 候補は**別々の作品**から 1 本ずつ。区切りと k ごとに、有効な k の窓を 1 つ以上持つ作品を「使える作品」とし、そこから N 作品を一様に、重複なしで選ぶ。
- 各作品の中で、有効な k の窓を一様に 1 つ選ぶ（作品の長さで重みを付けない）。
- 正解は、選んだ N 本の中から一様に 1 本（＝ 正解の作品は使える作品から一様に選ばれる。長い作品ほど正解になりやすい偏りは無い）。正解は必ず候補に入る。
- 記録は、正解の窓の本文を書き手が打ったもの（理想または雑音あり）。区切りの数は k（攻撃者は記録の区切りの数を知っている）。
- 同点: 距離が最小の候補が m 本あり、その中に正解があれば 1/m の得点（一様な無作為の決め方の期待値）。同じ並びが複数の候補に出る場合も同点として扱う。
- 重複する作品は §3 で除く。
- 使える作品の数が N より少ないセルは計算しない（「計算不能」と書く）。

### 7.2 攻撃者

候補ごとに、標準の表で k 個の打鍵数の並びを計算し、記録の並びとの L1 距離（差の絶対値の和）が最小のものを選ぶ。雑音の型も大きさも知らない。

### 7.3 値（研究者の選択 2026-10-09）

- k ＝ 1, 2, 3, 5, 8, 12, 20。N ＝ 10, 100, 1000。区切り B0〜B3。
- 試行は 1 セル 2,000 回。区切り・k・N ごとに候補と正解の選び方を固定し、雑音の条件の間で同じ試行を使う（比べやすくするため）。
- 区間: 正解の作品を単位にしたブートストラップ（2,000 回・百分位の 95%）で、正答率と「正答率 − 1/N」の区間を出す。

### 7.4 雑音の条件

| 条件 | 書き手の読み | 揺れ（各癖を使う書き手の割合） | BackSpace（文字キー ＋ BS に占める BS の割合） | 打鍵数のずれ（区間ごと） |
|---|---|---|---|---|
| 理想 | P（SudachiPy） | なし | なし | なし |
| 弱 | W（ルビ） | 25% | 1.8% | なし |
| 中 | W | 50% | 6.3% | 5% の区間で ±1 |
| 強 | W | 50% | 10.8% | 15% の区間で ±1 |
| ルビだけ | W | なし | なし | なし |
| 揺れだけ（中） | P | 50% | なし | なし |
| BS だけ（中） | P | なし | 6.3% | なし |
| ずれだけ（中） | P | なし | なし | 5% の区間で ±1 |

- 1.8%・6.3%・10.8% は [P269]（Dhakal et al. 2018・英語の書き写し）の「Backspace か Delete の押下が全押下に占める割合」の平均 6.3%（SD 4.5%）から、平均 −1SD・平均・平均 +1SD とした（本文を pypdf で抽出して確かめた: *"The average number of error corrections is 2.29 per sentence (6.3%, SD = 4.5%)"*）。英語の書き写しの値で、日本語の自由な作文の値ではない。打鍵数のずれの 5%・15% は根拠のない仮定の値。
- BackSpace の型: かなの単位ごと（`#`・`ー` も 1 単位）に確率 p で誤りが起きる。半分は、かなになる前に気づき、誤ったキー 1 打と BS 1 打（差し引き 0）。半分は、誤ったかなを打ってから BS 1 打で消し、そのかなを打ち直す（文字キー +r・BS +1・差し引き +r−1。r はそのかなの標準の打鍵数）。攻撃者は「文字キー − BS」を数える。
- p の決め方: BS の割合 s から p ＝ s·r̄ ／ (1 − s·(1.5 + 0.5·r̄))（r̄ はコーパスの書き手の読みの、単位あたりの標準の打鍵数の平均。結果より前の前処理で計算して記録する）。分母に Space・Enter・修飾キーを入れないので、[P269] の割合（全押下が分母）より少し強めになる。
- 打鍵数のずれ: 区間ごとに確率 q で +1 か −1（半々）。0 より下にはしない。読みの取り違え・記録の取りこぼし・IME 固有の打ち方など、ほかの源をまとめた仮定。
- 理想の条件の記録は、攻撃者の計算と完全に一致する（＝ 正答率は同じ並びの候補の数だけで決まる）。

### 7.5 確かめるための追加の出力（診断）

- 理想の条件で、情報を使わない予測 2 つ（無作為に選ぶ・窓の数がいちばん多い作品の候補を選ぶ）の正答率。どちらも 1/N に近いはず。
- 正解の位置（0〜N−1）の頻度の偏り（カイ二乗）。

## 11. 限界（結果のノートに書く）

- 上限ではない: 時刻の癖・本人の過去の文章・言語モデル・キーの順序で確定の Enter を推す攻撃・記録の区切りの数を使わない攻撃（ずれた位置合わせ）を含まない。雑音の型を知る攻撃者（尤度）はもっと強い。
- 合成の書き手は推敲・貼り付け・カーソル移動・変換の取り消しをしない。打鍵の個数は本文の長さと同じではない（IME の変換・推敲で崩れる）。
