## D-1: ★★★ ADR-014（R3）を **Accepted** にした

- **決定**: 研究者判断 6 件をすべて確定し、ステータスを `Proposed` → **`Accepted`** にした。
- **理由**: ⚠️ Accepted にできていなかった理由は **技術ではなく研究者判断が空だったこと**である
  （ADR-014 の当該節が「⚠️ なぜ dev が決められないか」を列挙していた）。★ 本セッションの grill で 6 件とも埋まった。
- **却下案**: 「G1 の判定が出るまで Proposed のまま置く」——
  ⚠️ **判定を待つ必然性が無い**（D-4 参照）。★ 置いたままにすると **設計が実装より先に腐る**。

## D-2: R3 の対象者 = ★ **形成的サブコホート（3〜5 名）**

- **理由**: `personalization §4.3` / ADR-009 D4 が **subject / task / session の 3 分割すべて**を必須にしており、
  ⚠️ **研究者 1 名では subject 分割が作れない** → **ADR-008 D8 の「写像係数の個人差が本命」を R3 で見られない**。
- **却下案**:
  - 「研究者自身のみ」—— ⚠️ 上記のとおり **R3 の主目的の半分が見られない**。
  - 「一般ユーザー」—— ⚠️ **倫理審査の不要判断（D-5）の根拠 4 が崩れる**。

## D-3: 開始時期 = ★ **G1 の *収集完了* 直後**（⚠️ GATE3 の verdict は待たない）

- **理由（2 段に分ける）**:
  - ★ **判定は待たない** —— **ADR-014 D2 が R3 を確証から明示的に外している**ので、
    ⚠️ **GATE3 が Go でも Kill でも R3 の問い（`left_observation` の混合が割れるか）は変わらない**。
    → ★ **間違ったゲートで待つことになる**（ADR-011 §Context-6「待つと止まる」の再発）。
  - ⚠️★★★ **収集完了は待つ** —— **R3 は G1 と同じ計器（GSE 本体）を使う**。
    ★ 収集中に記録仕様を変えると `preregistration.md §3.6`（ブロックの事後除外の禁止）により**回復不能**。
- ★ **これで D-2 の募集競合が時間軸で解ける**（G1 の 3 名 → R3 の 3〜5 名の順に募集する）。
- **却下案**: 「G1 と並行（別被験者）」—— ⚠️ **計器の変更が G1 の凍結に直撃する**。

## D-4: 倫理審査 = ★ **不要。⚠️ ただし根拠を 4 点で記録し、崩れる条件も書いた**

- **理由**: ADR-012 D12-c と同じ作法（「**要否を決定として記録する**」）。
- ★ 根拠 4 点（**すべて揃っていることが条件**）: content-free / ローカル保存のみ / 被験者が停止・削除できる / 一般公募をしない。
- ⚠️★★★ **1 つでも崩れたら再判断する**と ADR に明記した。★ とくに
  **役割カテゴリを入れた瞬間に根拠 1 が崩れる** / **一般ユーザーへ広げた瞬間に根拠 4 が崩れる**。
- ⚠️ **判断の責任は研究者にある。** ★ ADR は「不要と決めた事実と根拠」を記録するだけで、
  **所属機関の規程に照らした適法性を主張しない**と明記した。

## ⚠️★★★ D-7: **D-6 に研究上の代償があることを発見した**（★ 研究者へ返す）

- **事実（逐語・`bin/replay.rs:3104-3108`）**:
  > 匿名化は `is_text_producing` より粗い `KeyCategory` を使うため、**OEM 句読点・Tab・テンキー演算子**
  > (= raw では text-producing だが匿名化で `Other`) が匿名化後に text-producing と判別できず、
  > `collect_key_events` → **manual_insert 系がちょうどその件数だけ過小評価**される。
  > これは #27 の匿名化設計に内在し **replay では復元不可**。
- ⚠️★★★ **`manual_contribution_ratio` は `research-positioning §5` H-Y の主要アウトカムである。**
  → ★ **D-6 をそのまま実装すると、H-Y のアウトカムが構造的に過小評価される。**
- ★ **緩和案（⚠️ 本セッションでは採択しない）**: `KeyCategory` に **`Punctuation`** を足し、
  OEM 句読点を `Other` から分離する。⚠️ **代償**: 句読点を分けると**文境界の情報が増える**ため
  `data-privacy` の再検討が要る（★ ただし**どの句読点かは残さない**ので本文再構成不能は保たれる）。
- → ⚠️ **D-6 は「決定は下りたが、実装前に緩和案の採否が要る」状態である**（ADR-014 Migration 8）。

## ⚠️★★★ D-12: **D-8 の macOS 結論を訂正した**（2026-08-23・研究者の問いを受けて再調査）

## D-13: ★★★ `Punctuation` / `Tab` を実装した（2026-08-23・研究者判断）

- **決定**: `KeyCategory` に **`Punctuation`**（`0x6A..=0x6F` / `0xBA..=0xC0` / `0xDB..=0xDF` / `0xE2` の **19 VK**）
  と **`Tab`**（`0x09`）を足した。
- ★ **結果**: `is_text_producing` が true な VK は **1 つ残らず非 `Other`** に入るようになり、
  ⚠️ **`manual_insert` 系の過小評価はゼロ**になった（`replay.rs` の `other => 0x07` も**厳密に正しく**なった）。
- ★★★ **これは新しい privacy 判断ではなかった** —— ⚠️ **`data-privacy` Skill の `anonymization.md` は
  最初から enum に `Punctuation` を宣言していた**が、**`from_vk` が 1 つも割り当てていなかった**。
  → ★ **仕様と実装のずれであり、2026-08-23 に両方向で正した**。
- ★ **プライバシーの向き**: ⚠️ 判断 6 の実装は **正味で改善**である。
  今日ローカルに書いているのは **生 VK（キー個体）**で、変更後は **14 カテゴリ**。
  ★ `Punctuation` を足しても **今日より粗い**。
- ★ **不変条件を 4 つテストで固定した**（`anonymization.md §不変条件`）。
- ⚠️ **残**: 量子化の適用点を **transfer 境界 → logger の書き出し境界**へ移す（別タスク・ADR-014 Migration 8）。
