# 設計案比較 — /reimagine 1 回目

## v1 の要旨

上流（形成的研究）と下流（収集仕様）を 2 本の ADR に分け、**いきなり新コホートを募集**して
専用計測器で沈黙被覆率を測る。合格閾値 `θ` は事前登録で**人が決める自由パラメータ**。
画面録画は**全セッション**で取り、コード化直後に破棄。`capabilities` は **meta 行に手書きで列挙**。
候補チャネルは 6 つを**一括で**測る。

## v2 の要旨

同じ 2 本の ADR だが、**Stage 0（募集ゼロ・新規実装ゼロ）を前に置く** ——
`starved_ms` が「沈黙のうち入力を伴った時間」そのものである（`liveness.rs:86-104` 実測）ことを使い、
**G1 ログで打鍵タスクの被覆率 `C_write` を先に出す**。⚠️ **`θ` はそこから導かれ、人が選ばない。**
候補チャネルは**取得コストで層別**し、**前の層で足りたら次を集めない**。
画面録画は**検証用サブサンプルのみ**。`capabilities` は **`LogEntry` の variant から導出し、テストで固定**する。

## 主要な差異

| 観点 | v1 | v2 |
|---|---|---|
| **アプローチ** | 新コホート募集 → 測る | ★ **既存計器 + G1 ログで先に測る（Stage 0）→ 足りない分だけ新規（Stage 1）** |
| **閾値 θ の出所** | ⚠️ 事前登録で人が決める自由パラメータ | ★★★ **打鍵タスクの実測値（`C_write` の最大）から導く** |
| **要件 #2 への答え方** | 同一人物の論述ブロックのみ | ★ 論述ブロック **＋ Stage 0 の別コホート基線**（2 重の比較） |
| **募集リソース** | ⚠️ 最初から G1 の残り 2 名と競合 | ★ Stage 0 は **1 名も使わない** |
| **候補チャネル** | 6 つを一括で測る | ★ **層別（L-a〜L-d）。前の層で足りたら次を集めない** |
| **画面録画** | 全セッション | ★ **検証用サブサンプルのみ**（被覆率の計算に録画は不要という気づき） |
| **`capabilities`** | ⚠️ 手書き列挙（★ 腐る） | ★★★ **コードから導出 ＋ テストで固定** |
| **変更規模** | 同じ（ドキュメントのみ・コード変更ゼロ） | 同じ |
| **テスト戦略** | 「変えていないことの証明」 | 同左 ＋ ★ **実装時の acceptance（variant 網羅テスト）を先に宣言** |
| **リスク** | ⚠️ 募集が失敗すると**何も測れずに終わる** | ★ Stage 0 が単独で結果を出すので**空振りしない**。⚠️ 代わりに G1 ログの提供が律速 |
| **「同じ形だった」の扱い** | 記述なし | ★★★ **`C_nonkey ≈ C_write` を「要件 #2 への答え」として明示的に受け入れる**（失敗扱いしない） |

## ★ v2 が v1 の何を壊したか（★ 隠さない）

1. ⚠️ **Stage 0 は G1 ログの提供に依存する。** `raw/` にあるのは P000 と Phase1 のみで、
   **G1 ログはローカルに無い**（handoff §8-2）。→ ★ 研究者からの提供が新しい律速になる。
   （★ ただし v1 の律速＝募集より速い見込みであり、**引き継ぎプロンプトで待ち時間ゼロにする**）
2. ⚠️ **`C_write` は G1 の確証標本 1/3 名から出る。** 点推定として扱えない。
   → ★ v2 は「全員値を併記し、**最大値**を θ に置く」ことで厳しい側に倒している。
3. ⚠️ **層別（L-a→L-b→L-c）は「早く止まる」ので、後から「L-c も測っておけばよかった」が起こりうる。**
   → ★ ただしこれは **ADR-008 D1 の裏返し（実測で足りたのに集める、を禁じる）**を意図的に採った結果である。

## 推奨案

**v2** — 理由:

1. ★★★ **要件 #1（実測で決める）を θ にまで適用しているのは v2 だけ。**
   ⚠️ v1 は「候補の採否は実測で決める」と言いながら、**合否の線引きは dev の推測**のままだった。
   ★ これは要件が名指しで否定した構造そのものである。
2. ★★★ **要件 #2（同じ形になる）に、v2 は「同じ形だった」という結論を出せる形を与えている。**
   ⚠️ v1 は「被覆率が高ければ採用」しか書いておらず、**発意が外れていた場合に何と書くかが無かった**。
3. ★★★ **要件 #3（計器がコホートを跨げなかった）に、v2 だけが *機械的な* 答えを出している。**
   ⚠️ v1 の手書き `capabilities` は、**今回の失敗（規約はあったが適用しなかった）と同じ壊れ方をする。**
4. ★ **募集リソースの競合**（G1 の残り 2 名＝すべてのボトルネック）を、v2 は Stage 0 で回避している。
5. ★ v2 は ADR-011 Migration 3b（**未了**）を設計の一部として消化し、**新しい仕事を増やしていない**。

⚠️ **v1 から引き継ぐもの**（v2 が捨てていない要素）: ADR 2 本構成 / 観測と宣言を融合しない /
同一人物内の論述ブロック / モダリティを打鍵密度順に降りる / n の下限 / 入れない判断の明示 /
`§8` T3 行は「降格先」列のみ改訂。
