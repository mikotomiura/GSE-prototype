# requirement — O1 の「裸の行の乗っ取り」を塞ぐ（G1 からの移植）

## 背景

★ PR #140 は G1 の P-ID 欠陥 9 件を塞いだが、⚠️ **O1 には同じ穴が残っていた。**
★ G1 のコード自身が「⚠️★★ **O1 も同じ穴を持つ**（`Form_O1/GSE_O1_Form_Builder.gs:1022`）」と
書いており、引き継ぎメモ §4-1 でも HIGH として起票されていた。

## ⚠️ 欠陥（★ 実コードを読んで確認した）

`Form_O1/GSE_O1_Form_Builder.gs` の `o1FindInPhase1Roster_()`:

```js
rowEmail = String(rows[i][2]).trim().toLowerCase();
if (!rowEmail) return { pid: rowPid, row: i + 1 }; // ★ 空欄 = 埋めてよい
```

★ 攻撃経路:
1. 採番は `appendRow([newPid])` で **氏名もメールも空の行**を作る
2. ⚠️ 研究者が手入力するまでの間、その P-ID を申告した**誰でも**この分岐を通る
3. → その ID を受け取り、**自分のメールがその行に書き込まれ**、受付メールが届く

⚠️ P-ID は連番・フォーム URL は配布済み・`setCollectEmail(false)` で Google 認証も無い
→ ★ **総当たりで当たる**。
⚠️★★ しかも **ロスターは Phase1 / G1 / O1 で共用**なので、被害は O1 に閉じない。

### ⚠️★ コードが自身の doc と食い違っていた

★ 同関数の doc コメントは
「その行のメールが**空**なら採用する (**氏名だけ先に入れた行**を埋める正当な経路)」
と書いているのに、⚠️ **コードは氏名を一度も見ていなかった**。
→ ★ 本修正はコードを**自身の仕様に合わせる**ものである。

## ゴール

1. 裸の行（氏名もメールも空）は `conflict` にして研究者に判断させる
2. ⚠️ 氏名が入っている行（研究者が用意した正当な経路）は**通す**
3. ★ 検査が実在の欠陥を捕まえることを**変異注入で示す**

- [x] 裸の行を申告 P-ID で取れない（`reason: "bare-row-claim"`）

- [x] メール不一致は `conflict`（`reason: "email-mismatch"`）
- [x] ★ メール一致の経路が壊れていない（**陽性対照**）
- [x] ⚠️ **変異を注入すると赤になる**
- [x] 既存の検査（O1 134 / 提出ガード 44 / G1 74 / 変異 41）がすべて緑
