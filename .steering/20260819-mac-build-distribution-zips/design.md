# 設計 — v0.1.27 配布 zip の作成

## アプローチ

★ **既存の `make-common-app-zip.sh` をそのまま使う。設計し直さない。**
zip の形 (dmg ではなくフォルダ入り `.app` の単一 zip) は、すべて実測記録に基づく決定である:

1. dmg のドラッグ工程を残すと G1 モードにならない (2026-08-07 実機・`decisions.md` D-9)
   → `.app` を**あらかじめ**フォルダに入れる
2. `g1.mode` を `.app` の中に置くと `codesign --verify --strict` が
   `a sealed resource is missing or invalid` で落ちる (`g1.rs` D-7)
   → マーカーはバンドルの**外**
3. Drive はパーミッションを保存しない (2026-08-07 実測) → **単一ファイルの zip** で配る
4. 公証を通していない → `初回セットアップ_mac.sh` を初回だけ研究者と一緒に実行する

## 実行

```bash
cd experiments/20260801-controlled-friction-task
./make-common-app-zip.sh --tag v0.1.27      # ⚠️ 既定は v0.1.24。付け忘れると古いアプリを配る
```

## テスト戦略

スクリプトの機械検査 (配る物そのものを展開して検査する) に加え、
引き継ぎ §3 の 4 項目を**実機起動**で確かめる。

| # | 項目 | 手段 |
|---|---|---|
| §3-1 | zip に `.app` があり `.dmg` が無い | `unzip -Z1` のエントリ計数 |
| §3-2 | `app_version = 0.1.27` | 実起動して NDJSON `meta` 行を読む |
| §3-3 | G-1 二度押しでファイルが分かれる | AX API で「開始する」→「← 戻る」→「開始する」 |
| §3-4 | `starve_window` | 出れば `win_ms` を見る (出ないのは異常ではない) |

### ⚠️ 検証の隔離 (本番データを汚さない)

- テスト起動は `GSE_G1_PARTICIPANT_ID=P999` で行う (この Mac の実 ID は `P009`)
- ⚠️ **「送信する」「提出する」は押さない** —— 送信層は `.age.ok` (被験者の確認) が
  付いたものだけを送るので、押さなければ実エンドポイントへは 1 本も飛ばない
  (起動時の収束器が `sent:0` を返すことで実測確認)
- zip は repo 外 (scratchpad) に展開して被験者と同じ経路で起動する
