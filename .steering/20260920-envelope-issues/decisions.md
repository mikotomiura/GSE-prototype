## 判断 1: 実施形態 —— issue に切らず本セッションで直接実装する

- **判断日時**: 2026-09-20（研究者裁定）
- **背景**: 判断 25 #14 の逐語は「封筒を足す**小 issue**」。しかし封筒の変更は
  `001-acceptance.sh` 〜 `008-acceptance.sh` の **8 本すべて**に触れる。

  - B: `issues/009.md` を切って Loop（モードC）で回す

- **理由**: Loop Engineering の縦切り issue は **Allowed Files 非交差**を前提に置く

  封筒自体の検査は `envelope-acceptance.sh` として同ディレクトリに置く（判断 7）。

## 判断 4: `basename` を載せるが、参加者 ID 検査は `rows` に限定する

- **判断日時**: 2026-09-20（研究者裁定）

  参加者らしき文字列（`PARTICIPANT_RE`）があれば赤」。★ 封筒に `basename` を置くと、
  実セッション名（`gse_20260918_101500_P003.ndjson`）で**必ず赤になる**。

- **採用**:

## 判断 10: `008` の計時検査だけ封筒の剥がし方を変える

- **判断日時**: 2026-09-20（★ 実装中）
- **背景**: 判断 8 は「取得時に `| jq '.rows'`」と定めたが、`008-acceptance.sh` の
  AC18 / AC18b は `timeout 20 ... ; rc=$?` で**時間切れ (`rc=124`) を見分けている**。
- **中身**: ⚠️★★★ `timeout ... | jq` にすると、打ち切られた部分的な出力で jq が `5` を返した瞬間、
  `set -o pipefail` が**「最も右の非 0」= 5** を採り、★ **`rc=124` が消える**。
  → ⚠️ 「20 秒で終わらない（計算量が二乗のまま）」という診断が
  「非 0 で終了した」に化け、**AC18 が守ろうとしている性質が読めなくなる**。
- **採用**: この 2 か所だけ **生取得 → `rc` 判定 → 別の行で剥がす** の 3 段にする。
- **理由**: ★ 判断 8 の目的は「28 箇所の書き換えを避ける」ことであって、
  「1 行で書く」こと自体ではない。⚠️ 診断の情報量を落としてまで守る形ではない。
- **影響範囲**: `008-acceptance.sh` の AC18 / AC18b（★ 理由をその場にコメントで残した）。
