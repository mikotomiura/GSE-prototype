# 重要な設計判断

## 判断 1: G1 の `buildLinksTab_` に倣い、運営シートに派生の表示として置く
- リンク集は毎回作り直す（ログのタブのような追記のみではない）。手で入れる 3 欄だけ項目名で引き継ぐ。
- 参加者ロスターは名前で指すだけ（G1 と同じ）。ID・URL を書かない（氏名・メールへのポインタ）。

## 判断 2: レビューの指摘を反映した（code-reviewer: HIGH 0・MEDIUM 3 / security-checker: HIGH・MEDIUM 0・LOW 4）
- 手で入れた欄は `getDisplayValues` で読む（`getValues` だと日付が `String(Date)` に化ける）。
  ⚠️ 数式・挿入したリンクは保たない → 2 行目の注記に「URL をそのまま貼る」と書いた（保つ実装〔`getFormulas`〕は採らなかった: 研究者の手入力の数式を書き戻すと、無害化の約束と衝突するため）。
- 同じ項目名の行が複数あれば、空でない最初の値を採り、ログに出す。
- 行を組み立ててからタブを作る（失敗で空のタブを残さない）。
- `buildO1MgmtSheet` の try/catch にテストと変異を足し、失敗を「作れていません」と肯定形で言う。
- 注記: 「手動の 3 欄以外は作り直すと消える」「どの欄にも氏名・メールを書かない」（メモ欄の備考にも）。
- 数式のテストは「読み戻した値が `=` で始まる文字列だった場合の防御」と名前を改めた（実物では数式は表示値で読まれる）。
- 採らなかった LOW: 「更新」行の自動の日時解釈（見た目だけ）・`o1BuildLinksTab_` 内での `o1MgmtConfigProblem_` の再検査（呼び出し元 2 か所が既に通る）。

## 判断 3: Codex のレビューは回していない
- 2026-10-07 の Codex 予算を超過済み（306,004 / 300,000）。⚠️ 完了時の `/cross-review` は Claude 側（code-reviewer ＋ security-checker）だけ。

## 判断 4: 各リンクに「いつ・誰が使うか」の列を足した（研究者依頼 2026-10-07）
- 研究者の問い「各リンクごとの説明（どのタイミングで被験者に回答していただくか）も載っている？」→ 備考に短い説明しか無かった。
- 列を 5 つにした: 項目 / 値・URL / 種別 / **いつ・誰が使うか** / 備考。説明の列は折り返す。
- 文言の出所: O1-C = 同意フォームの説明・受付メール（`o1RegisterAckBody_`）・`docs/o1-roster-operations.md` §5／O1-S = `buildO1PostSurveyForm` の説明文（約 5 分・解析に使わない・理由を聞かない）と研究者判断（終了判定の後に手で送る）／アプリ = 受付メール。
- テスト 4 ケース（全行 5 列・O1-C【募集時】・O1-S【終了判定の後】・空の説明が無い・折り返し）と変異 1 件。
