# TRACE 研究設計改善提案書 v2.0

**対象資料**：`TRACE_草稿_2026-10-18(1).docx`（2026-10-19版、25頁）、`TRACE_共著者への案内_2026-10-18.docx`（10頁）、`TRACE_研究設計改善案_事前登録前_v1.md`。  
**位置づけ**：著者への設計上の提案。既定のプロトコルや実施済みの結果ではない。事前登録前に著者間で採否を決めるためのレビュー。  
**原則**：研究の中心的構想は維持する。未実施の検証を実施済みと書かない。追加分析を安易に増やさず、判断規則の概念的妥当性を優先する。

## 0. 結論と前版からの更新

### 0.1 現段階の総評

**大枠の研究コンセプトと研究実施設計は初稿より明確に改善した。** とりわけ、(a) 人間の第二著者による全文の独立スクリーニングとメインセット全件の独立符号化、(b) AIを採否決定者からタイトル・抄録段階の安全網へ降格、(c) 「報告上の不整合」「名称・帰属の差異」「推論の過剰拡張の可能性」の分離、(d) コード別の一致度と感度分析の明確化を評価する。

一方、現在のボトルネックは**C1→C6c/C7(ii)の判定規則が本当に意図した概念を捉えるか**、**第1段階での見落としをどう見積もるか**、**登録資料・共著者案内・実行用スクリプトの三者整合性**である。信頼性（同じ基準で判定できるか）と妥当性（その基準が正しい対象を判定しているか）は異なる。

| 観点 | 現行版の判断 | v2での扱い |
|---|---|---|
| 研究の問い | 維持推奨 | RQ1/RQ2/RQ5を論文上の中心に据えるが、現行登録用RQの削除は求めない |
| AIの役割 | 大幅改善 | AIの安全網運用の停止・エスカレーション規則を固定 |
| 二重スクリーニング | 改善 | 第1段階の偽陰性リスクを追加検証 |
| C1 | 非品質ランキングと明記済み | L2・L5等の異種次元を反例テストで検査 |
| C6/C7 | 3カテゴリー化は適切 | 「単なる名称差」と「不支持の推論」の判定基準を検証 |
| C2b | 内容分析として妥当 | 境界項目の事例検査とカテゴリ説明を追加 |
| 再現性 | コードと表の自動生成を予定 | 計算スクリプトのテスト合格条件と記録方式を明示 |

### 0.2 優先度

- **P0：登録前に決着**：C1/C6/C7の反例テスト、事前登録用文書の整合、主要な判定規則、合成データによるスクリプトテスト、第二著者の担当範囲。
- **P1：本番符号化前に決着**：探索セットによる較正、符号化規則修正のログ、実際の選別一致と偽陰性点検、証拠記録の定式化。
- **P2：論文執筆までに整備**：表の読み方、記述的分布と「観察された」の表現、推薦文の根拠対応、公開パッケージのチェック。

## 2. 追加する最重要工程：TRACE Coding Framework Validation

### 2.1 目的

登録前に、**既知の判定規則の論理的整合性、曖昧さ、反例耐性**を点検する。メインセットの結果を見てルールを後から最適化しないため、登録前に実施する。

**検証対象**：C1（AI帰属位置）、C2b（項目内容）、C6（タイトル対デザイン・尺度名・帰属）、C7（結論対デザイン・名称・帰属）。C3のAI側変数の操作情報を併せて点検する。

### 2.2 検証用ケース（最低8件、推奨12件）

新しい実在論文の結果を持ち込まず、**架空の研究要約・架空の項目文**で作る。探索11研究や既読79候補に似た事例を使う場合は「開発・較正用」と明記し、メインセットの独立性の根拠には使わない。

| ケース | 仮想研究の構成 | 争点 |
|---|---|---|
| V01 | 一般的疲労尺度＋AI利用をランダム割付 | AIへの項目内帰属なしでも因果推論は可能か |
| V02 | AIを項目に明記した尺度＋横断相関研究 | AI明示でも因果推論は不可 |
| V03 | 項目は一般的、教示で「AI利用後」を指定 | C1のL1bとL1aの分離 |
| V04 | AIを1項目だけ問う尺度 | C1 L2と「AIを含む項目」の優先順位 |
| V05 | 面接テーマとしてAI由来の疲労を掘り下げる質的研究 | L5の扱いと「AI fatigue」呼称の規範性 |
| V06 | 一般疲労尺度とAI利用時間の縦断的関連 | 関連の証拠と固有の疲労概念の違い |
| V07 | 名称はburnoutだが項目は疲労中心、用語を明示定義 | 名称差は欠陥ではない |
| V08 | 非実験研究だが因果語を引用・仮説として記述 | C6b/C7(i)で著者自身の主張と他者の主張を分ける |
| V09 | 介入研究だが操作したのはAI側でなく休息時間 | 操作有無の意味と因果主張の対象 |
| V10 | AI利用を操作したが交絡・遵守・選択の問題がある | 「操作あり」だけで妥当性確定しない |
| V11 | 項目に「AIを使いたくない」だけ記載 | AVOと疲労の判定境界 |
| V12 | 表題と尺度名は一致、結論の範囲のみ超過 | C6aでは見逃し、C7で検出する例 |

**各ケースで保存する成果物**：case_id、架空デザイン、項目・教示・タイトル・結論、期待コード、許容される複数の解釈、根拠、曖昧さ、ルール修正が必要か、修正箇所。二者の判定差はそのまま保存する。

### 2.3 合否規則（提案）

- 登録前に**クリティカルな反例が0件**：同一ケースで妥当な結論を「欠陥」と断定する、又は論理的に両立しない2つのコードが強制される、といった事例を解決する。
- 不一致が残る場合は**「決定規則」「not_verifiable」「unresolved」**のどれを使うか文書化する。
- 「12/12一致」などの任意の数値だけでは概念妥当性を立証したと主張しない。
- 記録を著者間で確認し、最終的なC1/C6/C7導出表をコードブックに反映する。

### 2.4 C1をどうするか

**最小改訂を優先**：現行L1a〜L6をすぐ廃止せず、単一の質的順位と見なさないこと、L2・L5が項目位置だけでなく測定形式を含むことを説明し、代表値だけでなく該当フラグを保存する。既存の `records` 様式ではC1各値を持つ予定なので、この利点を維持する。

**重要な禁止規則**：L3〜L6であること**だけ**から「AI fatigueという結論は不当」「測定が無効」と推論しない。現行C6c・C7(ii)は名称・帰属の差異を示す**記述フラグ**として扱い、因果性・概念妥当性の独立した裁定から切り離す。

**拡張するなら**：C6bに記録される「研究デザイン」「AI側の操作有無」に加え、結論の種類（記述／関連／因果／概念同定）を**必要最小限の補助変数**として導入する案を事前登録前に検討する。ただし、追加すると2名の符号化負担が増えるため、反例テストで必要性が実証されたときだけ採用する。

### 2.5 C6/C7の出力語を固定

- **Descriptive wording difference**：名称・帰属の差。単独では測定不備でも論文不正でもない。
- **Internal reporting inconsistency**：同一論文内の数値や記述の食い違い。
- **Potential inferential overreach**：デザインと主要な因果主張の間の不一致の可能性。著者の意図や真偽の全体を判定するものではない。
- **Not assessable / unresolved**：情報不足または判断未確定。

表12の `C7(i)/(ii)/(iii): met` は「問題条件が満たされた」と「適合条件が満たされた」の混同を招きやすい。内部データ列は `condition_triggered`、`condition_not_triggered` とし、既存コードが `met` を残すなら注に正方向を明記する。

## 3. 独立した内容レビューと較正を分離

### 3.1 実施者の役割

- **第一著者**：事前登録文書、架空反例集、集計スクリプトを作成。探索11研究を4週間以上空けて2回較正する。
- **第二著者**：登録前に反例集・コードブックを独立に読み、境界判断と反対意見を残す。本番ではメインセット全件を独立に符号化する。
- **AI**：架空反例の網羅性の補助やコードのテストケース起案には使用可。ただし正解の裁定者とはしない。C4f/C5のAI下書きは既存の後開封ルールを遵守。

### 3.2 独立性の守り方

(1) 第二著者は第一著者の期待コードを見ずにケースを判定し、(2) 双方の判定を固定し、(3) 相違と修正理由を残す。**ここは訓練・内容レビューであり、外部バリデーションの証明ではない**と書く。探索セット較正も、メインセットにおける再現性の保証ではない。

### 3.3 較正中に変更が生じた場合

現行草稿は探索セット較正後に定義を改訂して登録修正する計画である。したがって初回OSF登録を「全規則が以後変更されない」という意味で記述しない。**登録時の版、較正で生じた改訂版、メインセット符号化開始時の最終版**を時間順に特定し、各版の適用対象を記録する。

## 4. 文献選別の品質保証（既存の二人制を維持）

### 4.1 保持事項

- 264追加候補と300件のカバレッジ標本について、第一著者がタイトル・抄録を全件評価。
- 第二著者は両集合からそれぞれ無作為20%（案内では53件と60件、計113件）とAI安全網が拾った候補を評価。
- 事前に定めた基準で一致が80%未満の場合はタイトル・抄録の残り451件も第二著者が評価。
- フルテキストとCentre判定は、到達した全記録を2名が独立評価し合議。

### 4.2 追加すべき偽陰性点検

**問題**：双方がタイトル・抄録で除外した記録は全文に進まない。AI安全網も完全ではない。

**提案**：メインの採否判定と独立に、タイトル・抄録で除外されたレコードから、あらかじめ定めた割合又は件数を無作為抽出し、第二著者が全文取得可能性を含めて再点検する。採択候補の見落とし件数、再点検できなかった件数、処理方法を記録する。実施可能でなければ限界として明示する。

- これは全件の感度・特異度推定ではない。抜粋監査の範囲を明示する。
- ランダム20%で80%以上一致しても、**一致率は見落とし率ではない**。ほとんどの記録が除外なら高い一致率は得られやすい。
- 単純一致率、Cohenのκ、判定を「全文へ回す」側に置いた不一致の内訳を併記する。
- 境界例について、判定者ごとの除外理由を保存する。

### 4.3 AI安全網のルールを具体化

登録時に、モデル・プロンプト・実行日・入力（英語原文か機械翻訳か）・呼出し単位・閾値・出力の保存先を固定する。AIが第一著者の除外を覆して「全文候補」と判断したが、第二著者が除外した場合の扱いを明文化する。AIの性能評価について、34探索レコードでの適合は独立した一般化性能ではないと記載する。

### 4.4 カバレッジ検索の限界

案内では外部検索から10,854件の新記録、うち300件を無作為抽出している。**これは特定の検索クエリで新たに発見した記録に対する標本**であり、世界中の関連研究総数や文献検索全体の再現率を表さない。300件で0件ヒットしても上限は0ではない。検索日・抽出シード・重複統合ルール・候補選定単位を報告する。現行草稿の記述と突き合わせて確定する。

## 5. 集計・導出判定スクリプトの事前テスト

### 5.1 テストする機能

1. C1の複数フラグ→代表値の選択、曖昧・欠測の優先規則。
2. C6c/C7各条件の導出、`condition_triggered`の方向性。
3. 操作あり／なし／確認不能の層別（C6c・C7(ii)）。
4. 分母：評価可能、評価不能、未解決、適用なしを混同しない。
5. E5で同一標本と確認されたレコードを研究単位に集約（別に不確定重複は除外感度分析）。
6. 一つの尺度バージョンが複数研究に現れる場合のユニーク項目集計。
7. C2b境界項目の二次カテゴリーによる感度分析。
8. C4fの計算可能／不可能、丸め誤差、p値の有意判定境界。
9. `n<10`の表では割合非表示。
10. すべての表の和・重複・ゼロ除算・欠測値の処理。

### 5.2 合格基準

- **実行可能な全テストが成功**し、期待値・実値・テスト実行日時・コミットIDを保存する。
- 合成データから生成した既知の表と照合する（少なくとも「1件のみ問題」「評価可能0件」「未解決」「複数の尺度」「重複標本」「両層あり」を含む）。
- 失敗時は修正→再実行。解析本番中のコード修正は変更履歴に記載し、元版の結果との違いを確認する。
- スクリプトが通ることは、**研究上の符号化規則の妥当性そのものを証明しない**。

### 5.3 最小限の実行記録テンプレート

```text
run_id, code_commit, protocol_version, test_fixture_version,
expected_summary_hash, observed_summary_hash,
tests_passed, tests_total, executed_at, reviewer
```

## 6. 修正版の実行スケジュール：3回の受け渡しを維持

**期間上の注意**：較正とメインセットの第一著者2パスにそれぞれ最低4週の間隔が必要。G6は文献選別と並走させる。登録草案と共著者案内にある年末締切は、**実際の承諾・G1〜G4の所要期間**を見て再決定する。締切を優先して独立評価や較正を形式的に短縮しない。

### 6.1 共著者の仕事量と合意

案内は全文約100〜140本＋カバレッジ由来の追加分、メインセット約30本の符号化を想定（符号化1本1〜2時間なら30〜60時間）。**これは符号化のみで、全文選別と合議・原稿査読を含まない。** G0で可処分時間を確認し、担当を引き受けられない場合に採用する代替案を登録前に確定する。事前登録後に実施主体を恣意的に切り替えない。

### 6.2 工程を増やしすぎないための優先順位

人手の不足時は、**(1) 二重全文選別と全件二重符号化、(2) 反例テスト、(3) スクリプト検証**を優先。任意の拡張的な推論軸や高度な追加分析は省き、未実施と記録する。文献の網羅率が不足しても、研究範囲を限定して報告する方が、無理に完全性を主張するより誠実である。

## 8. 論文での主要な主張（固定すべき境界）

### 主張できること

- この**指定された文献フレームのメインセットにおいて**、疲労尺度のAI帰属位置と項目内容がどう分布するか。
- 尺度の出自・改作・報告された測定特性・AI側変数の扱い。
- 名称の相違、報告の内部的な食い違い、デザインを超える因果語の可能性の件数（評価可能な分母とともに）。
- 独立判定と感度分析により、**このデータセットで**結果がどれだけ規則の変更に敏感か。

### 主張できないこと

- AI疲労が独立した実在的構成概念であることや、AIが疲労を引き起こすこと。
- 尺度の心理測定上の妥当性が、文面分類のみで証明されたこと。
- 文献全体の問題の有病率・普遍的な割合。
- コードでフラグが立った論文が、臨床的・倫理的に不適格であること。
- 合成反例テストの合格が、フレームワークの外的妥当性を立証すること。

**推奨する研究の中核表現**：

> TRACE describes how a defined set of studies operationalizes fatigue in relation to AI and how the terminology and inferential claims reported by those studies align with their instruments and designs. Its coding flags are descriptive indicators, not direct ratings of construct validity.

**TRACEは研究の大枠を維持して進めるに値する。** 現行版は初稿より研究設計上の独立性と記述上の慎重さが強化されている。最大の未解決点は、コードの定義が意図した方法論的な差異を捉えているかという**内容妥当性と推論規則**であり、単純な一致率の向上だけでは解決できない。事前登録前に反例検証とスクリプトのテストを入れ、役割・時制・登録草案の整合を取れば、主たる研究の範囲を広げずに信頼性を高められる。
