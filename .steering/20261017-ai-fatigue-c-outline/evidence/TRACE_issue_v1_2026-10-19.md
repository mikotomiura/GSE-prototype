## 0. エグゼクティブサマリー

TRACEは、AI関連疲労を扱う既存研究について、(i) 疲労がどのようにAIに結びつけられるか、(ii) 尺度と項目が何を尋ねているか、(iii) 報告・表題・結論が測定内容および研究デザインと整合するかを検討する **methodological review / meta-research** である。新しいAI疲労尺度の開発、構成概念妥当性の直接検証、因果効果のメタ分析ではない。

現行案の強みは、探索セットとメインセットの分離、事前に規則と表を固定する意図、項目水準の分類、再計算・サンプル重複の確認、未評価・不一致の明示、コードとスクリプトの公開計画である。これらは保持する。

**最優先の改訂は3件**：

1. **C1（instrument-level attribution）と研究デザインによるAIへの推論根拠を切り離す。** 項目に「AI」が書かれていなくても、無作為化されたAI使用条件との比較によりAI使用の影響を検証できる場合がある。
2. **C6/C7の判定を、名称の不一致・報告の矛盾・推論の過剰拡張に分ける。** 名称の違い自体を「研究の欠陥」と断定しない。
3. **文献選定フレームとAIスクリーナーの検証を強化する。** 既存の探索集合による検索語の最適化や人間評価者との共有バイアスを明示し、できれば独立した人間による盲検チェックを追加する。

以下では各提案を **[保持] / [修正] / [追加案] / [要決定]** として区別する。とくに「新たな軸B」は検証を要する提案であり、現行の登録草案に存在するコードではない。

## 1. 研究のスコープと主要な主張を固定する

### 1.1 現行設計にある区別 [保持]

- C1：疲労尺度がAIに結びつく位置・方法。
- C2a–C2d：出自・改変、項目内容、適応手続、測定特性等の**報告状況**。
- C3：AI側の変数で用いた道具。
- C4：報告の完全性・内部整合性、統計値再計算。
- C5：サンプル重複のリンクおよび疑い。
- C6：タイトル・抄録と測定名・デザイン・帰属の対照。
- C7：主要な結論とデザイン・帰属・名前との対照。

### 1.2 推奨する中心研究質問 [修正案]

> **AI-related fatigueを扱う研究では、疲労の測定操作とAIへの関連づけ（帰属・比較・関連性の証拠）がどのように構成され、それらは論文のタイトルおよび主要結論でどのように表現されているか。**

この質問は「報告実践の記述」と「推論の条件付き評価」を含むが、**ある尺度がAI疲労を測定できると証明したり、できないと断定したりする質問ではない**。

### 1.3 RQの階層化 [修正案]

| 位置づけ | 原稿の問い | 提案する役割 |
|---|---|---|
| 主軸 | RQ1 C1 attribution | AIへの結びつけ方の記述。新たな推論根拠軸を補助的に併記するか検討 |
| 主軸 | RQ2 C2a–d、C3 | 尺度の出自・改変・項目内容・報告状況の記述 |
| 主軸 | RQ5 C6、SQ2 C7 | 主張と測定・デザインとの関係。ただし判定語を厳密化 |
| 補助 | RQ3 C4 | 報告の整合性・再計算の点検 |
| 補助 | RQ4 C5 | 記録間の非独立性と単位の把握 |
| 補助 | SQ1 | ソースデータベースの2 eligibility centres内の記述的比較。母集団差と断定しない |

**推奨**：主要解析の中心となる表を、C1/C2/C6/C7の連関に設定する。C4/C5は重要な監査項目として残すが、研究の主要貢献を分散させない。

### 1.4 禁止する解釈 [保持・明文化]

- 項目文面から潜在変数の構造的・構成概念的妥当性を推論しない。
- AIへの言及が尺度項目にないこと**のみ**から、AI使用に関する研究上の推論を不当と断定しない。
- AI利用と疲労の相関を、AIによる疲労の因果効果と扱わない。
- 対象集合の割合をAI疲労研究全体の有病率・問題率・文献全体の頻度として一般化しない。
- C6a / C7(iii) の名称比較結果を、尺度の内容妥当性の評定と同一視しない。

## 2. C1の再設計：測定上の帰属と研究上の推論を分離する（P0）

### 2.1 現行C1を「名義的な帰属位置の分類」として保持 [保持・明確化]

原稿Table 1にある **L1a（items）、L1b（instructions/stem）、L2（single question）、L3（definition）、L4（variable label）、L5（interview theme）、L6（none）** を出発点とする。ただしこれらは一方向に強くなる順序尺度ではない。とくにL2は「質問形式」、L5は「質的な収集形式」であり、L1a・L1bと同じ軸に完全には収まらない。

**低侵襲の選択肢A（推奨、変更コスト低）**：現在のラベルを保持し、研究本文・データ辞書で **非順序の類型（nominal typology）** と明記。L1a–L6を「強い→弱い帰属」のスコアとして集計しない。L2とL5の代表値が他の値と衝突する事例は、事前に優先判定規則を定める。

**選択肢B（大きな改訂）**：`location_of_AI_reference`（項目／教示／概念定義／変数名／質的テーマ／なし）と`measurement_format`（複数項目／単一項目／質的）を分割する。C2aのformatと重複するため、採用時は正規化し、1つの属性を二重に手入力しない。

**事前登録前の決定**：AまたはBを一方に固定。本文で「level」という語を使う場合、階層的な品質序列だと誤解されないよう定義する。

### 2.2 新設する「推論根拠」軸 [追加案]

仮称 `B1: inferential_basis_for_AI_claim`。これはC1の置換ではない。**研究の主要なAI関連主張を支えるデザイン／分析**の記述である。

| 値（例） | ルールの方向性 | 典型的な主張の上限（単独では保証しない） |
|---|---|---|
| B0：AI使用者集団のみの記述 | AI使用条件との対比がない | AIを使用する対象者の疲労の記述 |
| B1：観察的な群間・相関比較 | AI使用量・有無などとの関連分析 | 観察的な関連 |
| B2：時間的順序を伴う観察研究 | 縦断的測定があり、関連する時間順序を記述 | 時間的関連。交絡は残る |
| B3：介入・実験比較 | AI条件の操作と比較条件がある | 研究デザインに応じた因果推論の候補 |
| B4：質的なAI経験の記述 | 参加者による帰属・経験記述 | 主観的経験・意味づけ |
| B5：その他・混合 | 上記を単一値で表せない | 説明欄で明示 |
| BU：情報不足 | 設計情報が足りない | 判定不能 |

**注意**：B2/B3は「因果が証明された」コードではない。非無作為化介入、測定タイミング、対照条件、交絡調整、アウトカムの妥当性などの別問題を残す。混合デザインでは研究全体で1値に決めず、**主要結論ごとに根拠をリンクする**設計も候補となる。

**登録前のミニ検証**：少なくとも4種類の対照事例を用い、C1とB1で分類が独立に変わりうることを確認する。

1. 尺度項目にAIが明示されている、比較条件なしの横断調査。
2. 一般的疲労尺度を用いたAIあり／なしの無作為化比較。
3. AI使用頻度と一般的疲労尺度の観察的相関。
4. AI使用の疲労をインタビューで語る質的研究。

いずれも**架空事例**で事前に検証し、実在するメインセット研究で規則を最適化しない。

## 3. C6/C7を「差異」「矛盾」「推論上の懸念」に分解する（P0）

### 3.1 現行コードの見直し [修正案]

| 現行 | 確認する内容 | 推奨する表記・扱い |
|---|---|---|
| C6a | タイトルの構成概念語 vs 主尺度名 | **名称の相違（descriptive naming difference）**。直ちにエラーと呼ばない |
| C6b | タイトル／抄録の因果語 vs デザイン | **potential causal overreach**。因果語の定義と対象文を登録 |
| C6c | AI-fatigue語 vs C1の帰属 | **attribution-language mismatch flag**。文脈と推論根拠B1を参照した二次評価を提案 |
| C7(i) | 主結論の因果主張 vs デザイン | **potential causal overreach**。結論文を逐語記録 |
| C7(ii) | 主結論のAI疲労語 vs C1の帰属 | **AI-specific construct-claim flag**。C1単独で欠陥を断定しない |
| C7(iii) | 主結論の構成概念語 vs 主尺度名 | **名称の相違**。内容妥当性評価に転用しない |

C7の `met/not met` は、**「過剰主張の条件に該当した」のか「適切な条件を満たした」のかをデータ辞書で一意に定義**する。推奨は表に表示する段階で `flag_present / flag_absent / not_assessable / unresolved` に統一すること。既存コードとの互換性が必要ならクロスウォークを準備する。

### 3.2 強制すべき「証拠連結」フィールド [追加案]

C6/C7各判定について、少なくとも以下を保存する。

- `verbatim_claim`：タイトル／抄録／主要結論の該当箇所の短い引用とページ・節。
- `instrument_reference`：主疲労尺度の出典、バージョン、実施時の教示、参照ページ。
- `design_reference`：研究デザイン／比較群／アウトカム測定の出典位置。
- `decision_rule_id`：適用した登録済みルール番号。
- `assessment`：差異あり／なし、推論懸念あり／なし、評価不能、未解決。
- `rationale`：判定の一行理由。

これにより、評定者と読者が「何を比較しているか」を独立に点検できる。著作権上の配慮から公開する逐語引用は短くし、必要に応じページ・節の参照に限定する。

### 3.3 Table 12の見出し・解釈 [修正案]

現行の **Problem statements** は、性質の異なる指標をひとまとめにしている。表を次の3区分に整理する。

1. **Formal/internal reporting inconsistencies**：N・結果方向・報告値など、報告内に直接矛盾があるもの。
2. **Descriptive naming and attribution flags**：尺度名の相違、AIへの帰属の明示位置など（それだけでは不適切としない）。
3. **Potential inferential overreach**：表題／主要結論の因果主張がデザインでは支持されない可能性など。

カテゴリーごとに `n_flagged / n_evaluable / n_not_evaluable / n_unresolved` を報告する。名称の相違を「方法論上の欠陥の件数」に加算しない。

### 3.4 反例テスト [追加案]

以下が正しく判定できるかを登録前にテストする。

- **RCT + 一般的疲労尺度**：AIが項目にないだけではAI使用の因果効果への言及を不適切と判定しない。
- **AI特化尺度 + 単時点横断研究**：項目にAIがあっても因果主張は自動的に支持されない。
- **タイトルと尺度名が異なるが説明十分**：名称差異は記録しつつ、内容不備や因果逸脱を断定しない。
- **質的インタビュー**：L5であることだけでAI関連経験の報告を不当と判定しない。

## 4. 文献選定とカバレッジ検索を強化する（P0）

### 4.1 現行案の保持点

- 探索的34レコード・主要11研究を **development/calibration set** として扱い、主解析の発見に用いない。
- メインセット、late stratum、coverage stratumを分離する。
- DOI／正規化タイトルによる重複処理、固定シードによる抽出、検索式・日時・処理件数を公開する。
- Free full textのみの制約を明示し、文献母集団の完全網羅を主張しない。

### 4.2 現行案の制約

草稿のcoverage searchは、OpenAlex・Europe PMC・ACM Digital LibraryでAI用語と疲労用語を検索し、探索セット11研究を検索できる語で設計したものである。**この集合の検索成功率は外部再現率の証拠ではない**。また新規文献300件は、検索結果の中からの抽出であり、検索に現れない研究は評価対象にならない。

### 4.3 推奨変更

1. **検索の対象と目的を2つに分ける**：主解析候補を作るsource databaseの探索手順／補完漏れを点検するcoverage search。各々の検索式、フィールド、言語、日付、DB更新日、dedup規則を文書化する。
2. **検索語の過適合を注記**：探索セットから形成した検索語の評価を、独立した検索感度の推定として表示しない。
3. **補助的な独立検索 [可能なら]**：別の担当者が先に確認した探索セットの項目を見ずに検索式を起案し、候補の重なりと追加文献を記述。労力が大きければ未実施と明記する。
4. **除外理由を追跡可能に**：レコードごとの判定段階、判定理由、全文入手不可の状態、Centre A/Bの判断、救済手続きを保存する。
5. **推定対象を限定**：coverage searchの「見落とし件数」は、その特定検索の返した新規レコード内での推計であり、分野全体の欠落研究数ではない。
6. **人数ではなくレコードと研究を区別**：E5リンクによる実質的同一研究の数え直しは主解析と感度分析で整合させる。

### 4.4 300件サンプルの推定に関する補足

Clopper–Pearson区間は二項割合の不確実性を表現できる。ただし、**未判定者が無作為に発生している保証はない**。未判定を「全て対象外」「全て対象」とする極端ケースの範囲は適切な補助情報であるが、単一の無偏推定を保証しない。また抽出が実質的に有限母集団からの非復元抽出なら、その設計と区間推定の対応を補足資料で説明する。

## 5. スクリーニングと評価者独立性（P0–P1）

### 5.1 問題の整理

原稿では第一著者とClaude Opusを独立した二者として用い、相違は第一著者が決定する。探索34件では人間最終判断との一致が高いが、これらは基準調整にも使われたため、新規候補における偽陰性率を直接保証しない。第二著者の事後再スクリーニングは結果を知った後の感度分析であり、盲検の独立審査と区別が必要。

### 5.2 改善案：資源別3段階

**Option 1（最善）**：追加候補の全文採否判断を**独立した2名の人間**が実施。AIは補助的な証拠箇所抽出・チェックに用いる。

**Option 2（実行可能性との両立、推奨）**：原則は現行ワークフローを保持し、結果を読む前に無作為抽出した候補（とくに**除外判定**を十分に含む）を第二著者が独立評価。抽出規則、標本サイズ、層化、判定時点を事前登録。誤除外を中心とする差異と判断変更を報告する。

**Option 3（人的制約が厳しい場合）**：現行体制を維持するが、「二名の独立した人間によるスクリーニングと同等」という表現は避け、結果の一般化範囲をさらに限定する。

### 5.3 AI運用を固定する

`provider/model/version or model identifier`,実行日時、温度等の指定可能な条件、プロンプトのSHA-256と全文、バッチ構成、入力文書・ページ、前処理、応答全文、失敗・再試行規則、判定コミットの順序を保存する。モデルが後日同一出力を保証しないことは明記する。

**推奨評価指標**：段階ごとの一致率、κ（解釈に注意）、AI除外判定から人間側が採択に変更した件数、採択候補の見落とし疑い、判定不能率。34件でのκ = 0.89はあくまで探索・校正材料であり、外部妥当化結果と呼ばない。

## 6. C2b・項目分類の妥当性と再現性（P1）

### 6.1 維持すべき設計

C2bの `FAT, MOT, AVO, FUT, IRR, OTH` と、MOT/AVO/FUTに対する `TASK, AI_USE, AI_VERIFY, AI_PRIV, SOCIAL, OTHER` のtarget分類は、各研究の項目文面が何を問うかを可視化する独自の手段として保持価値がある。**心理尺度の因子構造・診断カテゴリーを推定したものではない**と明示する。

### 6.2 事前登録前に決める事項

- `unit`：項目全文、下位項目、項目＋教示のどこを単位とするか。
- 否定形、二重質問、身体症状と動機低下を併記した項目の優先規則。
- 原文が入手できない場合の`items_unavailable`と、実施版が確認できない場合の`version_not_verifiable`を区別。
- 一項目に主・副分類がある場合の閾値と、表7の感度分析3での数え方。
- 翻訳版の語義差と、同名でも異なる尺度バージョンを一つにまとめない規則。
- 探索セットで見た分類を最終ルールに再投入した後、メインセットでは分類ルールを事後変更しない原則。

### 6.3 校正テスト

架空または探索セット由来の **境界事例リスト** を作成し、各項目に「許容コード」「判断理由」「競合しやすいコード」を記載する。C1・C2b・C6・C7の不一致を優先的に検討。単純一致率80%だけで妥当性が確認されたと書かない。

## 7. C4・C5・C3の扱い（P1）

### 7.1 C4：再計算の対象母数を明確に

現行C4fは、本文と表にある統計量、割合、間接効果等を人間が判断して再計算し、調整済みp値を対象外とする。**何を再計算可能と認定するか**は観察される不一致率に影響する。

次の項目を登録する：`result_id`, `statistic_type`, `inputs_as_reported`, `reported_value`, `recomputed_value`, `tolerance_rule`, `status`, `location`, `exclusion_reason`。丸め誤差・報告の誤記・分析選択差を区別し、**再計算で不一致＝研究結論が誤り**とは断定しない。

### 7.2 C5：サンプル重複の推測と同一性の確定を分ける

著者・地域・調査機関・助成番号・同一Nは重複の兆候であり、**同一サンプルの証明ではない**。リンク根拠と未確認理由を記録し、重複疑いを除外した感度分析では推定対象が変わることを注記する。

### 7.3 C3：AI側変数の分類は主張と結びつける

「利用量／依存・addiction／態度・acceptance／その他／なし」を保持する。AI疲労とAI側変数との関係を論じる際は、C3だけで研究デザインや推論を代用しない。

## 10. 原稿の具体的な修正文案（英文・提案）

以下は**本文に追加・置換するためのドラフト**。共同著者とコードブック仕様を確定してから採用する。

### 10.1 Introduction：研究の限界を含む問い

> TRACE examines how published studies operationalize fatigue in relation to AI, what their fatigue instruments ask, and how titles and main conclusions relate to the measures and inferential designs reported. It is a methodological review of research practices, not a psychometric validation of AI fatigue or an estimate of its prevalence or causal effects.

### 10.2 Method / C1：非順序性を明示

> The C1 categories describe where AI is referenced in relation to the fatigue measure. They are nominal categories, not an ordinal ranking of measurement quality or inferential validity. The presence or absence of AI wording in an item is not, by itself, sufficient to judge whether the study design supports a claim about AI-related fatigue.

### 10.3 Method / C6-C7：フラグの解釈

> We distinguish descriptive differences in construct labels from inconsistencies in reported information and potential inferential overreach. A difference between a title or conclusion term and an instrument name is recorded as a naming difference; it is not treated, on its own, as evidence of invalid measurement or an unsupported causal claim.

### 10.4 Synthesis：件数先行と限定

> For each prespecified flag, we report the number of records flagged, the number evaluable, the number not evaluable, and unresolved cases. Observed/not-observed labels, when used, are secondary summaries of these counts and do not estimate how common a problem is across the literature beyond the sampled record set.

### 10.5 Limitations：AIによるスクリーニング

> Agreement between the AI screener and human decisions on the exploratory records does not establish accuracy on newly identified records, since those records informed the eligibility rules. The AI and first-author screening process is not equivalent to two independent human reviewers, and the adjudicating author also applies the coding rules.

## 11. 想定される反対意見と回答

**Q. 新コードB1を追加すると事前登録がさらに複雑にならないか？**  
A. その通り。既存C1の誤用を防ぐ最小修正は「C1の非順序性の明示」と「C6/C7でC1単独から妥当性判断しないこと」。B1は、研究の中心的な推論問題を実際に評価するなら採用する。時間が不足する場合、B1を採用せずにC6/C7の主張を縮小する方が適切である。

**Q. RCTでも一般的疲労尺度の構成概念妥当性は不明では？**  
A. 不明な場合がある。RCTはAI条件の効果を推定しうるが、測定した疲労がAI特有の構成概念かどうかは別問題。因果効果の妥当性と構成概念妥当性を独立に扱う。

**Q. 名称の差異を欠陥と呼ばなければ、研究の価値が弱まらないか？**  
A. むしろ主張が正確になる。構成概念の名づけと尺度使用の不透明性を記述するだけでも価値があり、因果的な過大主張や統計的不整合は別途より強い問題として判断できる。

**Q. 人間2名の独立スクリーニングが不可能なら研究は無効か？**  
A. 無効ではない。ただし、選択過程の信頼性への疑問は残り、記述研究として主張範囲を限定しなければならない。結果を知る前の無作為な二重評価が現実的な妥協案となる。

## 14. 最終判断と採用すべき最小改訂セット

**最小改訂セット（登録前に必須と推奨）**

1. C1を順序的な品質尺度として扱わないと明記。
2. C6a/C7(iii)の名称差異を不適切な測定の証拠として扱わない。
3. C6c/C7(ii)で「AIという文言が項目にない＝AI関連の主張が不当」という判定を避ける。対応する判定ルールを修正するか、単なる記述フラグへ縮小する。
4. C6b/C7(i)では、主張の因果性を研究デザインや比較の実態に結びつけ、根拠箇所を残す。
5. 主解析での `n_flagged / n_evaluable / n_not_evaluable / n_unresolved` を優先し、名称差異・内部矛盾・潜在的推論逸脱を分けて提示する。
6. Source databaseとcoverage sampleの限界を主結果の解釈へ反映。
7. AIスクリーナーの探索セット上の一致と、未評価候補に対する妥当性を明確に分け、可能なら結果確認前の人間二重評価を追加。

**B1の追加は条件付き推奨**：TRACEが「推論の適切性」を中心的貢献とするならB1を採用する価値が高い。既存のC1〜C7による**報告実践の記述**を中心にするなら、B1を増やさずにC6/C7の解釈を狭める方が、研究を過度に複雑化させず実行可能性も高い。

**結論**：研究自体を作り直す必要はない。測定におけるAIへの言及、研究デザインが支持する推論、論文の主張という3層を混同しないように再設計することが、TRACEの妥当性を最も大きく改善する。
