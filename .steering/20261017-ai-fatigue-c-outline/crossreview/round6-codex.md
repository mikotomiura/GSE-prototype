1. **[高] 既知レコードの除外に「同題名の DOI は最大3個」が適用されていない**  
   `c_search.py:remove_known()` は題名の長さしか確認していません。`merge_records()` が異なる4 DOIの同題名レコードを別々に保っても、既知DBに同題名が1件あれば全件除外されます。登録文の “such a title” とも不一致です。検索結果と既知DBを含めた題名の適格性を判定し、除外にも適用してください。**同題名・4 DOI・既知1件で、別 DOI の記録が残るテスト**が必要です。

2. **[中] OpenAlex の重複数の計算が、各 ID が2回だけ出る前提**  
   `export_openalex()` の `n - sum(len(v) ...)` は「重複したIDの種類数」を引いています。同じIDが3回返ると、全件取得できていても最後に異常終了します。年ごとの一意件数を合計するか、`Counter` の `count - 1` を合計してください。3回重複のテストが不足しています。

3. **[中] ACM の途中ページで件数変化を検知しない**  
   `acm_export.js` は各パスの先頭だけ `first.count` を検査し、後続ページの `p.count` を無視しています。「reported count changes で停止」という仕様を満たしません。検索集合が途中で変化すると、異なる時点の和集合を正常な結果として受理する可能性があります。全ページで比較し、途中ページだけ件数が変わるテストを追加してください。なお、件数一致だけでは集合の同一性までは保証できません。

4. **[中] 抄録取得の通信失敗が、恒久的な「抄録なし」になる**  
   `make_coverage_records.py` の取得関数はすべての例外を空文字にします。`cmd_long()` は両サービスの一時障害でも元の抄録を消し、出典も空にするため、再実行時の処理対象から外れます。「存在しない」と「取得失敗」を区別し、失敗時は再試行可能な状態を保存してください。429・タイムアウトのテストが必要です。

5. **[中・設計上の懸念] 1,000語という長さだけで本文と断定している**  
   長い正規の抄録を除去し、短い本文混入を通す可能性があります。実際の誤分類は未確認です。閾値は要確認フラグとして扱い、除去判断の根拠を記録する方が、選別材料の欠落を防げます。
