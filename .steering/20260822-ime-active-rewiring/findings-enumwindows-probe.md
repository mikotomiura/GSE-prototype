# 実測記録 — EnumWindows 経路は候補ウィンドウを検出しない (2026-08-22)

⚠️★★★ **これは handoff §2.1 の gate に対する答えである。結論: B は成立しない。**

## 1. 何を測ったか

`examples/ime_winevent_probe.rs` を拡張し、**本番の検出関数そのもの**
(`input::ime::is_ime_candidate_window_visible` = `lib.rs` の IME Monitor が
`is_candidate_window_open()` 経由で毎周期呼ぶもの) を叩いた。

⚠️★ **プローブ側にロジックを複製していない。** 複製を測ると「複製の方が動いた」という
無意味な計測になり、本番経路の可否を答えられないため。
→ `is_ime_candidate_window_visible` を `pub` へ上げた (★ **可視性のみ**。中身は 1 行も変えていない)。

計測は 60 秒 × 2 回。⚠️ 2 回目は**変換候補リストを意図的に開く**手順
(Space → もう一度 Space → 2-3 秒開いたまま → ←→ で文節移動 → Enter、5-6 回) で実施。

## 3. ⚠️★★★ なぜ検出しないのか — 2 つの診断で切り分けた

### 3.1 ⚠️ 先に自分の誤りを訂正する

1 回目の解釈で「`CREATE 583 = DESTROY 583` なので **583 個の窓**が出入りしている」と読んだ。
⚠️★ **これは誤りだった。** 2 回目で `OBJID_WINDOW` (idObject==0 && idChild==0) に絞ったところ、
**窓レベルのライフサイクルは 25 件しかなかった** (CREATE 5 / SHOW 20 / HIDE 0)。

→ ★ **残り 567 件の CREATE は窓ではなく「子オブジェクト」である。**
⚠️ 窓の数と読んだのが間違いで、この誤読のまま結論を出していたら根拠が崩れていた。

### 3.2 診断A — 可視トップレベル窓のクラス (全件・絞り込み撤廃)

| 出現 | クラス |
|---|---|
| 600/600 | `CEF-OSC-WIDGET` / `CabinetWClass` / `EdgeUiInputTopWndClass` / `Internet Explorer_Hidden` / `Notepad` / `Progman` / `Shell_TrayWnd` / `Windows.UI.Core.CoreWindow` |
| 1200/600 | `ApplicationFrameWindow` / `ThumbnailDeviceHelperWnd` |

| 4800/600 | `Chrome_WidgetWin_1` |

⚠️★★★ **一過性のクラスが 1 件も無い。** 最少でも `600/600` = **常時可視**。
→ ★ **変換中だけ現れるトップレベル窓は存在しなかった。**

⚠️ 1 回目のセンサスは `looks_ime_like` で**絞ってから**数えていたため、
候補ウィンドウのクラス名がその語に当たらなければ構造的に見えなかった。
★ 2 回目は絞り込みを撤廃したので、この盲点は潰れている。

### 3.3 ⚠️★★★ 診断B — 窓レベル CREATE/SHOW/HIDE (★ 取りこぼし無し)

## 4. ★ 結論

### 4.1 ⚠️★★★ B は成立しない (handoff §2.1 の gate に従う)

★ 100ms 本番相当の立ち上がりが **0** である。handoff §2.1 の表のとおり:

> ⚠️ 検出しない → ⚠️★★★ **B は成立しない。** ★ `IME_ACTIVE` は「取れない」と結論し、
> `config_gated` のまま据え置く

→ ★ **`lib.rs` の配線 (§2.2) は実施しない。**

### 4.2 ⚠️★★★ なぜ取れないのか — **原因は 2 説あり、実測では割れない**

> ⚠️ **2026-08-22 訂正 (code-review HIGH)。** ★ 初稿は
> 「候補 UI はトップレベル窓として可視化されない**ため構造的に**捕まえられない」と書いた。
> ⚠️ **これは実測が支持する以上の断定だった。** ★ 対立仮説が残っている。

| 説 | ★ 根拠 | ⚠️ 弱点 |
|---|---|---|
| **A. 候補 UI はトップレベル窓に無い** | ★ 診断A に一過性の窓が **1 件も無い** / 診断B の窓レベル `HIDE` が **0 件** / `_IMEBROKER_HIDDEN_CLASS` は名前どおり **HIDDEN** | ⚠️ 窓レベル `SHOW` が **20 件**飛んでいることを説明しにくい |
| **B. 常駐トップレベル窓を DWM が cloak/uncloak している** | ★ `Windows.UI.Core.CoreWindow` が **600/600 で常時可視** ＋ 窓レベル `SHOW` **20** / `HIDE` **0** ＋ `CLOAKED` 76 / `UNCLOAKED` 80。⚠️★★★ **`IsWindowVisible` は cloaked な窓に TRUE を返す** | ⚠️ cloak と変換の対応を確認していない |

### 4.2.1 ★★★ **結論はどちらの説でも変わらない** (★ ここが要点)

| 説 | ⚠️ `EnumWindows` が使えない理由 |
|---|---|
| **A** | ★ `EnumWindows` は**トップレベル窓しか列挙しない**ので、**見えない** |
| **B** | ⚠️★★★ **常時可視なので可視性が信号を運ばない。** ★ そのクラス名を網に入れると **常時 `true`** になり、⚠️ `ime_windows.rs` の回帰テスト `excludes_language_bar_and_imm32_system_window` が固定した **「分析が永久停止する」事故を再発させる** |

→ ★★★ **どちらにせよ `IsWindowVisible` ＋ クラス名では「変換中」と「非変換中」を分離できない。**
★ したがって **B 不成立という結論は、説 A / B の決着を待たずに確定する。**

⚠️ **決着させたい場合**: `CLOAKED`/`UNCLOAKED` を窓レベル (`OBJID_WINDOW`) に絞って
クラス名付きで数え直せば 60 秒で分かる (★ プローブは既に `HIST` で総数を持っている)。
⚠️ **ただし結論が変わらないので、本タスクでは実施しない。**

## 8. ⚠️★★★ 自己訂正 — **UIA 経路を測っていなかった**

★ 本番が実際に使う述語は `is_candidate_window_open()` = **WinEvent `||` EnumWindows `||` UIAutomation** の OR である
(`ime_windows.rs:61-110`)。⚠️ **私が測ったのは `is_ime_candidate_window_visible()` (EnumWindows 経路) だけ**だった。

| 経路 | 状態 |
|---|---|
| WinEvent `EVENT_OBJECT_IME_*` | ✅ **0 件と確定** (60 秒 × 5 回) |
| EnumWindows | ✅ **0 件と確定** (0/2400・立ち上がり 0) |
| ⚠️★★★ **UIAutomation** (`GetFocusedElement` の `Candidate` / `候補`) | ⚠️ **未測定** |

⚠️ `ime_windows.rs:58-60` の逐語コメントは
「Limited: only fires when the focused element is the IME window itself,
which doesn't happen during normal composition」と**予想**を書いているが、
★ **これは実測ではない。**

→ ★ **プローブに本番の完全な述語 `is_candidate_window_open()` を追加した** (2026-08-22)。

### 8.1 ★★★ 実測結果 — **UIA の寄与は 0。B 不成立が確定した**

★ 本番の完全な述語 is_candidate_window_open()  検出=0/2400 (  0.0%) 立ち上がり=0

### 8.2 ⚠️ 3 回目で初めて出た「一過性のトップレベル窓」（★ 結論は変わらない）

⚠️ 1・2 回目は一過性クラスが **1 件も無かった**が、3 回目は出た:

| 診断A | `Xaml_WindowedPopupClass` **5/600** |
|---|---|
| 診断B | `CREATE`/`SHOW` `Xaml_WindowedPopupClass` 各 1、`SHOW`/`HIDE` `XamlExplorerHostIslandWindow` 各 1 |

→ ★ **仮説 A（候補 UI はトップレベル窓として現れない）は弱まった** —— 一過性の窓は**現れうる**。

⚠️★★★ **それでも結論は変わらない。理由は 2 つ、いずれも実測。**

1. ⚠️ **滞在が短すぎる。** 5/600 ポーリング ≒ **合計 500 ms**。
   ★ 被験者は「候補一覧を 2〜3 秒開いたまま × 5〜6 回」（＝ 100〜180 ポーリング相当）を行っている。
   → ⚠️ **候補ウィンドウの滞在を表していない。**
2. ⚠️★★★ **クラス名が IME 固有でない。** `Xaml_WindowedPopupClass` は
   **ツールチップ・コンテキストメニュー・フライアウトなど、あらゆる XAML ポップアップ**が使う。
   → ★ 網に入れれば **IME と無関係な UI で `true` になる**。
