## Goal

未マージブランチ `feat/resumption-outcome-arbitration` から**アウトカム系**を main へ取り込む。
ADR-023（主要アウトカムを「出口への結合」へ移す）と ADR-024（推定器を出口から外す）、
およびその実装（`metrics.rs` +909 行ほか）と実験記録を 1 PR で入れる。

## Background

- ⚠️★★★ **ブランチを `git checkout` / `git switch` で切り替えない。** main で作業し、
  `git checkout <branch> -- <path>` でファイル単位に取り出すか `git show <branch>:<path>` で読む。
- ADR-023 と ADR-024 は**一体**。ADR-024 は ADR-023 の D6 / D7-2 / §Migration M2・M3 を
  明示的に上書きして完了扱いにしている。片方だけ入れると ADR-023 の Migration が未完のまま残る。
- ADR-024 は「本 ADR はコード変更を伴う」と明記しており、`metrics.rs` の +909 行がその成果物。
- ⚠️ **`HMM_VERSION` bump は不要**。ADR-024 は意図的に回避している
  （`engine.rs` / `schema_dto.rs` / `schema/current.json` に差分なしを実測確認済み）。
  ADR-023 が検討した A3-(i) 案（回復判定を `p_stuck` 低下へ置換）なら bump が必要だったが、
  ADR-024 は A3-(ii) 相当を採った。
- ⚠️★★★ **`scripts/build_analysis_db.py` を同時に変更すること。** `metrics.rs` の識別子改名
  （`recovery` → `pflow_exit`）は **schema drift check の対象外**であり、
  `build_analysis_db.py` を追随させないと**無音で壊れる**。ブランチ側に +75 行の変更が既にある。
- `recovery` → `pflow_exit` は単なる改名ではなく**格下げ＋バイアス開示**。
  受領を見る窓の右端が `p_flow` の立ち上がり速度そのもので決まり、速いほど指標が機械的に
  押し上げられる（テストで 0.0→1.0 の反転を再現）という発見に基づく。旧指標は削除せず副次に残す。
