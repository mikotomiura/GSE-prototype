# 設計 — O1 のフォーム類 ＋ 配布物の o1.mode

## 1. C-4 フォーム類 — `Form_G1/GSE_O1_Form_Builder.gs`

### 1-1. ⚠️★★★ **G1 の隣に立たない**

★ 2026-08-07 の事故: Apps Script の関数セレクタの選択が反映されないまま `setupG1Forms` が走り、
`buildConsentForm()` の `clearForm()` が **G1-C の全設問を削除**した (回答 3 件は残ったが
どの設問への答えか失われた・⚠️ Forms に版履歴は無い)。

→ ★ **3 段で防ぐ**。どれか 1 つではなく 3 つとも置く。

| 段 | 何をするか |
|---|---|
| 1 | **別プロジェクトに貼る**。⚠️ `setupG1Forms` / `buildConsentForm` と**同じ名前空間に置かない** |
| 2 | ★ **G1 のフォーム ID を拒否する** (`o1AssertNotG1Form_`)。⚠️ 貼り間違いを機械で止める |
| 3 | ★ **回答があるフォームは作り直さない** (`o1AssertSafeToRebuild_`・既定 fail-closed) |

⚠️ 段 2 が本ファイル固有の眼目である。G1 の 3 本の ID をハードコードした**拒否リスト**を持ち、
`FORM_ID_O1_*` にそれが入っていたら `openFixed_` の前に throw する。
★ これは秘密ではない (フォーム ID は URL に出る) ので `.gs` に書いてよい。

### 1-2. フォーム 2 本

| キー | 役割 | 備考 |
|---|---|---|
| `O1_CONSENT` | ★ **参加登録＝説明・同意** | ⚠️★★ **これが同意の正本**。文面の元は `consent-draft-o1.md` |
| `O1_SURVEY` | 終了後アンケート | ★ 受容性・負担 ＋ 宣言 UI の使い勝手 (研究者判断 2) |

★ G1 と同じ「登録フォームを別に作らない」方針を踏襲する
(G1 は 2026-08-03 に別立ての参加登録フォームを**重複として廃止**している)。

### 1-3. P-ID

★ **Phase1 のロスターただ 1 つ**から採番する (`PHASE1_MGMT_SHEET_ID` は G1 と同じ値)。
⚠️ 2 か所で採番すると相手の最大値が見えないので**必ず衝突する**。
★ 既存参加者 (メール一致 / P-ID 記入) は**再発番しない** (冪等)。

### 1-4. 受付メール

`onO1ConsentSubmit` (フォーム提出トリガ) → ロック取得 → 採番 → 受付メール。
⚠️ ★ **G1 の受付メールを流用しない**。O1 は「70 分 1 回」ではなく「数日〜数週間の常時記録」なので、
本文は (a) 参加者 ID、(b) アプリの入手、(c) ★ **自動起動の登録**、(d) ★ **いつでも止められる・消せる**
の 4 点を書く。⚠️ 課題ページの話は 1 文字も入れない (O1 に課題は無い)。

### 1-5. ⚠️ 秘密を置かない

`FOLDER_ID` / `SHARED_SECRET` は**この .gs に持たない** (受け口 `GSE_O1_Submit.gs` の担当)。
★ 本ファイルが持つのは公開情報 (フォーム ID・シート ID・連絡先) だけ。

## 2. C-5 配布物 — `make-common-app-zip.sh --mode g1|o1`

### 2-1. ★ 既存の G1 経路を 1 バイトも変えない

⚠️ 既定は `--mode g1`。★ 引数を付けない呼び出しは**今までと同じ物を作る**
(`G1_実施用_*` / `g1.mode` / G1 の README / `launch-g1-windows.bat`)。

### 2-2. モードで変わるもの

| 何 | g1 | o1 |
|---|---|---|
| フォルダ / zip 名 | `G1_実施用_*` | `O1_実施用_*` |
| マーカー | `g1.mode` | ★ `o1.mode` |
| README | `dist-readme-macos.txt` | ★ `dist-readme-macos-o1.txt` |
| Windows README | (無し) | ★ `dist-readme-windows-o1.txt` (⚠️ 自動起動の手順が要る) |
| Windows launcher | `launch-g1-windows.bat` | ★ `launch-o1-windows.bat` |
| 課題ページ検査 | あり | ★ あり (O1 にも入ってはならない) |

⚠️★★★ **`g1-submit.json` はファイル名を変えない。** 中身 (endpoint / secret) で行き先が決まる
(`GSE_O1_Submit.gs` の配備手順 6 と同じ規約)。★ 名前を変えると端末側が読めなくなる。

### 2-3. README の機械検査

★ 現行スクリプトは G1 の README を 4 語で検査している
(「研究者と一緒に」「壊れていません」「ゴミ箱に入れないで」「ターミナルの窓へドラッグ」)。
⚠️ O1 でも **macOS の Gatekeeper 経路は同じ**なのでこの 4 語はそのまま要る。
★ そのうえで O1 固有の語を**足す**:「いつでも止められます」「自動的に起動」。

⚠️★★ **被験者向け文面は研究者の承認が要る。** → ★ README の 1 行目に
`【ドラフト・未承認】` を入れ、⚠️ **承認前に配れないことを機械でも保てる**ようにする
(`--mode o1` は draft マーカがあると警告を出すが止めない —— 止めると検算ができなくなるため)。

### 2-4. ⚠️ 本機では実行できない

`ditto` / `hdiutil` / `codesign` は macOS 専用。★ Windows でできるのは
`bash -n` (構文) と **モード分岐の単体検査** (`--selftest`) までである。⚠️ 実行したと書かない。

## 4. sync-session の O1 ガード

⚠️★★★ 通すと `metrics/` は gse-dataset に **追跡・push される** (2026-08-28 に 34 件を実測) ので、
削除要求が来たときに **git 履歴の書き換え**が要る = 台帳 §4 の運用規則が破れる。

★ 実装: 入力 NDJSON の**ファイル名**が `gse_o1_` で始まるなら **exit 4 で止める**。
⚠️ 名前だけでは足りない (改名される) ので、**`meta` 行の `o1_mode`** も見る
(`reconcile.rs` が O1 判定に使っているのと同じ第 1 の根拠)。★ どちらか一方でも当たれば弾く。

⚠️ 新しい exit code 4 を足す (既存の 0/1/2/3 と衝突させない)。

★ テスト: `scripts/sync_session_o1_guard_test.sh` —— 一時ファイルを作って
**弾くこと**と**通常セッションは弾かないこと** (陽性対照) の両方を実測する。
