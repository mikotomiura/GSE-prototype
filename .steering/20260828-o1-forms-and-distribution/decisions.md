# 設計判断 — O1 のフォーム類 ＋ 配布物

## 研究者判断（2026-08-28・本セッションで確定）

### 判断 1: 毎日の起動は「自動起動の手順を README に載せる」

★ O1 は常時記録なので、**アプリが起動していない日は記録がまるごと空**になる。
選択肢は (a) README に自動起動手順 (b) 案内しない (c) 研究者が必ず一緒に登録、の 3 つ。
→ ★ **(a) を採用**。⚠️ ただし README には「難しければそのままで構いません。研究者が一緒に設定します」
と書き、(c) を**逃げ道として残す**（★ Windows の被験者に対面回を必須化しない）。

- mac: システム設定 → 一般 → ログイン項目 → ＋ で **このフォルダの中の** `gse-next.app`
- Win: `shell:startup` へ `GSE_起動.bat` の **ショートカット**（⚠️ コピーではない）

⚠️★★ どちらも「**このフォルダの中のものを指す**」ことを強調している。
★ `o1.mode` マーカーはフォルダ同居で効くので、コピーすると研究モードにならない。

### 判断 2: 終了後アンケートは「受容性・負担」＋「宣言 UI の使い勝手」の 2 本

⚠️ 「記録の正確さの自己申告」（誤警告を見た回数など）は**入れない**と決めた。
★ そちらは客観側（`hook_health` / `starved_ms`）で測るべきもので、
自己申告を混ぜると「主観が客観の代わりに使われる」経路ができる。

### 判断 3: 保管上限

| 項目 | 値 |
|---|---|
| `.age`（暗号化） | **受領から 2 年** |
| 復号済み平文 NDJSON | **解析完了後 30 日以内** |
| 集計 `metrics.json` | **論文発表から 5 年** |

★ 根拠: 最も危険な形（平文＝時間の並びがそのまま読める）を最短にし、
暗号化されたものは再解析に耐える長さを残す。⚠️ ADR-012 D12-b の 7 日 / 30 日は
**録画（映像）の数値であって打鍵の数値ではない**（★ 台帳 §5 に併記して混同を防いだ）。

### 判断 G: ★ マーカーの書き出しを「変数にまとめず literal で 2 行」書く

⚠️ `scripts/check-o1-release-readiness.sh` は「`o1.mode` を**書き出す文**があるか」を grep で見る。

### 判断 H: ★ O1 の launcher は「殺さない・pause しない・読み上げない」

⚠️ G1 の launcher は「1 ブロック 1 回」の前提で **旧プロセスを確実に taskkill** している。
★ O1 でこれを流用すると、**スタートアップから毎朝起動されるたびに記録中のアプリを叩き落とす**。
→ ★ 既に動いていれば**何もせず exit 0**（二重起動も同時に防げる）。
⚠️ `pause` も外した（★ 毎朝黒い窓が残る）。ただし**中断時だけ** pause する。

### 判断 I: ★ プローブは O1 で構造的に発火しない（★ 確認した）

⚠️ 同意文書は「その推定値をもとにした助言・介入は**一切出しません**」と約束している。
★ `lib.rs` のプローブスケジューラは `GSE_DISABLE_PROBES` と **g1_mode** でしか止まらず、
**O1 マーカーでは止まらない**。→ ⚠️ 危ないのでは？と疑って一次資料を読んだ。

★ **結論: 発火しない。** 根拠:
- プローブのスレッドは `SESSION_START_MS != 0` を要求する（`lib.rs`）
- `SESSION_START_MS.store(now)` は `start_session` の中だけ
- ⚠️ O1 は `start_session` も `record_session_meta` も**呼ばない**（`App.tsx`）。
  さらに `record_session_meta` は O1 で**拒否される**（`lib.rs`: "O1: record_session_meta rejected"）

→ ★ 構造的に成立しているので**実装は変えない**。⚠️ ただし将来 O1 で `session_start` を立てる
変更が入ると**黙って約束が破れる**ので、launcher に `GSE_DISABLE_PROBES=1` を
**2 本目の引き金として**置き、理由をコメントに残した。
