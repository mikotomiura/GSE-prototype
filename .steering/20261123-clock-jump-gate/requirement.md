# 起動直後の時計の飛びで記録を始めない（clock-jump-gate）

## 背景

2026-11-22 17:20 JST にこの Mac が起動した直後、NTP で合う前の数分、時計が 1976-03-31 15:00 UTC ごろになっていた。
O1（段 1）の GSE がその時刻で記録を 2 本開き（`gse_o1_19760331_150024` / `_150114`）、無作為の枠の起点も 1976 年になった。
時計が合った最初の 1 秒で、調停器（`analysis/probe_arbiter.rs` の `while self.frame.next_candidate_ms() <= now`）が 50 年分の候補を 1 つずつ判定し、
1,907,310 行の `probe_suppressed`（全部 `random`・`away`・行の `t` は同じ時刻）を書いた（208 MB）。

- 行種と時刻だけで数えた。時計は 1976-03-31T15:02 → 2026-11-21T15:02（約 17 時間遅れ）→ 2026-11-22T08:22（正）と 2 回前へ飛んだ。後ろへの飛びは無かった。
- 発火は 0 件（ラベルは汚れていない）。害はファイルの大きさと、机上の道具（`desk.rs`・`s1_replay.rs`）が範囲外の時刻で止まること（fail-closed・`MIN_EPOCH_MS` 2020-01-01）。
- 3 本目 `gse_o1_20261122_082337` は日次ローテート（起点 1976 年と今の差が 24 時間を超えた）で始まった。
- VS Code のログのフォルダ名（`19760401T000025`）も同じ時刻で、時計はシステム全体でずれていた。

引き継ぎ: `.steering/_handoff/next-session-gse-clock-jump-probe-catchup.md`（main のチェックアウト・未追跡）。

## ゴール

O1 のとき、起動時の時計がO1 の時計の範囲（2020-01-01〜2040-01-01・孤児回収と同じ定数）の外なら、記録のファイルを開かず、段 1 の枠も作らず、時計が範囲に入ってから始める。

## スコープ

### 含むもの
- `run()` の入口（記録のファイル名を決める前）で、O1 のときだけ時計を待つ。
- 待ちの判定と待ちの回し方を純粋な関数にしてテストする。

### 含まないもの
- 記録の途中の大きな飛び（何日も前へ・1970 年へ戻る）で枠を作り直すこと（研究者が今回は入れないと選んだ）。
- 調停器の追いかけ（スリープ後の候補を離席で抑える作り）は変えない。
- 既にできた 2 本の記録の扱い（研究者が決める）。消さない。
- 版を上げる・配布する（別の PR。研究者に確かめる）。
- G1・通常の運用（「開始する」を押して始めるので起動直後の時計に当たりにくい）。

## 受け入れ条件

- [ ] 時計が範囲の外の間は待ち、範囲に入ったら抜ける（テスト）。
- [ ] 範囲の内なら 1 回も待たない（テスト）。
- [ ] 範囲は既存の `o1::MIN_PLAUSIBLE_EPOCH_MS`〜`MAX_PLAUSIBLE_EPOCH_MS`（2020〜2040・孤児回収と同じ）を使う。机上の道具の 2020〜2100 より狭いので、待ちを抜けた時刻は机上の道具も通る。
- [ ] O1 でないときは待たない。
- [ ] `cargo test`・`cargo clippy`・replay の回帰が緑。
