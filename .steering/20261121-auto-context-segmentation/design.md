# 設計（v2・要件だけから作り直した案）

## 実装アプローチ

考え方は 3 つある。

1. Rust は「1 秒ごとの生の数」だけを出す。窓の長さはすべて解析側の引数にする。
2. 境界を先に探さない。短い固定の窓をまとめてから、時間方向に平滑化する。境界は「名前が変わったところ」として後から出てくる。
3. まとまりが偶然でないことを、宣言との照合とは別に、本人の中での再現性でも確かめる。

### 層 1: `--features` に tick ごとの文脈の数を足す（Rust）

- 特徴行に `context` を足す。中身はその 1 秒の tick の中の数だけにし、窓で集約しない。
  - `focus_transitions`（`focus_transition` 行の数）
  - `pointer_active`（その秒に `pointer_bin` 行があるか）
  - `pointer_moved`（`moved` バケット）
  - `key_presses`
  - `cat_counts`（tick 内の全 press の `KeyCategory` ごとの数）
  - `ime_on`（その秒に IME がオンだったか。入力から作れなければ null）
- 窓・時間尺度の引数を Rust に持ち込まない。そのため、封筒の config も事前登録（p1-episode）も動かない。窓の長さを変えても Rust のテストやゴールデンに波及しないので、事前に決めた複数の窓で感度を見るのも解析側だけで済む。
- 欠測は 3 状態で分ける。宣言が無い → null。宣言があって行が無い → 0。config_gated で行が無い → null。理由語は既存の `missing_reasons` に載せる。
- 推論の経路（HMM・`FeatSnapshot`・`features.rs`）には流さない。ログの形（`schema_dto.rs`・`logger.rs`）は変えない。

### 層 2: 窓のまとめ → 平滑化 → 区間と名前（Python・`experiments/20261121-auto-context-segmentation/`）

1. **窓**: 1 秒の数を、重ならない長さ `W`（既定 60 秒）の窓に集める。窓ごとに文脈ベクトルを作る。
   - フォーカス遷移の率
   - ポインタの活動の割合
   - 打鍵の率
   - ポインタと打鍵の比
   - IME オンの割合
   - キーの種類の構成比（合計が 1 になる比なので、加法対数比で変換する）
   - 打鍵もポインタも無い窓は「無操作」として取り分け、まとめに入れない。
2. **まとめ**: 人ごとに、文脈ベクトルを標準化してまとめる。
   - k = 1..6 の混合ガウスを BIC で選ぶ。k = 1 を許す。
   - まとめる前に、各窓の「量」（打鍵の率・ポインタの活動の割合）と「構成」（比の列）を別の軸として残す。打鍵の多さだけで割れたまとまりかどうかを後で見分けるため。
3. **平滑化**: 窓の名前の列に、最小の滞在長 `L_min`（既定 3 窓）を課す。これより短い名前の連続は前後に吸収する。吸収の規則は、前後が同じ名前ならそれに、違えば事後確率の高い方にする。
4. **区間と名前**: 平滑化の後に名前が変わった点と、無操作の窓の始まりを境界にする。無操作が `G_idle`（既定 300 秒）以上続いたところは強制の境界とし、平滑化で吸収しない（v1 から取り込んだ規則）。平滑化で消えた短い行き来の数と合計時間は、人ごとに notes に出す。名前は合計時間の多い順に `task-A`, `task-B`, … とする。宣言の名前には写し替えない。
5. **判定**: `criteria.json` は実データを処理するより前のコミットに入れる。
   - (a) 合成: `gen_synth.py`（seed 固定）で NDJSON を作る。2〜4 種類の文脈（打鍵中心・ポインタ中心・頻繁なフォーカス遷移・IME 多用）を、既知の時刻で切り替える。
     - 陽性: 境界の F1（±W）と、真の文脈との ARI が閾値以上。
     - 陰性: 1 種類だけの文脈で k = 1 か、境界の数が閾値以下。
     - 壊した入力: 境界を消した合成で終了コードが非 0 になる。
   - (b) 本人の中での再現性（追加）: 人ごとに記録を時間の前半と後半に分け、前半で学んだまとめを後半に当てはめる。後半だけで学んだまとめとの ARI を出す。偶然のまとまりはここで落ちる。宣言が無い人でも数えられるので、判定できない人を減らせる。
   - (c) 宣言・`activity_label` との照合:
     - 宣言の切り替えの再現率。
     - 宣言の区間とまとまりの NMI。
     - 帰無分布は、宣言の列を巡回させてずらしたもの。
     - O1 は宣言の切り替えでファイルが分かれるので、人ごとにファイルをまたいでまとめる。
   - (d) 循環の検査: まとまりと推定状態（HMM の最尤状態）の NMI を出す。(c) の NMI 以上なら「状態を写しただけ」とする。加えて、量の軸だけで同じまとまりがほぼ再現できるなら「打鍵の多さで割れただけ」とする（ARI を閾値で判定）。
   - (e) 本人の振り返り: 段 1 の本人の区間の一覧（時刻・長さ・名前・文脈の要約）を研究者が見て、区間ごとに合う／合わない／覚えていないを付ける。
   - 結論は人ごとに「使える／使えない／判定できない」とし、そのうえで全体を書く。どの段の基準で落ちたかも残す。
6. **識別子の見積もり**: 結果の後で、フォーカス遷移が多いのにまとまりが割れなかった区間、つまり識別子があれば分けられたかもしれない区間の割合を出し、decisions.md に書く。

## 既存パターンとの整合性

- tick ごとに値を出す形は、既存の Tier（`activity` など）の tick 単位の出し方と同じ。窓で集約する Tier（`dispersion` の因果窓）の形は採らない。
- 欠測の 3 状態と収集関数の形は、極 B のポインタ（issue 006）に乗る。
- 既存の `--segment` は残す。
- ADR-010 D3・ADR-012 D3（観測から種別を作らない・融合しない）・ADR-014 D4b（推論に流さない）に従う。

  - `context_switch.ndjson` による統合テスト。
  - `cargo test --workspace` が緑。
  - `--snapshot` が minimal と byte-equal。
  - `check_no_feature_output.sh --self-test` が緑。
- Python:
  - `evaluate.py --synthetic` の陽性・陰性・壊した入力の 3 本を、終了コードで確かめる。
  - 平滑化の単体テスト（短い連続の吸収規則）。
- 外部送信: diff だけを `/cross-review` に回す。

## 設計判断の履歴
- 実行回数: 1 回目
- 採用: ハイブリッド（v2 に v1 の「無操作が続いたら必ず切る」を足したもの）
- 根拠: 研究者が推奨案を選んだ（2026-11-21）。事前に決める値が減ること、窓の長さを変えても Rust と事前登録に響かないこと、宣言が無くても本人の中での再現性で判定できることによる。

## 実装で変わったこと（2026-11-21・詳細は decisions.md）

- 窓は 60 秒から 180 秒に、最小の滞在長は 3 窓から 2 窓に、分散の床は 1e-3 から 0.3 にした（判断 10・11・合成の陰性で割れたため）。区間の最短は約 6 分。
- 陽性の基準に「平滑化の後に 2 種類以上」を足した（判断 12）。
- 判定は「どれかが落ちたら使えない／落ちたものが無く測れないものがあれば判定できない／全部通れば使える」の形にした（判断 13）。宣言との照合は平滑化の前のまとまりで行う。
- 宣言の区切りが少ない人は判定できないにし、打鍵の量の検査は量以外の軸でも確かめる形にした（判断 14）。
- 宣言との照合の帰無分布は、巡回でずらす方式から、宣言のブロックに付いた値を入れ替える方式に変えた（判断 15）。
- 封筒は窓に集めたら消す。ファイルは時刻の順に並べ、匿名化で相対時刻になった O1 のファイルは記録の時刻の順に 1 時間空けて置き直す（判断 17・18）。
- 宣言の切り替えの再現率は計算しない（O1 では継ぎ目と重なり、構造的に測れない・判断 13）。
- 研究者本人の振り返り用に、`--abs-segments-for` で絶対時刻つきの区間の一覧を `work/` に出せるようにした（コミットしない・判断 19）。
