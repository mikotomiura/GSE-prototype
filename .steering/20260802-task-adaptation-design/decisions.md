# 設計判断の記録

## 判断 0: ADR-006 は**拡張**する（改訂しない）→ ADR-010 を新規に起票

- **理由**: ADR-006 が決めたのは head の**選択**であり、本ラウンドが足すのは
  「選ばれた head が**当てはまっていない**場合の経路」で、選択規則そのものは変えない。
  `personalization-and-online-learning.md §9` に「ADR-006 との関係（拡張であって改訂ではない）」という
  同型の先例がある（ADR-008 の場合）。
- ADR-006 への追記は**関連/拡張欄の 1 ブロックのみ**。Decision 本文・下位決定 #2/#3 は無改変。

## 判断 1: out-of-scope は **head ではなくフラグ**（`scope_fit`）

- **却下した案**: `NullHead` / `UnknownHead` を head の 1 つとして追加。
- **理由（4 つ）**:
  1. routing は「どのモデルが適用対象か」、scope は「**この証拠にモデルが適用できるか**」で問いが違う。
     後者は証拠の性質であり `evidence_quality` が定義上そのための欄である。
  2. head にすると**切替判断に確信が要る**。検出器は本質的に低確信（外的正解ラベル 1 件）。
  3. hard switch は走っていた head の推定を捨てる。フラグなら**連続的に縮退**できる。
  4. ★ `§11-11` の最大の長所（**新しいゲート機構が要らない**）を保存できる。
- **代償**: `scope_fit` が「なんでも下げる弁」に育つ危険。→ §3.5 の allow-list ＋ 禁止リストで縛った。

## 判断 2: scope は **head 相対**（絶対的な「対象外作業」を定義しない）

- content-free では「何をしていたか」は原理的に分からない以上、絶対的な定義は書けない。
- ★ **副産物**: 宣言が誤っていた場合（`argumentative` 宣言で実際は coding）、
  Writing head の `scope_fit` が下がって強介入が止まる。
  **§11-11 の穴の本体（誤った head で黙って処理される）が、ルーティングを直さずに塞がる。**
- 帰結として **特徴集合と定数は head 所有**（機構だけ共有）。ADR-006 の「β は head 所有」と同じ所有規則。

## 判断 3: 宣言と観測が食い違っても **re-route しない**

- **却下した案**: 観測署名で `task_kind` を推定し head を切り替える。
- **理由**:
  1. ② は分散ゼロで教師に使えず、③ は「何をしていたか」を言えない。**互いの役割を果たせない。**
  2. ★ **閉ループ**——head を切り替えると参照 baseline が変わり、それが次の判定の入力になる。
     外的正解ラベルが無い状態でこのループを本番に載せない。
  3. **失敗コストが非対称**: 割引の最悪＝介入が減る／re-route の最悪＝別 baseline で**自信を持って誤採点**。
- 将来の自動 re-route には**昇格ゲート 3 条件**を先に書いた（設計本体 §3.3）。

## 判断 4: 時間解像度 — 推定は streaming 窓、読み出しは Decision Episode

- セッション単位は事後にしか出ないので介入に使えない（これまでの実験がセッション単位だったのは
  **オフライン解析だったから**であり、本番の解像度ではない）。
- 単一 episode は率の推定に短すぎる → **推定は遅く・読み出しは速く**の分離。
  `§4.4` Phase A の EWMA / robust quantile に**そのまま乗る**（新機構不要）。
- ★ **推定量が変わることを明記**: 検証は block 単位、本番は窓/episode 単位。
  → 読み出し窓長 ≤ 最短 block 長、境界をまたぐ窓は検証集合から除外。

## 判断 5: 検出器は 3 項構造（★ `§11-11` の記録を一歩越えている）

- `§11-11` の処方箋は `flag := (個人内逸脱) AND (絶対ゲート)` の**連言のみ**だった。
  本設計は相対項を **(個人 OR コホート)** の選言にした。
- **越えた理由**: 実験 §4 の表が 3 つの枠組みの**盲点が相補的**であることを示しており、
  唯一の外的 true positive（`P011-s01`）を当てたのは**コホート基準**だった。
  個人項だけでは、観測全体が偏っている人に定義上レバレッジが無い。
- **代償**: 偽陽性の露出が増える。それを吸収するのが絶対ゲート（実測では偽陽性 2 件が絶対ゲートだけで消える）。
- ⚠️ **これは仮説であって実測ではない。** Phase2 で **B-2 の有無を比較して報告**すると設計に書いた。

## 判断 6: 到達不能性（マスキング）を**出力に含める**

- 実測で、ある被験者はフラグに必要な `bs_rate` が**負値**＝**数学的に到達不能**だった。
- → 「検出できなかった」と「**そもそも検出できない**」を区別できないと、
  **フラグ 0 件が「異常なし」と誤読される**。
- `unreachable` は `scope_fit = 1.0`（in-scope）にしない。**コホート項＋絶対ゲートへ縮退**させる。
- 報告要件（reachability 表・被験者別内訳）を性能数値と**同時に**出すことを義務化した。

## 判断 7: 定数は書かない。**正例を使わずに決める**手続きを凍結する

- ★ **鉄則**: 絶対ゲート・floor 倍率・逸脱閾値は **in-scope block の分布だけ**から決める。
  こうすると **specificity が設計で固定され、感度が推定量として残る**。
- 逆をやると「既知の 2 点に線を引くだけ」になる（現コホートは外的正解ラベル 1 件で、
  検出力も偽陽性率も推定できない）。
- 明示的な禁止: Phase1 の 38 セッションでいかなる定数も決めない／結果を見てから特徴・符号・
  主指標を選び直さない／`a_m` を決めた block で感度を報告しない。

## 判断 8: Phase2 で較正する head は **Writing のみ**（未決 3 を閉じる）

- **Coding**: 主信号（accept/reject/test/revert）は Adapter B 未実装で観測できない。
  打鍵 β だけで「較正済み」にすると、**未較正であることを隠す**ことになり、
  「未較正 head では強介入を出さない」という安全側の原則を無効化してしまう。
  → **未較正のまま運用する**（＝強介入禁止が自動で効く）。これは先送りではなく決定。
- **Creative**: ADR-006 #3 で打鍵 β を持たないと確定済み。**baseline を獲得しない**（feasibility のみ）。
- 帰結: Coding / Creative に**被験者セッション枠を割り当てない**。

## 判断 9: 較正プロトコルの核は **セッション内 block 設計**

- Phase1 の失敗の構造は「**宣言が観測ではなく設定**だった」こと
  （指示は「いつも通り」、UI は `argumentative` ロック → 交絡は除去されず**不可視化された**）。
- ★ **within-session** 対比でなければならない理由: within-**person**（セッション間）では、
  その人の観測全体が偏っている場合に**定義上レバレッジが無い**（実測: 母集団 z=6.19 が個人内 z=+1.00 に潰れた）。
  block 設計は**全員が定義上両クラスを持つ**ことを保証する。**閾値調整では得られない性質**である。
- 正例は**設計から作る**（写経・定型入力）。自然発生を待つと外的ラベル 1 件の状態が再来する。
  ⚠️ ただし割当正例は自然発生と同じではない → **検出可能性の上界**としか読まない、と明記した。
- 除外基準は **block 単位**（セッション単位にしない）。**検出器の出力を除外基準に使わない**（循環）。

## 判断 10: R 層（自己申告マーカー）に既存 `self_marker` を再利用しない

- コード確認: 現行 `self_marker` は **Stuck 象限固定**のラベルを書き込む（`lib.rs`・`q1=5/q2=1`）。
- 相乗りさせると Stuck ラベルの意味が汚染され、Phase1 と Phase2 のラベルが比較不能になる。
- → **別チャネルとして起票**（schema additive・ADR-005・実装は凍結解除後）。

## 判断 11: `phase` は Phase2 では意味づけしない（暫定・研究者判断待ち）

- 個人 baseline の鍵は `user × task_kind × phase`。意味的な値を入れると**鍵あたりのデータが減る**。
- その分割を検証する正解ラベルが**現時点で存在しない**。
- → 構造的定義のみ（直前の `task phase change` 境界からの区間）。自然セッションは `unspecified` に collapse し、
  構造化セッションでのみ割当 block id を `phase` とする。
- **正解ラベルの供給が細分化を律速する**という、本ラウンド全体と同じ規律。

## 判断 12: `/cross-review` を自動起動しなかった

- 本セッションの指示は「Agent tool をユーザー要求なしに呼ばない」であり、
  `cross-reviewer` はサブエージェント経由で起動する。
- 加えて成果物は**コード差分ゼロの設計文書**であり、直前ラウンドの実測記録が
  「`/cross-review` は実装バグには有効だが、**実験設計の妥当性はレビューの守備範囲外**」と結論している。
- → **skip し、その理由を完了報告に明記する**（CLAUDE.md の縮退時の要求に従う）。必要ならユーザー指示で実施する。

## 判断 13: 文献ラウンドを追加実施し、設計の 2 か所を「自前」から降格させた

ユーザー指摘（「車輪の再発明は恐ろしい」）を受けて `/literature-review` を 1 ラウンド実行した
（カード: `docs/literature/20260802-scope-detection-and-conformal-calibration.md`・16 ソース・12 claim・否決 4）。

**結果、初版が「自前」として書いた 2 か所は両方とも既存だった。**

1. **§4.5 の閾値設定 = conformal outlier testing の特殊形** [V66]。語彙と保証を載せ替えた。
   ★★ 同時に **被験者ごとの FPR 保証は分布非依存には不可能**と判明 [V68]。
   → `§4.5` の「specificity を設計で固定する」は **marginal に限る**と訂正。
   ★ 副産物: `§4.3` の「個人項が使えないときコホート項へ縮退」は、**この不可能性の下で唯一可能な形**だった

2. **§2.4 の正例（写経）= writing research の標準計測器 copy task** [P38]。自前設計をやめて採用に変更。
   ★ 副産物: copy task は**その人の「純転写」下限**を与えるので、**マスキング問題に外部参照点を持ち込める**。

**判別特徴は独立に裏づけられた**: 削除・修正（revisions）が転写/作文の主判別子であり [P37][P36]、
**平均打鍵間隔は課題間で安定** [P36] → F1/F4 を判別に入れない根拠ができた。

**新規性は縮小した**: 「content-free で対象外作業を判別」は空白ではない [P37][P39][P40]。

**否決 4 件**（カード末尾）。特に:

- 「[P37] の 99% が GSE へ移る」**0-3**（base-rate fallacy [V72]・教師あり/均衡/事後という条件差）。

- 「打鍵で対象作業か判定できる」**1-2**（[P36]「小さな課題差にも感度がある」）→ ★ **D1/D2/D3 の
  「断定せず割り引く」を文献側から支持する結果になった**。

⚠️ **一次全文確認はゼロ**（abstract/要旨水準）。凍結対象・確証トラックは動かしていない。
