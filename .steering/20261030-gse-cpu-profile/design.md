### A. 開始前の「停止中」では feat は出ない（引き継ぎ 2-4 の答え）

- `lib.rs` の分析のループは、`o1::analysis_gate_open(o1_always_on, session_active)` が閉じている間、入力を捨てて 50ms 眠るだけで、`step()` を呼ばない。`LogEntry::Feat` はこの門の先でしか送られない。非 O1 で「開始する」（`App.tsx` の `handleStart` → `start_session`）を押す前は門が閉じているので、feat は出ない。
- run7 は本当に「停止中」のままだった（`session_meta recorded` は 2:35:08 JST、研究者が押した時刻だけ）。feat が出ず、記録のスレッドは書くものが無いまま空回りした。これがふつうの振る舞いで、run7 が特別だったわけではない。
- 違っていたのは他の起動のほう。run1（起動 0:29:19 → 0:30:10 に開始）、run6（1:39:25 → 1:41:11）、run9（14:52:17 → 14:52:27）、run10、run11（15:24:24 → 15:24:41）、それに空回りの修正のタスクの直す前の起動（15:45:05 → 15:45:16）で、主窓の開始の処理（`Overlay window shown` → `session_meta recorded` → `tray state -> Measuring`）が走っていた。
- 自動で始める経路はコードに無い（`start_session` を呼ぶのは `App.tsx:453` の `handleStart` だけ、`handleStart` を呼ぶのは開始ボタンの `onClick` だけ）。前のセッションの記録（transcript）では、run1・run6・空回りの修正のタスクのどの開始時刻にも Claude の道具の呼び出しは無い。誰が押したかは記録からは決められない（研究者が押した見込みが高いが、研究者に確かめる）。
- 訂正が要る: 空回りの修正のタスクの `results.md` の 1 と判断 6 は、「開始前の停止中で 1 秒ごとに feat が書かれ、空回りの条件に入らない」としている。しかしログでは、測る窓（15:45:11 から 60 秒 × 2）の 5 秒目に `tray state -> Measuring` になっている。測ったのは記録中で、本当の開始前の停止中では、直す前の版は空回りしたはず（run7 と同じ）。直した版での確かめは本タスクの測定 1 で行う。

## 測る手順

- 版: 本 worktree（`fix/logger-flush-busy-loop` 140b376b・空回りの修正の入った版）。
- 起動: `probe/run-dev.sh`（識別子 `com.johnd.gse-next-cpu-profile`・記録は一時フォルダ）。O1 の収集アプリ（pid 99037）には触れない。
- CPU: `probe/cpu-window.sh 60 <pid>...`（`ps` の累積 CPU 時間の差・1 コア = 100%）。本体と WebKit の子（GPU・WebContent・Networking）。子は `responsibility_get_pid_responsible_for_pid` で本体または起動元が責任者のものを拾い、数を出す（`probe/procs.py`）。
- 状態と順番（各 60 秒 × 2・最後に `sample` 10 秒）:
  1. 停止中（開始前）。起動の後、研究者は開発版の窓に触れない。開始の処理が勝手に走らないかもログで見る（A の確かめを兼ねる）。
  2. 記録中・打鍵なし（Claude が AX で「開始する」を押す。押す前に AX でボタンの名前を読んで確かめる。実際は AX から主窓を読めず、研究者が押した）。研究者はキーボードとマウスに触れない。
  3. 記録中・打鍵あり（研究者が普段のエディタで打ち続ける。開発版の記録は一時フォルダに入り、終わったら消す。O1 も普段どおり記録する）。
  4. 一時停止中（Claude が AX で「すぐ止める」を押す）。研究者は触れない。修正の後に 0% 近くまで下がるかを初めて実機で確かめる。
- スレッドの内訳: `probe/threads.py`（スレッドごとの累積 CPU 時間の差）で測り、各状態の `sample` のスタックで名前を付ける（sample のサンプル数は眠っているスレッドも数えるので CPU には使わない）。
- 電源: 測った時点の電源と低電力モードを記録する（低電力モードは WebKit の描画を 1 秒 30 回に絞る）。
- 片付け: 自分が起動したプロセス番号・npx・vite だけを止め、ポート 1420 を確かめ、一時フォルダを消す。
