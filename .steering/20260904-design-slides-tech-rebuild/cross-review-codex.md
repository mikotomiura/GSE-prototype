## Codex の出力（原文）

**指摘事項**

1. **高: `--template` 経由で第三者画像を再混入できる可能性**
   `md2pptx.py` の `capture_chrome()` は、テンプレート内の「非プレースホルダ・文字なし」図形を複製し、画像 relationship も張り直します。つまり、`deck_temp1.pptx` のようなロゴ入りテンプレートを指定すると、Markdown 画像の repo 外拒否とは別経路で第三者画像が出力に残り得ます。`make_deck_template.py` は audit していますが、`md2pptx.py --template` 側には media/fonts/禁止文字列 audit がありません。意図的に任意テンプレートを許す設計なら誤検知寄りですが、今回の目的からは危険です。

2. **中: `docProps/app.xml` が既にある場合、スライド数が更新されない**
   `_ensure_app_xml()` は `docProps/app.xml` が存在すると即 return します。既定テンプレートや通常の PowerPoint テンプレートでは既に存在するため、`<Slides>` がテンプレート由来の古い値のまま残る可能性があります。表示には影響しにくいですが、成果物メタデータや検査系で不整合になります。

3. **中: selftest の“退行検出”が実際の失敗条件を検証していない箇所がある**
   例: 「版面の上書きを検出できる」は、壊した pptx を `measure()` して元サイズと違うことを確認するだけで、`build()` の退行を自動的に捕まえる構造ではありません。同様に図欠落・表非テーブル化・レイアウト単一化も、壊れた出力を作って観測しているだけで、期待仕様を assert する補助にはなっても mutation test としては弱いです。

4. **低: Markdown 画像パスのパースが素朴**
   `IMAGE_LINE = ...\(([^)]+)\)` のため、URL エンコードなしの `)`、タイトル付き画像構文、空白を含む一部 Markdown 形式は扱えません。仕様として「単独行の単純な相対パスのみ」と割り切るなら問題は限定的です。

5. **低: `svg2png.py` は未知オプションを黙って無視する**
   `args = [a for a in argv[1:] if not a.startswith("--")]` なので `--chek` 等が通常実行になります。`md2pptx.py` では直しているため、同じ方針で弾くべきです。
