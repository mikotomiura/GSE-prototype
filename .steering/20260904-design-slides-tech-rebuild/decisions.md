# 設計判断と根拠

## D1: レイアウト種別は「自動を既定・ディレクティブで上書き」にした

**判断**: `.pptx.md` に `<!-- layout: title|content|two|figure -->` を書けるようにし、
無ければ**図の有無で自動**に決める（図＋本文 → `two` / 図だけ → `figure` / それ以外 → `content`）。
`title`（表紙）は**明示指定でしか選ばれない**。

**理由**: 全スライドにディレクティブを書くのは冗長で、書き忘れが静かに効く。
一方で完全自動だと表紙が作れない。★ 自動で表紙を選ぶ規則（「1 枚目は表紙」等）は、
スライドを並べ替えた瞬間に壊れるので置かなかった。

## D2: 版面の座標をテンプレートから継承せず、明示的に置いた

**判断**: タイトル・本文・左右 2 枠の矩形を、**スライド寸法に対する比**で持つ（`Geometry`）。

**理由**: ⚠️ `deck_temp1.pptx` の「タイトルとコンテンツ」の本文枠は
**(0.80, 2.50) 9.01 x 1.60 inch**（版面の 3 割弱・**上端が版面の 44% の位置**）の
**バナー型**である（2026-09-04 実測）。図も密度のある技術説明も入らない。
★ さらに**同梱スライドはその継承座標を使っていない** —— 各スライドが座標を上書きし、
タイトルを (0.29, 0.18) の 15pt で置いている。
→ ⚠️ **「継承すればテンプレートどおりになる」は成り立たない。**

**代償**: テンプレートを差し替えても版面は本スクリプトの比のままになる。
★ 比で持っているので**寸法の違うテンプレートでも崩れない**が、
「テンプレート側で版面を設計する」運用はできない。

## D3: テンプレートの「地」だけを複製する

**判断**: 同梱スライドのうち**図形数が最小のもの**（同数なら先頭）を見本とし、
**プレースホルダでなく・文字を持たない図形だけ**を全スライドの最背面へ複製する。
`--chrome-from N` で明示指定、`--no-chrome` で無効化。

**理由**: `deck_temp1.pptx` は Google スライドの書き出しで、
**全面 `#F4F4F4` の矩形 ＋ 左端 0.16 inch の青いグラデーション画像**を各スライドが直接持つ
（`showMasterSp="0"` でマスタ図形は隠している）。ここがテンプレートの見た目の実体である。

★ 「図形数が最小」を既定にしたのは、**表紙のような装飾の多いスライドを見本にすると
全ページにその装飾（写真の帯・お断り書き）が乗る**ため。
★ 「文字を持たない図形だけ」に絞ったのは、同じ理由で**お断り書きのテキストボックスを外す**ため。
★ 実測では 2 枚目が選ばれ、複製されるのは狙いどおり背景と帯の 2 図形だけだった。

## D4: 欠けている `docProps/app.xml` は、検査を緩めずに出力側で補った

**判断**: `_ensure_app_xml()` で本体・content type・関係を対で足す。

**理由**: ⚠️ `deck_temp1.pptx` には **`docProps/app.xml` が無い**（Google スライドの書き出しが
出力しない。★ 壊れているわけではなく、同ファイルは PowerPoint でも Google スライドでも開く）。
`python-pptx` はパート構成を引き継ぐので、テンプレート経由の出力にも app.xml が無くなり、
`verify()` の必須パート検査に落ちた（実測）。

★ **必須パート検査から app.xml を外す**という直し方は採らなかった。
外すと、テンプレート無しの経路で**本当に欠落したときに気づけなくなる**からである。

## D5: 表を本物の `a:tbl` にした（引き継ぎの「表を減らす」案を採らなかった）

**判断**: `shapes.add_table()` で生成し、列幅を**中身の量で比例配分**、
フォントを**列幅と行高から逆算**して決める。

**理由**: 引き継ぎは「図中心にするなら表を減らすのが先」と書いていたが、
研究者の指定（モデル比較・昇格ゲート・層ごとの実装状況）は**表が最も読みやすい形**である。
`python-pptx` の `add_table()` で足りるので、減らすのではなく作れるようにした。

★ 列幅を均等にしないのは、実機で確認したところ
**「記号」1 文字の列と説明文の列が同じ幅になり、版面の半分が空白のまま説明文だけが折り返した**ため。
★ テンプレートに `ppt/tableStyles.xml` が無いので、**セル塗りを自前で指定**している
（ヘッダ = テーマ dk2 `#158158`、本文行 = 白 / `#EAEAEA` の交互）。

## D6: 図は全幅スライドに置く（左右 2 枠に置かない）

**判断**: 図を含むスライドは実質すべて `figure`（本文枠いっぱい）にした。

**理由**: ★ 版面が 10.00 x 5.625 inch と小さい。左右 2 枠は 1 枠 4.35 x 3.71 inch なので、
**1400px 幅の図を入れると図中の 19px の文字が 4.2pt になり読めない**（計算と実機で確認）。
全幅（9.0 x 4.02 inch）なら同じ文字が **8.8pt** になる。
→ ★ **新規図もすべて横長（縦横比 2.0〜2.3）で描いた。**
⚠️ 縦長で描いた介入決定の図は、この理由で横長に作り直した。

## D7: `verify()` の検査 (7) に等価写像を入れた

**判断**: layout → master のプレースホルダ型照合に `PH_TYPE_BASE`
（`ctrTitle→title` / `subTitle→body` / `obj`・`tbl`・`chart` 等 →`body`）を入れた。

**理由**: 表紙レイアウトの `ctrTitle` / `subTitle` が master の `title` / `body` を継承するのは
**PowerPoint の正常な形**であり、型名で素朴に照合すると**偽陽性が出る**（実測で 2 件出た）。

⚠️★★★ **旧版でこれが露見しなかったのは、検査が正しかったからではない。**
★ 旧版は**全スライドが「タイトルとコンテンツ」1 種類だけ**を使っており、
**表紙レイアウトを 1 度も参照しなかった**からである。
→ ★ 検査の網羅性は「緑であること」からは分からない、という実例をもう 1 つ得た。

## D8: 図の PNG 書き出し手順を実測で復元し、スクリプトに閉じ込めた

**判断**: `scripts/svg2png.py` を新規作成。LibreOffice の `draw_png_Export` に
**SVG の `viewBox` と同じ画素数**を渡す。

**理由**: ⚠️ **既存 4 枚をどう作ったのかが、どの文書にも書かれていなかった。**
★ 上記の手順で `gse-architecture.svg` を書き出したところ、コミット済みの
`gse-architecture.png` と **md5 が完全に一致した**（`661e8a91f4e9fa8ad43c605992c68086`）。
→ ★ 手順を復元できたので、二度と失われないようスクリプトにした。

⚠️ **PyMuPDF (`fitz`) は使えない** —— SVG を開けて PNG も出るが、
**長音のグリフが落ち、`text-anchor` の解釈も違って文字が枠からはみ出す**（実測）。

⚠️★★★ **1 倍で上書きしない安全弁を入れた。** ★ `gse-workflow.png` だけは **3 倍**
（3600x1290）で書き出されており、引数なしで全図を回したときに**黙って 1 倍へ縮小してしまった**
（`git checkout` で復旧）。→ 倍率が違う既定の PNG は skip し、`--force` を要求する。

## D9: 未踏参考文献に番号を新設しなかった

**判断**: スライドが引く `[n]` は、既に『GSE参考文献』に実在する番号だけにした。

**理由**: 未踏文書の `[n]` は『GSE参考文献』の通し番号で、`docs/references.md` の
`[Pn]`/`[Vn]` とは**別体系**である。番号は append-only で再利用しない規約なので、
スライド側の都合で採番すると 2 文書の対応が崩れる。

★ したがって、一次資料メモに出てくる `[P161]`（疲労）/ `[P221]`（ストレス）/
`[P226]`（マインドワンダリング）/ `[V59]`（離散時間ハザード）などは、
**未踏参考文献に存在しないので番号を付けずに事実だけ書いた**。

## D10: 枚数は 34 枚に収めた

**判断**: 一度 38 枚まで書いてから 4 枚ぶんを統合した。

**統合したもの**:
- 「埋まっている層は入力に近い側ではない」→ 図がそのまま語るので削除
- 「作業種別と入力方式は、役割が違う」→ 図の脚注が同じことを言っているので削除し、
  失われる 1 点（変換の実装は 1 か所にしか置かない）を「層と層をつなぐのは、型と契約である」へ移した
- 「回帰保護」＋「推論を変えるときの手続き」→ 1 枚に統合
- 「撤退の設計」→ まとめと「昇格の判定量」へ吸収

## D11: 研究者指定のテンプレートを取り込まず、デザインだけ自前で再現した

⚠️★★★ **これは着手後に判明した事実による方針転換である。**

**判断**: `deck_temp1.pptx` を repo へ入れるのをやめ、`scripts/make_deck_template.py` が
生成する `_template/gse-deck-template.pptx` を基盤にした。

**理由**: security-checker の指摘を受けて中身を開いたところ、**第三者の資料**だった
（★ 私も独立に開いて確認した）:

| 実測したもの | 中身 |
|---|---|
| `ppt/slides/slide1.xml` | 逐語「**許諾なく撮影や第三者への開示を禁止します**」 |
| `ppt/slides/slide2.xml` | 「アジェンダ / 1)背景 / 2-1)生成AIの基礎知識 …」＝ **生成AI 講座の見本** |
| `ppt/media/image3.png` | **「松尾・岩澤研究室 / Matsuo-Iwasawa Lab UTokyo」のロゴ** |
| `ppt/media/image4.png` | 同研究室の「M」マーク |
| `ppt/fonts/*.fntdata` | Tahoma 2 本（★ 本文では 1 文字も使っていない・519 KB） |

⚠️★★★ **決定的だったのは「同梱スライドを消しても消えない」こと** ——
ロゴは `slideMaster1` / `slideLayout5` から参照されているため、
`_drop_all_slides()` を通した**あとの生成物にも残っていた**（★ 実測で unzip して確認）。
⚠️ 画面には出ない（`showMasterSp="0"`）が、**IPA 未踏へ出す成果物に第三者研究室のロゴが同梱される**。
⚠️ **一度コミットすれば git 履歴から消えない。**

**再現したもの**（★ 汎用的な体裁だけ）: 版面 10.00 x 5.625 inch / 地 `#F4F4F4` /
左端 0.16 inch の青いグラデーション帯（★ ビットマップではなく**グラデーション図形**で描く）/
主色 `dk2 #158158`。⚠️ **ロゴ・見本スライド・埋め込みフォントは 1 バイトも持ち込まない。**

**副次的な効果**: 出力が **2.04 MB → 1.13 MB** に減った（★ 未使用のロゴ 388 KB と
未使用フォント 519 KB が消えたぶん）。★ 生成器は出力を機械監査する
（画像 0 / 埋め込みフォント 0 / 第三者由来の文字列 0）。

**代償**: ⚠️ 研究者が見た `deck_temp1.pptx` の見た目と**完全一致ではない**。
★ 再現したのは背景・帯・配色・版面であって、同梱スライドの写真の帯や罫は持ち込んでいない。

## D12: 検査 (8) を足した —— 中核機能が無検査だった

**判断**: `verify()` に「パートが参照する rId が、そのパートの `.rels` に実在するか」を足した。

**理由**: code-reviewer の指摘。⚠️ 検査 (5) は **rels → パートの向きしか見ておらず**、
**宙吊りの `r:embed`（rels に無い rId を XML が指す）を素通りさせていた**。
⚠️★★★ `_ChromeSpec` の関係張り替えを失敗させると**まさにこの形**で壊れる ——
★ **本版の中核機能が、それまで無検査だった。**

★ 併せて selftest の合成テンプレートを直した。旧版は画像を 3 枚目にだけ置いていたが
`capture_chrome` は図形数最小＝1 枚目を選ぶため、**rId 張り替えの経路を 1 度も通っていなかった**。
→ 全見本スライドに画像を置き、`chrome_images == 1` と「全スライドに media 関係がある」ことを検査する。
★ 変異体（`r:embed` を存在しない rId に書き換え）で落ちることも確認した。
