## 1. なぜトレイなのか

⚠️ ★ 指摘の 2 つは**同じ穴**である:

> 窓を閉じる／戻ると **UI ごと消える**のに、**プロセスと計測は生きている**。

→ ★ **窓と独立に生き続ける常駐 UI** に置けば、両方いっぺんに解ける。

★ 実例（2026-08-08）: 3 時間動き続けていた `gse-next`（CPU 157 分）。
研究者は「閉じた」と思っていたが、`g1_mode:"marker"` のまま 80 KB 記録し続けていた。
⚠️ **窓が無いので、動いていることを知る手段が無かった。**

## 2. 3 つの状態（★ 2 値にしない）

| 表示 | 条件 | なぜ分けるか |
|---|---|---|
| `○` / 停止中（記録していません） | セッション無し | — |
| `● 計測中` | セッション中 ＋ `HOOK_ACTIVE` | — |
| `⚠ 計測できていません` | セッション中だが `HOOK_ACTIVE=false` | ★★ **ここが値打ち**。macOS の CGEventTap は失効しうる（memory: `macos-tap-idle-away-probe-bug`）。⚠️ 気づかないと**打鍵ゼロのブロックが静かに記録される** |

⚠️ ★ 「止めた」と「壊れている」を同じ表示にしない
（`hook_down_is_distinguished_from_stopped` テストで固定）。

★ `HookDown` は `tracing::error!` にも出す。**トレイは後から読み返せない**が、
`gse-app.log`（本日追加）があれば研究者が後から追える。

## 3. ⚠️ 盲検（`preregistration.md §2.12`）

★ **認知状態 (Flow / Incubation / Stuck) はトレイに出さない。** 出すのは
「打鍵を記録しているか」だけ。⚠️ 出すと被験者がトレイを見るだけで仮説を推測できる。
→ `tray_labels_never_leak_cognitive_state` テストで**非開示語 13 個**を禁止する。

## 4. 更新は 1Hz の polling

★ セッションの on/off は `start_session` / ブロック自動終了 / 停止 と**複数の箇所**で
切り替わる。⚠️ 呼び出し側に通知を足して回ると、**足し忘れた経路だけ古い表示が残る**（静かに間違う）。
→ Atomic を 1Hz で読む。`FeatSnapshot` のゲートと同じ粒度で費用も無い。
★ 値が変わったときだけ UI を触る。

## 5. 終了経路を 1 本にする

```
画面の「セッション終了」 ─┐
トレイの「GSE を終了」  ─┼→ shutdown_and_exit() → shutdown() → exit(0)
main 窓の ×            ─┘
スタート画面の「GSE を終了」┘
```

⚠️ ★ 経路ごとに書くと、**どれか 1 つだけ「ログを閉じずに落ちる」**ようになる。
★ `SHUTTING_DOWN` の `swap` で **二重起動を防ぐ**（× を押してからトレイの終了を押す等）。

★ overlay 窓の `CloseRequested` は**無視する**（道連れにしない）。

### ⚠️ G1 では分析とフォルダ表示をやらない

`quit_app` は終了前に `behavioral_gt.py` を起動し、セッションフォルダを開く。
★ 被験者の画面に NDJSON の並んだフォルダが開くのは混乱のもとであり、
`behavioral_gt.py` は被験者の端末に無い。
→ `g1_mode().is_none()`（= 研究者の通常運用）のときだけ従来どおり行う。

## 6. ⚠️ 検証の限界（★ 正直に書く）

- 単体テストで固定できるのは**状態遷移と文言**だけである。
- ★ **トレイが実際に出るか・押せるか・プロセスが本当に死ぬかは、動かして見るしかない。**
- ⚠️ dev ビルドで見た結果は**配布物（CI の本番バイナリ）で見たことにならない**。
  → 配布前に本番バイナリでもう一度見る（引き継ぎに書く）。
