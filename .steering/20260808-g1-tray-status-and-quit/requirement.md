# 計測中かどうかを常に見えるようにし、いつでも終了できるようにする

## 背景

研究者の指摘（2026-08-08）:

1. 「GSE アプリが起動した後の『戻る』ボタンを押した後は、ちゃんとアプリが終了できるようにしないといけないかも」
2. 「現在 GSE が計測中かどうかなども判別できるようになったらめちゃくちゃいい」

★ この 2 つは **同じ穴** である: **窓を閉じる／戻ると UI ごと消えるのに、
プロセスと計測は生きている。**

### 実物で確かめたこと（★ ドキュメントの記述を鵜呑みにしていない）

| | 実測 |
|---|---|
| 「← 戻る」 | `App.tsx:795` `handleBack` は `setIsStarted(false)` だけ。★ **意図的にアプリを終了しない**（コメントに明記） |
| 戻った先 | ⚠️ ★ スタート画面のボタンは「開始する」と「尺度理解テスト」の **2 つだけ**。**終了する手段が無い** |
| × で閉じる | ⚠️ ★ `on_window_event` / `CloseRequested` / `ExitRequested` は **コードのどこにも無い**（grep 済み）。`lib.rs` が `overlay` 窓を実行時に作るので、★ **overlay が残る限り Tauri は終了しない** |
| 実例 | ★★ 2026-08-08 に **3 時間動き続けていた `gse-next`（CPU 157 分）** を発見。`g1_mode:"marker"` のまま研究者自身の打鍵を 80 KB 記録していた |
| `quit_app` | `app_handle.exit(0)` に到達するので**終了はする**。⚠️ ただし終了前に `behavioral_gt.py` を起動し、セッションフォルダを Finder/Explorer で開く |

### ★ 「計測中か」を知る手段が今は無い

`SessionActive`（`lib.rs:175`）と `HOOK_ACTIVE` は Rust 側にあるが、
**Dashboard を開いていないと見えない**。⚠️ 窓を閉じた状態＝いちばん知りたい状態で見えない。

## ゴール

- ★ **窓を閉じていても**「いま計測しているか」が分かる
- ★ **窓を閉じていても**アプリを終了できる
- ⚠️ ★ 「セッション中なのにフックが死んでいる」を**気づける**ようにする
  （`macos-tap-idle-away-probe-bug`: CGEventTap は失効しうる。今は画面を見ないと分からない）

## スコープ

### 含むもの
- メニューバー／タスクトレイのアイコン（Tauri 2.10.2 の `tray-icon` feature）
  - 3 状態の表示: 停止中 / 計測中 / ⚠️ 計測できていません
  - メニューに「GSE を終了」
- スタート画面に終了ボタン
- main 窓の `CloseRequested` を捌く

### 含まないもの
- ⚠️ **認知状態（Flow/Incubation/Stuck）はトレイに出さない**。盲検が壊れる
  （`preregistration.md §2.12` の非開示。出すのは「計測しているか」だけ）
- 介入の変更（`intervention-design` には触らない）
- 配布物の作り直し（★ 別途 CI とタグが要る）

## 受け入れ条件

- [ ] トレイの表示が 3 状態を正しく切り替える（★ 単体テストで状態遷移を固定する）
- [ ] トレイの「終了」で**プロセスが本当に消える**（★ `ps` で確認する）
- [ ] × で閉じてもプロセスが残らない
- [ ] スタート画面から終了できる
- [ ] ⚠️ ★ **認知状態がトレイに出ていないこと**（盲検）
- [ ] `cargo test --workspace` / golden / schema が緑
- [ ] ⚠️ ★ **実際にアプリを起動して目で見る**（★ トレイは「見た」以外に確かめようがない）
