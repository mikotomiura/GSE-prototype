# 設計判断

## D-1: トレイ（常駐アイコン）にした

**決定**: メニューバー / タスクトレイに常駐アイコンを置く。

**理由**: ★ 指摘の 2 つ（「戻る の先で終了できない」「計測中か分からない」）は**同じ穴**である
—— 窓を閉じると UI ごと消えるのに、プロセスと計測は生きている。
→ **窓と独立に生き続ける UI** に置けば両方いっぺんに解ける。

**却下案**: 画面の中の表示を増やす
→ ⚠️ ★ **いちばん知りたい「窓を閉じた状態」で見えない**。問題そのものが解けていない。

## D-2: 2 値ではなく 3 状態にした

**決定**: 停止中 / 計測中 / ⚠️ 計測できていません。

**理由**: ★★ macOS の CGEventTap は失効しうる（memory: `macos-tap-idle-away-probe-bug`）。
⚠️ 「セッション中なのにフックが死んでいる」を **「止まっている」と同じ表示にすると、
打鍵ゼロのブロックが静かに記録される**。★ 今までこれに気づく手段が無かった。
→ 「止めた」と「壊れている」を必ず区別する
（`hook_down_is_distinguished_from_stopped` テストで固定）。

★ `HookDown` は `tracing::error!` にも出す。**トレイは後から読み返せない**が、
`gse-app.log`（同日追加）なら研究者が後から追える。

## D-3: ⚠️ 認知状態はトレイに出さない（盲検）

**決定**: 出すのは「打鍵を記録しているか」だけ。

**理由**: `preregistration.md §2.12` の非開示。⚠️ ★ 状態を出すと、被験者はトレイを見るだけで
仮説を推測できる。→ `tray_labels_never_leak_cognitive_state` テストで**非開示語 13 個**を禁止し、
3 状態 × 2 文言（label / title）の全組み合わせを検査する。

## D-4: 更新は 1Hz の polling

**決定**: 状態変化の通知を呼び出し側に足さず、Atomic を 1Hz で読む。

**理由**: ⚠️ セッションの on/off は `start_session` / ブロック自動終了 / 停止 と
**複数の箇所**で切り替わる。通知を足して回ると、★ **足し忘れた経路だけ古い表示が残る**（静かに間違う）。
1Hz は `FeatSnapshot` のゲートと同じ粒度で費用も無い。★ 値が変わったときだけ UI を触る。

## D-5: 終了経路を 1 本にした

**決定**: 4 つの入口（画面の「セッション終了」/ スタート画面の「GSE を終了」/ トレイの「終了」/
main 窓の ×）を全部 `shutdown_and_exit()` に通す。`SHUTTING_DOWN` の `swap` で二重起動を防ぐ。

**理由**: ⚠️ ★ 経路ごとに書くと、**どれか 1 つだけ「ログを閉じずに落ちる」**ようになる。
二重に走ると、ログを閉じる待ち合わせが二重になり `exit(0)` が競合する。

★ overlay 窓の `CloseRequested` は無視する（道連れにしない）。

## D-6: ⚠️ G1 では分析起動とフォルダ表示をやらない

**決定**: `g1_mode().is_none()`（研究者の通常運用）のときだけ `behavioral_gt.py` 起動 +
セッションフォルダを開く。

**理由**: ★ 被験者の画面に NDJSON の並んだフォルダが開くのは混乱のもと。
`behavioral_gt.py` は被験者の端末に無い。⚠️ 研究者の開発フローは変えない。

## D-7: ⚠️★ ランタイムを generic にしない

**決定**: `tray::setup(app: &AppHandle)`（= `AppHandle<Wry>`）。`<R: Runtime>` にしない。

**理由**: ★ 最初 generic で書いて**コンパイルが通らなかった**
（`TrayIconBuilder::build` が `Manager<Wry>` を要求し、`shutdown_and_exit` も `AppHandle<Wry>` を取る）。
→ 呼び出し側で必ず型が合わなくなる。

## D-8: ⚠️★ 検証で確かめられたこと / 確かめられなかったこと

★ **dev ビルドを実際に起動して**確かめた（トレイは「見た」以外に確かめようがない）:

| 確かめたこと | どうやって |
|---|---|
| トレイが出る・title が `○` | `osascript` で `menu bar 2` の status item を読んだ |
| メニューの中身が 3 行 | 同上（状態表示 / 区切り / 終了） |
| ★★ トレイの「終了」でプロセスが消える | 実際にクリックし、`ps` で 2 秒後に消滅を確認 |
| ★★ × でもプロセスが消える | 閉じるボタンを押し、`ps` で 2 秒後に消滅を確認 |

⚠️ ★ **確かめられなかったこと**: `計測中` / `計測できていません` への遷移。
`開始する` は WKWebView の中にあり **AX に露出しないので押せなかった**
（`entire contents` に「開始」が 0 件。`screencapture` も Screen Recording 権限が無くて不可）。
→ ★ **「動く」とは書かない。** 確認方法だけ残す:
セッションを 1 回始めて `gse-app.log` に `tray state -> Measuring` が出るのを見る。

⚠️ そして **dev ビルドでの確認は配布物（CI の本番バイナリ）での確認ではない**。

## D-9: Codex レビューの判定 (2026-08-08)

| 指摘 | 判定 | 対応 |
|---|---|---|
| **1** `CloseRequested` で `prevent_close()` していない → 窓破棄と終了処理が競合しうる | ⚠️ ★ **実測では再現しない**。× を押して 2 秒でプロセスが消え、ログに `session closed` が**先に**出ている（`exit(0)` はロガー完了を `shutdown_rx` で待つ）。★ `prevent_close` を入れると窓が 2 秒残るぶん体感が悪くなる | 変えない（★ 実測の根拠を記録） |
| **2** トレイ更新スレッドが終了シグナルを見ない | ★ 正しい。落ちるまでのあいだ破棄済みハンドルを触りうる | `is_shutting_down()` を見て抜けるようにした |
| **3** 初期状態が `measure_state(false,false)` 決め打ち | ★ 正しい。setup の順序が変わると**最大 1 秒だけ嘘を表示する** | `current_state()` で実際の Atomic から始める |
| **4** セッション未開始で終了したときの `session_path` | ★★ **正しい。しかも私が作った経路である**（スタート画面に終了ボタンを足したので「未開始のまま終了」が現実的になった）。`Path::new("").parent()` は `Some("")` を返すので**意図しないフォルダが開く** | `wants_researcher_exit_flow()` で空パスを弾く |
| **5** 統合経路のテスト不足 | ★ 正しい | 二重終了ガード / G1 抑止 / 空パス抑止 / 非回帰 の 4 件を追加。★ **3 変異すべてで赤を実測** |

★ 修正後にもう一度 dev ビルドを起動し、トレイ title = `○` / トレイの終了で 2 秒消滅を再確認した。

## D-10: ⚠️★★ スタート画面の「空の箱」— 見た目を確かめていなかった

**指摘 (2026-08-08・スクリーンショット付き)**: 「開始する」の下に**中身の見えない箱が 2 つ**並んでいた。

### 真因（★ 推測ではなく実測した）

`.start-button` は緑地用に `color: #0f172a` を持っている。そこへインラインで
`background: transparent` **だけ**を上書きしていたため、⚠️ ★ **文字色が body 背景と完全に一致**した。

ブラウザに実マウントして対照つきで測った値:

| | 文字色 | 背景 (`body`) との輝度差 |
|---|---|---|
| 旧のやり方（背景だけ透明） | `rgb(15, 23, 42)` | ★ **0**（= 背景と同一色） |
| `.start-button-secondary`（新） | `rgb(203, 213, 225)` | 189 |

★ 文字が無かったのではなく、**背景と同じ色で塗られていた**。

### ⚠️ ★ 私の落ち度

「尺度理解テスト」は以前からこの状態だったが、⚠️ **私は同じ書き方を写して
「GSE を終了」でも同じ穴に落ちた**。★ 原因は単純で、**画面を見ずにコミットした**こと。
`tsc` も `cargo test` も、この不具合を検出しない種類の欠陥である。

### 直し方

1. ★ 色と背景を **1 つのクラス** (`.start-button-secondary`) にまとめ、書き忘れられなくした。
2. スタート画面から 2 つとも外した:
   - 「尺度理解テスト」は `docs/functional-design.md:143` のとおり**現行スコープでは延期**。
     → `VITE_GSE_DEBUG=1` の研究者ビルドにだけ残す（`Dashboard.tsx:224` と同じ規約）。
   - 終了ボタンは不要になった。★ **× とトレイの両方で終了できることを実機で確認済み**。
3. ★ 同じ罠を grep で洗い、**提出確認ダイアログ**（被験者が見る画面）の
   「送信する」「あとで」にも文字色が無かったので明示した。
   ⚠️ ボタンは `color` を継承しないので、**指定しないと UA 既定（ほぼ黒）**になる。

### ★ 検証

⚠️ Tauri API が無いとブラウザでアプリが描画されない（`getCurrentWindow()` が投げる）。
→ `window.__TAURI_INTERNALS__` の最小 shim を入れて `/src/main.tsx` を再 import し、
★ **実スタイルシートに対して実マウントさせて**測った（偽の CSS を作らない）。

- スタート画面のボタンは「開始する」＋既存のモード切替のみ = ★ **空の箱は消えた**（スクショで確認）
- ⚠️ 提出確認ダイアログは pending が無いと出ないので**画面では未確認**。色は inline に明示してある
