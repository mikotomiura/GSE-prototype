# 重要な設計判断

## 判断 1: 直し方は「`${name}` と括る」— 全角の置換でも `set -u` の撤廃でもない

- **判断日時**: 2026-08-29
- **背景**: macOS 標準の bash 3.2 が多バイト文字を変数名の一部として読み、
  `set -u` のもとで落ちる。⚠️ 実害として `sync-session.sh` の **O1 ガードが `exit 4` を返せず
  `exit 1`** になっていた（★ O1 セッションを gse-dataset へ出さない番人）。
- **選択肢**:
  - A: `${name}` と括る
  - B: メッセージの全角括弧を半角に置き換える
  - C: 当該スクリプトの `set -u` を外す
  - D: bash 5 を前提にする（★ 研究者に homebrew の bash を入れてもらう）
- **採用**: **A**
- **理由**:
  - ★ `${` を見た bash は閉じ `}` まで変数名として読むので、⚠️ **後続バイトの解釈に依存しない**。
    bash 3.2 / 5.x / git-bash / zsh で同じ結果になる（★ 陰性対照で実測）。
  - ⚠️ B は**被験者と研究者が読むメッセージの文面を変える**（日本語の体裁が崩れる）。
  - ⚠️ C は**未定義変数を黙って空にする**。★ 本プロジェクトが最も避けている silent failure に倒れる。
  - ⚠️ D は**この Mac に homebrew の bash が無い**ことを実測済み（`/opt/homebrew/bin/bash` 不在）。
    ★ さらに「被験者・研究者の機械に前提を足す」のは配布の敷居を上げる。
- **トレードオフ**: ★ 書き方の規約が 1 つ増える。→ ⚠️ **人の注意力に頼らず機械で見張る**ことで相殺する
  （`scripts/check-shell-portability.sh`）。
- **影響範囲**: リポジトリ全体のシェルスクリプト 17 箇所。★ `.ps1` は無関係（同じ罠が無い）。
- **見直しタイミング**: ★ macOS が既定 bash を 4 以降にしたとき。⚠️ ただし
  **git-bash・Linux・CI の bash も含めて**全部が新しくなるまで規約は残す。

## 判断 2: ⚠️ **コメント行も規約に従わせる**（検査から除外しない）

- **判断日時**: 2026-08-29
- **背景**: ★ 移植性ゲートを書いた直後、⚠️ **自分がコメントに書いた「壊れる書き方の実例」を
  ゲートが捕まえた**。★ 実行されない行なので無害ではある。
- **選択肢**:
  - A: コメントを走査対象から外す
  - B: コメントも規約に従わせ、実例は**バイト列を並べずに散文で説明する**
- **採用**: **B**
- **理由**:
  - ⚠️ **コメントはコピペされる。** ★ 「壊れる書き方」がリポジトリに残っていると、
    次に書く人がそれを見本にする（★ 実際 `prepare-subjects.sh` は正しい規約をコメントで
    説明していたのに、⚠️ **リポジトリ全体では 17 箇所が壊れたままだった**）。
  - ⚠️ A の除外ロジックは**シェルの引用規則を正確には解けない**（`#` は文字列の中にも出る）。
    ★ 誤除外すると**本物の違反を見逃す**。
- **トレードオフ**: ★ 「こう書くと壊れる」を逐語で書けない。→ ⚠️ 散文で説明し、
  **実演は対照フィクスチャ（実際に bash で走らせる）に任せる**ほうが証拠として強い。
- **影響範囲**: `check-shell-portability.sh` / `check-o1-release-readiness.sh` /
  `prepare-subjects.sh` の説明コメント。

## 判断 3: 移植性ゲートは **grep に頼らず python3 で書く**

- **判断日時**: 2026-08-29
- **背景**: ★ 走査を `LC_ALL=C grep -E '\$[A-Za-z_][A-Za-z0-9_]*[^[:print:][:space:]]'` で
  書こうとしたが、⚠️ **この Mac の `grep` は ugrep 7.8.4 で、1 件も拾わなかった**（実測）。
  ★ さらに検証中、⚠️ **ugrep は非 UTF-8 バイト混じりのパイプ入力を黙って空で返す**ことも実測した
  （`unzip -Z1 | grep 'mode'` が 0 行 → `LC_ALL=C grep -a` にしたら拾えた）。
- **選択肢**:
  - A: grep で書く
  - B: python3 でバイト列を自分で読む
- **採用**: **B**
- **理由**: ⚠️ ★ **検査そのものが実装差で空回りしては意味がない。** grep は
  BSD / GNU / ugrep / git-bash で挙動が割れる。★ python3 はこのリポジトリが既に
  `check_schema_parity.py` 等で前提にしている。
- **トレードオフ**: ⚠️ python3 依存が増える。→ ★ **不在なら緑にせず赤にする**（fail-closed）。
- **影響範囲**: `scripts/check-shell-portability.sh`。

  ⚠️ これは意図的（生成物・退避ファイルを走査しない）。

## 判断 5: ⚠️ `sync-all.sh` の `exit 4` は **意味が違う**（★ 今回は触らない・記録のみ）

- **判断日時**: 2026-08-29
- **背景**: ★ `sync-session.sh` の `exit 4` は「**O1 セッションを弾いた**」だが、
  ⚠️ `sync-all.sh:108,117` の `exit 4` は「**parity スクリプトが無い / python が無い**」である。
  ★ さらに `sync-all.sh:176-181` は `sync-session.sh` の戻り値を**特別扱いせず**
  「`FAILED: <pid>/<file> (exit 4)`」と表示する。
- **採用**: ★ **今回は変更しない。記録に留める。**
- **理由**:
  - ★ 本タスクの目的は「**exit code の契約を本来の姿に戻す**」ことであり、
    ⚠️ 契約そのものを設計し直すのはスコープが違う（★ 混ぜると「直したから緑」なのか
    「変えたから緑」なのか区別できなくなる）。
  - ★ 実害の程度: ⚠️ O1 が「FAILED」と表示されるのは**紛らわしい**が、
    ★ 同期は止まる（fail-closed）ので**データは出ていかない**。
- **⚠️ 次にやる人へ**: ★ `sync-all.sh` 側で `exit 4` を「意図的にスキップした」として
  区別して表示すると、⚠️ 研究者が「壊れた」と誤解しなくなる。→ **未着手**。

## 判断 6: ⚠️★★ `sync-all.sh` が **ガードより前に** O1 の生 NDJSON を dataset へコピーする

- **判断日時**: 2026-08-29（★ security-checker MEDIUM）
- **背景（★ 自分で実測して確認した）**:
  - `scripts/sync-all.sh:132` の Step 1 は `"$FALLBACK_DIR"/gse_*.ndjson` でループしており、
    ⚠️ **`gse_o1_*.ndjson` に一致する**。
  - ★ `o1_guard` は **Step 2 の `sync-session.sh` の中でしか走らない**。
    → ⚠️ O1 の**生の打鍵ログ**が `$DATASET_ROOT/raw/$LOCAL_PID/` に物理的に置かれる。
  - ★ 緩和は実測済み: gse-dataset の `.gitignore` に **`raw/**/*.ndjson`** があり、
    かつ Step 2 で `FAILED>0` → `exit 1` で **commit 前に中断**する。
    → ⚠️ **push には至らない（fail-closed）**。
- **選択肢**:
  - A: 本 PR で `sync-all.sh` の Step 1 にガードを前倒しする
  - B: 起票して、`sync-all.ps1` と**対で**直す
- **採用**: **B（本 PR では直さない）**
- **理由**:
  - ⚠️★★ **片方だけ直すと「片方の OS でだけ漏れる」型になる。** ★ このプロジェクトが
    繰り返し踏んでいる罠であり、`o1_guard` の大文字小文字判定を文字クラスで書いた理由もそれ
    （`sync-session.sh:138-141`）。⚠️ **PowerShell はこの Mac で実行できない**ので、
    `.ps1` 側を直しても**検証できないまま入る**。
  - ★ 本 PR の主題は「**exit code の契約を macOS で本来の姿に戻す**」であり、
    ⚠️ 同期の設計変更を混ぜると「直したから緑」「変えたから緑」の区別がつかなくなる。
  - ★ fail-closed は保たれている（★ 実測: `.gitignore` ＋ Step 2 の中断）。
- **⚠️ 残るリスク（★ 隠さない）**:
  1. ★ push される repo の**作業ツリーに生ログが常駐する**。
     ⚠️ `git add -f` や ignore 規則の変更で流出しうる。
  2. ⚠️ 一度コピーされると **以後毎回 `FAILED>0` で全同期が止まり続ける**。
     ★ 研究者が回避策（ガード無効化・手動 `gse-replay`）を採る**運用圧力**になる。
- **★ 次にやること**: Step 1 のループ内で `o1_guard` 相当（ファイル名 ＋ meta）を先に当て、
  **コピーせず `skip` として数える**。⚠️ O1 起因の skip は `FAILED` に数えず中断もしない。
  ★ `sync-all.sh` と `sync-all.ps1` を**同じコミットで**直し、**Windows で 1 回実行して確かめる**。
