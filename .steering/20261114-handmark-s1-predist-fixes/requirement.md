# 段 1 の 3 名に配る前の条件（手跡の分）

## 背景

段 1 の 3 名の同意文書（PR #410・`.steering/20261114-gse-stage1-n3-consent/consent-draft-s1.md`）の末尾の「配る前の条件」のうち、手跡の実装に関わる 3 件を終える。

- 条件 3（判断 13）: 消した時間帯の手跡の表示の量（`shown_ms`・`visible_ms`）が、後の行の累計からも消える。今は区間の中の行は消えるが、後の行と状態ファイルの累計に区間の中の量が残り、前後の行の差から読める。
- 条件 5（ADR-052 D2）: 段 1 で足す行種が区間の削除の鍵 `"t"`（または明示した別名）を持ち、削除で消えることをテストで縛る。
- 条件 12: 一時停止中の後半の表示の挙動を確かめ、§4 の 2 番に書き足すか決める。コードを読むと、一時停止中も `shown_ms`・`visible_ms` が足され、「やめる」「描く」・入力ごとの入れ切り・起点の時刻も状態に残り、再開の後の行に出る（一時停止中の在席とロックの量と時刻が残る）。

## ゴール

- 削除した区間の手跡の量と時刻が、端末に残るどの行・状態ファイルからも読めない。
- 一時停止中の手跡の量と時刻が、どの行・状態ファイルからも読めない（表示は出たまま、操作には合わせて動かない）。
- 全行種の削除の鍵を schema から導いて縛るテストがある。
- 同意文書の §4 の 2 番とフォームに一時停止中の表示の文を足し、承認の印を外す（研究者の承認の取り直し待ち）。

## スコープ

### 含むもの
- `redaction.rs`: 削除の前に全ファイルの `handmark_day` の行から日ごとの引く量を求め、区間より後の行から引く。
- 駆動役と状態ファイル: 走行中の累計からも同じ量を引く。一時停止中は量を足さず、時刻の要素を残さない。
- 行種の削除の鍵のテスト。
- 同意文書の md とフォームの文、`docs/o1-deletion-ledger.md` の段 1 の行（研究者側の削除も同じ引き方）。

### 含まないもの
- 送った後の記録を研究者側で消す道具（台帳に手順を書くだけ）。
- どけた回数（条件 4・手跡の PR 6）、`S1ConsentPanel.tsx`（条件 6）、事前登録（条件 8・9）。
- Windows の手跡（窓が無い）。
