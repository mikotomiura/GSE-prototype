# secrets-filter の引用符バイパスを塞ぐ

## 背景

★ **`scripts/secrets-filter.sh` の fail-closed が、引用符つきファイル名に対して開いていた。**
⚠️★★★ **5 セッション連続で未着手だった項目**（★ 引き継ぎ `next-session-after-adr027.md` 第一候補）。

★ **git は非 ASCII を含むファイル名を C-quote して引用符で囲む**（★ `core.quotepath` の既定は `true`。
★ 本機は**未設定 ＝ 既定**なので、⚠️ **常にこの形になる**）:

```text
diff --git "a/docs/.../[\346\217\220\346\241\210...]GSE\350\250\255\350\250\210...pptx" "b/..."
```

⚠️ 一方フィルタの判定は **行末 `$`** に依存していた:

| 判定 | 実装 | 引用符つきだと |
|---|---|---|
| proprietary 拡張子 | `\.(pdf\|docx\|xlsx\|pptx)$` | ⚠️★★★ **末尾が `"` なのでマッチしない** |
| `.env` / `.pem` / `.key` | `\.(env\|pem\|key)([[:space:]]\|$)` | ⚠️★★★ **同上** |
| `.ndjson` | `\.ndjson([^a-z0-9_]\|$)` | ★ `"` が `[^a-z0-9_]` に当たるので**塞がっている** |
| `credentials` / `secret` | 部分一致 | ★ 影響なし |

## ★ 一次の実測（★ 2026-09-08・陽性対照つき）

| # | 条件 | rc | ハンク除去 | ⚠️ 本文の流出 |
|---|---|---|---|---|
| **①** | ★ **実物**（作業ツリーの日本語名 `.pptx` / `.pptx.md`） | ⚠️★★★ **0（素通り）** | **0 件** | ⚠️★★★ **追加行 257 行がそのまま出力に残った** |
| **②** | ★ **陽性対照**: ASCII 名の `.pptx` | **2** | 1 件 | ★ 消えた |
| **③** | ★ ②と**同じ内容で名前だけ引用符つき** | ⚠️ **0** | 0 件 | ⚠️ **残った** |

→ ★★★ **違いは引用符の有無だけである。**★ 実装が仕様（`docs/external-skills.md`「pdf / docx / xlsx / pptx は
送信禁止」）を満たしていない。

⚠️★★★ **既存テストが見逃していた理由**: `secrets-filter-test.sh` の該当ケース
（`diff --git a/R.PDF b/R.PDF` / `diff --git a/x.env b/x.env`）は
★ **引用符なしの形しか試していない**。→ ★ **検査の「入力の形」が実物と違っていた。**

## ゴール

- ★ **引用符つきファイル名でも proprietary / `.env` / `.pem` / `.key` のハンクが除去される。**
- ★ **Done は exit code で言える**:
  1. `bash scripts/secrets-filter-test.sh` → **rc=0**（★ 引用符つきの陽性対照を足したうえで）
  2. 実物の diff（日本語名 `.pptx`）を通して → **rc=2 かつ本文が出力に残らない**

## スコープ

### 含むもの
- ★ `diff --git` ヘッダの判定を**引用符に影響されない形**にする
- ★ `secrets-filter-test.sh` に**引用符つきの陽性対照**を足す（⚠️ 陰性対照も保つ）
- ★ 実物の diff で再実測する（⚠️ 合成テストだけで済ませない）

### ⚠️ 含まないもの（★ スコープ外・別論点）
- ⚠️★★★ **`.pptx.md` / `.docx.md`（proprietary 資料の Markdown 版）を送信禁止に含めるか** ——
  ★ **これは仕様変更であって、本タスク（実装が仕様どおり動いていない）とは別の判断である。**
  ★ 実物 `[提案プロジェクト補足資料]GSE設計スライド.pptx.md` は **中身が pptx の本文そのもの**だが、
  現行仕様（`docs/external-skills.md`）は拡張子 `.pdf/.docx/.xlsx/.pptx` だけを禁止している。
  → ★ **研究者に判断を仰ぐ。**★ 本タスクでは触らない。
- ⚠️ **フィルタを弱めない**（★ 既存コメント `:64-73` の設計哲学 —— over-block の解き方は
  「フィクスチャ側を `_00000000_` 形式へ寄せる」であってフィルタを緩めることではない）。
- ⚠️ 多行 secret / base64 断片 / URL query 内の値（★ 元から「第一段フィルタのみ」と宣言済み）。

## 受け入れ条件

- [ ] ★ 引用符つき `.pptx` / `.env` / `.pem` / `.key` / 大文字拡張子が **rc=2 で止まる**
- [ ] ★ 実物の diff で **rc=2 かつ本文が残らない**
- [ ] ⚠️ **陰性対照が壊れていない**（★ ふつうのコード・架空セッション名は 1 バイトも変わらない）
- [ ] ★ `scripts/secrets-filter-test.sh` が **rc=0**
- [ ] ★ `code-reviewer` ＋ `security-checker` → **`/cross-review`（★ Codex 使用の許可あり）**

## 運用メモ
- /reimagine 適用: **No**
- 理由: ★ **直し方が自明**（★ 判定の終端を `.ndjson` と同じ `([^a-z0-9]|$)` に揃えるだけ）で、
  複数の実装案が競合しない。⚠️ アーキテクチャ判断も外部 API 定義も伴わない。
