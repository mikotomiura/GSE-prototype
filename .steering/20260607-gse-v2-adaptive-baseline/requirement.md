# gse-v2-adaptive-baseline — タスク別 baseline (β) の汚染耐性つき緩やか適応

## 背景

`need` の計算は `need = p_stuck`（`intervention.rs:172`）であり、その `p_stuck` は
Friction/Engagement 軸 → `phi(x, β)` 正規化（`features.rs:40`）→ **β (baseline)** に依存する。

現状の β は **母集団レベルのハードコード定数**で、IME 状態による 2 値切替のみ:

| context | β_F1 | 由来 |
|---|---|---|
| coding (ime_open=false) | 150ms | Dhakal et al. 2018 母集団中央値 |
| writing (ime_open=true)  | 100ms | 実セッション較正 (2026-03) |

このため、打鍵速度が母集団値から外れる個人・タスクでは φ の**原点が系統的にズレる**:

- 遅いが流暢な人 (F1≈230ms): 流暢時でも friction に底上げ (0.25·φ1≈0.067) が乗り、
  engagement が抑制 → Incubation/Stuck 方向へ系統バイアス → `p_stuck` 過大 → **need 過大 → 偽介入**。
- 速い人 (F1≈120ms): φ1 が 0 に張り付き、本人比の詰まりを取り逃す（**検出漏れ**）。

コード自身がこれを未実装の future work として認めている:
> `engine.rs:289-290`: "Both sets are population-level estimates; future work can adapt
> them per-session using EWMA updates (update only the matching β when IME state is known)."

ユーザー提起の素案は「GSE 起動直後 (first step) でタスク基準を確定する」だったが、
single-shot 確定には **baseline 汚染**（冒頭がたまたま苦闘だと、その遅さが基準に焼き付き
以後その苦闘を永久に正常化＝検出不能化する）という思想レベルの自己矛盾リスクがある。
GSE は「生産的苦闘を守る」のが目的なので、守るべき信号を基準が飲み込むのは致命的。

→ 単発確定でなく、**苦闘サンプルを除外しながら緩やかに収束させる適応 (A+C)** を採る。

## ゴール

`need` 計算式・HMM・25+1 ビン・閾値・axes EWMA は変えず、その入力である **β を
「母集団固定値」から「汚染耐性を持たせた本人・コンテキスト基準」へ置き換える**。
これにより φ の原点が本人基準に合い、偽介入と検出漏れの双方を低減する。

## スコープ

### 含むもの
- **A. 緩やか β 適応**: context ごとに β を状態変数化し、遅い EWMA (α≈0.02-0.05) で更新。
- **C. 頑健統計 + 更新ゲート**: β はローリング窓の低位パーセンタイル / trimmed mean で推定し、
  更新は `p_stuck < GATE` の「流暢サンプル」のみから行う（汚染対策の本体）。
- **κ / バンドモデル再設計**: β を動かすと φ の飽和点 `β·(1+κ)=3β` がズレ、感度レンジが
  変化する。比例モデル (`κ·β`) 維持 + κ 微調整か、固定バンド (`C`) への変更かを決定する。
- warmup / cold-start 中の β 既定値と挙動の定義。
- オフライン検証（`gse-replay` 等）での before/after 比較。

### 含まないもの
- `need = p_stuck` の定義変更、HMM 構造・遷移行列の変更。
- 介入閾値 (NUDGE 0.60 / WALL 0.70) の変更。
- 新規 OS フック・入力経路の追加（analysis 層に閉じる）。
- UI への baseline 可視化（別タスク）。
- β の永続化（セッション跨ぎ学習）— 今回はセッション内適応に限定（要相談）。

## 受け入れ条件

- [ ] β が context ごとに状態変数化され、流暢サンプルのみから緩やか EWMA 更新される。
- [ ] 苦闘サンプルが β を汚染しないこと（更新ゲートのテストで保証）。
- [ ] β 適応に伴う感度レンジ変化に対し、κ/バンドモデルの方針が決定・実装されている。
- [ ] warmup 中の β 既定値と挙動が定義され、cold-start で破綻しない。
- [ ] 既存のオフライン検証で、遅い人/速い人の合成または実データで原点バイアスが減ることを確認。
- [ ] 既存テストが緑、analysis 層に OS 依存を持ち込んでいない。

## 未決の設計論点（Plan で詰める）

1. **タスク境界の単位**: session 開始 / IME context / window フォーカス — β の保持単位を決める。
2. **更新ゲート閾値** `GATE`: 「流暢」とみなす `p_stuck` 上限。
3. **κ / バンドモデル**: 詰まりは「絶対 ms の遅れ」か「本人比の遅れ」か（比例 vs 固定バンド）。
4. **適応速度** α_slow と頑健統計のパーセンタイル / 窓長。
5. β 永続化（セッション跨ぎ）の要否。
