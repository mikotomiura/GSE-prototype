- 実施: Drive for desktop の同期フォルダで移した。スプレッドシートは ID を保ったまま `文献DB` の下に入った（Drive の API で親が `文献DB` になったことを確かめた・URL は変わらない）。`作業` で `--verify` が「揃っている」。

## 判断 17（2026-10-18・研究者・AskUserQuestion・xlsx で 1 つにまとめる）

- 研究者の問い「xlsx形式にしてから全部を一つにまとめるのは無理なの？」への答え: 表にかかわるもの（一覧・書誌・説明）は 1 つの xlsx にできる。.bib（LaTeX と pandoc が読むファイル）と検索のページ（Web ページ）はファイルとして別に要る。xlsx を Drive で変換して本体にすると、作り直すたびに新しいスプレッドシート（新しい URL）になる。既存のスプレッドシートを xlsx で上書きして ID を保てるかは確かめていない（手元の Drive のツールではできない）。
- 研究者の答え（推奨どおり）: ねらいは「フォルダの中を減らす」。`文献DB` には、スプレッドシート（本体・URL はそのまま）・`GSE文献DB.xlsx`・`GSE文献DB.bib` の 3 つだけを置く。CSV・`.csl.json`・`.html`・manifest は `文献DB/作業` に置く。
- 決めたこと（メイン）: `.bib` は BibTeX の 1 本にした。論文の原稿 2 本が BibTeX を使う（IME の論文 `papers/ime-observation/manuscript/main.tex` は sn-jnl の `\bibliography`、C の外枠は natbib の `apalike`。どちらも 2026-10-18 に grep で確かめた）。`文献DB` に置く 2 本は日付の無い名前で上書きし、日付つきのものは `作業` に残す（作り直しでフォルダが増えない）。
- 実装: `build.py` が `GSE文献DB_<日付>.xlsx`（シート: 説明・一覧・書誌）を作り、manifest のハッシュに載せる。`--deliver <文献DB>` で xlsx と BibTeX を写す。`=` で始まる文字列は xlsx で数式にしない（文字列として置く）。openpyxl は `scripts/requirements-dev.txt` に版を固定して足し、`~/.venvs/gse-provision` に入れた。CI では同じ版を入れて xlsx のテストも走らせる。
- 実データ: 906 行の一覧・906 行の書誌（BibTeX の欠けは 0）。Excel のセルの上限（32,767 字）に対して最長は 3,102 字（接地）。Quick Look で説明のシートを見て、数が広い列の右端に隠れていたのを文字で置くように直した。
- 途中で踏んだこと: Sheets の MCP は大きな返り値を `.txt` に保存するため、`--keep` が JSON を CSV と読み、`key` の列が無いとして止まった（判断 11 の止まる形が働き、何も書かなかった）。中身で JSON を見分けるようにした。
- `文献DB` から、判断 16 で写した日付つきの 4 本（`.html`・`.csl.json`・`.bib` 2 本）を消した（`作業` の同じもの と 1 バイトずつ同じことを確かめてから・Drive のゴミ箱に入る）。

## 判断 18（2026-10-18・メイン・/cross-review（xlsx の回）への対応）

Claude と Codex の両方が回った（Codex は台帳の今日の記帳が 3 → 4 回に増え、新しい出力ファイルを読んだことを確かめた）。採用して直したもの:

- **xlsx のセルの上限（両者一致）**: openpyxl は 32,767 字を超えた分を黙って切り、manifest のハッシュも `--verify` も通っていた（再現済み）。超えたら、シート・行・列を示して止める。いまのデータの最長は 3,102 字。
- **`--deliver` の新旧の混在（両者一致・Codex）**: `--no-bib` / `--no-xlsx` と一緒だと前の回のものが渡し先に残っていた。一緒に使えないとして止める。`deliver()` 自身も、片方が無ければ何も写さない。2 本を一時の名前で写し終えてから入れ替え、途中で止まっても一時のものを消す。直した最初の版は、一時のファイルを写した後に覚えていたので、写す途中で止まると一時のファイルが残った。足したテストがこれを見つけた。
- **制御文字（Claude）**: 1 セルに混じるだけで xlsx 全体が例外で作れなかった（再現済み）。外して `xlsx_removed_control_chars` に数える（いまのデータでは 0）。
- **引用キーの再衝突（Claude・低）**: 末尾を足しても重なるときは番号を足す。
- **`--keep` の JSON の見分け（Claude・低）**: JSON とみなして読めなかったとき、そうみなした理由を示す。

採用しなかったもの:
- **xlsx のバイト列を毎回同じにする（Claude・低）**: 作成と更新の時刻を固定したが効いていなかった。openpyxl は保存のたびに更新の時刻を今に書き換え、zip の各項目にも時刻が入る。足したテストは 2 回の実行が同じ秒に入って通っていただけだった。zip を書き直すほどの価値は無いので、固定のコードとテストを外した。README に「xlsx のバイト列は回すたびに変わる。同じ入力かどうかは CSV のハッシュで見る」と書いた。

変異: 直した所を 1 つずつ壊した。上限・制御文字・一時のものの掃除・再衝突・`deliver()` の欠けの検査は赤。引数の組み合わせの検査は、`deliver()` 自身の検査が同じく止めるので、壊しても緑のまま（二重の守り）。途中で、壊す置き換えが同じ文字列の別の箇所（`keep_map` の `if lacking:`）に当たって「生き残り」に見えたことがあり、置き換え先を確かめて取り直した。テスト 40 本（openpyxl の無い python3 では 7 本を飛ばす）。
