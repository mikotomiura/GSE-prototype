# 設計（再生成案 v2）

requirement.md だけから組み直した案。仮説の文面「人ごとの違いではなく、構造の足りなさを人ごとに補っていた」を、2 つの部分に割って、それぞれに見分ける仕掛けを付ける。

- 部分 1（足りなさが原因）: 上積み G は、その構造が前の記号への依存を運べない量（足りなさ D）に沿って動く。母数の数ではない。
- 部分 2（人ごとの違いではない）: 本人の当てはめが共通に勝つのは、その人に固有の何かを捉えたからではない。それなら、他の人の本人の当てはめを w に当てても、共通に勝つはずである。

## 1. アプローチ

### 1.1 量 3 つ（書き手 w ごと・評価の単位の 1 記号あたりの対数尤度）

- G(s) = 本人_w(s) − 共通_w(s)。本人は τ 他人で選んだ τ。共通は w を除く共通。
- D(s) = r1_w − 共通_w(s)。r1 は w の学習の記号の 1 次のマルコフ（閉じた形・構造の集まりに依らない）。正なら、その構造の共通が 1 次のマルコフに届かない量。選びの段を持たないので、w の値が選びに漏れる道が無い。
- S(s)（他人の当てはめ）= 他人_v→w(s) − 共通_w(s) の、v（w と同じパネル・同じ k の他の書き手）についての中央値。他人_v→w は、v の本人の当てはめ（v について τ 他人で選んだ τ）の母数で w の評価の単位を予測した値。新しい当てはめはせず、評価だけ。

### 1.2 対照の列（並べ替え）

- 各系列の中で行の順を一様に並べ替えた列。記号の頻度と長さは保たれ、前の記号への依存は消える。同じ構造・同じ列のまま D だけが動くので、母数の数をそろえた比べになる。
- 乱数は EM と別の流れ（`[SEED + 41, データ, 書き手, 単位, 系列]`）。並べ替えは行に当て、3 列で同じ。

### 1.3 読みの形（結果を見る前に決める・閾値と検定は置かない）

主のセル: CoAuthor P15 の k = 5・15、P30 の k = 30。各セルで、構造 s・列 q ごとに、そのまま（o）と並べ替え（p）の組を作る（6 × 3 = 18 組）。

- 部分 1 の読み（対の比べ・母数をそろえる）: 各組で、ΔD = D_o − D_p と ΔG = G_o − G_p の符号を見る。hmm3 の 3 組（3 列）で ΔD > 0 かつ ΔG > 0 で、ΔG が G_o の半分より大きい → 「足りなさが消えると上積みも消える」。hmm3 で ΔD > 0 なのに ΔG ≤ 0 → 「上積みは足りなさに沿わない」。
- 部分 2 の読み: そのままの列の hmm3 で、S が正で、G と同じ桁（G の 1/10 より大きい）→「他の人の当てはめでも共通に勝つ・人ごとの違いとは言えない」。S が負、または G の 1/10 以下 →「上積みは本人の当てはめに固有」。
- 全体の形:
  - 形 A（仮説と合う）: 部分 1 が「消える」かつ部分 2 が「他の人でも勝つ」。
  - 形 A'（足りなさは効くが人ごとの違いもある）: 部分 1 が「消える」かつ部分 2 が「本人に固有」。
  - 形 B（対抗の説明と合う）: 部分 1 が「沿わない」。
  - 形 C: 主のセルで割れる → 値を並べ、分けられないと書く。
- 構造をまたぐ並び（6 構造の D と G の順位の相関）は記述として出すだけで、形の判定に使わない（構造をまたぐと母数の数と D がいっしょに動き、対抗の説明と見分けられない）。
- CS1 は同じ形を当てるが、前の試験で hmm3 の G がもともと小さいので、別に書く。

## 2. 変える所（前の試験のコードから）

- 列: feat 行の ewma_x・ewma_y から q × q + 1 記号（q ∈ {3, 5, 7}）。engine.rs と同じ式（floor・上は q − 1・負は 0）、obs = 25 の行は q²。門 P-Q: q = 5 で全行が obs と一致。
- 構造: hmm3・hmm6・hmm10・ar1・ar2・ar3 を当てはめる。放出の幅を列に合わせる。
- k: P15 {1, 5, 15}・P30 {30}・C5 {1, 5}。作らない k と折り目の乱数は同じ位置で引いて捨てる（P-REPRO のため）。
- 行: τ 固定の 9 行と τ 他人だけ。最頻値・τ 本人 CV・2 段・K 本人 CV は作らない。
- 他人の当てはめ（新）: 書き手ごとの処理が、τ 他人の選びの後で使う本人の母数を返し（`keep_fits`）、親の処理で全組（v, w）の評価をする。母数は repo の外へも書かない（メモリの中だけ）。
- 実行: 列 × 順の 6 組を順に。組ごとに summary を書く。
