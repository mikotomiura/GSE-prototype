# W-3 を裁く —— 意味フィールドの組が変わらない間、チャネルが生きていることをどう示すか

## 背景

★ **`W-3` は ADR-027 D6 が名指しで起票した未決である**（2026-09-08）。
⚠️★★★ **ADR-027 が作った穴ではない** —— ★ 逐語「**D1 が『変化時のみ発火』を維持したことで *可視化された* 穴である**」。

### ⚠️ 一次の不足（★ ADR-027 Context 5 の実測をそのまま引く）

| 何 | 逐語 / 実測 |
|---|---|
| `ADR-017` D2 再接続の意味論 項目 4 | 「⚠️ **一定時間 `epoch` が更新されなければチャネルを失効させ、層 0 へ縮退する。**」 |
| ⚠️ 同 D2 の表の `epoch` の定義 | 「★ **チャネルの世代**。⚠️ **PC 再起動 / 再ペアリングで新しくなる**」 ＝ ★ **変わらないのが正常** |
| ⚠️ 同 D2 項目 1 | 「★ **`epoch` が変わったら `seq` の比較を打ち切り、初期同期からやり直す。**」 ＝ ★ **周期更新は初期同期の連発になる** |
| `ADR-021` D9 | 「★ **実装への義務**: **`evidence_quality` が閾値を下回る間、PC は liveness を更新しない**」 |
| ⚠️★★★ 実測（2026-09-08・本タスクで再確認） | ★ 表現文脈の docs で `liveness` は **5 箇所のみ**ですべて D9 由来。⚠️ **更新機構の定義は 0 件**。★ `src-tauri/src/input/liveness.rs` は**フックの生存監視**で別物 |

→ ⚠️★★★ **項目 4 の「`epoch` が更新される」が何を指すのかは、一次では確定できない。**

### ⚠️★★★ 露出している逆説

★ **長い `stable`（＝ 設計が守りたい状態）ほどイベントが出ず、断と区別できない。**
→ ⚠️ **受信側が「最後の受信からの経過時間」で失効を判定すると、静かなほど層 0 へ落ちる。**

### ★ なぜ「失効させない」で逃げられないか

★ `expression-channel.md` §2.3 制約 3 / 4 が塞いでいる:

- 制約 3 逐語「★ **チャネル不在でも表現が成立する** —— 途切れたら **層 0（状態に応答しない基層）へ縮退**する」
- 制約 4 逐語「⚠️ **チャネルが無い間のフレームを捏造しない**（★ 離席ギャップの既定 180 秒と同じ理由）」

→ ★ **断の検出そのものを諦める道は無い。**

## ゴール

★ **`W-3` を閉じ、`W-1`（wire protocol）が書ける状態にする。**
⚠️★★★ **ADR-027 D6 は「`W-1` の wire protocol ADR で裁く」と書いたが、本タスクは `W-3` を先に閉じる** ——
★ 理由は、⚠️ **ADR-027 自身が「`W-1` は `W-3` を閉じずに書けない」と書いており、
そのまま読むと循環する**ためである。→ ★ **`W-3` が *制約* を決め、`W-1` が *機構* を選ぶ、と順序を明示して断つ。**
