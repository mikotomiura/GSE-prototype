# 研究者の判断

Claude の作業（草稿・確かめ・レビューの対応）は design.md に置く。

## 判断 1: タスク名と進め方

- **判断日時**: 2026-10-21（研究者・AskUserQuestion・推奨どおり）
- **採用**: タスク名は `handmark-input-adr`。`/reimagine` は使わない。
- **理由**（Claude が示したもの）: 中身は `20261020-handmark-multi-input` の判断 7・9・12 でほぼ決まっていて、ADR はそれを文書にする作業。

## 判断 2: ADR の番号とステータス

- **判断日時**: 2026-10-21（研究者・AskUserQuestion・推奨どおり）
- **採用**: ADR-040・Proposed。実物への持ち込みのタスクで見直す。
- **番号の確かめ**: `git fetch` の後、origin の全枝とローカルの全枝の `docs/adr/` に ADR-040 以降は無かった（最新は ADR-039）。
- **理由**（Claude が示したもの）: 実物への持ち込みと Windows の実測がまだ。ADR-038・039 と同じ扱い。

## 判断 3: ADR-025 D1 をこの ADR で手跡の入力に当てる

- **判断日時**: 2026-10-21（研究者・AskUserQuestion・推奨どおり）
- **背景**: ADR-025 の Accepted の射程は層 A だけで（D2）、PC 側の面は `expression-channel.md` §8 の E-11 で未決。
- **採用**: 手跡の入力（カーソル・クリック・ホイール）から出た値を数で返さないことを ADR-040 の決定に含める。E-11 全体は閉じず、手跡の入力に限ると書く。
- **退けた案**: ADR-025 を参照するだけにし、射程の拡張は E-11 に残す（決定が弱くなる）。

## 判断 4: ホイールは、O1 の記録の経路を通さずに取れない OS では使わない

- **判断日時**: 2026-10-21（研究者・AskUserQuestion・推奨どおり）
- **背景**: ホイールは両 OS とも繰り返し読む方法がなく、イベントを取る仕組みが要る。Windows の Raw Input の受け先は 1 プロセスで装置の種類ごとに 1 つの窓で、O1 の `observe_windows.rs` がすでに使っている（`20261020-handmark-multi-input` design.md §2b）。
- **採用**: 実物へ入れる条件を「O1 の受け先を奪わず、O1 の記録の経路と同じ場所を通らずに取れること」にする。満たせない OS ではホイールを使わない。
- **退けた案**: O1 の受け先で受けた値を表現へも分ける（記録と表現が同じ場所を通り、境界の検査を O1 のコードにも広げることになる）。条件を ADR で決めず、実物のタスクに残す。
- **実物のタスクに残るもの**: 各 OS で条件を満たして取れるかの確かめ。

## 判断 5: ADR の射程は手跡の背景の層だけ

- **判断日時**: 2026-10-21（研究者・AskUserQuestion・推奨どおり）
- **採用**: ADR-040 が許すのは手跡の背景の層の入力だけ。別の表現（層 A・肖像など）で使うときは、この ADR を先例として改めて決める。
- **退けた案**: GSE の表現全般に広げる（確かめていない面まで広がる）。

## 判断 6: 草稿で足した 4 点をそのまま入れる

- **判断日時**: 2026-10-21（研究者・AskUserQuestion・4 点とも選んだ）
- **採用**: (1) 試作の計測のファイルも記録に含める（D2）。(2) Windows の `GetAsyncKeyState` はマウスボタンの仮想キーだけを読み、境界の検査に入れる（D3）。(3) 画面の取り込みは本 ADR で扱わない（Consequences）。(4) 使うボタンは実物で決める（D6）。

## 判断 7: 背景の層の試作の負荷は、人の入力では書かず、合成の入力で測る

- **判断日時**: 2026-10-21（研究者・AskUserQuestion・推奨どおり）
- **背景**: 試作（`spike/handmark-stage`）は負荷を測るために毎秒の描画の回数を CSV に書いている（`handmark_stage_spike.rs` の `TickRecord`・`File::create`）。ポインタで描画が回るようになると、この値は入力の代わりになり、ADR-040 D2（判断 6 の (1)）とぶつかる（`/cross-review` 2 巡目の指摘）。
- **採用**: ポインタを入れた版では、人の手で動かした描画の量を計測に書かない。負荷は、決まった動きを流す合成の入力か、ポインタを切った条件で測る。D2 に例外は作らない。
- **退けた案**: 手元だけ・測った後に消すなら許す（判断 6 に穴が開く）。持ち込みのタスクで決める。
