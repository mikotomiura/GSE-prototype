# probe-card-ui (ランダムプローブ UI を非侵襲な右上カードへ)

## 背景

実機セッション (gse_20260623_055742) で被験者からフィードバック:
- ランダムプローブ発生時に **Wall のように画面前面が占有され、認知状態がかなり邪魔された・驚いた**。
- 原因 (code 確認): `ProbeCard` 自体は右下の小カードだが、プローブ表示中に **全画面オーバーレイ窓が
  前面化し画面全体のクリックを奪う** (`Overlay.tsx:85` `setIgnoreCursorEvents(false)` が窓全体に作用)。
  さらに唐突に出る (アニメーションなし)。nudge も同じ全画面ブロックを起こしている。

## ゴール

ランダムプローブ回答カードを **右上から ぴょこっと スライドインする非侵襲な小カード**にし、
**被験者は作業を続けながら任意のタイミングで回答**できる (カード以外はクリック透過)。被験者を驚かせない。

## スコープ

### 含むもの
- ProbeCard を **右上**に配置 + **スライドイン animation** (gentle / ぴょこっと)。
- **非ブロック化** (ユーザー承認): プローブ/nudge 表示中はオーバーレイ窓を右上の小ボックスに縮小し、
  カード以外を OS レベルでクリック透過。Wall 時のみ全画面ブロックを維持。

### 含まないもの
- 介入判定ロジック (Wall/Nudge トリガー) の変更。
- プローブのスケジューリング・回答記録スキーマの変更 (ProbeCard 送信ロジックは不変)。
- Wall の挙動変更 (全画面ブロックは維持)。

## 受け入れ条件

- [ ] プローブが右上からスライドインし、全画面の白い前面占有が起きない
- [ ] プローブ/nudge 表示中も被験者がカード外で作業継続できる (クリック透過)
- [ ] Wall は従来どおり全画面ブロック (回帰なし)
- [ ] `tsc`/`vite build` 緑・`cargo build` 緑・既存テスト緑
- [ ] 実機 (Win) で驚かせない挙動・クリック透過を確認 (GUI は手元検証)
