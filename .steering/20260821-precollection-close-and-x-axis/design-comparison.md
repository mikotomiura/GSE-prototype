# 設計案比較 (/reimagine) — T-1: 自動終了 × 押下の競合

## v1 の要旨 (`design-v1.md`)

★ 引き継ぎメモの **案 A**。`SESSION_START_MS` を「ブロックの同一性トークン」とみなし、
自動終了スレッドが `compare_exchange(observed, 0)` で**終了権をアトミックに奪う**。
失敗＝その間に新ブロックが始まっていた、として中止する。
加えてアイドル待ちの直後に `SESSION_START_MS == 0` を再確認してから `BlockEnd` を送る。
★ **ロックを 1 つも増やさない**のが最大の利点。

## v2 の要旨 (`design.md`)

★ 守りたいのは値ではなく**順序**（「`BlockEnd` は次の `Rotate` より前に channel へ入る」）
だと言語化するところから始める。→ ⚠️ **1 語の CAS では 2 操作間の順序を表現できない**。
→ **`BLOCK_TRANSITION` Mutex を最外側の直列化点**として置き、
「開始する」の押下と自動終了の臨界区間をそこに通す。
勝敗の判定は純関数 `g1::decide_block_end` に切り出し、
排他を取った**直後**に `SESSION_START_MS` を再照合して `Superseded` なら中止する。

## 主要な差異

| 観点 | v1 (案 A: CAS のみ) | v2 (排他 ＋ エポック照合) |
|---|---|---|
| 守る対象 | ★ **値**（`SESSION_START_MS`） | ★ **順序**（`BlockEnd` → `Rotate`） |
| 「押下が先」 | ✅ CAS 失敗で中止 | ✅ `Superseded` で中止 |
| ⚠️★★★ 「押下が後」 | ❌ **閉じない**（下記） | ✅ 排他で `BlockEnd` の後ろに回る |
| 新しいロック | ★ なし | ⚠️ 1 本（**最外側**・循環不能） |
| 通常運用への影響 | なし | ★ 無競合のロック取得のみ＝**観測可能な挙動は不変** |
| 純関数テストの射程 | ⚠️ 「押下が後」を**表現できない** | ✅ 交錯 2 方向とも決定的にテストできる |
| 待ち時間 | なし | ⚠️ 押下が最大 1500 ms 待つ（★ ブロック境界のみ） |

## ⚠️★★★ v1 が閉じられない理由（★ これが決め手）

`start_session` は `Rotate` / `SessionStart` を**ログのロックの中**で送るが、
`SESSION_START_MS.store(now)` は**ロックを抜けた後**で行う（`lib.rs:2193`）。

→ ★ **「`Rotate` は送られたが `SESSION_START_MS` はまだ 0」という窓が実在する。**

したがってアイドル待ちの直後に `SESSION_START_MS == 0` を確認しても、
⚠️ **その窓の中では 0 のまま通過し**、`BlockEnd` が**新しいファイル**へ `session_end` を書く。
（★ `logger.rs:1744` で `Rotate` が `block_closed = false` に戻すため、実際に書かれる。
⚠️ **コードで確認済み**であって推測ではない。）

★ v1 を救うには `SESSION_START_MS.store(now)` をログのロックの**中**へ移す必要があるが、
それは結局「2 つの操作をひと続きにする」＝ **v2 と同じ排他を、別の名前で導入する**ことである。
⚠️ しかも `log` の Mutex を遷移の排他に流用すると、
★ **ロックの意味が二重になる**（ログの整合性 ＋ ブロック遷移）ので、後から読む人が壊す。

## ⚠️ v2 の弱点と、その受け止め

| 弱点 | 受け止め |
|---|---|
| ⚠️ 新しいグローバルロックが増える | ★ **最外側**に固定し、自動終了スレッドは `log` の Mutex を**取らない**（`Sender` clone を持つ）ので**循環を作れない**。順序をソース走査テストで固定する |
| ⚠️ 押下が最大 1500 ms 待つ | ★ 起きるのは**ブロック境界だけ**。⚠️ しかもその待ちは「押下を待たせている」のではなく「**押下が壊れないように待たせている**」時間である |
| ⚠️ 通常運用（非 G1）も同じコードを通る | ★ 自動終了スレッドは `if g1_mode().is_some()` の中でしか spawn されない → **他に取る者がいない＝無競合**。観測可能な挙動は 1 バイトも変わらない |

## ★ 推奨: **v2**

⚠️★★★ 受け入れ条件に「**交錯の 2 方向をそれぞれテストで固定する**」がある。
★ v1 では「押下が後」を**そもそも閉じられない**ので、この条件を満たせない。
→ ★ 選択の余地は実質的に無い。

★ ただし v1 の発想は**捨てない**: 「観測したブロックと同じか」を照合する部分は
v2 の `decide_block_end(observed, current, ...)` として**そのまま生きている**。
⚠️ v2 は v1 の置き換えではなく、**v1 に足りなかった「順序」を足したもの**である。
