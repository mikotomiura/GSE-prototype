# 設計判断と根拠 (2026-08-21)

## R-1 ⚠️★★★ T-1 は「排他」と「照合」の**両方**が要る (案 A は不成立)

### ★ 判断

`BLOCK_TRANSITION: Mutex<()>`（**最外側**の直列化点）＋
純関数 `g1::decide_block_end` による**エポック照合**の**組**を採る。

### ⚠️ なぜ案 A（`compare_exchange` のみ）では閉じないか

★ 守りたい不変条件は**値ではなく順序**である:

> **`BlockEnd` は、次のブロックの `Rotate` より前にログ channel へ入る。**

⚠️ `start_session` は `Rotate` / `SessionStart` を**ログのロックの中**で送るが、
`SESSION_START_MS.store(now)` は**ロックを抜けた後**で行う（`lib.rs`）。
→ ★ **「`Rotate` は送られたが `SESSION_START_MS` はまだ 0」という窓が実在する。**

したがってアイドル待ちの直後に `SESSION_START_MS == 0` を再確認しても、
⚠️ **その窓の中では 0 のまま通過し**、`BlockEnd` が**新しいファイル**へ `session_end` を書く。
★ `logger.rs` の `Rotate` 処理が `block_closed = false` に戻すため、**実際に書かれる**
（⚠️ **コードで確認済み**であって推測ではない）。

### ⚠️ なぜ排他だけでも足りないか

★ 先に排他を取った自動終了が、**既に交代済みのブロック**を閉じてしまう。
→ ⚠️ **照合（`Superseded`）が要る。**

### ★ 交錯 2 方向の閉じ方

| 交錯 | 閉じる仕組み |
|---|---|
| **押下が先** | 排他を取った直後に `SESSION_START_MS` を再照合 → `Superseded` → **中止** |
| **押下が後** | 排他が `BlockEnd` の後ろへ回す → `Rotate` は必ず後 |

⚠️ **`session_active` を見てはならない** —— 実行中の再押下（`RotateForRestart`）は
`true` のまま維持されるので、★ **その経路でだけ気づけない**（Codex HIGH・2026-08-19 と同じ罠）。
→ 照合するのは `SESSION_START_MS`（どちらの経路でも必ず動く）。

## R-2 ★ 「1 バイトも変えない」の**唯一の例外**を、隠さず明記する

### ⚠️ 事実

所見 C の修正（`starved_ms_carried_into_new_window`）は **モードで分岐しない**。
→ ⚠️ **通常運用（非 G1）でも**「セッション実行中に『開始する』を押した」tick で、
`starve_window` のエピソードが **1 本数えられなくなる**。

### ★ なぜモードで分岐させないか

1. ★ 誤帰属は**通常運用でも同じく誤り**である。片方だけ直すと
   ⚠️ **同じ行が読み手のモード知識に依存して意味を変える** ——
   ADR-013 が潰そうとした取り違えの**新種**を作る。
2. ⚠️ `liveness.rs` に G1 の知識を持ち込むことになる（`architecture-rules`）。

### ★ 影響の大きさ（★ 検算した）

変わるのは `starve_window` の `n_lt30` が**最大 1 本**。
⚠️ 当該行は `threshold_gated` で、支えているのは ADR-012 Stage 0 の**形成的な投資判断**
であって確証の判定基準ではない。
★ しかも Phase1 コホート（63 ファイル）には **`starve_window` 行が 1 行も無い**
（計器の追加は収集の 16 日後）ので、⚠️ **既存データの解釈は 1 文字も変わらない**。

## R-3 ⚠️★★★ 所見 C は **1 行では閉じなかった**（★ レビューで判明）

### ⚠️ 最初に書いた案は**効いていなかった**

引き継ぎが指定した直し方はこうだった:

> ★ **直し方は 1 行**: `is_new_block_epoch` が真の tick では、
> `tick()` に渡す `prev_starved_ms` を **0 にする**。

★ そのとおりに `starved_ms_carried_into_new_window` を書いたが、
⚠️★★★ **code-reviewer が実トレースで「ほぼ閉じていない」ことを示した。**

理由: `step()` が `starved_ms` を 0 に落とすのは
**打鍵が届いた tick**か**非計測になった tick**だけである。
★ ところが `RotateForRestart` は「開始する」ボタンの **マウス押下**で起きるので、
⚠️ **エポックの tick では `starved_ms` は 0 ではなく増え続けている。**

| tick | 何が起きるか | `prev` | `now` | 結果 |
|---|---|---|---|---|
| N (押下) | マウスなので `step` は進める | 8000 | 9000 | ★ 抑止が効いて計上なし |
| N+1 (打鍵) | ここで初めて 0 に落ちる | **9000** | 0 | ⚠️★★★ **前ブロックの 9000 ms が新窓へ計上される** |

★ 抑止が効くのは「**打鍵がエポックと同一 tick に来た**」場合だけ ＝ ほぼ起きない。

⚠️★★ **しかも私が書いたテストは `now_starved_ms` に 0 を手で渡していた**ので、
★ **配線を 1 バイトも検証していなかった。** —— ⚠️ 「テストが緑だから閉じている」の典型的な失敗。

### ★ 実際に閉じた形（★ +1 行）

`liveness::reset_starvation_at_new_block` を足し、**エポックで累積そのものを 0 に戻す**。
★ これは**通常のブロック境界で `session_active = false` により起きていることと同じ**であり、
⚠️ **再押下経路だけがその例外だったのを揃えるだけ**である。

⚠️★★★ **`peak_starved_ms` は戻さない。** 戻すと復帰行の `starved_ms` が 0 になり、
★ 「**何秒落ちていたか**」という測った量が消える —— ⚠️ **誤帰属ではなく嘘になる。**
（★ code-reviewer は「ピークも揃えよ」と MEDIUM で指摘したが、**ここは採らなかった**。
判断の根拠は `liveness.rs` の doc と専用テストに固定した。）

### ⚠️ 「1 行で終わらないなら捨てる」に抵触しないか

★ 研究者決定は「⚠️ **構造をいじる必要があると分かった時点で捨てて T-2 へ進む**」だった。
→ ★ 実際に必要だったのは **`if` の中の 1 行 ＋ 1 行の純関数**であり、
⚠️ **構造は 1 つも変えていない**（`tick()` の引数も既存テストも触っていない）。
→ ★ **範囲内と判断して閉じた。**

### ★ テストも作り直した

⚠️ 「`now` を手で渡す」形をやめ、**`step` → `reset` → `carried` → `tick` の鎖を実際に回す**
補助を書いた（★ `lib.rs` の 1 Hz ループと同じ順序）。
★ 併せて**対照**（エポックが無ければ同じ入力で 9000 ms を数える）を置き、
⚠️ 「常に `None` でも緑」になる空振りを防いだ。

→ ★ 人が適用し忘れられる形のままでは 3 件目が起きる。

### ⚠️ ADR-013 の判定表に**足したもの**（★ 実装して初めて要ると分かった）

|---|---|
