## 0. 何を問うか

揺れの world の L300 で、`res=sub` の候補が赤になった（c100 で 12 本中 10 本、c200 で 9 本）。前のタスクの notes の「赤の数値の確かめ直し」から、赤には 2 つの読みが残る。

- 読み 1: 描画が、A_speed に無い停滞の手がかりを運んでいる。
- 読み 2: A_speed の中にある手がかりのうち lr が線形には取り出せない形のものを、描画の特徴が lr に取り出せる形で運び直している（c100 の hgb の上乗せは +0.014 以下）。

このタスクは次の 2 つを問う（引き継ぎ §3 の 1）。

- **問い (a)・攻撃者の能力の差**: A_speed の特徴に非線形の変換を足した lr（以下 `lrbin`）を基準にしても、赤の候補の上乗せは 0.03 を超えて残るか。
- **問い (b)・推論の元の特徴**: 赤の候補の描画の特徴から `r_absdiff`・`r_sd`（と前の窓の差 `d1_`・`d2_` の同じ量）を落とすと、上乗せは消えるか。

材料として、前のタスクの `e13.json` から読める次の事実を design の前提に置く（固定の前に見た値・結果の前の見込みの材料）。c100 の `S-raw-ground-sub` の上乗せは full/lr +0.070・small/lr +0.027・full/hgb +0.014・small/hgb +0.003 で、赤は full（前の 2 窓との差を含む）の lr が運んでいる。c200 では同じ候補で full/hgb +0.041・full/lr +0.062・small/hgb +0.023・small/lr +0.025。

### 1.3 問い (a): 変換した基準 `lrbin`

- **変換**: A_speed の L300 の特徴（33 列）のそれぞれを、分位で 10 個のビンに分けた one-hot と、元の値（標準化）を並べる。分位の境目は当てはめの訓練の側だけで決める（`GroupKFold` の各折りの中・`sklearn` の `KBinsDiscretizer(n_bins=10, encode="onehot-dense", strategy="quantile")`、同じ値の境目は落とす）。欠けた値は前と同じく中央値で埋めてから変換する。その後に `StandardScaler` と `LogisticRegression(max_iter=2000)`（前と同じ既定の正則化）。
- **基準**: `S_bin` = 変換した A_speed だけ。**B**: `S_bin` ＋ 描画の特徴（full なら窓の 20 ＋ 前の 2 窓との差、small なら窓の 20・どちらも変換しない）。上乗せ = AUC(B) − AUC(`S_bin`)。攻撃者は `full/lrbin`・`small/lrbin` の 2 通り。
- **記述の変種** `lrbin2`: 描画の特徴にも同じ変換を掛けたもの（B の側も非線形に使える lr）。判定の読みには使わず、記述として並べる。
- hgb（全体に非線形・交互作用も使える）は、作り直しの列での full/hgb・small/hgb の値（§1.5 で前の値と一致するもの）を並べる。c100 の hgb は A_speed で AUC 0.930 に届いており、余地が小さいことを併記する。

### 1.4 問い (b): 特徴を落とす

描画の窓の特徴（`stage.FEAT_NAMES` の 20・`a_` と `r_` それぞれ 10）から、次の組を落とす。full では前の 2 窓との差（`d1_`・`d2_`）の同じ量も落とす。

| 組 | 落とす量 | full で落ちる列 | small で落ちる列 |
|---|---|---|---|
| `R2`（主） | `r_absdiff`・`r_sd` | 6 | 2 |
| `Rall` | `r_` の 10 量すべて | 30 | 10 |
| `A2`（比べ） | `a_absdiff`・`a_sd` | 6 | 2 |

- 基準は落とさない（A_speed のまま、`lrbin` では `S_bin` のまま）。
- 攻撃者: 元の 4 通り（`full/lr`・`small/lr`・`full/hgb`・`small/hgb`）と `full/lrbin`・`small/lrbin`。
- `A2` は、同じ数の列を `a` の側から落とした比べで、「どの 2 量を落としても上乗せが減る」のか「`r` の揺れの 2 量が特に効く」のかを見分ける材料にする（記述）。
- PC-stall は `r` を 0.5 の定数にしている（`stage.series`）ので、`R2`・`Rall` を落としても PC-stall の上乗せは変わらない見込みで、`A2` では減りうる。PC-stall は §3 の検出器の条件にだけ使う。

## 3. 読み方（固定する節）

### 3.1 量

変種 V（`lr`・`hgb`・`lrbin` と、それぞれの落とす組）と名前 n ごとに、V の攻撃者（full と small の 2 通り）の上乗せの点推定の最大 `gain_max`、95% 区間の下限の最大 `lower_max`、上限の最大 `upper_max` を出す。最大は full と small の 2 通りの中で取る（前の判定の「攻撃者の最大」と同じ形で、分類器は混ぜない）。

### 3.2 検出器の条件（候補ごと・変種ごと）

候補 c の読みは、同じ変種で次の 2 つを満たすときだけ行う。

- `PCs-c` の `lower_max` > 0.03（前の design の `pc_stall.lower`）かつ `gain_max` ≤ 0.08（同 `pc_stall.upper`）: その変種でも、0.03〜0.08 の大きさの PC-stall の型の漏れを拾える。上限は前の `judge` の `stall_ok` と同じで、PC-stall の漏れが大きすぎて 0.03 付近の感度を示さない場合を外す（`/cross-review` 1 巡目）。
- `PC0-c` の `upper_max` < 0.03（`e13.margin`）: 停滞の無い土台が持ち上がっていない。

満たさないときは「読めない（検出器）」とする。前の design の天井の規則（AUC(A_speed) ≥ 0.90 の分類器を外す）は、このタスクでは使わず、代わりにこの条件で余地を確かめる（理由は §9 の 3）。AUC(基準) は変種ごとに必ず並べる。前の `judge` の条件のうち、強い対照 PC1 の条件はこのタスクでは使わない（PC1 を当てはめない・§1.2）。

最大は、どちらかの攻撃者の値が NaN なら NaN とし（Python の `max` は 2 番目の NaN を落とすので使わない・`/cross-review` 1 巡目）、NaN を含む比べは偽にする: 候補は「決まらない」、PC-stall か土台なら「読めない」になり、「残る」「消える」には入らない。

**この条件が保証する範囲**（`/cross-review` 1 巡目）: PC-stall は描画の `r` を 0.5 の定数にし、停滞の手がかりを `a` の側のブロックの値で運ぶ（`stage.series`）。したがってこの条件が示すのは「その変種で、`a` の側に入った PC-stall の型の 0.03〜0.08 の漏れを拾える」までで、候補自身の特徴（とくに `r` の側）が運ぶ手がかりへの感度を保証しない。また (b) の `R2`・`Rall` の落としでは、PC-stall と土台の特徴は構造上変わらない（`r` が定数なので、落とした列はもともと情報を持たない）。そのため (b) の `R2`・`Rall` の検出器の条件は、落とさない変種の条件を引き継ぐだけで、落とした後の感度を独立には確かめない。`A2` では PC-stall の手がかりそのものを落とすので、「読めない」になりうる。

### 3.3 候補ごとの読み

- **残る**: `lower_max` > 0.03。
- **消える**: `upper_max` < 0.03。
- **決まらない**: ほか。

### 3.4 問いへの読み（前のタスクで赤だった `res=sub` の候補について）

| 問い | 変種 | 読み |
|---|---|---|
| (a) | `lrbin` で「消える」 | A_speed の特徴を加法の非線形で使えば、その候補の上乗せは 0.03 未満に収まった。読み 2（攻撃者の能力の差）と矛盾しない |
| (a) | `lrbin` で「残る」 | A_speed の特徴を加法の非線形で使っても上乗せが残った。加法の非線形だけでは読み 2 を説明できない（交互作用か、描画に固有の手がかり）。hgb の値を並べて読む |
| (b) | `lr`（と `lrbin`）で `R2` を落として「消える」 | その攻撃者の上乗せは `r_absdiff`・`r_sd` の系統が運んでいた（落とした量の情報が他の量で代わりに運べなかった） |
| (b) | `R2` を落としても「残る」で `Rall` で「消える」 | `r` のほかの量も運ぶ |
| (b) | `Rall` を落としても「残る」 | `a` の側（か `r` と `a` の組）も運ぶ |

- `A2` の値は (b) の比べとして並べる（`A2` でも同じだけ減るなら、`r` の 2 量が特に効くとは読まない）。
- (b) の「消える」は、落とした量がその攻撃者の上乗せを運んでいた、までである。列を落とせば上乗せは機械的に減りうるので、「`r` の系統にしか停滞の手がかりが無い」とは読まない。§3.2 のとおり、`R2`・`Rall` の検出器の条件は落とさない変種のものを引き継ぐだけであることを、(b) の読みに必ず併記する。
- 判定（緑・赤）の語は使わない。前のタスクの判定は書き換えない。
- 24 本 × 変種の多重の補正はしない（探索的・記述）。段を併せた読みは作らない（c100 と c200 は別々に読む・c200 は前のタスクで探索的と併記した段）。
- `res=sec` の 12 本も同じ表に並べる（前のタスクで緑・変種で上乗せが増えないかの記述）。

### 3.5 結果の前の見込み（推論・固定の時点で書く）

- (a): c100 は hgb の上乗せが小さい（+0.014 以下）ので、`lrbin` でも多くの赤の候補が「消える」か「決まらない」に寄ると見込む。c200 の `raw` の `sub` の 3 本は hgb でも下限が 0.03 を超えたので、`lrbin` でも「残る」と見込む。
- (b): 重要度の上位から、`R2` を落とすと `raw` と `jitter` の `sub` の上乗せは大きく減ると見込む。ただし重要度は上乗せを分けたものではないので、`Rall` まで落とさないと消えない候補もありうる。
- 見込みと違っても、それも結果として書く。

### 3.6 自己検査（`selftest_split.py`・回す前に 0 件の失敗）

- ビンの境目が訓練の側だけで決まる: 試験の側の値だけを変えても、訓練の側の変換の出力が変わらない。
- `KBinsDiscretizer` の同じ値の境目（例えば 0 が多い数の量）で落ちずに通り、列の数が決まる。
- 落とす組の列: `R2`・`Rall`・`A2` で落ちる列の名前が、`checks.feature_names("L300")` の名前で表の数と一致し、ほかの列は値も順も変わらない（変異: 1 列ずらした添字を捕まえる）。
- `lrbin2` は描画の特徴にも変換が掛かり、`lrbin` は掛からない。
- 照合: 合成の小さな `e13.json` で、1e-9 を超える差を 1 つ入れると門が止まる、1e-9 以下なら通る。名前が欠けても止まる。
- 前のタスクの計器のファイルの SHA-256 が `config.json` と合わなければ止まる（陰性対照として 1 バイト変えた写しで止まる）。
- 読み（§3.2・§3.3）の境目: 0.03 ちょうどは「残る」にも「消える」にも入らない。PC-stall の下限が 0.03 ちょうどなら「読めない」。
- 小さな列（P 12）での通しの実行（スモーク）: `run.sh --smoke --step <段>`（seed 20261022・P 12・ブートストラップ 200）で、全体が最後まで回り、`split.json` の形が決まる。スモークは照合の門を通らない（列が違う）ので、`--smoke` のときだけ門を飛ばす（門を飛ばす別の旗は作らない。`--main` は必ず門を通る）。
- `/cross-review` 1 巡目で足した検査: 最大の NaN（攻撃者の順の 2 通りで NaN になり、「残る」にも PC-stall の「読める」にもならない）・門の欠落（作り直しの名前・攻撃者・AUC が欠けると止まる、期待した名前が両方に無くても止まる）・PC-stall の上限（0.08 を超えると「読めない」、ちょうど 0.08 は読める）・乗数（本番の関数 `multipliers` が `checks.e13_target` の作りと一致する）・版（scikit-learn の版が違えば止まる）。
- 揺れの world の当てはめとの一致: 合成の小さな表で、`split.py` の lr・hgb の上乗せと区間が、揺れの world の `checks._fit_job`・`_boot_job` の経路の値と完全に一致する。

## 9. Claude が足した細部（研究者が変えてよい）

研究者が決めたのは判断 1（範囲・列・回す時期）と、引き継ぎ §3 の切り分けの形（(a) 非線形の変換を足した lr を基準にする・(b) `r_absdiff`・`r_sd` の系統を落とす）。次は Claude が足した細部で、固定の前に研究者が変えてよい。

1. (a) の非線形の変換を、分位 10 ビンの one-hot ＋ 元の値にしたこと（スプラインは数の量で同じ値の境目に弱く、2 乗・対数は形を決め打ちにする。ビンは単調でない形も拾う）。変換は A_speed の側だけに掛け、描画の側にも掛けたもの（`lrbin2`）は記述に回したこと。
2. (b) の落とす組を `R2`（主）・`Rall`・`A2`（比べ）の 3 つにしたこと。
3. 前の design の天井の規則（AUC(A_speed) ≥ 0.90 の分類器を外す）を使わず、変種ごとの PC-stall と土台で余地を確かめる条件（§3.2）にしたこと。天井の規則のままだと、c100 で `lrbin` が 0.90 を超えたときに問い (a) がその段で読めなくなる。一方、PC-stall で 0.03〜0.08 の既知の漏れを拾えることを示せれば、少なくとも PC-stall の型の漏れについては、上乗せが 0.03 未満に収まったことを余地の不足では説明できない。ただしこれは候補自身の特徴が運ぶ手がかりへの感度の保証ではない（§3.2 の「この条件が保証する範囲」・`/cross-review` 1 巡目で言い過ぎを直した）。前の `judge` の PC-stall の上限 0.08 は残し、PC1 の条件は使わない。
4. 読みの境目を前の判定と同じ 0.03 にしたこと。
5. 並べ替えの帰無を計算せず、土台 `PC0-<候補>` を床にしたこと（§1.6）。
6. 前のタスクの計器を写さずに import し、SHA-256 で照合すること（§1.1・§1.2）。
