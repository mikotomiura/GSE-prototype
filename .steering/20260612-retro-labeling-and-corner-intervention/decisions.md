# decisions.md

## D-1 v0.2 を破棄せず「較正先行」へ立て付け直す
- **判断**: v0.2 を捨てず、Part B の追加・置換で検証可能化する。ただし**確証的 GT 収集を名乗らず**、スモークは「UI 操作可能性確認＋測定法較正研究」に降格。
- **根拠**: 自分(Opus)と codex の独立レビューが、波形の 4 役兼任(測定対象/cue/判断材料/機能ラベル)による測定法の非独立性に収束。確証主張は審査で容易に折れる。較正で測定法を成立させてから核検証に進む順序が頑健。

## D-2 主観ラベルの confound-free 化を最優先
- **判断**: 較正ブリッジ(リアルタイム申告)+ 時刻のみ cue 条件を主分析へ昇格。波形 cue は補助。
- **根拠**: X と Q1 が同一打鍵由来である循環論法は、波形を見ずに付けたラベルでしか切れない。v0.2 は較正を最小化していたが因果が逆。

## D-3 反証可能性の回復(事前登録 kill 基準)
- **判断**: PreReg-1..5 を `docs/` に凍結。各「どちらでも成果」に閾値を付し、大域 kill(confound-free |r|<0.3)を置く。
- **根拠**: 「どちらに転んでも成果」は反証不能設計。失敗条件の事前明示が検証の前提。

## D-4 統計は順序混合モデル、CV は被験者内 LOSO 主
- **判断**: z 化 Pearson → 順序ロジット混合モデル。LOUO は探索に降格、LOSO(被験者内)を主に。
- **根拠**: 1–5 は順序尺度・反復測定で非独立。個人化モデルを横断汎化で測る LOUO は評価対象の取り違え。n=3–5 は効果量推定フェーズ。

## D-5 介入 UI は「ハード全画面 Wall 廃止 → ソフトコーナー companion」
- **判断**: 全画面ブロック(霧)を廃し、右下アンカーの段階 companion(peek→expand→walk-QR)+ ソフトビネット + 打鍵警告へ。クリック遮断はしない。
- **根拠**: ユーザー要望(大胆グラフィック廃止・右下ひょこっと・QR 散歩導線)。不便益の forcing function は「能動的に QR をスキャンして散歩する」コミットへ移す。Monk/却下で裁定権をユーザーに残す GSE 哲学と整合。
- **確定(2026-06-12 ユーザー承認)**: Lv2 は**ソフトのみ**。ハード全画面ブロックは残さない。強制力は「能動的に QR をスキャンして散歩する」コミット + 画面端ビネット + 打鍵警告に限定。クリック遮断なし。Monk/却下(✕/⏸)で恒久 off・裁定権をユーザーに保持。walk-hard モードは実装しない。

## D-6 却下 UI と研究データの統合
- **判断**: コーナーカードの却下 2 択(✕ 詰まってない / ⏸ 今はもがきたい)を、v0.2 §4 の `InterventionDismiss` ログ源と同一コンポーネントにする。
- **根拠**: UI と GT 収集を二重実装しない。「⏸」押下数は GSE 思想の実証データ(独立指標)。

## D-7 スキーマは既存 DTO ミラー方式に同期追加
- **判断**: `LogEntry` 本体と `schema_dto.rs` の DTO を同期して新バリアント追加 → emit_schema → current.json → CI drift 緑。不変条件は producer 側で強制。
- **根拠**: 既存の schema drift 検知運用(`schema_dto.rs` 冒頭注記)を踏襲。プライバシー境界(本文・タイトル・選択文字列 非保存)を全新規ログで維持。

# v0.3 改訂(2026-06-13) — codex 第2次独立評価で Part B を上書き

> 経緯: 改善案フェーズで codex を独立アドバイザーとして再起動(`.idea/codex_out.txt`)。
> Part B の方向性は是としつつ、**具体策レベルで4点が甘い**と判明。以下 D-8〜D-11 で D-2/D-3/D-4 を上書きする。
> v0.3 設計書本体は `.idea/GSE_事後ラベリングシステム設計書_v0.3.md`。

## D-8 主基準は「ランダム時点リアルタイムプローブ」+ 時間隔離(D-2 を上書き)
- **判断**: confound-free の主データは `realtime_bridge` を**ランダムプローブ化**したもの単独とする。`temporal_only` との合算(B-1)は廃止。
- **時間隔離で P1(申告が打鍵を汚染)を解く**: プローブ時刻 t に対し分析窓は `t−31s〜t−1s`(プローブ前)のみ。`t〜t+60s` は破棄。自己ホットキーは `t−35s〜t−5s`。
- **根拠**: 「中断を消す」のではなく「時間順序で分析対象から隔離」する方が、P1 を構造的に解ける(codex)。プローブは ≤2回/30分・間隔 ≥8分。

## D-9 `temporal_only` を `context_beacon` へ置換(D-2 の cue 設計を上書き)
- **判断**: 時刻・アプリ切替・離席は**状態を推論可能=confound-free でない**。内容非由来の `context_beacon`(5分ごとランダムな色・図形、ログは ID のみ)に置換。`feature_waveform` は GT から降格し「波形読みバイアスの比較条件」に。
- **根拠**: 4役分離を徹底するには cue から状態の漏れを完全に断つ必要がある(codex)。

## D-10 kill 基準は |r|≥0.30 を廃止し「2段ゲート+順序一致度」へ(D-3 を上書き)
- **判断**: `|r|≥0.30`(PreReg-1)は**逆相関でも合格する穴**。廃止。代わりに**測定法ゲート(回答率・再現性)とモデルゲート(順序 C-index)を分離**。
  - モデル Go 候補: 各人 C-index 中央値 ≥0.65・全員 >0.55 / Kill: 中央値 ≤0.55 or 2人以上 ≤0.50 / それ以外 `INCONCLUSIVE`。
- **根拠**: 方向性を持つ妥当性判定が必要。測定法の失敗とモデルの失敗を混ぜない(codex, HIGH-5)。

## D-11 主評価は LOSO でなく「前向き固定 holdout」(D-4 を上書き)
- **判断**: 各人の最初の2セッションで β 較正→凍結→残り8セッションで前向き評価。LOSO/LOUO は探索扱い。
- **根拠**: LOSO も未来セッションで過去を較正する時間リークを含む。前向き holdout が実運用(今日較正→明日使用)に一致(codex, HIGH-4)。

## D-12 Recall はスモークで推定しない / MNAR は除外でなく範囲報告
- **判断**: 独立陽性エピソード <30件 では Recall 点推定を出さない(PreReg-3 の「10件」は過少)。B-4 三層化/B-8 重み付き Recall は P2 以降へ延期。欠測30%超の被験者**除外は廃止**(難しい状態の人が落ち偏り強化)。代わりに未回答を全部高摩擦/全部低摩擦と置いた**上下限を併報**。
- **根拠**: n=3〜5 では Recall は原理的に検出力不足。MNAR は補正でなく感度分析(極端値範囲)が最も堅牢(codex, HIGH-3/MNAR)。

## D-13 呼称を「Ground Truth」→「主観参照ラベル / criterion label」へ
- **判断**: この段階のラベルを GT と呼ばない。設計書・提案書とも criterion label と表記。
- **根拠**: GT を名乗った瞬間に審査で折れる。測定法が較正で成立して初めて妥当性を語れる(codex)。

# v0.3 実装フェーズ移行(2026-06-16) — methodology → 動くコードの落とし込み

## D-14 初回較正スモークは「最小核・計測プラミング先」で実装(実装順の確定)
- **判断**: v0.3(methodology は凍結)を初めてコードに落とす初回スモークの範囲を**最小核**に限定し、**計測プラミングを介入 UI より先**に作る。
  - **IN**: `session_meta` / ランダムプローブ(backend scheduler + `probe_assignment`)/ プローブカード UI(Q1摩擦/Q2前進・skip理由・latency)/ `realtime_label`(時間隔離窓 t−31s..t−1s 含む)/ 尺度ビネット8問 + `vignette_response` / オフライン解析(窓抽出→被験者内 方向付き C-index→2段ゲート→MNAR 上下限→ビネット採点)/ PreReg-1..8 を docs 凍結 + glossary 改訂。
  - **OUT(次段へ延期・明記)**: `context_beacon`・波形 cue ラベル(PreReg-3 比較条件)、`task_checkpoint` 統制課題(機能妥当性は §5.3 通り「**未評価**」と正直に記す)、コーナー介入 UI(Phase4・プラミング後)、Recall 点推定(v0.3 既定で取らない)。
- **実装順**: 0 PreReg/glossary 凍結 → **A schema** → (**B backend scheduler** ∥ **C frontend collect**) → **D 解析** → **E 自己ドッグフード→3-5名**。A が全ブロッカー。
- **技術判断**: プローブ生成は **backend 所有**(「一様ランダム・モデル非依存」を `probe_assignment` で監査証明する必要があるため)。rolling thinning(λ≈2回/30分・gap≥8分・cap≤2回/30分・離席時間は適格から除外)で scheduled/shown を両方ログ。
- **既存資産への注意**: `analysis/metrics.rs` の `ConfusionMatrix`/`precision`/`recall` は **v0.2 流**。v0.3 は「Recall はスモークで推定しない」「z化Pearson→C-index」なので**流用せず**、C-index 系の新解析パスを足す。
- **根拠**: ユーザー判断(2026-06-16, AskUserQuestion)。最短でスモークを一周させ、研究のブロッカー(計測の血流)を先に外す。介入 UI の却下ログ(`intervention_dismiss`)は後から同一コンポーネントで合流できる。
