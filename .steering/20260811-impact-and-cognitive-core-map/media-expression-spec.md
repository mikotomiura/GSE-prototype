> **本書以降、MhD（推論層）の設計議論は行わない**（研究者指示）。MhD の出力は**入力として使うだけ**にする。

## §0 研究者の構想（確定）

> **メディア表現は常時リアルタイムで変動、またはリアルタイムで収集中のデータ駆動型でのアート、
> 波的な役割としての音の出力。**

これを設計語彙に落とすと 3 つの要求である:

| # | 要求 | 設計上の意味 |
|---|---|---|
| **R1** | **常時リアルタイムで変動** | **作業中に存在し、状態に応答する**＝ 案 **α**（`.idea` §2.5.3） |
| **R2** | **リアルタイムで収集中のデータ駆動** | **その場の打鍵から作る**。事後の圧縮再生（β）ではない |
| **R3** | ★ **波的な役割としての音** | **離散イベントでなく連続的なうねり**。オンセット・拍・音高のステップを持たない |

★★ **R3 は文献が特定した「安全な形」と完全に一致している**——
ISE を引き起こすのは **acoustic change ではなく segmentation（分節）**であり、
**連続的なランダム音高グライドは系列再生を阻害せず、同じグライドを規則的な無音で区切ると通常の
changing-state 効果が出た** [P64]。
分節を生むのは**オンセット・拍・音高のステップ・和声の切り替え**＝**アラームを「アラームらしく」している特徴**である。

> ★★★ **「波として鳴らしたい」という直感は、ISE 文献が破壊的と特定した特徴の裏返しになっている。**
> **設計の直観と文献が同じ方向を指している。**

## §1 ★★★ 最重要 — 「波」の周波数を間違えると、ちょうど最悪の帯域に乗る

**波を作ることは許される。しかし波の周波数が決定的である。**

### 1.1 禁止帯（数値で書ける）

| 変調周波数 | 何が起きるか | 根拠 |
|---|---|---|
| ★★ **4 Hz 付近** | ★★★ **fluctuation strength が最大**。この量は **ISE を 70 例中 63 例予測した**予測子である | [P69] / [P65] |
| **0.5–20 Hz** | fluctuation strength の定義域（f_mod < 20 Hz）。**4 Hz を頂点とする山の内側** | [P69] |
| **15–70 Hz** | **roughness が立ち上がり 70 Hz で最大**。粗さは不快 | [P69] |
| ★ **0.001–0.02 Hz（分〜十分オーダー）** | ★ **禁止帯から 2〜3 桁下。ここに状態の波を置く** | 同上 |

> ★★ **書き方を間違えないこと**: 「**緩慢だから安全**」ではなく「**禁止帯から離れているから安全**」である。

### 1.2 ★ GSE の信号は構造的に 4 Hz を作れない（安全側）— しかし別の穴がある

一次資料で確認した:

| 事実 | 出所 |
|---|---|
| 推論ゲートは **1Hz**（`ENGINE_TICK_MS = 1000`） | `loop_step.rs:40` |
| → **Nyquist は 0.5 Hz**。信号自体が 0.5 Hz より速い変動を持てない | 上記の帰結 |
| ヒステリシス層の時定数は **≈2.5 秒**（α=0.40・「~2.5s time-constant」と逐語） | `engine.rs:113` |
| 軸の EWMA は **α=0.3** | `engine.rs:108` |

★ **したがって「4 Hz に乗る」ことは構造的に起こらない。** ここは安全側である。

⚠️★★★ **しかし本当の危険は変調周波数ではなく「ステップ」である**:

```text
1Hz の離散サンプルを、そのまま音量 / 密度 / 帯域幅に当てる
      ↓
毎秒、値が階段状に飛ぶ
      ↓
その段差が振幅のオンセットになる
      ↓
★★ オンセットは聴覚ストリームを分節する [P64] ＝ ISE の条件そのもの
```

> ★★★ **「1 秒ごとに値が変わる」形は、周波数が低くても分節を作る。**
> **必要なのは「1 秒ごとに次の値へ滑らかに向かう」形である。**

### 1.3 ★ 帰結 — 表現層で追加の平滑化が必須

| 段 | 時定数 | 周波数 |
|---|---|---|
| `ewma_x` / `ewma_y`（MhD 内部・既存） | α=0.3 | — |
| `display_probs`（ヒステリシス・既存） | ≈2.5 秒 | ≈0.4 Hz |
| ★ **表現層の平滑化（新規・必須）** | ★ **≥60 秒** | ★ **≤0.017 Hz** |

★ **既存の値をそのまま音に流してはいけない**——2.5 秒時定数は禁止帯の低い端にあり、
かつ 1Hz のステップが残っている。**表現層は自前でもう 1 段、時定数 60 秒以上の平滑化を掛ける。**

⚠️ **この 1 点だけは耳で判断せず、数値で固定する。**

### 1.4 ★ 検算の計器（耳だけで決めない）

作った音の **変調スペクトル**を計算し、**エネルギーが 4 Hz 付近に乗っていないこと**を機械で確認する
（[P72] からは**測り方だけ**借りる。効果主張は 0-3 で否決済み）。

> ⚠️★★ **計算だけでも決められない**——[P65] の予測子は
> **合成的な定常音（＝まさにドローン）でちょうど予測を外す**と著者自身が書いている。
> **耳と機械の両方が要る。**

## §2 音の層構成（具体仕様）

```text
┌─ 層 0  基層 (bed)  ────────────────────────────────────────────┐
│  55–110 Hz 帯の持続音 ＋ 整数次倍音のみ（2f, 3f, 4f…）          │
│  非調和成分ゼロ / sharpness 低                                  │
│  ★ 動かさない = [P48] が要求する「自分の通常」の参照点           │
│  → 状態由来の層は常にこの上で聴かれるので、並置が構造的に成立する │
└─────────────────────────────────────────────────────────────┘
┌─ 層 1  うねり (swell)  ── 摩擦を写す ──────────────────────────┐
│  帯域幅 / スペクトル重心を動かす。全遷移は時定数 ≥60 秒          │
└─────────────────────────────────────────────────────────────┘
┌─ 層 2  粒子 (grain)  ── 前進を写す ───────────────────────────┐
│  グラニュラー密度。★★ 粒子率の下限 = 100 grains/s              │
│  （これを下回ると粒が個別に聞こえ、リズムとして分節する = ISE 側）│
└─────────────────────────────────────────────────────────────┘
┌─ 層 3  空間 (space)  ── 状態の遠近 ───────────────────────────┐
│  残響時間 / 初期反射 / 定位の広がり。★ 音色を変えない            │
│  「近づく / 遠ざかる」は評価を含まない（案 γ の要素を α に統合）  │
└─────────────────────────────────────────────────────────────┘
```

**全層に共通する禁止事項**（[P64] から直接）:

- ✗ **オンセット**（アタックのある音を鳴らさない。全て持続音の重ね合わせ）
- ✗ **拍・リズム**（周期的な無音・周期的な強弱を作らない）
- ✗ **音高のステップ**（動かすなら連続グライド）
- ✗ **実物音の引用**（水・鳥・機械音。[P45]「断定しない」／実物音は指示対象を断定する [P63]）

★ **粒子率が「作品の質感」であると同時に「作業を壊すかどうかの制御量」である**——
[P64] の「連続グライド vs 無音で区切ったグライド」と同じ軸に乗っている。
**TouchDesigner で実装でき、聴きながら安全側かを判断できる。**

## §3 何を音に写すか（データ駆動の入力）

★ **MhD の設計議論はしない。出力を入力として使うだけにする。**
`design.md §4.2` の 2 系統をそのまま使う:

| 系統 | 入力 | 層への割当 | 性質 |
|---|---|---|---|
| **A（推定経由）** | `ewma_x`（摩擦）/ `ewma_y`（前進）/ `p_flow`・`p_inc`・`p_stuck` | 層 1・層 2・層 3 | 意味は豊かだが**外れうる** |

**MhD が Kill でも系統 B は生き残る。**

⚠️ **どちらの系統でも、§1.3 の追加平滑化（時定数 ≥60 秒）を必ず通してから音に当てる。**

## §4 3 状態を非評価的な語彙へ（D16 の音響版）

★ D16 は「`Flow` / `Incubation` / `Stuck` をそのまま 3 語彙に、**Incubation を肯定的に読める形に**」と決めた。
★ **実測で Incubation は最頻の予測クラス**（windows 42.2% / macos 42.2%・Stuck の約 1.8 倍）なので**空回りしない**。

音響語彙の案（★ **決定ではない。聴いて決める部分**）:

| 状態 | 音響語彙 | なぜ非評価的か |
|---|---|---|
| **Flow** | ★ **流れ** — 粒子密度が高く均質、帯域が安定、一方向の緩いグライド | 記述的 |
| **Incubation** | ★ **拡散** — 残響が伸び、帯域が広がり、粒子が疎に散る | ★ **肯定的に読める**（広がり・余白） |
| **Stuck** | ★ **滞留 / 堆積** — 粒子が特定の帯域に溜まり、動きの速度が落ちる | ★ **「溜まる」は悪ではない**（沈殿・熟成の含意も持つ）。**暗さ・荒さ・不快さに写さない** |

⚠️★★ **快さ（pleasantness）は常に高いまま固定し、事象性（eventfulness）にだけ状態を写す**（[V79] の 2 軸）。
**`p_stuck` を「不快な音」に写すことは評価を下すことであり、[P45] に正面から反する。**

⚠️ **「Incubation は肯定的に読める」「滞留は悪ではない」は設計者側の想定**であって、
**被験者がそう読むかは未検証**である。→ pilot に**自由記述 1 問**を足して読み取りを確認する。

## §5 常時鳴らす場合の必須要件（交渉不可）

| # | 要件 | 根拠 |
|---|---|---|
| ★★★ **1** | **ユーザーが止められる／音量を変えられること** | **制御できない連続音は主観的 well-being をむしろ低下させる**（26 週フィールド）[P71]。[P46]（強制的でない）・[V33]（dismiss-first）と同型 |
| **2** | **どの聴取水準も強制しない** | [P67] Eno の定義＝[P54] の `change blind` / `make aware` に留め `interrupt` へ上げない |
| **3** | **主観指標だけで go を出さない** | ★ **GSE の証拠基盤で「主観は動くが客観は動かない」形が 3 度出ている**——[V35]（客観生産性 null・主観のみ上昇）/ [P71]（26 週で改善せず）/ [P73]（ANC: 系列再生 null・知覚プライバシーのみ改善） |
| **4** | **pilot 実施中にマッピングを動かさない** | ADR-008 D4 / prequential [V64] / 適応的デザインの事前規定 [V65]。★ **`EXPR_VERSION` を刻んで凍結** |

> ★ **要件 1 を守れば、連続音は [P55] の失敗様式（偽陽性に耐えかねてチャネルごと殺される）に落ちない**——
> **止められるものは、止めるために犠牲を払う必要がないからである。**

⚠️ **慣化は避けられない**——[P70] は **30 日・毎日 20 分で約 53% 減衰**（[V33] の「3 週で相対 25% 減」と同桁）。
**常時鳴らす形は最も速く慣れる。** → **慣化を避けるのではなく ABA 撤去設計で測る。**

## §8 ★★ 壊していないことをどう測るか（文献では埋まらない空白）

> ★★★ **ドローンを刺激にした ISE / 執筆課題の実験は、9 通りの探索でも存在しなかった。**
> **GSE 側で「ドローン ON/OFF」を独立変数にして測るのが、この問いに答える唯一の道である。**

★ **骨格は既に手元にある**——**G1 の設計をそのまま流用できる**:

| G1 の要素 | ドローン実験での役割 |
|---|---|
| **copy ブロック（positive control）** | ★ **打鍵で条件が分離できることの確認**。これが ✓ でないと他の結果が読めない |
| **1 ブロック = 1 セッション = NDJSON 1 ファイル** | ★ ON/OFF の割付が**ファイル単位できれいに分かれる** |
| **5 分ブロック × 位置固定 + 無作為化** | ★ 順序効果の統制がそのまま使える |
| **強制比較の操作チェック** | 主観の操作確認（★ **判定には使わない**） |
| **ブロック水準の最小打鍵ゲート** | 適格性判定がそのまま使える |

⚠️ **G1 は凍結されているので、これに足してはならない。別実験として設計する。**
⚠️ **主観だけで go を出さない**（§5 要件 3・3 例の前科）。
⚠️ ★ **G1 が自ら「最も重要な弱点」と書いた検定の到達可能性**（C(8,4)=70 の離散性で
**主判定が事実上 AUC≈1.0 を要求**）は、**ブロック数を設計する段階で逆算して回避する**。
