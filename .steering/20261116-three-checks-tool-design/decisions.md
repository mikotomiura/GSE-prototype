# 重要な設計判断

## 判断 1: 道具の形（言語・置き場・推定器の扱い）

- **判断日時**: 2026-11-16（研究者が AskUserQuestion で選択・推奨どおり）
- **背景**: 3 つの検査の分析は全部 Python で、予測の床の推定器だけ Rust の gse-replay（inventory.md）。規則の値はどれも直書き。
- **選択肢**:
  - A: Python・新しい公開 repo。推定器は道具に入れず、出力を入力の列として受ける。GSE の NDJSON は gse-replay で変換して渡す
  - B: Rust・gse-replay の新しいモード
  - C: Python・GSE repo の中で育てて後で公開 repo へ切り出す
- **採用**: A
- **理由**: 研究として強いのは「どの推定器にも当てられる」こと。HMM を中に入れると GSE 専用の検査に見え、床（推定器）と上限（学習器）の比べを利用者の推定器に開けない。今の純関数（`branch`・`detect`・`_distance`・`near_chance_at`）をそのまま移せる。公開 repo に .steering と GSE の docs を入れない規則とも合う。
- **トレードオフ**: Replay-as-Truth の byte-equal の回帰から外れる（道具側に自前の回帰のテストを持つ）。GSE の推定器の床を出すには gse-replay を別に回す 2 段の手順になる。
- **影響範囲**: 入力の形式（推定器の出力の列）・回帰のテスト・lockfile。
- **見直しタイミング**: 利用者の多くが Rust の推定器を持ち込む、または gse-replay との byte-equal が査読で求められたとき。

## 判断 2: 入力の形式（キーの種類の語彙）

- **判断日時**: 2026-11-16（研究者が選択・推奨どおり）
- **背景**: 予測と定義は文字の挿入・削除だけを使い（論文 2 の `unit_record`）、漏れはキーの種類の列そのものを使う。語彙は GSE の `KeyCategory` 14 種と KLiCKe 側 16 種の 2 つがあり、対応表は無い。
- **選択肢**: A 語彙は利用者が宣言し、最小の 3 区分（文字・削除・その他）への写しを必須にする（14 種と 16 種を既定として同梱）／B GSE の 14 種に固定／C 挿入・削除だけ
- **採用**: A
- **理由**: 漏れの結果は語彙の粗さで変わる。固定すると利用者の記録の実際の語彙での漏れを測れない。宣言した語彙を出力の限定に書けば、記録どうしの差が語彙の差かを読める。
- **トレードオフ**: 記録どうしの比べに語彙の差が混ざる（出力に書いて読み手に渡す）。
- **見直しタイミング**: 3 区分の写しで予測・定義の結果が論文と合わないとき。

## 判断 3: 予測の面の判定（学習器の上限）

- **判断日時**: 2026-11-16（研究者が選択・推奨どおり）
- **背景**: 今の「読めない」は手で作った HMM の失敗に頼りすぎる（引き継ぎ追記・MhD の直し方の方針）。O1 では人の中の学習器（0.59 前後・2 人）と人をまたぐ学習器（論文 1 の 0.54〜0.57）で値の意味が違った。
- **選択肢**: A 事前に固定した学習器の集合の上限で判定し、人をまたぐ／人の中 × 打鍵だけ／＋打鍵以外を別の行にする。推定器は床として並べるだけ／B 推定器で判定・学習器は参考（論文 1 の形）／C 上限で判定し行をまとめる
- **採用**: A
- **理由**: 「手を尽くした学習器でもこの程度」なら「推定器が弱いだけ」を構造で封じられる。評価の単位を混ぜると値の意味が変わる。上限の区間は再標本の中で最大を取り直し、選んだ楽観を入れない。打鍵以外の無い人・観測 0 の本はその行を判定不能にする。
- **トレードオフ**: 学習器の集合に無い型の信号は「読めない」と出うる（出力の限定に「この学習器の集合に対して」と書く）。計算が重い。
- **見直しタイミング**: 学習器の集合の外で帯を超える例が出たとき。

## 判断 4: 定義の面（他の検査を包む外側の軸）

- **判断日時**: 2026-11-16（研究者が選択・推奨どおり）
- **背景**: 論文 2 の結論（作文の点との関連の向き）は結果の変数を要し、GSE 自身の記録には無い。ADR-054 D4 は予測の結果に定義の検査を当てることを残している。
- **選択肢**: A 利用者が宣言した定義の族のそれぞれで予測の判定（と、あれば結果の変数との関連の向き）を出し直し、入れ替わりの割合が利用者の閾値を超えたら「定義しだい」／B 結果の変数との関連だけ／C 予測の判定だけ
- **採用**: A
- **理由**: 結果の変数が無くても定義の面が空にならない。「3 つの検査を同じ記録に当てる」という差の候補が道具の構造になる。
- **見直しタイミング**: 定義の族の計算量が実用を超えたとき。

## 判断 5: 漏れの面（候補の受け方・攻撃者・粒度）

- **判断日時**: 2026-11-16（研究者が選択・推奨どおり）
- **背景**: 今の攻撃（`closed_set.py`）は候補の打鍵列を合成入力の計画から生成器で作り直す設計で、利用者の記録に当てられない。
- **選択肢**: A 候補を①既知の句を打った記録の区間（正解つき）か②本文→宣言した語彙のキーの種類の列を作る関数で受ける。攻撃者は道具の固定の集合で、結果は下限と書く。粒度を振り、規則を満たす最も細かい粒度（無ければ「なし」）を返す／B 合成入力の生成器を同梱／C 脅威の一覧だけ
- **採用**: A
- **理由**: ①は人の打鍵での漏れという未検査の穴を研究者本人の記録で埋め、②は公開データに当てられる。下限と書くと「漏れない」の言い過ぎを構造で防ぐ。粒度を返す形は写し方 (3) にそのまま使える。
- **トレードオフ**: IME 論文の 0.90 の再現には、論文の生成器が作った候補の列を②の形（事前に計算した列）で渡す必要がある。
- **見直しタイミング**: 固定の攻撃者より強い既知の攻撃（言語モデルを使うもの等）を足すとき。

## 判断 6: 完成の条件の検査（3 層）

- **判断日時**: 2026-11-16（研究者が選択・推奨どおり）
- **背景**: CS1・KLiCKe の記録は公開 repo に入れられない。予測の判定（0.49）は CS1 の holdout の値で、holdout は開かない。
- **選択肢**: A ①合成の陽性・陰性の対照（CI）②論文の公開済みの中間から既定の例の規則で 3 つの判定を再現（CI）③公開データを取得した手元で見た書き手の側だけ通しで再現／B 合成の対照だけ／C holdout まで通し
- **採用**: A
- **理由**: ①が無いと常に「読めない」を返す壊れ方を検出できない。②は判定の規則の移植、③は入力からの計算の移植を確かめる。holdout の確認は 1 回きり。
- **補足（一次で確認）**: ③で照らす見た書き手の側の値は論文 1 の探索に実在する（枝 `docs/public-data-findings-paper` の `experiments/20261106-findings-paper1-exploration/notes.md:7-9`・`:42`。CS1 2019 の見た 319 人で `d_p_stuck` 0.492（0.485〜0.499）ほか）。
- **見直しタイミング**: 公開の中間が判定の再現に足りないと分かったとき。

## 判断 7: 期間の区別（R1 の定義の検査は道具の前に今のコードで）

- **判断日時**: 2026-11-16（研究者が選択・推奨どおり）
- **選択肢**: A 道具の前に今のコードで条件を先にコミットして済ませ、道具の回帰の例に加える／B 道具の最初の利用例として期間に入れる／C 両方
- **採用**: A
- **理由**: 独立のコードで先に出した結果があれば道具の計算を外から照合できる。「読めない」が定義で動くかは応募の尖りに効くので早いほうが設計に返せる。未踏の期間に入るのは道具の開発と GSE 自身の記録への適用。
- **一次で分かった前提の訂正（2026-11-16・この判断の後）**: ADR-054 Context 6 と R1 の引き継ぎ（枝 `docs/gse-core-and-edge` の `.steering/_handoff/next-session-gse-r1-definition-check.md` §1）は「論文 1 の感度解析は停滞の定義を変えていない」とするが、論文 1 の確認は補足で停滞の定義の 3 軸を holdout で振っている（`papers/public-data-findings/manuscript/appendix/supplement.tex:232-234`: 分位 q=0.995・条件 A の窓 W=15 s・W=60 s。値は `experiments/20261105-findings-paper1-prefreeze/results_holdout/confirm_holdout.json` の `sensitivity.replay_q995`・`replay_w15`・`replay_w60`。推定器の 2 信号とも分岐 1＝帯の内）。変えていないのは、θ の固定値・規則（ins）・観測区間の軸と、学習器（上限）を定義で振ること。→ R1 の定義の検査のタスクで新しく要るのはこの残りで、範囲が狭まる。判断 A は変えない。ADR-054 は書き換えず、R1 の引き継ぎを直すのは R1 のタスクで行う（研究者に伝える）。
