# 設計: 3 つの検査の公開の道具（v1・初案）

状態: 初案（2026-11-16）。判断 1〜7（decisions.md）は研究者が AskUserQuestion で選んだ。実装はしない。数値と既存コードの位置は inventory.md で一次と照合した。

## 0 何を作るか（一言）

本文を保存しない打鍵の記録に、予測・定義・漏れの 3 つの検査を当て、面ごとの判定（読める・読めない・漏れる・定義しだい・未決・判定不能）と証拠の格・限定・検査していない脅威を返す、Python の公開の道具。推定器は持たず、利用者の推定器の出力を受けて「床」として並べる。判定の規則の値は持たず、利用者が事前に決めた値を入れる（ADR-054 D5・判断 11・12）。

## 1 形と置き場（判断 1）

- 新しい公開 repo の Python パッケージ（仮名 `keystroke-three-checks`。名は実装の前に決める）。GSE の repo には置かない（公開 repo に .steering と GSE の docs を入れない）。`analysis/` の層規則（architecture-rules）の対象外で、GSE の本体のコードは変えない。
- 依存: numpy・scipy・scikit-learn（学習器）。版は lockfile（`uv.lock` か `requirements.lock` を hash 付き）で固定する。今の 3 つのコードはどれも Python の lockfile を持たない（inventory 横断 4）ので、これは新しく足す。
- CLI と関数の 2 つの入口: `three-checks run --records <dir> --rules <rules.json> --out <dir>` と、検査ごとの関数（`predict.check`・`definition.check`・`leak.check`）。
- GSE の記録は 2 段で渡す: gse-replay（`--features`・推定器の出力）で中間を作り → 変換器で道具の入力にする。GSE の NDJSON を道具が直接読むかは §11 の未決。

## 2 入力（判断 2）

全部ファイル（Parquet か CSV）。必須は 1 と 2 だけで、残りは任意。欠けた入力に頼る行は「判定不能（理由: 入力 X が無い）」を返す。

| # | 表 | 列 | 使う検査 |
|---|---|---|---|
| 1 | 打鍵 `keys` | `person`・`session`・`t_ms`（int64）・`key`（宣言した語彙の 1 語） | 全部 |
| 2 | 語彙 `vocabulary.json` | 語の一覧・各語の 3 区分（`char`・`delete`・`other`）への写し・名前と版。GSE の `KeyCategory` 14 種と KLiCKe 系 16 種を同梱 | 全部 |
| 3 | 観測区間 `observed` | `person`・`session`・`start_ms`・`end_ms` | 予測・定義（停滞を区間の中に限る。論文 2 の `iv`） |
| 4 | 打鍵以外 `events` | `person`・`session`・`t_ms`・`kind`（focus・pointer・paste・ime など宣言した種類）＋ 人ごとの「記録されていた種類」の宣言 | 予測の ＋打鍵以外の行 |
| 5 | 推定器の出力 `estimator` | `person`・`session`・`t_ms`・信号の列（名前は自由） | 予測の床・新しい推定器 |
| 6 | 結果の変数 `outcomes` | `person`（か `session`）・値・共変量（任意） | 定義（関連の向き） |
| 7 | 照合の候補 `candidates` | ① 記録の区間（`person`・`session`・`start_ms`・`end_ms`・`phrase_id`・正解の印）か ② 候補の列（`phrase_id`・キーの種類の列）。② を本文から作る関数は語彙ごとの差し替え | 漏れ |
| 8 | 規則 `rules.json` | §3 の値・定義の族・学習器の集合・事前登録の記録（URL と SHA-256、無ければ空） | 全部 |

- 時刻の単位は ms の整数。打鍵の時刻は押下（論文 1・2 と同じ）。離しの時刻は持たない。
- 3 区分への写しで予測・定義に要る `ins`・`dele`（論文 2 の `unit_record`）を作る。漏れは宣言した語彙をそのまま使う。
- 変換器（同梱する）: GSE（gse-replay の中間から）・KLiCKe・CS1・CoAuthor。今は実験ごとに複製されている変換（inventory 予測の項）を 1 つにまとめる。公開データの記録そのものは同梱しない。

## 3 3 つの検査と面の判定

### 3.1 予測（判断 3）

- 停滞と対照の対: 論文 1 の作り方（停滞の `u`＝確定の手前の最後の文字・同じ書き手の短い休止の手前の `u′`・区切りの種類をそろえる）を移す（`confirm_p1.py` `stall_anchors` :260・`control_ok` :308）。対照の条件の値（短い休止の幅・1 停滞あたりの数・観測開始からの最小の距離）は `rules.json` に出す。
- 特徴量: 打鍵の 18 量（`confirm_p1.py` `feats18` :248 と O1 の `auc.py` `feat_k` :184 を突き合わせて 1 つにする）・打鍵以外（宣言した種類の数と最後からの秒）・止まりの最中（`u` から宣言した秒数の後の量。O1 の `early=True`）。止まりの最中の量は「契機の時点で見える量」かを行ごとに印す（ADR-054 D5 の写し方は、契機の後の量を時機の判断に使えない）。
- 学習器の集合（`rules.json` で事前に固定）: 既定の例はロジスティック回帰（L2・C=1）と勾配ブースティング（論文 1 の `models` :660）。
- 行（混ぜない）: {人をまたぐ（人を単位に分割）・人の中（時間順の後ろを取り置く・ADR-019 D3）} × {打鍵だけ・打鍵＋打鍵以外} の 4 行。人の中の行は人ごとに出し、人の数ぶんの行になる（1 人ごとの予測）。
- 上限: 集合の学習器の AUC の最大。区間は再標本（人をまたぐは人を、人の中は日を単位に復元抽出）の各回の中で最大を取り直して作る。
- 床と推定器: 利用者の推定器の各信号の AUC と区間を同じ対の上で並べる。判定には使わない。
- 判定（`rules.json` の帯 `[lo, hi]`・幅の上限 `width_max`）: 論文 1 の `branch()`（`confirm_p1.py:138`）を移して上限に当てる。区間の幅 > `width_max` → 未決（精度不足）／区間が帯の内 → 読めない（この学習器の集合に対して）／区間の下端 > `hi` → 読める／それ以外 → 未決。
- 判定不能: 人の停滞の数が `min_stalls` 未満・日の数が `min_days` 未満（O1 の `MIN_STALLS=30`・`MIN_DAYS=5` を既定の例に）・打鍵以外の種類が記録されていない人の ＋打鍵以外の行・観測 0 の本。
- 限定の欄に自動で書くもの: 停滞の定義が打鍵だけから作られているとき「正解と量が同じ材料から来る（循環）」。学習器の集合の名前。評価の単位。

### 3.2 定義（判断 4）

- 定義の族: 論文 2 の軸（窓 W・保持 θ（分位か固定）・規則 net/ins・観測区間の扱い）を `rules.json` で宣言する（論文 2 の `core.py:24-28` は直書き。これを引数にする）。検出は `core.py` `detect`（:62-111）を移す。始まり `s` と確定 `t0` を両方返す（Codex round 3 の (1)）。
- 結論の 2 種:
  - (a) 予測の判定（§3.1 を族のそれぞれで出し直す）。いつでも出せる。
  - (b) 結果の変数との関連の向き（順位相関・共変量で調整した偏相関・書き手の復元抽出の区間。論文 2 の `round1_extra.py`・`round5_length.py` を関数にまとめる）。結果の変数があるときだけ。
- 判定: 族のうち基準の定義と結論（判定の値か、向き＝区間が 0 の上・下・含む）が違う定義の割合が `rules.json` の `flip_share` を超えたら「定義しだい」。超えなければ、その結論は「定義を振っても残る（この族の中で）」。定義への感度と共変量の調整への感度は別の行にする（attack-me round 3 の一致 6）。

### 3.3 漏れ（判断 5）

- 候補: ① 記録の区間（研究者本人が既知の句を打つ区間など・正解つき）か ② 候補の列。
- 攻撃者（道具の固定の集合）: IME 論文の `closed_set.py` の `_tokens`（:156）と `_distance`（:183）を移した編集距離の照合。定数（`PAUSE_MS=600` :122 など）は `rules.json` に出す。合成入力の計画と生成器への依存（`build_trial`・`align_plan`）は移さない。
- 粒度: {時刻あり・1 秒の窓・時刻なし・数だけ}（`apply_features`・`coarser_or_equal` :114）に、丸めの幅を宣言で足せる形。報告は「その粒度と、それより粗くできる全ての粒度の最大」（攻撃者は情報を捨てられる）。
- 判定（`rules.json` の「偶然に近い」の規則。既定の例は Wilson 95% 上端 ≤ 2/K を K=10・100 の両方・`results_tables.py:518`）: 規則を満たさない粒度があれば「漏れる（その粒度で）」。規則を満たす最も細かい粒度を返す（無ければ「なし」）。結果は「この攻撃者の集合の下での下限」と書く。
- 検査していない脅威（いつも出す）: 本人の同定・属性の推測・候補の集合を替えた一般化・言語モデルを使う攻撃・同じ人の複数の試行の併用・最終の本文との照合・合成入力から人の打鍵への外挿（① が無いとき）。出典は IME の README L276-287 と照合の論文の脅威の節（読むだけ）。

### 3.4 読める所

- 予測の上限が「読める」の行だけが「読める」の候補になる。その量が漏れる・定義しだいの面にも属すれば、制限の強い規則を当てる（ADR-054 D5 判断 12: 漏れる・読めない ＞ 定義しだい ＞ 読める）。

## 4 出力

- `map.json`（機械向け）と `map.md`（人向けの表）。行 = (検査・行の種類・量の組・定義)。列 = 判定・値と区間・証拠の格・限定・検査していない脅威・判定不能の理由。
- 証拠の格: `rules.json` の事前登録の記録を写す。記録が規則のファイルの SHA-256 と一致すれば「確認」、記録が無いか一致しなければ「探索」、検査を回していない面は「未検査」。道具は格を自分で上げない。
- 限定（自動）: 語彙の名前と版・学習器の集合・評価の単位・攻撃者の集合・循環・帯を決めた時点（規則のファイルに書かれていれば）。
- 来歴: 道具の版・lockfile の hash・入力ファイルの SHA-256・seed（論文 2 と同じく定義と行ごとに `[seed, crc32(id)]` で派生）。
- 出力は集計だけ。打鍵の列・個人の値・書き手の識別子は出さない（人の中の行は記号を付ける）。人の中の行と小さな数の伏せ方は O1 の `cr_common.py`（`public`・`coarsen`・`mask_small`）を移す。

## 5 地図から系への写し方

道具は写し方を実行しない（実行時に面を判定しない・ADR-054 D5）。出力の各行に「写し方 (1)〜(4) のどれに当たるか」の欄を付け、系の作り手が読む。

## 6 完成の条件の検査（判断 6）

| 層 | 何 | どこで | 外れ方 |
|---|---|---|---|
| ① 合成の対照 | 信号を埋めた合成記録で「読める」、埋めない記録で「読めない」。既知の句を打った合成の区間で「漏れる」、候補をそろえた（列が同じ）記録で漏れない。定義で向きが逆になるよう作った記録で「定義しだい」。論文 2 の `core.synth` と論文 1 の陽性の対照（`explore_positive_control.py`）を下敷きにする | 公開 repo の CI | 常に同じ判定を返す壊れ方が赤になる |
| ② 公開の中間からの判定 | 論文 1 の `confirm_holdout.json` の区間 → 帯の判定（4 つとも分岐 1・補足の感度の行も）、論文 2 の公開の集計 → 向きの判定、IME 論文の正答数 → 2/K の判定。既定の例の規則（`examples/rules-papers.json`）で、論文の判定と一致すること | 公開 repo の CI（中間は記録を含まない集計だけ・公開済みのもの） | 判定の規則の移植の誤りが赤になる |
| ③ 通しの再現 | 公開データを取得した手元で、記録 → 判定。予測は見た書き手の側だけ（論文 1 の探索の値・`20261106-findings-paper1-exploration/notes.md:7-9, 42`）。定義は論文 2 の 90 通り（`run.sh`・約 1 時間 50 分）。漏れは IME 論文の生成器の候補の列を ② の形で渡して 0.9019（`summary.md:46`） | 研究者の手元（記録は repo の外・論文の run.sh と同じく repo の中なら止める） | 入力からの計算の移植の誤りが出る |
| ④ GSE 自身の記録 | 正解の無い面を「未検査」と返す。漏れは研究者本人が既知の句を打つ区間で測る | 研究者の手元（未踏の期間） | 正解の無い面に判定を出したら赤 |

- 加えて、R1 の定義の検査（判断 7・道具の前に今のコードで）の結果を ②③ の回帰の例に足す。
- holdout は開かない。② は公開済みの集計だけを読む。

## 9 守ること

- 道具は手元で走り、外に何も送らない。記録・NDJSON・公開データの記録を外部の LLM（Codex を含む）に送らない。
- 公開 repo に .steering・GSE の docs・投稿先や状態を書かない。
- holdout は開かない（③ は見た側だけ）。
- 出力に打鍵の列・個人の値を出さない（§4）。

## 10 テスト戦略

- 単体: 移した純関数ごとに元のコードとの一致（同じ入力で同じ出力・元の selftest を移す）。`branch` は帯の端の値で分岐ごとに 1 つ。
- 統合: §6 の ①②（CI）。③④ は手元の手順書（run.sh）で、結果を notes に残す。
- 変異: 判定の規則を 1 つ壊すと ① か ② が赤になること（論文 2 の `mutate.py` の作法）。
