# 3 つの検査の公開の道具の設計（v4: 採用案に codex-consult と /cross-review 2 巡を織り込んだ版）

状態: 設計のみ・実装しない（2026-11-16）。骨格は /reimagine の v2（初回案を読ませない Opus のサブエージェントが書いた）で、v1 の 5 点を足したハイブリッド（研究者の選択）。codex-consult の 7 件（§9）と /cross-review 1 巡目（§10）・2 巡目（§11）の指摘は本文に織り込み済み。判断 1〜7 は decisions.md。数値と file:line は inventory.md と decisions.md の一次の照合による。

## 0 設計の芯

1. **検査を 1 つの枠で表す**: どの検査も「主張 × 摂動の族 × 判定の規則 → 面の判定」で書く。予測は学習器の族、定義は停滞の定義の族、漏れは粒度 × 攻撃者の族を摂動として振る。3 つを並べた道具ではなく、同じ手順を 3 つの摂動に当てる道具にする（ADR-054 Context 6「検査の手順としてつなぐと方法になる」に構造で答える）。
2. **規則は事前登録の様式そのもの**: 利用者が書く規則のファイル（`checks.toml`）は事前登録に貼る節と同じ文書。`freeze` がその SHA-256・入力の目録・実装と lockfile の hash を刻んだ記録を出し、`run` はハッシュが合わなければ止まる。道具は規則の値を 1 つも持たない（論文の値は「例」として同梱するだけ）。凍結が検知するのは**凍結の記録と実行時の規則・入力の不一致**だけで、事前性・一回性の証明でも、凍結し直しの検知でもない（§2.4）。
3. **封をした分割**: 単位の表に分割の列（seen／holdout）を持たせ、`run` は holdout の行を既定で読まない。開くのは凍結の記録に書いた実行だけ。封は**誤って読むことを防ぐ仕組み**で、別のコピーや別のプログラムからの閲覧は防げない（限定に書く）。

## 2 構成

### 2.1 パッケージの層（依存は上から下へだけ）

```
threechecks/
  schema/      正準の表の型・検証（単位・行の順・未知のキー・文字列の拒否）・語彙の宣言
  seal/        分割の封・凍結の記録
  perturb/     摂動の族
    learners.py    学習器の族（判断 3）
    definitions.py 停滞の定義の族と detect（判断 4）
    granularity.py 粒度の梯子（時刻の除去・丸め・語彙の粗さ）と攻撃者の族（判断 5）
  measure/     統計量（AUC・同時区間・人の中の AUC・クラスタの再標本・Wilson 区間・関連の向き）
  rules/       判定の純関数（numpy にも依存しない）
  checks/      3 つの検査（摂動 × 測り × 規則を組むだけ）
  faces/       面の地図の組み立て・系への写し
  report/      map.json・ledger.csv・summary.md
  cli.py       freeze / run / validate
adapters/      入力の変換（GSE の gse-replay の中間・KLiCKe・CS1・CoAuthor）
examples/      論文の値の例の規則・語彙の宣言の例
tests/         層 ①②（CI）。tests/local/ は層 ③④ の手順と期待値の hash だけ
```

- `rules/` は数値（区間の端・点推定・件数）と規則の値だけを受ける。層 ② と規則の境界のテストはこの層だけで走る。
- `checks/` は値を持たず、規則のファイルから読んだ値を `rules/` に渡すだけ。

### 2.2 共通の枠

| 検査 | 主張 | 摂動の族 | 判定に使う測り | 判定の規則（値は利用者） | 面 |
|---|---|---|---|---|---|
| 予測 | 量 X は停滞の手前を短い休止の手前から分けるか | 学習器の族 | 族の各学習器の AUC の同時区間（族の数で補正） | 同等の帯・幅の上限（ε は AUC の同値の幅） | 読める／読めない／未決／判定不能 |
| 定義 | 予測の判定（と結果の変数との関連の向き）は定義で残るか | 停滞の定義の族（基準の定義を 1 つ宣言） | 基準と比べた入れ替わり（予測の判定 3 種・関連の向き） | 入れ替わりの割合の閾値・有効な比べの数と割合の下限 | 定義しだい／残る（有効な部分で）／判定不能 |
| 漏れ | 保存しない内容は観測から照合されるか | 粒度の梯子 × 道具の固定の攻撃者 | 正答率のクラスタ区間（その粒度とそれより粗くできる全粒度について） | 「偶然に近い」の規則 | 漏れる／規則適合／未決／判定不能 |

- 定義の検査は予測の検査を包む外側の摂動（判断 4）。`checks/definition.py` は `checks/prediction.py` を族の各定義で呼び直すだけ。
- 摂動の台帳: 振った摂動（学習器 × 行・定義・粒度）ごとに 1 行。学習の失敗・単一のクラス・NaN・判定不能の行も落とさない。何通り試して何通りで判定が出たかを読み手が数えられる。

### 2.3 入力の表（CSV か Parquet・時刻は ms の int64）

| 表 | 必須の列 | 欠けたとき |
|---|---|---|
| `units` | unit_id・person_id・obs_start_ms・obs_end_ms・split（seen／holdout）。任意で課題の識別 | 走らない |
| `events` | unit_id・event_index（単位の中の連番）・t_ms・key_class（宣言した語彙）・class3（文字・削除・その他） | 走らない |
| `estimator` | unit_id・t_ms・score・estimator_id | 床の行が「未検査」 |
| `context` | unit_id・t_ms・channel・value（数値だけ） | ＋打鍵以外の行が「判定不能」 |
| `collection` | person_id（か unit_id）・channel・collected（真偽）・期間 | `context` があっても、収集の宣言の無いチャネルは「判定不能」 |
| `outcomes` | unit_id・name・value | 定義の関連の向きが「判定不能」（予測の入れ替わりは出す） |
| `candidates` | どちらの形も source_id・role（candidate／probe）・phrase_id を持つ。① 正解つきの区間（unit_id・t の範囲）か ② 事前計算のキーの種類の列（source_id は元の区間か `generated:<生成器と版>`）。probe は必ず記録の区間（①）。任意で候補の事前確率 | 漏れの面が「未検査」 |

- `collection` で「観測なし」と「出来事なし」を分ける（/cross-review の Codex 4・v1 の「記録されていた種類」の宣言を戻した）。収集されていた期間の出来事 0 は特徴量 0。収集されていない期間にかかる錨は、その人の ＋打鍵以外 の行から除く（欠損）。除いた後に `min_stalls`・`min_days` を満たさなければ、その人の ＋打鍵以外 の行は「判定不能（収集なし）」。人をまたぐ行では、その人を ＋打鍵以外 の行の分母から外し、外した人の数を台帳に出す（2 巡目 Claude）。
- 時刻の同じ打鍵の順は `event_index` で決める。行の順の入れ替えは `event_index` で並べ直してから計算するので結果は変わらない（2 巡目 Codex 3）。
- 観測区間（`units` の始まりと終わり）の外は欠損で、停滞にも対照にも数えない（codex-consult 3）。
- 語彙の宣言（`vocab.toml`）: 名前と版・各キーの種類から 3 区分への写し・梯子で使う粗い写し（任意）。語彙の名前は出力の限定に必ず写す。
- `schema/` の検証（codex-consult 7）: 時刻の単位の取り違え（秒らしい値）を拒む・宣言に無いキーを拒む・`context` の文字列の列を拒む・行の順に結果が依存しない。
- 形は GSE の NDJSON の key 行と論文 2 の `unit_record`（prep.py:54-61）に合わせる。`class3` の文字・削除が `ins`・`dele` に当たる。

### 2.4 規則のファイル

```toml
[meta]       # 事前登録の識別子・外部の登録先の記録の hash（任意）・証拠の格（確認／探索）
[split]      # 分割と再標本の単位（person / unit / task）・purge の幅
[prediction] # band = [lo, hi]・width_max・eps（AUC の同値の幅・1 つか 2 つ）・alpha（同時区間）・n_boot・seed
             # learners（道具の族から選ぶ）・rows（across_person / within_person）・signals（keys / keys+context）
             # min_stalls・min_days・early_s（止まりの最中の量の秒）
[definition] # family（W・theta・rule・interval の格子）・reference・flip_share_max・min_valid_comparisons・min_valid_share
[leak]       # K・chance_coef・priors（任意）・pause_ms・ladder・cluster（person / phrase）
[holdout]    # open = false
```

- 道具は値の既定を持たない。欠けた値はその面を「判定不能（規則なし）」にする。
- `examples/paper-defaults.toml` に論文の値を例として置く: 帯 0.45・0.55・幅 0.10（confirm_p1.py:45）と ε（:38）、定義の族 90 通りと B0（core.py:24-29）、N_BOOT=2000・PHI_CUT=1.5・SHARE_CUT=0.25（analyze.py:24-26）、Wilson 上端 ≤ 2/K（results_tables.py:518）と `PAUSE_MS=600`（closed_set.py:122）。
- 凍結が検知するのは「凍結の記録と、実行時の規則・入力の不一致」だけで、記録を持つ本人が凍結し直すことは検知しない（2 巡目 Claude）。
- 凍結の記録: 規則・語彙・入力の目録（各表の SHA-256 と行数。holdout の行は数だけ）・道具の版・lockfile の hash・親の実行 ID。
- 証拠の格は `[meta]` を写すだけで、道具は格を上げない（codex-consult 5）。外部の登録先の記録の hash が書かれていれば限定に「外部の記録あり」、無ければ「凍結はこの手元の記録だけ」と書く。ハッシュが合わないときは止まる。凍結なしの実行を許すかは未決 8。

### 2.5 出力

- `map.json`: 量ごとに、予測の判定・定義の判定・漏れの判定・証拠の格を**直交した項目**として持つ（6 つの語は排他ではない・codex-consult 6）。各項目に測りの値と区間・規則の値・限定・検査していない脅威・判定不能の理由。別に `system_mapping`（ADR-054 D5 の強い規則で畳んだ 1 つの写し）と、写し方 (1)〜(4) のどれに当たるかの欄。
- `ledger.csv`: 摂動の台帳。
- `summary.md`: 人が読む 4 面の表（material §3 と同じ列）。
- 伏せ方: 出力は集計だけ。打鍵の列・個人の値・書き手の識別子は出さない。人の中の行は記号で、小さな数は伏せる（O1 の `cr_common.py` `public`・`coarsen`・`mask_small`）。
- 来歴: 道具の版・lockfile の hash・入力の SHA-256・seed（定義と行ごとに `[seed, crc32(id)]` で派生・論文 2 の作法）。
- 固定の限定の文: 予測は「この学習器の族と特徴の集合に対して。族の外の信号の不在は主張しない」と検出力の曲線（§4 ①）、漏れは「この攻撃者の族・この候補の集合に対する下限。返す粒度は安全な粒度ではない」、定義は「どの定義が正しいかは言わない」、封と凍結は「凍結の記録と実行時の不一致の検知で、閲覧の防止・事前性の証明・凍結し直しの検知ではない」。検査していない脅威の初版の一覧は IME README L276-287 と照合の論文 threat-model.tex の項目（上界・言語モデル・同じ人の複数の試行・最終の本文との照合・同定と属性・候補の集合の一般化）。

## 3 3 つの検査の最小の実装と判定

### 3.1 予測（判断 3）

1. 錨: 基準の定義で `detect` を回し、停滞の始まり s と確定 t0 = s + θ と、対照（同じ書き手の短い休止の手前）を取る（`stall_anchors` :260・`control_ok` :308 を移す）。対照の条件の値は規則に出す。
2. 量: 錨の前の窓から 18 量（`feats18` :248 と O1 の `feat_k` :184 を突き合わせて 1 つに）。＋打鍵以外の行は `context` を足す（`feat_n` :199 の型）。止まりの最中の量は u から `early_s` 秒の後。
3. 学習器の族: 初版は logreg・hgb（`models` :660）。前処理と調整は外側の分割の中で行う（入れ子・codex-consult 1）。
4. 行（混ぜない）: 「人をまたぐ（人を単位に分割した OOF・`oof_auc` :716）」と「人の中（時間順の後ろを取り置く・ADR-019 D3・`matched_auc` :253・再標本は日を単位）」×「打鍵だけ／＋打鍵以外」。人の中の行は人ごと（1 人ごとの予測。人をまたぐ評価から 1 人への判断を導かない）。学習と評価の境界の前後に、特徴とラベルが参照する最長の範囲ぶんの purge を置く（codex-consult 3）。分割と再標本の単位は `[split]` で宣言。
5. 推定対象と測り: AUC は同値を ε の幅で数える（論文 1 の `wins_ties`・ε を 2 つ宣言すれば両方で判定し、両方で同じ判定のときだけその判定・違えば未決）。推定対象は「族の各学習器の性能の最大」で、選ぶ手順の性能とは書かない。判定には族の各学習器の同時区間（`alpha` を族の数で補正）を使う。再標本の中で最大を取り直した区間（`boot_oof` :721 を族の最大に広げたもの）は記述として並べるだけ（codex-consult 1）。
6. 判定（非対称・上から順に当てて最初に当たったもの・2 巡目 Claude）:
   1. 行の入力が足りない（件数が `min_stalls`・`min_days` 未満・収集なし・観測 0 の本）→「判定不能（入力）」。
   2. 学習器ごとに「成功」（学習できた・2 つのクラスがある・NaN でない・区間の幅 ≤ `width_max`）か否かを決める。成功の学習器が 0 → 全部が失敗なら「判定不能（学習の失敗）」、失敗と幅の超過が混じるなら「未決（精度不足）」。
   3. 成功の学習器のどれかの同時区間の下端 > hi →「読める」（族の最大についての主張なので 1 つで足りる）。
   4. 全学習器が成功で、全部の同時区間が [lo, hi] の内 →「読めない」（族の全体についての主張なので全部を要る。1 つでも失敗・幅の超過なら読めないとは言わない）。
   5. 全学習器が成功で、全部の上端 < lo →「未決（下に外れる）」（論文 1 の補足の undec. (lower)）。
   6. それ以外 →「未決」。
   失敗の学習器と理由は台帳に必ず出す。帯の判定の核は `branch`（:138）を引数化して移し、退化は `h1_branch` :153 の扱いを移す。
7. 床: `estimator` の score の AUC を同じ錨と同じ行で並べる。判定に使わない。
8. 契機の印: 量ごとに「契機（t0）の時点で見える量か」を印す。t0 より後の情報を含む量は「契機の後」とし、`system_mapping` で時機の判断に使えない側に置く（ADR-054 D5 写し方 (1)）。
9. 循環の限定: 停滞の定義が打鍵だけから作られているとき「正解と量が同じ材料から来る（循環）」を限定に書く。

### 3.2 定義（判断 4）

- 族の各定義で §3.1 を呼び直す。各定義の区間は定義ごとに独立の再標本（論文 2 と同じ）。定義どうしの差を比べる行だけは対応づけた再標本（同じ添字）で出す（codex-consult 4）。
- 入れ替わりは 3 種に分けて数える: (i) 読める ↔ 読めない、(ii) 判定 → 未決、(iii) 判定 → 判定不能。結果の変数があれば関連の向き（区間が 0 の上・下・含む・`round3_speed.py:51-53` 等を `rules/` に 1 つに）も同じ族で出す。
- 判定の規則（/cross-review 1 巡目の一致 HIGH・2 巡目の一致 2 件）:
  - 結論は 2 つあり、それぞれに判定する: (A) 予測の判定、(B) 結果の変数との関連の向き（結果の変数があるときだけ）。
  - 有効な比べ: 基準も相手も「判定を持つ」定義（(A) は読める・読めない、(B) は区間が 0 の上か下）。有効な比べの**数**が `min_valid_comparisons` 未満、または族の全体に対する**割合**が `min_valid_share` 未満なら、その結論は「判定不能（評価できる定義が少ない）」。
  - 基準が判定を持たないとき: その結論は「判定不能（基準が判定を持たない）」。ただし基準以外の定義のあいだに相反する判定（(A) で読めると読めない、(B) で正と負）が両方あれば、別の項目「基準なしの割れ」を真にし、`system_mapping` では「定義しだい」として扱う（強い規則の側）。
  - 有効な比べのうち、基準と相反する判定（(A) は (i)、(B) は正 ↔ 負）の割合が `flip_share_max` を超えたら「定義しだい」、超えなければ「残る（有効な部分で）」。(ii)(iii) と (B) の「判定 → 0 を含む」の数は判定に使わず並べ、有効な割合と一緒に出す。
  - 定義の面の最終の判定は (A) と (B) の強いほう（どちらかが定義しだいなら定義しだい）。
- 格子の偏り: 割合は族の全体と軸ごとの両方で出し、反転の境界（どの軸のどの値で入れ替わるか）を並べる。全定義で停滞と対照が作れる人だけの共通の対象での比べも出す（codex-consult 4）。
- 定義への感度と、結果の変数の共変量の調整への感度は別の行にする（attack-me round 3 の一致 6）。

### 3.3 漏れ（判断 5）

- 候補と評価の分離（/cross-review 1 巡目の Codex 3・2 巡目の Codex 2）: ①② のどちらも role で候補（candidate）と照合の対象（probe）に分け、同じ source_id・重なる区間を両方に使うことを `validate` で拒む（② の候補の source_id が元の区間なら同じ検査を当てる）。同じ句の候補が複数あるときは句で束ねる。同点は seed から決めた乱数で破り、同点の数を台帳に出す。
- 攻撃者の族: `closed_set.py` の `_tokens` :156・`_distance` :183・`attack` :261 を移す（生成器 `build_trial`・`align_plan` への依存は移さない）。
- 粒度の梯子: `apply_features`（simulate_obs.py:83）と `coarser_or_equal`（:114）を移し、丸めの幅と語彙の粗い写しを宣言で足せる形にする。各粒度で報告する正答率は**その粒度と、それより粗くできる全ての粒度の最大**（攻撃者は情報を捨てられる・v1 にあり v2 で落ちていたものを戻した・/cross-review の Codex 2）。
- 偶然の水準: 事前確率を知る攻撃者が最も確からしい候補を選んだときの正答率＝**事前確率の最大**（均等なら 1/K）。閾値＝係数 × 偶然の水準が 1 以上になる規則は、どの入力でも「規則適合」になるので `validate` で「判定不能（規則が退化）」にする（例の 2/K では K ≤ 2・2 巡目 Claude）。区間は人と句を単位にしたクラスタの再標本（同じ人・句の反復で独立が崩れるため・codex-consult 2）。
- 判定（3 値・/cross-review 1 巡目の Codex 1・2 巡目 Claude）: 粒度 g について、g とそれより粗くできる全粒度のうち**どれか**の区間の下端 > 閾値なら「漏れる」、**全部**の上端 ≤ 閾値なら「規則適合」、それ以外は「未決（精度不足）」。区間は記録の試行があれば人と句のクラスタの再標本、試行の無い公開の集計（正答数だけ）なら Wilson（論文と同じ）で、どちらを使ったかを限定に書く。
- 返す粒度: 「この攻撃者の族・この候補の集合で規則適合だった最も細かい粒度」（無ければ「なし」）。「安全な粒度」とは書かない。梯子の全体で 1 つを選ぶ多重性は限定に書く。候補の外の句・候補の重複・正解なしの試行は台帳の別の行。

### 3.4 面の地図への組み立て

- 予測の「読める」の行だけが「読める」の候補。同じ量が漏れる・定義しだいにも属すれば、`system_mapping` で強い規則を当てる（ADR-054 D5 判断 12）。
- `system_mapping` の値は 漏れる・読めない・定義しだい・読める・**未決** の 5 つ。どの面の未決・判定不能・未検査も、漏れの未決も、写しでは「未決」に入れ、「読める」には入れない（判断に使えない側・2 巡目 Claude）。
