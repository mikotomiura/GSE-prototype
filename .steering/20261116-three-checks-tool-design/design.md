# 3 つの検査の公開の道具の設計（採用案: v2 ＋ v1 の 5 点・/reimagine 1 回目）

初回案を見ずに、requirement.md・decisions.md（判断 1〜7）・inventory.md・ADR-054・core-and-edge-material.md だけから書いた。判断 1〜7 は制約として守り、組み替えたのはその中の構成である。数値と file:line は上の資料にあるものだけを使う。

## 0 設計の芯（v2 の 3 つの柱）

1. **検査を 1 つの枠で表す**: どの検査も「主張 × 摂動の族 × 判定の規則 → 面の判定」で書く。予測は「学習器の族」、定義は「停滞の定義の族」、漏れは「粒度 × 攻撃者の族」を摂動として振り、主張がその族の上でどうなるかを判定する。3 つを並べた道具ではなく、同じ手順を 3 つの摂動に当てる道具にする（ADR-054 Context 6 の「検査の手順としてつなぐと方法になる」に構造で答える）。
2. **規則は事前登録の様式そのもの**: 利用者が書く規則のファイル（`checks.toml`）は事前登録に貼る節と同じ文書で、道具は `freeze` でそのハッシュと入力の目録を刻んだ記録を出す。`run` は凍結した規則のハッシュと一致しなければ走らない。道具は値を 1 つも持たない（既定の例の規則は「例」としてだけ同梱する）。
3. **封をした分割**: 入力の単位の表に分割の列を持たせ、holdout の行は `run` が既定で読まない。開くのは利用者が凍結の記録に書いた 1 回だけ（判断 6 の「holdout の確認は 1 回きり」を道具の側で守る）。

## 2 構成

### 2.1 パッケージの層（依存は上から下へだけ）

```
threechecks/
  schema/      正準の表の型・検証・語彙の宣言の読み込み（3 区分への写しの検査）
  seal/        分割の封・凍結の記録（規則と入力の目録の SHA-256）
  perturb/     摂動の族を作る
    learners.py    学習器の族（判断 3）
    definitions.py 停滞の定義の族と detect（判断 4）
    granularity.py 粒度の梯子（時刻の除去・丸め・語彙の粗さ）（判断 5）
  measure/     統計量（AUC・人の中の対応つき AUC・再標本・Wilson 区間・関連の向き）
  rules/       判定の純関数（区間と帯の関係・偶然に近いか・入れ替わりの割合）
  checks/      3 つの検査（摂動 × 測り × 規則を組むだけ・計算は下の層）
  faces/       面の地図の組み立て・系への写し（強い規則）
  report/      JSON・台帳・Markdown の書き出し
  cli.py       freeze / run / validate
adapters/      入力の変換（公開データ・GSE の gse-replay 出力）。本体に依存しない別の層
examples/      既定の例の規則（論文の値）・語彙の宣言の例（14 種・16 種）
tests/         層 ①・② の回帰（§4）。tests/local/ は層 ③ の期待値のハッシュだけ
```

- `rules/` は numpy さえ持たない純関数にし、数値の入力（区間の端・点推定・件数）と規則の値だけを受ける。層 ② の回帰はこの層だけで走る。
- `checks/` は値を持たず、規則のファイルから読んだ値を `rules/` に渡すだけにする。

### 2.2 3 つの検査を共通の枠で書く

| 検査 | 主張（何について） | 摂動の族 | 測り | 判定の規則（値は利用者） | 面 |
|---|---|---|---|---|---|
| 予測 | 量 X は停滞の手前を短い休止の手前から分けるか | 学習器の族（各行で上限を取る） | 上限の AUC の区間（再標本ごとに最大を取り直す） | 同等の帯・区間幅の上限・ε | 読める／読めない／未決 |
| 定義 | 予測の判定（と結果の変数との関連の向き）は定義で残るか | 停滞の定義の族（基準の定義を 1 つ宣言） | 族の上での判定の入れ替わりの割合 | 入れ替わりの割合の閾値 | 定義しだい／残る |
| 漏れ | 保存しない内容は観測から照合されるか | 粒度の梯子 × 道具の固定の攻撃者 | 候補 K の照合の正答率と Wilson 区間 | 「偶然に近い」の規則（上端と K の関係の係数） | 漏れる（下限）／規則を満たす最も細かい粒度 |

- 定義の検査は予測の検査を包む外側の摂動として実装する（判断 4）。`checks/definition.py` は `checks/prediction.py` を族の各定義で呼び直すだけで、予測の側に定義の分岐を持たない。
- 摂動の台帳: 振った摂動（学習器 × 行、定義、粒度）ごとに 1 行を必ず書く。地図だけでなく、何通り試して何通りで判定が出たかを読み手に渡す（選んだ楽観を読み手が検出できるようにする）。

### 2.3 入力の表（正準形・CSV か Parquet）

| 表 | 必須の列 | 任意 | 欠けたとき |
|---|---|---|---|
| `units` | unit_id・person_id・obs_start_ms・obs_end_ms・split（seen／holdout） | 課題の識別 | 走らない |
| `events` | unit_id・t_ms（int64）・key_class（宣言した語彙）・class3（文字・削除・その他） | — | 走らない |
| `estimator` | unit_id・t_ms・score・estimator_id | 複数の推定器 | 予測の床の行が「未検査」 |
| `context` | unit_id・t_ms・channel・value（数値だけ・本文を持たない） | — | 「＋打鍵以外」の行が「判定不能」 |
| `outcomes` | unit_id・name・value | — | 定義の検査の関連の向きが「判定不能」（予測の入れ替わりは出す） |
| `candidates` | ① 正解つきの区間（unit_id・t の範囲・label）か ② 候補ごとの事前計算のキーの種類の列 | ② を作る関数の指定 | 漏れの面が「未検査」 |

- 語彙の宣言（`vocab.toml`）: 語彙の名前・各キーの種類から 3 区分への写し・粒度の梯子で使う粗い写し（任意）。出力の限定に語彙の名前を必ず写す（判断 2）。
- 形は inventory の「GSE の NDJSON の key 行（ms の整数・KeyCategory）」と論文 2 の `unit_record`（prep.py:54-61・t は int64 の ms・ins/dele の bool）に合わせる。`class3` の文字・削除はそれぞれ ins・dele に当たる。

### 2.4 規則のファイル（事前登録の様式から生成）

```toml
[meta]       # 事前登録の識別子・凍結の日時・証拠の格（確認／探索）を利用者が書く
[prediction] # band = [lo, hi]・width_max・eps・n_boot・seed
             # learners = 道具の族から選ぶ（族の外は書けない）
             # rows = across_person / within_person、signals = keys / keys+context
[definition] # family = {W, theta, rule, interval}・reference = 基準の定義・flip_share_max
[leak]       # K・near_chance_coef・pause_ms・ladder = [no_time, round:<ms>, vocab:<name>, ...]
[holdout]    # open = false（true にできるのは freeze の記録に一度だけ）
```

- 道具は値の既定を持たない。欠けた値は「規則が無い」として、その面を「判定不能」と返す（黙って既定で埋めない）。
- `examples/paper-defaults.toml` に論文の値を「例」として置く: 予測の `0.45, 0.55, 0.10` と ε `(0.001, 0.0)`（confirm_p1.py:45・:38）、定義の族 90 通りと B0（core.py:24-29）、関連の規則 N_BOOT=2000・PHI_CUT=1.5・SHARE_CUT=0.25（analyze.py:24-26）、漏れの Wilson 上端 ≤ 2/K（results_tables.py:518）と `PAUSE_MS=600`（closed_set.py:122）。層 ② の回帰はこのファイルを使う。
- `freeze` は規則・語彙・入力の目録（各表の SHA-256 と行数。holdout の行は数だけ）・道具の版と lockfile のハッシュをまとめた記録を出す。利用者はこれを事前登録に添える。
- 証拠の格は `[meta]` から写すだけで、道具は判断しない。凍結の記録と `run` の規則のハッシュが合わないときは、格を書き換えず、限定に「凍結の記録と不一致」と書いて止まる（未決 8）。

### 2.5 出力の形

- `map.json`: 量ごとに、面ごとの判定・測りの値と区間・規則の値・証拠の格・限定・検査していない脅威。量が複数の面に属するときは全部を残し、別に `system_mapping`（強い規則で畳んだ 1 つの写し）を付ける。
- `ledger.csv`: 摂動の台帳（摂動 1 つにつき 1 行）。
- `summary.md`: 人が読む 4 面の表（material §3 と同じ列）。
- 伏せ方: 出力は集計だけ。打鍵の列・個人の値・書き手の識別子は出さない。人の中の行は記号で、小さな数は伏せる（O1 の `cr_common.py` `public`・`coarsen`・`mask_small` を移す）。
- 来歴: 道具の版・lockfile の hash・入力の SHA-256・seed（定義・行ごとの派生）を `map.json` に刻む。
- 固定の限定の文（道具が必ず書く）: 予測は「この学習器の族に対して」、漏れは「この攻撃者の族に対する下限」、定義は「どの定義が正しいかは言わない」。検査していない脅威は、IME README L276-287 と照合の論文 threat-model.tex の項目（上界・言語モデル・同一人物の複数試行・最終本文との照合・同定と属性）を初版の一覧にする。

## 3 3 つの検査の最小の実装と面の判定

### 3.1 予測（判断 3）

1. 錨: 基準の定義で `detect` を回し、停滞の始まり s と確定 t0 = s + θ、対照の短い休止の手前を取る（`stall_anchors` :260・`control_ok` :308 の考えを移す）。
2. 量: 錨の前の窓から 18 量（`feats18` :248）を `class3` だけで計算。「＋打鍵以外」の行は `context` を足す（O1 の `feat_n` :199 の型）。
3. 学習器の族: logreg・hgb（`models` :660）を初版の族とする。行は「人をまたぐ（人を単位に分割した OOF・`oof_auc` :716）」と「人の中（時間順の後ろを取り置く・ADR-019 D3。対応つき・`matched_auc` :253。再標本は日を単位）」×「打鍵だけ／＋打鍵以外」の 4 行。人の中の行は人ごとに出す（1 人ごとの予測。人をまたぐ評価から 1 人への判断を導かない）。
4. 上限: 推定対象は「族の各学習器の性能の最大」（選ぶ手順の性能ではない）。前処理と調整は外側の分割の中で行う（入れ子）。族の各学習器の同時区間（族の数で補正）を出し、再標本の中の最大（`boot_oof` :721 を族の最大に広げたもの）は記述として並べる（§12 の 1）。
5. 判定（非対称・§12 の 1・6）: 優先順は 判定不能（入力・件数）＞ 学習の失敗・単一のクラス・NaN ＞ 幅の超過（未決）＞ 帯との関係。「読めない」は各学習器の同時区間の上端の最大が帯の上端以下で、かつ下端が帯の下端以上のとき。「読める」はどれかの学習器の同時区間の下端が帯の上端を超えるとき。帯より下は「未決（下に外れる）」、それ以外は未決。帯の判定の核は `branch`（:138。帯・幅の上限・ε は規則から）を移し、退化は `h1_branch` :153 の扱いを移す。
6. 床: `estimator` の score の AUC を同じ錨で出し、行に並べる。判定には使わない。
7. 判定不能: 打鍵以外の無い人・観測 0 の本はその行を判定不能にする（判断 3）。人の中の行は停滞の数・日の数が規則の下限（`min_stalls`・`min_days`。例は O1 の 30・5）に満たなければ判定不能。
8. 契機の印: 量ごとに「契機（停滞と確定できる時刻 t0）の時点で見える量か」を印す。止まりの最中の量（u から規則の秒数の後・O1 の `early=True`）が t0 より後の情報を含むときは「契機の後」と印し、`system_mapping` で時機の判断に使えない側に置く（ADR-054 D5 写し方 (1)・Codex round 3 の (1)）。
9. 循環の限定: 停滞の定義が打鍵だけから作られているとき、限定に「正解と量が同じ材料から来る（循環）」を自動で書く。

### 3.2 定義（判断 4）

- 族の各定義で §3.1 を呼び直し、基準の定義の判定と違う割合（入れ替わり）を出す。割合が規則の閾値を超えたら「定義しだい」、超えなければ「残る」。結果の変数があれば向き（区間が 0 の上・下・含む）も同じ族で出す（`round3_speed.py:51-53` 等に散在する判定を `rules/` に 1 つにする）。
- 再標本は論文 2 と同じく定義ごとに独立に行う（`[seed, crc32(定義の id)]` で派生・並列数に依らない）。族で添字を共有する近道は既定にせず、未決 6 に残す。

### 3.3 漏れ（判断 5）

- 候補: ① は区間の `key_class` 列をそのまま候補の観測とし、② は事前計算の列を受ける（IME 論文の 0.9019 の再現は ② で渡す）。
- 攻撃者: `closed_set.py` の `_tokens` :156・`_distance` :183・`attack` :261 を固定の族として移す。粒度の比べは `coarser_or_equal` :114、時刻の除去と丸めは `apply_features`（simulate_obs.py:83）の考えを `perturb/granularity.py` に移す。
- 判定: 梯子の各粒度で正答率の Wilson 区間を出し、`near_chance_at`（上端 ≤ 係数/K）を満たす最も細かい粒度を返す。無ければ「なし」。宣言した最も細かい粒度で満たさなければ「漏れる（下限）」。

### 3.4 面の地図への組み立て

- 量ごとに面の判定を全部残し、`system_mapping` で強い規則を当てる（ADR-054 D5 判断 12）。正解の無い面（結果の変数・候補が無い等）は「未検査」で、判定の欠けを「読める」に倒さない。

## 4 完成の条件の検査（3 層・外れうる形）

## 6 既存パターンとの整合・テスト戦略・守ること

- Replay-as-Truth からは外れる（判断 1）。代わりに層 ② を道具の「判定の一致」の背骨とし、`map.json` を正準の並びで書いて golden と比べる。
- 再現性: lockfile を持つ（inventory「横断」4 の穴を埋める）。乱数の seed は規則のファイルに書かせ、凍結の記録に入る。
- 守ること:
  - holdout を開かない（設計でも、道具の層 ③ でも封のまま）。
  - 打鍵の記録・NDJSON・公開データの中身を外部の LLM（Codex を含む）に送らない。送るのは設計の抜粋だけ。
  - 公開 repo に `.steering/` と GSE の docs を入れない。入れるのは道具のコード・例の規則・合成の fixture・数値の中間だけ。
  - `context` は数値だけを受け、文字列の列があれば `validate` で拒む（本文を入れさせない）。
