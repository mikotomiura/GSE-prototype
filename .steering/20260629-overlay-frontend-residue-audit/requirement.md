# 要件: オーバーレイ残存/クリック奪取フロントエンドバグの厳密監査 (Windows)

## 最重要・前提の訂正
**先行タスク `20260629-macos-overlay-idle-clickthrough` の幾何退避修正 (v0.1.21 にリリース済) は
Windows で不十分だった。** 実機検証で **ランダムプローブ後の idle 残存バグがまだ発症**している
(透明オーバーレイ窓が画面に残り背後クリックを奪う)。よって「修正済」と扱わないこと。

## 背景
- 観測 OS は **Windows 11** (被験者環境・プライマリ)。透明 Tauri/WebView2 窓は
  `setIgnoreCursorEvents(true)` でもクリックを素通りさせない既知制約 (Tauri #11461/#13070/#2090)。
  → Windows ではクリック透過に頼れず、**幾何退避 (画面外移動) が唯一の堅牢策**のはずだった。
- だが幾何退避を入れてもランダムプローブ後に残存が再現 = **退避が実際には効いていない / 後で
  上書きされている / そもそも idle 分岐に到達していない** のいずれか。原因未確定。
- セッション記録自体は健全 (別途検証済: feat 1Hz 連続・プローブ 3/3 ラベル一致・session_end 正常)。
  本件は **記録ではなくフロントエンドの窓状態制御 (Overlay.tsx)** の問題。

## ゴール
1. **厳密に判定する (推測で直さない)**: Windows 実機で、各オーバーレイ状態遷移の**直後に窓の実
   位置・サイズ・ignoresMouseEvents を読み返して計測**し、残存が「どの状態」で「なぜ」起きるかを
   一次情報で確定する。
2. **全状態を網羅監査**: 同種の残存/クリック奪取バグが以下のどれで起きるかを白黒つける:
   - random probe → 回答/スキップ → idle (**既に再現**)
   - Nudge ("Pause point" カード) → dismiss/silent → idle
   - Wall (全画面ブロック) → 解除 → idle
   - probe ⇄ nudge ⇄ wall の相互遷移・連続発火
   - 起動直後 idle / セッション開始前後
3. 確定した真因に対し、Windows で**確実に効く**修正を入れ、計測で回帰番兵を残す。

## 受け入れ条件
- [ ] Windows 実機で、上記すべての遷移後 idle にて **画面全域で背後アプリがクリックできる**。
- [ ] 各遷移直後の窓計測ログで、idle 時に窓が画面外 (x<=-10000 等) または不可視であることを確認。
- [ ] Probe/Nudge カードは表示時クリック可・カード外透過、Wall は全画面ブロック (非回帰)。
- [ ] フォーカス非奪取 (D12)・hide/orderOut 不使用 (D10)・maximize 不使用 (D8) を維持。
- [ ] macOS 非回帰。

## 非対象
- セッション記録/プローブ収量/提出パイプライン (別途検証済・別タスク)。
- idle 残存以外の HMM/介入ロジック。
