## ★★★ S4-D4: 混同テストは **盲検・強制選択トライアル**。**60 s × 10 回/案**、★ **閾値 7/8**（研究者判断・grill）

- **決定**: §4c の混同テスト（本 Step の関門）を、印象の聴取ではなく **盲検の強制選択**で行う。

  | 項目 | 値 |
  |---|---|
  | 1 トライアルの長さ | **60 s** |
  | 1 案あたりのトライアル数 | **10**（層 0 が動く **4** / 層 2 が動く **4** / ★ **何も動かない catch 2**） |
  | 回答 | **『いま変わったのは 基層 / 自分 / わからない』の強制選択** |
  | ★ **案を残す閾値** | ★ **採点 8 問中 7 問以上正答**（二項検定 片側 **p = 0.035**） |
  | catch の役割 | ★ **「いつも何か変わったと答える」応答バイアスの検出**（採点には入れない） |
  | 対象 | **A 案（周波数で分ける）/ B 案（次元で分ける）/ C 案（両方）** |

- ★★ **なぜ 60 s か（数値の出所を書く。発明していない）**: `spec` §1.3 が要求する平滑化は
  **時定数 τ ≥ 60 秒**（**交渉不可・数値で固定**）であり、★ **変化が耳に届くまでに 1 時定数（63% 到達）が要る。**
  → **トライアルを 60 s より短くすると「案が悪い」と「まだ届いていない」が区別できない。**
- **理由（形式の選択）**: ★ **偽陽性は好みの問題ではなく事実の問題である。**
  自由試聴で得られるのは「区別できたつもり」であって「実際に区別できた」ではない。
  ⚠️ `spec` §5 要件 3 が挙げる前科 **3 例**（[V35] / [P71] / [P73]）は、すべて
  **「主観は動くが客観は動かない」**形である。★ **最も安全側の判断を、最も主観的な計器で下さない。**
- ⚠️★★★ **正直に書く限界（★ この検定を過大に読まない）**:
  1. ★ **n = 1 である。** これは統計的検出力を持った検定ではなく **スクリーニング**である。
  2. ★ **3 案を測るので多重比較が効く。** Bonferroni（α = 0.0167）を適用すると
     **7/8（p = 0.035）は閾値を通らない**。★ **本 Step は補正を適用しない**が、
     ⚠️ **「有意に区別できた」ではなく「7/8 以上の案だけ残した」と書く。**
  3. ★ **判定の向きは非対称にする** —— 閾値は **「落とす」ために使い、「残った案が安全である」証明には使わない。**
- **却下案**: 自由試聴で印象を述べる（Step 3 と同じ形）→ 速いが、
  ★ **「区別できたつもり」と「実際に区別できた」を切り分けられない。**
- **却下案**: 自由試聴 → 絞ってから盲検 → 時間は最も掛かる。研究者は今セッションで聴くと決めており、
  ★ **絞る工程で「聴きやすかった案」に引っ張られる**（盲検の目的を先に汚す）。

## ★★ S4-D5: 盲検の刺激は **合成注入**。実データは **自由試聴**で使う（研究者判断・grill）

## ★★★ S4-D8: 層 0 のコードは **複製する。ただし「2 実装になっていないこと」を検査で固定する**

> ★ **S4-D2 で TD を却下した理由が、そのまま自分に跳ね返ってくる問題。先に手当てする。**

- **背景**: `reproducibility-discipline` ルール 1 は **実験を `experiments/<date>-<name>/` に隔離**せよと言う。
  ★ **Step 4 の player が Step 3 の HTML を読みに行くと隔離が壊れる**（Step 3 を直すと Step 4 の音が変わる）。
  ⚠️ **しかし複製すると、S4-D2 が TD を却下した理由「層 0 が 2 実装になる」に自分で当たる。**
- **決定**: ★ **複製する。そのうえで、複製が乖離していないことを `step4_selftest.py` が毎回実測する。**
  `step4.html` と `layer0.html` の**両方から同名関数を抽出して正規化比較**し、
  **一致しなければ FAIL** にする（対象: `partialAmps` / `buildGraph` / `dbToLinDev` /
  `maxPartials` / `allDriftRates` / `hannAmplitude` / `decimate` / `sincGain`）。
- ★★ **理由**: **「2 実装が危険」なのは、2 つが黙って乖離するからである。**
  ★ **乖離した瞬間に赤くなるなら、それはもう「2 実装」ではなく「検査付きの複製」である。**
  → **隔離（ルール 1）と単一性（S4-D2）を両立できる唯一の形。**
  これは `verify-before-claiming` ルール 6（**主張を書いたら、それを検査するものを一緒に置く**）の適用でもある。
- ⚠️ **層 2 を足すために層 0 側へ手を入れる必要が出たら、この検査が必ず赤くなる。**
  ★ **そのときは「検査を緩める」のではなく、Step 3 側にも同じ変更を入れて両方を動かす**
  （＝ 単一実装であり続ける）。**赤を消すために比較対象を減らさない。**
- **却下案 A**: Step 4 から Step 3 の HTML / JS を直接読み込む → 隔離が壊れる。
  ★ **完了した実験のファイルが、後の実験の依存物になる**のは再現性規約の意図に反する。

## ⚠️★★★ S4-D9: **S4-D5 の「τ≥60 s の一次遅れを通す」を raised-cosine へ改訂する**

> ★ **実装後のレビューで欠点が出たので、決定を書き換える**（実装だけ直して決定を放置しない）。

- **背景**: S4-D5 は「合成注入でもステップを直接当てず、**τ≥60 s の一次遅れを通す**」と決めた。
  ⚠️ **しかし一次遅れは 1 時定数で 63% しか到達せず、37% が次のトライアルへ持ち越される。**
  ★ **その結果、catch トライアル（何も動かさない）でも前の変化が動き続け、
    「いつも何か変わったと答える」応答バイアスの検出（S4-D4 の catch）が成立しない。**
- **決定**: 合成注入の遷移を **raised-cosine（`transition_s = 60 s` で完全到達）** に替える。
- ★★ **理由（★ 「緩めた」のではなく、2 点とも安全側に強くなる）**:
  1. ★ **始端・終端の傾きが 0**。⚠️ **一次遅れは t=0 で傾きが最大**（＝導関数に角がある）。

  2. ★ **`transition_s` で完全に到達するので残留がゼロ。** catch が本当に「何も動かない」になる。
  3. 帯域は約 **1/60 = 0.017 Hz** で `spec` §1.3 の上限に収まり、**禁止帯からは 2 桁下のまま**。
- ⚠️ **実データ経路には掛けない** —— CSV は既に `expr_smooth.py --tau 60` を通っている（二重掛けしない）。
- ★ **検査を一緒に置いた**（`verify-before-claiming` ルール 6）:
  `transition_s >= 60` / `transition_s <= trial_seconds` / 帯域が禁止帯の外 / player に式が実在。
  ★ **各トライアルの開始時残留を `results` に記録する**（「なるはず」で済ませない）。
- **却下案**: トライアルを 90 s に延ばす → 残留は 22% に減るが**ゼロにならない**。試聴時間は 1.5 倍。
- **却下案**: catch を採点から事後に外す → ★ **実施後の事後除外は不可**（S4-D4 の閾値の意味が壊れる）。
