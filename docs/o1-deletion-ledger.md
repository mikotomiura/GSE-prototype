## §1 ⚠️★★★ 「送る前」と「送ったあと」で手順が違う

★ O1 のログは **1 日ごとに閉じ、そこから 48 時間おいて**自動提出される
（`o1.rs:62` `SUBMIT_GRACE_MS = 48h`）。★ この 48 時間が**削除保証を守るための機構**である。

| いつ | 誰が消すか | 何が起きるか |
|---|---|---|
| ★ **提出される前**（その日＋約 2 日） | ★ **被験者が自分の端末で**（アプリの「この時間帯の記録を消す」） | ★ 端末上の `gse_o1_*.ndjson` から該当行が消える。⚠️ **研究者には届かない** |
| ⚠️ **提出されたあと** | ★ **研究者が本手順で** | ⚠️ **被験者の端末操作では消えない。** ★ 本文書 §3 の全経路を回す |

### ⚠️ なぜ端末操作では消えないのか（一次資料）

`delete_time_range`（`lib.rs:1342-1466`）→ `redact_dir`（`redaction.rs:154-183`）は
**`gse_*.ndjson` の通常ファイルだけ**を書き換える。★ 対象の判定は
`is_redactable_session_file`（**`redaction.rs:188-196`**・呼び出しは `redaction.rs:169`）で、
`name.ends_with(".ndjson")` を要求する。

→ ⚠️ **`.age`（提出物）は `.ndjson` で終わらないので構造的に対象外**である。
★ `redaction.rs` に `.age` という語は 1 度も出てこない（除外は帰結であって明示ではない）。

> ⚠️★ **既存文書の行番号がずれている**（2026-08-28 に実測）。
> `.claude/skills/data-privacy/SKILL.md:179` と `docs/adr/ADR-014-…:430` は根拠として
> `redaction.rs:174-181` を挙げるが、そこは `redact_dir` の**ループ本体**であって、
> 除外を決めているのは **`redaction.rs:188-196`** である。★ 主張は正しいが出所がずれている。

## §2 ★ 削除要求の経路（⚠️ 被験者に理由を尋ねない）

1. ★ 被験者が **口頭・メール・フォームのいずれか**で研究者に申し出る
   （宛先: 三浦尊統／ZEN大学／`mmiura.network@gmail.com`）。
   ⚠️★★★ **理由を尋ねない。**（同意文書 §4 逐語「理由を説明する必要はありません」）
   ⚠️ `delete_time_range` は**引数に理由を持たない**（`lib.rs:1347` 逐語
   「⚠️ **引数に理由が無い。★ 追加してはならない**」）。★ 運用でも揃える。
2. ★ 受け取る情報は **P-ID と時間帯（または「全部」）だけ**。
3. ★ **§3 のチェックリストを上から順に全部回す。**
4. ★ 終わったら **§6 の表に 1 行足してコミットする。**
5. ★ 被験者に「消しました」と伝える（⚠️ 何を消したかの内訳は返さない）。

⚠️ ★ **参加の取りやめ**も同じ経路で扱う（同意文書 §4 逐語「やめた時点で、
それまでの記録をすべて削除するよう求めることもできます」）。★ その場合は時間帯＝全期間とする。

## §4 ⚠️★★★ gse-dataset に O1 を出すと、削除が git 履歴の書き換えになる

★ 2026-08-28 に**実測で確認した穴**である。

| 実測 | 結果 |
|---|---|
| `scripts/sync-session.sh` / `sync-session.ps1` に O1 を弾く記述はあるか | ⚠️ **`o1` の出現 0 件**＝**弾いていない** |
| gse-dataset の `.gitignore` は `metrics/` を除外しているか | ⚠️ **していない**（除外は `raw/**/*.ndjson` 等の NDJSON だけ） |
| `metrics/` は実際に追跡・push されているか | ⚠️ **されている**（`git ls-files metrics/` = **34 件**） |

→ ⚠️★★★ **O1 のセッションを `sync-session.sh` に通すと、O1 由来の `metrics.json` が
private repo にコミットされ push される。** ★ そうなると削除は
**force push を伴う履歴の書き換え**になり、⚠️ **他の clone には残り続ける**。

### ★ 運用上の規則（⚠️ 守れないなら O1 を dataset に出さない）

1. ⚠️★★★ **O1 のセッションを `sync-session.*` に通さない。**
   ★ O1 の解析は**研究者端末のローカルで完結させる**（`experiments/` に来歴のみ残す）。
2. ★ どうしても dataset に出す必要が生じたら、**先に本文書を改訂して**
   「削除が履歴書き換えになる」ことを同意文書に反映してから行う。
3. ★ 起票済み: **`sync-session.*` に `gse_o1_*` を弾くガードを足す**（本タスクでは未実施）。
   ⚠️ ガードが無い今は**人の注意だけが防波堤**である。

## §6 ★ 実施記録（⚠️ **メタデータのみ**。append-only）

⚠️ ★ **P-ID・日付・件数・実施者だけを書く。** 氏名・連絡先・時間帯の中身・作業内容を書かない。

| 受付日 | P-ID | 範囲 | A-1..A-8 完了 | B-1..B-6 依頼/完了 | 削除件数 | 実施者 | 備考 |
|---|---|---|---|---|---|---|---|
| （まだ 1 件も無い） | | | | | | | |

### 記入の仕方

- **受付日** … 申し出を受けた日（YYYY-MM-DD）。⚠️ 時刻は書かない
- **範囲** … `全期間` または `YYYY-MM-DD の一部`。⚠️ 何時から何時までかは書かない
- **A-1..A-8 完了** … 全部済んだら `✅`。⚠️ **一部だけなら `⚠️ 未完（A-5）` のように残す**
- **B-1..B-6** … 被験者への依頼日と、完了の連絡を受けた日
- **削除件数** … `.age` 何本 / metrics 何件
- **実施者** … ★ **イニシャルまたは役割**（例 `PI` / `M.M.`）。⚠️ 実名を書かない
  （★ 本ファイルは repo に入る。⚠️ 研究チーム構成員の PII を git 履歴に永久化しない）
