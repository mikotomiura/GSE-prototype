## Context

### 1. 作業時間の相当部分が「打鍵が薄い」ことが実測された

`experiments/20260816-cv-gate-null/` は P010–P014 の 5 分窓 617 個について次を出している:

| ゲート | 残る窓 | 落ちた窓 | 除外率 |
|---|---|---|---|
| なし | 617 | 0 | — |
| `keydown ≥ 1` | 494 | 123 | 打鍵ゼロが **19.94%** |
| `≥ 100`（G1 事前登録 §2.9 で凍結） | 382 | 235 | **38.09%** |

⚠️★★★ **ただし 38.09% は上限側の数字である。**
`experiments/20260815-expression-power/data.md:40-42` 逐語:

> 事前登録は逐語で **「論述セッション」** と限定しており、本実験は **全セッションを入れている**
> （読解・離席を多く含む）。→ **「事前登録の数字を再現した」とは書かない。本実験の CV は上限側である。**

★ **確証解析の母集団（論述セッション）では G1 事前登録 §2.9 が `<100` を 29%・360 窓と記録している。**

### 2. 低打鍵窓は打鍵分布の裾ではなく別の集団である

`cv-gate-null §3-4 (b)`: 左側打ち切り最尤で当てた対数正規から `[1, 100)` の期待窓数を外挿すると、
**情報のある 4 名すべてで H0 予測の 4.7〜19.9 倍の低打鍵窓が観測される**。
→ ★ **ゼロ打鍵窓とは別に「席にいて作業しているが打鍵しない」モードが実在する。**

補強: `experiments/20260802-task-scope-detector/notes.md §3` は `keys/min` が
P011=252.0 / P013=21.2 と **12 倍差**である一方、`iki_p50` は 142–185ms で **ほぼ同一**であると実測している。
→ ★ **差は「打つ速さ」ではなく「打っていない時間の割合」である。**

### 3. しかし文献は「モダリティを足せば当たる」を支持していない

[P118] の限界利得 **+0.9pt**、[P120] は切替単独で [P118] の全部入りと同帯域、
[P117] は**アプリ識別子依存**（GSE が `data-privacy` で禁じた情報）でなお precision 0.57（base rate ≈0.5）、
[V84] は無作為基線 +15% 止まり、[P119] は実配備実績があるが **低操作量側の弁別を一度も要求されていない**。
→ ★ **問いは「モダリティを足すか」ではなく「打鍵が無い窓で *何を* 弁別したいのか」である。**

### 4. `§8` 段別表は T1/T2 を「抑制側のみ」と決めており、正面から矛盾する

`docs/research-positioning.md:537-547`（2026-08-16 研究者決定）は T1/T2 について
「**`Need` 推定から外し、`evidence_quality` の減衰＝介入を *抑制* する側にのみ使う**」と決めている。
⚠️ しかし **打鍵が薄すぎて T0 が動かない窓では、抑制する対象の推定そのものが無い。**
→ 「低打鍵窓を検出できるようにする」は定義上 T1/T2 の**検出側への昇格**を意味する。

## Decision

### D1. 低打鍵窓の弁別対象を「在席×非打鍵 / 入力皆無」の 2 分割に置く

⚠️ 「停滞 / 熟考 / 離席」の 3 分割や、[P121] mid 帯の「離脱 / 外部資源への相談」は
**正解ラベルが Phase1 に存在しない**（content-free 制約・`cv-gate-null §5-4` 逐語
「**「ゼロ打鍵窓＝離席/非打鍵作業」は解釈であって観測ではない**」）。

★ **「在席×非打鍵 / 入力皆無」だけが、既存ログから構造的に決まる。**
`src-tauri/src/input/liveness.rs:86-104` の `step()` は
`system_input_seen && !hook_event_seen` でのみ `starved_ms` を進め、`!system_input_seen` では**凍結する**。
→ **`starved_ms` は「沈黙のあいだ入力デバイスに触れていた累積時間」そのものである。**

### D2. 「低打鍵窓の弁別」を `§8` 段別表の **外** の探索トラックとして新設する

⚠️ **`§8` の T1/T2 行は据え置く**（抑制側のまま）。**`§9` A-Q3 の解除条件も変更しない。**
★ 昇格の可否は、探索トラックの実測を見てから**別途裁く**。

★ **理由**: 実測なしで 2026-08-16 の研究者決定を書き換えない。かつ、
`§9` A-Q3 の解除条件①（検出力の算術）は**未了**である。
→ **確証核 L0 は 1 ミリも動かない**（`§9` A-Q2「確証核は固定したまま動かさない」と整合）。

### D3. 適格性ゲート `keydown ≥ 100` は触らない

G1 事前登録 §2.9 で凍結済みであり、⚠️★★★ **2026-08-19 のリブート後も 1 文字も変えていない**
（`preregistration.md` 第 17 版が「**適格性ゲート `keydown ≥ 100` も変えていない**」と明記した。
★ 触ると `§9` A-Q3 が基準にしている CV `0.502` の再計算に波及する）。
~~**G1 は実施中（1/3 名）**である。~~ → ★ 現在は **確証標本 0/3 名**（収集はリブート待ち）。
⚠️ 実施中に適格性基準を動かすのは PreReg-5 が排除したい forking paths を直接踏む。
★ 探索トラックは**ゲートを適用しない**（617 窓）。確証解析は**ゲートを適用したまま**（382 窓）。
⚠️ **2 トラックの結果を混ぜない。**

### D4. ⚠️★★★ 「読む実装」は G1 判定まで出さない。探索トラックは `experiments/` に閉じる

★ **本 ADR は §Context-5 の順序を維持する。**
`paste` / `keys` / `bs_keys` / `ime_dwell` を `engine.rs` や X/Y 合成式へ流すこと、
`ContextBuilder` / `PersonalizationStore` / `OnlineUpdater` を入れることは、**G1 の判定後**とする。

★ 代わりに **`experiments/` でのオフライン再解析**は G1 に依存しない。
理由は `§10` の例外注記と同型である —— **パイプラインを作らないから**である。
`src-tauri/` を 1 バイトも変えず、`HMM_VERSION` を動かさず、ゴールデンにも schema にも触れない。

| | 本番推論経路 | 探索トラック（`experiments/`） |
|---|---|---|
| `src-tauri/` | ⚠️ **G1 判定後** | ★ **変更しない** |
| `HMM_VERSION` | bump が要る | ★ 不変 |
| ゴールデン | 再生成が要る | ★ 不変 |
| 確証主張 | 使える | ⚠️ **使わない** |

### D5. ⚠️ `starved_ms` の**用途転用**であることを明示する

`src-tauri/src/input/liveness.rs` のテスト `mouse_only_work_is_a_known_false_positive` は
「**マウスだけ動かしている人も Down になる**」を **仕様として固定**している
（逐語「この挙動を『バグ』ではなく『限界』として明示的に残す」）。

★★★ **本 ADR はその「誤検知」を信号として使い直す。**
同テストの逐語は続けてこう書いている:

> → だから NDJSON には `starved_ms` を載せ、**後から再解釈できる**ようにしてある。

★ **設計者が明示的に用意した再解釈の余地**を使う。⚠️ ただし転用であることを実験文書に明記する。

⚠️ **`starved_ms` は「入力デバイスに触れた」ことしか意味しない。「作業していた」ことの証明ではない。**

### D6. 「38.09%」を単独で書かない

⚠️ **38.09%（617 窓・全セッション・上限側）と 29%（360 窓・論述限定・確証母集団）を必ず併記する。**
★ `cv-gate-null §4-3` が「式を使うときは必ず**どの閾値の下での値か**を併記する」と決めた規律と同型であり、
**「どの母集団の下での値か」も同じ扱いにする。**

### D7. 「個人差が支配的」とは書かない

Phase1 の `session_meta.task_kind` は **全 40 セッションが `argumentative`（分散ゼロ）**
（`experiments/20260802-task-scope-detector/data.md:14`）であり、同 `notes.md §発見3` は
「**宣言された `task_kind` は教師として使えない**」「較正プロトコルが値を固定してしまうため、
宣言値は『実際に何をしたか』と独立に決まる」と実測している。

→ ⚠️ **「個人差か実タスク差か」は Phase1 データでは原理的に切り分けられない。**
★ これは ADR-008 Context の Codex 指摘（「『個人差』が実は作業種別差の可能性」）に対して、
**Phase1 が材料を提供できない**ことを意味する。⚠️ **記述に留め、観測空間拡張の正当化には使わない**
（`§9` A-Q3 は正当化を**検出力の算術**で書くことを要求している）。

## Alternatives

- **T1/T2 を低打鍵窓に限って検出側へ今すぐ昇格させる**: 実測なしで 2026-08-16 の研究者決定を
  書き換えることになる。文献も支持していない（[P118] +0.9pt / 低操作量側を割った先行はゼロ）。却下。
- **何もしない（低打鍵窓は今後も除外のまま）**: `§1` の問い「デスク上の行動から停滞を推定できるか」に対し、
  作業時間の相当部分を測らないと宣言することになる。却下。
- **`keys` / `paste` を `engine.rs` へ流す（handoff の初案）**: §Context-5 のとおり
  SSOT が G1 判定に紐づけた「読む実装」に当たる。★ **G1 の判定後に再検討する**（却下ではなく順序の問題）。
- **適格性ゲートを `starved_ms` ベースの在席判定へ置換する**: 事前登録の事後改訂であり、
  `§9` A-Q3 が基準にしている CV `0.502` の再計算まで波及する。却下。
- **マウス / `EVENT_SYSTEM_FOREGROUND` の新規フックを実装する**: input 層の新規実装で
  Win/mac 両方が要り、前セッション D-7 が別タスクと決めている。★ **本 ADR の射程外**。

## Consequences

- ★ **`src-tauri/` は無変更。** `HMM_VERSION` は `0.4.0` のまま、ゴールデン 6 本・
  `schema/current.json`・gse-dataset に差分ゼロ。
- ★ `§8` 段別表と `§9` A-Q3 は**不変**。追記のみ。確証核 L0 も不変。
- ⚠️ **探索トラックの結果は確証主張に使えない。** 昇格の可否を裁くには、
  `§9` A-Q3 の解除条件①（検出力の算術）を別途埋める必要がある（G1 待ち）。
- ⚠️ **本 ADR が依存しているのは「記録の仕様」であって「実験のためのインタフェース」ではない。**
  `hook_health` の出力条件・閾値（`liveness.rs:63-66` / `lib.rs:2923`）が変わったら
  **旧ログと新ログを混ぜてはならず、探索トラックの結果は再計算が要る**。
- ⚠️ **30 秒未満の沈黙は既存ログに残っていない**（`lib.rs:2923` の間引き）。
  → **micro 帯（2–15 秒 = [P121] が「局所思考」と位置づけた帯）については何も言えない。**
  ★ 収集側を改める投資判断は、探索トラックが「情報がある」側に出たときに初めて費用対効果を持つ。

### ⚠️★★★ 2026-08-19 実施記録 — **計器は Phase1 コホートに存在しなかった**

`experiments/20260819-silence-presence-decomposition/` を実行した結果、
**Phase1 コホート（P010–P014）の NDJSON には `hook_health` 行が 63 ファイル中 1 行も無い**ことが判明した。

| 事実 | 出所 |
|---|---|
| 本コホートの記録期間 | **2026-07-04 〜 2026-07-24**（実測） |
| `src-tauri/src/input/liveness.rs` の追加コミット | **2026-08-09** |

→ ★★★ **計器は収集が終わった 16 日後に作られた。**
⚠️ **したがって D1（`starved_ms` による 2 分割）は、Phase1 コホートには適用できない。**
★ **設計と実装は有効であり、`liveness.rs` 導入以降のログ（G1 を含む）ではそのまま走る**
（`validate_blocks.py:494` が G1 ログの `hook_health` を機械判定している）。

⚠️★★★ **教訓（Tier 0 と同型）**: 「既存ログにある」は**現行コードが出す**の意味であって、
**対象コホートにある**の意味ではない。`§5.2` は `keys`/`bs_keys` について
「⚠️ **旧 NDJSON には本フィールドが無い**」と警告しており、**同じ検査を `hook_health` にも
先に当てるべきだった**。→ ★ **収集済み信号を使う設計では、必ず「対象ログの行種を数える」を最初に置く。**

★ **それでも model-free の層（L1/L2）は結論を出した**（`notes.md §2`）:
**適格性ゲートが落とす 235 窓は、時間の 84.3% が ≥30 秒の沈黙**である。
特に `1–99` 打鍵の窓（`cv-gate-null` が「余分な質量」と特定した帯）は **87.0%** が沈黙で最大。
→ ★ **「打鍵が薄い窓を測る」とは「長い沈黙の中身を割る」ことに他ならない**ことが実測で裏づいた。
⚠️ **ただしその中身は依然として不明である**（本 ADR の D1 は未検証のまま）。
