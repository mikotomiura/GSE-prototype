## Context

### 実測（推測ではない）

- **旧 X 軸（Cognitive Friction）は主観摩擦を予測できていない**。最も検定力のある P010（n=103）で
  全特徴量が偶然水準（f1=0.442 / f3=0.507 / f5=0.468 / 合成 0.503）。Bonferroni 通過は到達可能な
  70/103 セルでゼロ。
- **φ 正規化は単調変換なので C-index をほぼ変えない**（実測差ほぼ ≤0.03）。
  → 「生特徴量が偶然水準」は **β に依存しない結論**であり、正規化修正では解けない。
- **産出側には弱いが一貫した信号がある**。単純な `keys`→Q2 の個人内 C-index が
  0.615/0.600/0.657/0.676（P014 のみ 0.368）で、**現行 5 特徴量のどれよりも高い**。
- **ラベルの供給が壊れた**。Phase1 は probe 枯渇・P013 の straight-lining により GATE3 = DataInsufficient。
  旧 X 軸の criterion は主観プローブ Q1 であり、**まさにそこで死んだ**。

### 提案されていた案の破綻

`.idea` doc#2 §4.1 は latent state を
`Progress / Stagnation / ExternalizationPressure / Receptivity` の 4 つに限定し、
`z_t ~ p(z_t | z_(t-1), context_t, head)` と categorical（相互排他）を主張していた。これは成立しない:

1. **相互排他でない**（Receptivity は Progress と排他でない）。1 つの潜在次元の分割になっていない。
2. **Receptivity は観測の放出元でない**。入力（cooldown / daily_cap / recent_dismiss / time-of-day）は
   システム状態と履歴であり、潜在状態からの放出ではない。**放出モデルが書けない**。
3. **ExternalizationPressure は状態でなく傾向**で、§0 の X 軸定義と機能が重複し循環する。
4. **既存 `WorkStateEstimate`（連続 proxy 5 つ）への写像が未定義**。
5. **「4」の根拠が無い**。Phase1 の 3 状態は手で選んだ状態だった。3→4 は同じ轍で、
   失敗が「ラベルの入れ替わり」から**「データ中の何にも対応しない状態」**へ移るだけである。

さらに **層跨ぎの事故**: 既存 SSOT で **Receptivity は Layer 5** の概念であり、
**ADR-007 が「分解形の維持」を Accepted** で採択済み。4 状態をそのまま昇格させると
「Layer 4 の Receptivity」と「Layer 5 の Receptivity」が並立し、**ADR-007 が静かに無効になる**。

## Decision

### D1. X 軸を `self_directed_recovery_risk` へ再定義する

> このユーザーが、この task 文脈で、**近い時間範囲（horizon H）内に自力による前進を回復できない確率**。

- Layer 4（Work-State Proxy）の**出力**とし、`WorkStateEstimate` に
  `self_directed_recovery_risk: Option<f32>` と `recovery_risk_uncertainty: Option<f32>` を
  **additive に追加**する（ADR-005 の additive 原則。既存 5 proxy は不変）。
- **採用の主要根拠は「行動から自己ラベル付けできる」こと**。criterion が主観プローブでなく
  行動（stall onset 後の自力回復までの離散時間・D2 改訂後）であるため、
  **プローブを 1 件も撃たずに教師信号が生成される**。
  Phase1 で死んだ label supply の構造問題への直接の答えである。

### D1b. 旧 X 軸（Cognitive Friction）の**格を落とす** ★D1 と対で読むこと

新軸を additive に足すだけでは不十分である。それだと「旧 X も recovery risk も**どちらも確証対象**」と読めてしまう。
**旧 X 軸は明示的に降格させる**——これは ADR-001 が HMM に対して行ったこと（ontology → Writing head の baseline）の、
**軸に対する版**である。

| 対象 | 現在 | 降格後 |
|---|---|---|
| **主張上の格** | **確証の核**（H-X1 / GATE3 = PreReg-4 の対象。`research-positioning §1`「反証可能な確証核」） | **比較用 baseline・歴史的説明**。新しい確証主張の対象にしない |
| `friction_score` フィールド | Layer 4 の主要出力 | **削除しない**（`WorkStateEstimate` に残す）。ただし主役ではない |
| 合成式 `0.30φ(F3)+0.25φ(F6)+0.25φ(F1)+0.20φ(F5)` | 手決めの重みが本番経路 | **凍結のまま維持**。新軸側では重みは学習され、手決め式は継承しない |
| `p_stuck` → Need 層 | 介入トリガの唯一の供給元 | **Phase 2b までは現行のまま**。置換は recovery risk が G2/G4 を通ってから |
| 外部説明・UI の語り | 「摩擦を推定する」 | 主要な語りにしない（ADR-001 の三状態表示の降格と同じ扱い） |

**なぜ削除ではなく降格か**: (i) Phase1 の確証トラックとの連続性を切らない、(ii) 新軸の**比較対象**として必要
（新軸が旧軸を上回らなければ、軸を変えた意味が無いことになる）、(iii) `p_stuck` は現に介入を駆動しており、
代替が G2/G4 を通る前に外すと介入機能そのものが止まる。

> ⚠️ **降格は「X の測定に失敗したから」ではなく「X には現行の観測空間で信号が無いことが実測で示されたから」**である。
> 統制タスク実験（D7 / G1）で分離できれば、旧 X が復権する余地は残る。降格は不可逆な棄却ではない。

### D2. 目的変数の operational definition を先に閉じる ★ **2026-08-01 改訂**

> **改訂の経緯**: 初版 D2 は `self_directed_recovery` を「stall onset から **H 分以内**に回復したかの**二値**」と
> 定義していた。**打ち切りのある time-to-event を固定 horizon で二値化するこの定式化は方法論的に誤りである**
> ことが一次文献で確認されたため改訂する（本 ADR は Proposed であり改訂可能）。
> 判定基準は結果を見る前に固定した: `.steering/20260801-recovery-axis-grounding/requirement.md`。
> 判定と根拠: 同 `decisions.md` 判断 1 / `docs/literature/20260801-recovery-labeling-and-online-prereg.md` RQ-1。

- `progress_proxy` = 個人×task_kind×phase 基準で正規化した**純産出の持続**
  （窓内の 挿入−削除 打鍵数を個人基準で正規化し、T 秒以内に取り消されないこと）。content-free。**不変**。
- ★ `self_directed_recovery` = **離散時間の time-to-event 観測**である。stall onset で時計をリセットし、
  幅 Δ の期 k = 1,2,… ごとに次の 4 択を記録する: `recovery` / `externalized`（paste）/
  `left_observation`（focus 喪失・アプリ切替）/ `still_stalled`。
  ラベルは二値ではなく **（イベント期 k, 種別 j）または（最終観測期 k, 打ち切り）**の組。
- ★ **H はラベル定義から外す**。H は推定器の外側にあり、**意思決定層が読み出すときのパラメータ**になる。
  ハザードから任意の H に対する `CIF_rec(H)` を計算できるため、介入層ごとに異なる H を問い合わせてよい。
- ★ **打ち切りではなく競合リスクとして扱う**。ある事象の発生が目的事象の発生を排除するとき、
  それは打ち切りではなく競合イベントであり、単純に打ち切り扱いすると発生率が上方バイアスする [V61]。
  また生存解析の独立打ち切り仮定は「事象を起こしやすいかどうかで選択的に離脱していないこと」を要求するが [V59]、
  GSE の focus 喪失は「詰まったから離脱した」形で起こりうるため**この仮定が破れている疑いが強い**。

| 事象 | 扱い |
|---|---|
| `externalized`（paste） | **競合イベント**（外部化して解決したなら自力回復ではない＝軸の定義と一致） |
| `left_observation` | ★ **競合と真の打ち切りの混合。潰さずに両方の極端で上下界を取る**（新 G2） |
| セッション終了 | 管理的打ち切り（independent） |

- ★ **反証ゲート G2 を再定義**した。旧 G2「打ち切り区間が事前宣言した割合を超えたら失格」は
  **打ち切りを捨てる前提のゲート**であり本改訂で意味を失った。新 G2 は
  **「上下界の幅が介入判断を反転させないか」**（`personalization-and-online-learning.md §3.4/§8.2`）。

> ⚠️ **一次確認は [V59]（Allison 1982）1 本**である（該当章を逐語照合）。[V60] [V61] は abstract 水準。
> ⚠️ **H の任意性は消えたが、期の幅 Δ の任意性は残る**（`personalization-and-online-learning.md §11-7`）。
> 「任意性が完全に消えた」とは主張しない。

#### ★ **どこまで測れると主張するか** ★ 2026-08-21 追記（本 ADR の主張範囲を明文化）

> ⚠️★★★ `self_directed_recovery_risk` は、**点推定として測れると主張しない。**
> ★ 測れると主張するのは、**`left_observation` の内訳に関する両極端の仮定で挟んだ上下界**である。
> ⚠️ 上下界の幅が**介入判断を反転させる**なら、**目的変数として使えない**と報告する（G2）。

★ **主張を縮めるのは弱さではない**。⚠️ 点推定を主張してしまうと、`left_observation` の混合物を
「独立打ち切り」と決めつけたことになり、**[V59] が要求する独立打ち切り仮定を破ったまま数字を出す**
ことになる（`personalization-and-online-learning.md §3.4`）。

⚠️★★ **上下界のために推定器を 2 本学習しない。** 3 カテゴリ多項モデルを**1 本だけ**学習し、
`CIF_rec(H)` を計算する**読み出し段階**で `left_observation` の扱いを切り替える。
★ 2 本学習すると**係数まで変わり**、「打ち切りの仮定だけを変えた比較」ではなくなる。

#### ★★★ G2 が落ちたときの**入口** ★ 2026-08-21 追記（それまで空欄だった）

`personalization-and-online-learning.md §8.2` の G2 失敗分岐は逐語で
「**観測空間の拡張——特に『詰まって離脱』と『無関係な離脱』を分ける手段——が先**」と書いているが、
★ **「では何を足すのか」は空欄だった。** 次を入口として記録する
（材料: `.idea/20260819-user-validation-workspace-behavior-and-mhd.md §2.1`「注意の連続性」/「回復」群）:

| 候補 | ⚠️ `left_observation` の混合をどう割るか |
|---|---|
| フォーカス喪失・**復帰の有無と時刻** | ★ 現行は**回数のみ**。「戻ってこなかった」＝真の打ち切り寄りに割れる |
| **切替後の復帰率**（個人基準） | ⚠️ 「いつもの離席」と「詰まって出た離席」の事前確率が分かれる |
| 離脱の**滞在時間** | ★ 短い離脱（通知）と長い離脱（会議）を分ける |
| ⚠️★ **役割カテゴリ**（`editor` / `terminal` / `browser`）への抽象化 | ★★★ **決定的**: `browser` へ出て `paste` + 実行を伴って戻ったなら**競合イベント**寄り、無関係な滞在なら**打ち切り**寄り |
| 停止後の**操作系列**（最初の操作・外部化後の自力作業への復帰） | ★ `recovery` の判定を `progress_proxy` 単独から**系列**へ広げる |

⚠️★★★ **これは現行の設計を 1 段越える。** 本 ADR は `left_observation` を
「**回数のみ・識別子は保存しない**」と定めており、上表は「**抽象カテゴリ**」への拡張である。
→ ★ **記録仕様の変更**なので **ADR-012（形成的トラック）/ ADR-013（計器の自己記述）の管轄**であり、
⚠️ **本 ADR では採否を決めない**。G2 が落ちたときに初めて起動する入口として置くだけである。
⚠️ 収集開始前に計器へ入れることはしない。

### D3. 潜在状態の層を ontology から head の実装詳細へ降格し、**状態数を今決めない**

```text
Layer 4 の出力（固定）
    WorkStateEstimate + self_directed_recovery_risk (+ uncertainty)

推定器（未確定・競合させる）
    ★正   baseline : 離散時間の競合リスク・ハザード（person-period 多項ロジスティック・D2 改訂後）
                     h_j(k) = softmax_j( α_j(k) + bias + (w_head + δ_user_task)·context_k )
                     潜在状態を持たない（α_j(k) は状態ではなく stall onset からの経過時間の関数）
      候補 A       : 相互排他な作業モードの状態フィルタ（例 Progressing / Stalled / Externalizing）
      候補 B       : online EM による潜在構造学習（→ D6）
```

- **stateless baseline を「正」とする**。
- `ExternalizationPressure` は**状態でなく `recovery_risk` の構成要素（特徴）**として扱う。
- **`Receptivity` は Layer 5 に戻す**。ADR-007（分解維持）を**維持**する。

### D4. 潜在状態モデルの採用ゲートを事前に宣言する

候補 A / B は次を**両方**満たしたときにだけ baseline を置き換えられる:

| ゲート | 内容 |
|---|---|
| **勝ち幅** | held-out（subject-level / task-level / session-level split **3 つとも必須**。1 つでも欠けたら失格）の recovery 予測で、stateless baseline を**事前宣言した幅**だけ上回る |
| **退化検出** | ① 状態占有エントロピーが下限超 ② 各状態の**最小占有率**が下限超（使われない状態が無い） ③ 初期値・seed を変えても**状態ラベルが安定**（label switching が起きない） |

**この退化検出の追加こそが §Context の破綻点 5 への実質的な回答**であり、状態数を変えることではない。

#### ★ 退化検出の**数値** ★ 2026-08-21 に凍結

⚠️ これらは**データのノイズ水準に依存しない**（状態占有分布の性質そのもの）ので、P1 を待たずに決めてよい:

| 条件 | 数値 | 根拠 |
|---|---|---|
| ① 状態占有エントロピー | **H(occupancy) ≥ 0.5 · log K** | ★ K 状態のうち実質半分未満しか使っていないなら「状態数を手で選んだ」失敗の再演 |
| ② 各状態の最小占有率 | **≥ 5%** | ★ 20 分の 1 未満しか出ない状態は、§Context 破綻点 5 の「**データ中の何にも対応しない状態**」 |
| ③ seed 間のラベル安定性 | **≥ 5 seed で、Hungarian 対応づけ後の一致率 ≥ 0.90** | ⚠️ label switching が起きるなら、その状態は**同定されていない** |

#### ⚠️★★★ 勝ち幅は**数値を今入れない**。「決め方」を凍結する ★ 2026-08-21

★ GATE3 の `0.65 / 0.55` はデータを見る前に凍結できた。**なぜ D4 は同じにできないのか**:

| | GATE3（H-X1） | ⚠️ D4 の勝ち幅 |
|---|---|---|
| 指標 | **C-index** | ★ **2 モデルの差**（時間依存 AUC / Brier / `CIF_rec(H)` の較正） |
| 帰無値 | ★ **0.5**（既知・普遍） | ⚠️ 0 ではあるが、**差の標準誤差が未知** |
| 慣習的な解釈尺度 | ★ **ある**（0.65 = 中程度） | ⚠️ **無い** |
| 依存する未知量 | 無し | ⚠️ **Δ・打ち切り率・被験者あたりのエピソード数** —— ★ **すべて P1 まで分からない** |

→ ⚠️★★★ **いま「+0.05」と書くのは、動作特性の分からない数を凍結することである。**
★ それは「事前宣言した」という**形式だけ**を満たし、⚠️ **ゲートとしては空振りする**。

> ★ **決め方（2026-08-21 に凍結）**: **勝ち幅は、P1 で得た `stateless baseline` の held-out 成績の
> 「fold 間標準偏差」を単位として、P2 開始前に宣言する。**
> ⚠️ 宣言するのは **P1（baseline のみ）を見た時点**であり、
> ★ **候補 A / B の成績は 1 つも見ていない**状態で固定する。
> ⚠️ **データを見てから幅を緩めることはしない。**

★ これは 2026-08-16 に Δ について研究者が採った「**決め方だけを先に固定する**」
（`personalization-and-online-learning.md §11-7`）と同じ型である。

#### ★ 指標 ★ 2026-08-21 に明記

離散時間 × 競合事象向けの **時間依存 AUC / Brier**、複数の H での **`CIF_rec(H)` の較正**
（`personalization-and-online-learning.md §8.1`）。
⚠️★★★ **単一の二値 C-index を主指標にしない** —— ★ **旧定式化の遺物**である。

### D5. 旧仮説 H-X1 を新軸へ流用しない

`research-positioning.md §5` の **H-X1 は旧 X 軸（Cognitive Friction ↔ Q1）に対する仮説**であり、
GATE3 の判定（DataInsufficient）も旧軸に対するものである。
**新軸には新しい仮説番号が要る**。本 ADR は **H-X1d（案）** を提案する:

> `self_directed_recovery_risk` は、行動由来 criterion（stall onset 後の自力回復までの離散時間・
> 競合イベントと打ち切りを含む）を個人内で偶然を超えて予測する。
> ★ 2026-08-01 の D2 改訂に追随して文言を更新した（旧: 「stall 後 H 分以内の自力回復の**有無**」）。
> 検証は二値 C-index ではなく**離散時間・競合事象向けの時間依存指標**で行う
> （`personalization-and-online-learning.md §8.1`）。

> ⚠️ `research-positioning.md §5` は「研究者による確認が必要な節」である。
> **本 ADR は提案に留め、§5 は変更しない**。採択は研究者判断。

#### ★ 研究者判断（2026-08-21）— **今は載せない。採択は P2 開始時。**

⚠️ ★ **「載せない」ことをここに明記する。** さもないと次に読む人が
「新軸は仮説として登録されていない ＝ 存在しない」と読む。

理由:

1. ★ `§5` の**確証ゲートは H-X1 / H-X1b（ともに L0 軸）のみ**である。⚠️ いま H-X1d を載せると
   「**確証の核が 2 つある**」と読め、★ **D1b（旧 X 軸の降格）の意味がぼやける**
   —— 降格したのに新旧どちらも確証対象、という形になる。
2. ⚠️★★★ **D7 により検証はどの道 G1 の後**である。手続きを書けないまま番号だけ先行させると、
   ★ 「登録されているのに検証手続きが無い仮説」ができる。
3. ⚠️ 目的変数の **Δ とリンク関数が未決**（§11-7）。検証手続きの中核が空欄のまま登録することになる。

→ ★ **採択の時期は P2 開始時**（`personalization-and-online-learning.md §10` の P2）。
そのとき §5 へ H-X1d を追記するかを研究者が決める。

### D6. online EM は Phase 4 へ降格する（理由を明文化する）

降格の理由は「重い」でも「難しい」でもなく、**3 つの前提が揃っていないため現時点で評価不能**だからである:

1. **目的変数が未確定だった**（D2 で今回閉じた）。何に対して「良い潜在状態」かが定義されていなければ
   当たり外れを判定できない。
2. **比較対象（baseline）が無かった**（D3 で置いた）。
3. **識別可能性が未解決**。教師なし EM はクラスタを作るが Stuck は作らない。
   半教師ありアンカーに使う予定だったラベルは **Phase1 でまさに枯渇した**。

→ 「本命を降格した」のではなく「前提が揃うまで評価できないので順序を後ろに置いた」。
D4 のゲートを通れば Phase 4 で復活しうる。

### D7. 軸を書き換えても統制タスク実験は免除されない

「打鍵由来の content-free イベントで作業状態を分離できるか」という**測定可能性の問いは未検証のまま**である。
高摩擦を誘発する短い統制タスクを作り同一人物内で低/高条件を交互に取る実験を、
**新軸に対しても必要な反証ゲート**として設計に組み込む（`personalization-and-online-learning.md §8.2` G1）。
凍結解除後の最初のタスクに置く。

#### ★ 帰結の明文確認（2026-08-21）

> ★ **議論を先に進めても、実装は G1 の後である。**
> ⚠️ X 軸を書き換えても G1 は免除されず、**G1 の結果を待つ構造は変わらない**。

#### ⚠️★★★ G1 を「較正環境」へ縮小する案は**採らない**（2026-08-21 裁定）

`.idea/20260819-user-validation-workspace-behavior-and-mhd.md §4` は逐語で
「**G1 は、既知の課題条件で計測器と特徴の対応を確認する短い較正環境に縮小する**」
「ランダムプローブを主軸にしない」と書いている。

⚠️ 一方、本 ADR と `§8.2` の G1 は**反証ゲート**である ——
「分離できないなら、自然ログで粘る前に**軸そのものを疑う**」。

→ ⚠️★★★ **この 2 つは両立しない。** メモの文言をそのまま昇格させると
**G1 が「較正」に化けて反証ゲートが消える** ——
つまり ★ **測定可能性の問いが永久に答えられないまま、パイプラインだけが積み上がる。**

| | 扱い |
|---|---|
| **いま走らせる G1** | ★ **反証ゲートのまま。1 文字も変えない**（`experiments/20260801-controlled-friction-task/preregistration.md` 第 17 版） |
| メモ §4 の「較正環境へ縮小」 | ⚠️ **次段の話**。★ **G1 の結果が出てから**、G1 が反証ゲートとして機能したかを見て判断する |

⚠️ **順序が逆になってはならない** —— ★ 「G1 を較正に縮小してよいか」は
**G1 を反証ゲートとして 1 回走らせた結果**でしか判断できない。

## Alternatives

- **旧 X 軸を維持し、正規化と重み付けを直す**: φ が単調変換である以上 C-index はほぼ動かない（実測）。
  正規化修正は衛生管理としては実施すべきだが、**決定的実験ではない**。却下。
- **doc#2 の 4 状態をそのまま採る**: §Context の 5 点で破綻し、ADR-007 を静かに無効化する。却下。
- **3 モード（Progressing / Stalled / Externalizing）を今確定する**: 破綻点 1〜4 は解けるが、
  **破綻点 5（状態数を手で選ぶこと自体）を 4→3 の向きで繰り返す**。
  「なぜ 3 か」に答えられないまま SSOT に入る。却下（ただし D3 の**候補 A** として残す）。
- **潜在状態を完全に廃し、連続 proxy のみとする**: 現時点の「正」は実質これ（stateless baseline）だが、
  **将来の状態モデルを構造的に排除しない**ために候補として残す枠を用意する。D3 は両者の中間ではなく、
  「正は stateless、状態モデルは昇格候補」という**明確な非対称**である。
- **`self_directed_recovery_risk` を既存 `stuck_likelihood` に統合する**: `stuck_likelihood` は
  凍結対象（`engine.rs` HMM 出力）であり、意味も違う（今詰まっているか vs 戻れるか）。
  additive な別フィールドにする。

## Consequences

- **`WorkStateEstimate` に additive 拡張が入る**（Epic 2/5）。既存 5 proxy・`uncertainty`・
  `evidence_quality` は不変。`emit_schema` の diff を意図的に確認する（Phase1 完了後）。
- **「GSE の潜在状態は何か」に現時点で答えを持たない文書になる**。外部説明では「4 状態です」より
  弱く聞こえうる。→ これは弱さでなく **採用ゲートを事前宣言した反証可能な設計**として提示する。
- ADR-001（HMM を Writing head の baseline へ降格）と整合する。HMM は候補 A の一実装であり、
  D4 のゲートに服する。**現行 HMM の内部挙動・`HMM_VERSION` は本 ADR では変えない**。
- ADR-007 は**維持**（Receptivity は Layer 5・分解形）。本 ADR はこれを再確認するだけで変更しない。
- ★ **`left_observation`（focus 喪失・アプリ切替）の内訳が同定できないため、軸は点推定でなく
  上下界として計算される場面がある**（D2 改訂）。幅が介入判断を反転させるなら新軸のラベルは成立しない。
  → 反証ゲート G2（`personalization-and-online-learning.md §8.2`）として事前宣言する。
- ★ **推定器が多項（3+1 カテゴリ）になる**（D2 改訂）。sigmoid → softmax の 1 段だけで、
  逐次更新は O(d·m), m=3 のまま。**軽量性（§4.5）・ONNX 不要の結論は変わらない**。
  ただし replay の pinning（ADR-008 D5）には **期の幅 Δ・baseline hazard の形・
  person-period 展開の順序**が追加で pin 対象になる。
- **コード変更ゼロ**。凍結対象に一切触れない。
