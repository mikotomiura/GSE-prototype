## Context

### 1. 研究者の発意（2026-08-19・⚠️ 要旨。逐語は `.steering/…/requirement.md`）

1. ⚠️ **打鍵だけで推論すると、タスクを変えても「また同じ形」になる。**
2. ★ 各タスクで **実際に主に行われている操作** を推論の素材にすべきではないか。
3. ★★★ **「何を入れるか」は dev の推測ではなく、そのタスクを普段行っているユーザーから
   データを抽出して *実測で* 決めるべきではないか。**

### 2. 打鍵中心のタスクですら、時間の大半は「打鍵していない」

`experiments/20260819-silence-presence-decomposition/notes.md §2.2`（実測・model-free）:

| 窓の種類 | n | ≥30 秒の沈黙が占める割合 |
|---|---:|---:|
| 全窓 | 617 | 0.574 |
| `≥100`（適格） | 382 | 0.408 |
| **`<100`（除外）** | 235 | ⚠️ **0.843** |
| うち **1–99 打鍵** | 112 | ★ **0.870**（最大） |

→ ★★★ **「打鍵が薄い窓を測る」とは「長い沈黙の中身を割る」ことに他ならない。**
⚠️ **その中身は依然として不明である**（同 `§3-1`）。
⚠️★★★ **論述ですらこうであり、動画編集・スライド・CAD では打鍵がさらに薄い。**

### 3. ⚠️ 現状「何を足すか」を決める手続きが repo に存在しない

**ADR-008 D1** は superset を **dev / 研究者が決める**と定めた。
⚠️ しかし **「何を根拠に決めるか」は空白**であり、実務上は **dev の推測**になっている。
★ 発意 3 はまさにこの空白を突いている。

⚠️ 併せて、前 handoff §1-B は逐語で
「**superset を決めずに『全部集めてから学習器に選ばせる』もやらない**」と禁じている。
→ ★ **「推測で決める」と「学習器に選ばせる」の両方を避ける第三の手続きが要る。**

### 4. ★ 総量の問いは、**既存の計器で、募集ゼロで、いま答えられる**

`src-tauri/src/input/liveness.rs:86-104` の `step()` は 3 分岐である（実測）:

```rust
if !session_active || hook_event_seen { return Starvation { starved_ms: 0 }; }  // 打鍵でリセット

Starvation { starved_ms: prev.starved_ms.saturating_add(tick_ms) }              // それ以外で加算
```

→ ★★★ **`starved_ms` は「打鍵が無い時間のうち、OS が入力（マウス含む）を見ていた累積時間」そのもの**であり、
`lib.rs:2951-2956` の復帰行が**エピソードのピーク**を搬送する。
★ これは転用ではなく、**設計者が明示的に用意した再解釈**である（ADR-011 D5・
`liveness.rs` のテスト `mouse_only_work_is_a_known_false_positive` 逐語
「だから NDJSON には `starved_ms` を載せ、**後から再解釈できる**ようにしてある」）。

### 5. ⚠️ 募集リソースは G1 の残り 2 名と正面から競合する

⚠️★★★ **2026-08-19 更新（G1 リブート）**: G1 は **確証標本 0/3 名**である

★ **Stage 0 の入力としては引き続き使える**（`hook_health` を持つ数少ないログである）。
⚠️ ただし **`--last-session-on-restart` が要る**（block07）。

## Decision

### D1. 判定量を **沈黙被覆率** に置く（★ 「何の平均か」を閉じる）

```
沈黙区間      := 打鍵イベントが 1 つも無い連続区間で、長さ ≥ 30 秒
                 ★ 閾値 30 秒は liveness.rs:64 の log_after_ms と揃える。
                 ⚠️ 揃える理由は既存トラックと同じ土俵で読むためであって、
                    30 秒に理論的な意味があるからではない。

被覆率(C)     := Σ(チャネル集合 C のイベントが覆った沈黙時間) / Σ(沈黙時間)
限界寄与(c)   := 被覆率(C) − 被覆率(C \ {c})
null 被覆率(c):= そのチャネル自身のイベント率から期待される被覆率（★ 併記必須）
```

⚠️ 「覆った」の定義（イベント時刻 `t` が `[t−w, t+w]` を覆う）の `w` は
**実データを見る前に事前登録で凍結する**。

⚠️★★★ **上の定義は「イベント型チャネル」（L-b / L-c）のものである。**
★ **L-a（`starved_ms`）はイベント列ではなくエピソードのピーク持続時間**なので、
**別の推定量を置く**（事前登録 **§2.1** の `被覆率_L-a`）。
⚠️★ **L-a は 30 秒で *左打ち切り* されるため下界であり、イベント型と同一土俵ではない。**

★ **なぜ被覆率か**:
- ★★★ **埋めるべき対象が数字で特定されている唯一の量**である（§Context-2 の 84.3%）。
- ★★★ **発意 1 の指摘を構造的に回避する** —— 「頻度」や「占有時間」を判定量にすると
  **最も頻度の高い操作＝打鍵が再び選ばれる**（＝「また同じ形」の再演）。
  ★ 被覆率は**分母から打鍵の時間を定義上除いている**ので、この退行が起きない。
- ★ **Stop 規則が書ける**（閾値未満なら次の層へ、または結論）。

### D2. ★★★ 手続きを 3 段に分け、**段 2 だけを実測に委ねる**

⚠️ これが **ADR-008 D1 の空白**（「どう決めるか」）に対する本 ADR の答えである。

| 段 | 誰が決めるか | ⚠️ 何を禁じるか |
|---|---|---|
| **1. 候補チャネルの列挙** | ★ **人（dev / 研究者）が、実データを見る前に凍結する** | ⚠️ 「あると便利そうだから全部」を禁じる。★ **ゼロから起こさず既存表から起こす** |
| **2. 候補の順位と採否** | ★ **実測（沈黙被覆率）が決める** | ⚠️★★★ **dev の推測が決めることを禁じる**（＝発意 3） |
| **3. 推論への配線** | ★ 人が決める（**G1 判定後**・ADR-011 D4） | ⚠️ 学習器に選ばせることを禁じる |

→ ★ **段 1 と段 3 を人が持つので ADR-008 D1 を守っている。**
⚠️ **段 2 で学習器は一切当てない**（記述統計のみ）。
→ ★ したがって前 handoff §1-B の禁止（「全部集めて学習器に選ばせる」）とも**整合する**。

### D3. content-free は **「観測は OS 汎用のみ・種別は宣言から・融合しない」** で保つ

```
  観測（OS 汎用イベント） ─→ 被覆率の計算              ★ アプリ識別子ゼロ
  宣言（ブロック単位）    ─→ 「どのタスクの被覆率か」    ★ ラベル付けのみ
  参照（画面録画）        ─→ 解釈と妥当性検査           ⚠️ 検証用サブサンプルのみ・コード化後に破棄
```

⚠️★★★ **3 つを融合して「真の操作種別」を作らない。**
★ 根拠は **ADR-010 D3** 逐語「**宣言は routing のみ、観測は `scope_fit` のみに使う。
融合して「真の task_kind」を作らない**」の写しである（★ **新しい原則を持ち込まない**）。

⚠️ **保存しないもの**（`data-privacy` / `personalization-and-online-learning.md §5.4` を 1 文字も緩めない）:
アプリ識別子 / ウィンドウタイトル / URL / full path / プロジェクト・リポジトリ名 /
入力文字内容 / clipboard 本文 / **`vk_code`・スキャンコード・修飾キー状態**（★ 本トラックには不要・D7）/
**スクリーンショット・録画の永続化**（★ **一時保管の条件は D12** を見る）。

### D4. 候補チャネルを **取得コストで層別**し、**前の層で足りたら次を集めない**

⚠️★★★ **ゼロから起こさない**。`domain-adapter-boundary.md §Adapter A/B/C` と
`personalization-and-online-learning.md §5.2 (a)` の既存列挙から起こす。

| 層 | チャネル | 取得手段 | ⚠️ content-free |
|---|---|---|---|
| **L-a** | **「何らかの入力があった」の 2 値** | ★ **既存**（`starved_ms`・追加実装ゼロ） | ★ 可 |
| **L-b** | ポインタ移動量 / ボタン押下 / ホイール | 新規フック（**別計測器**・D7） | ⚠️ **条件付き**（下記 L-b 仕様を満たすときのみ） |
| **L-c** | フォーカス遷移**回数** | 新規フック（別計測器） | ⚠️ **条件付き**（下記 L-c 仕様を満たすときのみ） |
| **L-d** | アプリ内の操作種別 | ⚠️ **プラグイン方式**（`§Adapter C` が警告） | ⚠️ 要設計・**本 ADR の次段** |

★★★ **層の順に測り、前の層で閾値を超えたら次の層に進まない。**
⚠️ 理由: ADR-008 D1 が禁じた「dev の推測で superset を決める」の裏返しとして、
**「実測で足りたのに、さらに集める」も禁じる**。

#### ⚠️★★★ L-b の仕様 — 「座標を捨て量だけ」では**不十分**である

★ **固定ビン（1 秒）ごとの集計行のみ**を出す。保持するのは
**量子化したスカラ総移動量 / ボタン押下回数 / ホイール回数**だけ。

| ⚠️ 保存しないもの | ⚠️ なぜ |
|---|---|
| **符号付き `dx` / `dy`（イベント単位）** | ★ **累積すれば軌跡が復元でき**、原点未知でも UI 配置・クリック位置を相対再構成できる ＝ **画面内容の代理** |
| 絶対座標 / クリック座標 | 同上 |
| 画面解像度 / マルチモニタ配置 | ★ 上記の復元を補助する |
| イベント単位の移動量＋時刻の列 | ⚠️★★★ **mouse dynamics として個人識別可能な生体特徴**になる |

★ **なお被覆率の計算（事前登録 §2）はイベント *時刻* しか使わない。**
→ ⚠️ **移動量は本来不要である。** ★ 取るなら「**取る理由**」を **D2 の段 1 の記録として残す**こと。

#### ⚠️★★★ L-c の仕様 — 「識別子を保存しない」だけでは実装者が踏む経路を塞げない

★ Windows の `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` は **HWND** を、
macOS の AX 通知は **要素参照**を渡してくる。→ ★ **具体的に塞ぐ**:

- ⚠️ **HWND / PID / bundle id / AXUIElement をメモリの外に出さない。**
- ⚠️ **`GetWindowTextW` / `QueryFullProcessImageName` / `NSRunningApplication` を呼ばない。**
- ⚠️★★★ **ウィンドウ通し番号・distinct ウィンドウ数も保存しない**（★ **擬似識別子になる**）。
- ★ **保存するのは「遷移が起きた時刻」のみ。**

### D5. ★★★ 実施を 2 段階にし、**1 段目を募集ゼロで回す**。閾値はそこから**導く**

```
  Stage 0 ── 募集ゼロ・既存計器・新規収集ゼロ ────────────────────────
    入力  : G1 コホートのログ（★ hook_health を含むことが機械確認済み）
    実装  : experiments/20260819-silence-presence-decomposition/ の抽出をそのまま使う
            (⚠️ 被覆率の集計層だけは新規。事前登録 §2.1)
    出す量: ★ 打鍵タスクにおける沈黙被覆率 C_write  ＝ ★★★ 比較の基線
    副産物: ADR-011 Migration 3b（未了）の消化
              ↓ ★ ここで閾値 θ が データから 決まる。人が選ばない
  Stage 1 ── 形成的コホート・専用計測器 ──────────────────────────────
    入力  : 非打鍵タスクを普段行う人 ＋ 同一人物の短い論述ブロック
    出す量: ★ チャネル別の被覆率と限界寄与 ＝ superset の順位
```

★ **θ の定義**: `θ := max( max_i C_write,i , θ_floor )`、`θ_floor = 0.20`（★ 事前登録で固定）。
→ ★★★ **「非打鍵タスクの被覆率が、打鍵タスクの最大値をも超える」ことを要求する。**
⚠️ **意図的に厳しい側に置いている** —— 甘い θ は「同じ形」を「違う」と読ませてしまう。

⚠️ **forking paths を踏まない理由**: Stage 0 は**別コホート・別モダリティ**であり、
**非打鍵データを 1 バイトも見ずに θ が決まる**。

⚠️★★★ **`θ_floor` が要る理由（★ 本 ADR の設計時に直接計数して判明した）**:

| 実測 | 出所 |
|---|---|
| **ローカルの NDJSON 76 ファイル（P000 13 + Phase1 63）すべてで `hook_health` が 0 行** | ★ 2026-08-19 に直接計数 |
| **G1 P010 は 10 ブロック中 9 ブロックで `hook_health` が 0 行** | `experiments/20260801-controlled-friction-task/notes.md:1808` 逐語「★ **他の 9 ブロックは `hook_health` 行が 1 件も出ていない**（＝ 30 秒の閾値にすら一度も届いていない）」 |

★ 意味論上、**沈黙のうち *入力を伴った累積時間* が 30 秒未満なら `hook_health` 行は出ない**（★ `step()` は入力ありの tick だけ加算し入力なしで凍結、`lib.rs:2924` は状態変化時のみ出力する）。⚠️★★★ **60 秒の沈黙中に 25 秒マウスを動かしていても 0 行になる。**
→ ⚠️ **`C_write ≈ 0` になりうる。**
⚠️★★★ **ただしその場合に「打鍵タスクの沈黙はほとんど入力皆無だった」と読んではならない** ——
★ **30 秒未満の入力エピソードが多数あっても同じく 0 になる**（＝ **左打ち切り**）。
→ ★★★ **`C_write` は真の被覆率の *下界* であって推定値ではない。**
⚠️★★★ **その場合 `θ = max(C_write)` だけでは主基準が空文になる。**
→ ★ 床を置く。⚠️ **`θ_floor = 0.20` は実データから導いた値ではなく恣意的である**が、
★ **恣意的であることを明示し、実データを見る前に宣言する**ことで forking paths を避ける。
⚠️ **後から動かさない。** ★ なお副基準（null 超過）が独立に効くので、低い θ による素通りは起きない。

⚠️ **Stage 0 の限界**: G1 は確証標本 **0/3 名**（2026-08-19 リブート・P010 はパイロット）で
**1 ブロック 5 分**。
★ ⚠️★★★ **リブートで 1 つ緩和された**: 新 G1 ログには **`starve_window` が載る**（ADR-013 D4）ので、
**左打ち切り（30 秒未満が 1 行も残らない）が緩む** —— `C_write` を下界だけでなく**幅で**出せる。
★ これは **ADR-013 実装 → リブート**の順にしたから得られた利得である（逆順なら失っていた）。
★ **`C_write` は点推定として扱わず全員値を併記する。**
⚠️ **§9 の下限を満たさなければ「Stage 0 では θ を出せなかった」と記録し `θ = θ_floor` を使う**
（★ **下限を緩めない**）。

⚠️★★★ **その分岐では本 D5 の中心的な主張は成立しない。**
★ `θ = θ_floor` は **dev が事前宣言した恣意値**であり、**データから導かれていない**。
→ ⚠️ **`design-comparison.md` が v1 を破棄した理由（θ が dev の推測のまま）と同じ構造に戻る。**
★ **結論に明記すること**（★ 隠す方が本 ADR の作法に反する）。

### D6. モダリティは **打鍵密度が薄い順に優先し、n を満たさなければ降りる**

★ **CAD → 動画編集 → スライド** の順に n を満たすまで降りる。⚠️ **降りたら降りたことを記録する。**

★ 理由: **T3 の問い（打鍵が無いところで測れるか）に最も厳しい側から当たる。**
⚠️ 「最初に集まったモダリティ」を採るとスライド（打鍵が残る）に寄り、**最も弱い答え**になりやすい。
⚠️ **一括で始めない**（`§Adapter C` 逐語「まず一アプリに限定した feasibility study」）。

### D7. 計測器は **GSE 本体ではなく専用の別計測器**にする

| 項目 | 決定 |
|---|---|
| 形態 | ★ **standalone**（GSE 本体と別プロセス・別バイナリ） |
| 出力 | ★ **Layer 2 `EventEnvelope` 互換**（`domain-adapter-boundary.md §Layer 2`）→ 後で本体へ **additive** に移植できる（ADR-005） |
| 品質要求 | ★ **使い捨ての測定器**。本番品質を要求しない |
| ⚠️ 禁止 | `src-tauri/` に触れない・`HMM_VERSION` を動かさない・ゴールデン / schema に触れない |
| ★ 必須 | **計測器自身が `capabilities` を刻む**（ADR-013 の規律を最初から満たす） |

⚠️★★★ **計測器の生データにも録画と同格の統制を課す（★ D12 は録画しか扱っていなかった）**:

★ この計測器は **被験者の実業務マシンで、実際の顧客作業中に、システム全体の入力フックを張る**。
⚠️ **G1（5 分・専用入力画面）とは危険度の階級が違う。**

| # | 制約 |
|---|---|
| 1 | ★ **ローカル保存のみ。自動送信しない**（`data-privacy` ルール 2） |
| 2 | ★ 保存先は**暗号化領域・repo 外**。⚠️ **クラウド同期配下に置かない** |
| 3 | ★ **削除要求経路と保管上限**を D12-b の台帳に載せる（★ 録画と同じ扱い） |
| 4 | ⚠️★★★ **被験者が開始 / 停止でき、宣言ブロック外では走らない**（★ **常駐させない**） |
| 5 | ★ **稼働中インジケータ**を出す |
| 6 | ⚠️★★★ **打鍵は時刻のみ。`vk_code` / スキャンコード / 修飾キー状態を持たない** |

★ **6 の根拠（データ最小化）**: 事前登録 §2 の沈黙定義は
「**打鍵イベントが 1 つも無い**」しか要求しない。→ ⚠️ **`vk_code` は本トラックに一切不要である。**
★ **`EventEnvelope 互換` を理由に本体の `vk_code` を引き継がないこと**
（⚠️ 互換にするのは *外枠* であって中身ではない）。

★ **理由**（⚠️★★★ **2026-08-19 に前提が変わった。下の「更新」を先に読むこと**）:
⚠️ **G1 は実施中**であり、実施中に記録仕様を変えると
`preregistration.md §3.6`（ブロックの事後除外の禁止）により**回復不能な損失**になる。
★ ADR-011 §Context-6 逐語「**G1 の残り 2 名は募集に依存し、期日が読めない。
★ G1 に依存しないまま観測空間の問いを前進させる経路が要る**」と同じ論法である。

### D8. 合格基準（★ 実データを見る前に事前登録で凍結する）

| 判定 | 条件 |
|---|---|
| **主基準** | 層 L の**合同**被覆率が **n 名全員**で `θ`（Stage 0 由来）を超える |
| **副基準（必須併記）** | ① **null 被覆率**、② **`C_write`（同一人物の論述ブロック）** の **2 基線** |
| **採否** | チャネル `c` を superset に入れるのは **限界寄与(c) ≥ δ** かつ **null 超過**のとき |
| **Stop-1** | 合同被覆率 < θ → ★ 次の層へ（L-a → L-b → L-c） |
| **Stop-2** | ⚠️ L-c まで進んでも θ 未満 → ★★★ **本トラックは Stop**。「**L-a〜L-c の観測空間では埋まらなかった**」を結論にする。⚠️★ **L-d（プラグイン方式）へ進むか、T3 を future work に戻すかは *別 ADR で裁く*** —— ★ 本 ADR では決めない（★ D4 の「L-d は次段」と揃える） |
| **⚠️ 逆向きの結論** | ★ **`C_nonkey ≈ C_write` なら「まさに *同じ形* である」と実測で書く。** ⚠️ **これは失敗ではなく、発意 1 への答えである** |
| **除外** | warm-up / block 境界をまたぐ窓 / 沈黙区間 <20 本の被験者 |

⚠️★★★ **2 基線を必須にする根拠**: [V83] 逐語
**`We cannot replicate models that significantly improve over the baseline of a majority classifier.`**
＋ `§8` の 2026-08-16 決定「**勝ち幅は 2 つの基線に対して報告する**」。
★ これが無いと、**[P117] の「base rate ≈0.5 に対し +0.07」を「有望」と読む誤り**が形を変えて再発する。

### D9. n と期間の下限 — **全員一致 ＋ 区間数の床**

**n≥3 名 × 各 ≥3 セッション × 各 ≥30 分、かつ沈黙区間 ≥20 本/人。**

★ 根拠は **既存先例と同型**であり、新しい原則を持ち込まない:
- 「全員」条件 = GATE3 の「C-index 中央値 ≥0.65 & **全員 >0.55**」（`§8`）
- 「≥20 件/人」= `§8` 逐語「**≥20件/人 は floor**: 単一事例最小 ~15–18点 [V28] と
  within-person 信頼性理想 ~70–100機会 [V27] の間に位置し、Stage-1 の方向検定の最低床として採る」

⚠️ **n=1,2 で「顕著」を判定しない** —— `cv-gate-null §5-6` と前トラックで
**P011 が `<100` 窓 1 個で実質的に情報を与えなかった**ことが実測されている。

### D10. `§8` 段別表の **T3 行「降格先」列のみ**を改める

- ★ **「現行 sensing 層では原理的に測定不能」（証拠の状態）は据え置く** —— 依然として真である
  （GSE 本体は打鍵しか取らない。⚠️ **別計測器は GSE 本体ではない**）。
- ★ **改めるのは「future work（sensing 再設計）」の一語**のみ →
  「**形成的トラックで *測定可能性* を調査中。利得の主張は引き続き行わない**」。
- ⚠️★★★ **T1/T2 行は 1 文字も変えない**（ADR-011 D2）。★ **別の段の話である。**
- ⚠️ **`§9` A-Q3 の解除条件は変更しない。確証核 L0 も不変。**

### D11. セッション構造に **同一人物内の論述ブロック**を入れる

```text
[warm-up] → [A: 非打鍵タスク] → [B: 短い論述] → [A': 非打鍵タスク]
  破棄       （普段の作業）        ★ 同一人物内の比較   （復帰の確認）
```

★ 根拠は `task-adaptation-and-scope-gating.md §2.2` の **C-2** 逐語
「**同一セッション内に両クラスを入れる**」／「**block 設計は、全員が定義上両クラスを持つことを
保証する。これは閾値調整では得られない、観測設計でしか得られない性質である**」。

⚠️ **B が無いと ADR-011 D7 を自ら踏む** —— 逐語「**「個人差か実タスク差か」は
Phase1 データでは原理的に切り分けられない**」。
★ 順序は被験者間で **counterbalance**。⚠️ **要因を掛け合わせない**（`§2.8` 逐語）ので**セッションあたり 1 本**。

### D12. 参照チャネル（画面録画）は **検証用サブサンプルのみ**・**コード化直後に破棄**

- ★ **被覆率の計算に録画は要らない**（量的指標である）。
  録画が要るのは「**被覆＝作業だったか**」の妥当性検査だけである
  （⚠️ [P121] の mid 帯「離脱 or 外部資源への相談」と同じ曖昧さが被覆にも残るため）。
#### D12-a ⚠️★★★ **撮影範囲を規定する**（★ これが無いと本 ADR は自プロジェクトの約束を破る）

⚠️★★★ **GSE は既に被験者に「記録しない」と約束している**
（`experiments/20260801-controlled-friction-task/consent.md:38-53` 逐語の「記録しない」欄）:
**「画面の内容・スクリーンショット」「音声・映像」「あなたが書いた文章そのもの」**。

→ ⚠️ **無制限の画面録画はこの姿勢を静かに反転させる。** ★ 次を仕様として固定する:

| # | 制約 |
|---|---|
| 1 | ★ **全画面ではなく、対象アプリの単一ウィンドウのみ**を撮る |
| 2 | ⚠️★★★ **論述ブロック（D11 の B）と資格情報入力中は撮らない**（★ 録画を実際に停止する）。**「書いた文章そのもの」を映像として記録しないため** |
| 3 | ★ **音声を録らない** |
| 4 | ★ 事前手順として **通知 OFF・無関係ウィンドウを閉じる**を必須にする |
| 5 | ⚠️★★★ **「この素材を録画してよい権限があるか（雇用主 / NDA / 第三者の顔・氏名）」を同意前に被験者に確認させる**。★ **被験者本人の同意では第三者・雇用主の権利をカバーできない**（⚠️ D6 の対象は CAD / 動画編集 ＝ **顧客図面・映像素材が写り込む**） |
| 6 | ★ **録画中インジケータと、被験者がいつでも押せる即時停止手段**を用意する |

#### D12-b ⚠️ 破棄規約（★ ADR-008 §Consequences 逐語「**永続化にはユーザー同意と削除 UI が要る**」と同格に扱う）

1. 保管は**研究者 PC の暗号化領域のみ**。⚠️ **repo にもデータ repo にも置かない**。
   ⚠️★★★ **クラウド同期フォルダ・OneDrive・VSS シャドウコピー・バックアップ配下に置かない。**
2. ⚠️★★★ **破棄の上限を数値で決める**: **コード化後 7 日以内**、かつ **各セッションの収録から 30 日以内**、
   **いずれか早い方**。★ 「収集終了から」ではない —— ⚠️ **コホート全体を待つと初回被験者の録画が最後まで生き残る。**
3. ★ **削除台帳**を残す（session / 収録日 / コード化日 / 削除日 / 実施者）。
   ⚠️ **台帳は repo にメタデータのみ**（★ 映像も被験者識別情報も載せない）。
4. ★ 削除は**暗号化ボリューム上で上書き削除**。⚠️ **ごみ箱経由にしない。**
5. ★ **閲覧可能者を実名で限定**する。
6. ⚠️★★★ **フレーム・録画を外部 LLM / クラウド文字起こし／外部サービスへ送らない。**
   （★ `docs/external-skills.md` は NDJSON の送信を禁じているが、**録画はどの規約にも載っていない**ので本 ADR で塞ぐ）
7. ⚠️ **コーディング規則を録画を見る前に凍結する**（★ 再コード化ができないため）。
   ★ **出力は閉じたコード集合のみ**とし、⚠️ **自由記述・スクリーンショット貼付を禁じる**
   （★ 自由記述に作品内容が転記されるため）。
8. ★ 被験者からの**削除要求経路**を同意文書に明記する。

#### D12-c ⚠️ 倫理審査の要否を**決定として記録する**

⚠️ G1 では倫理審査の枠を明示的に撤去した経緯がある
（`experiments/20260801-controlled-friction-task/notes.md:765-775`）。
★ しかし **Stage 1 は「外部専門職 × 実業務 × 画面録画 × 第三者素材」**であり、
**G1（5 分の統制課題・録画なし）とはリスクの階級が違う。**
→ ⚠️★★★ **同じ姿勢を無検討で引き継がない。**
★ **「審査に付す」か「付さない理由」を研究者が明示的に決め、募集開始のゲートに紐づける**
（⚠️ 本 ADR 時点では**未決**として起票する）。

## Alternatives

- **いきなり新コホートを募集して測る（初回案）**: ⚠️ 閾値 `θ` が **dev の推測**のまま残り、
  ★ **発意 3 が名指しで否定した構造**を合否の線引きに温存する。
  ⚠️ さらに募集が失敗すると**何も測れずに終わる**。→ D5 で却下。
- **判定量を頻度 / 占有時間シェアにする**: ⚠️ **最も頻度の高い操作＝打鍵が再び選ばれる**。
  ★ 発意 1「また同じ形になる」の再演である。却下。
- **アプリ識別子→カテゴリ写像を使う（[P117] と同じ方式）**: ⚠️ `data-privacy` の禁止事項であり、
  ★ **[P117] はその情報に支えられてなお base rate ≈0.5 に対し +0.07** である。却下。
- **プラグイン方式（L-d）から始める**: ⚠️ アプリごとの実装が要り、対象が 1 アプリに固定される。
  ★ **L-a〜L-c で足りないと実測で分かってから進む**（却下ではなく**順序**）。
- **モダリティを混ぜて n を稼ぐ**: ⚠️ `§Adapter C` 逐語「**一括で実装しない**」に正面から反する。却下。
- **G1 完了を待ってから募集を始める**: ⚠️ ADR-011 §Context-6 が回避した「待つと止まる」の再発。
  ★ **Stage 0 は募集ゼロなので待つ必要が無い。** 却下。
- **`§8` T3 行を全面改訂して「勝ち幅の測り方」に被覆率を入れる**: ⚠️ 「勝ち幅」は**利得の語彙**であり、
  ★ 冒頭で固定した切り分けを自ら破って **A-Q3 を誘発する**。却下（D10 で列を限定）。
- **新しい段 T3f を足す**: ⚠️ 段の数を増やすこと自体が先例になり、表が肥大する。却下。
