## Context

1. 段 1 のカード（`src/components/S1ProbeCard.tsx`・main 03cae459）は 1 枚に 3 問を並べ、最後に「回答する」を押して送る。Q1 摩擦・Q2 前進は初期値 3 のスライダーで、動かさずに送れるので、3 と未操作を区別できない。Q3 は 7 択のラジオと長い優先の規則の文（ADR-055 D2）を持つ。
2. 研究者は本人の段 1 で、答え方を負担の主因と見た（2026-11-25:「質問に対しての回答がしづらい形」「頻度のあるが回答の仕方の UI がストレス」「クリックして送信する感じなのがストレス」）。頻度は変えない。
3. 3 名はまだ始めていない（ADR-055 Context 5 と同じ）。ADR-043 D9 は人ごとの期間について言うので、始める前に答え方を変えることは D9 に触れない。本人の段 1（配布物 v0.1.42）は今の形で終える。
4. `realtime_label` は較正（v0.3）・自己マーカー・段 1 で共有の行種で、「answered なら q1/q2 は 1..=5」を書き手の不変条件にしていた（`logger.rs` の debug_assert・`bin/replay.rs` が破損として捨てる）。
5. 打鍵のフックの `InputEvent` は修飾キーの状態を持たない。修飾キー＋数字の押下も、数字の打鍵として `key` 行と段 1 の押下（調停器）に入りうる。回答の操作を除く仕組みは今は無い（事前登録の草案 S1-B3 の「確かめていない」の答え）。
6. `tauri-plugin-global-shortcut` は入っており、研究者用の 6 本（3 つの修飾キー＋文字）を O1 の形では登録しない（`lib.rs` の setup の注釈: 数週間キーの組を奪う・同意文書に無い行を書きうる）。

## Decision

### D1. 1 回の押下で答える。「回答する」を無くす（判断 0）

- Q3 は 7 つの大きなボタン。押した時点で答えとして受け取る。
- 問いの文は「直前の30秒、何をしていましたか?」だけにする。ADR-055 D2 の優先の規則の一文は、カードから外して初回の説明（同意文書 §3・アプリの同意の画面）へ移す。規則そのものは変えない。
- 選択肢の集合・並び・見出し・説明は ADR-055 のまま。自由記述を置かない・理由を問わない（ADR-031 D3 条件 ii〜iv）。
- 「思い出せない」「閉じる」は残す（記録の値も今のまま）。

### D2. Q1・Q2 は、Q3 で詰まり・熟考・作業を選んだときだけ続けて聞く（判断 0）

- 外部資料・会話・離席・回答不能では聞かない。規則は `logger::ActivityCategory::asks_scales` の 1 か所に置く。
- Q1・Q2 は初期値の無い 5 つのボタン（1〜5・両端の言葉は今のまま）。押した時点で次へ進む。
- 問いの文は今のまま。

### D3. 記録は行種を増やさず、段 1 の `realtime_label` で answered でも q を null にできる（判断 3・6）

- カードが閉じたときに、今と同じ 2 行（`realtime_label`・`activity_label`）を同じ時刻で書く。途中の答えは backend の駆動役（`s1_driver::ProbeCard.answer`）が持つ。
- Q3 を押していれば answered。`realtime_label` の q1・q2 は答えた分だけ入り、残りは null。閉じた経路（閉じる・思い出せない・層化のカードの差し替え・一時停止・終了）に関わらず、押した分を残す。Q3 の前に閉じたら今どおり skipped の 2 行。
- 同意の取り消しで閉じたときは、途中の答えも書かない（取り消しの後に `activity_label` を出さない）。
- 「聞かなかった」と「答えなかった」は、対の `activity_label.category` の `asks_scales` で分かる。
- 書き手を分ける: 段 1 は `LogEntry::realtime_label_s1_answered`。較正と自己マーカーの `realtime_label_answered` は今どおり q を必ず持つ。
- 読み手: `gse-replay` の較正の読み（`load_calibration_session`）は、q のそろわない answered を破損と扱わず `skipped_answered_without_scales` として数え、較正の点には入れない。既存の記録にこの形の行は無いので、既存の記録での較正の回答率・GATE の意味は変わらない。ただし段 1 の版の記録をこの較正の読みに通すと、q のそろわない answered が回答率の分母と分子の両方から抜けて回答率が低く出る。段 1 の記録は段 1 の再生（`s1_replay.rs`）で読み、較正の読みには通さない。段 1 の再生は answered と skip_reason を読む。途中まで答えた層化のカードは差し替えでも superseded ではなく answered で閉じるので、再生の差し替えの照合は「記録がその tick に answered で閉じたカード」を照合済みとして扱う（実装の後のレビューで見つけた穴。直す前は、その差し替えが tick の境目の分類に落ちていた）。
- ADR-005 との関係: 行の形（型）は変えない。変わるのは段 1 の版の行の値の取り方で、schema の description を直す。gse-dataset の schema の写しも合わせる。ADR-031 D4 が新しいフィールドを避けた理由（古い版と答えなかったが分けられない）は、ここでは当たらない。古い版は answered で q を必ず書くので、answered かつ q が null の行は新しい版にしか現れない。ただし版で分けるときは `meta.app_version` を使う（ADR-055 D5 と同じ注意）。

### D4. 回答の遅れは backend の時計で、カードを出した時刻から測る

- `activity_label.latency_ms` は Q3 を押すまで、`realtime_label.latency_ms` は最後の押下まで。閉じる・思い出せないも同じ起点。
- ボタンとキーで同じ起点にするため、画面の時計（描いた時刻）をやめる。描くまでの遅れ（通知の数十ミリ秒）が加わる。

### D5. 修飾キー＋数字で答えられる。カードを出してから長くて 2 分だけ登録する（判断 0・1・2・8）

- macOS は ⌥、Windows は Ctrl＋Alt（Ctrl＋数字はブラウザのタブや VSCode のエディタの移動でふだん使われ、表示中にそのつもりで押すと本人が選んでいない答えになるため・判断 8）。Q3 は 1〜7、Q1・Q2 は 1〜5、0 で閉じる。ボタンにキーを表示する。
- 登録と解除は、カードの状態を画面へ送る 1 か所（`run_s1_effects`）で、送る状態から「あるべき数字の組」を決めて差分を取る。カードの開閉の全経路がそこを通るので、経路を数え上げない。登録はメインスレッドへ非同期に頼む（プラグインの登録は呼んだスレッドで待つので、駆動役のロックを持つスレッドで待たない）。
- 1 つでも登録できなければ全部外し、キーの表示を消してボタンで答える（判断 1）。
- 押したまま離していないキーは、もう一度の押下として受けない（押しっぱなしの繰り返しで次の問いに同じ答えが入らないように）。押した側が見ていた問いと今の問いが違えば拒む。
- O1 の形で研究者用の 6 本を登録しない理由との関係: カードには表示の期限が無く、答えるか閉じるまで出たままなので、キーだけはカードを出してから 2 分で外す（カードとボタンは残り、キーの表示が消える・判断 8）。数週間キーを奪わない。ハンドラが書くのは同意文書にある 2 行だけで、新しい行を書かない。研究者用の 6 本は今どおり登録しない。同意文書 §3 に、キーを問いが出てから 2 分のあいだだけ使うことを書く。
- 画面（webview）に与えていた登録・解除の権限（`capabilities/default.json` の `global-shortcut:allow-register` / `allow-unregister`）は使われていなかったので外す（判断 6）。登録は backend だけが行う。

### D6. 回答の操作はフックで落とさず、カードの区間で除く（判断 5）

- 修飾キー＋数字は、数字の打鍵として `key` 行と段 1 の押下に残りうる。macOS では、答えの数字が `key` 行に numeric として残ることを実機で確かめた（2026-11-25。Windows は未確認）。クリックで答える今の形も、クリックとフォーカスの移りが同じように残る。
- 解析では、カードを出してから閉じるまでの区間の打鍵・クリック・フォーカスの移りを、停滞・C1・C2・再開の判定から除く（事前登録 S1-B3 に書く）。区間は `probe_assignment` と `realtime_label` の時刻と `latency_ms` から決まる。
- 生きている調停器（層化の候補の判定）では、答えの押下が最後の押下になる。限界として残す。
- キーはそのときの問いに当たる。層化のカードが無作為のカードに差し替わった瞬間にキーを押すと、まだ見ていない無作為のカードの Q3 に入りうる。また「思い出せない」「閉じる」のクリックは問いを照合しないので、同時にキーで Q3 が先に入ると、Q1 を聞かずに answered で閉じうる。どちらも稀なので、限界として残す。
- 画面のボタンが古い問いへの押下を送ってきたとき（キーが先に入った）は、その押下を捨てて受け付けた扱いにする（画面にエラーの文を出さない）。

## Alternatives

| 案 | 採らない理由 |
|---|---|
| 頻度を下げる | 研究者が負担の主因を答え方と見た。頻度は事前登録 S1-A1 の値で、別に決める |
| 押すたびに 1 行を書き、Q1・Q2 を新しい行種にする（/reimagine の v2） | 落ちても押した分が残るのはカードの表示中の数十秒の落ちに限られ、行種の追加が同意文書の表・削除保証・capabilities・gse-dataset に及ぶ。Q1・Q2 の解析が 2 行の突き合わせになる |
| キーの登録を画面の部品が JS で持つ（v2） | カードの真実と登録の真実が別の側に分かれる。npm の依存が増え、webview が任意の組を登録できる権限を使い始める |
| キーだけで答える | 登録に失敗したときに答える手段が無くなる（判断 1） |
| Windows も Alt | ホットキーの数字がアプリに届かず Alt の押下と離しだけが届き、離したときにメニューバーにフォーカスが移るおそれがある（判断 2） |
| フックで答えのキーを落とす | 両 OS のフックに手が入り、Windows の実機確認を待つ。クリックの答えは落とせないので、区間で除く規則は結局要る（判断 5） |
| Q1・Q2 をすべての選択肢で聞く | 外部資料・会話・離席の後に詰まりと前進を尋ねる意味が薄く、1 回の手間が増える |

## Consequences

### 良くなること

- 1 回の問いの手間が、聞かない選択肢では 1 押し、聞く選択肢でも 3 押しになる。ポインタを動かさずに答えられる。
- Q1・Q2 に初期値が無くなり、未操作の 3 と答えの 3 が混ざらない。

### 代償

- 外部資料・会話・離席・回答不能の後は Q1・Q2 が無い。事前登録の Q1 を使う詰まりの定義の候補（S1-A3）と、前進の測り方は、Q1・Q2 のある回答だけで決まる。
- 本人の段 1 の記録（3 問・スライダー）と 3 名の記録は、Q1・Q2 の取り方でも違う。並べるのは記述だけ（ADR-055 D4 に加わる差）。
- 答えのキーの数字が `key` 行に残る。区間で除く規則を解析が守る必要がある。
- カードを出してから 2 分のあいだ、作業中のアプリは ⌥＋数字（macOS）・Ctrl＋Alt＋数字（Windows）を受け取れない。ドイツ語やフランス語などの配列では Ctrl＋Alt が AltGr と同じに扱われ、そのあいだ AltGr＋数字の記号（`@`・`{` など）が打てず、押すと答えになる。確認の参加者が JIS 配列か US 配列かを配る前に確かめる（配る前の条件 14）。
- 期限は壁時計で測る。時刻が戻ったときは過ぎた扱いにしてキーを外す。macOS の単調時計はスリープ中に進まず、スリープの前に出したカードのキーが起きた後も残るので使わない。
- 画面は、問いが替わってから 400 ms は押下を受けない（ダブルクリックの 2 回目が次の問いの同じ位置のボタンに入らないように）。
- gse-dataset の schema の写しを合わせる PR が要る（description の変更）。
