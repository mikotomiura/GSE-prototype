### 2. ⚠️★★★ 本 ADR の起票中に、一次で **A3 が知らなかった依存**が見つかった

★ `verify-before-claiming` に従い、ADR-023 の記述を根拠にせず実装を読んだ結果:

```rust
// src-tauri/src/analysis/metrics.rs（改名前）
if let Some(rec_ts) = compute_recovered_at(ep.end_ms, feats,
        cfg.recovery_window_ms, DEFAULT_P_FLOW_THRESHOLD) {   // rec_ts = 最初に p_flow>0.5 になった時刻
    recovered_count += 1;
```

⚠️★★★ **ADR-023 D7 は「外部の事実はペーストの有無 1 点だけ」と書いたが、
その 1 点を評価する *区間* `[end_ms, rec_ts]` の長さ自体が `p_flow` の立ち上がり速度で決まる。**

→ ★★★ **`p_flow` が速く上がるほど窓が縮み、paste を拾う機会が減る。**
★ 分母は `episode_count` 固定なので、**① 回復判定を通る episode が増える ② 窓が縮む**の
**2 経路とも同じ向き（押し上げ）に効く**。

⚠️★★★ **これは誤読ではなく機械的バイアスである。**
→ ★ **A3-(iii)（現状維持 ＋ 併記義務）では防げない。**

> ★ **本 ADR はこのバイアスを *テストとして固定した***:
> `metrics.rs` の `pflow_exit_without_receipt_is_biased_by_window_length` は、
> **ペーストの挙動を完全に同一にしたまま `p_flow` の立ち上がりだけを速くすると
> 指標が 0.0 → 1.0 に反転する**ことを緑で示す。⚠️ **テストが緑であること自体がバイアスの存在証明である。**

## Decision

### D1. ★★★ **主要アウトカムを `receipt_free_resumption` とし、その「再開」を *時計の事実* で定義する**

★ **構造**:

| 位置 | 実体 | 由来 |
|---|---|---|
| **トリガー** | Stuck エピソード（`p_stuck >= 0.60`） | ⚠️ **推定器。ただし許容する**（→ 下記） |
| **イベント** | **離席候補ギャップ（≥180s）明けの初打鍵** | ★★★ **時計の事実** |
| **アウトカム** | 再開時刻を原点とした **receipt（external paste）の有無** | ★★★ **外部の事実** |
| **推定量** | **Aalen–Johansen の競合リスク CIF**（5 分 / 10 分） | ★ ADR-023 D6 が定めた形 |

★★★ **これは ADR-023 D6 が既に決めていた形の *実装* である。**
★ D6 は `receipt_free_resumption` を「トリガーから『受領なし再開』と『受領』の CIF」と書いたが、
⚠️ **「再開」を何で判定するかを書いていなかった。**→ ★ **本 ADR がそれを「打鍵の再開」に固定する。**

#### ★ なぜトリガーに `p_stuck` を残すのか

⚠️ **推定器をゼロにする案（(b)）もあった**（★ トリガーも「180s の打鍵途絶」にする）。★ 採らない理由:

1. ★ **`p_stuck` は「実運用で使う」と明言された量である**（★ 技術設計書逐語 ——
   「実運用で使うのは連続信号 `p_stuck` と、**それを消費する介入判断**である」）。
   ★ **ADR-023 D7 の判定表も `p_stuck` 由来の `paste_after_stuck_rate` を「問題なし」としている。**
2. ⚠️★★★ **相補性の問題は「トリガーが推定器であること」ではなく「トリガーと出口が同一事後分布の
   相補領域であること」だった**（ADR-023 D7 追記）。→ ★ **出口を外へ出せば構造は壊れる。**
3. ⚠️★★★ **(b) は stuck を狙う性質を失う** —— ★ 昼休み・会議・退勤も分母に入る。
4. ⚠️★★★ **(b) は処置後変数で条件付ける**（★ 本 ADR の新しい指摘）—— ★ Physical Anchor は
   **離席を誘う介入**なので、離席候補の発生自体が処置の結果である。
   → ★ 分母を「離席候補の個数」に置くと、H-Y の効果推定で**選択バイアス**になる。
   ⚠️ **(b′) でこの経路が *消える* とは書かない** —— ★ Nudge も打鍵動態を変えて `p_stuck` を動かす。
   ★ 言えるのは **浅くなる**までである。

#### ★★★ 副産物 —— **`HMM_VERSION` の bump が要らなくなった**

⚠️ A3-(i)（回復判定を `p_stuck` の低下へ置き換える）は **`HMM_VERSION` bump ＋ ゴールデン再生成**を伴い、
**既存 `metrics.json` との比較可能性が切れる**と ADR-023 が書いていた。
★ **(b′) は `FeatSnapshot` の計算に一切触れない**ので、そのどれも起きない。

★ **実測**（2026-09-07）: `gse-replay --snapshot tests/snapshots/minimal.json` が
**15 スナップショット一致・exit 0**。★ `emit_schema` も `schema/current.json` と **byte-equal**。

### D2. ⚠️★★★ **既存の二値率は削除せず、副次へ降格して `pflow_exit_without_receipt` と改名する**

⚠️★★★ **ADR-023 D6 の表は二値率に `stuck_exit_without_receipt` を割り当てていた。本 ADR はそこからずらす。**

★ **理由**: `stuck_exit_without_receipt` では **「出た」の判定が `p_flow` であることが名前から読み取れない。**
⚠️ **本 ADR の Context 2 が示したとおり、この指標には推定器依存が 2 経路ある。**
→ ★★★ **名前に依存を運ばせる**（★ D6 の命名原則 3 本 —— `self_` を落とす / `paste` でなく `receipt` /
`recovery` でなく `resumption` —— は**すべて満たしている**）。

★ **削除せず並置する理由**: ★ **新旧の差そのものが「推定器依存がどれだけ値を動かしていたか」の
直接証拠になる。**⚠️ 置換すると、この量は後から二度と測れない。

#### ★ 改名表（★ ADR-023 却下リスト #6 が「M2 で一括判断」とした件の決着）

★ **判定基準**: ① **報告面（論文・図表・被験者向け説明・`metrics.json`）に出るか**
（★ ADR-023 D6 の害の根拠は逐語「**指標名は論文・図表・被験者向け説明に出る**」）
② ⚠️ **実装者の誤読を招く位置にあるか**（★ D7 逐語「**次の実装者が『独立した 2 つの測定』と読む**」——
★ **今回の事故の起点はまさにそれだった**）。

| 旧 | 新 | 判定 |
|---|---|---|
| `self_recovery_without_paste` | **`pflow_exit_without_receipt`** | ★ ①（ADR-023 D6 が改名を決めた 1 件） |
| `productive_manual_recovery_rate` | **`pflow_exit_manual_gain_rate`** | ★ ① |
| `recovered_episode_count` | **`pflow_exit_episode_count`** | ★ ① |
| `compute_recovered_at` | **`compute_pflow_exit_at`** | ★ ②（★ 報告面には出ない） |
| `OutcomeConfig.recovery_window_ms` | **`pflow_exit_window_ms`** | ★ ② |
| `DEFAULT_RECOVERY_WINDOW_MS` | **`DEFAULT_PFLOW_EXIT_WINDOW_MS`** | ★ ②（⚠️ **15 分**。★ 上の 5 分と別値なので名前で区別できるようにした） |

⚠️★★★ **改名しないもの（★ 意図的に据え置く）**:

| 対象 | 理由 |
|---|---|
| `intervention_eval.rs` の `recovery_window_ms` フィールド（`InterventionMetrics` / `InterventionSweepReport` / `CorrectionFloorReport`） | ⚠️★★★ **3 つとも `Serialize` されており、改名すると `--intervention` / `--sweep` / `--corr-floor` の JSON キーが同時に変わる**。★ これは **defer / DC の面**であって本裁定の射程外 |
| `DEFAULT_DEFER_RECOVERY_WINDOW_MS` | ★ 同上（★ **defer からの回復**は別概念） |
| `experiments/**` の Python 側の複製定数 | ★ **凍結された記録**。遡って書き換えない |
| `docs/adr/ADR-0xx` 本文・`.steering/` の過去タスク | ⚠️ **書き換えない規約** |

> ⚠️★★★ **一次で確認した訂正**: ★ `compute_recovered_at` / `recovery_window_ms` が効くのは
> **DC（defer 正答率）だけ**である。★ `hir`（`intervention_eval.rs:435`）と `precision`（`:440`）は
> **`act_labeled` / `cm.tp` 由来**で、**この経路に一切関与しない**。
> ⚠️ **本タスクの design.md 初稿は「HIR / Precision」と書いていた。誤りだったので訂正した。**

### D3. ★ **「再開」は離席候補（≥180s）明けの初打鍵に限る。閾値の SSOT は 1 つにする**

★ `analysis/intervention.rs` の `AWAY_IDLE_MS`（180_000）を **`pub` にし**、
`OutcomeConfig::away_gap_ms` の既定値をそこから引く。
⚠️★★★ **180_000 を別の場所で再定義しない**（★ テスト `away_gap_default_matches_intervention_ssot` が固定）。

⚠️★★★ **系は「離席した」と判定しない**（**ADR-018 D1**）。
★ 離席候補は **事後の層別境界**であって系の出力ではない。★ UI にも `InterventionDecision` にも出さない。

★ **粒度を混ぜない**（ADR-023 D4 と同型の相殺を粒度方向で起こさないため）——
⚠️ ポーズ（≥2s）/ 沈黙区間は **第 1 弾では扱わない**（★ `arm1/notes.md` §9）。

### D4. ★ **時間原点は「再開時刻」、主イベントは「受領」、競合イベントは「次の離席候補ギャップの開始」**

⚠️ **ADR-023 D6 は「トリガーから CIF・5 分 / 10 分」としか書いていない。**★ 本 ADR が一意にする:

```
t0 = 離席候補ギャップ明けの初打鍵
  ├─ 主イベント  : receipt（external paste）が起きた
  ├─ 競合イベント: 受領を見ないまま次の離席候補ギャップが始まった
  │                 ⚠️ 「また離席した」ではない（系は離席を判定しない・ADR-018 D1）
  └─ 打ち切り    : どちらも起きないまま観測が終わった
```

★ **却下した置き方**:

| 案 | ⚠️ 却下理由 |
|---|---|
| 原点 = stuck エピソード終端、競合 = {再開} vs {受領}（★ D6 の逐語に最も忠実） | ⚠️★★★ **地平 5/10 分では大半が打ち切りになる** —— ★ 離席候補は定義上 ≥180s であり、実測 gap は**中央値 263.6s / p90 764.0s / 最大 2384.5s**。★ 5 分に収まるのは **180〜300s の帯だけ** |
| 原点 = 離席候補ギャップ開始 | ⚠️★★★ **競合リスクにならない** —— ★ ギャップ中は定義上打鍵が無く、**paste は `Ctrl+V` の打鍵を伴う**ので、ギャップ中に受領はほぼ立たない |

★ **同時刻のタイブレークは受領を優先する**（★ 保守側 —— `receipt_free_resumption` を高く出さない向き）。

### D5. ⚠️★★★ **「身体的」と名乗らない。名前は `resumption`（再開）のままにする**

★ 観測しているのは **「打鍵が 180s 途切れ、また打鍵が始まった」だけ**である。
⚠️★★★ **ADR-017 D10 が歩数 / 距離 / 速度 / 位置を GSE 本体から *恒久的に* 外した**ので、
★ **身体が動いたことは観測していない。**

★ **同じ観測形になるが身体的回帰ではないもの**: 席で紙を読んでいた / 電話・会議・来客 /
同じ PC で読んでいた・マウスだけ動かしていた / 別デバイスで検索していた（⚠️ **受領が立たない経路**）。

→ ⚠️★★★ **`physical_return` / 「身体的回帰」を指標名にしない**
（★ `docs/glossary.md` の禁止用語規約 ＋ ADR-017 D10 に当たる）。

### D6. ⚠️★★★ **報告時の併記義務を更新する（★ ADR-023 D7-2 は窓長依存を知らずに書かれている）**

★ `pflow_exit_without_receipt` / `pflow_exit_manual_gain_rate` を報告するときは、
**次の 3 点を必ず併記する**（★ ADR-023 D7-2 の 2 点に **3 点目を足す**）:

1. ★ 「抜けた」の判定に **3 クラス事後確率 `p_flow`** を用いていること。
2. ⚠️ **トリガー（`p_stuck >= 0.60`）と `p_flow` は独立した 2 つの測定ではなく、
   同じ 3 次元単体の相補的な領域である**こと（★ `p_flow > 0.5` は `p_stuck < 0.5` を必然的に含む）。
3. ⚠️★★★ **【新規】受領の有無を見る窓の右端そのものが `p_flow` の立ち上がり速度で決まること** ——
   ★ **速く上がるほど窓が縮み、指標が機械的に上がる**（→ Context 2）。

★★★ **対照として次の 2 つを必ず併報する**:
- **`manual_contribution_ratio`**（★ 推定に一切依存しない）
- **`receipt_free_resumption`**（★★★ **本 ADR が作った 2 つ目の「推定器の外」の指標**）

> ⚠️★★★ **ADR-023 D7 は逐語で「この構造の外にあるのは `manual_contribution_ratio` だけである」と書いた。
> ★ 本 ADR がそれを 2 つにした。**

### D7. ⚠️ **分子と分母の両方を明示する（★ B1 の知見を規約へ）**

★ ADR-023 **D8** は「分母を分けて報告する」と決めた。
⚠️★★★ **B1 の実測で、分母より分子のほうが 3 倍効くことが分かった**（★ −3.5pt ⇄ +11.2pt）。

→ ★ **報告時は分母（`stuck_episode_count` / `pflow_exit_episode_count` / その差分）に加えて、
分子が「成果を要求しているか」も書く。**

⚠️★★★ **`receipt_free_resumption` の分子は成果を要求しない** ——
★ 「戻ってきて画面を眺めていただけ」も同じ数字に入る。
→ ★ **これは D1 が受け入れた交換であって、隠してはならない**（→ §Consequences）。

### D8. ⚠️★★★ **推定量に 2 つのガードを課す（★ `code-reviewer` が見つけた外挿経路）**

⚠️★★★ **Aalen–Johansen は「追跡が地平に届いていない」ことを自分では教えない。**
★ 初版の実装には、**主要アウトカムを 1.0 側（＝ 受領なし側）へ押し上げる外挿経路が 2 本**あった。
→ ★ **どちらも塞ぎ、回帰テストで固定した。**

| # | 経路 | ⚠️ 何が起きるか | ★ 対処 |
|---|---|---|---|
| **1** | ★ **全事象が打ち切り**のとき、事象時刻の集合が空になりループが 1 度も回らず `CIF = 0.0` を返す | ⚠️★★★ **30 秒で観測が終わっただけ**なのに `receipt_free_at_5min = 1.0` ＝ 「5 分間 1 件も受領しなかった」と読める値が出る | ★ **「地平までに事象が 1 件も無く、かつ地平時点のリスク集合が空」なら `None`**。★ 併せて **`n_at_risk_at_5min` / `n_at_risk_at_10min` を出力**し、**読み手が外挿を棄却できるようにする** |
| **2** | ★ **再開した瞬間に次の離席候補ギャップへ入る**と、経過時間 0 の競合事象になる | ⚠️★★★ `t=0` の競合事象が**受領より先にリスク集合を食い潰し**、CIF が下がって `receipt_free` が 1.0 へ寄る ＝ **「戻ってきて 1 打鍵してまた消えた」が満点になる** | ★ **追跡時間ゼロの事象を CIF から除外**し、**`degenerate_count` として別に出す**（★ 受領は `t=0` でも情報を持つので除外しない） |

★ **回帰テスト**: `cif_receipt_none_when_followup_short_of_horizon` / `degenerate_resumption_excluded_from_cif`。

#### ★ 併せて **事象単位の観測結果を出力に載せる**

⚠️★★★ **セッション別 CIF の単純平均は Aalen–Johansen ではない。**
★ ところが `gse-replay` は **セッション 1 本しか取らない**ので、初版のままでは
**6 名 125 事象を束ねる本解析が成果物から実行できなかった。**

→ ★ `receipt_free_resumption.outcomes` に **(原点からの経過 ms, 分類)** を出す。
⚠️ **絶対時刻は出さない** —— ★ 絶対時刻を 3 本持つ `ResumptionEvent` は
**`Serialize` を意図的に derive しない**（★ `security-checker` の指摘。
**出せないことを型で担保する**）。★ 相対時間と分類だけなので `data-privacy` ルール 1 に抵触しない。

## Alternatives

### A1. ⚠️ **A3-(iii)（現状維持 ＋ 併記義務）**

⚠️★★★ **却下。**★ ADR-023 が暫定採用していた案。
→ ⚠️★★★ **本 ADR の Context 2（窓長依存）により成立しなくなった** ——
★ 併記は**誤読**を防ぐ装置であって、**機械的バイアス**は防げない。

### A2. ⚠️ **A3-(i)（回復判定を `p_stuck` の低下へ置き換える）**

⚠️ **却下。** 理由 3 つ:
1. ⚠️ **`HMM_VERSION` bump ＋ ゴールデン再生成**を伴い、既存 `metrics.json` との比較可能性が切れる。
2. ⚠️★★★ **相補性が残る** —— ★ ADR-023 A3 自身が逐語で
   「**相補性を実際に断てるのはこの案（(ii)）だけである**」と書いている。
3. ⚠️★★★ **窓長依存も残る** —— ★ `p_stuck` の低下時刻で窓を切っても、**やはり推定器が窓を決める**。

### A3. ★ **A3-(ii)（回復判定を打鍵側の観測だけで定義する）**

★ **却下ではない。**⚠️★★★ **本 ADR の D1 は (ii) の *具体化* である** ——
★ (ii) が書いていなかった「どの打鍵イベントを使うか」「窓をどう置くか」を、
**離席候補明けの初打鍵**と**固定原点からの経過時間**に固定した。

### A4. ⚠️ **(b)（トリガーも時計にして推定器をゼロにする）**

⚠️ **却下。**（→ D1 の 3・4）★ **推定器ゼロと引き換えに、狙いと識別可能性の両方を失う。**

### A5. ⚠️ **既存の二値率を新定義へ *置換* する**

⚠️ **却下。**★ 比較可能性が切れ、**「推定器依存がどれだけ値を動かしていたか」を測る機会を永久に失う**。
