# ADR-053: 文書の現行版と履歴を分ける —— 現行版は最新の ADR に合わせて書き直し、旧版は docs/history/ に逐語で残す

- **ステータス**: **Accepted**（2026-11-15。形は研究者が AskUserQuestion で選び、/cross-review 1 巡目の後、同日に研究者が Accepted にした）。コードの変更は無い。
- **日付**: 2026-11-15
- **決定者**: 研究者 ＋ Claude Code
- **関連**: ADR-047 Migration 1（research-positioning の本文は書き直さず、改訂ブロックと注で直す）／ADR-046 D1（3 状態の名前を新しい文書の地の文で使わない・既存の文書の直しは別タスク）
- **作業記録**: `.steering/20261115-gse-docs-clarity/`（判断 1〜6）
- 本 ADR は既存 ADR の本文を書き換えない。

---

## Context

1. `docs/research-positioning.md` は 1721 行になり、§1 に改訂ブロックが 3 層（2026-10-31・11-03・11-05）重なっていた。旧文には「〜で改めた」の注が付き、どの文が今の主張かを読むには、改訂ブロックと注の優先順を辿る必要があった。
2. ADR-047 Migration 1 が「本文の書き直しはしない」と決めたのは、確定した記述の履歴を損なわないためだった。その結果、履歴を保つ役と現行を示す役を 1 つのファイルが兼ね、どちらも読みにくくなった。
3. ADR-040〜052 で位置づけ・対象・推定の役・段の設計が組み替わり、agent-shared・glossary・functional-design・architecture などにも古い記述が残っている。
4. 研究者は 2026-11-15 に、research-positioning を現行版として書き直し、旧版を履歴へ移す形を選んだ。不要な docs は消すことも指示した（判断 6）。

## Decision

### D1. 現行の文書は、最新の ADR に合わせて書き直す

- `docs/` の研究・設計の主張を担う現行の文書（research-positioning・functional-design・architecture・agent-shared など）は、今の決定だけを書く。glossary は禁止用語の旧名や訂正の経緯を意図して残す表なので、この規則を一律には当てない（今の定義を先に書き、経緯は後ろに置く）。改訂ブロックや「〜で改めた」の注を重ねて直すことはやめる。
- 現行の文書と ADR が食い違うときは ADR を正とし、現行の文書を直す。
- 書き直すときは、各主張に根拠の ADR か実験のパスを付ける。ADR に無い決定を文書の書き直しで下さない。

### D2. 旧版は docs/history/ に逐語で残す

- 書き直す前の全文を `docs/history/<元の名>-<YYYY-MM-DD>.md` に逐語で写す。先頭に「履歴である・写しの元のコミット」の頭書きだけを足し、本文は変えない（`diff` で確かめる）。
- 履歴の文書は現行の根拠に使わない。直さない。
- 旧版を残す意味が無い文書（運用が終わった手順・同じ内容の翻訳など）は、履歴へ移さずに削除してよい。git の履歴に残る。

### D3. 旧パスの表を docs/history/README.md に置く

- 移した・削除した文書の旧パスから、移し先か削除のコミットを辿れる表を `docs/history/README.md` に置く。
- ADR の本文は書き換えないので、ADR に書かれた旧パスはこの表で辿る。ADR 以外の参照元（docs・CLAUDE.md・Skill とそのミラー（`.agents/`）・スクリプト・実験の手順とテンプレート）は新しいパスへ付け替える。
- 同じパスのまま中身を書き直した文書は、パスの grep では古い参照を拾えない。節番号の参照（「§n」）を grep し、手順書・テンプレート・Skill にある参照は付け替える。過去の記録（文献カード・実験の notes・ADR・コードのコメント）の節の参照は、現行の文書の §0 に「履歴の写しの節を指す」と書いて受ける。

### D4. ADR-047 Migration 1 を改める

- ADR-047 Migration 1 の「本文の書き直しはしない」は、本 ADR で改める。research-positioning は 2026-11-15 に D1・D2 の形で書き直した。
- ADR-047 の決定（D1〜D6）は変えない。

## 上書き・読み替えの範囲

|---|---|---|
| ADR-047 | D1〜D6・Migration 2〜4 | Migration 1 の「本文の書き直しはしない」（D4） |
| ADR-046 | すべて | なし（D1 の「既存の文書の直しは別タスク」を、本 ADR の書き直しで受ける） |

## Alternatives

- 冒頭に要約を 1 枚足すだけ（小さいが、上書きの鎖が残る）。
- 改訂ブロックを本文へ溶かし込み、履歴は git にだけ残す（1 ファイルのままだが、差分が大きく、経緯を読むのに git が要る）。
- 判断を作業記録にだけ残し、ADR を起こさない（ADR-047 を読んだ人が古い決定を掴む）。

## Consequences

- 現行の文書を読めば今の主張が分かる。経緯は docs/history/ と ADR で辿る。
- 書き直しのたびに、旧版の写しと旧パスの表の更新が要る。
- ADR に書かれた旧パスはリンクとしては切れるが、表で辿れる。

## Migration

2. agent-shared・glossary・architecture/gse-design-map・未踏の不採択コメントの対応表・不要な docs の削除と移動（PR2）。
3. functional-design・architecture（PR3）。
