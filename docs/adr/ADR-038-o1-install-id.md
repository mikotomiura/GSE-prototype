# ADR-038: O1 の `meta` に導入ごとの乱数識別子 `o1_install_id` を刻む

- **ステータス**: **Proposed**（★ 方針は 2026-10-07 に研究者が決めた。ADR としての承認は研究者）
- **日付**: **2026-10-07**
- **決定者**: 研究者 ＋ Claude Code
- **関連**: **ADR-013 D1 / D6**（`meta` へ刻むもの・入れないもの）/ **ADR-014**（O1・D4b / D9）/
  **ADR-016 4b-3**（陳腐化した宣言は限界として明記）/ **ADR-005**（additive versioning）/
  **ADR-034 D3**（G1 の配布物は v0.1.36 固定）
  ⚠️★★★ **本 ADR は既存 ADR の本文を 1 文字も書き換えない。**
- **作業記録**: `.steering/20261007-o1-install-id/`
- ★ **外部の理論・文献には依拠しない**（根拠はすべて repo 内の決定と実装）。
  ★ `citation-ssot` の対象だが、引くべき外部文献が無いので `[Pn]` は付けない。

## Context

O1 は自然な作業を数週間にわたって常時記録する。1 人の参加者が **複数の端末で O1 を走らせる**ことを
研究者は許す（2026-10-07）。このとき参加者 ID は人単位なので、**NDJSON から端末が分からない**。

⚠️ 端末 A を離れて端末 B で作業すると、A のログには「入力が止まった」区間が残り、離脱に見える。
G2（介入判断の割れ方）はこの区間を入力に使うので、**端末を分けないと入力が汚れる**。

## Decision

### D1. ★ O1 の `meta`（session_start）行に `o1_install_id` を足す

- 値: **16 桁の小文字 hex（8 バイトの乱数）**。`~/.gse/o1_install_id` に 1 度だけ作り、以後は読む。
- 位置: `o1_mode` の直後。**O1 のときだけ**出す。通常運用 / G1 の `meta` は 1 バイトも変わらない。
- ⚠️ 値が妥当でなければ（桁・文字違い）**刻まない**。書けなければ識別子なしで記録は続く。
- schema は additive（`Option<String>`・`required` に入れない。ADR-005）。旧ログは通る。

### D2. ★ ADR-013 D6 に抵触しない根拠

D6 の該当行は `app_version` にマシン GUID・ビルドホスト名などを入れることを「フィンガープリントになる」として禁じる（⚠️ `meta` 全般の禁止ではない）。本 ADR は**その趣旨**（外部から再識別できる値を作らない）に照らして裁く。
本 ADR の値は **ハードウェア・MAC・ホスト名・ユーザー名・OS の機械 ID のいずれにも由来しない乱数**で、
`~/.gse` を消せば別の値になる。端末や個人を**指さない**（導入を指す）。
⚠️ 同じ導入の識別子は複数セッションに現れるので、参加者 ID とは別の**長期の相関子**にはなる（D3 の限界表）。

### D3. ⚠️ 限界（★ 導入単位であって端末ではない）

| 状況 | 結果 |
|---|---|
| `~/.gse` をコピーした別端末 | **同じ値**になる（端末を分けられない） |
| 同じ端末で OS ユーザーが違う | **別の値**になる |
| 再導入・`~/.gse` 削除 | **別の値**になる（1 台が 2 導入に見える） |
| v0.1.39 以前の O1 ログ | **識別子が無い**（端末を分けられない） |

| 破損ファイルがある状態で 2 プロセスが同時に起動 | ごくまれに**値が割れる**（導入が 2 つに見えるだけ。読み取りエラーのときは既存ファイルに触らず識別子なしで続ける） |
| `hard_link` 非対応のファイルシステム | 直接 `create_new` で書くフォールバックに落ちる（書けなければ識別子なし） |

→ 解析は「識別子が無い `meta` がある」ことを**検査で拾い**、黙って 1 端末とみなさない
（事前登録の §4・§12 に反映する）。

### D4. ★ 参加者 ID は人単位のまま

削除台帳（`docs/o1-deletion-ledger.md`）は P-ID 単位である。削除要求は **P-ID 単位で全端末ぶん**として扱う。
端末ごとの削除経路は作らない。

### D5. ★ 提出ファイルは実質衝突しない（⚠️ 確率の議論であり、構造的な保証ではない）

`.age` の名前は `<participant>_o1day<NN>_<stem>.age`（`submission.rs` `o1_age_file_name`）で、`stem` はセッション
NDJSON 名（開始時刻・**秒粒度**）である。日番号は端末ごとのディスクの最大値＋1 なので**端末間で同番号になりうる**が、
`stem` が違うので名前は実質衝突しない（2 端末が同じ秒に同名で開始する確率はほぼゼロ。⚠️ ゼロではない）。
`reconcile.rs` は既存の提出物があれば**上書きせずエラーにする**ので、万一衝突しても黙って失われない。
⚠️ **未確認**: 台帳（`read_manifest_days`）は端末ごとのディスク上で閉じるため端末間では混ざらないが、
研究者側の受領後の突き合わせで (participant, day) をキーにしていないかは別途確認が要る。

## Alternatives

- **OS のマシン ID / ホスト名を使う**: ⚠️ D2 が禁じるフィンガープリント。却下。
- **端末ごとに別の参加者 ID を発行する**: 人単位の解析・削除台帳が壊れる。却下。
- **識別子なしで運用し、複数端末を禁じる**: 研究者が複数端末を許す方針。却下。

## Consequences

- 新タグ **v0.1.40** から O1 を開始する（v0.1.39 では開始しない）。`--mode o1` の配布タグは
  `docs/o1-distribution-tag.md` の最新節に従う。
- ⚠️ **配布前の必須ゲート**: 同意文書の「記録するもの」に**乱数の識別子**を足す改訂が要る（被験者向け文書は契約。
  反映は研究者・案は `.steering/20261007-o1-install-id/consent-revision-proposal.md`）。同意が先行しない順序で配る。
- schema は `^[0-9a-f]{16}$` の pattern を持つ（提出後に編集された値を検証で拾う）。
- gse-dataset 側の `schema/current.json` の同期が要る（additive）。
- ADR-016 4b-3（陳腐化したタスクラベル）は**限界のまま**。計器は変えない。
