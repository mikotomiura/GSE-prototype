#### ⚠️★★★ [P77] の境界条件を隠さない（★ 実験 4）—— **本 ADR の唯一の決め手に対する最大の反証である**

★ **実験 4 は「活動を *仕事(work)* として枠付けると負の効果が減衰する」ことを示した。**
⚠️★★★ **かつ操作は「ページ番号の表示有無のみ」** ＝ ★ **本 ADR の当の論点（数値の表示）そのものである。**
★ **N=310・2（計測）× 3（枠付け）被験者間・読書 8 分。**enjoyment 交互作用 **`F(2,304)=4.83, p=.009`**:

| 枠付け | 無計測 → 計測 | 効果 |
|---|---|---|
| control | 5.97 → 5.19 | **`F=8.89, p=.003`・`d ≈ −0.55`** |
| ⚠️★★★ **fun** | 5.70 → 4.98 | **`F=5.33, p=.022`・`d ≈ −0.48`**（★ **害が残る**） |
| work | 5.18 → 5.57 | `F=1.59, p=.208`・`d ≈ +0.26`（★ 方向反転） |

⚠️★★★ **「打鍵は work だから測ってよい」に飛びつかない理由が 3 つある**:

1. ⚠️★★★ **減衰は「害が消えた」のではなく「先に失われていた」** —— ★ 著者逐語
   *"**framing reading as work to begin with reduced enjoyment at baseline** … `t(159) = -3.06, p = .003`"*
   ＝ ★ **work 枠付けは *無計測時の楽しさそのもの* を `d ≈ 0.60` 下げている。**
2. ⚠️★★★ **GSE の目標状態 Flow は work 枠から外れる** —— ★ **fun セルの `d ≈ −0.48` が GSE に当たる帯である。**
3. ⚠️ **枠付けが守るのは enjoyment だけ** —— ★ subjective well-being の交互作用は **`F(2,304)=2.27, p=.105`** で非有意。

★ **かつ本 ADR に直接効く実数がもう 1 つある** —— ⚠️★★★ **output は枠付けに関係なく増える**
（**`F(1,304)=32.02, p<.001`**・**16.14 頁 vs 13.44 頁**）。
→ ★★★ **数値を添えることは、枠付けが何であれ「量を増やす向きの圧力」を常に掛ける。**
⚠️ **GSE で増える量は打鍵である。**★ **ADR-023 D3-d が言う「行動が動く」は、この圧力のことである。**

| 離席からの経過時間・残り時間 | ⚠️★★★ **ADR-018 D2 が禁じたタイマーそのもの**（★ ADR-021 D4 逐語「残り時間を載せない」） | ✗ |
| 離席回数・招待回数・連続日数 | ⚠️ **ADR-018 D3 の禁止語に接近**。★ **カウンタは達成度として読まれる** | ✗ |

## Decision

### D1. ★★★ **規則を 1 本立てる —— GSE は本人に *自分の量* を返さない**

> ★★★ **本人が読む面に、本人の状態を *量* として読める表示を置かない。**
> ★ 量とは **数値 / 順位 / 達成度 / 連続日数 / 経過時間 / 残り時間 / 累計**、
> および ⚠️ **`level` の 3 値を数字で書いたもの** を含む。
>
> ⚠️★★★ **`Accepted` の射程は *層 A* のみである**（→ **D2**）。
> ★ **層 B / PC 側 UI / 通知 / オンボーディング / 被験者への結果返却への適用は未決**であり、
> ★ **`expression-channel.md` §8 の `E-11`** で扱う。
> ⚠️ **本ブロックだけを読んで層 B や PC 側 UI を「確定禁止」と読まないこと。**
> ★ **研究者が読む解析出力（`metrics.json` / `gse-replay`）は「本人に返す」ではないので規則の外**である。

★ **Context 3 の 6 本は、本規則の *系* として位置づける。**
⚠️★★★ **本規則は新しい禁止ではない。**★ **既に散在していた 6 本に、共通の根拠と照合先を与える。**

### D2. ★★★ **`Accepted` の射程は *層 A* に限る**

⚠️★★★ **D1 の規則は GSE 全体を射程にしうるが、本 ADR が `Accepted` にするのは層 A だけである。**

★ **理由**:

1. ★ **層 B は「任意閲覧・数十秒」で曝露の性質が層 A と違う**（ADR-017 D6）ため、
   **同じ規則が同じ強さで当たるとは限らない。**
   ⚠️★★★ **ただし「任意だから安全」も言えない** —— ★ **[P77] は opt-in でも害が残ると実験 2 で示している。**
2. ★ **オンボーディング・被験者への結果返却は、本人が読む面でありながら *表現層ではない*。**
   ★ 別の設計要件（教示の必要性・研究倫理上の結果返却）が同時に当たる。

→ ★ **層 B / オンボーディング / 結果返却への適用は `expression-channel.md` §8 の `E-11` として立てる**
（→ **§Migration M3**）。

### D3. ★★★ **したがって層 A に数値を添えない**

★ **D1（規則）＋ Context 4（添えうる量は 0 個）の帰結である。**

⚠️★★★ **「添えない」は美学的選好ではない。**
★ かつ ⚠️★★★ **「抽象表現の方が読みやすいから」でもない**（★ 逆である → **D4**）。

### D4. ⚠️★★★ **却下する論拠と、却下しない論拠を分けて書く**

★ **「添える」側の論拠は弱くない。**★ 5 本あり、**うち 2 本は却下できない。**

| **5** | ★ **読み取り時間は律速でないので、数字は 2 秒予算に収まる** | **[P245]** | ★★★ **却下しない。**⚠️★★★ **ただし論拠の側を訂正する**（★ `code-reviewer` 指摘・2026-09-07・一次で検算）—— ★ `references.md` の [P245] は **24 値で `Bar 360 / Donut 162 / Radial 3593 ms`** であり、⚠️★★★ **初稿の「162–443 ms」は SSOT に存在しない**（★ `expression-channel.md` §3.5.2 **A-2** からの伝播）。★ かつ ⚠️★★★ **[P245] が測ったのは「2 本の棒の大小比較」であって *数字の読み取り* ではない**（★ 同カードが逐語で留保）。→ ★★★ **「2 秒に入る」も「入らない」も未検証である。**⚠️★★★ **したがって *どちらの向きにも* 時間予算を論拠に使わないと宣言する** |

### D5. ⚠️★★★ **本 ADR は「自己定量化を防ぐ」とは書かない**

★ **[P243]** —— ⚠️ **technology probe の *観察* である**（**N=17**・2 日・**統計なし**。★ 著者自身が *"not meant as a definitive explanation"* と書いている）。
★ 逐語で言えるのは *"some participants seemed to invest a **potentially harmful degree of authority** in the data display."* まで。
⚠️★★★ **「数値を出さなくても参加者は順序尺度を自作し、自他比較を始めた」は本 repo の解釈である**（★ `expression-channel.md` §4.2）。

→ ★★★ **D1 で防げるのは「*系が* 量を権威づけること」までであり、
本人が量を作ることは防げない。**

⚠️ **したがって「GSE は自己定量化を回避する設計である」とは書かない**（→ **却下リスト #15**）。

### D6. ★ **(b)（期間中の関与の計器）は閉じない。ただし (a) との *向き* を記録する**

⚠️★★★ **(a) と (b) は独立でない。**

★ **[P77] の逐語 "decrease continued engagement" は、(b) が測ろうとしている当の量である**
（★ (b) の出所 **[P315]** は **N=12・52 週で対話・関与行動が週 2.2% 減 → 52 週で約 9 割減**）。

→ ★★★ **数値を添えることは、(b) のリスクを *こちらから増やす* 操作である。**
★ **ADR-023 M9 は 2 件を並べて立てたが、向きが繋がっている。**

⚠️★★★ **計器は依然として存在しない。**★ 本 ADR が確認した障害:

| 経路 | ★ 現状 | ⚠️ なぜ今は計器にならないか |
|---|---|---|
| ★ Android ライブ壁紙の可視性（`onVisibilityChanged`） | ⚠️ **未決** | ★ **`expression-channel.md` §8 の `M-7`** —— ⚠️ **AOD 中に何を返すか実機で分かっていない** |
| ★ iOS ロック画面ウィジェットの表示回数 | ⚠️★★★ **未確認** | ⚠️★★★ **2026-09-07 訂正**（★ `code-reviewer` 指摘・一次で検算）—— ★ 初稿は「**取得する API が無い**（ADR-022 D4 / §3.5.1b）」と書いたが、⚠️★★★ **ADR-022 に `表示回数` / `impression` / `閲覧回数` は 1 件も無い**（★ grep 実測 0 件）。→ ★ **これは根拠のない断定だった。**★ 正しくは **「WidgetKit に該当 API があるかを一次で確認していない」**。→ ★ **確認は `E-10` の作業に含める。** |
| ★ PC 側で観測できる代理（招待の受諾） | ★ **観測可能** | ★ **ADR-017 D3 の inbound を作らずに済む**。⚠️ **しかしそれは「関与」ではなく「行動」であり、[P315] が測った量ではない** |

### D7. ★ **§7.1 の位置づけを「合否」から「*事前の* 操作チェック」へ改める**（★ ADR-023 M9 の前半）

★ **ADR-023 D3 が確定した 3 本をそのまま効かせる**:

1. ★ **可読性を除外基準に使わない**（**[V138]**: MC で被験者を落とすと識別が壊れる）
2. ★ **IV を使うなら事前登録する**（**[V139]**）
3. ⚠️★★★ **可読性チェックを本試験の途中に *反応的に* 挟まない**（**[V140]**）

⚠️★★★ **「事前に通れば十分」とは読まない** —— ★ **事前チェックが保証するのは
「符号が原理的に読めること」までであり、「期間を通じて読まれ続けたこと」ではない**（★ ADR-023 D3-c）。
★ その差を埋める計器は **未決**（→ **`expression-channel.md` §8 の `E-10`** / 本 ADR **D6**）。

★ **本決定は「新しい降格」ではなく「既決の明文化」である** —— ⚠️ **ADR-021 D8 は既に逐語で
「ISO 9186 準拠で 66%（67%）を超えたので合格」とは書かない** と決めており
（★ **その合格スコアは ISO 9186-1 本文に存在しない**・**[V112]**）、
★ **試視ハーネスにもその否認が実装されている**（★ `selftest.py` の検査 1 本が緑で守っている）。

### A1. ⚠️ **未決のまま §8 へ送る（★ M9 の字面どおり）**
