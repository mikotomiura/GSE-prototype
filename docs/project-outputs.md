# GSE の成果物と貢献の一覧

作成: 2026-11-15。状態は各記録の日付の時点で、投稿先の画面では確かめ直していない。使う前に測り直すこと。
この文書は内部用。投稿先と状態は公開物（スライド・公開 repo の README）に書かない。

## 全体の形

GSE の成果物は 5 つの柱に分かれる。

1. 観測: 本文を記録せずに打鍵と日本語 IME の変換を観る
2. 推定と定義の検査: 打鍵から作業の状態について主張できるか
3. 公開と保護: 打鍵の記録を、中身が漏れない形で出せるか
4. GSE 本体と介入: 記録の道具・段 1・手跡
5. 束ねるもの: 3 つの検査（予測・定義・漏れ）を当てる道具と、設計の記録

AI 疲労の系統（AF-*・TRACE）は同じリポジトリにあるが、GSE の目標とは別の研究として扱い、ここには数えない。

## 貢献として言えるもの

1. 文字を残さない日本語 IME の観測の方法と、その評価一式・データ（公開済み）。
2. 打鍵から作業の状態について主張する前の検査の手順。予測・定義・漏れを同じ観測の上で確かめる。論文 1・論文 2・IME 論文 2 が、それぞれの検査を回した記録になっている。
3. 公開データでの否定的な結果。手で置いた推定器は止まりの手前を見分けず、定義を変えると結論の向きが動いた。過大な主張を止める材料になる。
4. 打鍵の公開の形を、元の文章との照合で評価する方法。行動の生体データの匿名化のサーヴェイ（Hanisch ら、ACM Computing Surveys 2025）は、匿名化の評価が大まかなことが多いと述べ、打鍵の手法を文章との照合で評価したものを挙げていない。
5. 少人数で進める設計。固定の床と昇格の門を置き、1 人ごとに学んだ段は門を通ったときだけ使う（ADR-044・046・019）。

## 実施できる見込みと根拠

見込みは Claude の見立てで、高・中・低の 3 段。「できるか」は作業として仕上がるかを指し、論文の採否や結果の向きは含めない。結果の向きが分からないものは、その旨を別に書く。

| もの | 見込み | 根拠（すでにあるもの） | 下げうる要因 |
|---|---|---|---|
| IME 論文 2 の投稿 | 高 | 本文 12 頁の原稿と判断 92 件まで。主表の計算は済み、残りは探索分析 6・7 だけ（G-GEAR で 11-18〜19 ごろの見込み） | G-GEAR の計算の遅れ。締切 11-30 までの余裕は約 10 日 |
| 論文 3 の投稿 | 中 | 主張・根拠・配置の outline（11-11 改訂）と組んだ PDF がある。残りの計算は 1 つで、HP Z2 で回せる | 残りの計算（共通モデルから作る帰無）の結果しだいで、主張を弱める必要が出うる |
| 3 つの検査の公開の道具 | 高（作ること） | 3 つの検査それぞれのコードが公開済みか実験記録にある: 予測は論文 1 のコード、定義は論文 2 のコード、漏れは照合の攻撃の試作（`experiments/20261009-matching-attack-prototype`）と IME 論文 2 のコード。残りは束ねることと、地図の出力 | 公開データの間で記録の形が違うので、入力をそろえる層が要る。GSE 自身の記録への適用は本人の記録の扱い（公開しない）と切り分ける必要がある |
| GSE 本体の公開 | 高（作業として） | 両 OS で動くアプリ・CLI・回帰の仕組みが main にあり、CI も両 OS で回る | ライセンスの選択、本人の記録や内部の記録（.steering）を外す切り分け。公開 repo に入れないものの規則がある |
| 段 1（本人の約 1 週間） | 高 | ADR-043・052 が Accepted。手跡の状態・門・割付・再生は main にあり、O1 で長い記録を運用した実績がある | 手跡の帯の PR と段 1 のリリースタグが残り |
| 段 1（本人以外の n=3） | 中 | 手順（事前登録の凍結 → 確認）は ADR-052 で決まり、同意文書は O1 の型を使い回せる | 事前登録の値が空欄。同意文書・Windows 版の手跡が要る。3 名の集まり具合。審査を開始前に求める投稿先には使えない |
| 推定器が昇格の門を通る | 低〜不明（結果の向きが分からない） | 門の手順（床と比べる・時間順の holdout）は決まっている | 公開データでは学習器も 0.54〜0.57 にとどまった。止まりの手前の信号が本質的に弱い可能性。3 名では言える範囲が狭い。門を通らなくても、「読めない所」として地図に載るので研究としては成り立つ |
| 集計値の公開（関門の段 0） | 中〜高 | ADR-039 D6 で、段 0 は規則で判定する案（何を出さない・どう丸めるかを値の前に決める）が推奨されている | 規則の決定が未了（本番の関門の設計で決める）。少人数のセルや表の差の点検が要る |
| 関門を通る記録の加工の形 | 低（研究として未解決） | 評価の方法と攻撃は IME 論文 2 でそろっている | 11 通りの加工と区間ごとの差分プライバシーのどれも両立しなかった。内容が打ち方の構造そのものに入っている（語の長さの並びだけで 1 語あたり約 3.1 ビット）。記録を出さずに量だけを書き手単位の保証で出す道、問い合わせにだけ答える道は未評価 |
| 人の日本語 IME 打鍵データセット | 低（近いうちは） | 同意の段階（D4）・関門（D6）・個人情報保護法の扱い（D7）は設計済み | 審査を受けられる共同研究者がまだいない。記録を出すには上の加工の形も要る。採択後に PM の大学で審査を通す道を模索中 |

まとめると、作業として仕上げられるもの（IME 論文 2・3 つの検査の道具・本体の公開・本人の段 1）は見込みが高い。結果の向きが分からないもの（推定器が門を通るか）と、研究として未解決のもの（記録の保護の形）は見込みが低いか不明である。ただし、どちらも否定の結果が出ても地図の「読めない所」「漏れる所」として残るので、研究の成果は失われない。
