## §2 観測空間

### 2.1 ★ R3 の段 1（**凍結済み**・ADR-014 D4）

> ⚠️★★★ **実データを見る前に凍結してある。★ 凍結後に候補を足さない**（足すなら別 ADR）。
> ★ 取得手段は 2026-08-22 のサーヴェイで **両 OS の成立を確認済み**。

| チャネル | 記録するもの | Windows | macOS |
|---|---|---|---|
| **フォーカス喪失・復帰の時刻** | ★ **遷移が起きた時刻のみ** | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` | `NSWorkspace.didActivateApplicationNotification`（★ TCC 不要） |
| **離脱の滞在時間** | ★ 上の 2 時刻の差（**新規記録なし**） | 同上 | 同上 |
| **切替後の復帰率**（個人基準） | ★ 派生量（**新規記録なし**） | 同上 | 同上 |
| **ポインタ**（移動量 / ボタン / ホイール） | ★ **1 秒固定ビンの集計行のみ・量子化スカラだけ** | **Raw Input**（`RIDEV_INPUTSINK`。★ `RAWMOUSE` に絶対座標フィールドが **構造上存在しない**） | 既存 tap とは **別 tap** |
| **`secure_input` フラグ**（macOS のみ） | ★ 区間フラグ。⚠️ その区間の特徴量は **欠損扱い** | — | `IsSecureEventInputEnabled()` |
| **計器の健全性** | ★ `capabilities`（ADR-013 D1）と併記 | `LLKHF_INJECTED` ＋ フック生存監視 | `CGEventTapIsEnabled` の定期確認 |
| **キーボードレイアウト識別子** | ★ セッション開始時に **1 回だけ**・識別子のみ | `GetKeyboardLayoutNameW` | `TISCopyCurrentKeyboardLayoutInputSource` |
| **打鍵のキー種別** | ⚠️★★★ **R3 は生 VK を書き出さない。カテゴリへ量子化する**（ADR-014 D4e） | 既存 | 既存 |

### 2.2 ⚠️★★★ 記録しないもの（★ ADR-013 D6 の作法で明示 record）

| 記録しない | ⚠️ 理由 |
|---|---|
| **役割カテゴリ**（`editor`/`terminal`/`browser`） | ★ ADR-009 D2 が「**G2 が落ちてから**」と順序を付けている（§2.4） |
| **アプリ識別子 / ウィンドウタイトル / URL / full path / プロジェクト名** | ADR-012 D3 / `data-privacy` |
| **ウィンドウ通し番号・distinct ウィンドウ数** | ★ **擬似識別子になる** |
| **符号付き `dx`/`dy`（イベント単位）/ 絶対座標 / 解像度 / マルチモニタ配置** | ★ **累積すれば軌跡が復元でき、画面内容の代理になる** |
| **イベント単位の移動量＋時刻の列** | ⚠️★★★ **mouse dynamics は個人識別可能な生体特徴である** |
| **選択範囲の文字数 / クリップボードのサイズ** | ⚠️ 前者は **同じハンドルから本文が読める** ため境界が **静的に監査できない**。後者は **サイズ自体が内容情報**（パスワード長・URL 長） |
| **`dwExtraInfo` / `hDevice` / `kCGEventTargetUnixProcessID`** | ★ 任意アプリが書ける自由フィールドか、ハードウェア/プロセス識別子 |

### 2.3 ⚠️★★★ 天井の性質を 3 つに分ける（★ 「拡張できないこと」と「拡張しないこと」は別である）

| 障壁の種類 | 該当 | ★ 拡張可能か |
|---|---|---|
| **原理的に不可能** | 同一アプリ内のウィンドウ切替（両 OS）／アプリ内の操作種別の **完了**（保存・実行・テスト・undo）／仮想デスクトップ切替（Win に専用通知が存在しない）／他プロセスの IME composition | ⚠️ **不可。** ★ 理由は 2 種類ある: **(a) 公開 API が存在しない**（仮想デスクトップ切替の通知／他プロセスの TSF composition）／**(b) アクセシビリティ層が公開するのは UI の *構造* であって アプリケーションの *意味* ではない**（「保存が完了した」を報告する API が無い。★ 取れるのは `Ctrl+S` という**意図の表明**まで） |
| **方針で止めている** | 役割カテゴリ／選択範囲の文字数／クリップボードのサイズ／符号付き `dx`,`dy` | ★ **可**（⚠️ 決めれば取れる） |
| **条件付きの入口が開いている** | **役割カテゴリのみ** | ★ ADR-009 D2 が「**G2 が落ちたときに初めて起動する入口**」として残している ＝ **却下ではなく順序** |

### 2.4 ⚠️ 役割カテゴリ — **技術調査は済み。⚠️ 順序は変えていない**

★ 2026-08-23 の調査で **前段サーヴェイの結論が Windows について誤っていた** ことが分かった:

| 経路 | Windows | macOS |
|---|---|---|
| **アプリ指紋を in-memory で読み、カテゴリだけ保存** | ★ `GetClassNameW`（**repo に出荷済みの前例あり**・`input/ime_windows.rs:320`） | ★ `NSWorkspace` → `bundleIdentifier` |
| **ユーザー宣言**（OS API を 1 つも呼ばない） | ★ 可 | ★ 可 |
| **フォーカス要素の役割**（AX / UIA） | ⚠️ UIA —— **却下済み**（同じハンドルから本文が読める） | ⚠️ `AXUIElementCreateSystemWide()` + `kAXFocusedUIElementAttribute` —— ★ **pid を引数に取らない**が、⚠️ **同じ要素から `kAXValueAttribute` で本文が読める** |

⚠️★★★ **したがって本当の論点は OS ではなく「アプリ指紋を in-memory で読むことを許すか」の一点である。**
★ クラス名も bundle id も **どちらもアプリ指紋**であり、**非対称ではない**。

⚠️★★★ **そして「取れる」は「要る」を意味しない。** ★ 順序（ADR-009 D2）は **1 文字も変えていない**。
詳細（3 案 R-1〜R-3 ＋ macOS の 3 案 M-1〜M-3 ＋ 実機で確認すべき 3 件）は
`.steering/20260823-r3-accept-and-role-category/role-category-feasibility.md`。

## §6 ⚠️★★★ 文献の帯 — **「観測を足せば当てられるようになる」は一次が否定する側である**

| 出典 | 実測 | ⚠️ 留保 |
|---|---|---|
| **[P118]**（CHI 2018・プロ開発者 13 名 × 2 週・実地） | 逐語「computer interaction data is more accurate in predicting interruptibility at the computer than biometric data (**74.8% vs. 68.3%** accuracy), and that combining both yields the best results (**75.7%** accuracy)」 | ⚠️★★★ **一次全文未取得 → 多数派基線が不明**。★ **この 74.8% を GSE の到達目標に使わない** |
| **[P120]**（CSCW 2011・アプリ切替を単独主信号） | ⚠️ 二次記述水準で **約 78%** | ⚠️★★★ **2011 年の 78% が 2018 年の全部入り 74.8% とほぼ同帯域**。⚠️ 一次未取得（N・基線・被験者内/横断すべて未確認） |
| **[P117]**（4 社・開発者 20 名・平均 11 営業日・個人ごとのモデル・自己申告 criterion） | **precision 0.57 / recall 0.48**（★ 中央値分割なので base rate ≈0.5） | ⚠️★★★ **特徴量 `activities` はアプリ識別子 → カテゴリ写像に依存** しており、★ **GSE が `data-privacy` で自ら禁じた情報に支えられて、なお 0.57 である** |
| **[V84]**（マウス軌跡からの mind wandering） | **F1 が無作為基線 +15% 止まり** | ★ 独立に同帯域が 2 本目 |
| **[P119]**（12 か国 449 名・長期実地） | 中断 −46%。★ 測度は **直近 3 分の打鍵＋マウスを重み付き合計し、その利用者自身の過去数日の上位 9%/4% 分位で閾値化するだけ** | ★ **アプリ識別子もウィンドウタイトルも使わない**（⚠️ 二次記述水準） |
| **[P121]**（N=475・2 独立文脈） | ★ 沈黙は **「帯域では割れない・直前イベントが割る」** | ★ R3 の設計に直接効く |

→ ★★★ **したがって R3 の目的は「当てること」ではなく、
「打鍵が沈黙した区間を 停滞 / 熟考 / 離席 に割ること」である。**
⚠️★★★ **その弁別を行った先行研究は、これまでのサーヴェイの探索範囲では 1 本も見つかっていない。**
★ **空白であることは有望であることを意味しない。**

## §7 `vibe_coding` の段 2 判定量 — ★ **候補。⚠️ 凍結していない**

⚠️★★★ **ADR-012 D1 の判定量（沈黙被覆率）は `vibe_coding` に合わない。**
★ 理由は分母である —— 沈黙被覆率は「沈黙区間のうち非打鍵チャネルで覆えた割合」だが、
**打鍵が濃い `vibe_coding` では分母（沈黙）が小さく、比が不安定になる**。

★ 以下は **候補** である。⚠️ **凍結は Epic 4 の着手ゲート（過信検出のエビデンス確認）の後**。

| # | 候補 | 分母 | ★ 成立条件 | ⚠️ 取得可能性 |
|---|---|---|---|---|
| **V-1** | **`left_observation` 被覆率**（R3 の判定量をそのまま使う） | ★ **`left_observation` と判定された区間の総時間** | ★ 分母が沈黙ではなく「観測外」なので、**打鍵密度に依存しない** | ✅ **段 1 のチャネルだけで出る**（フォーカス遷移 ＋ ポインタ） |
| **V-2** | **外部化の前後弁別率** | ★ `paste` イベントの件数 | ★ `paste` の直前 30–60 秒が「詰まって外部へ出た」か「通常の参照」かを、**段 1 のチャネルで分けられるか** | ✅ `paste` は既存記録。⚠️ **正解ラベルが無い**（L-A の帰結で代用するか未設計） |
| **V-3** | **ポインタ専有区間の比率** | ★ 「打鍵ゼロ かつ ポインタ活動あり」の総時間 | ★ `vibe_coding` は **差分レビュー・スクロール・承認クリック** で打鍵が止まる時間が構造的に長い。⚠️ **その区間が現行は `starved_ms` で「入力あり」に潰れている**（`liveness.rs:543`） | ✅ **Raw Input で直接出る**。★ **段 1 に既に入っている** |

### ⚠️ 3 候補に共通する未解決

- ⚠️★★★ **`vibe_coding` に到達するには `App.tsx` の argumentative lock 解除（判断 5）と宣言 UI（§4.3）が要る。**
- ⚠️ **V-2 は正解ラベルを要求する。** ★ V-1 / V-3 は **ラベル不要**（記述統計で出る）→ **先に出せるのは V-1 / V-3**。
- ⚠️ **アプリ内の操作種別（diff 承認・テスト実行の完了）は原理的に取れない**（§2.3）。
  → ★ **メモ §2.2 の「編集 → 保存 → 実行 → エラー → 修正の周期」は、そのままでは判定量にできない。**
