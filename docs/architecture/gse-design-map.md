## 0 位置づけ

- GSE は、打鍵の時刻と種類（本文は保存しない）と打鍵の外の記録で作業上の停滞を観測し、その中身を本人の申告と照らして、観測でどこまで見分けられ、どこで系は判断を保留すべきかを確かめる。見分けられた所を、身体回帰の機会を差し出す招待の適格の条件に使う（ADR-047 D1・2026-11-05。「詰まる前に」は外した）。招待は採点せず、開始・継続・完了を系は測らない（ADR-018）。主の対象は行動上の停滞で、詰まり・熟考・資料・会話・離席は停滞の中身として記述する（ADR-045 D1）。段 1 と段 2 の主の比べで、推定は契機を作らない（ADR-047 D2。今の EH3 モードの招待は今の推定を契機にしている）。
- 確証の核は L0（X 摩擦・Y 前進の 2 軸と、プローブの Q1・Q2 との個人内の順序の一致・C-index）。L1（Stuck）・L2（Need・介入の時機）・Y は探索（`docs/research-positioning.md` §1）。L0 の Y（前進）は、HMM のコードでは関与（Engagement・`heads/writing.rs` の Y の軸）と呼ばれる同じ軸である（glossary の MhD の項は Productive Engagement）。
- 上流の文書のずれ: 2026-11-05 に `research-positioning.md` §1（改訂ブロック）・`agent-shared.md`・`wbs-verification-halfyear.md` B1・B2 を ADR-047 に合わせた（`.steering/20261105-gse-overview-and-concept/doc-drift.md`）。今の計画は段 1（招待なしで C4）→ 段 2（適格な時点での招待あり／なしの 1 人の中の無作為化・推定器の腕は副・ADR-047 D4）。

### 4.2 既にあるもの（main）

- 記録の側: `activity_label`（6 択・`recall_window_*`・`latency_ms`・`logger.rs:685-`）、`probe_assignment.stratum`（3 値・今はいつも `random`・`lib.rs:5643`）、区間の削除で自己申告の行も消える（ADR-031 D6・`redaction.rs`）、6 択の記録の門 `o1::activity_label_allowed`（`o1.rs:245`・`EsmConsent` を要求する型）。

- `activity_label` は送出元が無いので `capabilities` に宣言していない（ADR-031 D4・宣言を強制する検査あり）。

### 4.3 実装のタスクで決めて確かめる提案（Claude）

1. モード: 名前（仮に `s1`）・`meta` の値・launcher。プローブを止める条件（`GSE_DISABLE_PROBES`・G1・EH3）に、新しいモードでは止めないことを足す。Nudge と招待を切る（判断 10）。
2. 6 択の記録の門: `activity_label_allowed` を新しいモードと問いへの同意に結び直す。O1 では `None` を返す（O1 では C4 を取らない・ADR-043 D8）。
3. 層化の引き金: `low_operation_end`（打鍵の無い区間が閾値以上続いた後に特徴量のキーが戻った時点）と `resumption`（フォーカスの遷移の後に打鍵が戻った時点）。閾値は定数にし、値は S1-A1。推定器の出力は読まない（ADR-031 D2）。判定は `analysis/` の純粋な関数にし、`gse-replay` で記録から再現できるようにする。
4. 無作為と層化の調停（判断 8）を純粋な関数にし、「層化が先に出ても無作為の候補の時刻と件数が変わらない」ことを検査で固定する。
5. カード: Q1・Q2 と 6 択を 1 枚に。1 回の回答で `realtime_label` と `activity_label` を同じ `probe_id` で書く。自由記述を置かない（ADR-031 D3）。
6. `capabilities`: `activity_label` と `probe_suppressed` を `config_gated` で宣言する。3 点セットと一時停止の遮断の検査（ADR-013 D3・ADR-031 D4）。
7. 画面の確かめ: macOS と Windows の実機で、カードが見え、押せ、背後のクリックを奪わないことを見る（過去に Windows の透明窓が背後のクリックを奪った）。
8. 実装の前に `/start-task` で設計し、`/reimagine` をかけるかをそこで研究者に聞く。
