# **7\. 検証設計**

## **7.1 事前登録された合否契約（凍結済み）**

**本プロジェクトは、判定基準をデータを見る前に凍結する運用を既に実装・実施している。** これは提案上の宣言ではなく、**既に一度回した契約**である（§10）。

| ゲート | 問い | 通過基準（事前凍結） | 不合格時 |
| :---- | :---- | :---- | :---- |
| **GATE1 尺度理解** | 主観申告の尺度を正しく取れるか | 例題8問中6問以上 かつ被験者の8割以上 | 教示を作り直して再施行（本番データを取らない） |
| **GATE2 測定法** | 回答が集まるか | 回答率 ≥80% / 回答時間中央値 ≤10秒 / 有効プローブ ≥20件/人 | ラベル方式を再設計 |
| **GATE3 モデル** | 推定が申告の順序に沿うか | **方向付き順序C-index 中央値 ≥0.65 かつ全員 >0.55** | 特徴・モデルを差し戻し |

**併走する報告要件（PreReg-5〜8）**

- **前向き固定 holdout**: 各人の**最初の2セッションでベースラインを較正し凍結**、残りで前向きに評価する。**評価期間中の閾値・パラメータ調整は禁止。**
- **Recall の抑制**: 独立した陽性エピソードが30件未満なら**点推定を出さない**（定性所見のみ）。
- **欠測（MNAR）**: 未回答を「全て高摩擦」「全て低摩擦」と置いた**上下限を併報**する。**高欠測者を除外しない**——落とすと「難しい状態の人」だけ消えて欠測の偏りを強化するため。
- **二軸性**: 非対角象限の出現が <10% なら「**二軸性は検証不能**」と報告する。**単軸とも二軸とも結論しない。**

**「情報を持つ Kill」と「情報を持たない不足」を区別する規約**

「推論妥当性がKillでも、測定法の破綻検出という貢献が残る」が成り立つのは、**GATE2 を満たす十分なデータの下でC-indexが偶然以下だった真のKillに限る。** **主指標被験者ゼロ・提示プローブゼロ・最低要件未達は Kill ではなく `DataInsufficient`（データ拡充）であり、課題放棄や計測外への移行による空振りは反証ではなく「測定の失敗」として切り分ける。**

**この規約は既に一度、自分に対して適用した**（§10）。

## **7.2 Phase A: 統制タスク実験**

**2026年度版に無かった段である。そして本提案の入口である。**

**何を問うのか**: **打鍵由来の content-free な特徴量だけで、実験的に操作した高摩擦条件と低摩擦条件を、個人内で分離できるか。**

**これは較正（X1）とは違う。** criterion を主観プローブではなく**実験者が課題設計で与えた条件ラベル**にする。**較正が死んだラベル供給の問題を、統制実験では設計で回避できる。**

**かつ、この問いは軸の定義を書き換えても免除されない。** 分離できないなら、どの軸に書き換えても観測空間が足りていないことになる。

**判定（データを見る前に凍結済み）**

| 項目 | 内容 |
| :---- | :---- |
| 単位 | ブロック（＝無作為化の単位） |
| モデル | **L2罰則つきロジスティック回帰。λ = 1.0（z標準化後）を事前固定しチューニングしない** |
| 標準化 | **学習fold のみ**を使って z 標準化 |
| 交差検証 | **被験者内 leave-one-block-pair-out。被験者を跨いで学習しない**（universal marker 不在[41]） |
| 指標 | 個人内の out-of-fold AUC |

**なぜ罰則を事前宣言するか**: 1人8ブロック（各foldの学習は約6ブロック）に対して特徴量は最大14個。無正則化では**完全分離**が起き、係数が発散してAUCが人工的に1.0近くまで上がる。**λ=1.0 は最適値ではなく慣例値である。結果に有利な値を後から選べないように凍結することに意味がある。**

**特徴量セットは2本だけ（3本目を作らない）**

| セット | 内容 | 何を答えるか |
| :---- | :---- | :---- |
| **FS-A** | 現行5特徴量（F1 / F3 / F4 / F5 / F6） | **現行の観測空間**で分離できるか |
| **FS-B** | FS-A ＋ 打鍵近傍のイベント（打鍵数 / BS率 / 外部貼付文字数 / IME滞留中央値 / 沈黙長のp50・p90・max / バースト長のp50・p90）= 14特徴量 | **観測空間を広げれば**分離できるか |

**勝ち幅は2つの基線に対して報告する**: **(a) 多数派分類器** と **(b) FS-A ベースライン**。**多数派基線に対する勝ち幅を併記しないと、「偶然 +0.07」を「有望」と読む誤り[46][15]が再発する。**

**実施上の制約**: FS-A は**実行時にGSEが出力している5特徴量そのもの**から取り、打鍵ログからオフラインで再計算しない。理由は「現行の観測空間」とは実行時に実際に計算されている値だからである（特徴量計算にはオートリピート除外などログに現れない処理がある）。→ **この制約により、統制タスク実験は GSE 本体が動いている環境でしか実施できない。**

**現況**: 事前登録は凍結済み、課題文（8題材×2版）・割付スクリプト・解析スクリプト・検証スクリプトはすべて完成し、検証コマンドが緑である。確証標本のn（3名）も**データを見る前に凍結してある。**

## **7.3 Phase B〜D: 新規ゲートと実験**

**事前登録された合否基準（PreReg-1〜8 / GATE1–3）そのものは変更しない。** 追加するのは **Phase B 以降にのみ発効する新規ゲート**であり、Phase A / 較正には遡及しない。

| ゲート | 何を見るか | 閾値の置き方 |
| :---- | :---- | :---- |
| **Gate D（需要・新規）** | 自発的な初回利用 / 7日以内の再利用 / 研究参加外での利用意向 | **実配備ベンチ（30日継続率の中央値 3.3%）を桁のpriorとして置く。** 試験由来のコンプライアンスを前提に高く置かない |
| **Gate S（センシング・新規）** | イベント取得成功率 / 欠損率 / OS・アプリ差 / 遅延 / CPU・メモリ / **内容漏洩ゼロ** / 再実行可否 | 実測値で判定 |
| **Gate H（有害性・新規・拒否権付き）** | annoyance / tension / **自律性の毀損** / 偽陽性のコスト / 中断 / 早期離脱 / 監視されている感覚 | **悪化した場合、GATE3 が Go でも介入機能は Go としない** |

**Gate H の測定について、2点を明記する**

1. **自律性の測定尺度を「選択肢の多さ」で代用しない。** 自己決定理論の原典[20]は autonomy を「**自己による調整**」と定義し、逐語で「**多くの選択肢を持つことは基本的欲求ではない**」「**選択肢が1つしか無くても、本人が真にそれを是認しているなら十分に自律的だと感じうる**」と述べている。→ **正しい根拠は「選べるから」ではなく「本人が事前に是認しているから」である。**
2. **計器は METUX[21] の autonomy 下位尺度を第一候補とする。** **著者自身が「初期版であり、より徹底した検証と洗練を要する」と留保している**ため、**確証には使わずゲートの運用指標として使う。** 併せて反証[22]（k=99研究のメタ分析レビューが「基本的心理欲求が説明する分散は統計的には有意だが実務的には無視できる」と報告）も併記する。一方、同レビューの方法論的警告「**横断的な自己申告研究は推奨しない**」は、**GSEの個人内・縦断・日次デザインに有利である。**

**Phase C（較正 X1 と介入価値 Y）**: 個人適応した較正プローブでC-indexを算出し GATE2 → GATE3 を判定する。not-kill なら AB/BA クロスオーバーで介入の受容と効果を測定する。

**「AI依存が下がった」を「自力解決」と取り違えないための追加アウトカム**: 完了率 / 放棄率 / 時間超過 / 外部支援の自己申告（計測外への移行の捕捉）を併報する。**`paste_after_stuck_rate` の低下が「自力解決」ではなく「諦め」である可能性を、直接は棄却できない。**

**交絡の統制**: 「ツールを起動したこと自体」の効果（儀式効果）が実在するなら、アウトカムは介入内容ではなくそれに帰属しうる。**較正期（介入なし）と介入期の個人内対比が、この分離の既存の統制として機能する。**

**Phase D（介入機会 X2）**: 介入候補時点で nudge / defer をマイクロランダム化し、近接アウトカム（2〜5分後の手動復帰・外部貼付の回避・dismiss）の差を推定する[42][47]。**cutoff と近接アウトカムの向きは事前登録して凍結し、データを見てから方向を変えない。**

## **7.5 検証を支える装置 —— 何が動いていて、何が未達か**

**本節は作った量ではなく、判定を後から動かせなくするために先に置いた装置と、その現況を書く。**

### **(1) 判定を後から動かせなくする**

**事前登録は、改訂のたびに「この改訂で合格が容易になっていないこと」の記載を必須にしている。** 不変量は一つで、**「分離できた」と宣言できる経路の数が増えていないこと**である。**直近の改訂は、この不変量を満たすと言い切れなかった。そこで、言い切れないとそのまま書いて残した**——統制実験の被験者1名を確証標本から外す判断であり、**標本の定義をデータの後で変えた形に見えうる**からである。

**解析スクリプトは、凍結した見る順序を満たさない限り、条件ラベルに依存する量を出力しない。** 順序は「操作チェック → 陽性対照（positive control） → 分離の判定」であり、**前の2つが通らなければ3つ目を封印する。** どうしても見る場合は明示のフラグが必要で、**使うと「その回は確証的でない」という印が結果に刻まれる。**

**なぜ封印が要るか。** 操作が真に効いていても、操作チェックは分母の小ささから **18〜35%の確率で不合格を引く**（分母は割付の構成上4〜6に保証されており、20,000通りの割付での実測）。**そこで数値を見てしまうと、原因を直して再実施しても確証的でなくなる。** つまり偽の不合格が「実験全体が一回で無駄になる」事故に直結していた。**文書が「解釈するな」と書いていたものを、ツールのほうが目の前に出していた。** 実装側で閉じたのはこの穴である。

### **(2) 収集能力の自己記述 —— 0行の意味を分ける**

**ログは、その時点のビルドが何を記録できたかを自己記述する**（§10.3 ②）。目的は **0行の意味を「信号が無かった」と「計器が無かった」に分けること**である。

**この区別が最も効く実例がセキュア入力である。** macOSはOSがsecure inputの状態を返すため、その区間を記録できる。**Windowsには相当するAPIが無い。** ログはこれを「secureではなかった」ではなく**「計器が無い」と記録する。** したがって、**Windowsではパスワード欄の打鍵も他の打鍵と同じく種別へ量子化されて記録される。** なお、**検出できた区間を記録の停止へつなぐ配線は、どちらのOSにも入れていない。** macOSでセキュア入力中に打鍵が届かなくなるのはOS側の作用であって、本システムが抑止しているのではない。記録されるのは種別であって文字ではないが、**「抑止できている」とは書かない。**

### **(3) 削除保証台帳**

**自然作業の長期記録に用いる同意文書**は、削除の求めに応じたことを「記録に残します」と約束している。**その台帳を配備より先に作った。理由を問わない設計であり、削除の要求に理由の引数が無い。** なお、**この一文は自然作業の側の同意文書にだけあり、統制実験の同意文書には無い**（統制実験の側は「解析から外して破棄する」と書いている）。**同意文書そのものは、配布前の案である。** **また、端末上の操作で消せるのは提出前までで、提出後の分は研究者側の手続きになる。台帳はその後者のためにある。**

### **(4) 自然作業の長期記録に固有の再識別リスク**

**統制実験には無く、自然作業の長期記録にだけあるリスクを、配備の前に見つけた。** 統制実験の入力は日本語IMEによる論述なので、**生のキーコード列から復元できるのはローマ字の綴り（＝読み）までで、変換後の本文そのものには戻らない。****一方、自然作業ではURL・コマンド・パスワードなど英数の直接入力が混じるため、生のキーコード列がほぼ一対一で本文へ戻る。** 対処として、書き出しの境界でキーを種別へ量子化した。**同じ実装でも、収集の形が変わればリスクが変わることの実例である。**

### **現況 —— 何が未達か**

| 項目 | 統制実験 | 自然作業の長期記録 |
| :---- | :---- | :---- |
| 事前登録・判定基準 | データを見る前に凍結済み | 該当なし（探索的な収集） |
| 計測系の実装 | 実装済み。検証コマンドは緑 | 実装済み。リリース検査の残りは1件（送信タイムアウトが未実測） |
| 実データ | パイロット1名。**確証標本は 0/3 であり、判定は一度も出していない** | **0セッション。配布ゲートが未達で、まだ配備していない** |
| 削除の求めへの対応 | 該当なし | 台帳は動くが、**実績は1件も無い** |

**パイロットの1名は捨てていない。** そのデータで計器の不具合（同一ファイルに2セッションが積まれる）を実際に踏み、**その被験者を確証標本から外したうえで計器を作り直した。** 確証標本は3名のまま、**外した分を埋め合わせず、新規3名を取り直す形にしてある。**

# **10\. Phase1（較正データ収集）の実測 —— 判定に届かなかったこと**

**本章は、本書で最も重要な章である。**

## **10.1 何が起きたか**

2026年6月〜7月、被験者5名・**63セッション**を収集した。うち**主分析に使えるのは40セッション**である（残り23セッションは介入ONの条件で、較正の前提である「推定結果を被験者に見せない」を満たさないため除外した）。

| ゲート | 結果 |
| :---- | :---- |
| **GATE2（測定法）** | **pass**（コホート全体の回答率 **0.926** ≥ 0.80。回答率 <0.70 は1名のみで、Kill 条件の「2名以上」に該当せず） |
| **GATE3（モデル）** | **DataInsufficient** —— 母数を満たしたのは **5名中1名のみ** |
| overall | **inconclusive** |

**被験者別の内訳**

| 被験者 | 評価セッション | 提示 | 回答 | 回答率 | latency中央値 | 有効件数 | X→Q1 C-index | GATE3母数 |
| :---- | :---- | :---- | :---- | :---- | :---- | :---- | :---- | :---- |
| P010 | 10 | 104 | 103 | 0.990 | 6.5s | 103 | **0.45** | ✅ |
| P011 | 3 | 21 | 21 | 1.000 | 8.4s | 21 | 0.40 | ❌ 評価セッション不足 |
| P012 | 5 | 36 | 35 | 0.972 | 4.0s | 35 | **算出不能** | ❌ |
| P013 | 8 | 21 | 7 | **0.333** | 19.3s | 7 | **算出不能** | ❌ |
| P014 | 4 | 34 | 34 | 1.000 | 14.2s | 34 | **算出不能** | ❌ |

**判定パイプラインの `model.verdict` は機械的に `kill` を出した。私はそれを採用しなかった。** 凍結ルールは「**有効プローブ <20件/人 や人数不足は Kill ではなく DataInsufficient**」と事前に定めており、**母数1名の中央値は確証エビデンスにならない**からである。→ **結論: GATE2 = pass、GATE3 = DataInsufficient。**

## **10.2 なぜ起きたか —— 原因は HMM ではなく測定設計にあった**

**C-indexが「低い」のではなく「算出不能」な被験者が2名いた。** 原因は推論側ではなく、**主観申告（Q1）の回答分散の枯渇**である。

| 被験者 | 有効回答 | Q1 の分布 | 相異なる値 |
| :---- | :---- | :---- | :---- |
| P010 | 103 | 2:2　**3:59　4:41**　5:1 | 4（中央2値に97%） |
| P011 | 21 | 1:3　2:7　3:2　4:7　5:2 | 5（良好） |
| P012 | 35 | 1:1　**3:34** | **2**（97%が「3」） |
| P013 | 7 | **1:7** | **1**（完全に一定） |
| P014 | 34 | **1:16　3:18** | **2**（中間値なし） |

順序C-indexは「値が異なるペア」でしか定義されない。**P013 は Q1 が全て 1 ＝ 比較可能ペアがゼロ → 数学的に算出不能**である。

**そして、これは被験者の不誠実さではなかった。** 運用管理シートの主観データと突合した結果:

- **過多側（P012）**: プローブ頻度を **11件中10件で「多すぎた」**と回答。セッション毎アンケートの「集中」項目は5名中最低（2.91）。**その状態で Q1 を35件中34件「3」と回答した。** 事前・事後アンケートの**両方に未回答**であり、離脱していたと解釈するのが自然である。→ **定数化は測定器の過負荷が生んだものである。**
- **過少側（P011）**: 後半4セッション連続で「**少なすぎた**」と回答。有効プローブは21件と閾値ギリギリ。さらに**介入が全10セッションで一度も発火しなかった**（自由記述でも2回言及）。
- **過多側と過少側の両端で同時に外していたことが、律速が測定設計にあることの最も強い証拠である。**

**最も痛い所見**: **P013 は事前アンケートで AI依存「ほぼ毎回」・生成物のコピペ「1日複数回」と回答していた——すなわち GSE が最も狙うべき層である。その被験者が回答率 0.333（5名中最低）で、主観ラベルを事実上供給できなかった。**

**ただし「ターゲット層だから脱落した」とは書けない。2026年9月3日に旧記述「最も早く脱落した」を取り下げた。** P014 は事前アンケートで P013 と完全に同値（ほぼ毎回・生成物のコピペ1日複数回）でありながら、**回答率1.000・有効34件で完走している**。**同率者が直接の反証になっているため、AI依存度を脱落の説明変数として主張しない。** 併せて P013 は評価セッション8件で5名中2番目に多く、セッション毎アンケートは14件で最多である。事前・事後アンケートの両方が未回答なのは P012 のほうである。

**併せて得られた肯定的所見**: 事後アンケート（4名）で「GSEを使う中で詰まったとき考え直す感覚が戻った」は4名中3名が5段階中4–5、フラストレーションは全員1–2。**プライバシー不安は4名全員が「なかった」**——content-free 設計の受容性は支持された。**ただし最も負荷の高かった被験者が欠測しているため、満足度は生存者バイアスで上振れしている。欠測の議論はプローブだけでなくアンケート回答自体にも当てはまる。**

## **10.3 何を直したか**

**① 判定パイプラインの欠陥を修正した。** 尺度理解テストが**未実施**であるにもかかわらず、機械的に「通過率 0.00 ＝ 不合格」と出力される経路があった。**実際にこの出力が引き継ぎに転記され、「1人も通っていない」と誤読された。** → 「未実施」と「不合格」を区別するフィールドを追加し、**未実施のまま Go へ昇格しないことを反証方向のテストで固定した。**

**② 収集仕様の自己記述性を実装した。** 「**信号が無い**」のか「**計器が無い**」のかを、ログだけから機械判定できる形にした。**これは実際に起きた失敗への対処である**——後から沈黙区間を分解しようとしたとき、**必要な行が Phase1 の63ファイル中1行も存在しなかった**（計器の追加が収集の16日後だった）。**計器がコホートを跨げなかった失敗は既に2件あり、3件目を防ぐためである。**

**③ 較正解析パイプラインの穴を起票した。** 介入ONのセッションを混ぜても警告が出ない（配置段階の手作業で防いでいた＝再現性の穴）／時刻の単調性ガードが匿名化データに対して何も守っていない／未匿名化ログが提出される導線がある——**これらは実際にPhase1で顕在化した。**

**④ 次の実験を「設計で回避する」形に切り替えた。** 統制タスク実験（§7.2）では criterion を主観プローブではなく**実験者が与えた条件ラベル**にする。**Phase1 が死んだラベル供給の問題は、統制実験では設計で回避できる。**

## **10.4 プロトタイプ分析の予備的知見（n=1）**

参考として、開発者自身のセッションログによる予備分析を記す。**n=1 であり、汎化性は未検証である。**

- **F6（Pause-after-Delete率）** は Stuck 優勢ウィンドウで平均 **0.469** を示し、Flow優勢ウィンドウ（0.088）の約 **5.4倍**。
- F6 と `p_stuck` の相関は **r = 0.743**、F3（Correction Rate）は **r = 0.678**。
- 設計改善（ヒステリシス層・放出確率の方式変更・合成摩擦）により、Flow優勢率が **97.2% → 79.2%** に正常化し、状態遷移が観測可能になった。

**これらは「モデルの内部で相関している」という記述であって、外部の criterion に対する妥当性ではない。** 外部criterionに対する結果は §10.1 のとおりであり、**X→Q1 の C-index は5名全員で 0.52 以下（偶然水準以下）だった。** **ただしラベル分散が枯渇した状態のC-indexは交絡しており、これを「モデルが外れている証拠」と即断してはならない。** **その切り分けこそが Phase A（統制タスク実験）の目的である。**
