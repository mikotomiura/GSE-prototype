**Generative Struggle Engine (GSE)**

打鍵から「詰まり」を推定し、自力で考える機会を保存するプラットフォーム

本資料は全体像と設計思想を述べる。特徴量・推論・検証設計・実測データ・参考文献は、別添の『[提案プロジェクト補足資料]GSE技術設計書』（以下「技術設計書」）に置いた。本文中の文献は著者名と年で示し、書誌は技術設計書 §11 に集約している。

# **1\. なにをつくるか**

## **【原体験と社会的視点】**

かつての学校教育において、私は速く・正確に・皆と同じようにという画一的な効率の物差しに適応できず、深い劣等感を抱えてきた。しかし生成AIの登場は全てを変えた。私が苦しめられた効率は、いまやAIが秒速で代替してくれる——はずだった。ところがChatGPTが生成したコードを貼り付けてエラーが消えた瞬間に私が感じたのは、達成感ではなく強い虚しさだった。「私はAIのオペレーターに過ぎないのではないか」。この問いが本プロジェクトの出発点である。この虚しさの正体を当初は「AIを使う作業は消耗が激しいのだ」と考えていたが、**一次文献に当たった結果、その説明は成立しないと分かった。**

第一に、**「認知資源が一方向に消耗する」という説明そのもの**（限定資源モデル）**が、現在の心理学では支持されていない**。事前登録された大規模な多施設再現が二度これを否定し（23研究室・2,141名で d = 0.04、36研究室・3,531名で d = 0.06）、決定的なのは**後者では操作そのものは効いていた**（努力感 d = 1.76）ことである。第二に、**AIを使う作業が「重い」という証拠も無い**——因果推論が最も強い研究（24週・段階的ウェッジ設計の無作為化試験、66名）では疲弊はむしろ**下がっている**（−0.44, P < 0.001）。「AIで疲弊が増す」とする研究の多くは**AIに職を奪われる不安**を測っており、道具の使用負荷を測っていない。

**変わっているのは負荷の量ではなく、関与の在り処である。**事前登録された被験者内クロスオーバー実験（60名・脳波等を同時計測）は、AI支援下で前頭の θ/α 比が**低下**することを報告し、逐語で「**生成の努力をモデルへ肩代わりさせたときの、認知的関与の低下と整合する**」と説明する（Burelliら 2026）。319名を対象としたCHI 2025の調査も、生成AIは批判的思考の性質を「**情報の検証・応答の統合・タスクの管理**」の側へ**移す**と結論する（Leeら 2025）。そして努力の後に変わるのは処理能力ではなく**投資を続ける意思**である——事前登録4実験・686名の拡散モデル解析は、下がるのは抑制制御ではなく**決定閾値**であり、人は「**関与から降り、それ以上努力を投じることに関心を失う**」と報告している（Linら 2020）。

つまり生成AI時代の問題は、私たちが疲れ果てることではない。**生成の努力を肩代わりさせた結果として関与が下がり、残った検証の手間まで飛ばして「答えをそのまま受け取る」ようになること**である。実際、AI提案を**ほぼ無検証で受け入れる帯域では正答率が下がる**（Fanら 2026・N=60・事前登録：受容率の二次項 β₂ = −0.81, p = 0.005）。しかもこの傾向は**訓練や明示的な検証指示では防げない**ことが自動化研究で繰り返し示されており（Parasuraman & Manzey 2010）、**当人の主観はこの過程を追えない**——自己申告と実測ログの相関はメタ分析で **r = 0.38**（Parryら 2021・N=52,007）、開発者の生産性実感と客観出力の共有分散は **3%未満**である（Murphy-Hillら 2021・n=3,344）。高校数学の事前登録された現場試験でも、答えをそのまま出すAIは支援を取り上げた後の成績を有意に下げた一方、**学習者自身は学習の低下を認識していなかった**（Bastaniら 2025）。

**したがって必要なのは、さらなる効率でもAIの排除でもない。自己申告では捉えられない過程を作業中の行動から見て、関与が起きる余地を道具の側で残しておく設計である。**

## **【提案システム：GSE (Generative Struggle Engine)】**

GSEは、**ユーザー自身の「詰まり」を打鍵の仕方から推定し、自力で解こうとする試行が発生する機会を保存する**HCIフレームワークである。設計思想として「不便益」——平岡（2021）の定義で「労力がかかること」から得られる益——を引き、8枚のカードのうち「主体性の喚起」「気づきの促進」「工夫の余地」の3枚を使う。ただし**GSEを「不便益HCIである」とは書かない**——現時点で稼働する介入は労力を課さず、認定条件を満たさないからである。同様に「生産的失敗」（Kapur 2008）と「望ましい困難」（Bjork 1994）は**守るべき困難が存在すること**の根拠として引くが、「摩擦を与えれば学習が伸びる」という主張には使わない。

**GSEは追加の機材を必要としない。**普段使っているキーボードの打鍵の仕方だけを見て動き、**本文を一切保存しない**。この制約は精度上は不利だが、被験者の受容とデータ公開の両面で効いている（§5）。

## **【コア機能】**

**(a) 詰まりらしさの推定** — 打鍵動態から5つの特徴量をリアルタイムに抽出し、認知的意味を持つ2つの潜在軸（認知的摩擦／生産的な前進）へ射影した上で、HMMにより `p_stuck`（詰まりらしさの連続信号）を出力する。本文は保存しない。なお本提案は「集中・潜伏・停滞の3状態を分類できる」とは主張しない——実運用で使うのは離散ラベルではなく連続信号だからである。**ただし3クラス分類を捨てたわけではなく、後段のサブ応用研究として位置づけ直した**（§3）。

**(b) 「必要か」と「いま割り込んでよいか」を分けた介入判断** — 推定結果をそのまま介入に変換せず、判断を2層に割って**両方が揃ったときだけ介入する**。特に**能動的にタイプしている最中は見送り（defer）とし、進行中の苦闘には割り込まない**。この見送りは第一級の判断としてログに記録され、後から「介入しなかったこと」も評価できる。稼働している介入は**Nudge**のみで、画面右端から小さく現れ、クリックを遮らず、一定時間で自動的に消える。**2026年度提案に書いた4段階介入とMonk Modeは、2026年8月に全て削除した**——画面を塞ぐ介入はAI依存も助けを求める行為も作業そのものも一律に止めてしまい、「答えの受領だけを狙い撃つ」という要求に構造的に応えられないからである。

**(c) Physical Anchor —— 身体的回帰への方向づけ（未実装・第2の柱）** — 実際に労力を担う層である。GSEが提示するのは「**いま画面から離れる**」という方向づけであり、**系は離席の開始も完了も判定しない**。時間の長さも往復の回数も閾値を置かず、どれだけ離れるかは本人が決める。2026年8月30日に**完了条件そのものを取り下げた**——旧版は「歩数」ではなく「時間と復帰」と定めて量による解放を避けたつもりだったが、**単位が違うだけで、届かなかった状態を作る点では同型だった**（Deciら 1999 で最大の毀損は目標に届かなかった群の d = −0.88 であり、達成判定の存在自体が作る）。**身体活動のセンシングも恒久的に外した**——完了判定を置かない以上、センサが寄与しうる判定が構造的に存在しないためである。これが「計測なき身体回帰」である（§3）。

**(d) 表現チャネル（未実装）** — 現在の介入はNudgeに張り付いており、「強制的ではないが簡単には無視できない」中間帯域を持たない。そこで推定された内的状態を、スマートフォンのロック画面等へ**断定を避けた4値の抽象イベントとして一方向に送る**チャネルを設計する（連続値も本文も端末名も境界を渡さない）。**このチャネルの効果は主張しない。**

## **【主張の範囲と、自律性への配慮】**

**主張すること（機会保存）**: 反射的な外部依存——詰まった瞬間に答えをそのまま受け取ること——を減らし、自力で解こうとする試行が発生する機会を保存する。**詰まった直後の外部ペースト率**、**ペーストなしの自力復帰**、**手入力寄与率**という行動指標で測り、すべて本文を保存せずに算出できる。

**主張しないこと**: 保存された苦闘が能力や学習を育てるか（生産的失敗のメタ分析は、摩擦の学習効果が成果指標により符号を変え、**手続き的知識では g = −0.03 の完全なnull**であることを示す。Sinha & Kapur 2021）、および散歩が認知作業を回復させること。**GSEは苦闘の保護だけを実装し、その後の統合設計を持たない。**詳細は §3 に列挙する。

**自律性**については「オプトインと消去があるから脅かさない」という論法を使わない（自己決定理論の原典が、選択肢の多さは自律の根拠にならないと明言している）。原則は**(1)** 発動条件・強度・記録内容の事前の是認、**(2)** 自動消去とクリック透過、**(3)** 夜間帯の無効化、**(4)** 拒否権付きの独立した有害性ゲート、の4つで、**(4)では自己申告だけを根拠にしない**——Netflixの自動再生を無効化した無作為化試験では1日の視聴が−21.0分動いた（p = 0.003）のに、事前に**95%が「自分は制御できている」と回答していた**からである（Schaffnerら 2025）。

## **【ターゲット】**

**論理的構築と思考プロセスに価値を置くナレッジワーカー**——学術論文やレポートを書く学生・研究者、仕様書を練るプランナー、設計思想を言語化するエンジニアなど「キーボードで自分の思考を構築する」層である。ただし**適用範囲は「打鍵を伴う知的作業」に構造的に限定される**。5特徴量はすべて打鍵動態から算出されるため、動画編集・スライド作成・図面作業では特徴量が縮退して無音と離席が区別できない。これは特徴量の調整では解けず、入力層の再設計を要する別課題である。

**α版（統制タスク実験の完了後）**: 実験で使用したビルドを、被験者向け配布物と同じ形でα版として公開する。打鍵のみで論理構築を行えるMarkdownエディタを基本とし、「打鍵＝思考の痕跡」を高い純度で抽出できる形にする。日本語IMEの多段階変換が頻発する長文執筆は、「日本語特有の詰まり」の検証に最適なテストベッドである。

**実証（クローズドβ）**: ZEN大学の同級生とエンジニアコミュニティの有志（10名程度）を対象に、介入あり／なしのクロスオーバー設計で順序効果を相殺し、(a) 答えの受領の減少、(b) 自力解決率、(c) 悪化させていないことの確認、を測定する。(c) では第三者ブラインドの品質評価に加え**行動側の客観指標を必ず併報する**——「AI依存が下がった」ように見える指標は**諦めや課題放棄、別デバイスへの計測外移行でも動く**からである。

**学術発表**: 収集した「日本語IME入力における詰まりのキーストロークデータセット」を匿名化して公開し、WISS・インタラクション等のHCI系シンポジウムでの発表を目指す。既存研究がほぼ全て英語アルファベット入力を対象としているのに対し、**日本語IMEの未確定文字列操作を含む公開データセットは国際的に存在しない**。非アルファベット文字体系のログ取得手法が2026年に提案されたばかりであり、この領域は今まさに開きつつある。

**展開可能性**: GSEは「行動シグナル層 → 作業状態推定層 → 介入機会判定層 → 介入ポリシー層」の4層で設計され、この境界は実装のモジュール境界と一致する。推定層より上流は入力モダリティに依存しないため、行動シグナル層を差し替えれば他領域へ拡張できる構造にはなっている。ただし**「差し替えれば当たる」とは書かない**——同条件の一次実測は4社・開発者20名で precision 0.57 / recall 0.48（偶然 +0.07）に留まり、その特徴量はGSEが自ら禁じたアプリ識別子に依存している。

# **3\. 斬新さの主張、期待される効果など**

## **【HCIの目的関数の反転と、既存ツールとの差異】**

HCIの設計思想は、Nielsenのユーザビリティ原則やNormanの The Design of Everyday Things 以来、一貫して「認知的摩擦の最小化」を目的関数としてきた。GSEはこれを反転し、**摩擦を一律に消すのではなく、守るべき摩擦と消すべき摩擦を区別する**ことを問いに据える。ただし「反省を促す設計」自体は新規ではない——Slow Technology → Informative Art → Reflective Design という系譜が既にあり、その原則「反省は行為とは別の活動ではなく、行為の中に折り込まれる」は、GSEが**作業中に介入する**ことの根拠になる。したがって書けるのは「**既存の原則を実作業中のリアルタイム推定に適用した**」という形までであり、しかもこの系譜は全体が設計論で効果の出典を持たない。

| | RescueTime / Centered | FlowLight | **GSE（本提案）** |
| :---- | :---- | :---- | :---- |
| 何を推定するか | 時間計測・手動タグ | 「忙しいか」の単調写像 | **詰まりらしさの連続信号** |
| 割り込みの判断 | ✗ | 中断の可否のみ | **必要性と機会を分離し、見送りを記録** |
| 沈黙の扱い | ✗ | **要求されていない** | **熟考／停滞／離席の弁別を問いに据える** |
| 身体的回帰 | ✗ | ✗ | **計測を伴わない方向づけ** |
| 入力デバイス | アプリ監視 | 打鍵＋マウスの量 | **PCキーボードのみ・本文非保存** |

FlowLightを比較対象に加えたのは、この系が**12か国・449名の長期実地で中断を46%削減**という実配備に到達し、しかもアプリ識別子もウィンドウタイトルも使っていないからである。**しかしFlowLightが当てているものはGSEと違う。**FlowLightに必要なのは「操作量が多い＝忙しい」という単調写像であり、**GSEが必要とする操作量の少ない側（停滞／熟考／離席）の弁別を一度も要求されていない。**ここがGSEの問いの所在である。

## **【技術的な挑戦：沈黙の中身と、日本語IMEの逡巡】**

中心的な難問は、**打鍵が止まっている区間の中身を、本文を一切保存せずに割ること**である。「沈黙を長さで切れば分かれる」という期待は実測で否定されている——**475名の2つの独立文脈**で4帯域を**事前宣言してから**検定した結果は「あらゆる長さのポーズの頻度が成績と負相関する」であり、中間帯域は「気が散っているのか、外部資源を使って助けを求めているのか」と割れたままだった。**これはGSEが最も分けたい2つ（離脱と外部化して解決）そのものである。**代わりに弁別に効いていたのは「**沈黙の直前に何を押したか**」であり、「長さではなく位置を分類する」という方針に初めて実測が付いた。そして**沈黙中に何が起きていたかを本文非保存で同定した研究は依然ゼロである**。**ただし、空白であることは有望であることを意味しない。**

第二の挑戦は日本語である。欧米の研究は「キーを押す→文字が出る」という入力モデルを前提とするが、日本語入力は「ひらがな入力→変換候補→選択→確定」という多段階プロセスであり、この未確定文字列の中に概念レベルの迷いが含まれていると予想する。「しくみ」を確定した後に全削除して「こうぞう」と打ち直し、さらに迷って戻る——これは変換の問題ではなく「どの概念で思考を表現すべきか」の逡巡を示唆する。**到達点**として、Windows版はWinEventによる3層検出、macOS版はキーストローク状態機械による独自手法を実装し、両OSで動作させている。

## **【計測なき身体回帰】**

本提案が新規性として書ける主張の一つが**「計測なき身体回帰」**である。身体活動を促すシステムは例外なく**測ることを前提としてきた**——唯一の統制つき成功例であるUbiFit（Consolvoら 2008）も「測って・抽象で見せて・罰しない」設計であり、**証拠の上では「測る側」の方が強い。**

GSEはそれでも測らない側を選ぶ。Etkin（2016）が6実験で示した「**計測それ自体の害**」は、二値化や表示の抑制では減らないからである。同研究は**歩数計を着けるか自分で選べた群でも害が残り**、「計測が利用可能であるだけ」で楽しさが下がったことを示す。加えて計測反応性の系統的レビューが挙げる増幅機序には「**実際の行動と望ましい行動との乖離を自己調整で解消すること**」が含まれる——**完了条件とは、その「望ましい行動」を系の側が定義する行為そのものである。**したがってGSEは**判定も閾値も置かず、方向づけだけを提示する**。これは「不便を課しながら、その履行を系が検分しない」という、私の知る限り前例のない組み合わせである。**証拠が優ったから選んだのではなく、害とプライバシー境界と概念整合を優先した設計判断である**と明記する。代償も隠さない——「招待が受け入れられたか」の検証が自己申告に依存するため、その一点にだけ本体とは別プロセスの計測器を使う形成的調査で一度だけ答える。

## **【期待される学術的貢献と、主張しないこと】**

**第一に、本文非保存の行動プロキシが主観的な摩擦・前進と個人内で順序一致するかの前向き検証である。**反証可能な確証核を1つだけ明示してある——**方向付き順序C-indexの中央値 ≥ 0.65（全員 > 0.55）でGo、中央値 ≤ 0.55 または2人以上が ≤ 0.50 でKill**。この閾値は**データを見る前に凍結済み**であり、**「認知状態を捉えた」とは書かない。第二に、日本語IMEキーストロークデータセットの公開である**（§2）。ただし「本文を保存していないから安全」で止めない——貼付の文字数やキーのカテゴリ列は作業内容を推測させうるため、**未実装であるセキュア入力欄での記録抑止**を判定対象に明示的に含める。**第三に、守るべき苦闘を壊さないための介入設計の、事前登録された前向き実証例である。**不便益は思想を、生産的失敗と望ましい困難は「守るべき困難の存在」を与えるが、**実作業中にそれをリアルタイム同定して介入する閉ループ**を持たない。GSEの差分は、**(i) 本文を一切保存しない制約下で、(ii) 検出 → 介入機会の分離 → 意図的に不便な方向づけ を1つの動くシステムに閉じ、(iii) 前向きに較正した妥当性ゲートを事前宣言する**、この組合せにある。なおCHI 2026の著者自身が、この検証負荷について「**行動信号を直接監視し、軽量な閾値を超えたら介入せよ**」と提言している——**GSEはその提言の実装である。**

なお本提案が確証するのは連続信号と2軸の妥当性までであり、その上に載る**3クラス分類は後段のサブ応用研究に位置づける**。順序が逆であってはならない——連続信号の妥当性が確証されない限り、その上の離散分類は測定対象を持たない。2026年度提案はこの順序を誤り、分類を主役に据えていた。

**査読者が最初に疑うであろう点を、こちらから先に開示する。**本提案は以下を主張しない。**(1)** キーストロークからの3クラス分類（本フェーズでは行わない）。**(2)** 摩擦が能力・学習を育てること。**(3)** 散歩が認知作業を回復させること（micro-breakのメタ分析（22標本 / 2,335名）は**活力 d = .36 / 疲労 d = .35** を支持する一方、**成績は全体でnull**（d = .16, p = .116）。2026年度提案の「8分間の歩行で発散的思考が60%向上する」は取り下げる）。**(4)** 表現チャネルの効果（常在面それ自体の効能は事前登録された無作為化試験で確証6アウトカムすべてnull）。**(5)** 「ツールが作業を始めさせる」という活性化効果（実行意図の効果量は出版バイアス補正後 d = .15 まで縮んでいる）。**(6)** 母集団妥当性・被験者間一般化。**(7)** 不便益を測定可能にしたこと（合意された測定尺度が存在しない）。

## **【プロトタイプと、較正データ収集の実測】**

「思考の停滞」をリアルタイムに推定するプロトタイプを開発・公開している。Rust（Tauri 2.0）バックエンドで **5特徴量抽出 → ベースライン正規化 → 2軸射影 → HMM推論 → ヒステリシス安定化 → 介入判断** という一気通貫のパイプラインを Windows と macOS の両方で動作させている。改修の過程で一貫しているのは「**セッションログの定量分析 → 問題発見 → 設計変更 → ログ再検証**」というデータ駆動のサイクルである（改修履歴は技術設計書 §4.3）。

**そして本提案の最大の材料は、成功ではなく「判定に届かなかった実測」である。隠さずに書く。**2026年6〜7月、被験者5名・40セッション（本文非保存・介入OFFのブラインド較正）を収集した。測定法ゲートは**通過**（回答率0.926）した一方、モデルゲートは**データ不足**——母数を満たしたのは5名中**1名のみ**——で総合は**判定不能**だった。**これをKillと書かない。**凍結ルールは「人数不足はKillではなくデータ不足として扱う」と事前に定めており、**判定パイプラインが機械的に出した kill を、私はこのルールに照らして差し戻した**。

**原因はHMMでも被験者の不誠実さでもなく、較正プローブの負荷が個人差に対して一律すぎたことだった。**過多側の被験者は11セッション中10で「多すぎた」と回答し、その状態で摩擦の申告を35件中34件同じ値にしたため順序統計量が**数学的に算出不能**になった（**測定器の過負荷が生んだ定数化**である）。一方、過少側の被験者は後半4セッション連続で「少なすぎた」と回答した。**両端で同時に外していたことが、律速が測定設計にあることの最も強い証拠である。**そして**最も痛い所見**は、事前アンケートでAI依存が最も強いと答えた被験者——**GSEが最も狙うべき層**——が回答率0.333で最も早く脱落したことである。肯定的所見として**プライバシー不安は事後アンケート4名全員が「なかった」**と回答したが、最も負荷の高かった被験者が欠測しており**生存者バイアスで上振れしている**。対処として、判定パイプラインの「未実施」と「不合格」を区別し、「**信号が無い**」のか「**計器が無い**」のかをログだけから機械判定できる収集仕様を実装し、次の実験の基準を主観プローブではなく**実験者が与えた条件ラベル**に切り替えた。

## **【未踏へ申し込む理由 —— n=1では届かないと分かったから】**

私はサーヴェイから理論構築、実装、そして他者を被験者とした較正データ収集まで、1年をかけて到達させた。生成AIの登場以降、**調べること・設計すること・実装することは、個人でもおおむね完遂できるようになった**。実際、上に挙げたものはすべて独学と自力の実装で作っている。

**しかし、そこで止まった。**較正は判定を出せずに終わり、その原因は測定設計にあった。痛感したのは、**GSEを個人で実装し、個人で使い、個人で評価している限り、それはn=1の逸話にしかならない**ということである。私に足りないのは実装力ではなく、**何をどう測れば主張が成立するのかという検証の作法**であり、**被験者研究に必要な倫理的配慮の水準**であり、**「止まる」と判断する外部のチェックポイント**である。較正プローブの負荷が一律すぎるという失敗は、文献を読むだけでは事前に予測できなかった。

だからこそ、**第一線でこの領域を歩いてきた方々の助言を仰ぎながら進めることの必然性**を、自分の失敗から知ることができた。具体的には、(1) 測定設計を研究水準まで引き上げること、(2) 被験者研究の倫理と実施条件を設計すること、(3) 事前登録した合否ゲートで、母数が足りないまま自分に都合よくGoと言わないための外部検証を得ること——この3点である。**実装しきる力は示せた。示せていないのは、それを検証しきる力である。**未踏の中間報告とPMとの定期面談は、この欠けている部分を埋める場として理想的に機能すると考えている。

AIネイティブ世代の当事者として、AIへの依存がもたらす知的空洞化を自らの原体験として抱えている。この問題を**測れる形に落とし、測れなかったときに何が原因かまで特定できる段階**まで来た今、未踏の9ヶ月間で2つの学術的成果物（データセット公開とシンポジウム投稿）を確実に持ち帰る覚悟で臨む。
