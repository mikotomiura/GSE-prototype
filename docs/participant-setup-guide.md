# GSE ユーザー検証 参加者ガイド（アプリ導入・ログ提出）

ご参加ありがとうございます。このガイドは **参加者（被験者）向け** に、アプリの導入から
ログ提出までを具体的に説明します。技術的な手順（特に初回起動）は **初回セッションで研究者が
一緒に進めます** ので、分からない箇所は遠慮なくお尋ねください。

> 「ふだんの作業と短い問いの記録」（段 1）に参加される方は、先に §7 をお読みください。
> この研究では §1〜§5 の手順の一部が違います。

> ⚠ 重要: 本アプリは研究用のため正式な署名（Apple/Microsoft の配布証明）を付けていません。
> そのため起動時に OS が警告を出しますが、**マルウェアではありません**。下記の手順で回避できます。

参加にあたって研究者からお渡しするもの:
- **参加者ID（P-ID）**: 例 `P001`。以降のフォーム回答・ログ提出すべてで使います（実名は使いません）。
- **Google Drive リンク**（アプリ一式）: <https://x.gd/6crxj>
- 配布フォルダの中身（OS で違います）:
  - **macOS**: アプリ本体（`.dmg`）**だけ**です。提出に必要なものはアプリの中に入っています。
  - **Windows**: アプリ本体（`gse-next.exe`）/ `gse-submit.exe`（提出ツール本体）/
    **`提出する_win.bat`**（ダブルクリック提出）/ `pubkey.txt`（暗号化用の公開鍵）
    ⚠️ **これらは同じフォルダに置いたまま**にしてください（別々に動かすと提出できません）。

1. Google Drive リンク <https://x.gd/6crxj> を開き、フォルダを **ダウンロード** して展開します。

|---|---|---|

## 2-A. macOS の導入（Apple Silicon）

> ### ⚠️⚠️ ★ G1 統制タスク実験（`experiments/20260801-controlled-friction-task/`）では、この節の**とおりにしない**
>
> ★ G1 は **zip を展開してできたフォルダの中でアプリを動かす**。この節は Phase1 用である。
>
> | | この節（Phase1） | ★ G1 |
> |---|---|---|
> | 置き場所 | 「アプリケーション」フォルダへドラッグ | ⚠️ ★ **展開したフォルダの中に置いたまま**（`g1.mode` と同じ階層）。`/Applications` へ入れると **黙って通常モードで動き、ランダムプローブが復活してそのブロックのデータが使えなくなる** |
> | `xattr -dr …` | 実行する | 実行してよい。★ ただしパスは **`<g1.mode と同じフォルダ>/gse-next.app`** |
> | `codesign --force --deep --sign - …` | 実行する | ⚠️⚠️ ★ **実行しない。** 再署名は CDHash を変え、入力監視の再許可が要るかが**未実測**である |
>
> → G1 の手順は `experiments/20260801-controlled-friction-task/protocol.md §1.1` を正とする。
> ★ 被験者が読む `README_先に読む.txt` には `codesign` を書いていない。

1. `gse-next_..._aarch64.dmg` をダブルクリックし、**`gse-next` を「アプリケーション」フォルダ**へドラッグします。
2. **初回のみ**（研究者と一緒に）、ターミナルで次の2行を実行します:
   ```bash
   xattr -dr com.apple.quarantine /Applications/gse-next.app
   codesign --force --deep --sign - /Applications/gse-next.app
   ```
   > ⚠ `xattr -cr` は使わないでください（すべての属性を消して署名を壊すことがあります）。
3. それでも「**“gse-next” … マルウェアが含まれていないことを検証できませんでした**」と出る場合:
   **システム設定 → プライバシーとセキュリティ** を開き、下の方の
   「“gse-next” は…ブロックされました」→ **「このまま開く」** を押します。
4. **入力監視の許可**（キー入力の計測に必須）:
   **システム設定 → プライバシーとセキュリティ → 入力監視** で **gse-next を ON** にし、
   **アプリを一度終了して再起動**します。

<details>
<summary>許可したのに入力が記録されない場合</summary>

1. 入力監視で gse-next を一度オフ→オンし直し、アプリを再起動する。
2. ターミナルで `tccutil reset ListenEvent` を実行 → もう一度許可 → 再起動。
3. それでもダメなら Mac を再起動する。
</details>

## 2-B. Windows の導入

1. **ポータブル版 `gse-next.exe`** をダブルクリックします（インストール不要・管理者権限不要）。
2. 「**Windows によって PC が保護されました**」（SmartScreen）が出たら →
   **「詳細情報」→「実行」** を押します。
3. もし **Smart App Control (SAC)** にブロックされ「実行」ボタンが出ない場合:
   **設定 → プライバシーとセキュリティ → Windows セキュリティ → アプリとブラウザーの制御 →
   Smart App Control の設定 → オフ** にしてから、もう一度起動します。
   > ⚠ Smart App Control は **一度オフにすると再びオンにできません**（Windows の仕様）。
   > オフにしたくない場合は研究者にご相談ください（署名版の用意を検討します）。

## 3. ふだんの使い方

アプリを起動して、**いつも通り文章作成や思考作業をするだけ**です。特別な操作は要りません。
作業中、セッションのログ（キー入力のタイミングなどの数値データ）が自動で端末に保存されます。

- ログの保存先:
  - macOS: `~/Documents/GSE-sessions/gse_<日時>.ndjson`
  - Windows: `ドキュメント\GSE-sessions\gse_<日時>.ndjson`
- セッション中にアプリ内へ「途中の問い（プローブ）」が出ることがあります。表示に従って答えてください
  （これはフォームではなくアプリ内で完結します）。

### 「今とても詰まっている」ときのワンタップ記録（任意・歓迎）

プローブ（アプリからの問い）を待たずに、**自分が「今とても行き詰まっている」と感じた瞬間**に
その場で記録できます。較正の精度が上がるので、気づいたら気軽に押してください（負担にならない範囲で）。

- **方法 A（ボタン）**: ダッシュボードの **「🔴 今とても詰まっている」** ボタンを押す。
- **方法 B（ショートカット）**: 画面を切り替えずに記録したいときは
  **macOS: `Cmd+Shift+Option+D` ／ Windows: `Ctrl+Shift+Alt+D`**。
- 押すと「✓ 記録しました」と一瞬表示されます。連打は自動でまとめられます（数秒に1回）。
- 記録されるのは「詰まっている感覚」の合図だけです。**打った文字の内容は一切保存されません**。

> これは「正解を当てる」ものではありません。**あなたの主観でかまいません**。
> プローブ（受け身の問い）とこのワンタップ（自発的な記録）の両方が、推定の較正に役立ちます。

## 4. ログの提出（毎セッション）

ログは **匿名化＋暗号化してから** 提出します。元の生ログは送りません。研究者だけが復号できます。

### 方法1: アプリ内の「提出する」ボタン（推奨・いちばん簡単）

**すでに起動を許可した GSE アプリの中から提出できます。** 別アプリの起動が不要なので、
macOS で追加のセキュリティ警告（Gatekeeper のブロック）が出ません。

1. ダッシュボード下部の **「セッションの提出」** で、研究者から指定された **参加者 ID（例 `P006`）** を入力します。
2. **「提出する」** ボタンを押します。最新のセッションが匿名化＋暗号化され、提出ファイル `P006_*.age` が作られます。
   - 生成先: `~/Documents/GSE-submissions/`（Windows: `ドキュメント\GSE-submissions\`）。成功すると保存先が画面に表示されます。
   - 失敗したときは画面に赤い文字でエラーが出ます（静かに失敗しません）。文面を研究者に共有し、もう一度押してください。
3. できた `P006_*.age` を、下記 **Dropbox ファイルリクエスト** に提出します（→ 末尾の提出手順へ）。

### 方法2（フォールバック・**Windows のみ**）: `提出する_win.bat` をダブルクリック

アプリ内ボタンが使えない場合は、配布フォルダの中の **`提出する_win.bat`** をダブルクリックします。

> ★ **macOS には方法2 はありません。** 提出に必要なものはアプリ（`.dmg`）の中に入っているので、
> 方法1 のボタンをお使いください。うまくいかないときは**研究者にご連絡ください**。

- 自動で **最新のセッション**を探し、匿名化＋暗号化して `.age` を作ります。
- 生成先: `~/Documents/GSE-submissions/`（Windows: `ドキュメント\GSE-submissions\`）。
- 黒い画面にファイル名が表示されたら成功です。ウィンドウは閉じてかまいません。

> **Windows で「WindowsによってPCが保護されました」と出る場合（初回のみ）**
> 「詳細情報」→「実行」で一度だけ許可してください（初回セッションで研究者が一緒に行います）。
>
> ★ macOS の隔離属性（quarantine）の解除手順は、**アプリ本体の導入（2-A）**をご覧ください。
> 方法2 は Windows 専用なので、macOS でここの操作は不要です。

### 提出（方法1・方法2 共通）

**Dropbox ファイルリクエスト** <https://x.gd/PHtwA> を開き、できた `P001_*.age` を提出します。

- ⚠ **アップロード時に名前の入力を求められたら、必ず「あなたの P-ID（例 P001）」を入力してください。
  実名は入れないでください。** （Dropbox はアップロードした人の名前をファイル名に付けることがあり、
  実名を入れると提出ファイル名に実名が残ってしまいます。中身は匿名化済みですが、ファイル名から
  実名が分からないようにするためのお願いです。）
- 提出した人どうしはお互いのファイルを見られません。中身は研究者だけが開けます。

- 💡 **セッションID**（F4 アンケートで入力）は、提出ファイル名 `P001_gse_◯◯◯.age` の
  **`◯◯◯`（日時）部分**です（例 `P001_gse_20260302_075721.age` なら `20260302_075721`）。

<details>
<summary>うまくいかないとき</summary>

方法1（アプリ内ボタン）と、Windows の方法2（`提出する_win.bat`）の**どちらもだめな場合は、
研究者にご連絡ください。** エラー画面の文面をそのままお知らせいただけると助かります。

★ 以前は手動の `gse-package` コマンドをご案内していましたが、**配布をやめました**
（Phase1 で誰も使わずに完了したため）。ご自身でコマンドを打つ必要はありません。
</details>

## 6. よくある質問・プライバシー

- **Q. 起動時の警告は大丈夫?** → はい。研究用の未署名ビルドのための警告で、マルウェアではありません
  （§2-A / §2-B の手順で回避できます）。
- **Q. 文章の中身は記録されますか?** → **いいえ**。記録されるのはキー入力の**タイミングや種類**の数値
  だけで、打った**文字の内容は保存されません**。
- **実名は使いません**。氏名・メールは匿名の参加者ID（P-ID）で管理され、対応表は研究者のみが保持します。
- **いつでも撤回・削除できます**。参加は任意で、撤回しても不利益はありません。研究者にご連絡ください。
- ご不明点は、研究者からの案内メールにご返信ください。

> 個人情報の詳しい取り扱いは、参加時の同意フォーム（F1）に記載のとおりです。

## 7. 「ふだんの作業と短い問いの記録」（段 1）に参加される方へ

この節は、段 1 の説明・同意フォーム（`Form_O1/GSE_O1_Form_Builder.gs` の `buildS1ConsentForm`。
文面の上流は `.steering/20261114-gse-stage1-n3-consent/consent-draft-s1.md`）に同意された方のためのものです。
説明と約束はフォームに書いたとおりで、この節はその要点と、§1〜§6 との違いだけを書きます。

- **アプリの入手**: §1 のリンクではなく、同意フォームを送った後に届く受付メールの入手先を使います。
  導入の手順は、配布フォルダの説明書に書いてあります。フォルダの中のファイルは消したり動かしたりしないでください。
- **ログの提出（§4）とアンケート（§5）は要りません**。記録は 1 日ごとにまとめられ、48 時間おいてから
  暗号化して自動で研究者へ送られます。送られる前なら、端末の上で時間帯を指定して消せます。
- **自動で起動します**。パソコンにログインしたときにアプリが起動するよう設定されます（設定でいつでも切れます）。
- **短い問い**: 作業中にときどき画面のすみにカードが出ます（1 時間に多くても 9 回）。答えなくてかまいません。
  1 日の終わりにも 1 つ問いが出ます。
- **後半の画面の表示**: 後半の期間には、日によって画面の背景と下の縁に線の表示が出ます。アプリのアイコンのメニューの
  「やめる」でその日のあいだ消せ、「描く」で戻せます。
- **止める・消す**: ワンクリックで一時停止できます（一時停止中は問いが出ません）。あとから時間帯を指定して消せます。
  送られたあとの削除は研究者にお申し出ください。
- **やめる**: アプリの画面で「問いへの同意を取り消す」を押すと、参加をやめたことになります。そのあとはアプリを終了し、
  研究者にお知らせください。それまでの記録の削除もお求めいただけます。
- **期間**: 長くても 8 週間です。始める日と終わる日は研究者からお知らせします。謝礼はありません。
