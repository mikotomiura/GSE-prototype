# GSE ユーザー検証 参加者ガイド（アプリ導入・ログ提出）

ご参加ありがとうございます。このガイドは **参加者（被験者）向け** に、アプリの導入から
ログ提出までを具体的に説明します。技術的な手順（特に初回起動）は **初回セッションで研究者が
一緒に進めます** ので、分からない箇所は遠慮なくお尋ねください。

> ⚠ 重要: 本アプリは研究用のため正式な署名（Apple/Microsoft の配布証明）を付けていません。
> そのため起動時に OS が警告を出しますが、**マルウェアではありません**。下記の手順で回避できます。

参加にあたって研究者からお渡しするもの:
- **参加者ID（P-ID）**: 例 `P001`。以降のフォーム回答・ログ提出すべてで使います（実名は使いません）。
- **Google Drive リンク**（アプリ一式）: <https://x.gd/6crxj>
- 配布フォルダの中身: アプリ本体 / **`提出する`ランチャ**（ダブルクリック提出）/ `gse-submit`（提出ツール本体）/
  `pubkey.txt`（暗号化用の公開鍵）／ `gse-package`（上級者向けの手動版・通常は使いません）

---

## 1. アプリ一式の入手

1. Google Drive リンク <https://x.gd/6crxj> を開き、フォルダを **ダウンロード** して展開します。
2. お使いの OS の章へ進んでください（→ 2-A macOS / 2-B Windows）。

| OS | アプリ本体 | 同梱ツール |
|---|---|---|
| macOS（Apple Silicon） | `gse-next_..._aarch64.dmg` | `提出する_mac.command`、`gse-submit`、`pubkey.txt`（＋手動版 `gse-package`） |
| Windows | `gse-next.exe`（インストール不要のポータブル版） | `提出する_win.bat`、`gse-submit.exe`、`pubkey.txt`（＋手動版 `gse-package.exe`） |

## 2-A. macOS の導入（Apple Silicon）

1. `gse-next_..._aarch64.dmg` をダブルクリックし、**`gse-next` を「アプリケーション」フォルダ**へドラッグします。
2. **初回のみ**（研究者と一緒に）、ターミナルで次の2行を実行します:
   ```bash
   xattr -dr com.apple.quarantine /Applications/gse-next.app
   codesign --force --deep --sign - /Applications/gse-next.app
   ```
   > ⚠ `xattr -cr` は使わないでください（すべての属性を消して署名を壊すことがあります）。
3. それでも「**“gse-next” … マルウェアが含まれていないことを検証できませんでした**」と出る場合:
   **システム設定 → プライバシーとセキュリティ** を開き、下の方の
   「“gse-next” は…ブロックされました」→ **「このまま開く」** を押します。
4. **入力監視の許可**（キー入力の計測に必須）:
   **システム設定 → プライバシーとセキュリティ → 入力監視** で **gse-next を ON** にし、
   **アプリを一度終了して再起動**します。

<details>
<summary>許可したのに入力が記録されない場合</summary>

1. 入力監視で gse-next を一度オフ→オンし直し、アプリを再起動する。
2. ターミナルで `tccutil reset ListenEvent` を実行 → もう一度許可 → 再起動。
3. それでもダメなら Mac を再起動する。
</details>

## 2-B. Windows の導入

1. **ポータブル版 `gse-next.exe`** をダブルクリックします（インストール不要・管理者権限不要）。
2. 「**Windows によって PC が保護されました**」（SmartScreen）が出たら →
   **「詳細情報」→「実行」** を押します。
3. もし **Smart App Control (SAC)** にブロックされ「実行」ボタンが出ない場合:
   **設定 → プライバシーとセキュリティ → Windows セキュリティ → アプリとブラウザーの制御 →
   Smart App Control の設定 → オフ** にしてから、もう一度起動します。
   > ⚠ Smart App Control は **一度オフにすると再びオンにできません**（Windows の仕様）。
   > オフにしたくない場合は研究者にご相談ください（署名版の用意を検討します）。

## 3. ふだんの使い方

アプリを起動して、**いつも通り文章作成や思考作業をするだけ**です。特別な操作は要りません。
作業中、セッションのログ（キー入力のタイミングなどの数値データ）が自動で端末に保存されます。

- ログの保存先:
  - macOS: `~/Documents/GSE-sessions/gse_<日時>.ndjson`
  - Windows: `ドキュメント\GSE-sessions\gse_<日時>.ndjson`
- セッション中にアプリ内へ「途中の問い（プローブ）」が出ることがあります。表示に従って答えてください
  （これはフォームではなくアプリ内で完結します）。

### 「今とても詰まっている」ときのワンタップ記録（任意・歓迎）

プローブ（アプリからの問い）を待たずに、**自分が「今とても行き詰まっている」と感じた瞬間**に
その場で記録できます。較正の精度が上がるので、気づいたら気軽に押してください（負担にならない範囲で）。

- **方法 A（ボタン）**: ダッシュボードの **「🔴 今とても詰まっている」** ボタンを押す。
- **方法 B（ショートカット）**: 画面を切り替えずに記録したいときは
  **macOS: `Cmd+Shift+Option+D` ／ Windows: `Ctrl+Shift+Alt+D`**。
- 押すと「✓ 記録しました」と一瞬表示されます。連打は自動でまとめられます（数秒に1回）。
- 記録されるのは「詰まっている感覚」の合図だけです。**打った文字の内容は一切保存されません**。

> これは「正解を当てる」ものではありません。**あなたの主観でかまいません**。
> プローブ（受け身の問い）とこのワンタップ（自発的な記録）の両方が、推定の較正に役立ちます。

## 4. ログの提出（毎セッション）

ログは **匿名化＋暗号化してから** 提出します。元の生ログは送りません。研究者だけが復号できます。

### 手順（ダブルクリックするだけ・推奨）

1. 配布フォルダの中の **`提出する`** をダブルクリックします
   （macOS: `提出する_mac.command` ／ Windows: `提出する_win.bat`）。
   - 自動で **最新のセッション**を探し、匿名化＋暗号化して `P001_*.age` を作ります
     （P-ID もアプリが記録した値を自動で使うので、入力は不要です）。
   - 生成先: `~/Documents/GSE-submissions/`（Windows: `ドキュメント\GSE-submissions\`）。
   - 黒い画面にファイル名が表示されたら成功です。ウィンドウは閉じてかまいません。
   > 初回はセキュリティ警告が出ることがあります。macOS は右クリック→「開く」、Windows は
   > 「詳細情報」→「実行」で一度だけ許可してください（初回セッションで研究者が一緒に行います）。

2. **Dropbox ファイルリクエスト** <https://x.gd/PHtwA> を開き、できた `P001_*.age` を提出します。
   - ⚠ **アップロード時に名前の入力を求められたら、必ず「あなたの P-ID（例 P001）」を入力してください。
     実名は入れないでください。** （Dropbox はアップロードした人の名前をファイル名に付けることがあり、
     実名を入れると提出ファイル名に実名が残ってしまいます。中身は匿名化済みですが、ファイル名から
     実名が分からないようにするためのお願いです。）
   - 提出した人どうしはお互いのファイルを見られません。中身は研究者だけが開けます。

- 💡 **セッションID**（F4 アンケートで入力）は、提出ファイル名 `P001_gse_◯◯◯.age` の
  **`◯◯◯`（日時）部分**です（例 `P001_gse_20260302_075721.age` なら `20260302_075721`）。

<details>
<summary>うまくいかないとき / 上級者向け（手動の gse-package）</summary>

ダブルクリックでエラーが出る場合は、ターミナル（macOS）／コマンドプロンプト（Windows）で
`gse-package` と `pubkey.txt` のあるフォルダに移動し、次を実行します（`P001` は自分の P-ID）:

**macOS:**
```bash
./gse-package --input ~/Documents/GSE-sessions/gse_<日時>.ndjson --participant P001 --recipient pubkey.txt
```
**Windows:**
```bat
gse-package.exe --input "%USERPROFILE%\Documents\GSE-sessions\gse_<日時>.ndjson" --participant P001 --recipient pubkey.txt
```
→ `P001_*.age` ができます。提出方法（手順 2）は同じです。
</details>

## 6. よくある質問・プライバシー

- **Q. 起動時の警告は大丈夫?** → はい。研究用の未署名ビルドのための警告で、マルウェアではありません
  （§2-A / §2-B の手順で回避できます）。
- **Q. 文章の中身は記録されますか?** → **いいえ**。記録されるのはキー入力の**タイミングや種類**の数値
  だけで、打った**文字の内容は保存されません**。
- **実名は使いません**。氏名・メールは匿名の参加者ID（P-ID）で管理され、対応表は研究者のみが保持します。
- **いつでも撤回・削除できます**。参加は任意で、撤回しても不利益はありません。研究者にご連絡ください。
- ご不明点は、研究者からの案内メールにご返信ください。

> 個人情報の詳しい取り扱いは、参加時の同意フォーム（F1）に記載のとおりです。
