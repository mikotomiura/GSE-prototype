## §0 何のための台帳か

第 20 版は人単位の数え方（**登録 k・解析 m**）と、「やめた」「削除の求め」「未実施」の扱いを固定したが、
**その内訳は公表しない**（n=3 では人数の公表が個人を指す）ので、**研究者手元の台帳にだけ**残す。
O1 受領台帳（`Form_O1/GSE_O1_Ledger.gs`）は「**届いたか**」だけを言い、**人の状態は言えない**。
→ 本台帳が**人の状態**（G1・O1 それぞれの進み具合）を持つ。手入力が主。

## §1 一次で確かめた・絶対に落とせない制約

| # | 制約 |
|---|---|
| 1 | **「やめた」は本人の申し出で確定する**。時刻と**文言**を記録し、**理由は聞かない**（第 20 版 語の表 / `ADR-034 D4-2c`）。技術的な中断・連絡の途絶・研究者の推測では「やめた」としない |
| 2 | **「中断」と「やめた」は別**。曖昧な発言は「中断」。取り消しは**申し出から連続した同一セッションの内に限る** |

| 5 | **O1 と G1 の記録は結合しない**（`ADR-034 D4-6 / D4-7`） |

## §2 設計

### §2.1 置き場と閲覧

- **別のスプレッドシート**（Phase1 のロスター・O1 管理シートのどちらとも別）。
- ★ **研究者のみ閲覧・共有しない**。
- ⚠️ **氏名・メール・連絡先の列を持たない**（P-ID のみ。連絡先は既存のロスターにある）。
- ⚠️★★★ **シートの ID・URL を repo に置かない**（本文書にも書かない）。

### §2.2 タブ 1「状態ログ」（追記のみ・行は消さない・訂正は行を足す）

O1 削除台帳（`docs/o1-deletion-ledger.md`）と同じ流儀 — 状態セルを直接書き換えると
「いつ・何を根拠に」変えたかが残らない。→ **イベントを 1 行ずつ追記**し、現在の状態は導出する。

| 列 | 内容 | 入力規則 |
|---|---|---|
| A: 記録日時 | 入力した日時 | 手入力 |
| B: P-ID | `P<数字>` | 形式（正規表現） |
| C: 研究 | `G1` / `O1` | 2 択 |
| D: 出来事 | 下記 11 種のいずれか | **限定リスト**（自由記入なし） |
| E: 出来事の日時 | 出来事が起きた日時（記録日時と別） | 日時 |
| F: 根拠 | 本人の申し出 / 実施記録 / 連絡 / 受領台帳（参考） | 限定リスト |
| G: 申し出の文言 | 「やめた（申し出）」「削除の求め」のとき**逐語**（⚠️ 理由は聞かない・書かない） | 出来事が上記 2 つのときだけ必須 |

★ **出来事の限定リスト（11 種・自由記入禁止）**:

1. 案内
2. 登録
3. 配布
4. 開始
5. 中断
6. やめた（申し出） — ⚠️ 文言が必須（§2.4 で赤検知）
7. 取り消し — 「やめた」の申し出を撤回する。**申し出から連続した同一セッションの内に限る**
8. 削除の求め — ⚠️ 文言が必須。「やめた」とは別の申し出（制約 3）
9. 完了 — G1 は 8 ブロック（HI4/LO4）を全て実施したとき
10. 未実施のまま据え置き — 研究者が期限を決めず様子見にしたとき
11. 名簿から外した — **根拠**列に「結果を見る前に・条件や成績と無関係に決めた」旨の自己申告を書く（機械可読な版は `config.json` の `recruitment_closed.decided_before_seeing_results`。issue 002 参照）

### §2.3 タブ 2「現在の状態」（導出・数式のみ・スクリプトなし）

★ 関数は **INDEX / MATCH / ARRAYFORMULA** の組み合わせに統一する（`SORT`/`FILTER`/`QUERY` は使わない。
「適宜」にしない）。以下は (P-ID, 研究) ごとに 1 行のテンプレートで、`状態ログ` シートの A:G を参照する。

| 列 | 内容 | 数式（A2 が最初のデータ行） |
|---|---|---|
| A/B: P-ID・研究（ユニーク） | 状態ログに出てくる (P-ID, 研究) の組の一覧 | 下記コード参照 |
| C: 最新の記録日時 | その (P-ID,研究) の記録日時の最大値 | 下記コード参照 |
| D: 最新の出来事 | C 列の記録日時に対応する出来事 | 下記コード参照 |
| E: 出来事の日時 | 最新行の出来事の日時 | 下記コード参照 |
| F: 開始済みか | 「開始」または「完了」の行が 1 件でもあれば TRUE | 下記コード参照 |
| G: 完了か | 「完了」の行が 1 件でもあれば TRUE | 下記コード参照 |
| H: 未実施の経過日数（表示のみ） | F が FALSE のとき、直近の「配布」からの経過日数。**判定はしない・表示のみ** | 下記コード参照 |
| I: 削除の求めの注記 | §2.4-4 の誘導文 | 下記コード参照 |

A2（(P-ID, 研究) のユニーク一覧。B 列に自動でスピルする）:

```
=UNIQUE(FILTER({状態ログ!$B$2:$B, 状態ログ!$C$2:$C}, 状態ログ!$B$2:$B<>""))
```

C2（最新の記録日時）:

```
=MAXIFS(状態ログ!$A$2:$A, 状態ログ!$B$2:$B, $A2, 状態ログ!$C$2:$C, $B2)
```

D2（最新の出来事）:

```
=ARRAYFORMULA(INDEX(状態ログ!$D$2:$D, MATCH(1, (状態ログ!$B$2:$B=$A2)*(状態ログ!$C$2:$C=$B2)*(状態ログ!$A$2:$A=$C2), 0)))
```

E2（最新行の出来事の日時）:

```
=ARRAYFORMULA(INDEX(状態ログ!$E$2:$E, MATCH(1, (状態ログ!$B$2:$B=$A2)*(状態ログ!$C$2:$C=$B2)*(状態ログ!$A$2:$A=$C2), 0)))
```

F2（開始済みか）:

```
=OR(COUNTIFS(状態ログ!$B$2:$B,$A2,状態ログ!$C$2:$C,$B2,状態ログ!$D$2:$D,"開始")>0, COUNTIFS(状態ログ!$B$2:$B,$A2,状態ログ!$C$2:$C,$B2,状態ログ!$D$2:$D,"完了")>0)
```

G2（完了か）:

```
=COUNTIFS(状態ログ!$B$2:$B,$A2,状態ログ!$C$2:$C,$B2,状態ログ!$D$2:$D,"完了")>0
```

H2（未実施の経過日数・★ 表示のみ・判定はしない）:

```
=IF($F2=FALSE, IFERROR(TODAY()-ARRAYFORMULA(INDEX(状態ログ!$E$2:$E, MATCH(1,(状態ログ!$B$2:$B=$A2)*(状態ログ!$C$2:$C=$B2)*(状態ログ!$D$2:$D="配布"),0))), ""), "")
```

I2（削除の求めの注記・§2.4-4）:

```
=IF(COUNTIFS(状態ログ!$B$2:$B,$A2,状態ログ!$C$2:$C,$B2,状態ログ!$D$2:$D,"削除の求め")>0, IF($B2="O1", "→ docs/o1-deletion-ledger.md の手順へ", "→ G1 の記録破棄手順（未整備・前提条件 8）へ"), "")
```

### §2.4 タブ 3「数える」（公表用の 2 数だけ）

⚠️ **内訳を出す欄を作らない。** 次の 2 セルだけを持つ。

登録 k（G1 に登録した人数）:

```
=COUNTA(UNIQUE(FILTER(状態ログ!$B$2:$B, (状態ログ!$C$2:$C="G1")*(状態ログ!$D$2:$D="登録"))))
```

解析 m（G1 を完了した人数）:

```
=COUNTA(UNIQUE(FILTER(状態ログ!$B$2:$B, (状態ログ!$C$2:$C="G1")*(状態ログ!$D$2:$D="完了"))))
```

### §2.5 矛盾検知 4 件（条件付き書式・条件式の逐語）

★ すべて「状態ログ」シートの `A2:G` を対象範囲にした**カスタム数式**の条件付き書式ルールとして設定する
（先頭行 = 2 行目を基準に書き、範囲全体へ相対参照で適用される）。

1. **D4-2b 違反** → **赤**: 同じ P-ID で **O1 の「開始」が G1 の「案内/登録」より前**（G1 の記録が
   まだ無い場合も違反として扱う。O1 に先に参加した人を G1 に入れない・制約 4）。

```
=AND($D2="開始", $C2="O1", $E2 < MIN(IFERROR(MINIFS($E$2:$E,$B$2:$B,$B2,$C$2:$C,"G1",$D$2:$D,"案内"),9^9), IFERROR(MINIFS($E$2:$E,$B$2:$B,$B2,$C$2:$C,"G1",$D$2:$D,"登録"),9^9)))
```

2. **D4-2 違反** → **黄**: 同じ P-ID で G1 が「完了」でも「やめた（申し出）」でもないのに
   O1 の「案内」がある（G1 を先に完了する）。

```
=AND($D2="案内", $C2="O1", COUNTIFS($B$2:$B,$B2,$C$2:$C,"G1",$D$2:$D,"完了")=0, COUNTIFS($B$2:$B,$B2,$C$2:$C,"G1",$D$2:$D,"やめた（申し出）")=0)
```

3. **D4-2c** → **赤**: 「やめた（申し出）」の行に**文言（G 列）が空**。
   ⚠️ 「取り消し」は自動判定せず、申し出との**時刻差を表示するだけ**（判断は人）。

```
=AND($D2="やめた（申し出）", $G2="")
```

時刻差の表示（「取り消し」の行に併記する参考セル。判定はしない）:

```
=IF($D2="取り消し", $E2-IFERROR(MAXIFS(状態ログ!$E$2:$E,状態ログ!$B$2:$B,$B2,状態ログ!$C$2:$C,$C2,状態ログ!$D$2:$D,"やめた（申し出）",状態ログ!$E$2:$E,"<="&$E2),""), "")
```

4. **削除の求め** → 誘導する注記（色ではなく §2.3 の I 列の文字列で出す。⚠️ 破棄の実体は本台帳の仕事ではない）:
   「削除の求め」の行があれば、O1 は `docs/o1-deletion-ledger.md`、G1 は「G1 の記録破棄手順（未整備・前提条件 8）」へ誘導する
   （§2.3 の I2 の数式のとおり）。

### §2.6 O1 参考列（手で写す・状態には影響させない）

- O1 の「最終受領日・受領本数」は「状態ログ」とは別の**参考タブ**（または現在の状態タブの参考列）に
  **手で書き写す**（結合ゼロ・`IMPORTRANGE` は不採用・2026-09-27 研究者裁定）。
- ⚠️ **「途絶」「未受領」を「やめた」に自動変換しない**（制約 1・D4-2b。取り違えると不可逆）。
- 参考列は表示のみで、§2.5 の矛盾検知にも §2.3 の導出にも一切使わない。

### §2.7 やらないこと

- 自動遷移（途絶・未受領からの自動変換を含む）、メール送信、被験者への連絡。
- **氏名・メール・理由の記録**。「未完了」「やめた」等のラベルを `results/` に置くこと。
- G1 と O1 のデータの**結合**・対にした集計。
- GAS / Apps Script の追加（本設計は**スクリプトなし**）。

## §3 引き渡し前に研究者と行う確認手順（⚠️★★★ 本タスクでは未実施）

⚠️ **本文書の作成時点で、この手順は実行していない。**（`verify-before-claiming` 5b の型。
実物のシート作成と赤・黄・緑の実測は別タスク・要研究者同席。）

引き渡し前に、以下の**ダミー P-ID**（実在しない番号帯）で 3 状態を実際に出して確認する:

1. `P900` / `研究=G1` / `出来事=案内`、`P900` / `研究=O1` / `出来事=開始`
   （G1 案内より O1 開始が後）→ 「状態ログ」の O1 開始行の書式が**赤**にならないこと（正常系）。
2. `P901` / `研究=O1` / `出来事=開始` のみ（G1 の行が無い）→ O1 開始行が**赤**になること
   （D4-2b 違反の陽性対照）。
3. `P901` / `研究=O1` / `出来事=案内`（G1 が完了でもやめてもいない）→ その案内行が**黄**になること
   （D4-2 違反の陽性対照）。
4. `P902` / `研究=G1` / `出来事=やめた（申し出）` / 文言列を空のまま保存 → その行が**赤**になること
   （D4-2c の陽性対照）。
5. 上記 1〜4 の**赤・黄**を確認したら、違反を起こさない行（例: `P902` の同じ行に文言を入れる）に直し、
   書式が**緑**（＝赤でも黄でもない通常の状態）に戻ることを確認する。
6. 確認が終わったらダミー行（`P900`〜`P902`）を**すべて削除**し、実 P-ID の入力に進む。
