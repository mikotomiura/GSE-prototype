# **0\. この草案の使い方**

本書は Google Form にそのまま転記できる設問テキストを、設計企画書の制約に整合する形でまとめたものである。

前提となる設計上の制約は以下の3点。各フォームはこの制約を破らないよう設計している。

* **データ分離：**氏名・メール・同意情報（Form 側）と NDJSON ログ（Dropbox 側）は participant\_id でのみ結合する。Form 内ではログ本体を一切扱わない。

* **本文非保存：**Form の設問は主観申告（Q1 摩擦 / Q2 前進、自己効力感、UX）のみを扱い、執筆本文やプロンプト内容を書かせない。

* **blind 較正：**Phase 1 較正中は MhD の推定（Flow/Incubation/Stuck）を被験者に見せない。Form でも『システムが何と判定したか』を問わない。

*※ Google Form は「セクション分岐」「回答の検証（数値範囲）」「必須項目」をサポートする。各設問の type 欄はそれを前提に記載している。*

**作成するフォーム一覧**

| \# | フォーム名 | 使用フェーズ | 目的 | 頻度 |
| ----- | ----- | ----- | ----- | ----- |
| F1 | 参加同意・スクリーニング | Phase 0/1 入口 | 同意取得・適格性・participant\_id 発番 | 1回 |
| F2 | 事前アンケート（ベースライン） | Phase 0/1 開始時 | 属性・自己効力感ベースライン・AI利用習慣 | 1回 |
| F3 | プローブ申告（Q1/Q2） | Phase 1b 中核 | criterion label（摩擦・前進）取得 | プローブ毎 |
| F4 | セッション後アンケート | 各セッション末 | UX・負担・IME不具合・提出確認 | セッション毎 |
| F5 | 事後アンケート | Phase 1 終了時 | 自己効力感の事後測定・総括 | 1回 |

*※ F3 はアプリ内の**リアルタイム・ランダムプローブ**（blind・波形 cue なし）の Form 版フォールバックである。波形リプレイによる手がかり再生（cued recall）は Phase 1 では用いない。confound-free なラベルは「波形を見ずに、その場で付ける」ことが要件であり（retro-labeling 決定 D-2/D-9：波形を見せると被験者が波形を読んで逆算する循環論法に陥る）、波形 cue 条件は Phase 4 以降へ延期済み（D-12）。Form 版は予備・低負担運用・在宅セッション用として用意する。*

# **F1. 参加同意・スクリーニングフォーム**

## **フォーム冒頭の説明文（そのまま貼り付け可）**

GSE ユーザー検証へのご協力ありがとうございます。本研究は、執筆・思考作業中の操作ログ（キー入力の打鍵リズム、変換イベント、貼り付け回数など）と、ご自身の主観的な『詰まり感』『前進感』の対応を調べるものです。

* **記録するもの：**打鍵のタイミング・間隔、日本語入力の変換／確定イベント、貼り付けの回数と文字数、操作の種類。

* **記録しないもの：**入力した本文そのもの、クリップボードの中身、開いているウィンドウのタイトル。これらは一切保存されません。

* **データの扱い：**お名前・メールアドレスは、ログとは別に保管され、匿名の participant\_id でのみ結びつけられます。対応表は共有されません。

* **撤回：**いつでも理由を告げずに参加を撤回でき、提出済みデータの削除を求められます。

*未成年が参加する場合は、別途保護者同意の取得を本フォームの前段に置く（後述 F1-補）。*

## **設問**

| \# | 設問文 | type | 選択肢 / 検証 | 必須 |
| ----- | ----- | ----- | ----- | ----- |
| 1 | 上記の説明を読み、内容を理解しました。 | チェックボックス | 「説明を理解した」 | 必須 |
| 2 | 操作ログ（本文を除く）の記録と研究利用に同意します。 | チェックボックス | 「同意する」 | 必須 |
| 3 | 年齢を教えてください。 | ラジオ | 18歳以上 / 18歳未満 | 必須 |
| 4 | （18歳未満の場合）保護者同意フォームを提出済みですか。 | ラジオ | 提出済み / 未提出（→ 分岐で終了） | 条件付き |
| 5 | 普段、文章作成や思考作業に PC を週どのくらい使いますか。 | ラジオ | ほぼ毎日 / 週数回 / 週1回以下 | 必須 |
| 6 | 日本語入力（IME）で文章を書きますか。 | ラジオ | はい / いいえ（→ 適格外） | 必須 |

| 9 | 氏名またはニックネーム（対応表用）。 | 短文 | — | 必須 |

### **分岐・自動処理**

* 設問4で『未提出』→ 終了セクションへ分岐し、保護者同意の案内を表示。

* 設問6『いいえ』・設問7『その他』→ 適格外セクションへ分岐。

* participant\_id は Form では発番せず、研究者がローカルツール（auto P-ID 割当）で採番し、対応表（氏名↔P-ID）を別ファイルで管理する。

*Google Form の回答に participant\_id を後から紐づけるため、回答受領後に研究者が手動で P-ID を対応表へ記入する運用を推奨。Form 内で P-ID を自己申告させると分離が崩れるため避ける。*

# **F2. 事前アンケート（ベースライン）**

Phase 1 開始前に1回。自己効力感は『事後との比較』のため、ここでベースラインを取る。設計企画書どおり、一般性自己効力感は副指標、task-specific self-efficacy を主観の主指標として併用する。

**F2-A. 属性・AI 利用習慣**

| \# | 設問文 | type | 選択肢 |
| ----- | ----- | ----- | ----- |
| 1 | 主に行う作業の種類（複数選択可）。 | チェックボックス | 論述/レポート/企画/創作/コーディング/その他 |
| 2 | 詰まったとき、AI（ChatGPT 等）にどのくらい頼りますか。 | ラジオ | ほぼ毎回 / 時々 / まれ / 使わない |
| 3 | 1週間に AI 生成物をコピペする頻度。 | ラジオ | 1日複数回 / 1日1回 / 週数回 / ほぼ無し |

**F2-B. 一般性自己効力感（GSE-10：Schwarzer & Jerusalem 1995, 副指標）**

*※ 略称注意：ここでの「GSE」は本システム GSE ではなく Schwarzer の Generalized **S**elf-**E**fficacy 尺度（参考文献[15]、decisions D3）。和文略称「GSES」は坂野・東條(1986)=16項目2件法 を指すことが多いため、本書では用いず GSE-10 と表記する。*

*教示文：以下のそれぞれの質問について、あなたはどの程度自信がありますか？*

**回答尺度（全項目共通）：1 全く当てはまらない／2 当てはまらない／3 まあ当てはまる／4 全くその通り（4件法）**

* （GSE-10 公式日本語版の項目文・アンカーを逐語で使用。出典：Ito, K., Schwarzer, R., & Jerusalem, M. (2005) Japanese Adaptation of the General Self-Efficacy Scale（Schwarzer 公式配布ページ）。利用条件は公式ページで要確認）

*※ 本草案では尺度本文を再掲しない。GAS（GSE_Phase1_Form_Builder.gs）に公式日本語版10項目を逐語投入済み（2026-06-24, #B）。⚠ 運用前に公式ページで逐語一致を目視最終確認すること（WebFetch 経由取得のため）。pre(F2-B)/post(F5) は完全同一。Google Forms の ScaleItem は両端ラベルのみ表示のため中間2/3アンカーは教示文に明記。*

**F2-C. 作業再開感・自己調整感（self-regulation, 主観主指標）**

*※ 旧称「課題特異的自己効力感」。検証済み尺度ではなく GSE 用の自作（bespoke）尺度のため、過剰主張を避け「自己効力感」と呼ばず作業再開・自己調整感とする（codex-consult 助言）。**項目最終化済（2026-06-24, #D / FD9・ユーザー承認）**: 旧4項目の「AIに頼らず／自力で」方向偏重を是正し、効力感(正)・逆転・行動信念・選好を1項目ずつ混在させた4項目へ改訂。*

*教示文：執筆・思考作業について、今のあなたにどの程度あてはまりますか。*

**回答尺度（全項目共通）：1 全くそう思わない／2 あまりそう思わない／3 ややそう思う／4 強くそう思う（4件法・強制選択）** ※中心化傾向回避のため 5→4 件法に変更（FD10, 2026-06-25）。両端ラベルのみフォーム表示、中間は教示文。

| \# | facet | 項目文 | 採点 |
| ----- | ----- | ----- | ----- |
| 1 | 効力感(正) | 詰まっても、自分なりの糸口を見つけて書き進められると思う | 順 |
| 2 | 逆転(行動傾向) | 難しい場面になると、自分で考えるより先に AI に答えを求めてしまう | **逆転 (5−x)** |
| 3 | 行動信念(正) | いったん自分で考えてから AI を使う方が、最終的に良い文章になると思う | 順 |
| 4 | 選好(正) | 詰まったときは、すぐ答えを見るより、自分で糸口を探す時間をとりたい | 順 |

*採点法（プレレジ FD9 / 件法は FD10 で改訂）：項目2を逆転再コード（**5−回答値**）後、4項目の平均を合成スコア（範囲 1.0–4.0）とする。Cronbach α は報告のみ（基準 α=.70 を参照値とし Go/Kill 判定には用いない）。主仮説は pre→post の合成スコア変化の**記述的観察**（単群・対照なし(FD1)のため因果主張しない）。*

*pre/post の変化量を出すため、事後でも項目1–4を同一に再測定する（matched, byte 一致）。『GSE の介入は自分で考える感覚を取り戻す助けになった』等の介入体験項目は SE スコアと別構成概念なので F5 で分離して追加する（F5 参照）。*

# **F3. プローブ申告フォーム（Q1 摩擦 / Q2 前進）**

Phase 1b の中核。ランダム時点プローブごとに申告する。設計企画書の『申告直前30秒の時間隔離』『blind』『2軸（摩擦・前進）5段階』に対応。

**重要：このフォームでは『今この瞬間／直前の作業』について聞き、システムが何と判定したかは一切示さない（blind 維持）。**

## **教示文（冒頭）**

直前の作業を振り返って、2つの軸でお答えください。正解・不正解はありません。直感で構いません。

## **設問**

| \# | 設問文（Q軸） | type | 尺度（5段階アンカー） | 必須 |
| ----- | ----- | ----- | ----- | ----- |
| Q1 | 直前の作業は、どのくらい『詰まって』いましたか（摩擦）。 | 線形尺度 1–5 | 1 まったく詰まっていない / 3 どちらとも / 5 強く詰まっていた | 必須 |
| Q2 | 直前の作業は、どのくらい『前に進んだ』感覚でしたか（前進）。 | 線形尺度 1–5 | 1 まったく進まなかった / 3 どちらとも / 5 はっきり前進した | 必須 |
| Q3 | （任意）今この介入候補で、もし通知が出ていたら受け取れる状態でしたか。 | ラジオ | 受け取れた / 邪魔だった / どちらでもない | 任意 |

### **運用上の注意**

* 応答時間を測るため、プローブ提示時刻と送信時刻を記録する（PreReg GATE2：中央値 ≤10s）。Form 単体では応答時間が取りにくいため、エディタ内 UI と併用する場合は Form を予備に回す。

* probe\_valid（30秒隔離成立・申告完了）の判定はログ側で行い、Form 回答とは participant\_id \+ probe\_id で突合する。

* Q3 は Opportunity 層（X2）の探索用。Phase 1 では参考収集に留め、X1 判定には用いない（pool 分離）。

*※ calibration\_blind プール（X1 判定用）と post\_intervention プールは絶対に混ぜない。F3 で取る Q1/Q2 は calibration\_blind 側。介入後に取る同型ラベルは別フォーム／別フィールドで管理する。*

*※ プロトコル（2相）：blind 汚染を断つため、**Week1 = 介入なしの純 blind 較正**（アプリ開始画面で `intervention_enabled=false`・較正モード ON → `condition=blind_calibration` / `label_pool=calibration_blind`。Nudge も Wall も発火しない）、**Week2 = Wall + 2分Timer を実発火**（`intervention_enabled=true` / `label_pool=post_intervention`）。Monk Mode は Wall しか止めず Nudge が残るため week1 較正には使わない。*

# **F4. セッション後アンケート**

各執筆セッションの終了直後。負担を最小化するため5問以内。配管（Dropbox 提出）の確認も兼ねる。

| \# | 設問文 | type | 尺度 / 選択肢 | 必須 |
| ----- | ----- | ----- | ----- | ----- |
| 1 | 今回のセッション全体で、どのくらい集中できましたか。 | 線形尺度 1–5 | 1 全く / 5 非常に | 必須 |
| 2 | プローブ（途中の問い）の頻度は適切でしたか。 | ラジオ | 多すぎ / ちょうど良い / 少なすぎ | 必須 |
| 3 | 日本語入力（変換・確定）で不具合や違和感はありましたか。 | ラジオ＋短文 | あり（内容を一言）/ なし | 必須 |
| 4 | セッションログ（NDJSON）を Dropbox に提出しましたか。 | ラジオ | 提出済み / これから提出 | 必須 |
| 5 | （任意）気づいた点・困った点。 | 段落 | — | 任意 |

*設問3は IME ログ健全性（Phase 1a の最優先確認項目）の主観側クロスチェック。ここが頻繁に『あり』なら Phase 1b データを疑う。*

# **F5. 事後アンケート（Phase 1 終了時）**

Phase 1 終了時に1回。F2-B / F2-C と同一項目を再測定し、ベースラインとの個人内比較を可能にする（pre/post 設計）。

* 一般性自己効力感（GSE-10）：F2-B と同一項目・同一尺度を再掲。

* 作業再開感・自己調整感：F2-C の項目1–4 を**同一に**再掲（matched pre/post）。

* GSE 利用体験・継続意向（事後のみ・SE スコアと別構成概念として分離）：

| \# | 項目（事後のみ） | 尺度 |
| ----- | ----- | ----- |
| 5 | GSE を使う中で、詰まったときに自分で考え直す感覚が戻る場面があった。 | 1–5 |
| 6 | 今後も GSE を使い続けたいと思う（next-week willingness）。 | 1–5 |

* NASA-TLX short（事後のみ・介入害の同時監視, v0.4 §4.4）：精神的要求 / 努力 / フラストレーション を各 1–5。**本研究では原版(0–100 / 20段階)ではなく 1–5 件法の短縮版として使用**（論文化時に「修正 NASA-TLX, 1–5 件法」と明示）。
