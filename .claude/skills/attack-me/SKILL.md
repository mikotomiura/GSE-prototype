# attack-me —— 投稿の前に、自分の論文を攻撃させる

## このスキルの目的

一人で書く論文には、身内の厳しい読み手がいない。本 Skill は、投稿先の査読者が突くであろう所を
**投稿の前に**洗い出す。見るのは次の 5 つ（研究者の要望・2026-09-30）:

1. **意図との一致**: 論文が、狙った主張・文脈・読者に持ち帰ってほしいことを十分に届けているか
2. **簡潔さと構成**: 冗長でなく、節の順序と図表が主張に奉仕し、美しくまとまっているか
3. **持ち帰れるもの**: 読者が 1 文で言える成果と、実務で使える推奨があるか
4. **具体的な穴**: 妥当性への脅威・代替説明・過剰主張・再現できない手順
5. **規程への適合**: 投稿先の規程（分量・要旨・必須の節・書式・データ公開）に従っているか

★ LLM の査読は一般論・迎合・自信過剰に流れやすい。本 Skill は **接地（実在の論文）・引用（対象物の逐語）・
解消条件・裏取り** の 4 つでそれを抑える。

## やらないこと（⚠️ 毎回守る）

- ⚠️ **実在の個人を名乗らせない**。「X 先生ならこう言う」と書かせない。査読者は匿名で、誰に当たるかは
  分からない。実在の人の見解を作るのはでっち上げになる。→ ★ 立場（"a reviewer from the keystroke-logging
  methodology tradition" など）で語らせ、その立場の基準は**実在の論文からの引用**で持たせる。
- ⚠️ **査読の結果を研究の証拠にしない**。論文の主張の根拠・事前登録の根拠に使わない。採否は研究者が決める。
- ⚠️ **有料の本文を使わない**（研究者は費用を出せない）。接地の文献は無料で読める版（OpenAlex の
  `open_access.oa_url`・著者の公開版・arXiv）だけ。無ければその文献は使わない。
- ⚠️ **人の打鍵データ・被験者のデータ・NDJSON 生ログを誰にも渡さない**（`data-privacy`）。
- ⚠️ **査読の記録を公開物（`papers/<paper>/` の書き出す範囲）に置かない**。置き場は `.steering/` の下。
- ⚠️ サブエージェントの中からさらにサブエージェントを起動させない（入れ子禁止・`subagent-delegation` ルール 4）。

## 段階（stage）と、重く見るもの

| stage | 対象物 | 重く見るもの |
|---|---|---|
| `prereg` | 事前登録の下書き（凍結の前） | 固定すべきものが固定されているか（仮説・主要指標・除外規則・n の根拠・解析の分岐・停止規則）／穴 4 |
| `outline` | 原稿の外枠（節構成・主張 ↔ 根拠の対応表） | 意図 1・持ち帰り 3・先行研究の位置づけ |
| `manuscript` | 原稿の全体 | 1〜5 すべて（★ 規程 5 は分量・要旨の語数まで数える） |
| `revision` | 改訂稿と応答書 | 前の round の指摘が解消したか・新しい穴を作っていないか |

## 手順

### Step 0: context pack をメインが作る（⚠️ A と B を混ぜない）

置き場: `.steering/<task>/attack-me/round-<N>/`。★ 相手が知り得ないものは全部メインが先に埋める。
★ **A と B は別のファイルにする**（`context-A.md` と `context-B.md`）。1 つにまとめると、査読者に目録を渡せなくなる。

- **A（`context-A.md`）: 査読者と監査役の両方に渡すもの**（本物の査読者が見るものだけ）
  - 対象物のパス（原稿・事前登録・原稿の外枠・補助資料〔公開する README など〕）。対象物からリンクされたファイルは、
    **公開物（`papers/<paper>/` のうち書き出される範囲）に限り**読んでよい。
    ⚠️ 内部の設計文書・判断の記録・`.steering/`・`*.internal.*` は入れない（読ませると、読者には分からない穴を査読者が勝手に埋めてしまう）。
  - **投稿規程の一次の抜粋**: 毎 round 取り直す（URL・取得日・逐語）。
    - ⚠️ Springer の規程のページは WebFetch がリダイレクト（`idp.springer.com` の 303 など）を返す。**表示された URL を順に辿る**
      （数回・最後の `…?error=cookies_not_supported&code=…` の URL で本文が取れる）。
    - ⚠️ WebFetch は小さなモデルの**要約**を返し、長い逐語の写しは断られることがある。prompt で
      「該当する文を、1 文ずつ短く、一字一句そのまま引用せよ」と**文ごとに**頼む。
      判定に使う要件（語数・必須の節・置き場所・データ公開）は**別の経路**（別の prompt での 2 回目の WebFetch か WebSearch の抜粋。
      WebSearch は逐語を返さないことが多いので、2 回目の WebFetch を先に試す）でも取り、
      **同じ文（数値・語が同じ）が返った**ものだけを「照合済み」とする。それ以外には「未照合」と印を付ける。
- **B（`context-B.md`）: 意図の監査役にだけ渡すもの**
  - 主張の外枠（設計文書は**節まで**指定する。例: `design.md` §0・§4・§5）・想定読者・
    **持ち帰ってほしいこと（1〜3 文・メインが書く・未実測の数値は書かない）**・既知の限界・関連する判断の番号。
    B の設計文書に規程の写しが含まれていても構わない（監査役は A も読む）。

### Step 1: panel の 3 つの立場を設計し、実在の論文で接地する（メイン）

置き場: `round-<N>/panel.md`。立場は対象物ごとに決めるが、既定は次の 3 つ:

| 役 | 立場 | 植え付ける批判的な下位人格（1 つ） |
|---|---|---|
| R1 | **手法の核の専門家**（対象の測定法・分析法の伝統） | 「その測定は本当にそれを測っているか」を疑う懐疑家 |
| R2 | **隣接分野の専門家**（応用・実装・HCI・利用者の側） | 「で、読者は何に使えるのか」と問う実務家／冗長さに厳しい読者 |
| R3 | **投稿先の方法論と再現性の番人**（統計・事前登録・オープンサイエンス・規程） | 過剰主張と検証できない手順の摘発者 |

- 各立場に **2〜3 本の実在の論文**を割り当てる（書誌・DOI・無料の URL）。探し方: WebSearch と
  OpenAlex（`https://api.openalex.org/works?search=<語>&filter=open_access.is_oa:true`）。その立場の**代表的な方法論の論文**
  （評価の基準・よくある批判を述べたもの）を優先する。⚠️ 自分たちの論文・内部の文書は接地に使わない。
- PDF は WebFetch では読めないが、保存された原本を `pypdf` で開けば全文が取れる（依頼文にこの一文を入れる。
  Windows では `PYTHONIOENCODING=utf-8` を付けて印字する）。
- ★ 書誌の「確認済み」は、**OpenAlex の記録（`https://api.openalex.org/works/doi:<DOI>`）で題・筆頭著者・年・DOI が一致し、
  `open_access.is_oa` が真で `oa_url` がある**こと。⚠️ URL の実在を curl の HEAD で確かめない（出版社はボットを 403 で止めるので、
  実在しても「確認できない」になる）。本文を開けたかどうかは別に「読めた / 未読」と書く。
- ★ 各立場に**確認済みが 2 本以上**になるまで候補を足す（足りない立場を残したまま Step 2 に進まない）。
  取りやすいのは arXiv・PubMed Central・PsyArXiv / OSF Preprints・著者の公開版。確かめられなかった文献は外すか「未確認」と書いて数に入れない。
- ★ R3（方法論と再現性）には、再現性・事前登録の論文のほか、**対象物が使う統計手法そのものの方法論の論文**（例: 一致度の指標）を入れてよい。
- ★ 3 つの立場が互いに違う角度であることを確かめる（同じ系譜の 3 人にしない）。

### Step 2: 査読者役 3 人と意図の監査役 1 人を、1 メッセージで並列に起動する

- `Agent`（`subagent_type: general-purpose`）・★ **`model: opus` を明示**・`run_in_background: true`。同時に 4 本まで。
- 依頼文は下の「ひな形」を使う。★ 範囲（読んでよいファイル）・禁止事項・締切を必ず書く（`subagent-delegation` ルール 2）。
  送った依頼文は `round-<N>/brief-R1.md`〜`brief-R3.md`・`brief-audit.md` に保存する（何を渡したかの記録）。
  ★ 依頼文の中のパスはすべて**絶対パス**にする（相手は round の dir を知らない）。
  ⚠️ Windows のパスを含む文書は Write ツールで書く（bash の heredoc や `echo` では `\r`・`\\` が化ける）。
- 〔任意〕Codex を 5 人目に加えるときは `codex-consult` の手順で、対象物の本文を**プロンプトに貼る**（Codex は repo を読めない）。
  1 日の予算（`.codex/budget.json`・origin/main の台帳も見る）と機密フィルタを先に確かめる。既定では加えない。

### Step 3: 指摘をメインが一次で裏取りする（`verify-before-claiming`）

置き場: `round-<N>/verdict.md`。各指摘について:

- 引用された対象物の箇所が**本当にそこにあるか**を開いて確かめる（無ければ偽陽性）。
- 規程の指摘は、Step 0 の規程の一次の抜粋と照合する（記憶で判定しない）。
- 接地の引用は、その論文に本当にあるかを少なくとも 1 本ずつ抜き取りで確かめる。
- 判定: **採る**／**却下**（理由を 1 行）／**研究者に問う**（設計の判断が要るもの）。

### Step 4: 編集者の判定を書く（メイン）

`verdict.md` の冒頭に:

1. 判定: accept / minor revision / major revision / reject（★ 投稿先の水準で。甘くしない）
2. 査読者どうしで**一致した指摘**（2 人以上）と、1 人だけの指摘
3. 直す順: fatal → major → minor → nit（各 1 行・対象物の位置つき）
4. 意図の監査役の「意図にあって対象物に無いもの」「対象物にあって意図に無いもの（主張の漂流）」

→ 研究者には `AskUserQuestion` で、設計の判断が要る指摘だけを推奨と理由つきで問う。直したら round N+1
（★ 前の round の指摘と対応を渡し、**再掲を求めない**。同じ立場・同じ接地の文献で回す）。

## 評価表（査読者役が埋める）

各項目 1〜5 の点と所見。★ 点だけの項目を作らない（所見の無い点は無効）。
stage で重く見ない項目（例: `outline` の e）も点は付けるが、所見は短くてよい。依頼文には「今回の stage と重く見るもの」を 1 節として書く。

| # | 項目 | 5 の目安 |
|---|---|---|
| a | 主張と根拠の一致 | すべての主張に、それを支える節・図表・数値がある。根拠より強い言い方が無い |
| b | 方法の穴 | 妥当性への脅威・交絡・代替説明が挙げられ、手当てか限界として書かれている。第三者が再現できる |
| c | 持ち帰れるもの | 成果を 1 文で言える。読者が明日から使える推奨がある |
| d | 簡潔さと構成 | 重複が無く、どの段落を消しても主張が弱くなる。節の順序が読者の問いの順 |
| e | 規程への適合 | 投稿規程の各要件を満たす（★ 要旨の語数・必須の節・書式・データと材料の公開・声明） |
| f | 先行研究の位置づけ | 接地の文献の系譜から見て、抜けている比較・引用が無い。比較が公平 |
| g | 〔`prereg` だけ〕固定の十分さ | 分析者の自由度（除外・変換・主要指標・停止）が事前に 1 通りに決まっている |

指摘の型（1 件ずつ）:

```
- [severity: fatal | major | minor | nit] <見出し>
  - 位置と引用: <対象物のファイル:行 or 節> 「<逐語>」
  - なぜ問題か: <理由>（接地があれば: <文献> 「<逐語>」）
  - 解消の条件: <何があれば／どう書けばこの指摘は消えるか>
  - 自信: 高 / 中 / 低
```

## 依頼文のひな形

### 査読者役（R1〜R3 共通・役ごとに <> を埋める）

```
あなたは <投稿先> の査読者です。立場: <立場の説明>。批判的な下位人格: <1 つ>。
⚠️ 実在の個人を名乗らない。「この立場の査読者」として書く。応答は日本語、ただし引用は原文のまま。

## 最初にすること（接地）
次の論文を読み、この立場が論文に求める基準を、逐語の引用つきで 3〜6 個抜き出してから査読に入る:
<書誌・DOI・無料の URL を 2〜3 本>
（PDF は WebFetch では読めないが保存される。保存先を python の pypdf で開けば全文が取れる。
 有料の本文は使わない。読めなかった文献は「読めなかった」と書く）

## 今回の stage と重く見るもの
stage: <stage>。重く見るもの: <「段階」の表の該当行>。原稿がまだ無い段階なら、それ自体を欠陥にしない。

## 査読する対象（読んでよいのはこれだけ）
- `<絶対パス>/context-A.md`（対象物のパスと投稿規程の一次の抜粋）と、そこに書かれたファイル
- 対象物からリンクされた公開物（`papers/<paper>/` の中で `*.internal.*` でないもの）
- 上の接地の論文（repo の外）
⚠️ これ以外の repo のファイル（`context-B.md`・`.steering/`・`docs/`・設計文書・判断の記録・他の round や他の査読者の記録）を読まない。

## 出すもの
1. 接地: 抜き出した基準（文献・逐語）
2. 評価表 a〜f（<prereg なら g も>）: 点と所見
3. 指摘の一覧（上の型・severity の重い順）
4. 総合の推奨: accept / minor / major / reject と、その理由 3 行
5. 読めなかった範囲（「読んでいない」とはっきり書く）

## 禁止事項
作業ツリーを変更しない（書くのは指定したファイルだけ: <round-N/review-RX.md>）。サブエージェントを起動しない。
隔離クローンを作らない。長い検査やビルドを回さない。

## 締切
25 分で結論を出す。間に合わなければ、そこまでの指摘と読めなかった範囲を返す。
```

### 意図の監査役

```
あなたは、この論文の著者の意図と、書かれた対象物の食い違いを探す監査役です。応答は日本語。
## 読むもの
- `context-B.md`（意図: 主張の外枠・持ち帰ってほしいこと 1〜3 文・既知の限界・関連する判断）と、そこに書かれたファイル
- `context-A.md`（対象物と投稿規程の抜粋）と、そこに書かれたファイル
⚠️ 他の round や査読者の記録は読まない（査読者と独立に見るため）。
## 出すもの（<round-N/audit.md> に書く）
1. 意図にあって対象物に無いもの（届いていない主張・持ち帰り）
2. 対象物にあって意図に無いもの（主張の漂流・範囲を超えた言い方）
3. 意図どうしの矛盾・対象物の中の矛盾
4. 各項目に対象物の位置と逐語
## 禁止事項・締切
作業ツリーは指定したファイルだけを書く。サブエージェントを起動しない。20 分で結論を出す。
```

## 記録

`.steering/<task>/attack-me/round-<N>/` に次を置く（★ 公開物の範囲に置かない）:

| ファイル | 中身 | 書き手 |
|---|---|---|
| `context-A.md` | 査読者と監査役に渡すもの: 対象物の目録・規程の一次の抜粋（URL・取得日・逐語・照合の有無） | メイン |
| `context-B.md` | 監査役にだけ渡すもの: 意図・持ち帰ってほしいこと・既知の限界 | メイン |
| `panel.md` | 3 つの立場・下位人格・接地の文献（確認済み / 未確認・読めた / 未読） | メイン |
| `brief-R1.md`〜`brief-R3.md`・`brief-audit.md` | 送った依頼文 | メイン |
| `review-R1.md`〜`review-R3.md` | 査読 | 査読者役 |
| `audit.md` | 意図との食い違い | 監査役 |
| `verdict.md` | 裏取りの結果・編集者の判定・直す順・研究者に問うこと | メイン |

★ 接地の文献は `docs/references.md` に登録しない（査読の道具であって論文の引用ではない）。
論文で実際に引くことになったら、そのとき `citation-ssot` で登録する。
