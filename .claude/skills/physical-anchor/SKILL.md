# Physical Anchor 設計規則

## このスキルの目的

GSE の Physical Anchor（**離席・歩行という身体的回帰への方向づけ**）を、
既決 D8–D10 と ADR-015 / ADR-017 / **ADR-018** に整合した設計で扱うための規則を定義する。

⚠️★★★ **Physical Anchor は「あれば良い」構成要素ではない。**
★ 既決 **D8** 逐語: 「Lv2 Wall を主軸から外すのは可。**しかし表現層だけにして Physical Anchor を外すのは
不可とする**」。★ 理由 3 本のうち 3 本目に一次が付いた ——
**不便益の認定条件 1（益は不便だからこそ＝労力）を満たすのは Physical Anchor だけである** [P170]
（⚠️ Nudge は非ブロック・自動消失＝労力を課さない）。

⚠️★★★ **ただし「認定条件 1 を満たした」と *実証* すると主張しない。**
★ 完了条件を外した以上、**労力が実際に担われたことを系は確認できない**（ADR-018 §Consequences）。
★ GSE の主張は元々「不便益を **設計思想として引く**」までであり、ここは整合している
（`docs/glossary.md` 禁止用語「不便益 HCI **である**」）。

## 適用範囲

### 適用するもの
- Physical Anchor の介入ロジック（トリガー・安全条件。⚠️ **完了条件は置かない** — ADR-018 D1）
- PC ↔ スマホの境界（★ **ADR-017 が確定済み**。本 Skill はその再掲と運用規則）
- Flutter アプリ（Physical Anchor クライアント）の設計

### 適用しないもの
- ⚠️ **Wall / Zen Timer / Monk Mode** —— ★ **2026-08-23 に全削除された**（ADR-015 D1 / D2）
- 表現層の内部仕様（層 0–3 / 禁止帯 / 粒子率）→ `docs/glossary.md` §表現層
- 介入判断そのもの → `intervention-design` Skill / `docs/architecture/intervention-decision-engine.md`

## 介入レベル定義

⚠️★★★ **段階呼称 Lv1〜Lv4 は使わない**（**ADR-018 D7**）。★ 実体名で呼ぶ。

| 介入 | トリガー | 提示するもの | 系が判定するもの |
|---|---|---|---|
| **Nudge** | （`intervention.rs` の既存閾値） | メタ認知質問 | 自動消失 / dismiss |
| **Physical Anchor（室内）** | p_stuck > 0.80 × 60s (想定) | 「いま画面から離れる」という**方向づけ** | ★★★ **何も判定しない** |
| **Physical Anchor（屋外）** | p_stuck > 0.80 × 180s (想定) | 同上（屋外を想定した文言） | ★★★ **何も判定しない** |

⚠️★★★ **完了条件を置かない**（**ADR-018 D1**。★ 既決 D11 条件 2「時間・往復」を取り下げた）。
★ 理由は 3 本:

1. ★ **単位を量から時間へ替えても、届かなかったセルは残る** —— [P99] の performance-contingent は
   「最大報酬に届かなかった」群で `d = −0.88`。★ 「1 万歩で解除」と「10 分で完了」は**単位が違うだけ**である。
   ⚠️ 同メタ分析は逐語で *"anticipated evaluation (when followed by positive feedback) led to significant
   undermining … d = −0.40"* とも述べており、**肯定的な「完了しました」表示も射程に入る。**
2. ★ **完了の宣告は [P183] 原則 4 に直撃する** ——
   *"avoid making the technology, rather than the user, the final authority on what the user is doing"*。
   ⚠️ **表現層で禁じた断定を、介入層の完了判定が裏口から行っていた。**
3. ★ **[P163] の反応性機序 3**（*"resolving discrepancies between actual and desired behaviour"*）は、
   ⚠️ **`desired behaviour` を系が定義した瞬間に立ち上がる。**

⚠️★★★ **時間長・往復回数の閾値を系が置かない**（ADR-018 D2）——
★ **どれだけ離れるか、いつ戻るかは本人が決める。**
⚠️ **タイマー・カウントダウン・残り時間表示を実装しない**（★ 閾値を持たないと表示できないため）。

★ **観測は続ける**（ADR-018 D3 / ADR-017 D8 入力 1 は不変）——
「一定時間の離席のあと作業へ戻った」という**時計の事実**は content-free に記録してよい。
⚠️★★★ **ただしこれを「完了した」と解釈せず、`completed` / `achieved` / `達成` に相当する語を
UI・表現層・ログのいずれにも置かない。**

⚠️ Physical Anchor のトリガー閾値は確定していない。実装時に `docs/functional-design.md` を更新すること。

⚠️ **Phase1 における Physical Anchor の実体は WoZ ＋ 自己申告**である（既決）。★ 実装は次段。

## 主要なルール

### ルール 1: ★★★ 身体活動を計測しない（★ 本体からは恒久的に外れた）

⚠️★★★ **歩数・距離・速度・位置情報を取得しない。** ★ 使ってよいのは
**「歩いた / 歩かなかった」の二値のみ**で、⚠️ **量は本人にも表現層にも渡さない**（既決 **D11 条件 1**）。

⚠️★★★ **2026-08-30・ADR-017 D10（研究者判断）で、これは「第 1 版では」から「本トラックでは」へ格上げされた**
—— ★ **PM-D11 の「歩行はスマホ/簡易アプリで測って *よい*」という許可を取り下げた**
（★ 条件 1 / 2 / 3 はすべて生きている）。
⚠️★★★ **証拠が優ったから選んだのではない** —— [P101] UbiFit は**測って・抽象で見せて・量は見せず・罰しない**で
成功した**この分野で唯一の統制つき成功例**であり、**証拠の上では測る側が強い。**
★ 選んだ理由は **(a) 判定に寄与しない (b) [P77] の残余リスクが消せない (c) プライバシー境界が開く
(d) 「計測なき身体回帰」という名前とずれる** の 4 点である。
★ **例外は形成的トラックのみ** —— 「本当に歩いたか」を一度だけ確かめる調査は残すが、
⚠️ **計測器は GSE 本体ではなく別プロセス**とし、**利得を主張しない**（ADR-012 の先例）。

★ 根拠（[P77] Etkin 2016・PDF 全文逐語）:
- **"Even in the absence of explicit external incentives, measurement itself can thus have similar effects."**
  → ★ **「報酬ではない」は防御にならない。**
- ⚠️ **opt-in でも / 任意閲覧でも / 本人が望んでも害が出る**（★ 3 つとも論文内の実験で潰れている）。
- ⚠️ **撤去後はベースラインを下回る**（実験 6: 読書を**避けるようになった**）。

⚠️★★★ **2026-08-30 追加の条件**: [P77] 実験 4 の「仕事枠付けによる減衰」は、
**枠付けが *無計測時の楽しさ* を先に d ≈ 0.60 下げて買っている**（t(159) = −3.06, p = .003）。
→ ★ **保護は「本人が work と感じている限り」でしか働かない。★ 歩行（回復）は最も守られない側である。**

### ルール 2: ★★★ 境界は PC → スマホの一方向イベント（ADR-017 D2 / D3 / D4）

⚠️★★★ **inbound（スマホ → PC）の「歩いた」二値経路を第 1 版で作らない。**

★ 理由（★ **ADR-018 D4 で一段強くなった**）: **完了判定を置かない ＝ センサが寄与しうる判定が
存在しない**。★ 併せて **PC は既に離席候補区間 ＋ 復帰を content-free に観測している**。
⚠️ 旧根拠（「完了条件が時間・往復だから量が要らない」）は**完了条件が変われば再燃する形**だったが、
★ **新根拠は構造的であり再燃しない。**

★ **PC → スマホのイベント契約**（★ これ以外を載せない）:

| フィールド | 値域 |
|---|---|
| `level` | `stable` / `friction_rising` / `stuck` / `intervention_active` |
| `seq` | 単調増加整数 |
| `emitted_at` | 秒粒度 |
| `epoch` | 不透明な識別子（★ チャネルの世代） |

★ **発火は `level` が変わったときだけ**。⚠️ **1Hz を流さない**（PM-D4「常時流し続けるのは一段大きい」）。

⚠️★★★ **この設計が持てるビットは「歩いた」ではなく「離席候補区間があり、復帰した」である。**
→ ★ **UI も表現層も「あなたは歩いた」と断定してはならない**
（[P183] *"avoid making the technology, rather than the user, the final authority on what the user is doing"*）。
★ 「歩いた」の確定が要る場面では**センサではなく自己申告**を使う。

★ **運搬路の 4 制約**: (1) ⚠️ PC 側に**常設の LAN リスナを置かない** / (2) on-demand ＋ ティアダウン /
(3) チャネル不在でも表現が成立する（層 0 へ縮退）/ (4) ⚠️ **チャネルが無い間のフレームを捏造しない**。
★ **併せてセキュリティ最小要件 S1–S6**（ペアリング / 送信元認証 / 偽造・リプレイ対策 / 端末紐付けと失効 /
LAN 露出の明示 / ペイロードに本人性を載せない）は **ADR-017 D4** を見ること。
★ **再接続の意味論**（`epoch` 変化で `seq` 比較を打ち切る・履歴を再送しない）は **ADR-017 D2**。
⚠️★★★ **削除済みの `wall_server.rs` 型の LAN HTTP サーバを無審査で復活させない。**

### ルール 3: ★★★ 完了判定そのものを実装しない（ADR-018 D1 / D2 / D3）

⚠️★★★ **`check_completion` 型の関数を書かない。** ★ 系が持つのは**観測**だけである。

```rust
// ✅ 正しい設計（★ 観測であって判定ではない）
/// 離席候補区間の *観測*。⚠️ 完了判定ではない（ADR-018 D3）。
struct AwayObservation {
    away_ms: u64,   // ★ 打鍵の不在の長さ（時計の事実）
    resumed: bool,  // ★ 打鍵が再開したか（時計の事実）
}
// ★ 閾値と比較しない。★ 真偽を返さない。★ ログに残して評価時に読むだけ。

// ❌ fn check_completion(...) -> bool          （ADR-018 D1 違反）
// ❌ struct AnchorTarget { min_away_ms: u64 }  （ADR-018 D2 違反・系が閾値を持っている）
// ❌ 歩数・距離で判定しない                     （ADR-017 D10 / [P99]）
// ❌ 残り時間・カウントダウンを UI に出さない    （ADR-018 D2）
```

★ **評価は達成率ではなく、招待の受容と下流の機会保存指標で行う**（ADR-018 D5）——
`paste_after_stuck_rate` / `pflow_exit_without_receipt` / `manual_contribution_ratio`。

⚠️★★★ **2026-09-07 (ADR-024)**: ★ **主要アウトカムは `receipt_free_resumption`** になった（★ 離席候補明けの
再開を起点にした受領の競合リスク CIF・**推定器を通らない**）。★ 上の 3 本のうち `pflow_exit_without_receipt`
（★ 旧 `self_recovery_without_paste`）は **`p_flow` 依存の副次**であり、報告時は
`receipt_free_resumption` と `manual_contribution_ratio` を**必ず併記**する。

### ルール 4: ★★★ 歩行を MhD（推論層）の観測に入れない

★ 既決 **D10**。⚠️ **合流点は表現層に置く** —— `p_stuck` と「離席候補区間があり復帰した」を
**別入力として表現層で合流**させる。

⚠️★★★ **「歩いたか否か」を復帰後の打鍵から推定して第 2 の入力に使ってはならない** ——
★ 同じソースを共有するため、ADR-009 D2 の自己言及（「回復した」と「歩いたから推定が下がった」が
区別できない）が戻る。★ 入力の割り方は **入力 1 = 時計の事実（離席区間の長さ ＋ 復帰の有無）/
入力 2 = `p_stuck`** に固定する（**ADR-017 D8**）。

### ルール 5: ★★★ 報酬版を採らない

★ 既決 **D9**。⚠️ **「歩くと絵が綺麗になる」形を採らない。**
★ 連動は**記録版**で実装し、評価に**自己効力感 [P15] だけを使わない**。

⚠️ **「歩いたから作業が良くなった」を暗示しない** —— micro-break のメタ解析（**22 標本 / N = 2,335**）は
**活力 d = .36 / 疲労 d = .35** を支持する一方、⚠️ **成績は全体で null（d = .16, p = .116）／
認知負荷の高い課題では d = −.09** である [P162]。
→ ★ **「散歩が認知作業を回復させる」は文献に支持されていない。**

### ルール 6: ⚠️★★★ 位置情報は本体では使わない（★ 形成的トラックなら `data-privacy` の規定が先に要る）

★ 既決 **D11 条件 3** —— `geolocator`（GPS）は `pedometer` と別扱いにする。
⚠️ **位置履歴は GSE が扱ってきたどのデータより機微**である。

⚠️★★★ **2026-08-30 実測: `data-privacy` Skill に位置情報の規定は 1 行も無い。**
★ **ADR-017 D10 により、本体では位置情報を使わないので、これは本体のブロッカーではなくなった。**
⚠️ ただし **形成的トラック（別プロセスの計測器）を回すなら発効する**
→ ★ **参照先が空のまま GPS を実装してはいけない**（**ADR-017 D9**）。

### ルール 7: 安全条件

- ★ **夜間 22:00–6:00 は屋外向けの提示を無効**にする。
- ★ **opt-in** を前提にする。⚠️ ただし **「opt-in と dismiss があるから自律性を脅かさない」とは書かない**
  —— SDT の autonomy は *"regulation by the self"* であって選択肢の多さではなく、原典逐語で
  **"having many options is not a basic need"** [P178]。★ 正しい書き方は
  **「本人が事前に *是認 (self-endorse)* しているから」**である。
