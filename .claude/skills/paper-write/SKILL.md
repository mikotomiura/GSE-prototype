# paper-write —— 主張が伝わる本文と、再現のための補足資料を分けて書く

## このスキルの目的

方法がしっかりしていても、本文が長く、手順と但し書きが主張を埋めると、編集者は査読に回さない。
2026-10 に別の論文で実際にそう判断された（研究者が会話に貼った編集者の手紙。本文は repo に入れない）。指摘の要旨:

1. 本文を大きく減らす（その編集者の目安は 5,000〜7,000 語）。方法の細部・追加の分析・検証の手順は補足資料か repo へ。
2. 論文の中心となる仕組みごとに、何を確かめるつもりだったか・実際に何を測ったか・何が分かったか・なぜ大事かで組む。
3. 評価の説明を簡単にする。読者が中心の論を理解し評価するのに要る方法の細部だけを残す。
4. 登録・事後・取り置き（held-out）などの区別は保つが、繰り返さずに効率よく伝える（構成の問題でもある）。
5. 発見の意義を示す。例えば、評価を実際に損ねた問題と、可能性にとどまる問題とを分ける。
6. 語数を削るだけでなく、組み直しとして取り組む。読者に貢献を届けることと、再現に要る記録を補足資料に残すことの均衡をとる。

本 Skill は、この 6 点を書く前の手順にする。査読者役の指摘を直すときにも同じ規則を当てる
（attack-me の指摘を足し算で直すと、但し書きと手順がまた本文に増える）。

## やらないこと

- 新規性を盛らない。「初めて」「最初の」は、調べた範囲と方法を添えて書くか、書かない（`verify-before-claiming`）。
- 補足資料へ移したものを消さない。本文から補足資料の節を名指しで参照する。事前登録・逸脱・検証の記録は全部残す。
- 凍結した事前登録の手順を、書きやすさのために変えない（変えるなら逸脱として記録する）。
- 投稿先の規程を記憶で判断しない。毎回一次から取る（attack-me の Step 0 と同じ作法）。

## 手順

### Step 0: 投稿先の適合を調べる（一次）

置き場: `.steering/<task>/paper-write/venue-fit.md`。

- 先に目的を確かめる: 誰に読ませ、読んだ人の何を変えたいか（memory「投稿先は目的から選ぶ」）。格や通りやすさから並べない。
- 投稿先の Aims & Scope・記事種別・分量（本文の語数か頁・要旨の語数・図表の数）・必須の節・補足資料の扱い
  （置き場・査読者が読む義務があるか・頁の上限に数えるか）を原文から逐語で取る。取れなければ「未照合」と印を付ける。
- 同じ投稿先の最近の論文を 5〜10 本見る（OpenAlex の `primary_location.source.id` で絞る・無料で読める版だけ）。
  記録すること: 本文の長さの目安、節の並び、方法を本文にどこまで書いて残りをどこへ出しているか、
  どんな種類の貢献（新しい手法・新しい測定・反証・資源・再現）が載っているか。
  ⚠️ 検索語に原稿の文・数値・未公開の結果を入れない。
- 結論を 3 行で書く: この論文はこの投稿先のどの種類の貢献に当たるか・読者が誰か・分量の上限。

### Step 1: 主張と新規性を確定する（本文を書く前）

置き場: 原稿の外枠（例 `outline.md`）の先頭。

- 持ち帰り 1 文: 読者が読み終えて言える 1 文。数値は実測のものだけ（結果の前は形だけ書く）。
- 貢献を 2〜4 個。各々に付けるもの:
  - 種類（新しい / 既知の確認 / 反証 / 資源）と、何に比べて新しいか（先行研究を `citation-ssot` の番号で）。
  - 根拠の位置（節・図表・数値）。
  - 強さ: 実測で確立したもの / 条件つきのもの / 可能性にとどまるもの。指摘 5 のとおり、議論ではこの区別で書き分ける。
- いちばん強い主張を 1 つ選び、抄録・序論・考察の冒頭・結論で同じ言い方にそろえる。
- 主張しないこと（範囲の外）を 3 行以内で書く。本文では限界の節の 1 か所で述べる。

### Step 2: 本文と補足資料に分ける

段落・表・図ごとに、次の問いで置き場を決める。

> この部分を本文から消すと、読者が中心の主張を理解できなくなるか、評価できなくなるか。

- はい → 本文。ただし細部は削り、補足資料の節を参照する。
- いいえ → 補足資料（または repo・付録）。

補足資料へ移すものの既定:

| 本文に残す | 補足資料へ移す |
|---|---|
| 何を測ったか（量の定義を 1〜2 文で）・なぜその測り方で主張が確かめられるか | 厳密な定義・式の全部・パラメータの一覧・種・版 |
| 中心の結果の表と図（主張を支えるもの） | 追加の分析・頑健性の確認・全条件の表・付随する図 |
| 妥当性への脅威のうち、結論を変えうるもの | 検証の手順（自己検査・変異・陽性対照）・実行の記録 |
| 事前登録との関係を 1 か所で（下の Step 4） | 逸脱の一覧の詳細・事前登録との対応表 |

- 補足資料は本文とは別のファイルにする（投稿先の形式に合わせる）。本文の各節から、補足資料の節番号で参照する。
- 投稿先が補足資料の査読を義務にしていないなら、本文だけで主張の評価が閉じるようにする。

### Step 3: 中心の仕組みごとに組む

論文が依って立つ仕組み（例: 方法上の安全策・評価の柱・攻撃者の型）が複数あるなら、それぞれを同じ 4 項目で書く:

1. 何を確かめるつもりだったか
2. 実際に何を測ったか
3. 何が分かったか
4. なぜそれが論文の主張に効くか

節の順は読者の問いの順にする（何が問題か → どう確かめたか → 何が分かったか → それで何が変わるか）。
作業した順や、事前登録の項目の順に並べない。

### Step 4: 但し書きを 1 か所にまとめる

- 分析の地位（事前登録 / 探索的 / 事後 / 取り置き）は、方法の節で 1 度だけ定義する（表か 1 段落）。
  以後は短い目印（例: 表の列、[E] のような記号、節の題）で示し、同じ説明を繰り返さない。
- 限界・範囲の外・解釈の注意は、限界の節にまとめる。他の節では限界の節を参照するだけにする。
- 同じ但し書きが本文に 2 回以上出たら、1 回にする。機械で探す: 3 語以上の同じ言い回しが節をまたいで繰り返されていないかを grep する。
- 指摘を直すとき: まず「移す・まとめる・消す」で済むかを考え、足すのは最後にする。足したら、どこを削ったかを同じ記録に書く。

### Step 5: 分量の予算と測定

- 上限は投稿先の規程が先。規程が無ければ目安: 本文 5,000〜7,000 語（抄録・参考文献・補足資料を除く）、図表込みで 20 頁台前半まで。
  これは 1 人の編集者の目安と研究者の希望であって規則ではない。投稿先の最近の論文（Step 0）と比べて決める。
- 節ごとの予算（語数か頁）を外枠に書き、書いたら機械で測る（LaTeX は `texcount` などで本文だけ・Markdown は語数）。
  測った値を `.steering/<task>/paper-write/length-log.md` に、日付と版（commit）つきで追記する。
- 予算を超えた節は、Step 2 の問いで移すものを探す。文を縮めるのはその後。

### Step 6: 意義の議論

- 考察の最初の段落で、持ち帰り 1 文と、それが誰の何を変えるかを書く。
- 問題や発見を、実際に起きた・測って確かめたもの と、起こりうるが確かめていないもの に分けて書く。
- 実務への推奨（読者が明日から使えること）を 1〜3 個。根拠の節を添える。

### Step 7: attack-me に渡す

- 原稿の版を commit し、attack-me（stage `outline` か `manuscript`）を回す。編集者の役（E）が、本文だけを読んで査読に回すかを判定する。
- 指摘を直したら Step 4 の最後の規則（足すより移す）を当て、Step 5 の語数を測り直す。

## チェックリスト（書き終えたとき）

- [ ] 持ち帰り 1 文と貢献 2〜4 個が外枠の先頭にあり、各々に根拠の位置と強さが付いている
- [ ] 抄録・序論・考察・結論で、いちばん強い主張の言い方がそろっている
