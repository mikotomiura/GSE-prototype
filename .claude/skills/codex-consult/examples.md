# Codex Consult Examples

## 例 1: アーキテクチャ判断 (HMM 状態数の設計)

入力 (公開可能な抜粋):
- 何を解決: 認知状態推定の HMM 状態数を 3 から変更するか否か
- 候補案: A) 3状態維持, B) 5状態に拡張, C) 連続値 (Gaussian HMM)
- 採用したい: A (較正データが少ない間は過適合リスクが高い)
- 不安点: Stuck の細分化 (浅い詰まり vs 深い詰まり) が捨てられる

Codex の指摘 (典型的応答):
- 抜け観点: 遷移行列の初期化方法、ラベル収集数の推定
- 追加候補: A' = 3状態だが Stuck を soft-split (事後的に 2 クラスタへ)
- 採用案リスク: 状態数不足でセンシティビティが落ちる可能性

→ 統合判断: soft-split は後で検討できる。初期化方法は確かに抜けていたので design.md に追記。
